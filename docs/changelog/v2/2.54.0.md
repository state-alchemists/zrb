## 2.54.0 (August 4, 2026)

**Breaking.** The system prompt collapses from six rule sections to three, and the tool-guidance registry is removed. `ToolGuidance`, `add_tool_guidance`, `add_tool_guidance_factory`, `add_tool_guidance_section_factory`, `add_tool_group`, and `PromptManager.tool_names` are gone with no shim; `register_section` replaces them. A pinned `ZRB_LLM_INCLUDE_SECTIONS` naming a retired section still parses: it falls through to the custom-section path, composing to nothing with a warning — or emitting your own file if you have a markdown override of that name.

- **Improvement: the prompt carried its weight in a rulebook instead of next to the tools** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm/prompt/manager.py`, `src/zrb/config/mixins/llm_prompt.py`, ADR-0045): the composed default prompt measured **32,621 chars (~8,150 tok)**, ~5,200 tok of it rule prose against ~2,800 in Claude Code and OpenCode's `anthropic.txt`, and IFScale (arXiv 2507.11538) finds later instructions in a dense rulebook are dropped first. Rules now live at the layer that can enforce them (see ADR-0045). `DEFAULT_LLM_INCLUDE_SECTIONS` becomes `persona,workflow,examples,system_context,project_context` — three rule sections and two data sections. The default prompt is now **19,478 chars (~4,870 tok)**, about 40% down; with ~450 tok more in tool docstrings, the net context floor falls roughly 45%. `test_default_prompt_stays_within_its_budget` pins it under 24,000 chars.
- **Breaking: `mandate` folded into `workflow`; the back-compat shim is removed** (`src/zrb/llm/prompt/markdown/mandate.md` deleted, ADR-0045): the Priority Order now opens `workflow`, where primacy says it belongs, instead of living in a separately toggleable section. The `manager.py` shim that emitted both files when a config named only `mandate` is gone.
- **Breaking: `git_mandate` deleted — the rule was already enforced in code, and had drifted** (`src/zrb/llm/prompt/markdown/git_mandate.md` deleted, `src/zrb/llm/common_tools.py`, `src/zrb/builtin/llm/chat.py`, ADR-0045): `bash_safe_command_policy()` already allowlists only `git status`/`diff`/`log`/`show` and sends mutating git commands to the user, and the section had gone stale (it called `branch`, `remote -v` and `worktree list` approval-free, which the runtime never granted). The one behaviour a policy cannot produce, showing `git status` and `git diff HEAD` before requesting approval, is a line in `workflow`'s Priority 1. The policy moved from `builtin/llm/chat.py` into `apply_common_tools`, so every host with an approval channel gets it; hosts without one (programmatic `LLMTask`, `SubAgentManager`) are skipped.
- **Breaking: `tool_guidance` and its four-host registry deleted** (`src/zrb/llm/prompt/tool_guidance.py` deleted, `manager.py`, `task/building.py`, `task/chat/building.py`, `task/chat/execution.py`, `agent/subagent/manager.py`, `src/zrb/__init__.py`, ADR-0058): the 5,178-char section duplicated the tool docstrings and was synced by hand, which had already produced two different delegation trigger lists. Its 30 entries became docstring lines for cross-tool forks, a four-rule `### Tool usage` block in `workflow`, or nothing where the docstring already sufficed. The parallel-tool-call note moves into `system_context` as a `- Parallel tool calls: …` line. `PromptManager.tool_names` is removed. **Migration:** use `register_section(name, provider)` (ADR-0044), whose provider sees the live context. The move buys locality, not tokens: docstrings ship every request (ADR-0058).
- **Breaking: the journal is three tools and no prose** (`src/zrb/llm/tool/journal_write.py` added; `journal_mandate.md`, `journal_reminder.md`, `llm/hook/journal.py`, and `llm_plugin/core_skills/core-journaling/` deleted, ADR-0055): one line of memory used to cost an 838-token prompt section, an 11 KB skill, three templates and a 295-line linter. `LogActivity(summary, files=None)` appends a timestamped line to the day's activity log, and `WriteJournalNote(category, slug, title, context, finding, source, links=None, hud_line=None)` writes a topic note with reciprocal backlinks, index registration, and an optional HUD line; alongside `SearchJournal` they own the format, so the linter's four invariants cannot be violated and path traversal is closed by construction. What earns an entry is now in the tool docstrings. Legacy and hand-written journals still work: `SearchJournal` reads anything and journal-dir auto-approvals for `Write`/`Edit`/`RM`/`MV` remain.
- **Breaking: `LLM_JOURNAL_ENABLED` moved from `active_sections` to tool registration** (`src/zrb/llm/prompt/manager.py`, `src/zrb/llm/common_tools.py`, `llm_task.py`, `task/chat/execution.py`, `agent/subagent/manager.py`, ADR-0055): with no journal section left, the flag now unregisters all three journal tools in `apply_common_tools`, and `render_journal_index` checks it directly for the `<live-context>` injection. The four `"journal_mandate" in active_sections` guards are deleted. `ZRB_LLM_INCLUDE_JOURNAL_REMINDER` and its `STOP` hook are removed outright, since a single tool call needs no nudge.
- **Improvement: `examples` kept and made the third section** (`src/zrb/llm/prompt/markdown/examples.mini.md`): the collapse stopped at three sections because demonstrations are the highest-value content per token for small models (ADR-0049), so cutting rules *and* examples would hit the weakest models twice. The `mini` variant drops its two journal blocks (`Reading the journal table`, `Sequencing a journal write`), now covered by the tool docstrings or made moot by a single tool call.
- **Dead code removed alongside the refactor** (`src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/util/cli/style.py`, `src/zrb/llm/prompt/manager.py`): the `inject_journal_index` parameter of `create_summarizer_history_processor` and `summarize_history` (always `True` in production) is gone. `stylize_bold_green`/`_yellow`/`_red` had zero call sites (the semantic `stylize_warning`/`stylize_error`/`stylize_success` are used) and ADR-0027 is corrected to match. `PromptManager._emitted_sections` is inlined. A reachability scan over 1,216 top-level names and 1,283 class members found nothing else unreferenced.
- **Docs: a retired section name plus a user override still works, and now says so** (`docs/advanced-topics/upgrading-guide.md`, `docs/configuration/llm-config.md`, `docs/advanced-topics/programming-the-prompt.md`, `test/llm/prompt/test_manager.py`): a user who pins `mandate` in `ZRB_LLM_INCLUDE_SECTIONS` and has a `mandate.md` override keeps getting it at that position, pinned by `test_retired_section_name_still_serves_a_user_override`; the first draft of the upgrade notes said such overrides were no longer read. A new `## Upgrading to 2.54.0` section covers the removed API (before/after table), the four retired sections and where their content went, and this caveat.
- **Fix: `test_section_composition.py` guarded a section it can no longer reach** (`test/llm/prompt/test_section_composition.py`): `test_tool_guidance_is_self_contained` is removed with its section. `FILE_SECTIONS` drops from six to three (7 subset combinations instead of 63), and one `<!--requires:-->` guard remains — `workflow`'s pointer at `project_context`.
