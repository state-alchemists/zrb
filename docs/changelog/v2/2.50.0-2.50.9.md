## 2.50.0 (July 8, 2026)

- **Named style themes via `ZRB_THEME`** (`src/zrb/config/theme.py`, `src/zrb/config/mixins/theme.py`, ADR-0027): one theme preset now supplies the default for every style knob across the chat TUI, the markdown renderer, and the CLI colors. Ships `dark` (the historical defaults, so a default install looks identical) and `light`. Any individually set `ZRB_LLM_UI_STYLE_*` / `ZRB_CLI_*` env still overrides the theme, and `register_theme(name, values)` in `zrb_init.py` adds or overrides themes (partial themes inherit from `dark`; see `examples/themes/monokai/`). An unknown `ZRB_THEME` warns and falls back to `dark`.
- **Markdown rendering colors are now configurable** (`src/zrb/util/cli/markdown.py`, `src/zrb/config/mixins/llm_ui_styles.py`): the previously hardcoded Rich theme is driven by new `ZRB_LLM_UI_STYLE_MARKDOWN_{LINK,LINK_URL,H1,CODE}` knobs.
- **Previously hardcoded TUI styles lifted into config** (`src/zrb/llm/app/layout.py`, `src/zrb/llm/app/style.py`, `src/zrb/llm/ui/default/output_mixin.py`): the title-bar background and input-prompt color are now `ZRB_LLM_UI_STYLE_TITLE_BAR_BG` and `ZRB_LLM_UI_STYLE_PROMPT`; the jargon, choice-widget, and `shift+tab` hint shades follow the theme's `FAINT`/`TEXT` knobs. This is what makes the `light` theme coherent.
- **Install scripts: softer legacy `~/.local-venv` cleanup** (`install.sh`, `install.ps1`): the installers no longer delete `~/.local-venv` or rewrite rc files/the PowerShell profile. They only uninstall `zrb` from the old venv (so the `pipx` copy wins on PATH) and print how to remove the directory, noting that the existing activation block keeps activating the venv until it is removed. The `zrb`-uninstalled log fires only when `zrb` was actually present.

## 2.50.9 (July 29, 2026)

_Cumulative summary of the 2.50.1–2.50.9 patch line._

- **Breaking: `ActivateSkill`'s parameter is `skill`, not `name`** (`src/zrb/llm/tool/skill.py`): models resolved `name` to the domain noun. In an eight-model, 288-trial benchmark, 68 of 167 calls named the field wrongly (`skill` 41, `skill_name` 26, `skill_id` 1) across six models, each miss costing a validation retry. Aliases were rejected because accepting several spellings makes every field optional and drops `required`/`additionalProperties: false`. `ActivateSkill(name=...)` now raises a validation error.
- **Breaking: `LLMTask(summarize_command=...)` is `summarize_commands`** (`src/zrb/llm/task/llm_task.py`): the parameter was singular while holding a list, where the `LLMChatTask` equivalent and every sibling accessor were already plural. No alias — `LLMTask` is exported from the package root, so this raises `TypeError`.
- **Breaking: `*_mixin.py` modules renamed for what they are** (26 modules under `src/zrb/llm/`, 16 mirrored test files, ADR-0035): classes that read state only one host provides are now *parts* named `<Owner><Aspect>` in a file named for the aspect — e.g. `exec_mixin.py::ExecMixin` → `execution.py::ChatExecution`, `commands_mixin.py::CommandsMixin` → `commands.py::BaseUICommands`. `BufferedOutputMixin` keeps its suffix. Path stutter went too (`hook/manager/manager.py` → `hook/manager.py`). Package-level imports are unaffected; deep module paths moved.
- **Feature: session token usage in the TUI status bar** (`src/zrb/llm/ui/`, `src/zrb/llm/util/stream_response.py`): accumulated session input/output tokens render as `💸 1.5k in · 34 out` beside the ready/working indicator and reset on `/load`. The context gauge now counts last-request input **plus** output (the reply is re-sent next turn) and no longer double-counts cache reads/writes, which pydantic-ai already folds into `input_tokens`.
- **Feature: PDF fetching in `open_web_page`** (`src/zrb/llm/tool/web.py`): URLs ending in `.pdf` or served with a PDF `Content-Type` (including extensionless viewer URLs, with no extra round-trip) are read as PDFs, with text extracted by `pdfplumber`. On plain-HTTP failure the fetch falls through to the browser, so a PDF behind a JS or cookie wall still works.
- **Reliability: fan-out failure semantics, in two shapes** (`src/zrb/util/run.py`, `src/zrb/session/session.py`, `src/zrb/task/base/execution.py`, `docs/architecture/1-spine/task-execution.md`): plain `asyncio.gather` left siblings running after the first failure. `gather_isolated` lets every sibling settle, then re-raises (successors, fallbacks, task chains, root tasks). `gather_fail_fast` cancels siblings with a bounded settle, for siblings that may never return (a `Scheduler` loop, a deferred long-running body, a polling `HttpCheck`). It also keeps `ZRB_TASK_READINESS_TIMEOUT` a real ceiling: 29.4s overshoot against a 200ms cap before, 5.2s after.
- **Reliability: command hooks no longer leak processes or outlive their session** (`src/zrb/llm/hook/hook_creators.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/llm/task/chat/execution.py`): on timeout, `process.kill()` killed only the `shell=True` shell, so a forked grandchild survived and kept `communicate()` blocked. Hooks now run in their own session and are killed by process group (psutil recursive fallback on Windows). Since Ctrl+C no longer reaches fire-and-forget hooks, `HookManager.shutdown()` cancels pending hooks at teardown after a grace period, on the one-shot and web paths too (`drain=True` there).
- **Reliability: cleanup inside cancellation handlers could mask the cancellation** (`src/zrb/llm/ui/`): an audit of every `except CancelledError`/`except TimeoutError` that runs cleanup found three sites where the cleanup itself could raise and convert a cancelled run into an ordinary failure. `/exec` reaps its child before writing to the UI, `MultiUI.run` guards the main-UI unwind, and the message-queue loop re-raises when the cancel was aimed at the loop itself instead of swallowing it.
- **Fix: unbounded tool payloads froze the TUI** (`src/zrb/llm/tool/web.py`, `mcp.py`, `code.py`, ADR-0059): a tool return larger than the per-minute token budget could never pass the rate limiter, livelocking the UI. Web pages, MCP results and oversized single files are capped to `LLM_MAX_OUTPUT_CHARS`. MCP results share one budget across the whole structure (per-item caps let N parts total N times the limit); binary and rich content pass through uncharged. JSON truncation now cuts the dominant text field inside the dict and re-serializes, so the result stays valid JSON.
- **Fix: the TUI event loop is no longer blocked by the turn's hot path** (`src/zrb/llm/agent/common.py`, `src/zrb/llm/prompt/`, `src/zrb/llm/task/`, `src/zrb/llm/tool_call/`): sync tools froze the UI because `create_safe_wrapper` is a coroutine function, bypassing pydantic-ai's executor offload. They now run via `asyncio.to_thread`, as do git subprocesses, history load/save, live-context rendering, argument formatting and diff rendering. `ModelRetry` is re-raised so pydantic-ai's retry protocol works. Scroll-follow detection is O(1) per streamed chunk instead of O(buffer).
- **Fix: config knobs that did nothing, and one that finally does** (`src/zrb/config/mixins/`, `src/zrb/llm/util/git.py`): `ZRB_HOOKS_DEBUG`, `ZRB_HOOKS_LOG_LEVEL`, `ZRB_LLM_PROJECT_DOC_MAX_CHARS` and `ZRB_LLM_UI_STYLE_PROMPT` were never read by anything (tests only checked the env round-trip) and are removed. `ZRB_LLM_GIT_CMD_TIMEOUT` is now applied to the live-context git calls, which hardcoded `timeout=5` or had none, so a blocking git stalled every prompt compose. Its default moved 1000 → 5000. A timed-out git-repo probe is no longer cached as "not a git dir", which used to disable git context for the rest of the process.
- **Fix: style values crashed the TUI at startup** (`src/zrb/llm/app/layout.py`, `style.py`): the title-bar and prompt knobs, documented as prompt-toolkit styles, were interpolated into an HTML `color=` attribute, so any value with a space (`bold #ff0000`) crashed layout building. They now resolve through the style dict, and a title containing `<` or `&` is escaped rather than parsed.
- **Fix: web-chat approval and edit-mode races** (`src/zrb/runner/chat/`): decoded JSON args arriving with no edit slot were denied outright by the plain approval handler; the miss is now reported and the pending approval kept. A cancelled run left `is_waiting_for_edit()` stuck true, stranding later approvals; the slot is now released on cancellation and stale slots cleared. Approval broadcasts keep a strong task reference so they cannot be garbage-collected mid-flight.
- **Fix: assorted correctness** (`src/zrb/llm/tool/shell.py`, `file_edit.py`, `mcp.py`, `src/zrb/llm/history_manager/`, `src/zrb/llm/util/clipboard.py`, `src/zrb/runner/web_route/static/`): the shell reader's line limit rose from 64 KB (which lost all output on a minified-JS or one-line-JSON line) to 8 MB, and a post-start stream error terminates the subprocess; conversation saves write to a `.tmp` and rename, so a crash cannot truncate the live file; MCP `BinaryContent` passes through unstringified; terminal width is read from stdin; Termux clipboard uses `termux-clipboard-set`; and the refresh-token route serves an inert script when auth is disabled, ending a 401 on every page load.
- **Fix: agent-facing wording that cost real round-trips** (`src/zrb/llm/tool/shell.py`, `file_edit.py`): `Shell`'s `timeout` never said *seconds*; five benchmark calls passed milliseconds, and one run that passed all nine validator checks was recorded as a timeout (15 meant, 15000 sent). It now says `SECONDS, not milliseconds` and points long-running processes at `background=True`. A no-op `Edit` returned a bare `No changes made to <path>` without the `[SYSTEM SUGGESTION]` prefix, inviting the identical call again (one trial got it 76 times); its three causes now get separate guidance.
- **Security: `fstring_format` sandbox escape via dunder traversal** (`src/zrb/util/string/format.py`): template expressions referencing a dunder name are rejected, closing the `().__class__.__bases__[0].__subclasses__()` route back to real builtins — plain attribute access is not governed by the `eval` globals, so a builtins whitelist alone could not stop it.
- **Performance: LSP detection, repo analysis, conversation save, and the test suite** (`src/zrb/llm/lsp/configs.py`, `src/zrb/llm/tool/code.py`, `src/zrb/llm/task/llm_task.py`, `test/`): LSP `detect()` ran a `shutil.which` per server on every agent `Write`/`Edit` (up to ~1s each); it is now cached per process with an invalidation hook. Repo analysis no longer tokenizes each file twice. Summarization-path saves run off the event loop. A full test run dropped ~118s → ~66s, mostly from the hook process-group fix above.
- **Fix: the test suite ran the developer's real hooks** (`test/conftest.py`): two sites built a bare `HookManager()` that resolved its own search dirs, so a machine with `~/.claude/settings.json` hooks dispatched them during tests. Both now build managers that never scan the filesystem, with a guard test.
- **Documentation: three claims that described features that did not exist** (`docs/core-concepts/make-task.md`, `docs/configuration/llm-config.md`, `docs/advanced-topics/maintainer-guide.md`, `AGENTS.md`): `readiness_timeout` was documented as capping the initial readiness wait; it only applies to the re-check loop under `monitor_readiness=True`, while the initial wait is bounded by `ZRB_TASK_READINESS_TIMEOUT` (off by default). `ZRB_THEME` was undocumented outside its ADR. The maintainer guide specified nested changelog sub-bullets while recent releases used flat ones.
