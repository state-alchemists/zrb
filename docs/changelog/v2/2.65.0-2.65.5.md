## 2.65.0 (August 17, 2026)

- **Feature: custom slash commands in event-driven UIs** (`src/zrb/llm/ui/queue_based_input.py`, `src/zrb/llm/ui/simple_ui_base.py`, `src/zrb/llm/ui/ui_factory.py`, `src/zrb/llm/task/chat/running.py`, `src/zrb/runner/chat/http_ui.py`, `examples/chat-telegram/zrb_init.py`): the web (SSE) and Telegram UIs previously ignored user-sent slash commands that only the interactive prompt_toolkit TUI knew how to dispatch. `QueueBasedInput.handle_incoming` now resolves custom commands via `resolve_custom_command` before forwarding to the LLM, so `/my-command prompt text` works identically in event-driven and interactive sessions. The `custom_commands` list is threaded through `create_ui_factory` → `SimpleUI.__init__` → `UIConfig` so every UI variant receives it.
- **Chore: silent `except Exception: pass` blocks replaced with debug logging** (`src/zrb/llm/config/limiter.py`, `src/zrb/llm/ui/default/{agent_picker,lifecycle,selection}.py`, `src/zrb/llm/prompt/system_context.py`, `src/zrb/llm/hook/process_io.py`): eight bare `except Exception: pass` sites that swallowed errors in tiktoken fallback, UI focus/invalidate/scroll, infra-type detection, and pipe close now log at `DEBUG` level via `CFG.LOGGER`, making transient failures diagnosable without polluting normal output.
- **Chore: narrowed overly-broad `except Exception` catches** (`src/zrb/llm/hook/creator.py`, `src/zrb/util/asset_scanner.py`): the hook stdout JSON parser now catches `json.JSONDecodeError` instead of all exceptions; the file-scan walker now catches `PermissionError | OSError` instead of all exceptions — both avoid masking unexpected errors.
- **Chore: security/robustness comments added to `asyncio.gather` fan-out sites** (`src/zrb/llm/ui/base/exec_commands.py`, `src/zrb/llm/tool/shell.py`, `src/zrb/task/base/monitoring.py`, `src/zrb/task/base_trigger.py`): four `asyncio.gather` call sites that intentionally do NOT use `return_exceptions=True` (fail-fast semantics) now carry inline comments explaining why — a future sweep cannot accidentally "fix" them into masking reader/check/callback failures.
- **Refactor: `InputCompleter.get_completions` split for readability** (`src/zrb/llm/app/completion/completer.py`): the 80-line `/model` subcommand + single-token-argument dispatch was extracted into `_get_model_argument_completions`, `_single_token_arg`, and `_get_single_token_arg_completions` (with a dispatch table), reducing the main method to ~20 lines.
- **Refactor: `BaseUIProperties` exposes previously-internal state via public read properties** (`src/zrb/llm/ui/base/properties.py`, `src/zrb/llm/ui/default/{output,message_editing}.py`): `confirmation_output_buffer`, `pending_attachments`, `plan_mode_active`, `voice_mode_active`, `is_thinking`, `message_queue`, `queued_edit_entry`, `output_field`, and `input_field` are now public read-only (or read-write for the toggleable modes) properties, replacing direct `_`-prefixed access from sibling parts.
- **Chore: `/photo` command alias extended** (`src/zrb/config/mixins/llm_ui_commands.py`): the photo command now also responds to `/p`, matching the `/v` shorthand pattern of the `/voice` command.
- **Feature: sub-agent tool approval dialogs visible in TUI main window** (`src/zrb/llm/tool_call/ui_protocol.py`, `src/zrb/llm/ui/buffered_ui.py`, `src/zrb/llm/ui/simple_ui_base.py`, `src/zrb/llm/ui/multi_ui.py`, `src/zrb/llm/ui/std_ui.py`, `src/zrb/llm/ui/default/confirmation.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/tool_call/handler.py`, `src/zrb/llm/approval/terminal_approval_channel.py`): when a sub-agent calls an approval-gated tool (Write, Shell, etc.), the tool name and arguments are now written to the parent TUI window before the confirmation prompt appears, so the user can see what they're approving without navigating into the sub-agent's live view. The new `output_to_parent` parameter on `UIProtocol.ask_user()` threads the approval message from `ToolCallHandler` and `TerminalApprovalChannel` through `BufferedUI` to the wrapped parent UI. `AskUserQuestion` tool (auto-approved) is unaffected.

## 2.65.1 (August 17, 2026)

- **Fix: "↓ talk to a sub-agent" hint no longer shows after sub-agents finish** (`src/zrb/llm/ui/default/output.py`): the activity panel now only advertises the sub-agent picker when there are actively running sub-agents in the activity registry, preventing a stale hint after all sub-agents have gone idle.

## 2.65.4 (August 21, 2026)

- **Refactor: private/protected cross-object access eliminated across the LLM subsystem and task utilities** (`src/zrb/llm/ui/`, `src/zrb/llm/task/chat/`, `src/zrb/llm/config/limiter.py`, `src/zrb/llm/tool/plan.py`, `src/zrb/llm/voice/engine.py`, `src/zrb/llm/lsp/`, `src/zrb/group/{group,any_group}.py`, `src/zrb/util/todo/`, `src/zrb/util/git/`): continues the composition sweep from 2.65.3. `BaseUIProperties` and `ChatBuilding` were folded directly into `BaseUI`/`LLMChatTask`; `util/group.py`'s free functions (`extract_node_from_args`, `get_node_path`, `get_subtasks`, `get_all_subtasks`, `get_non_empty_subgroups`) became `AnyGroup`/`Group` instance methods; `util/todo.py` and `util/git.py` split into packages with matching test suites. Cross-part and cross-object reaches now go through public properties and methods instead of `_`-prefixed attributes.
- **Fix: `task/base/{execution,monitoring,lifecycle}.py` sibling parts hold direct references to each other instead of reaching through `BaseTask`'s private attributes** (`src/zrb/task/base/execution.py`, `src/zrb/task/base/monitoring.py`, `src/zrb/task/base/lifecycle.py`, `src/zrb/task/base/base_task.py`): the initial de-privatization pass had `BaseTaskExecution`, `BaseTaskMonitoring`, and `BaseTaskLifecycle` call back into each other via `task._base_monitoring` / `task._base_execution` / `task._base_context`, reintroducing the exact private-attribute-crossing pattern the sweep was meant to remove. Adding matching public delegators to `BaseTask` was rejected because it would have leaked internal wiring onto every exported task class (`Task`, `CmdTask`, `LLMTask`, `LLMChatTask`, and others); each part now holds a direct reference to the sibling it needs instead.
- **Fix: `LLMChatTask` system-prompt resolution restores its documented "no prompt manager → empty string" contract** (`src/zrb/llm/task/chat/execution.py`, `src/zrb/llm/task/chat/task.py`): the de-privatization pass had switched three call sites from the raw, nullable `_prompt_manager` attribute to the raising `prompt_manager` property, which would crash instead of degrading gracefully. The new `LLMChatTask.has_prompt_manager` property restores the original, non-raising check.
- **Refactor: duplicated approval-channel resolution and filesystem-safe-naming logic consolidated** (`src/zrb/llm/approval/multiplex_approval_channel.py`, `src/zrb/llm/task/chat/{execution,running}.py`, `src/zrb/util/string/conversion.py`, `src/zrb/llm/tool/plan.py`, `src/zrb/llm/snapshot/manager.py`): the "single channel, or wrap 2+ in `MultiplexApprovalChannel`" logic, previously written out three times, is now `resolve_approval_channel()`; the identical filesystem-name-sanitizing helper duplicated in `plan.py` and `snapshot/manager.py` is now the shared `to_safe_filename()`.
- **Tests: public API snapshot updated for `LLMChatTask.has_prompt_manager`** (`test/public_api_snapshot.json`).

## 2.65.5 (August 22, 2026)

- **Feature: `DelegateToAgent` fan-out concurrency is capped** (`src/zrb/config/mixins/llm_limits.py`, `src/zrb/tool/delegate.py`, `docs/adr/adr-0068.md`): each concurrent entry of a `tasks=[...]` fan-out is its own LLM run against the shared rate limiter and, with `isolate_worktree`, its own git worktree, so an unreasonably large model-requested batch multiplied both unboundedly. The new `ZRB_LLM_MAX_PARALLEL_DELEGATIONS` env var (default `10`, mirroring `LLM_MAX_AGENTS_IN_ROSTER`) gates entry into `_run_parallel` via an `asyncio.Semaphore`; `0` or negative disables the cap. The cap paces concurrency rather than rejecting tasks — a 50-task call still runs all 50, throttled to N in flight.
- **Feature: `Write` refuses to overwrite a file the current run hasn't observed** (`src/zrb/llm/tool/file_observation.py`, `src/zrb/llm/tool/{file_write,file_read,file_edit}.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/task/llm_task.py`, `docs/adr/adr-0084.md`): `write_file(mode="w")` against an existing file blindly truncated it regardless of whether the agent had ever seen its current content. A new run-scoped observation map records each successful Read/Write/Edit's full content hash; `check_observed` re-hashes right before a destructive overwrite and blocks with a `[SYSTEM SUGGESTION]` when nothing was recorded or the content changed since. Tracking is keyed by the new `current_agent_run_scope` ContextVar (the session name for a top-level conversation, a fresh id per delegation so sub-agents don't inherit their parent's observations) and held in an LRU capped at 256 scopes — every delegation mints a scope that outlives its run, and eviction fails safe (the next overwrite under an evicted scope is refused with a pointer back to `Read`). Binary (non-UTF-8) targets are refused outright in every mode, since Write/Edit emit UTF-8 only.
- **Feature: worktree tools run through the OS sandbox and permission gates** (`src/zrb/llm/tool/worktree.py`, `src/zrb/llm/sandbox/os_sandbox.py`, `src/zrb/llm/agent/gates.py`, `src/zrb/llm/permission/policy.py`, `docs/adr/adr-0065.md`): `enter_worktree`/`exit_worktree`/`list_worktrees` previously spawned bare `git` subprocesses outside both enforcement layers. `build_sandboxed_argv` now takes any discrete argv (not just a shell triple), so the worktree git calls get the same containment as `Shell`; `worktree_path` joined the sandbox/permission salient write keys so `ExitWorktree`'s deletion target is Python-gated too.
- **Security: secret inputs are masked in persisted session logs** (`src/zrb/session/session.py`): `_sanitize_input` replaced every declared-secret input value with `***` before the log reached disk or HTTP consumers; previously secrets were serialized verbatim into session state logs.
- **Security: task-session API route no longer serves another task's log by name-guessing** (`src/zrb/runner/web_route/task_session_api_route.py`): anyone authorized for one task could read another task's session log by guessing its random name; the route now verifies the log's recorded task path matches the task named in the URL (404 otherwise) and maps storage/validation failures to 404 instead of 500. Related hardening: the chat API parses malformed bodies as `{}` instead of raising (`runner/chat/chat_api_route.py`), and the task-input route returns 400 on non-JSON `query` (`runner/web_route/task_input_api_route.py`).
- **Security: `SSHPASS` is exported only for remote execution** (`src/zrb/task/cmd_task.py`): every local command's environment previously carried the remote password even when it never needed it; it now appears only when a remote host is configured and a password is set.
- **Reliability: background process output shares `Shell`'s bounded-capture machinery** (`src/zrb/llm/tool/shell_background.py`, `src/zrb/llm/tool/stream_capture.py`, `docs/adr/adr-0059.md`): `MonitorProcess` kept unbounded stdout/stderr line lists; it now feeds the same tail-keeping `StreamCapture` used by foreground shell commands, reports where truncated output was spilled, and reuses one spill file across polls instead of leaking a temp file per call.
- **Reliability: RAG index tracks file deletions and stops blocking the event loop** (`src/zrb/llm/tool/rag.py`): files deleted after indexing lingered in the vector store forever — they're now removed from the collection and hash baseline (guarded by existence so a transient unreadable file never drops live data). ChromaDB/embedding/query calls moved onto `asyncio.to_thread`, which previously froze the whole session's event loop for the duration of re-indexing.
- **Fix: `PYTHONUNBUFFERED` replaces misspelled `PYTHONBUFFERED` in command environments** (`src/zrb/task/cmd_task.py`): the typo'd variable did nothing, so child Python processes buffered output as before; the corrected spelling restores live streaming.
- **Fix: `NO_COLOR` is no longer forced into child command environments** (`src/zrb/util/cmd/command.py`): setting `NO_COLOR="0"` disables color under the NO_COLOR convention (any non-empty value counts), contradicting its "explicitly allow color" intent; absence now inherits the user's own choice.
- **Fix: failed `/session` switch rolls back the session name** (`src/zrb/llm/ui/base/conversation_commands.py`): a history-load failure left `conversation_session_name` pointing at the new conversation while the old transcript was still displayed, persisting subsequent turns under the wrong name.
- **Fix: `MultiUI` input races resolved deterministically and stale confirmations cleared** (`src/zrb/llm/ui/multi_ui.py`): `ask_user`/`ask_user_choice` picked the winning UI by arbitrary set order and returned early on winner errors without syncing sibling confirmation queues; the lowest-index UI now wins deterministically, losing same-round tasks are cancelled, and queues are cleared on both success and failure paths.
- **Fix: dirty history-manager cache survives external writes between update and save** (`src/zrb/llm/history_manager/file_history_manager.py`): a differing on-disk mtime invalidated the cache even for unsaved in-memory edits, letting `load()` discard newer-than-disk content; dirty entries are now always served from cache.
- **Fix: duplicate todo ids within one `set_todos` call no longer silently merge** (`src/zrb/llm/tool/plan.py`): two items claiming the same explicit id (or an auto-assigned id colliding with an existing todo) collapsed into one entry; `TodoManager._next_auto_id` now skips ids already claimed this call or persisted in the session.
- **Fix: readiness properties treat explicit values literally** (`src/zrb/task/base/base_task.py`): truthiness checks coerced an intentional `readiness_timeout=0` (disable the cap) to the default 60 s; the checks are now `is not None`, matching how monitoring consumes them.
- **Fix: `read_file` falls back to base64 only for genuinely binary files** (`src/zrb/util/file.py`): any exception during text/PDF extraction — including transient read errors — was swallowed into a base64 dump; now only `UnicodeDecodeError` takes the binary path and other errors propagate to the caller.
- **Fix: Xcom push/pop callbacks fire for every mutation path** (`src/zrb/xcom/xcom.py`): `appendleft`, `extend`, `extendleft`, `insert`, `remove`, and item assignment bypassed the deque-overridden callbacks; all now fire like `append`/`pop` do.
- **Fix: temp file leaked when the interactive editor crashed** (`src/zrb/llm/tool_call/edit_util.py`): `edit_content_via_editor` removed its tempfile only on the happy path; cleanup moved to a `finally`.
- **Fix: caught tool exceptions are tagged `error=True` in `ToolReturn` metadata** (`src/zrb/llm/tool/wrapper.py`, `docs/adr/adr-0057.md`): `tool_safe_async`-wrapped failures were indistinguishable by metadata from successes; both wrapping paths now tag consistently. `enter_worktree`/`exit_worktree`/`list_worktrees` dropped the decorator accordingly so direct in-process callers (delegate fan-out) still see real exceptions.
- **Fix: re-deferring a task action cancels the orphaned coroutine** (`src/zrb/session/session.py`): deferring twice left the first scheduled action running but never awaited by `wait_deferred`, invisible to terminate; the previous coroutine is cancelled first.
- **Fix: callback failures are logged even without an error queue** (`src/zrb/callback/callback.py`): trigger fan-out swallowed callback exceptions silently when no `error_queue` was configured; `CFG.LOGGER` now records them.
- **Improvement: nested agents inherit YOLO state explicitly** (`src/zrb/llm/agent/run/{runner,setup}.py`, `src/zrb/llm/agent/subagent/manager.py`, `src/zrb/llm/task/llm_task.py`): `run_agent`'s `yolo` parameter gained a tri-state contract — `None` inherits the ambient context, `True`/`False` force it — replacing the old truthiness merge that made an explicit opt-out indistinguishable from unset.
- **Improvement: `HttpCheck`/`TcpCheck` read their interval lazily** (`src/zrb/task/{http_check,tcp_check}.py`): the fallback interval was snapshotted at definition time, so an env change after task registration had no effect until restart.
- **Improvement: project-local prompt overrides take effect immediately** (`src/zrb/llm/prompt/prompt.py`): `_find_custom_prompt` dropped its `lru_cache`, so edits under `LLM_PROMPT_DIR` land on the next turn instead of requiring a restart.
- **Improvement: repo analysis no longer tears down the shared LSP servers** (`src/zrb/llm/tool/code.py`): `analyze_code` called `lsp_manager.shutdown_all()` after each run, forcing every other consumer's next query to cold-start a server; session-end teardown handles cleanup.
- **Refactor: `LLMTask` exposes its building state through public accessors** (`src/zrb/llm/task/{llm_task,building,history}.py`, `src/zrb/llm/agent/subagent/{manager,manager_loading}.py`, `src/zrb/llm/ui/base/{ui,system_info}.py`, `src/zrb/llm/ui/default/{selection,ui}.py`): continues the de-privatization sweep — `LLMTaskBuilding` reads owner state through new public properties (`tools`, `toolsets`, `prompt_manager_attr`, `hook_manager`, …), `SubAgentManagerLoading._scan_dir` became public `scan_dir`, `BaseUISystemInfo`'s methods dropped their underscores behind existing `BaseUI` delegators, and `UISelection._choice_window` gained a guarded `choice_window` property. `ToolCallHandler`'s `add_tool_policy`/`add_argument_formatter`/`add_response_handler` aliases (documented as removed in the upgrading guide) were deleted.
