## 2.53.0 (August 2, 2026)

- **Fix: every tool result was sent to the model twice, and each one presented as a new user turn** (`src/zrb/llm/agent/tool_result.py` added, `src/zrb/llm/agent/common.py`, `src/zrb/llm/agent/gates.py`, `src/zrb/llm/agent/truncate.py`, ADR-0043): every zrb wrapper populated both `ToolReturn.return_value` and `content`, and `content` is sent as a separate `UserPromptPart`. On a real 9-turn session the byte-identical duplicate was **73.6k of 356.3k input tokens (21%)**, persisted into saved history, and showed the model eight fake user turns, matching observed re-analysis loops. `content` is now unset in one helper, `tool_result.py::tool_return`, and `return_value` keeps the tool's own (unstringified) shape. A 14-shape differential showed zero provider-visible deltas besides the removed duplicate. Gate denials and tool errors no longer arrive as a `null` result plus a detached user turn.
- **Fix: a journal that had never been written to reported itself as broken** (`src/zrb/llm/tool/journal.py`, `docs/technical-specs/llm-context.md`): `search_journal` returned `Journal directory not found` when the directory was absent, and nothing created it, so on a fresh machine the agent concluded journaling was unavailable, fell back to `[journal-fallback]`, and never attempted the write that would have succeeded. A missing directory is now created and reported as an empty result; only an uncreatable directory is an error. The technical spec's claim that nothing under `src/zrb/llm/` calls `os.makedirs` is corrected.
- **Fix: the Stop-hook `systemMessage` extension had no ceiling** (`src/zrb/llm/agent/run/session_extension.py`): the block-to-continue path was capped at `STOP_HOOK_BLOCK_CAP = 8`, but a `systemMessage`, which also re-runs the turn, had no cap, so a hook returning one on every `Stop` looped the agent without bound (the built-in journaling hook escaped only because its guard reset per session, not per turn as documented). `STOP_HOOK_SYSTEM_MESSAGE_CAP` gives that path its own budget.
- **Feature: a cross-section reference is pruned when its target is not composed** (`src/zrb/llm/prompt/section_filter.py` added, `src/zrb/llm/prompt/manager.py`, ADR-0046): with sections toggled independently via `LLM_INCLUDE_SECTIONS`, a config omitting `journal_mandate` still got instructions to "search the journal", and the prose hedges ("where present") cost tokens in every configuration. A block wrapped in `<!--requires:section-->` … `<!--/requires-->` (comma-separated dependencies, all required; a marker alone on its line removes the line, mid-sentence only itself) is now removed at compose time, filtered against the sections actually emitted (e.g. `git_mandate` outside a git repo). `test_section_composition.py` checks all 63 combinations of the six file-backed sections in both profiles; it caught two real leaks.
- **Feature: `auto` selects the small-model profile from a declared size in the model id** (`src/zrb/llm/prompt/profile.py`, `docs/configuration/llm-config.md`, `AGENTS.md`, ADR-0049): the profile registry shipped empty, so `auto` resolved to `terse` for every model and `examples.explicit.md` reached zero sessions. `DEFAULT_MODEL_PROFILES` now matches only a stated parameter count of 14B or less (`-7b`, `gemma-2-9b`, `qwen3-14b`; not `-32b`/`-70b`/`-405b`) and a vendor small-tier label (`mini`, `nano`, `tiny`, `small`, `lite`, `haiku`). A family name is still never read as capability, and `flash` is excluded as a latency tier. A false positive costs only example tokens. User declarations are consulted first, so one line overrides either way.
- **Breaking: the `explicit` prompt profile is renamed `mini`, with no alias** (`src/zrb/llm/prompt/markdown/examples.explicit.md` → `examples.mini.md`, `src/zrb/llm/prompt/profile.py`, `src/zrb/config/mixins/llm_prompt.py`, `docs/configuration/llm-config.md`, `docs/advanced-topics/programming-the-prompt.md`, `AGENTS.md`, ADR-0049): `explicit` named the directive re-wording style that 2.52.0 removed; `mini` names the model class the profile serves. `ZRB_LLM_PROFILE=explicit` is no longer recognised and falls through to `auto`; `register_model_profile(..., "explicit")` raises `ValueError: Unknown profile`. No alias, because ADR-0026's preserve-the-old-key rule covers env keys, both consumers here fail loudly, and `auto` selects `mini` on small models anyway.
- **Improvement: the prompt is 18% smaller, journaling is opt-in by bar rather than mandatory, and demonstrations replace prohibitions** (all six files under `src/zrb/llm/prompt/markdown/`): composed markdown went 6,870 → 5,610 tokens; worked `<example>` blocks 3 → 9 under `terse` and 25 under `mini`; standalone prohibitions 3.8 → 2.0 per 1k tokens; bold directives 122 → 93. The journal section went 1,677 → 852 tokens: its default flipped from "when in doubt, log it" to "most turns record nothing", the everyday write is one appended line, and the insight-note format, indexes and backlinks moved to `core-journaling` (a conversational turn observed writing seven files now writes one). `journal_mandate` is the single owner of journaling rules. The uncertainty ladder dropped to three rungs, and eighteen prohibitions became affirmative instructions.
- **Fix: the Turn Sequence left a numbering hole when journaling was disabled** (`src/zrb/llm/prompt/markdown/workflow.md`, `test/llm/prompt/test_section_composition.py`): without `journal_mandate` the sequence read 1, 2, 4, 5, which reads as a withheld step. The conditional journal step moved to the end of the list and the Working Loop left the numbered list; a test checks every numbered run in all 63 subsets for holes.
- **Fix: a journal write rode along with the reply, so a filler line became the visible answer** (`src/zrb/llm/prompt/markdown/journal_mandate.md`, `examples.mini.md`): "log after the work and before the reply" is contradictory on a conversational turn, where the work is the reply; the model emitted the analysis and the `Write` together, and "Done" replaced a five-thousand-character answer as the turn's output. The order is now verify → log → answer, with the reply always last; the failure mode is named and demonstrated in `examples.mini.md`.
- **Fix: a missing path told the model nothing about how to find the right one** (`src/zrb/llm/tool_call/tool_policy/read_file_validation.py`, `replace_in_file_validation.py`, `src/zrb/llm/tool/file_search.py`, `file_list.py`): four "not found" returns lacked a `[SYSTEM SUGGESTION]`, and `Read`'s helpful message was unreachable behind the pre-execution policy denial. One model, working one directory above the repo, got three bare errors and declared the task impossible. Each message now resolves the path, names the usual cause (a relative path resolved against the current directory, not the project root), and points at `List`.
- **Fix: "this cannot be done" was the only claim in the prompt exempt from verification** (`src/zrb/llm/prompt/markdown/workflow.md`): Recovery's "task cannot succeed as stated → say so plainly and stop" carried no evidence requirement, while every other assertion in the prompt traces to something checked that session. A model that has guessed wrong twice satisfies the rule by halting, and halting looks like compliance. The clause now states that a failed guess is not evidence for impossibility, and that the actual state gets confirmed before the halt.

## 2.53.2a2 (August 4, 2026)

_Cumulative summary of the 2.53.1a1–2.53.2a2 patch line._

- **Feature: `Read` numbers every line, and `Edit` tolerates the prefix** (`src/zrb/llm/tool/file_read.py`, `file_edit.py`, `src/zrb/llm/prompt/markdown/persona.md`, `docs/llm/extending-the-llm.md`): `persona` requires `file:line` citations, but `Read` returned unnumbered text. `read_file` now emits `cat -n` form, numbering a ranged read from `start_line`. PDF text is not numbered (its line breaks come from the extractor), and the char cap is measured before numbering, so `LLM_MAX_OUTPUT_CHARS` keeps its meaning (prefixes would have cost ~13.5%). `replace_in_file` strips a copied prefix from `old_text` and `new_text` as a last resort, after exact and fuzzy matching, only when every line carries it.
- **Fix: skill activation matched the turn's *output* instead of the turn's *work*** (`src/zrb/llm/prompt/markdown/workflow.md`, the `description` of all five core skills, `generalist.agent.md`): rules keyed on "the turn's deliverable", so mapping unfamiliar code in order to change it activated only the coding skill. A skill now applies when its methodology is needed anywhere in the turn, and each description states the triggering activity. `ActivateSkill` is no longer a deferred tool, since activation is Turn Sequence step 2.
- **Fix: a wrong `agent_name` sent the model back to re-read a description it had already misread** (`src/zrb/llm/tool/delegate.py`, `delegate_background.py`): the not-found error now lists the roster and leads with the closest match (`general-purpose` → *Did you mean 'generalist'?*). `DelegateToAgentBackground` previously listed no valid names and, detaching immediately, failed an unknown agent only at collection; it now carries the roster and resolves the name before detaching. The delegation rule now says to pick by the tool schema's descriptions, never by a name from another harness.
- **Improvement: the prompt was restructured around one precedence order and self-contained sections** (`src/zrb/llm/prompt/markdown/`, `test/llm/prompt/test_section_composition.py`): Turn Sequence step 1 is now **Check the premise** (name load-bearing assumptions; ask one targeted question only when ambiguous, untestable and expensive to get wrong), after one run went ~15 calls deep on a wrong premise. Four partial precedence statements became one Priority Order, ending a contradiction about where `AGENTS.md` ranks. Every switchable section reads whole on its own. The worked examples moved to the `mini` profile, taking the examples section from 2,336 to 294 tokens under `terse`. `Recovery` gained a convergence test so a retry loop cannot satisfy it forever.
- **Improvement: the journal HUD carried the user's identity, not just links to it** (`src/zrb/llm/prompt/live_context.py`, `src/zrb/config/mixins/llm_content.py`): the root index is the only journal file injected unprompted, but no write path put facts there, and its hardcoded 1000-char head-first cut let a growing link list evict the identity it should carry. The cap moved to `LLM_JOURNAL_INDEX_MAX_CHARS` (default 2500), cuts on a line boundary, and orders near-static facts first and the growing list last. *(The prose protocol behind this was superseded in 2.54.0, when the journal became three tools that own the format.)*
- **Fix: `LLM_JOURNAL_INDEX_MAX_CHARS=0` uncapped the injection instead of disabling it** (`src/zrb/llm/prompt/live_context.py`): the falsy value fell through to "no limit", so the knob's off position was its most expensive setting.
- **Fix: every background delegation built its sub-agent twice, the first time on the caller's turn** (`src/zrb/llm/tool/delegate_background.py`): the construction that was meant to validate the request ran in full and was then discarded, so the caller paid a complete agent build before the work detached.
- **Improvement: `/resume` and `/v` aliases** (`src/zrb/config/mixins/llm_ui_commands.py`): `/load` accepts `/resume` and `/voice` accepts `/v`. Additive — existing spellings are unchanged and either default can still be overridden.
