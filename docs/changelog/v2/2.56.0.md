## 2.56.0 (August 7, 2026)

- **Feature: the chat greeting and `/help` render as width-aware tables that re-lay out on resize** (`src/zrb/util/cli/help_panel.py`, `src/zrb/llm/ui/base/commands.py`, `src/zrb/llm/ui/base/conversation_commands.py`, `src/zrb/llm/ui/default/ui.py`): the greeting was rendered once at startup, so the ASCII art was dropped entirely whenever `art + 2 + widest help line` exceeded the terminal, and every description was cut at 75 characters with `...`. `render_help_panel` now lays the rows out for the current width, again on every resize: descriptions wrap inside their column, and the art keeps its own column until the tables would drop under `MIN_CONTENT_WIDTH`, then moves above them instead of disappearing. Tables are borderless. The greeting lists at most `GREETING_COMMAND_LIMIT` (20) commands, summarizing the rest as `... and N more`; `/help` lists every one.
- **Improvement: any width-dependent output can now be re-rendered on resize, not just markdown** (`src/zrb/llm/ui/default/output.py`, `src/zrb/llm/ui/default/ui.py`, `test/llm/ui/default/test_output.py`): the tracking added in 2.52.0 was markdown-only — `_markdown_blocks` stored `[start, end, source]` and `rewrap_markdown` re-rendered each span through `render_markdown`. Blocks now store their own renderer (`[start, end, source, renderer]`) and are appended through the new public `append_rendered(source, renderer)`, with `append_markdown` as the markdown-shaped wrapper; `rewrap_markdown` is `rewrap_output` accordingly. That is what lets the greeting panel and `/help` re-lay out on SIGWINCH like markdown already did. The default UI's output buffer starts empty and appends the greeting through this path, so `create_output_field` no longer pads an empty greeting with two blank lines.
- **Refactor: `create_banner` removed in favor of art resolution plus panel composition** (`src/zrb/util/ascii_art/banner.py`, `src/zrb/util/cli/ansi.py`, `src/zrb/util/cli/markdown.py`, `test/util/ascii_art/test_banner.py`): the banner module's side-by-side composition (and its overflow rule that hid the art) is superseded by `help_panel`, leaving it responsible only for *which* art and *what is in it* — the former `_get_art_only` is now public as `get_ascii_art`, which the UI calls once at startup so an unresolvable name's random fallback cannot reshuffle the image on every resize. Rich's line padding is stripped by the shared `strip_trailing_padding` in the new `util/cli/ansi.py`, extracted verbatim from `render_markdown` and now used by both renderers.
