## 2.48.0 (July 1, 2026)

- **Feature: `disallowedTools` frontmatter field for sub-agents** (`src/zrb/llm/agent/subagent/manager/`): New `disallowedTools` field in `.agent.md` frontmatter lets sub-agent definitions remove specific tools from their resolved toolset after the allowlist and factories have been applied. Accepts YAML list (`[Edit, Write]`) or comma-separated string (`Edit, Write`) formats.
- **Feature: Comma-separated `tools` frontmatter** (`src/zrb/llm/agent/subagent/manager/loader_mixin.py`): The `tools` field now accepts both YAML list and comma-separated string formats, matching the Claude Code sub-agent specification for broader compatibility.
- **Fix: Tool name resolution edge case** (`src/zrb/llm/agent/subagent/manager/manager.py`): Extracted tool name resolution into a dedicated `_resolve_tool_name()` helper that uses explicit `is not None` checks, preventing falsy values (e.g., empty string) from incorrectly falling through to `__name__`.
- **Docs: Sub-agent frontmatter spec** (`docs/advanced-topics/claude-compatibility.md`): Documented `tools` and `disallowedTools` formats, and their precedence.

## 2.48.4 (July 4, 2026)

_Cumulative summary of the 2.48.1–2.48.4 patch line._

- **Reliability: task readiness and retry races** (`src/zrb/task/base/execution.py`, `src/zrb/task_status/task_status.py`): `mark_as_started()` now runs before the action coroutine's first suspension point, closing a window where two upstreams completing in the same event-loop tick could both pass `is_allowed_to_run` and run the action twice. Readiness gates on `is_permanently_failed` rather than the per-attempt `is_failed`, which raced with the retry loop and could skip `mark_as_ready` forever. A readiness check that exhausts its retries now cancels the action, fails the task and runs fallbacks instead of hanging in `wait_deferred` with no error exit.
- **Reliability: cancellation is no longer swallowed as completion** (`src/zrb/task/base/lifecycle.py`, `base/monitoring.py`, `src/zrb/callback/callback.py`, `src/zrb/task/base_task.py`): `execute_root_tasks` re-raises `CancelledError`/`KeyboardInterrupt` instead of returning `None`, so a cancelled session no longer looks like a successful run. The monitor distinguishes an expected action-cancel from being cancelled itself, and cancellation is no longer published as a task failure.
- **Reliability: cron parsing and Scheduler ticks** (`src/zrb/util/cron.py`, `src/zrb/task/scheduler.py`): wildcard steps inside a comma-separated list (`1,*/5`) parse correctly, out-of-range values raise instead of silently never firing, and `7` is accepted for Sunday. The scheduler dedupes on the fired minute, clamps sleeps to the next minute boundary so drift cannot skip a scheduled fire, and exits once the session is terminated.
- **Reliability: subprocess output ordering and `\r` progress** (`src/zrb/util/cmd/command.py`): two independently scheduled `readline()` readers could each drain a burst of buffered lines before yielding, reordering interleaved stdout/stderr. A single multiplexing loop reading raw bytes replaces them, so ordering matches write order and `\r`-driven progress bars display live. An unterminated line is force-flushed past `CFG.CMD_BUFFER_LIMIT`, restoring the memory valve `readline()` used to provide.
- **Reliability: deferred draining, approval channels and chat sessions** (`src/zrb/session/session.py`, `src/zrb/llm/approval/multiplex_approval_channel.py`, `src/zrb/runner/chat/chat_session_runner.py`): `wait_deferred` drains coroutines deferred *while* an existing batch is awaited, and a pruned coroutine's exception is logged rather than discarded. A single erroring approval channel no longer denies the request before a slower channel (a human at the terminal) can answer. A failed or timed-out chat request no longer kills the session loop.
- **Fix: LLM history and tool pairing** (`src/zrb/llm/message.py`, `src/zrb/llm/task/`): merging sequential `ModelRequest`s uses `dataclasses.replace` so `instructions`/`run_id` survive; `RetryPromptPart` counts as a tool return for orphan-stripping and pairing; duplicate-user detection compares only the most recent real user turn, so a repeated "continue" is not mistaken for an already-sent turn; toolsets resolve once per action instead of being re-resolved.
- **Fix: silently ignored inputs** (`src/zrb/builtin/llm/chat.py`, `src/zrb/llm/task/chat/`, `src/zrb/input/bool_input.py`): `--attach` was accepted but never wired through; `LLMChatTask` dropped its own `model_settings` in favour of `llm_config`'s; `BoolInput.get_default_str` returned `"True"`/`"False"` where its own `<option>` values are lowercase.
- **Fix: slash commands in interactive chat** (`src/zrb/llm/task/chat/`): the interactive path built its default UI kwargs before resolving custom commands, so a slash command passed as the starting message only worked in non-interactive runs.
- **Security: SSH password moves to `SSHPASS`** (`src/zrb/util/cmd/remote.py`, `src/zrb/task/cmd_task.py`, `src/zrb/task/rsync_task.py`): `sshpass -p <password>` is replaced by `sshpass -e` everywhere, so the password never appears in the process list or a shell command string.
- **Security: input rendering and the static route** (`src/zrb/input/*.py`, `src/zrb/runner/web_route/static/static_route.py`): `to_html()` escapes name, description and default before interpolation. A hand-rolled `/static/{file_path:path}` handler — dead code shadowed by the `StaticFiles` mount, and a path-traversal hole the day registration order changed — was removed.
- **Feature: `WEB_ENABLE_SECURE_COOKIES`** (`src/zrb/config/mixins/web.py`): the auth cookie's `Secure` flag is configurable (default on) instead of hardcoded, which silently broke cookie auth on plain-HTTP non-localhost deployments.
- **Feature: sub-agent `disallowedTools`, and comma-separated `tools`** (`src/zrb/llm/agent/subagent/`): `.agent.md` frontmatter can remove specific tools after the allowlist and factories resolve, and both fields accept a YAML list or a comma-separated string, matching the Claude Code sub-agent spec.
- **Chore: `pydantic-ai-slim` 2.2.0, typing, and docs** (`pyproject.toml`, `src/zrb/llm/agent/common.py`, `src/zrb/llm/util/stream_response.py`, `docs/`): adapted to `ToolCallEvent`/`ToolResultEvent` replacing the narrower function-tool event classes and to the removed `OpenAIModel` alias; `SafeToolsetWrapper` is annotated `WrapperToolset[None]` with `deps_type` pinned so the `toolsets`/`model_settings` overloads resolve. Corrections across 30+ documentation pages.
