## 2.58.0 (August 9, 2026)

**Breaking.** The Python API changes without shims — see [Upgrading to 3.0.0 → `add_X` on ordered collections](../../advanced-topics/upgrading-guide.md#add_x-on-ordered-collections-is-append_x-or-prepend_x), where this release's migration (the `add_X` aliases, keyword-only constructors, `auto_render_shell`/`AnyAttr` renames) now lives. Env keys are unaffected; `EnvField(aliases=...)` still covers those.

- **Fix: the prompt never said whether tool calls reach the real machine** (`src/zrb/llm/prompt/system_context.py`, `AGENTS.md`, `docs/adr/adr-0050.md`): with `LLM_SANDBOX_ENABLED` off by default, every `Write`, `Edit` and `Shell` call lands on the user's disk, yet the prompt never told the model, so the rank-1 "irreversible, external, or destructive" rule was under-applied. `system_context` now emits `- Sandbox: none — file writes and shell commands take effect on this machine directly and are not contained.` There is deliberately no "you are sandboxed" line. A task built with `sandbox=True` is honoured. See ADR-0050.
- **Fix: three relative ratchets could not see uniform prompt drift** (`test/llm/prompt/test_section_composition.py`, `AGENTS.md`): the burden ladder and the composed-total guard pin the *ordering* across presets, and only `full` had an absolute ceiling, so adding a paragraph to all three variants kept every ratchet green. Each preset now has its own ceiling on the composed prompt, `PRESET_BUDGETS`: full 24,000 / lean 20,000 / minimal 6,000 chars against 20,066 / 17,371 / 4,923 shipped. This enforces the rule that a more capable model buys more *autonomy*, not more *text*.
- **Improvement: the two constrained presets get a number instead of a judgment call** (`src/zrb/llm/prompt/markdown/persona.minimal.md`, `persona.lean.md`): `persona` calibrated reply length qualitatively, the judgment `minimal` exists to avoid; opencode anchors it numerically ("fewer than 4 lines"). `minimal` now caps replies at four lines and says one word is often the whole answer; `lean` applies the same number to direct answers but not to structured plans. Both fold into existing bullets, since the burden ladder requires the rule count to fall across presets.
- **Documentation: the model-family axis already existed and nothing said so** (`AGENTS.md`, `docs/adr/adr-0051.md`): opencode forks nine prompt files by model-id substring; zrb's equivalent is `register_preset("gemini", Preset(variant="gemini"))` plus `register_model_profile("gemini-", "gemini")`, which ships `workflow.gemini.md` with `register_preset`'s safety checks. zrb ships zero family variants and should keep it that way — an unmeasured family delta is overfitting (opencode's `beast.txt`). Capability governs how much the model is asked to hold; family stays an escape hatch.
- **Fix: a comment invited a refactor that would have regressed two model families silently** (`src/zrb/llm/prompt/profile.py`, `test/llm/prompt/test_profile.py`, `docs/adr/adr-0051.md`): `ModelProfileRegistry` claimed to mirror `model_capabilities`, but the two key differently on purpose. Capabilities match the **bare** model name (a property of the weights, so deny patterns can be `^`-anchored); profiles match the **full** id (a property of the deployment: `ollama:phi4-mini` is `minimal`, `phi4-mini` is `lean`). Merging would either send local small models back to `lean` or grant a text-only model image support, silently. The comment now states the distinction, a test pins both halves, and both registries are exported from `zrb`. See ADR-0051.
- **Fix: `py.typed` was missing, so every downstream type-checker saw zrb as untyped** (`src/zrb/py.typed`): PEP 561 requires the marker file for annotations (`StrAttr`, `BoolAttr`, `AnyTask`, protocols, `TypeGuard`) to reach a consumer; without it `mypy` and `pyright` treated `from zrb import Task` as `Any`. One empty file.
- **Fix: `upstream=(a, b)` stored the tuple as if it were a task** (`src/zrb/task/base_task.py`, `src/zrb/task/any_task.py`, `src/zrb/task/base/operators.py`): only a `list` was treated as a collection, so a tuple failed later with `'tuple' object has no attribute 'name'`, and `a >> (b, c)` broke the same way. Both now accept any `Sequence` and reject `str`/`bytes`. The check is on the collection side, not `isinstance(tasks, AnyTask)`, so stubs, mocks and duck-typed tasks still work. `input=(...)` already worked.
- **Improvement: `Sequence` everywhere a task accepts a collection** (`src/zrb/task/*.py`, `src/zrb/llm/task/*.py`): `input`/`env` were `Sequence[...]` on `BaseTask` and `make_task` but `list[...]` on the other nine task classes, so a tuple type-checked against `Task` and failed against `CmdTask`; `readiness_check`/`upstream`/`fallback`/`successor` were `list[...]` even on `BaseTask`. All are now `Sequence`, including the public `append_upstream`/`append_fallback`/`append_successor`/`append_readiness_check` and the `>>`/`<<` operators. Widening, so no existing call breaks.
- **Improvement: `RsyncTask` now accepts what its own docstring promised** (`src/zrb/task/rsync_task.py`): it claimed "Every parameter `CmdTask` accepts is also accepted here" while omitting nine: the five `readiness_check_*`/`monitor_readiness` knobs, plus `shell_flag`, `render_shell_flag` and `is_interactive`. All nine are forwarded, and the docstring names the three real exclusions: `cmd` and `render_cmd` are generated from the path parameters, and `warn_unrecommended_command` screens a command you wrote.
- **Improvement: `LLMChatTask` accepts `hook_manager=`, like `LLMTask`** (`src/zrb/llm/task/chat/task.py`, `chat/execution.py`, `chat/state.py`): chat built a fresh `HookManager` per run with no way to supply one except `append_hook_factory`. The default is unchanged (`None` means a fresh manager per run, keeping one session's hooks out of the next); passing one explicitly is the documented opt-out.
- **Removed: 22 `add_X` aliases on ordered collections** (`src/zrb/llm/task/building.py`, `src/zrb/llm/task/chat/building.py`, `src/zrb/llm/agent/subagent/manager.py`, `src/zrb/llm/prompt/manager.py`, `src/zrb/llm/common_tools.py`): each forwarded to `append_X` (nineteen) or `prepend_X` (three), so `add_response_handler`, `add_tool_policy` and `add_argument_formatter` inserted at the *front* while every sibling appended. Position is the whole semantics of these calls, so the name now states it. Convention: **ordered pipelines take `append_X`/`prepend_X`, unordered registries keep `add_X`** (`skill_manager.add_skill`, `sub_agent_manager.add_agent`, `Group.add_task`, `PromptManager.add_live_context`).
- **Removed: `AnyAttr`** (`src/zrb/attr/type.py`, `src/zrb/util/attr.py`, `src/zrb/input/base_input.py`): defined as `Any | fstring | Callable[..., Any]`, which collapses to `Any`, so it constrained nothing. Use `Any`, or the specific `*Attr` alias. `fstring` stays: in `BoolAttr = bool | fstring | ...` it documents "or a template string that renders to a bool". `StrListAttr` is now exported, since it appears in `LLMChatTask(active_skills=...)`.
- **Breaking: task constructors are keyword-only after `name`** (`src/zrb/task/*.py`, `src/zrb/llm/task/*.py`): `LLMChatTask` had 73 positionally-passable parameters, `LLMTask` 53, `CmdTask` 45, so inserting a parameter anywhere was a silent breaking change for positional callers. `Task("build")` still works; `Task("build", 5)` no longer does.
- **Breaking: `RsyncTask(auto_render_shell=)` is `render_shell=`** (`src/zrb/task/rsync_task.py`): the only site spelling that flag with an `auto_` prefix; its parent `CmdTask` spells it `render_shell`, and `RsyncTask` already forwarded it under the new name.
- **New: 18 names exported from `zrb`** (`src/zrb/__init__.py`): the managers were exported without the types needed to call them (`hook_manager` with no `HookResult`). Added: `Skill`, `SubAgentDefinition`, `HookEvent`, `HookContext`, `HookResult`, `PromptManager`, `Preset`, `register_preset`, `register_model_profile`, `model_capabilities`, `register_theme`, `register_always_auto_approve`, `PermissionPolicy`, `Rule`, `ALLOW`, `DENY`, `ASK`, `StrListAttr`. No `zrb/llm/__init__.py` was added on purpose: `zrb.llm` is an implicit namespace package whose eleven children each curate their own `__all__`, and an eager root would make a narrow `zrb.llm.sandbox` import pull the whole LLM stack.
- **Refactor: `llm/ui` no longer imports `LLMTask`, and seven lazy imports hoisted** (`src/zrb/llm/ui/*.py`, `src/zrb/llm/common_tools.py`, `src/zrb/llm/tool/plan.py`, `src/zrb/llm/prompt/live_context.py`): 27 `# lazy: circular` imports traced to one edge, `ui → llm_task`, and every use of `LLMTask` in `ui` was a type annotation (plus one `cast()`). Moving those behind `TYPE_CHECKING` — rather than extracting a single-implementation protocol — cut `zrb.llm.ui.base.ui`'s dependency on `zrb.llm.task` and let seven imports hoist, including a `permission.state` trio whose cycle comment was simply wrong. 27 → 20.
- **Refactor: two whole components moved out of the tool modules they were embedded in** (`src/zrb/llm/ui/buffered_ui.py`, `src/zrb/llm/tool/stream_capture.py`): `BufferedUI`, a full `UIProtocol` implementation, moved from `llm/tool/delegate.py` to `llm/ui/buffered_ui.py` and is exported from `zrb.llm.ui` (`delegate.py` 509 → 387 lines). `_StreamCapture` moved from `llm/tool/shell.py` to `llm/tool/stream_capture.py` as public `StreamCapture`, now testable without a subprocess (`shell.py` 620 → 496). The 13 `BufferedUI` tests moved to `test/llm/ui/test_buffered_ui.py`.
- **Refactor: `PromptManager` had one registry shape written three times** (`src/zrb/llm/prompt/manager.py`): live, system and project context each re-implemented "replace or append by name" and "call each provider, swallow its errors, keep non-empty results" (one bad plugin must not cost the whole prompt). They now share `_ProviderRegistry`. Section providers stay separate: one provider per section is selected, not concatenated.
- **New: `./zrb-api-doc.sh` renders the API reference from docstrings** (`zrb-api-doc.sh`, `pyproject.toml`, `docs/advanced-topics/maintainer-guide.md`): previously only `LLMChatTask` had a hand-written reference. The script uses `pdoc` (not `mkdocstrings`, since `docs/` has no `mkdocs.yml`) and writes to the gitignored `dist/api`. `test_public_api_docs.py` and `test_public_api_contract.py` keep the page free of blanks. Its `ToolCallPart` parse warnings are expected: those pydantic-ai types stay behind `TYPE_CHECKING` for startup time.
- **New: the web page layer has smoke tests** (`test/runner/web_route/test_page_routes.py`): `test/runner/web_route/` covered only API routes and login/logout, so a renamed template failed only at request time. The home and chat tests assert every stacked URL alias, and the 404 test asserts the `/api` branch rather than the status code, which would pass with the handler missing.
- **Fix: four shims that were mislabelled, and three that were real** (`src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/llm/prompt/manager.py`, `src/zrb/llm/prompt/prompt.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/llm/ui/polling_ui.py`, `src/zrb/llm/ui/event_driven_ui.py`): removed `create_summarizer_history_processor`'s unused `agent=` and its `token_threshold=` shadow of `conversational_token_threshold`; `_file_section_middleware` takes a single `name` now that `mandate` is retired; `get_prompt`'s docstring no longer uses `get_prompt("mandate")`. Relabelled as real API, not shims: `HookManager.execute_hooks_simple` (an adapter to `HookResult`'s Claude-format mapping) and `PollingUI.input_queue` / `EventDrivenUI.input_queue`. `render_diff(ui=)` was already gone.
- **Documentation: the four highest-traffic public symbols had no docstring at all** (`src/zrb/group/group.py`, `src/zrb/task/make_task.py`, `src/zrb/task/task.py`, `src/zrb/input/str_input.py`): `Group` had no docs across twelve public members; `make_task` had none despite 22 parameters; `Task` and `StrInput` were `class X(Base): pass` with `__doc__ is None`, and are the first names in every tutorial. All four now carry worked examples. `Group.add_group` is now typed `AnyGroup | str` (it always accepted a bare string), and the alias-then-name fallback in `remove_group`/`remove_task` is documented.

### Also in this release (previously staged as 2.57.1, never published)

- **Improvement: `Bash` removed; `Shell` is the only shell tool** (`src/zrb/llm/tool/bash.py` deleted, `src/zrb/llm/tool/shell.py`, `src/zrb/llm/agent/subagent/manager.py`, `src/zrb/llm/permission/capability.py`, ADR-0058): two overlapping shell tools cost a schema on every request and a choice on every call; `Shell` takes `shell="bash"` when bash is wanted. Claude Code sub-agent or skill files listing `Bash` in `tools:` / `disallowedTools:` keep working (mapped to `Shell` case-insensitively on load), and hook matchers accept `{"matcher": "Bash"}`. No alias on the tool: a model calling `Bash` gets an unknown-tool error naming `Shell`.
- **Improvement: `lean` subtracts a tool surface, and small local models reach `minimal`** (`src/zrb/llm/prompt/profile.py`, `src/zrb/llm/common_tools.py`, `docs/adr/adr-0049.md`): `Preset` gained a `drops` denylist beside the `tools` allowlist, both resolved through `Preset.admits`. `LEAN_DROPS` removes the journal trio, taking `lean`'s eager tools from 20 to 17; 13 more stay deferred behind `search_tools`. Separately, `auto` sent 3.8B local models to `lean`: a small-tier label plus a local provider prefix (`LOCAL_PROVIDERS`: `ollama:`, `lmstudio:`, `llamacpp:`, `localai:`) now selects `minimal` (`ollama:phi4-mini`), while a label alone does not (`gpt-5-nano`) and Ollama's `:cloud` tier is excluded. Un-deferring now applies only to a preset that closes the tool surface.
- **New: `register_preset` — user-defined prompt profiles beside `full`/`lean`/`minimal`** (`src/zrb/llm/prompt/profile.py`, `docs/configuration/llm-config.md`): adding a preset by dict assignment failed silently three ways — a missing `variant` file fell back to the frontier rulebook, custom presets skipped the rank-1 safety test, and `tools` with `drops` was ignored. `register_preset(name, preset)` raises on an invalid name, a non-`Preset`, or the reserved `auto`, and warns on a variant with no file, a rulebook missing a rank-1 concept, or a section list with no rulebook. The `tools`/`drops` conflict is checked in `Preset.__post_init__`, so `PRESETS[name] = Preset(...)` stays supported. Each axis is optional: `register_preset("no-journal", Preset(drops=...))` is complete.
- **Improvement: the Working Loop gained the step it was missing** (`src/zrb/llm/prompt/markdown/workflow.md`, `workflow.lean.md`, `workflow.minimal.md`): the loop went Understand → Plan → Execute → Verify with no diagnosis gate; `root cause` appeared once across all variants and `hypothesis` never. It is now **Understand → Diagnose → Plan → Execute → Verify → Reply**: `Diagnose` names the cause and its evidence (or says it is treating a symptom), and `Understand` asks for a hypothesis and what would rule it out before searching. `When you don't know` gained a rung: with two defensible options, score them on two or three named criteria and recommend one rather than asking. All three land in every preset; `minimal` gets one line each plus a worked example.
- **Improvement: the rulebook now ends where it also begins** (`src/zrb/llm/prompt/markdown/workflow.md`, `workflow.lean.md`, `workflow.minimal.md`, `test/llm/prompt/test_section_composition.py`): every variant now closes with `Final Reminders`, ~70 tokens restating the six most-violated rules (the slot opencode's kimi and gemini prompts use). The duplication stays inside one section as ADR-0046 allows, and `test_the_closing_recap_restates_only_what_the_body_states` pins each recapped rule to a body statement, per preset.
- **Improvement: `lean` varied how long its rules were, not how they were written** (`src/zrb/llm/prompt/markdown/workflow.lean.md`, `examples.lean.md`, `workflow.md`): `workflow.lean.md` had been `workflow.md` minus 526 words of clauses (41 rules to 42), still in frontier register. It is now written in `minimal`'s register at `full`'s coverage — imperative sentences, decision tables for `When you don't know` and `Recovery`. `examples.lean.md` fell 1,086 → 568 tokens by dropping six demonstrations that restated rules. `lean` composes to 4,038 tokens against `full`'s 4,583; `full` ends 55 tokens heavier after trimming ~350 and adding the three behaviors above.
- **Fix: three declared prompt invariants had nothing enforcing them** (`src/zrb/llm/prompt/markdown/persona.lean.md`, `persona.minimal.md`, `examples.lean.md`, `test/llm/prompt/test_section_composition.py`): the burden ladder summed `persona` and `workflow`, hiding that every preset shipped the same 486-token frontier `persona` (35% of `minimal`'s rule payload, contradicting its reply-length rule); `persona.lean.md` (355 tok) and `persona.minimal.md` (145 tok) now exist. `examples.lean.md` carried three `Wrong:` rules and a verbatim copy of `examples.md`, and demonstrations escaped the budget, leaving `lean` heaviest at 5,061 tokens against `full`'s 4,563. Four guards now enforce rules per section, no rules in `examples`, no verbatim base inside a variant, and composed totals ordered across presets. `examples.lean.md` fell to 1,086 tokens.
- **Fix: injected context named tools the preset never registered** (`src/zrb/llm/prompt/live_context.py`, `test/llm/prompt/test_live_context.py`): `<live-context>` and `<journal-index>` mentioned `AskUserQuestion`, `SearchJournal`, todos and worktree on presets that register none of them. Each tool-naming line now checks `Preset.admits`, and the journal index requires `SearchJournal` to survive the preset, not just `LLM_JOURNAL_ENABLED`. The `Interactive: no` branch no longer spends ~55 tokens per turn forbidding tools that branch already unregisters.

## 2.58.1 (August 9, 2026)

- **Fix: rank-1 safety rules were prohibitions, and prohibitions do not survive a long rulebook** (`src/zrb/llm/prompt/markdown/workflow.md`, `workflow.lean.md`, `test/llm/prompt/test_section_composition.py`, `docs/adr/adr-0049.md`, `AGENTS.md`): across 8 models `full` complied with rank 1 at 44% and `minimal` at 88%, because only `minimal` said what to do instead ("say the file has one") — `full` printed `sk-live-9f3a…` verbatim. Both rules now lead with the substitute behavior ("say that it holds one and carry on"; "describe what you are about to do and wait for a yes"), lifting combined compliance **48% → 69%** (`full` destructive 38% → 69%, `lean` 38% → 62%) with a ~330-char *longer* prompt. `test_rank_one_rules_name_the_substitute_behaviour` pins the form. Injection rules were already affirmative and resistance was at ceiling (zero exfiltration-capable calls in 96 runs).
- **New: tool-schema weight is measured per tool, and three docstring passages are documented as load-bearing** (`llm-experiment/measure.py`, `docs/adr/adr-0058.md`, `AGENTS.md`): effective instructions are the composed prompt (3,929 tok on `full`) plus eager tool schemas (2,482 tok). `measure.py` now reports the latter per preset and tool; `Shell` (539) and `Read` (328) are 35% of it. Three passages that look like deletable methodology — `Shell`'s summarize-first guidance, `Shell`'s "call Shell, not Bash", and `Read`'s batching clause with its System-Context exception — are recorded in ADR-0058 as load-bearing with the test pinning each, plus the caution that a null result from a battery that cannot exercise the hazard is not evidence of no cost.
- **Fix: `Sequence coupled edits` was a rule nothing acted on** (`src/zrb/llm/prompt/markdown/workflow.md`, `workflow.lean.md`, `docs/adr/adr-0049.md`, `llm-experiment/`): `full` (42 rule-lines) did not beat `minimal` (18) even on rules only `full` states (44% vs 41%), but ADR-0049 now records that a cross-preset gap says nothing about one rule; only a within-preset ablation does. Ablated, *completeness-as-checklist* costs `full` 9pp and `lean` 12pp when removed, a *scope* demonstration moves nothing, and `Sequence coupled edits` scored **0% in every preset** (no model in 48 runs looked for the changelog), so it was deleted. `Recovery` (0/7, 1/7, 2/7) is the next candidate once a runtime guard can replace it.
- **New: the prompt design is measured instead of argued** (`llm-experiment/`, `docs/adr/adr-0045.md`, `adr-0046.md`, `adr-0049.md`, `adr-0058.md`, `AGENTS.md`): `llm-experiment/` ran 928 runs over 8 models from 6 families, composing prompt arms through the real `PromptManager` with deterministic scorers over a mock repo. Findings: no model×preset interaction; method adherence flat across presets (79/80/80%) while rank-1 safety ran 44/53/88% before the fix above; `full` is four times `minimal`'s size for no measurable method gain; dropping `persona` keeps method flat and lifts safety 44% → 56%; injection resistance is at ceiling, so that probe measures disclosure; and no preset follows the Recovery rule (0/7, 1/7, 2/7 on an unfixable build).
- **Fix: primacy and recency were load-bearing justifications with nothing behind them** (`docs/adr/adr-0046.md`, `adr-0045.md`, `AGENTS.md`): one checkable rule placed at the start, middle and end of an otherwise identical prompt (8 models, n=32 each) scored **100% / 97% / 94%** — no position effect, and the weak trend runs against recency. Placement effects in the literature are model-specific in direction (arXiv:2607.19257), and lost-in-the-middle (arXiv:2307.03172) measures fact retrieval, not rule adherence. `Priority Order` and `Final Reminders` stay on structural grounds (a precedence ladder must precede what it ranks; the recap covers the most-violated rules). IFScale's density finding still stands, now corroborated by three further results; only its primacy claim is dropped.
- **Fix: family-variant avoidance was argued rather than measured** (`docs/adr/adr-0049.md`, `AGENTS.md`): opencode's `anthropic.txt` / `gemini.txt` / `kimi.txt` against 8 models showed no family advantage (75% / 75% / 67% vs zrb's 74%), and `kimi-k2.6` scored worst on its own file. zrb still ships no family variants, but the reason changed: format sensitivity is real and idiosyncratic (FormatSpread, arXiv:2310.11324); opencode's forks are simply **unmeasured** — empty commit bodies, no eval harness, copied vendor prompts, two never imported. The earlier "weaker family → longer prompt" reading is withdrawn as confounded by which harness was copied.
- **Fix: the prompt and tool-size figures in the docs were folklore** (`llm-experiment/measure.py`, `docs/adr/adr-0049.md`, `adr-0058.md`, `src/zrb/llm/prompt/profile.py`, `src/zrb/llm/common_tools.py`, `src/zrb/config/mixins/llm_prompt.py`, `AGENTS.md`): hand-derived figures had drifted — `LEAN_DROPS` was quoted as 694 and "~920 tokens, ~18%"; measured 437 tokens (18%). Eager tool schemas were overstated by ~55% (full 3,840 → **2,482**, lean 3,146 → **2,045**, minimal 2,339 → **1,544**); the counts (20/17/10) were right. `common_tools.py`'s "lean keeps thirty-three" is now explained (17 eager + 16 deferred) and `llm_prompt.py`'s "all 21 tools" fixed. `measure.py` regenerates the numbers.
- **Fix: `PRESET_BUDGETS` measured the machine, not the prompt** (`test/llm/prompt/test_section_composition.py`, `AGENTS.md`): the ceiling was asserted against the *composed* prompt, which embeds `system_context` (OS, cwd, detected tools) and `project_context` (every `AGENTS.md`/`README.md` up the parent chain), so it moved with the working directory and a real regression could hide behind a shallower checkout. It now budgets the file-backed sections: full 20,500 / lean 17,500 / minimal 5,500 against 17,105 / 14,358 / 4,366 shipped.
- **Fix: `test_lean_drops_only_tools_that_are_actually_registered` asserted nothing** (`test/llm/prompt/test_section_composition.py`, `test/llm/prompt/test_profile.py`): it exempted factory-built names, and all three `LEAN_DROPS` entries are factory-built, so it was vacuously true; it now resolves the factories. `test_every_requires_block_is_closed` now also covers `workflow.lean` and `workflow.minimal`, and the runtime safety-floor warning test checks all three rank-1 concepts instead of two.
