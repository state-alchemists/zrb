## 2.59.0 (August 10, 2026)

**Breaking.** The `lean` profile is removed and `full` is renamed `capable`. See [Upgrading to 2.59.0](../../advanced-topics/upgrading-guide.md#upgrading-to-2590).

- **Breaking: `lean` profile removed; profiles are now `minimal`, `standard`, `capable`** (`src/zrb/llm/prompt/profile.py`, `src/zrb/llm/prompt/markdown/`): four profiles become three. `lean` and its variant files (`persona.lean.md`, `workflow.lean.md`, `examples.lean.md`) are deleted. `full` is renamed `capable`; a new `standard` fills the middle rung but is not the default — `auto` remains the default and the `auto` ladder is unchanged (≤4B → `minimal`, ≤14B → `standard`, above → `capable`). `Preset` — the three-axis dataclass binding sections, phrasing variants, and tool surface — is removed from the public API, as is `register_preset`. Profiles now control exactly two things: which `profile.{name}.md` lands, and whether delegate (sub-agent) tools register.

- **Improvement: prompt simplified to seven fixed sections** (`src/zrb/llm/prompt/markdown/`, `src/zrb/llm/prompt/manager.py`, `src/zrb/config/mixins/llm_prompt.py`, `docs/adr/adr-0044.md`): `persona`, `principle`, `workflow`, `example`, `profile`, `system_context`, `project_context`. No more config-positioned custom sections, no per-profile phrasing variants, no `<!--requires:-->` conditional markers, no section switching. The `profile` section is the only one that resolves per-profile (`profile.{name}.md`); the other four rule sections are shared. The prompt is now plain markdown — ADR-0046.

- **Improvement: persona, principle, and workflow rewritten** (`src/zrb/llm/prompt/markdown/persona.md`, `principle.md`, `workflow.md`): persona condensed from 16 lines to 5 — identity plus two imperatives. New `principle` section (8 lines) states four meta-rules: establish facts, work within scope, protect the user's work, do not invent. Workflow simplified from a 163-line Operating Rules with Priority Order, Turn Sequence, Working Loop, Verify, and Recovery to 25 lines of concrete procedure plus the Methodology and Skill Activation block whose content is injected by `build_skill_replacements`. The elaborate rulebook was replaced by the principle that runtime policies and tool docstrings enforce what they can, leaving the prompt to carry general judgment (ADR-0045). `persona.minimal.md` and `workflow.minimal.md` are deleted — `minimal` now uses the same sections as every other profile, differentiated only by `profile.minimal.md`.

- **Improvement: the prompt now makes concurrency, multi-methodology work, and journal hand-off explicit** (`src/zrb/llm/prompt/markdown/workflow.md`, `profile.*.md`): independent tool calls — including independent `ActivateSkill` calls — are batched by default unless System Context explicitly names the model's one-call override; matching several core methodologies or skills means activate all of them. A journal write is now explicitly recordkeeping rather than the final response, so the model must answer the user after `LogActivity` or `WriteJournalNote`. The rendered label is now **Operating Profile**, and the three profile files give concrete operating guidance; `minimal` explicitly says sub-agent delegation is unavailable while keeping skill activation available.

- **Improvement: examples consolidated into one shared file** (`src/zrb/llm/prompt/markdown/example.md`, `examples.md` deleted, `examples.lean.md` deleted): three demonstrations — a test fix, a library-change question, a design-and-document request — covering stance, research, and multi-methodology activation. Per-profile example variants are gone; demonstrations are the same for every profile.

- **Removed: `llm-experiment/` directory** — the 928-run prompt evaluation harness is deleted. Its findings are recorded in the ADRs, and the measurement acted on is in the prompt changes above.

- **Documentation: ADRs rewritten for the simplified prompt system** (`docs/adr/adr-0044.md`, `adr-0045.md`, `adr-0046.md`, `adr-0049.md`): ADR-0044 now records seven fixed sections rather than config-positioned custom ones. ADR-0045 records the "put each instruction at the layer that can enforce it" principle rather than a detailed rule-sorting exercise. ADR-0046 records that prompt files are plain markdown. ADR-0049 records three explicit profiles with one optional auto ladder. ADR-0051 is deleted — the capability/profile registry split it argued for became moot when `Preset` was removed and the two axes no longer shared a shape worth merging.

- **Fix: `Shell` tool background process monitoring** (`src/zrb/llm/tool/shell.py`, `shell_background.py`, `src/zrb/util/cmd/command.py`): background shell processes now correctly report their PID and status.

- **Fix: LSP server registration** (`src/zrb/llm/lsp/server.py`): LSP server initialisation no longer fails on missing optional dependencies.

- **Fix: regression in chat task building** (`src/zrb/builtin/llm/chat.py`, `src/zrb/llm/task/chat/building.py`, `chat/execution.py`, `chat/state.py`): profile resolution and delegate-tool gating corrected after the profile simplification.

- **Fix: theme config** (`src/zrb/config/theme.py`): a stray reference to a retired config path.

- **Fix: `Config` mixin defaults** (`src/zrb/config/config.py`, `src/zrb/config/mixins/llm_prompt.py`): `DEFAULT_LLM_PROFILE` now `standard`; `DEFAULT_LLM_INCLUDE_SECTIONS` now `persona,principle,workflow,example,profile,system_context,project_context`.

- **Documentation: `AGENTS.md` updated** (`AGENTS.md`): the LLM Prompt System section reflects the seven-section composition, the new profile structure, and the plain-markdown convention.
