## 2.62.0 (August 13, 2026)

- **Feature: LaTeX math renders as Unicode in assistant markdown** (`src/zrb/util/cli/latex_math.py`, `src/zrb/util/cli/markdown.py`, `src/zrb/config/mixins/llm_ui_styles.py`, `pyproject.toml`): `render_markdown` converts `$...$`/`$$...$$` spans and ` ```latex `/` ```tex ` fences to Unicode, including super/subscripts (`x^2` → `x²`), gated by the new `LLM_UI_ENABLE_MARKDOWN_MATH` toggle (default on). Code blocks, inline code, ambiguous prose like "$5 and $10" and markdown's `_italic_` are left alone, and unparseable LaTeX falls back to its source (a latex fence stays a highlighted fence). `pylatexenc` is a new core dependency. See ADR-0079.
- **Improvement: the assistant is now shown the expected math syntax** (`src/zrb/llm/prompt/markdown/example.md`): a new example teaches the model to write math between `$...$`/`$$...$$` rather than inside a fenced ` ```latex ` code block, since only the former renders as math in the terminal.
- **Feature: Mermaid diagrams render as Unicode art in assistant markdown** (`src/zrb/util/cli/mermaid_diagram.py`, `src/zrb/util/cli/markdown.py`, `src/zrb/config/mixins/llm_ui_styles.py`, `pyproject.toml`): ` ```mermaid `/` ```mmd ` fences render as Unicode box-drawing diagrams in-process, gated by the new `LLM_UI_ENABLE_MARKDOWN_MERMAID` toggle (default on); an unparseable fence falls back to the original. `termaid` is a new core dependency. PlantUML was deferred: no pure-Python, no-subprocess, no-network option exists. See ADR-0080.
- **Improvement: the assistant is now shown that Mermaid diagrams render** (`src/zrb/llm/prompt/markdown/example.md`): a new example encourages a fenced ` ```mermaid ` block whenever a diagram clarifies structure or flow better than prose, now that it renders as Unicode art instead of raw text.
- **Fix: a Mermaid diagram no longer gets corrupted across a terminal resize** (`src/zrb/util/cli/mermaid_diagram.py`, `src/zrb/util/cli/markdown.py`): a diagram wider than the console was word-wrapped mid-line by Rich, splitting box-drawing characters, most visibly after narrowing the terminal. `convert_mermaid_to_art` now shrinks the diagram to the console width first. See ADR-0080.
- **Improvement: the assistant is now shown to declare a shared Mermaid edge only once** (`src/zrb/llm/prompt/markdown/example.md`): a new example steers away from repeating a parent edge as a prefix for every child in a chain (`P --> G --> G1`, `P --> G --> G2`, ...) -- termaid doesn't dedupe identical edges, so the repeats render as separate, overlapping, tangled arrows into the same node. Declaring the shared edge once and chaining each child separately renders cleanly.
- **Fix: web chat now renders math and diagrams at all** (`src/zrb/llm/task/llm_task.py`, `src/zrb/llm/task/chat/running.py`, `src/zrb/runner/chat/http_ui.py`, `src/zrb/runner/web_route/chat_page/`, `src/zrb/runner/web_route/static/resources/`): the web chat's per-message loop never finalized its output, so `$...$` LaTeX and ` ```mermaid ` fences always showed as raw source. Every attached UI is now finalized with `append_markdown` (new `LLMTask.get_uis()`), and the browser renders the raw markdown with `marked`, DOMPurify, KaTeX (real math typesetting, including `\frac`) and `mermaid.min.js` (SVG diagrams). Reopened sessions render the same way. See ADR-0081.

## 2.62.2 (August 14, 2026)

_Cumulative summary of the 2.62.1–2.62.2 patch line._

- **Feature: attachments are capped and content-sniffed before they reach the model** (`src/zrb/llm/util/attachment.py`, `src/zrb/config/mixins/llm_limits.py`, `src/zrb/llm/ui/base/conversation_commands.py`, `src/zrb/runner/chat/chat_api_route.py`, `examples/chat-telegram/zrb_init.py`): the CLI's `/attach`, the web chat upload endpoint and the Telegram example reject a file over the new `LLM_MAX_ATTACHMENT_BYTES` (default 20MB, `0`/negative disables) before reading it, and check its magic bytes against the declared media type (`check_attachment_bytes`), so a renamed file can't masquerade as an image or PDF.
- **Feature: web chat and the `chat-telegram` example accept file attachments** (`src/zrb/runner/chat/{chat_api_route,chat_session_manager,chat_session_runner}.py`, `src/zrb/runner/web_route/chat_page/{chat.js,chat.css,view.html}`, `examples/chat-telegram/{zrb_init.py,README.md}`): a new `POST /api/v1/chat/sessions/{id}/attachments` endpoint saves a checked upload to a per-session temp dir; the chat page gained an attach button, pending-attachment chips and per-message attachment display, and queued messages carry `{message, attachments}` end to end. A Telegram photo or document (with optional caption) is downloaded, checked the same way, and queued as a pending attachment for the turn.
- **Feature: replayed and web-displayed history separates auto-appended live context from what the user typed** (`src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/ui/base/replay.py`, `src/zrb/runner/chat/chat_session_manager.py`, `src/zrb/runner/web_route/chat_page/{chat.js,chat.css}`): a new `split_live_context` pulls the trailing `<live-context>` block off a stored user message, and both the CLI replay and the web chat render it as de-emphasised metadata outside the user's bubble.
- **Feature: model capability tracking covers documents and more models** (`src/zrb/llm/util/capabilities.py`): `ModelCapabilities` gained `supports_document_input` (PDF/docx/xlsx/doc/xls as opaque binary; plain-text formats are unaffected), tracking the image-support pattern list. Image support added for `claude-fable-5`, `claude-mythos`, `claude-opus-5`, `claude-sonnet-5`, `grok-3`/`grok-4` (with a `grok-3-mini` deny override), `glm-4.5v`/`glm-4.6v`/`glm-5v`, `moonshot-v1-*-vision` and `computer-use`; audio support for `whisper`.
- **Refactor: Mermaid authoring rules move out of the always-on prompt into the `core-diagram` core skill** (`src/zrb/llm_plugin/core_skills/core-diagram/`, `src/zrb/llm/prompt/markdown/example.md`, ADR-0044, ADR-0053, ADR-0054, ADR-0080): 2.62.0's shared-edge rule and the termaid hazards now live in a skill loaded only when the model is about to emit a `mermaid` fence, instead of `example.md` (paid for on every turn); `example.md` keeps only the general "reach for a mermaid fence" example. Per-family syntax sits in on-demand companions, cutting a sequence diagram's read from 306 lines to 162. It first shipped as the optional `skills/mermaid-diagrams` and now loads regardless of `LLM_ENABLE_BUILTIN_SKILLS`.
- **Documentation: termaid's authoring hazards mapped from parser source** (ADR-0080): ADR-0080 now tabulates termaid's silent failures, each confirmed against rendered output: unsupported diagram types (`requirementDiagram`, `sankey`, `C4*`, `radar`, `zenuml`) render as boxes of their own source; inline edge labels are unsafe in every arrow style (use `-->|t|`, `-.->|t|`, `==>|t|`); an `erDiagram` relationship without `: label` empties the whole diagram; plus traps around `<br/>`, `sequenceDiagram` `title`/`box`, and multi-line state notes. Unrecognized statements land in a parser `warnings` list nothing displays.
