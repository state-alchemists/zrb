## 2.55.0 (August 5, 2026)

A benchmark run of 156 cells across five models (`gpt-4o-mini`, `gemini-2.5-flash`, `gemini-3.5-flash`, `deepseek-v4-flash`, `gemma4:31b-cloud`) produced ten non-excellent outcomes. Every one traced to a rule the prompt already stated and the model did not follow, or to a harness defect no rule could reach. Per ADR-0045's ladder, the fixes go to the runtime where the runtime can hold them.

- **Reverted: the runtime anti-loop guards do not ship** (`command_repetition.py`, `file_freshness.py`, `shell.py`, `file_write.py`, `file_edit.py`, `file_read.py`, `post_write_check.py`, `llm_limits.py`): the write-freshness refusal, the blind-edit-streak nudge, and the repeated-outcome counter built in this window were removed before release. An injected instruction is the weakest lever for the model that needs it (an escalated "stop and report" was ignored 22 times), the stale-write refusal carried the most cross-tool state in the tool layer, and the components that measurably made models worse were already reverted. The prompt's Recovery ladder stands alone again. Lessons kept: a tool policy is an approval chain that never sees a result; a synchronous tool cannot keep state in a `ContextVar`; an injected instruction must be bounded and never regenerate its own input.
- **Reverted: `post_write_check` no longer tells the model to fall back to a whole-file `Write`** (`src/zrb/llm/tool/post_write_check.py`): the 2.52.0 advice to rewrite a file that failed twice is gone — a small model's whole-file rewrite regenerates the diagnostic that issued the instruction. The guidance now asks for a re-read and *one targeted fix*, naming the other file when the error points outside it.
- **Fix: an unbounded shell command spent minutes being printed and was killed by its own timeout** (`src/zrb/llm/tool/shell.py`, `src/zrb/config/mixins/llm_limits.py`, `docs/configuration/llm-config.md`): shell output was echoed and held in RAM line by line, truncated only at the end. An unscoped `git diff` over ~2,948 dirty changes produced ~139MB per trial (3,777 copies of the zrb system prompt from earlier history JSONs); printing ~1.4M lines outran the 120s timeout, and those cells ran ~3× slower while still scoring EXCELLENT. Capture now has three budgets: tail-biased retention capped by `LLM_MAX_OUTPUT_CHARS`, console echo capped by the new `LLM_MAX_CONSOLE_OUTPUT_CHARS` (default 1,000,000), and a spill file for the full output, which is still preserved.
- **Fix: a command killed mid-write was diagnosed as a hung process** (`src/zrb/llm/tool/shell.py`): every timeout reported "the process is still running in the background… pass `-y` or `CI=true`", sending the model after an already-dead process. A timeout that also truncated now reports the character count, says the command was writing rather than waiting on input, and suggests scoping it, a summarizing flag, `head`, or redirect-and-Grep. A quiet timeout keeps the original wording. The `lock` and `permission denied` hints, previously unreachable behind the timeout branch, work again.
- **Fix: the parallel-tool-call affordance was unreachable code** (`src/zrb/llm/prompt/system_context.py`, `src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm/tool/file_read.py`, ADR-0038): the capability check is a deny-list that never returns `True`, so System Context never rendered the "supports batching" line that `workflow.md` gated batching on, and no model batched. Round-trips drive wall clock: `gpt-4o-mini` ran the 44-site migration at 7.35 calls/response in 168s and at 2.62 in 434s; `gemini-3.5-flash` averaged 1.04 over 583 responses. Batching is now the unconditional default; System Context emits only the negative override, which outranks the workflow rule and tool descriptions. `read_file`'s docstring repeats the rule and prefers one wide range over repeated 20-line slices.
- **Docs: "does not support parallel tool calls" is three different things** (`src/zrb/llm/util/capabilities.py`, `src/zrb/llm/agent/common.py`): `_NO_PARALLEL_TOOL_CALLS` is only for models that **malform** parallel calls (two calls concatenated and lost). A model whose provider **rejects the parameter** (OpenAI's o-series, kimi-k2.5 behind NVIDIA NIM) must stay off it, since listing it would send the argument that 400s every request; a model that **never emits more than one call** (gpt-oss via Ollama, most small local models) needs nothing.
- **Improvement: two verification instruments that running the code cannot provide** (`src/zrb/llm/prompt/markdown/workflow.md`): two models ran their code and still failed — `gemini-3.5-flash` shipped `DB_PASS = os.getenv("DB_PASS", "password123")`, which no execution can catch, and `gemma4:31b` wrote a module-level `asyncio.Lock()` that passes the first `asyncio.run()` and fails every later one. The Verify gate now names a grep check for any remove/replace/stop-using requirement, and a double-run check for state that survives a run (a client bound to a dead loop, a cache, a temp file, a migration, an import-time global).
- **Improvement: `core-design` no longer swallows the document** (`src/zrb/llm_plugin/core_skills/core-writing/SKILL.md`, `core-design/SKILL.md`): both descriptions read as a partition, so an ADR went to `core-design` alone. On the ADR challenge the trial that also activated `core-writing` scored 1.0; the two that did not scored 0.875 and 0.5 (one emitted an ADR with no headings). `core-writing` now names the case (ADR, RFC, design doc, postmortem, migration guide), and `core-design` says it covers the thinking, not the document.
- **Fix: re-writing a journal note destroyed the backlinks other notes had added** (`src/zrb/llm/tool/journal_write.py`, ADR-0055): `write_journal_note` rebuilt the whole file from its arguments, so updating note A dropped the `## Backlinks` entries other notes had written into it (the `missing-backlink` half-edge `journal-lint.py` used to catch); `## Related` had the mirror problem. Both blocks are now merged rather than rebuilt, so a link is only ever added.
- **Fix: a cancelled response killed the `MultiUI` message loop** (`src/zrb/llm/ui/multi_ui.py`): `_process_messages_loop` re-raised every `CancelledError`, so cancelling one response stopped all further message processing; the earlier behavior of swallowing them all instead discarded a shutdown cancel. It now tells the two apart with `current_task().cancelling()`, as `base/ui.py` already did. Latent, not observed — nothing cancels `MultiUI._running_llm_task` today.
- **Improvement: `write_todos` binds completion to verification** (`src/zrb/llm/tool/plan.py`): the docstring is read at exactly the moment a model claims something is done, so it now says an item reaches `completed` only once its work is done *and* verified — never on intent, never because the edit landed. An item awaiting verification or blocked stays `in_progress`, the latter gaining a follow-up naming the blocker.
- **Docs: corrected stale references after the parallel-tool-call and journal changes** (`AGENTS.md`, `docs/technical-specs/llm-context.md`): `system_context` is now described as announcing only the no-batching exception (ADR-0038). The claim that `SearchJournal`'s description warns that a missing index block does not mean an empty journal was corrected: nothing tells the model that any more, a known gap that matters only when `LLM_JOURNAL_INDEX_MAX_CHARS` is `0` while the journal tools stay registered.
- **Improvement: the Working Loop stopped being a per-turn classification problem** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm/prompt/markdown/examples.mini.md`): the four-row routing table (`conversational` / `inquiry` / two directive rows) with blurry soft rows is replaced by three stances defined by the deliverable — an **answer** (reply from what you know), a **proposal** (investigate to a verdict, await approval before any write), a **change** (autonomous). `Frame the turn` names the deliverable in those words. The "can't yet specify" case and the `EnterPlanMode` trigger keep their prose; the "prefer conversational" tie-break and the `Loop steps before Verify` column are gone. `examples.mini.md` is rewritten to the three stances.
- **Improvement: three redundant rules trimmed out of `workflow.md`** (`src/zrb/llm/prompt/markdown/workflow.md`): `Turn Sequence` dropped `First look`, and *"Only step 1 may end the turn"* became *"Within this sequence"*, since it contradicted the ask-one-question rule. `Verify Before Done` lost its `Evidence` bullet (already in `persona`'s `Verify before you assert` / `Cite inline`), keeping only artifact checks. The intro now states the tie-break "brevity shapes the report, never the check". `Tool usage` leads with the batching rule, and the stall line in *When you don't know* is compressed since `Recovery` owns that ladder.

A follow-up run widened the grid to 180 cells and 12 challenges. Twelve timeouts and eight failures; five cells traced to the harness rather than the model, two of them to defects a mock could never have caught.

- **Fix: the shell PID-tracking wrapper corrupted any command whose last line could not absorb a trailing `; }`** (`src/zrb/llm/tool/shell.py`): the wrapper was spliced onto the command's last line, which broke heredocs (`EOF ; }` is not a terminator), trailing comments, a trailing `;`, and, on bash and `sh`, a trailing newline — six of thirteen tested shapes. The model saw `zsh:13: parse error near '\n'` with no `[SYSTEM SUGGESTION]`; 13 such errors hit 11 of 180 cells and killed one `deepseek-v4-flash` trial. Every wrapper token now sits on its own line, and an empty command skips the wrapper. The regression test runs real `bash`/`sh`/default shells.
- **Fix: `LLM_REQUEST_TIMEOUT` was declared, documented, and never applied to an agent** (`src/zrb/llm/agent/common.py`, `docs/configuration/llm-config.md`): only the web session runner read it, so `zrb chat` model requests had no deadline and a provider that stopped sending blocked forever — two cells burned their full 600s with no output. `create_agent` now applies it to the main agent, sub-agents and programmatic `LLMTask`; a caller-supplied `timeout` wins and `0` disables it.
- **Fix: nothing could stop a run that had stopped converging** (`src/zrb/llm/agent/run/runner.py`, `src/zrb/config/mixins/llm_limits.py`, `docs/configuration/llm-config.md`): runs were explicitly uncapped, and `gpt-4o-mini` spent one cell on 343 tool calls, re-editing the same nine files 8–9× each. The new `ZRB_LLM_MAX_REQUEST_PER_RUN` (default 300; the largest legitimate run in the grid was 79 tool calls) halts with a message naming the knob, does not consume the retry budget, and preserves the partial history.
- **Fix: "batch twelve edits" read as "describe twelve edits"** (`src/zrb/llm/prompt/markdown/workflow.md`, `examples.mini.md`): `gemini-2.5-flash` solved the 44-site migration and then printed the edits into its reply as 9,193 tokens of `{path, old_text, new_text}` objects, with zero `Edit` calls. `Edit` stays single-replacement; `Tool usage` now states a batch is N tool calls, never one payload describing them, and `examples.mini.md` demonstrates it.
- **Fix: a change that never reached disk** (`src/zrb/llm/prompt/markdown/examples.mini.md`): `gpt-4o-mini` failed all three `refactor` trials by reading `pipeline.py` and pasting the refactor into its reply; the file never changed. *Where the deliverable goes* already stated the rule, but the `mini`-profile model needed a worked demonstration, which `examples.mini.md` now gives.
- **Improvement: `Shell` and `Bash` say they are for running things, not for touching files** (`src/zrb/llm/tool/shell.py`, `src/zrb/llm/tool/bash.py`, `src/zrb/llm/prompt/markdown/workflow.md`): per ADR-0045 the routing rule moved from `workflow`'s `Tool usage` into both docstrings, which name the file tools (`Read`/`Write`/`Edit`, `Grep`/`Glob`/`LS`, `RM`/`MV`) and the shell idioms that bypass post-write diagnostics, path validation and per-path approval (`cat`, `head`, `sed -i`, `find`, `test -f`, `rm`, `mv`, `>` into a file). `Bash` carries its own copy because Claude skills call it by name.
- **Fix: `ActivateSkill`'s description pointed at a prompt section** (`src/zrb/llm/tool/skill.py`, `AGENTS.md`): it said to use a name "exactly as listed under Core Skills / Available Skills", but those sections can be toggled off while the tool ships regardless. The description now describes the argument, and an unknown or user-only name returns the activatable names, mirroring `agent_not_found_message` for delegation. AGENTS.md gains the invariant.
- **Fix: the batch-by-default rule pointed at a section it might not be given** (`src/zrb/llm/prompt/markdown/workflow.md`, `test/llm/prompt/test_section_composition.py`): "Unless System Context says this model cannot batch" lacked a `<!--requires:system_context-->` guard, so a trimmed `LLM_INCLUDE_SECTIONS` cited a missing section (failing safe: the model batches). It is now guarded, and `system_context` joined `OWNED_VOCABULARY` so the subset walk asserts it.
- **Improvement: the "Available Skills" heading disappears with its list** (`src/zrb/llm/prompt/claude.py`): every built-in utility skill is `disable-model-invocation`, so a stock install rendered the heading over "(none registered)" plus five lines of matching guidance. The heading now lives in `AVAILABLE_SKILLS` and both vanish together.
- **Improvement: `workflow.md` trimmed by 10%** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm/tool/delegate.py`): 14,213 → 12,717 chars, and the composed default prompt 21,068 → 19,339, while adding the batch-is-N-calls rule and a verification bound. Cut: the file-tools routing rule (now in `Shell`/`Bash`); "Read a tool's own description before its first use"; the destructive-action list the approval cascade already covers; the sub-agent envelope contract duplicated in `DelegateToAgent`'s docstring; `Project Documentation`'s restated trigger; and the standalone `Stop` heading, folded into `Recovery`, whose six bullets became four. Every `OWNED_VOCABULARY` term survives, and the 7-subset walk and 24,000-char budget still hold.
- **Improvement: verification has a finish line** (`src/zrb/llm/prompt/markdown/workflow.md`): `deepseek-v4-flash` finished `refactor` correctly, then went hunting for the benchmark's validator to self-grade and died on the heredoc bug above. `Verify Before Done` now says the request defines the finish line: check what it asked for, then stop. (The opposite failure appeared too: `gemma4:31b` ignored "Run it twice" and failed validator trials 2–6.)

## 2.55.1 (August 6, 2026)

- **Refactor: `hook_creators.py` split into three modules** (`src/zrb/llm/hook/creator.py`, `src/zrb/llm/hook/process_io.py`, `src/zrb/llm/hook/process_kill.py`, `src/zrb/llm/hook/manager.py`): the 739-line module mixed the three `create_*_hook` factories with ~310 lines of POSIX subprocess plumbing only the command hook needs. The read side is now `process_io.read_hook_output` / `run_detached`, the kill side `process_kill.read_process_group` / `kill_process_tree`, both public; the factories stay in `creator.py`. Flat siblings match the `manager.py` + `manager_<aspect>.py` shape and drop the `hook/hook_*` stutter. No behavior change.
- **Refactor: `command_hook` reduced from 256 lines to 72** (`src/zrb/llm/hook/creator.py`): pre-spawn work (env, stdin payload, cwd) and exit-code interpretation moved into helpers, leaving spawn → capture-pgid → read-with-timeout as the linear core. The exit-2 and exit-0 branches keep separate stdout parsers on purpose: only exit 2 distinguishes a JSON control object from an empty dict, so merging them would change what `echo '{}'; exit 2` reports as its block reason.
- **Refactor: the prompt and agent hooks stopped duplicating each other** (`src/zrb/llm/hook/creator.py`): `create_prompt_hook` and `create_agent_hook` were 58 lines each sharing roughly 40 — model resolution, the JSON-output parse and the error handler were verbatim identical, comments included. Both are now eight lines over the shared `_run_llm_hook`, differing only in where their two prompts come from (`_render_prompt_template` for placeholder substitution, `_agent_hook_input` for the event-payload fallback chain).
- **Tests: the hook tree-kill safety test never exercised the process-group guard** (`test/llm/hook/test_process_kill.py`): its two cases passed the same value, so the `killpg` case never reached the group logic. It is now two tests, the group case patching `os.getpgid`. Publishing the process helpers also retired a private-member import of `_kill_process_tree`.
- **Tests: `test_hook_creators.py` split by feature group** (`test/llm/hook/test_creator.py`, `test_creator_subprocess.py`, `test_creator_llm.py`, `test_process_io.py`, `test_process_kill.py`): the 922-line file was split with coverage preserved (`creator.py` at 100%) and then raised — `process_kill.py` 75% → 94%, `process_io.py` 87% → 90% via real `os.pipe()` tests. Only Windows-only branches and EAGAIN races remain uncovered.
- **Docs: the hooks row of the chat-lifecycle file map** (`docs/advanced-topics/llm-chat-lifecycle.md`): names `creator.py` and `process_{io,kill}.py` in place of `hook_creators.py`. Historical `hook_creators.py` references in `changelog-v2/` are left as written — they record what shipped at the time.
