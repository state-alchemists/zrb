## 2.57.0 (August 8, 2026)

- **Security: `aiohttp` bumped to `>=3.14.3` in the `xai` and `voyageai` extras** (`pyproject.toml`, `poetry.lock`): three advisories land below the previous `>=3.14.1` floor — GHSA-cq5v-8q36-5273 / CVE-2026-69244 (out-of-bounds heap read in the C response parser while formatting the error for a malformed chunked response, so a hostile or merely broken server can DoS the client), GHSA-mfx4-hv73-q22v / CVE-2026-69243 (HTTP request smuggling via WebSocket upgrade), and GHSA-mq44-7p77-q5h7 / CVE-2026-59881 (the WebSocket client accepts compressed frames without negotiated `permessage-deflate`). 3.14.3 covers all three. The lock also carried a stale second `aiohttp` entry pinned at 3.14.1 for the `rag`/`xai` markers, which a full re-resolve cleared — `rag` reaches aiohttp transitively through chromadb and was never covered by the direct pin.
- **Chore: pydantic-ai upgraded from 2.8 to 2.27** (`pyproject.toml`, `poetry.lock`): nineteen minor releases, and none of them breaking — pydantic-ai's V2 stability policy holds no-breaking-changes until V3, so the whole suite passed on 2.27.0 before a line of zrb changed. What did move is the floor underneath: `openai` is now pinned `>=2.45.0` (was `>=2.29.0`). That one is not cosmetic — `OpenAIChatModel._completions_create` passes `prompt_cache_options=` to `chat.completions.create()` on every call, and the parameter only exists from openai 2.45.0, so an older SDK raises `TypeError: got an unexpected keyword argument 'prompt_cache_options'` on *every* request while a fully-mocked test suite stays green. `test_the_installed_openai_sdk_accepts_what_pydantic_ai_sends` now pins that coupling. Extras were realigned to pydantic-ai's own floors as well: `mistralai>=2.4.2` (was `>=2.0.0`, below the `prompt_cache_key`/`reasoning_effort` parameters), `xai-sdk>=1.14.0` (was `>=1.12.2`), and the `huggingface` extra picks up the `hf-xet<1.5.0` cap that `huggingface_hub` 1.3.x needs.
- **Documentation: the supported-provider table listed 6 of the 30 providers zrb can reach** (`docs/configuration/llm-config.md`): model routing goes through `infer_provider_class`, so every provider pydantic-ai ships has always worked — the table just never said so, and readers had no way to learn that OpenRouter, Z.ai, Cerebras, Together, Fireworks, Moonshot, Alibaba, Azure, Vercel, Snowflake and the rest need no extra at all, because `openai` is a core dependency and they all speak its wire protocol. The list is now split by what it costs to use one: no-extra providers with their credential env vars, then the ten that need a vendor SDK with the matching `zrb[...]` extra.
- **Improvement: `Retry-After` is honored on errors pydantic-ai wraps** (`src/zrb/llm/agent/run/error_classifier.py`): `get_retry_wait` read the header off `exc.response`, which only exists on a raw provider-SDK exception. pydantic-ai hands back `ModelHTTPError`, so a 429 that asked for a specific wait got exponential backoff instead. It now reads `ModelHTTPError.retry_after` first — which also parses the HTTP-date form of the header, where the existing path's bare `float()` gives up — and keeps the `.response` path for unwrapped exceptions.
- **Fix: the `content: null` patch reintroduced the 400 it exists to prevent, for empty responses** (`src/zrb/llm/agent/run/openai_patch.py`, `test/llm/agent/run/test_openai_patch.py`): upstream returns `None` from `_into_message_param` when a `ModelResponse` has neither text nor tool calls, so no assistant message is emitted at all. zrb's override did not reproduce that guard and returned `{"role": "assistant", "content": null}` instead — an assistant message with a null `content` and no `tool_calls`, which the Chat Completions API rejects. The guard is now reproduced verbatim. Re-verified against 2.27.0 that the patch is still needed at all: the upstream method still writes `content = None` beside `tool_calls`, and no model profile flag disables it. The tests drive the real `OpenAIChatModel._MapModelResponseContext` rather than a `MagicMock` of it, which would have kept passing through an upstream rename.
- **Improvement: `/model` completion reads the public model list** (`src/zrb/llm/app/completion/completer.py`): `get_args(KnownModelName.__value__)` unwrapped a `TypeAliasType` internal, so any change to the alias's shape would silently drop completion to a nine-entry hardcoded fallback. `known_model_names()` is the supported accessor and returns all 650.
- **Documentation: the history-sanitization layers were re-audited against 2.27** (`docs/advanced-topics/maintainer-guide.md`): every mitigation is still load-bearing, and the guide now records why per layer, so the next bump starts from a verdict rather than a re-investigation. The short version: these work around *provider* behavior, not pydantic-ai behavior, so a framework upgrade rarely retires one — and the two orphan-related layers exist because zrb's own summarizer splits turns.
- **Feature: `ZRB_LLM_PROFILE` selects a preset over three axes, and `minimal` serves ~3B models** (`src/zrb/llm/prompt/profile.py`, `src/zrb/llm/prompt/manager.py`, `src/zrb/llm/common_tools.py`, `src/zrb/config/mixins/llm_prompt.py`, `src/zrb/llm/prompt/markdown/workflow.minimal.md`, `docs/adr/adr-0049.md`): a profile used to pick per-section phrasing only, which left the largest item on every request — the registered tools' docstrings and schemas, ~4,000 tokens — outside any knob. A profile is now a `Preset`: a named binding of which sections compose, how they are phrased, and which tools register. `minimal` composes `persona`/`workflow`/`system_context` through `workflow.minimal.md` over a ten-tool surface (`MINIMAL_TOOLS`), taking a session's preamble from ~9,000 tokens to ~3,500 — inside a ~3B model's effective instruction-adherence window, at the documented cost of no skills, sub-agents, web, todos, journal, MCP or project-doc reading. Two invariants bound a preset and are tested: rank-1 safety rules survive every composition, and the tool set is closed under docstring cross-reference (which is what makes it ten tools rather than six). See ADR-0049.
- **Improvement: presets renamed to `full` / `lean` / `minimal`, and `lean` got its own rulebook** (`src/zrb/llm/prompt/profile.py`, `src/zrb/llm/prompt/markdown/workflow.lean.md`, `src/zrb/llm/prompt/markdown/examples.lean.md`, `docs/configuration/llm-config.md`, `AGENTS.md`): the previous names — `terse` / `mini` / `micro` — mixed a prose register with two size words, labelled the *largest* preset "terse", and collided with the vendor tier labels the selector matches on, so a model named `-micro` matched no pattern and fell through to the heaviest preset. The new names sit on one axis: how much the model is asked to hold at once. `lean` (5-14B) was the heaviest composition in the system, shipping the frontier `workflow.md` plus 1,200 tokens of extra examples; it now resolves `workflow.lean.md` (~25% smaller, precedence ladder flattened) while keeping every section and tool. Burden falling monotonically across presets is asserted by `test_rule_burden_falls_as_the_target_model_gets_weaker`, not assumed. No alias for the old values: an unrecognized `ZRB_LLM_PROFILE` falls through to `auto`.
- **Fix: a fractional parameter count in a model id selected the wrong preset** (`src/zrb/llm/prompt/profile.py`, `test/llm/prompt/test_profile.py`): built-in selection matched each size band with its own digit pattern, and a digit class cannot see a decimal point — `deepseek-r1:1.5b` matched the 5-14B pattern on its `5b`, so the two most widely-run local models on the planet (`1.5b`, `0.5b`, plus `phi3:3.8b`) received `lean`, the preset built for models up to ten times their size, instead of `minimal`. A stated count is now parsed as a number and compared against `SIZE_BANDS`, which also settles the two ambiguous id shapes by rule: the first count in an id wins, so an MoE reads as its total rather than its active parameters (`qwen3-30b-a3b` → 30B → `full`), and a count outranks a vendor label (`some-mini-32b` → `full`). Introduced in 2.53.0, when declared-size selection was added.
- **Fix: a hook subprocess that exited during the first selector poll lost its output** (`src/zrb/llm/hook/process_io.py`, `test/llm/hook/test_process_io.py`): `read_hook_output` left its drain loop once the child was gone and a poll "turned up nothing to read" — but stdin is writable from the moment the child is spawned, so the very first `select` returns immediately on stdin alone and proves nothing about a quiet interval. A child that ran, wrote and exited in that window had its buffered stdout and stderr closed unread: a `SessionStart` hook contributed no `additionalContext`, an exit-2 hook lost the stderr its deny reason comes from, and the hook suite was flaky at roughly 1 run in 10. The exit test is now "this poll returned no events at all", which a write-only wake-up no longer satisfies. Introduced in 2.55.1, with the selector-based reader that replaced `communicate()`.
- **Refactor: the preset's tool axis is a predicate, not a wrapper host** (`src/zrb/llm/common_tools.py`, `test/llm/test_common_tools.py`, `test/llm/prompt/test_section_composition.py`): `apply_common_tools` applied the tool filter by wrapping the real host in a `_PresetHost` proxy and passing three lazily-imported tools into a helper as arguments. It now resolves one predicate (`_preset_tool_filter`) and applies it to the static list and to each tool factory (`_selected` / `_gated`), split across `_register_tools` and `_register_tool_factories` so each function owns its own imports and its own capability tagging. The new public `tool_name(tool)` replaces four copies of the "unwrap `.function`, try `__name__` then `name`" idiom across `src/` and `test/`. Behavior is unchanged, including that a constrained preset drops MCP toolsets — now covered by `test_minimal_registers_no_mcp_toolsets`.
- **Refactor: methods a composed part contributes to its host are public** (`src/zrb/llm/task/history.py`, `src/zrb/llm/task/building.py`, `src/zrb/llm/task/llm_task.py`, `src/zrb/llm/task/chat/execution.py`, `src/zrb/llm/task/chat/running.py`, `src/zrb/llm/agent/subagent/manager.py`, `docs/adr/adr-0035.md`): `LLMTaskHistory` and `LLMTaskBuilding` are parts under ADR-0035 — the host calls their methods by name, sibling parts declare them in host-contract blocks, and subclasses override them — yet they carried a leading underscore, which forced their tests to violate ADR-0034's public-API-only rule. `get_history_manager`, `get_conversation_name`, `get_effective_prompt`, `is_context_length_error`, `handle_run_error`, `save_cancelled_history`, `post_process_output`, `get_all_tools`, `get_all_toolsets`, `get_model` and `get_model_settings` are now public and documented, joining the already-public `get_system_prompt` / `get_live_context` beside them. Helpers called only from inside their own part keep the underscore. No alias for the old names.
- **Improvement: `CFG.is_env_set(name)` answers "did the user set this?"** (`src/zrb/config/env_field.py`, `src/zrb/config/config.py`, `src/zrb/builtin/config.py`, `docs/adr/adr-0022.md`): a config read cannot distinguish a chosen value from a defaulted one, and the preset section-list precedence turns on exactly that difference. `EnvField` gained `is_set(prefix)` (aliases included, so a renamed knob still counts as set) and a public `serialize(value)`; `CFG.is_env_set("LLM_INCLUDE_SECTIONS")` reaches them through the flat surface, replacing a `type(CFG).<FIELD>` descriptor poke in `PromptManager` and a `_serialize` private call in `zrb config explain`. `HookManager.search_dirs` became a property for the same reason — the test suite was assigning its backing field.
- **Feature: `UICommands` replaces fifteen `ui_*_commands` constructor parameters** (`src/zrb/llm/task/chat/ui_commands.py`, `src/zrb/llm/task/chat/task.py`, `src/zrb/llm/task/chat/execution.py`, `src/zrb/__init__.py`, `test/llm/task/chat/test_ui_commands.py`): `LLMChatTask` took one `list[str] | None` parameter per slash command — `ui_summarize_commands`, `ui_attach_commands`, `ui_exit_commands`, and twelve more — which put a fifth of its 86-parameter signature into a single repeated shape and made the valid set discoverable only by reading the signature. They collapse into `ui_commands: UICommands | None`, a frozen dataclass with one field per command accepting a bare alias or a list: `UICommands(exit="/quit", save=["/save", "/w"])`. The field names autocomplete, a misspelled command is a `TypeError` at construction rather than an override that silently never applies, and a field left unset still resolves its `CFG` default at session start so a later env change wins. `UI_COMMAND_CFG_ATTRS` moved beside the dataclass as the single source of truth for the command set, with `test_fields_match_the_configured_commands` asserting the two stay in step. No alias for the old parameters.
- **Fix: `render_ui_ascii_art_name` renamed to `render_ui_ascii_art`** (`src/zrb/llm/task/chat/task.py`): the flag renders `ui_ascii_art`, and no `ui_ascii_art_name` parameter has ever existed — the name pointed at nothing, breaking the `render_x` ↔ `x` pairing every other flag on the class follows. No alias.
- **Improvement: every public method, property and constructor parameter on the exported API is documented** (43 modules across `src/zrb/`, `test/test_public_api_docs.py`): 60% of the public methods and properties reachable from `zrb.__all__` had no docstring, concentrated in a few base classes — `BaseTask` alone accounted for 110 of the 323 gaps, inherited by eight task types. Documenting the protocols (`AnyInput`, `AnyGroup`, `AnySharedContext`) rather than each implementation closes most of them at once, since `inspect.getdoc` walks the MRO. That same inheritance was hiding a second problem the first pass counted as solved: `CmdTask.__init__` (44 parameters) resolved to `BaseTask`'s docstring describing 21, and `LLMChatTask.__init__` resolved to `object`'s "Initialize self" placeholder — both read as documented while presenting an argument list that was wrong or absent. Every constructor that adds parameters now documents the ones it adds and points at its base for the rest. Two parametrized guards pin it: members must be documented, and a constructor that widens its signature must have a docstring of its own.
- **Improvement: a golden-file contract pins the public API surface** (`test/test_public_api_contract.py`, `test/public_api_snapshot.json`): `__all__`, every exported class's public members, and every constructor's parameter names, order, kind and whether-defaulted are recorded in a reviewable JSON snapshot. Parameter *values* are deliberately not recorded — several defaults are live singletons whose `repr` carries a memory address — but the boolean still catches a parameter dropped, renamed, reordered, or turned from optional into required. Regenerate deliberately with `ZRB_UPDATE_API_SNAPSHOT=1`; the failure message names the drifted class and the added/removed entries.
- **Refactor: the three most tangled functions in the tree were decomposed** (`src/zrb/llm/agent/run/deferred_calls.py`, `src/zrb/llm/tool/file_edit.py`, `src/zrb/llm/agent/subagent/manager_loading.py`): `_resolve_approval` (complexity 34 → 11) became one function per priority in its documented approval cascade, each returning a verdict or `None` to fall through, so the precedence chain is now the call order rather than a comment describing it. `replace_in_file` (25 → 8) split its match-location strategies and its two explainer paths — missing match, and located-but-no-op — out of the main procedure. `_load_agent_from_markdown` (29 → 11) lost three copies of the same list-or-comma-string frontmatter coercion to one `_as_str_list` helper. Behavior is unchanged in all three, including every `[SYSTEM SUGGESTION]` message, which are reproduced verbatim.
- **Improvement: a second complexity ratchet measures true per-function complexity** (`zrb-test.sh`): the existing `flake8 --max-complexity` gate uses mccabe, which sums a nested function's branches into its enclosing function. That scores route- and keybinding-registration functions — flat sequences of small handlers — as high as genuinely tangled logic, and pinned the ratchet at 47 where it caught almost nothing: `serve_chat_api` reads as 36 under mccabe and 1 under radon. A radon-based check now fails the suite on any *single* function above 23, which is the number that reflects tangled control flow, and prints every offender with its score when it trips.
