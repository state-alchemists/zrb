## 2.57.0 (August 8, 2026)

- **Security: `aiohttp` bumped to `>=3.14.3` in the `xai` and `voyageai` extras** (`pyproject.toml`, `poetry.lock`): fixes three advisories below the old `>=3.14.1` floor — GHSA-cq5v-8q36-5273 / CVE-2026-69244 (out-of-bounds heap read in the C parser on a malformed chunked response; a broken server can DoS the client), GHSA-mfx4-hv73-q22v / CVE-2026-69243 (request smuggling via WebSocket upgrade), and GHSA-mq44-7p77-q5h7 / CVE-2026-59881 (compressed WebSocket frames accepted without negotiated `permessage-deflate`). A full re-resolve also dropped a stale second lock entry pinned at 3.14.1 for the `rag`/`xai` markers; `rag` reaches aiohttp through chromadb and was never covered by the direct pin.
- **Chore: pydantic-ai upgraded from 2.8 to 2.27** (`pyproject.toml`, `poetry.lock`, `docs/technical-specs/llm-history-sanitization.md`): nineteen non-breaking minor releases; the suite passed unchanged. `openai` is now pinned `>=2.45.0` (was `>=2.29.0`): pydantic-ai passes `prompt_cache_options=` on every request, and an older SDK raises `TypeError` on each one while a mocked suite stays green — `test_the_installed_openai_sdk_accepts_what_pydantic_ai_sends` pins it. Extras realigned to pydantic-ai's floors: `mistralai>=2.4.2` (was `>=2.0.0`), `xai-sdk>=1.14.0` (was `>=1.12.2`), and `huggingface` gains the `hf-xet<1.5.0` cap `huggingface_hub` 1.3.x needs.
- **Documentation: the supported-provider table listed 6 of the 30 providers zrb can reach** (`docs/configuration/llm-config.md`): every provider pydantic-ai ships has always worked, and OpenRouter, Z.ai, Cerebras, Together, Fireworks, Moonshot, Alibaba, Azure, Vercel, Snowflake and the rest need no extra because they speak the `openai` wire protocol. The table now lists no-extra providers with their credential env vars, then the ten that need a `zrb[...]` extra.
- **Improvement: `Retry-After` is honored on errors pydantic-ai wraps** (`src/zrb/llm/agent/run/error_classifier.py`, `docs/technical-specs/llm-history-sanitization.md`): a 429 wrapped as `ModelHTTPError` got exponential backoff instead of the requested wait. `get_retry_wait` now reads `ModelHTTPError.retry_after` first (which also parses the HTTP-date form) and keeps the `.response` path for unwrapped exceptions.
- **Fix: the `content: null` patch reintroduced the 400 it exists to prevent, for empty responses** (`src/zrb/llm/agent/run/openai_patch.py`, `docs/technical-specs/llm-history-sanitization.md`): for a `ModelResponse` with neither text nor tool calls, zrb's override emitted `{"role": "assistant", "content": null}`, which Chat Completions rejects; upstream emits no message. The upstream guard is now reproduced verbatim. The patch was re-verified as still needed on 2.27.0, and its tests now drive the real `OpenAIChatModel._MapModelResponseContext` rather than a `MagicMock`.
- **Improvement: `/model` completion reads the public model list** (`src/zrb/llm/app/completion/completer.py`): `get_args(KnownModelName.__value__)` unwrapped a `TypeAliasType` internal, so any change to the alias's shape would silently drop completion to a nine-entry hardcoded fallback. `known_model_names()` is the supported accessor and returns all 650.
- **Documentation: the history-sanitization layers were re-audited against 2.27** (`docs/advanced-topics/maintainer-guide.md`): every mitigation is still load-bearing, and the guide now records why per layer, so the next bump starts from a verdict rather than a re-investigation. The short version: these work around *provider* behavior, not pydantic-ai behavior, so a framework upgrade rarely retires one — and the two orphan-related layers exist because zrb's own summarizer splits turns.
- **Feature: `ZRB_LLM_PROFILE` selects a preset over three axes, and `minimal` serves ~3B models** (`src/zrb/llm/prompt/profile.py`, `src/zrb/llm/prompt/manager.py`, `src/zrb/llm/common_tools.py`, `src/zrb/llm/prompt/markdown/workflow.minimal.md`, `docs/adr/adr-0049.md`): a profile is now a `Preset` binding which sections compose, how they are phrased, and which tools register — bringing the ~4,000 tokens of tool docstrings and schemas under a knob. `minimal` composes `persona`/`workflow`/`system_context` through `workflow.minimal.md` over a ten-tool surface (`MINIMAL_TOOLS`), cutting the preamble from ~9,000 to ~3,500 tokens, at the cost of no skills, sub-agents, web, todos, journal, MCP or project-doc reading. Tests assert rank-1 safety rules survive every preset and the tool set is closed under docstring cross-reference.
- **Improvement: presets renamed to `full` / `lean` / `minimal`, and `lean` got its own rulebook** (`src/zrb/llm/prompt/profile.py`, `src/zrb/llm/prompt/markdown/workflow.lean.md`, `src/zrb/llm/prompt/markdown/examples.lean.md`, `docs/configuration/llm-config.md`): the old names `terse` / `mini` / `micro` mixed axes, labelled the largest preset "terse", and collided with vendor tier labels — a model named `-micro` fell through to the heaviest preset. `lean` (5-14B) was the heaviest composition (frontier `workflow.md` plus 1,200 tokens of extra examples); it now uses `workflow.lean.md` (~25% smaller) with every section and tool kept. `test_rule_burden_falls_as_the_target_model_gets_weaker` asserts burden falls monotonically. No alias: an unrecognized `ZRB_LLM_PROFILE` falls through to `auto`.
- **Fix: a fractional parameter count in a model id selected the wrong preset** (`src/zrb/llm/prompt/profile.py`, `docs/llm/programming-the-prompt.md`): `deepseek-r1:1.5b` matched the 5-14B band on its `5b`, so `1.5b`, `0.5b` and `phi3:3.8b` models got `lean` instead of `minimal`. A count is now parsed as a number and compared against `SIZE_BANDS`; the first count in an id wins (an MoE reads as its total: `qwen3-30b-a3b` → `full`), and a count outranks a vendor label (`some-mini-32b` → `full`). Introduced in 2.53.0.
- **Fix: a hook subprocess that exited during the first selector poll lost its output** (`src/zrb/llm/hook/process_io.py`): `read_hook_output` treated a poll with nothing to read as quiet, but stdin is writable at spawn, so the first `select` proved nothing; a child that wrote and exited in that window had its stdout and stderr discarded. A `SessionStart` hook lost its `additionalContext`, an exit-2 hook lost its deny reason, and the hook suite failed ~1 run in 10. The loop now exits only on a poll with no events at all. Introduced in 2.55.1.
- **Refactor: the preset's tool axis is a predicate, not a wrapper host** (`src/zrb/llm/common_tools.py`): `apply_common_tools` dropped its `_PresetHost` proxy for one predicate applied to the static tool list and to each tool factory. A new public `tool_name(tool)` replaces four copies of the name-unwrapping idiom. Behavior unchanged, including that a constrained preset drops MCP toolsets (`test_minimal_registers_no_mcp_toolsets`).
- **Refactor: methods a composed part contributes to its host are public** (`src/zrb/llm/task/history.py`, `src/zrb/llm/task/building.py`, `src/zrb/llm/task/chat/execution.py`, `docs/adr/adr-0035.md`): the host, sibling parts and subclasses call these `LLMTaskHistory` / `LLMTaskBuilding` methods, so their leading underscore forced tests to break ADR-0034. `get_history_manager`, `get_conversation_name`, `get_effective_prompt`, `is_context_length_error`, `handle_run_error`, `save_cancelled_history`, `post_process_output`, `get_all_tools`, `get_all_toolsets`, `get_model` and `get_model_settings` are now public and documented. Part-internal helpers keep the underscore. No alias for the old names.
- **Improvement: `CFG.is_env_set(name)` answers "did the user set this?"** (`src/zrb/config/env_field.py`, `src/zrb/config/config.py`, `docs/adr/adr-0022.md`): `EnvField` gained `is_set(prefix)` (aliases included) and a public `serialize(value)`, reached through `CFG` so `PromptManager` and `zrb config explain` no longer poke descriptors or private methods (see ADR-0022). `HookManager.search_dirs` became a property.
- **Feature: `UICommands` replaces fifteen `ui_*_commands` constructor parameters** (`src/zrb/llm/task/chat/ui_commands.py`, `src/zrb/llm/task/chat/task.py`, `src/zrb/__init__.py`, `docs/advanced-topics/upgrading-guide.md`): `LLMChatTask`'s `ui_summarize_commands`, `ui_attach_commands`, `ui_exit_commands` and twelve more collapse into `ui_commands: UICommands | None`, a frozen dataclass with one field per command taking an alias or a list: `UICommands(exit="/quit", save=["/save", "/w"])`. A misspelled command is now a `TypeError` instead of a silently ignored override; an unset field still resolves its `CFG` default at session start. `UI_COMMAND_CFG_ATTRS` lives beside the dataclass as the source of truth. No alias for the old parameters.
- **Fix: `render_ui_ascii_art_name` renamed to `render_ui_ascii_art`** (`src/zrb/llm/task/chat/task.py`): the flag renders `ui_ascii_art`, and no `ui_ascii_art_name` parameter has ever existed — the name pointed at nothing, breaking the `render_x` ↔ `x` pairing every other flag on the class follows. No alias.
- **Improvement: every public method, property and constructor parameter on the exported API is documented** (43 modules across `src/zrb/`, `test/test_public_api_docs.py`, `docs/contributing/maintainer-guide.md`): 60% of public members reachable from `zrb.__all__` lacked a docstring, 110 of the 323 gaps on `BaseTask` alone; documenting the protocols (`AnyInput`, `AnyGroup`, `AnySharedContext`) closed most through MRO inheritance. Inheritance also hid wrong constructor docs: `CmdTask.__init__` (44 parameters) showed `BaseTask`'s 21, and `LLMChatTask.__init__` showed `object`'s placeholder. Every constructor that adds parameters now documents them and points at its base. Tests require both.
- **Improvement: a golden-file contract pins the public API surface** (`test/test_public_api_contract.py`, `test/public_api_snapshot.json`): `__all__`, every exported class's public members, and every constructor's parameter names, order, kind and whether-defaulted are recorded in a reviewable JSON snapshot (default values are not, since some are live singletons). Regenerate deliberately with `ZRB_UPDATE_API_SNAPSHOT=1`; the failure names the drifted class and entries.
- **Refactor: the three most tangled functions in the tree were decomposed** (`src/zrb/llm/agent/run/deferred_calls.py`, `src/zrb/llm/tool/file_edit.py`, `src/zrb/llm/agent/subagent/manager_loading.py`): `_resolve_approval` (complexity 34 → 11) became one function per step of its approval cascade, so precedence is call order. `replace_in_file` (25 → 8) split out its match strategies and explainer paths. `_load_agent_from_markdown` (29 → 11) replaced three copies of frontmatter list coercion with `_as_str_list`. Behavior unchanged, including every `[SYSTEM SUGGESTION]` message.
- **Improvement: a second complexity ratchet measures true per-function complexity** (`zrb-test.sh`, `docs/contributing/maintainer-guide.md`): mccabe counts nested handlers into their enclosing function, which pinned the `flake8 --max-complexity` ratchet at 47 (`serve_chat_api` scores 36 under mccabe, 1 under radon). A radon-based check now fails the suite on any single function above 23 and prints every offender.
