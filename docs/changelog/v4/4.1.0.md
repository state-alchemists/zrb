## 4.1.0 (November 28, 2026)

- **Fix: a typed input is refused instead of crashing the run** (`src/zrb/runner/web_route/task_session_api_route.py`, `src/zrb/input/base_input.py`): the route took `inputs: dict[str, Any]` and handed it on as `str_kwargs`, so `{"flag": true}` reached `BoolInput`, whose `to_boolean` calls `.lower()` on a real bool and raised `AttributeError` out of the request as a 500. It declares `dict[str, str]` now, so FastAPI answers 422 before a session starts, and `BaseInput.update_shared_context` catches `TypeError` and `AttributeError` beside `ValueError`, so a library caller gets the same `Invalid value for input '<name>'` message a bad string gets.
- **Fix: `Xcom` fires its callbacks for the mutations it inherits, and `set` tells them the truth** (`src/zrb/xcom/xcom.py`): `deque`'s own `__iadd__` and `clear` bypassed the overrides, so `ctx.xcom[task] += [...]` or a `clear()` between two events dropped a trigger's wake-up with no error. `__iadd__` extends through the override; `clear` fires the pop callbacks when there was something to remove; `set` replaces the contents before it pushes, where a push listener used to read the old values plus the new one. `rotate` and `reverse` only rearrange, which the class docstring now says.
- **Fix: the printed "To run again" hint survives the shell it is pasted into** (`src/zrb/runner/cli.py`, `src/zrb/util/string/conversion.py`): `Cli.get_run_command_param` quoted only a value holding a quote, a space or nothing, so a value typed at a prompt printed bare — `--k a;b` ran a second command, `--k $(whoami)` substituted, `--k *` expanded. Every value now goes through `shell_quote`: `shlex.quote` on a POSIX shell, `subprocess.list2cmdline` on Windows, whose C runtime parses the same argv.
- **Fix: `@weekly` is Sunday, and a stepped day field is a star** (`src/zrb/util/cron.py`, `docs/task-types/triggers-and-schedulers.md`): `@weekly` matched Monday, where Vixie cron and cronie put Sunday, so a schedule copied from a crontab fired a day early. And the rule that ANDs the two day fields tested each whole field against `"*"`, so `0 0 */2 * 1` was read as OR and ran on every Monday; cronie reads a leading `*` as the star flag, and `match_cron` reads it that way now.
- **Fix: no `assert` stands as a runtime check** (`src/zrb/`, `test/architecture/test_no_assert_in_src.py`): `python -O` removes an `assert`, and the line after it then raises an opaque `AttributeError` where the message should name the task or the state. All 21 in `src/zrb` are now an explicit `if ...: raise RuntimeError(...)`, or a condition the type checker narrows on — `_strip_part`'s `isinstance`, `match_cron`'s day fields — and a guard test holds the count at zero.
- **Fix: `gather_isolated` says what a cancelled sibling means, and does not hand it back as a result** (`src/zrb/util/run.py`): its docstring promised "every coroutine completes, then the first exception is re-raised", and a cancellation is not a completion — `asyncio.gather(..., return_exceptions=True)` reports a child cancelled on its own as a `CancelledError` *value*, which came back looking like an answer. Decided explicitly and written down: a cancelled child is raised once the siblings settle, because `execute_root_tasks` reads a cancelled root task as the run being stopped, and tolerating it finished the session quietly instead. A caller cancelled while it waits still gets its own `CancelledError` out of the `await`, before the results are read.
