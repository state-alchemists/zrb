## 4.0.0 (Unreleased)

The one announced break since 3.x: **`zrb.llm` is five directories, and the directory is a module's layer.** Every import path under `zrb.llm` that named a unit at the top of the package — `ui`, `task`, `tool`, `prompt`, `subagent`, `camera`, `speech` and the rest — has moved into `contracts/`, `capabilities/`, `engine/`, `orchestration/` or `presentation/`, and the old spellings no longer resolve. There is no compatibility shim: one would have to import the package above it and would restore the upward edge the move removes.

[Upgrading to 4.0.0](../../advanced-topics/upgrading-guide.md#upgrading-to-400) has the table of old path → new path. The decision and its rejected alternatives are in [ADR-0144](../../adr/adr-0144.md).

- **Breaking: `zrb.llm` is five directories, and the directory is the layer** (`src/zrb/llm/contracts/`, `capabilities/`, `engine/`, `orchestration/`, `presentation/`, `test/architecture/llm_layers.py`, ADR-0144): `contracts/` is L0, `capabilities/` L1, `engine/` L2, `orchestration/` L3, `presentation/` L4, and a module's layer is its first path segment. `src/zrb/llm/` now holds those five directories and nothing else, so a path states its own rank instead of sending a reader to a table in the test tree. Moved, with their tests: `config`, `memory`, `shared` and `util` → `contracts/`; the eleven capability units (`tool`, `tool_call`, `prompt`, `hook`, `permission`, `approval`, `sandbox`, `history_manager`, `skill`, `lsp`, `snapshot`) → `capabilities/`; `agent` and `summarizer` → `engine/`; `task`, `subagent`, `custom_command`, `common_tools.py` and `resumed_session.py` → `orchestration/`; `ui` and the six media units (`camera`, `dictation`, `emotion`, `screenshot`, `speech`, `voice`) → `presentation/`. **Importing a moved module from its old path raises `ModuleNotFoundError`.** No behaviour change: the code is the same code, moved.
- **The layer table and the `any_*.py` glob are deleted** (`test/architecture/llm_layers.py`, `test/architecture/test_llm_layer_rules.py`): a module's rank came from `_UNITS_BY_LAYER` plus a glob that granted L0 to any file named `any_*.py`, so a reader could not tell from a path why a file at L4 was importable from L1. The contracts a lower layer must name now live where their path says — `contracts/shared/`, `contracts/ui/`, `contracts/config/`, `contracts/memory/`, `contracts/util/` — and the `AnyUI*` protocols stay in `presentation/ui/` beside the implementers that answer them. Two floors keep an L0 rank through a path prefix (`presentation/ui/fallback/`, `presentation/ui/buffered/`), and one file is exempt (`engine/agent/types.py`, the framework's own types handed around by name). A guard now fails if `llm/` grows a sixth directory.
- **Both ratchet allowlists are empty, and the deferred-import allowlist with them** (`test/architecture/test_llm_layering_ratchet.py`, `test/architecture/test_circular_import_allowlist.py`): the twenty upward edges and two same-layer cycles the move started with are gone, each replaced by a contract or a seam rather than by a `# lazy: circular` comment. `KNOWN_UPWARD_EDGES` and `KNOWN_SAME_LAYER_CYCLES` may only stay empty; a new entry fails the suite.
- **The UI's roles and capabilities are contracts, not the UI package** (`src/zrb/llm/contracts/ui/`, `src/zrb/llm/presentation/ui/`, `test/architecture/test_ui_contract_roles.py`): the three UI roles a lower layer must be able to name moved down to `contracts/ui/`, and the seam a parent message needs became the capability protocol `AnyUIMessageSink` — so the last runtime edge into the UI package that a filename had been granting is gone. The aggregate `AnyUI` declares its roles as accessors, so a UI backend still answers nine members rather than fifty.
- **New: one usage row per request, with its reason and a digest of its prompt** (`src/zrb/llm/contracts/shared/request_log.py`, `request-YYYY-MM.jsonl` beside `usage-YYYY-MM.jsonl`, ADR-0143): the usage log sums a round, and a round of fifty-four requests paid for one number, so a miss could not be attributed to a request. Every model call now writes its own row — the ten call sites, the turn loop's and the auxiliary ones (hooks, the shell judge, the namer, the summarizer, a side question, dictation's judge, speech) — joining the summed line on `turn`. A run handed a `message_history` folds that history into its count and its digest, so a side question's row describes the prompt that was actually sent. A second file, not a second meaning: every table built on the usage log keeps its numbers.
- **Fix: a diary page compacts before it fills, and a write with no body is refused** (`src/zrb/llm/contracts/memory/`): a page that had reached the cap was compacted only after it overflowed, and a metadata-only write (`body is None`) was judged as a compaction and refused instead of skipping the rewrite. A full page now compacts its way down as it is written, and a write that carries no body leaves the page's prose alone.
- **Improvement: an agent hook reads the turn with one cap on it** (`src/zrb/llm/engine/agent/hook_agent.py`, `src/zrb/llm/contracts/util/history_formatter.py`, `src/zrb/util/truncate.py`, `test/llm/engine/agent/test_hook_agent_transcript.py`, #989): a hook fires outside the turn loop, so its opening request has no cached prefix to read and pays nearly all of its prompt fresh. The transcript it is handed now arrives whole except for one part — a tool return is cut to 2,000 characters, 1,200 at the top and 800 at the bottom, with the number dropped named between them, and the writer's thinking is omitted — while tool-call arguments, a failed return and the memory tools' own returns pass through untouched: a wrong number read off a cut return becomes a remembered claim. `format_history_as_text` takes the shape as a `TranscriptPolicy`, and `truncate_head_tail` keeps both ends of the cut because a head-only one can invert what a return said.
- **Fix: a command hook cancelled while it is still spawning kills the child it made** (`src/zrb/llm/capabilities/hook/execution/creator.py`, `src/zrb/llm/capabilities/hook/execution/process_io.py`): the cancel handler covered the wait for the child's output, but a cancel that landed between the spawn and that wait left the task without a process to kill, so the child kept running with its pipes open — a leaked hook process per cancelled turn, on every platform. The spawn now hands its result to `run_in_daemon`'s `on_orphan`, which `run_detached` passes through, so a child whose spawn outlived the cancelled await is killed and reaped on its own thread. Nothing changes when nothing cancels.
- **Fix: the reviewer dates the turn, and a diary page keeps its hours** (`src/zrb/llm/contracts/shared/markdown/memory_reviewer.md`, `src/zrb/llm/capabilities/hook/builtin/memory_reviewer.py`, `src/zrb/llm/engine/agent/run/turn_cursor.py`): the note told the reviewer the clock read `06:13`, and the prompt then said that clock was the review's rather than the moment's — so the reviewer read its only clock as somebody else's and stopped naming hours. No page written on 2026-11-16, 11-19 or 11-20 carries one, and a day without hours loses the order of an argument. The note now states the turn's span, `the turn ran from 05:57 to 06:13`, from the Stop payload's new `turn_started_at` and `turn_ended_at`: the cursor's own clock for the start, and the event's for the end, so a turn that spent an hour on tools is not dated to the hour it ended and a turn that ended before midnight is not filed under the next day. The prompt asks for the hour as `HH:MM` from those two while still forbidding one inferred from the shape of the transcript — the failure of 2026-11-18, when three morning paragraphs said "late in the night" — and a paragraph carried into a rewrite keeps the hour it already names.
- **Internal: `zrb_init.py` loads under an older zrb** (`zrb_init.py`): the repository's own init file imports through the 4.0 path first and falls back to the 3.x one. This exists for one reason — the review container pins an older zrb and loads the base branch's init file — and it is the only place a 4.0 path is spelled with a fallback.
- **Internal: the two ratchets the reformat tripped are cleared, not budgeted** (`test/llm/presentation/speech/`, `test/llm/presentation/camera/backend/`, `test/llm/presentation/ui/default/`, `test/llm/presentation/ui/base/`, `test/llm/engine/summarizer/`, `src/zrb/llm/presentation/ui/default/ui.py`, `src/zrb/llm/orchestration/task/`): six test files were past the 500-line split rule and three facades past their size budget, which left `main` red for every pull request behind it. Each test file is split by feature group with every test body byte-identical to the commit it came from; each facade loses only the lines that restate what the same file already says — twelve setter docstrings that repeat their own getter in `llm_task.py`, four copies of one comment in `ui.py`, and three pointer lines in `task.py`, where the fifteen `remove_*` docstrings had to stay because `test_public_api_docs.py` requires one on every public method. No budget moved: 829→819, 1050→1047, 826→814.
