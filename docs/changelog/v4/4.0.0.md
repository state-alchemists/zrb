## Unreleased

- **Fix: a loaded file's declarations keep a module identity without keeping its name** (`src/zrb/util/load.py`, `test/util/test_load.py`): 4.0.0b5 freed a loaded file's bare stem from `sys.modules` so a task, hook or skill called `openai.py` could not answer every later `import openai`, but that also left every class and function defined in the file unpicklable and made `typing.get_type_hints` raise `NameError` for a class whose annotations are strings: both resolve an object through `obj.__module__`. Each declaration defined in the body is now moved onto a private, UUID-suffixed identity while the stem is still freed; the identity stays in `sys.modules`, so `pickle`, typing and `inspect` work after the body, and a later `import openai` still reaches the real module. `load_module_from_path` keeps the UUID name its hook, skill and agent callers already supply, since that name cannot shadow anything. The load is serialized so two same-stem files cannot take each other's temporary entry, and a `sys.modules[name] = None` import blocker is restored rather than dropped. A late `import <stem>` from inside the loaded file still runs the file again; only the body-time self-import is held.
- **Fix: a full disk no longer takes a background reader down with it** (`src/zrb/llm/capabilities/tool/shell/capture.py`, `src/zrb/llm/capabilities/tool/shell/background.py`, `test/llm/capabilities/tool/shell/test_stream_capture.py`): opening, flushing, capping and reading the spill were best effort, but writing to it was not. An `ENOSPC`/`EIO` escaped `feed()` into `_read_pipe`; the reader died after `total_chars` had counted the chunk but before the tail retained it, so the output was lost and a large-output child could block on a full pipe with no exit code and no wake. The write now catches `OSError`, disables the spill (the in-memory tail stays) and logs why. A truncation note for a capture with no usable spill says the overflow was not saved, instead of naming `None`.
- **Fix: a mistyped permission action is refused instead of failing open** (`src/zrb/llm/capabilities/permission/policy.py`, `test/llm/capabilities/permission/test_policy.py`, `docs/llm/permission-policy.md`): a `Rule` accepted any string as its action, and every consumer only understands `allow`, `ask` and `deny`; an action such as `"deni"` looked like "no decision" to `get_policy_skip_decision` and fell through to YOLO, while `permission_gate` did not block it either. A one-character typo in a security policy therefore loosened it silently. `Rule` now validates its action and raises `ValueError` naming the accepted three, so the mistake surfaces when the policy is built rather than at the call it was meant to stop.

- **Improvement: the spoken-block prompt asks for the block on every reply, and says to write it first** (`src/zrb/llm/contracts/shared/markdown/speech_live.md`, `src/zrb/llm/presentation/speech/feature.py`, `test/llm/presentation/speech/test_text.py`, `docs/configuration/llm-voice-camera.md`): the rule had narrowed to "only a reply that is nothing but the answer can go without", and a single-voice answer is exactly that, so a model could follow the prompt as written and still leave the block out — most often on the long reply that needed it. The decision was positional besides: whether a reply needs a block depends on a table it has not written yet, or on crossing four hundred characters somewhere in the middle, so the exemption won before the content existed. `<spoken>` is now the first characters of every reply, a one-sentence answer included, and a table, path or command below it is what the block is for rather than what earns it; `_MISSED_BLOCK_NOTICE` states the same rule, so the reminder and the prompt no longer disagree. `needs_spoken_block` is unchanged and stays wider than the rule on purpose — it decides what a miss costs, a repair call and a notice, and a short reply in one voice is heard whole without harm — which the test holding it now says.

## 4.0.0b5 (November 24, 2026)

_What landed on `main` after `4.0.0b4`: a sentence interrupted while it waits for the device is dropped rather than read out, an open loop that nobody has moved for a week says how long, a message that names a setting names the prefix this deployment actually reads, the browser proxy validates the address it connects to, and a file loaded by zrb no longer keeps the module name it borrowed._

- **Fix: a sentence interrupted while it waits for the device is dropped** (`src/zrb/llm/presentation/speech/player.py`, `test/llm/presentation/speech/test_player_shared_device.py`): `play` asked the caller's predicate whether the sentence was still wanted, then took the audio lock. Those are two instants, and an interrupt landing between them left a sentence the caller had dropped to be read out — `interrupt` bumps the generation and releases its own hold on the device at the same moment, so the take that follows succeeds. It surfaced as a macOS-only flake: `test_a_sentence_interrupted_while_waiting_is_dropped` played `waits` on CI and passed on the same machine by hand. The predicate is now asked again once the lock is held, which is inside the device and cannot re-open the check-then-take gap the first look exists to close.

- **Feature: an open loop untouched for a week says how long** (`src/zrb/llm/contracts/memory/render.py`, `src/zrb/llm/capabilities/prompt/memory_context.py`, `test/llm/contracts/memory/test_memory_render.py`): a loop's line was its claim and its id, so a thread nobody had moved in a fortnight read exactly like one written this morning — which is how a finished loop sat in the block for weeks. `render_core` now takes the day and appends `· 12d` past seven, and it closes nothing: the count is a nudge, and retirement stays a decision. It is derived from the claim's own `updated` and never stored, so it cannot disagree with the file beside it; the copy written to `core.md` passes no day, because the file is the same bytes whenever it is written. A claim whose date is empty, unreadable or in the future draws nothing, because frontmatter is a text file people edit and an age that is wrong is worse than the age the file already shows. `core_budget` and `core_line` take the same day, since both compare a claim's line against the block's — without it every dated loop would read as cut by the cap. The write that decides the cap is measured the same way: a `remember` against the dated core, so a write that would push the block past its limit once the ages are drawn is refused there instead of being accepted and then cut out of the next turn's block.

- **Fix: a message that tells the user which setting to change names their prefix** (`src/zrb/llm/contracts/shared/request_log.py`, `src/zrb/task/http_check.py`, `src/zrb/task/tcp_check.py`, `test/architecture/test_env_prefix_in_messages.py`): zrb is white-labelled through `CFG.ENV_PREFIX`, and four messages spelled `ZRB_` instead — `ZRB_LLM_USAGE_DIR` in both request-log warnings, `ZRB_HTTP_CHECK_INTERVAL` and `ZRB_TCP_CHECK_INTERVAL` in the two readiness checks' rejection of a non-positive interval. A deployment that renamed the prefix was told to set a variable nothing reads, so following the message changed nothing. All four interpolate `CFG.ENV_PREFIX` where the message is built, which keeps the read lazy, and a new architecture guard fails on any string constant under `src/zrb` that spells the default prefix — the bare bootstrap keys carry a leading underscore and are untouched.

- **Security: the browser proxy validates the address it connects to** (`src/zrb/llm/capabilities/tool/web/tools.py`, `docs/configuration/llm-tools.md`, `test/llm/capabilities/tool/web/test_web_tool_proxy_resolver.py`, #1045): the loopback CONNECT proxy took Chromium's resolver out of the decision, then handed its own lookup's answer straight to the tunnel — so a name that answered publicly when the URL guard ran could answer a private address when the proxy did, which is the rebinding window the proxy was built to close. It now resolves through `_assert_public_addresses`, and takes a private answer only when `ZRB_LLM_WEB_ALLOW_PRIVATE_HOSTS=on`, where reaching a private host is the intent. The refusal a user reads named `LLM_WEB_ALLOW_PRIVATE_HOSTS`, a key nothing reads because the prefix defaults to `ZRB`, so following the message changed nothing; it names the key under `CFG.ENV_PREFIX` now, which is this deployment's own prefix and not the default one. `docs/configuration/llm-tools.md` said the proxy "tries the validated addresses itself", which described the behaviour this change supplies rather than the one it had. Its resolver is now public, `resolve_proxy_addresses`, because the proxy is constructed with it: a private-access ratchet counts every dotted private reach in `test/` and the suite drives the public surface only (ADR-0034), so the seam a test needs is the seam the module exports.

- **Fix: a loaded file no longer keeps the module name it borrowed** (`src/zrb/util/load.py`, `test/util/test_load.py`): a `zrb_init.py` was named after its file stem, registered in `sys.modules` before its body ran so that a file could import itself, and never taken back out — so the file went on answering every later `import` of that name for the life of the process. A task, hook or skill file called `openai.py` replaced the SDK with itself; every `zrb_init.py` shares the stem `zrb_init` with the next one, which is why `__main__.py` already collected the loaded sources in a list and said `sys.modules` "cannot be used"; and the three managers that load a file under a unique name (`zrb_hook_`, `zrb_skill_`, `zrb_agent_` plus a uuid) left those entries behind too. Registration is now `_registered`, a context manager held only while the body runs: it restores whatever held the name and drops a name that held nothing, so the self-import still resolves and the leak is gone. The directory a file sits in is still added to `sys.path` and `PYTHONPATH`, because its later imports rely on that — only the module entry was ever temporary. Nothing in the tree read one of those entries back, so no behaviour that was ever promised changed; all four new cases were seen red first. The module is reachable through the loader's return value only, which is the cost of the name being free again: a later `import` of that name runs the file a second time, and a class defined in it no longer pickles, because pickling looks the module up by name. Side effects belong in a `zrb_init.py`; definitions do not.

## 4.0.0b4 (November 24, 2026)

_What landed on `main` after `4.0.0b3`: a facade's size is pinned to its exact line count and the gate checks the house format, the deprecated setting names are gone, a prompt may name a limit instead of copying its value, a diary rewrite must name the page it replaces and land under the compaction point, the sandbox enforces the boundary it describes, a web fetch is pinned to a public address and the browser reaches the network only through a loopback proxy, session state masks both spellings of a secret, history backups have a directory of their own, delegation states when to fan out, and a sweep of reported defects closed the readiness hang, the deferred approval with no verdict and the silent data losses._

- **Feature: a prompt may name a numeric setting, not one of three** (`src/zrb/llm/contracts/shared/prompt_text.py`, `test/llm/capabilities/prompt/test_prompt_placeholders.py`, `docs/architecture/2-extension-surface/prompts.md`): `get_prompt` has filled `{CFG_*}` placeholders since 2.4.0, and the list of names it filled was three — `ROOT_GROUP_NAME`, `LLM_ASSISTANT_NAME`, `ENV_PREFIX`, down from five when the journal took its two with it. So a section could not name the diary's page length, and neither could a user's own override: `{CFG_LLM_MEMORY_DIARY_MAX_CHARS}` was left in the text as written and read by the model as a brace. Every number a prompt states is a number that goes stale the day the setting moves, and the diary caps moved from 8,000 and 6,000 to 12,000 and 10,000 the same week — the stale 8,000 that survived in the `Remember` tool's schema is the same defect one layer over. The resolver now reads the placeholders the prompt itself names and answers each from `CFG` — but only when the setting holds a number or a switch. That boundary is the point rather than an afterthought: a prompt is sent to a model provider and kept in the history, so the limit a page holds is worth naming and a credential, which is a string, must not be nameable from a repository's override. The three string settings a prompt has always been able to name stay listed one by one, a caller's `extra_replacements` still beat them, and a name that does not fill is left as written, because a placeholder emptied into nothing leaves a sentence with a hole in it that no reader can see. The `lru_cache` keyed on the three values went with the fixed list; the work is proportional to the placeholders a prompt actually carries.

- **Fix: a diary rewrite must name the page it replaces, and may not open the day later** (`src/zrb/llm/contracts/memory/model.py`, `src/zrb/llm/capabilities/tool/memory.py`, `src/zrb/config/mixins/llm_content.py`, `docs/technical-specs/llm-memory.md`, `docs/configuration/llm-context.md`, `docs/llm/hooks.md`, `test/llm/capabilities/tool/test_memory_diary_rewrite.py`, `test/llm/capabilities/tool/test_memory_diary_compaction.py`, `test/llm/contracts/memory/test_memory_model.py`): on 2026-11-23 an evening session's first diary write replaced a 6,073-character day with its own 658 characters, and every check passed — `body_overflow` asks whether a body fits the cap and `rewrite_not_compacted` asks whether it freed anything, and neither compares the body to the one it replaces, so a replace that keeps nothing is a legal compaction. `body_digest` was the guard for exactly this loss and it was optional, which a session's first write of a day can never satisfy: it has read nothing, so it sends none. A replace of a day that exists now requires the digest, and the refusal carries the day and the digest that answers it, so the first write of a day becomes an append. The second refusal holds the one property of a day's shape that can be checked: the earliest `HH:MM` a body names may not move later, because a rewrite that opens at 17:54 in place of 06:37 has dropped the morning rather than shortened it. The same reading of the store found the shape that produced the pages this loss hid: `rewrite_not_compacted` refused only a rewrite that started at or over the threshold *and* landed there, so a page just under it could be rewritten straight to the cap. That is where the ceiling-hugging days came from — 28 days of the store peak at 4,991 under a 5,000-character cap and at 7,979–7,993 under an 8,000 one, so the number a page fills to is the number it is given. The rule is now one line, a rewrite lands under the threshold from either side: from above because a rewrite there *is* a compaction and has to free something, from below because growth is an append's job and an append is measured against the whole it makes. The two defaults move with it — `LLM_MEMORY_DIARY_MAX_CHARS` from 8,000 to 12,000, `LLM_MEMORY_DIARY_COMPACT_AT` from 6,000 to 10,000 — so a day with a morning and an evening fits without one of them being compressed on arrival; the cap now bounds only the first body a day is given, since every rewrite has to land under the point. The schema a model reads had the same defect one layer over: `Remember`'s `body` and `handover` fields stated 8,000 and 700 by hand, so the release that raised the diary's page would have shipped a schema still saying 8,000. A tool may now declare `__description__` as a callable, resolved in `create_safe_wrapper` where the tool is built — which is after `zrb_init.py`, so the number in the text is the one the run enforces, as R3 requires — and `remember` uses it to state the three lengths it applies. The parameter fields say what they are for and no longer repeat a number.

Neither rule claims to know what a rewrite kept — that stays the reviewer's judgement — and all three were seen red first: the reproduction and the compaction that answers it in `test_memory_diary_rewrite.py`, the rules themselves in `test_memory_model.py`, and the growth case in `test_memory_diary_compaction.py`.

- **Tests: a facade is pinned to its exact line count, and the gate checks the house format** (`test/architecture/test_facade_size_budget.py`, `zrb-test.sh`): the budget file was 271 lines, 213 of them comments — a ladder of thirty-five numbered bumps for `llm/presentation/ui/base/ui.py` alone (1200 to 1294), each one teaching the next contributor that raising a ceiling is what a considered change looks like. Its own note claimed "ceilings that only ever go DOWN" and no test could tell: the second test fired only when a budget sat far above its file, so a ceiling raised to fit growth was invisible to it, and a 5% band left 65 lines free on that file regardless. The ladder is gone, the five counts are now their files' exact lengths, and one equality test fails in either direction — over, name the ADR that says the surface grew; under, lower the number in this same diff. Exact counts only hold if formatting cannot move them, so `./zrb-test.sh` now runs `isort --check-only` with `--profile black --force-grid-wrap 0` and `black --check`, the flags `zrb code format` already runs; the tree passed both the day this landed.

- **Breaking: the deprecated setting names are gone** (`src/zrb/config/`, `src/zrb/__main__.py`, `test/public_api_snapshot.json`, `docs/advanced-topics/upgrading-guide.md`): 3.35.0 renamed every on/off switch to `<x>_ENABLED` and kept the old spelling readable, with one warning, for as long as it took to move. Thirty names were still answering in 4.0.0b3 — `ZRB_LLM_ENABLE_REWIND`, `ZRB_WEB_ENABLE_SECURE_COOKIES`, the two prefix-less `ENABLE_*` — and two public methods existed only to serve them, `Config.get_deprecated_env_keys` and `Config.get_field_renamed_from`. The aliases are gone, from the environment and from `CFG`: setting `ZRB_LLM_ENABLE_REWIND` now prints the retired-setting line naming `ZRB_LLM_REWIND_ENABLED`, and `CFG.LLM_ENABLE_REWIND = ...` raises the `AttributeError` a typo does. The reason is not tidiness — an alias in the tree is an example, and every name kept "for now" teaches the next change that keeping the old one is how it is done here. `config/retired.py` records all thirty with what replaces each, `R13` now gives an alias the life of one major, and `config/test_deprecated_settings.py` is gone with the mechanism it covered.

- **Fix: the injected block's budget line says which moment it reports** (`src/zrb/llm/contracts/memory/render.py`, `test/llm/contracts/memory/test_memory_render.py`, `docs/technical-specs/llm-memory.md`): the line read `Core: 2949 of 4000 characters (74%)`, present tense, inside a block that is written into the conversation's first user message and never rewritten — a snapshot wearing a live measurement's grammar. So it could be quoted back as the current figure hours after claims under it had been closed, and the reasoning built on it described a store state that no longer existed. The line now opens `Core as of this block:`, which costs seven characters of the 4,000-character budget and turns a stale number from a trap into what it always was: the core when the block went in. Changes since still arrive on their own terms — a `<memory-delta>` line for every claim written, revised or retired — which is why the block can afford to be a snapshot: refreshing it in place would rewrite a message already in the transcript, and invalidate every cached token after it.

- **Improvement: `DelegateToAgent` says when to fan out, and what a sub-agent's report is worth** (`src/zrb/llm/capabilities/tool/delegate/runner.py`, `test/llm/capabilities/tool/delegate/test_delegate_tool_construction.py`): the description explained how to fan out — `tasks=[...]`, `background=true`, `isolate_worktree` — and never when, so the threshold was whatever the turn guessed. It now says to fan out when the units' working sets will not fit at once or when they must run in parallel, as one batch in one detached call, and that a unit readable in one or two Reads is cheaper done inline — a delegation re-sends its own context every round, so it costs tens of times what reading the unit does; states the envelope every unit shares; that a report is a lead the parent reproduces with one command of its own before it decides; and that `isolate_worktree: true` is for concurrent units that may write the same files, since an isolated worktree keeps its branch unmerged — a lone writing unit shares the tree, so its change is where the parent can use it. It sits in the tool description because the delegate tools reach the main agent alone — the rule arrives with the tool and leaves with the `minimal` profile that drops it.

- **Security: the sandbox enforces the boundary it describes** (`src/zrb/llm/capabilities/sandbox/bwrap.py`, `src/zrb/llm/capabilities/sandbox/fs_policy.py`, `src/zrb/llm/engine/agent/gates.py`, `src/zrb/llm/capabilities/permission/policy.py`, `docs/llm/sandbox.md`, `docs/llm/permission-policy.md`, #1017, #1021): `bwrap` mounted a fresh `/proc` but left the host PID namespace shared, so the procfs listed host processes and `/proc/<pid>/root` reopened the deny-read paths the sandbox hides; it now passes `--unshare-pid`. The filesystem gate judged a call's path argument while `Grep`, `search_files` and `AnalyzeCode` opened every file beneath it, so a parent of a deny-read root or a symlink inside the workspace surfaced protected content; both readers now ask `is_read_allowed` for each file they open. The key lists that decide what the gate checks gained the spellings plugins use (`filePath`, `dir_path`, `destination`, ...), and a `DENY` rule whose pattern matches no recognized key fails closed instead of falling through to a later allow.

- **Security: a web fetch and a background shell stay inside their boundaries** (`src/zrb/llm/capabilities/tool/web/`, `src/zrb/llm/capabilities/tool/shell/background.py`, `src/zrb/llm/capabilities/tool/shell/capture.py`, `docs/configuration/llm-tools.md`, #1028, #1029): `WebFetch` handed any URL to Playwright or `requests`, so `file://` returned local files and `http(s)` could reach loopback, private, link-local or cloud-metadata hosts; it now accepts only `http`/`https`, resolves and validates the host, and re-validates every redirect hop on the pinned path, with `LLM_WEB_ALLOW_PRIVATE_HOSTS` as the opt-in; the browser path routes every request through the same guard. SerpAPI errors name only the exception type and host, so the request URL and the API key no longer reach the model. A background shell now gets the foreground's 8 MB asyncio line limit and a 256M-character spill cap, and `poll`/`collect`/`kill` report another web session's handle as unknown, as `summary` already did.

- **Security: the rendering path resolves through a loopback CONNECT proxy, not Chromium** (`src/zrb/llm/capabilities/tool/web/pinned_proxy.py`, `src/zrb/llm/capabilities/tool/web/tools.py`, `docs/configuration/llm-tools.md`, #1028, #1045): the opt-in browser path still let Chromium resolve the target after the URL guard had approved the name, so a name that answered publicly during the check could answer loopback when the browser connected. Chromium now receives only a `127.0.0.1` CONNECT proxy; the proxy resolves each request target once, connects to the address it resolved, and tunnels the browser's bytes to the socket it opened, so the browser's own resolver is no longer part of the decision. The browser path stays behind `LLM_WEB_ALLOW_PRIVATE_HOSTS`, and applying the public-address check inside the proxy is what a rendering default needs first.

- **Security: persisted session state masks both spellings of a secret and writes atomically** (`src/zrb/session/session.py`, `src/zrb/session_state_logger/file_session_state_logger.py`, `src/zrb/util/owner_only.py`, #1018): `_get_secret_input_names` collected only the declared input name while `BaseInput.update_shared_context` stored the snake_case alias too, so `PasswordInput("db-password")` persisted `{"db-password": "***", "db_password": "s3cr3t"}`; both spellings are masked now. The state file is written to a unique temporary file and `os.replace`d in, so a concurrent web read no longer sees an empty or partial file, and `list` skips an entry it cannot read instead of returning a 500. An existing 0644 state file is narrowed with `fchmod` before it receives private text, which `O_CREAT|O_TRUNC` did not do.

- **Security: history backups live in their own directory, so a name cannot escape the history root and rotation cannot delete a live conversation** (`src/zrb/llm/capabilities/history_manager/file_history_manager.py`, `docs/architecture/3-peripheral-flow/history-and-compaction.md`, #1020): a backup was another `<name>-<timestamp>.json` beside the live transcript, so a client-supplied base name such as `../escaped` wrote outside `LLM_HISTORY_DIR`, a real conversation `standup-2026-11-20-09-00` looked like a backup and was deleted by rotation, and two concurrent saves shared a predictable `.tmp` file. Backups now live under `backups/<safe name>/`, paths are containment-checked after resolving symlinks, and the temporary file is a `mkstemp` + `os.replace`. Backups written flat before this change stay where they are and remain readable; classifying them would need the same guess that made `standup-2026-11-20-09-00` look like one.

- **Fix: a turn answers the calls it defers, and its agent mode is its own** (`src/zrb/llm/engine/agent/run/deferred_calls.py`, `src/zrb/llm/presentation/ui/turn_execution.py`, #1019, #1025): `_resolve_approval` returned `None` when no approval channel, tool confirmation or `ask`/`force_ask` policy applied, and pydantic-ai accepts only a bool, `ToolApproved` or `ToolDenied`, so a deferred call with no one to answer it resumed into `UserError` and was lost; that fall-through now returns `ToolDenied` with a reason, and `rebuild_for_denials` clears the calls it cannot run. `run_turn` set the turn's agent mode on the process-wide `AgentModeState` before `llm_task.async_run`, so two interleaved runs inherited each other's mode; the setter and the run now sit inside `enter_agent_mode_scope()`/`exit_agent_mode_scope()`, which copies the run's final mode back for the `ui.plan_mode_active` badge.

- **Fix: a live sub-agent session has one owner turn, and a failing factory fails the delegation** (`src/zrb/llm/orchestration/subagent/live_session.py`, `src/zrb/llm/orchestration/subagent/building.py`, #1022): `add_session` registered an already-running delegation as `"idle"`, so a human message arriving between model rounds was queued and also spawned a continuation — two turns on one session — and a cancelled turn's `finally` could idle the session under its replacement and append `<Done>` or report a stale reply. The delegation now claims `"running"` at registration, and only the task that still owns a session resets it, writes `<Done>` and reports back. `create_agent` also caught every exception from a definition's `agent_factory` and fell through to an agent with the definition's empty prompt and tools; when the factory is the definition's only source, the failure is now raised through the delegate tool instead.

- **Fix: the turn keeps the continuation it accepted, and its recovery writes report and retry failures** (`src/zrb/llm/engine/agent/run/session_extension.py`, `src/zrb/llm/engine/agent/run/checkpoint_writer.py`, `src/zrb/llm/engine/agent/run/turn_snapshot.py`, #1039, #1038): `ExtensionState` captured the output and history only at the first extension while every later one overwrote `return_extended`, so a block-to-continue followed by a default `systemMessage` extension returned the pre-continuation answer and discarded the continuation the hook asked for; the first side-effect extension now freezes an explicit answer pair, a replacing extension clears it so the continuation's own result is frozen next, and later side-effect runs cannot overwrite it. `CheckpointWriter` cleared `_in_flight` in a `finally`, so a `checkpoint_fn` that raised on call or returned a non-awaitable left `drain` nothing to observe and the waiting snapshot lost; the failed task is now kept for `drain`, which logs it and retries the snapshot. A snapshot timeout is retried on a later turn instead of blacklisting the workdir, which only an over-budget directory still does.

- **Fix: a non-positive rate-limit budget is refused instead of waited on** (`src/zrb/llm/contracts/config/limiter.py`, #1036): `LLMLimiter.acquire` promised that a zero per-minute budget blocks every request, but its wait loop could never end — a request budget of `0` makes `len(request_log) < 0` permanently false and a token budget of `0` rejects every positive ask — so the run hung while the notifier repeated the throttle message. `acquire` now checks both budgets before the loop and raises a `RuntimeError` naming the setting and its value; pacing off is still a no-op, and positive-budget pacing, including a request larger than a whole minute, is unchanged.

- **Fix: readiness checks reject a non-positive interval, bound a TCP connect, and stop monitoring a finished action** (`src/zrb/task/http_check.py`, `src/zrb/task/tcp_check.py`, `src/zrb/task/base/params.py`, `src/zrb/task/base/monitoring.py`, `src/zrb/task/base/execution.py`, `src/zrb/callback/callback.py`, `docs/task-types/readiness-checks.md`, #1023, #1024): `HttpCheck` and `TcpCheck` slept for `interval`, so a zero — passed in or set through the millisecond setting — made `asyncio.sleep` return at once and hammered the endpoint; the resolved value is now rejected with a `ValueError` naming it, and `TcpCheck`'s connect is bounded at one second, which its timeout handler had assumed. `monitor_task_readiness` looped until the session ended and never noticed its action had returned, so a finite task with `monitor_readiness=True` hung `Session.wait_deferred`; it now stops on `action_coro.done()` and does not restart a finished action. A `readiness_failure_threshold` below 1 is clamped to 1 inside the monitor, a raising `retry_if` means "not retryable" without replacing the action's error, and `Callback.async_run` re-raises `SystemExit`/`GeneratorExit`.

- **Fix: a task renders against its own context, and the file-operation tasks touch only their own files and arguments** (`src/zrb/context/context.py`, `src/zrb/context/shared_context.py`, `src/zrb/task/scaffolder.py`, `src/zrb/task/rsync_task.py`, #1027, #1026, #1033): `Context.render` delegated to `SharedContext.render`, which binds `"ctx": self` — the shared context — so a `Tpl` action could not see the task's own `Env` while a callable action could; the helper dictionary moved into `render_template`, and `Context.render` now passes the task context. `Scaffolder` transformed every file under the destination, so scaffolding into an existing directory rewrote files it never wrote; `_copy_path` now returns the files it actually wrote and only those are transformed. `RsyncTask` interpolated its source, destination, key and `--exclude-from` unquoted and never validated the pair; every value is now `shlex.quote`d and a command needs exactly one local and one remote side, so a local-to-local copy must be a plain `rsync` or `CmdTask` rather than an `RsyncTask`.

- **Fix: the text utilities stop dropping or misreading their input** (`src/zrb/util/yaml.py`, `src/zrb/util/string/format.py`, `src/zrb/util/markdown.py`, `src/zrb/util/cron.py`, #1035): `yaml_dump`'s multiline presenter rstripped every line, dropping trailing spaces and the final newline from a value the tool arguments are edited from; it now passes the original string through, so PyYAML picks a lossless scalar. `fstring_format` parked `{{`/`}}` as single sentinels and misread `{{{x}}}` as one expression; a single-pass scanner renders `{{{x}}}` as `{42}` and `{{literal}}` as `{literal}`. `_adjust_markdown_headers` closed a fence on any line starting with a run, so an inner ```` ```python ```` popped the outer block; a close is now a run of the same character with nothing but whitespace after it. `parse_cron_field` accepted `70/5` and `5-1` as an empty set; range endpoints are validated and a reversed range raises.

- **Fix: the error classifier reads every provider body and stops calling a billing error a context overflow** (`src/zrb/llm/engine/agent/run/error_classifier.py`, #1034): `_get_body_message` read only `body["message"]`, so Anthropic's `body["error"]["message"]` and Bedrock's `body["Error"]["Message"]` never reached the invalid-tool check; all three shapes are read now, with `str(e)` as the fallback. The invalid-tool test matched `tool` plus any of `unknown`/`invalid`/`not found` anywhere, so a 400 for "invalid function arguments" told the model it used a nonexistent tool; it now needs a no-such-tool phrase that names the tool. Any "max tokens" or "token limit" counted as context overflow, so billing and validation errors pruned history; a context word (or `ModelContextWindowExceededError`) is now required, and 401/403/404 win before the context branch.

- **Fix: a clipped archive, a scanned PDF and an unreadable memory note are no longer lost silently** (`src/zrb/llm/engine/summarizer/history_summarizer.py`, `src/zrb/llm/contracts/util/attachment.py`, `src/zrb/llm/contracts/memory/migrate.py`, `src/zrb/llm/contracts/memory/store.py`, #1030, #1037, #1040): `_clipped_tail` sliced the verbatim source by the rendered tail's length, so a trailing pending tool call shifted every index and the archive held the neighbour of the clipped result instead of its middle; the slice now starts from the whole tail's size. `normalize_attachments` appended an empty string when `extract_pdf_text` returned `""` for an image-only PDF, so the document vanished from the prompt; the text is appended only when it is non-empty and an image-only PDF falls through to the binary attachment. The memory migration wrote `.version` even when a note was unreadable, so that note was never retried; `read_document_strict` separates an empty note from an unreadable one, and the migration leaves `.version` unwritten until every note is readable.
