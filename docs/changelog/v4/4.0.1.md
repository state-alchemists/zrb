## 4.0.1 (November 27, 2026)

- **Security: no automatic approval reaches a hard ask** (`src/zrb/llm/engine/agent/run/hard_asks.py`, `src/zrb/llm/orchestration/subagent/yolo.py`, `docs/adr/adr-0146.md`): two calls the documentation promises a person will see were approved without one. A call carrying `run_sandboxed: false` — the escape hatch `docs/llm/sandbox.md` and ADR-0065 say is never auto-approved — reached yolo, which approved it; the inheritance checker now answers `False` for that argument, so the call falls through to the cascade. A write to the MCP config was an ordinary edit, though its `command` and `args` start a host process in a later session, outside `build_sandboxed_argv`, the filesystem gate and every approval prompt; writing that file is now a hard `ask` above yolo, and a denial in an unattended run. The two hard asks live in one module, `hard_asks.py`, and the second decision is recorded as ADR-0146.

- **Security: sandbox containment is decided by the disk, and a glob cannot leave the directory it judged** (`src/zrb/llm/capabilities/sandbox/fs_policy.py`, `src/zrb/llm/capabilities/tool/file/listing.py`, `src/zrb/llm/engine/agent/gates.py`): `is_within` compared `os.path.normcase`d strings, and `normcase` is the identity on POSIX, while `realpath` keeps the caller's casing on a case-insensitive volume — so `~/.SSH/KNOWN_HOSTS` compared as outside `~/.ssh` and was readable. `is_within` is now two functions, `is_read_within` and `is_write_within`: each case-folds first, then confirms by `(st_dev, st_ino)` against the root and each existing ancestor, so the disk answers and nothing is written to find out. The two directions part company where the disk cannot confirm — a read errs toward refusing, a write never overrules it. Separately, `glob_files` joined the pattern onto `path`, which discards `path` for an absolute pattern and climbs out of it for one containing `..`, so the search listed files the gate never judged; such a pattern is refused with a suggestion to name the directory with `path`, and `pattern` joins the read-checked argument keys, so a pattern naming a deny-read root is refused before the search starts.

- **Security: a `cli_only` task stays off the web, and a 404 names nothing** (`src/zrb/runner/chat/chat_api_route.py`, `src/zrb/runner/web_route/node_page/node_page_route.py`, `src/zrb/runner/web_util/task_lookup.py`): three web entry points — the node page, the task lookup behind the JSON routes, and the `llm chat` resolver — called `extract_node` without `web_only=True`, so a task hidden from web listings still resolved by URL and ran. They resolve the tree as the web sees it now, and a hidden task answers 404 exactly like a name that does not exist. The 404 page also rendered `NodeNotFoundError`'s `Did you mean ...?` candidates to anyone who could load the root group, hidden aliases among them; it says `Not found` and nothing else.

- **Security: an MCP config this process never loaded is refused** (`src/zrb/llm/capabilities/tool/mcp.py`, `src/zrb/llm/engine/agent/tool_seed.py`, `docs/adr/adr-0147.md`): the MCP config decides what runs, and the loader reloaded it per run so a long session picks up an edit made on purpose — which also meant a file written between runs started a host process no approval had ever covered. A config is honored only if its SHA-256 still matches the bytes this process read and parsed; one that appeared or changed is refused with a warning that names the file and says why, and the other configs still load, so one unexpected file does not disable MCP for the session. The baseline is per process, with `clear_mcp_config_provenance()` to reset it. The user-facing cost is a restart after an intentional edit, which the warning states (ADR-0147).

- **Fix: a deferred `ask` keeps its capability** (`src/zrb/llm/engine/agent/run/deferred_calls.py`, `src/zrb/llm/engine/agent/run/tool_capabilities.py`): a deferred `ToolCallPart` carries a name and its arguments and no capability tag, so `tool_capability(part)` answered `UNKNOWN` and a rule keyed `edit:ask` fell through to a later `*:allow`. The name → capability map the skip decision already built is now registered when the agent is built, and the cascade reads it by the name the model saw.

- **Fix: cleanup no longer cancels itself, and shutdown always runs session cleanup** (`src/zrb/runner/web_app.py`, `src/zrb/session/session.py`): the leftover-task sweep collected every task except the main one — the task running the sweep among them — cancelled them, then waited a grace period it had just aborted; the sweep now excludes itself, and the grace period ends by reporting any survivor by name. A task run that ignored cancellation made `asyncio.wait_for` raise `TimeoutError` out of the shutdown path before `cancel_all_sessions()` ran, so a chat session's cleanup could be skipped; the timeout is reported and swallowed, and the cleanup always runs.

- **Fix: an unknown `@` cron preset fails at construction instead of never firing** (`src/zrb/util/cron.py`, `src/zrb/task/scheduler.py`, `src/zrb/builtin/cron.py`): `match_cron` refused only what it could not parse, so a preset it did not know matched nothing at all and a scheduler sat on "Monitoring" forever. The preset list is now one `validate_cron_expression` in `util/cron.py`, the same registry the matcher dispatches on, so the two cannot disagree; the scheduler calls it for a literal at construction and for a rendered pattern the first time it is used, and the built-in cron task uses it instead of a private copy and reports the message it raises.

- **Fix: a condition-skipped task skips its successors** (`src/zrb/task/base/execution.py`, `src/zrb/task/base/lifecycle.py`, `docs/adr/adr-0013.md`): a false `execute_condition` marked the task skipped and returned, and its explicit successors ran anyway — the task was reported as never having run while everything downstream of it did. They are marked skipped now, the way the permanent-failure path marks them, so their own downstreams resolve instead of waiting on a task nobody started. Skipping on `execute_condition` was already ADR-0013's decision; this makes the successors follow it.

- **Fix: an edit keeps a CRLF file's bytes** (`src/zrb/llm/capabilities/tool/file/edit.py`): `replace_in_file` read with universal newlines and wrote back translated, so a one-line edit in a CRLF file rewrote every line's bytes. Both ends use `newline=""` now, so the bytes read are the bytes written, and the observation record is normalized to `\n` first, because the store keys on the form a default reader sees.

- **Fix: truncation stays under the cap it reports** (`src/zrb/util/truncate.py`, `src/zrb/llm/capabilities/tool/file/read.py`): `truncate_chars` appended its marker after cutting at `max_chars`, so the result was longer than its own limit, and `read_file` measured the budget before line numbering, so the delivered body exceeded the figure its header reported. Both count the whole result now — marker and `cat -n` prefixes included — and reserve room for the marker before cutting.

- **Fix: a remote index line cannot raise** (`src/zrb/remote/execution.py`): `parse_probe_output` used `isdigit()`, which is true for `²` while `int('²')` raises, and it converted an arbitrarily long digit run that `int()` refuses. A non-decimal, over-long or out-of-range index is ignored now, so an unreported target keeps its `error` instead of losing the line.

- **Improvement: the prompt says what makes a reply easy to read** (`src/zrb/llm/contracts/shared/markdown/workflow.md`, `src/zrb/llm/contracts/shared/markdown/profile.capable.md`, `docs/llm/programming-the-prompt.md`): the shape of a reply was one clause in the capable profile — "keep the final response short" — so a deployment on the standard profile had no rule about it at all, and whether a reply led with its answer, repeated itself in the detail, or reached for a table was left to the model. `workflow` now owns the rule in one section: the answer in the first sentence, one idea per sentence, a table only for things compared and prose for a chain of reasoning, nothing restated below the first line, and length proportional to what the reader has to do. The capable profile's clause is removed rather than left as a second copy, and the prompt guide names reply shape among what `workflow` holds. `workflow` grows from 633 to 802 words — 59 for the turn-ending rule below and 105 for this one, with 13 coming back from the capable profile.

- **Improvement: the workflow step says a turn never ends on an announcement** (`src/zrb/llm/contracts/shared/markdown/workflow.md`): step 3 said to make the change, and nothing said what an ending is, so a turn could close on "I am fixing all ten findings now" with no tool call after it — the runner reads that text as the answer, the turn settles, and the work waits for the user to type again. Step 3 now names the two shapes an ending takes, the complete answer or the thing being waited on and whose answer it is, and says why an announcement cannot be kept: the turn is over the moment the tool calls stop. It is 59 words in a section sent on every turn.

- **Improvement: the spoken-block rules say which one wins** (`src/zrb/llm/contracts/shared/markdown/speech_live.md`): six rules governed one block, and two pairs of them could not both be obeyed. A decision reply must fit "about three sentences" and carry "a closing line naming what is being approved"; "the block is the answer" fights "say the number and let the table hold the rest" whenever the number lives in the table. The model resolved the conflict by guesswork, and a reply that repeats its number in the block and again in the table is what obeying both looks like. One 27-word line now sets the order — the answer, the one fact the listener must act on, nothing else, the third cut first — and the section grows from 590 to 617 words.

- **Improvement: the ask rule has one owner** (`src/zrb/llm/contracts/shared/markdown/principle.md`, `src/zrb/llm/contracts/shared/markdown/profile.standard.md`): "ask only when you must" was stated twice, in `principle` (22 words) and in the standard profile (33), and the profile's copy listed three sources and one exception in a single sentence. `principle` now owns the full rule in 18 words. The profile keeps autonomy plus the one clause it cannot borrow from a section that might be absent: "but confirm anything destructive or hard to reverse", since `include_sections` can drop `principle` and the profile alone would otherwise say to finish the work without a counterweight. 29 words come back, and a deployment reading both no longer has two thresholds for asking.

- **Improvement: the spoken-block prompt says what an explanation's block is** (`src/zrb/llm/contracts/shared/markdown/speech_live.md`, `docs/configuration/llm-voice-camera.md`): every line described the block as a status report — what happened, whether it worked, what the user has to decide — so a reply that explained how something works had nothing the rules licensed it to put there, and the one worked example was a fix report. The definition now names an explanation's block as the one thing it establishes, the self-sufficiency test asks only for a fact the listener must act on rather than any fact they must understand, and a second worked example shows a conclusion in the block with its table below it. The prompt is 380 characters longer, paid for by cutting the sentence under the first example, and it is sent on every turn while speech is on.

- **Fix: the examples say how many of them are judgment calls** (`src/zrb/llm/contracts/shared/markdown/example.md`): the introduction said "the last three are judgment calls: when to keep going, when to proceed alone, and when to stop and ask", but six examples follow and only two are that pair — proceeding alone and stopping to ask. It says two now. 6 words.
