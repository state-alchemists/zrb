## 4.0.1 (Unreleased)

- **Improvement: the spoken-block prompt says what an explanation's block is** (`src/zrb/llm/contracts/shared/markdown/speech_live.md`, `docs/configuration/llm-voice-camera.md`): every line described the block as a status report — what happened, whether it worked, what the user has to decide — so a reply that explained how something works had nothing the rules licensed it to put there, and the one worked example was a fix report. The definition now names an explanation's block as the one thing it establishes, the self-sufficiency test asks only for a fact the listener must act on rather than any fact they must understand, and a second worked example shows a conclusion in the block with its table below it. The prompt is 380 characters longer, paid for by cutting the sentence under the first example, and it is sent on every turn while speech is on.
- **Improvement: a turn that ends announcing work it never started is asked to start it or name what it waits for** (`src/zrb/llm/capabilities/hook/builtin/unfinished_action.py`, `src/zrb/llm/contracts/shared/markdown/workflow.md`, `docs/configuration/llm-context.md`): the turn is the unit of work, so a closing "I am fixing all ten findings now" with no tool call behind it settled the turn and left the findings for the human's next message — twice in two minutes in one session. A default-on Stop hook now reads the closing message, blocks once when it claims work in progress, and quotes the claim back with a request for the work or for what is really being waited on. No model call and no file read: one lexical pass, once per turn, and offers ("I'll review it when you hand it over") and closings ("I'm done") are left alone. The prompt states the same rule in step 3, so the gate is the backstop rather than the only teacher.
