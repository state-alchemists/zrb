## 3.41.0–3.41.4 (November 17, 2026–November 19, 2026)

_Cumulative summary of the 3.41.0–3.41.4 line._

- **Feature: one run can name the chat settings it starts with** (`src/zrb/builtin/llm/chat.py`, `src/zrb/builtin/llm/chat_flags.py`): `zrb chat` gained `--voice`, `--volume`, `--thinking`, `--profile`, `--memory`, `--self-review` and `--judge`, so a quieter voice, a cheaper thinking level or a session with no memory no longer costs an exported variable that outlives the try. An empty flag leaves the deployment's value alone and a value overrides it for this run, as `--sandbox` already worked; values are cast through `CFG` as `/set` casts them, `--volume` is held to 0-200, and `--profile` is checked against the profile names rather than accepted and silently ignored.
- **Feature: a safe shell command can be auto-approved for one run** (`src/zrb/llm/approval/judge_state.py`, `src/zrb/llm/ui/default/output.py`, `src/zrb/llm/tool_call/judge_note.py`, `docs/adr/adr-0141.md`): `--judge off|on|auto-approve` puts ADR-0141's second grant on a command line typed in full, where before it was a deployment setting only; `/judge on` withdraws it for its own session, so a keystroke can move the judge towards asking and none can hand a prompt away, and the info bar shows `AUTO` when a `safe` verdict may skip the prompt. The approval line now names what raised the risk — `sandbox off`, a non-empty uncommitted count — read from the call's arguments and `git status` rather than from the model. ADR-0141 also records why a launch may reach that grant where a keystroke may not, and corrects its claim about the judge's tokens in `/usage`, counted under `shell_judge` since `27ae01c34`.
- **Fix: a full day is handed to the reviewer instead of refused** (`src/zrb/llm/hook/builtin/memory_reviewer.py`, `src/zrb/llm/agent/hook_agent.py`, `src/zrb/llm/tool/memory.py`, `src/zrb/llm/prompt/markdown/memory_reviewer.md`): a diary page caps at 8,000 characters, and once it filled every later append was refused to a reviewer that could not tell a full page from a day that had not changed — on 2026-11-17 the body reached 7,962 characters at half past ten and recorded nothing for the rest of the day. A turn now opens with the date and the room left, and under 600 characters the reviewer is handed the body and asked for the whole day back, shorter; `Remember` takes `body_digest` and refuses a rewrite of a day that moved, so two sessions cannot replace each other's paragraph. The note carries the clock too, because with no hour to check the reviewer invented one — three paragraphs about the same morning read "late in the morning", "late in the evening" and "late in the night" on 2026-11-18. A claim is now one sentence of what is true or what was decided plus the reason, and a turn that already called `Remember` or `Forget` is revised rather than answered twice, which is how one subject came to hold two files.
- **Fix: a plugin directory that is not there is no longer reported as unreadable** (`src/zrb/util/dir_search.py`, `test/util/test_dir_search.py`): every plugin scan walked `<plugins root>/marketplaces/`, and a missing directory raised `FileNotFoundError`, reported as `Failed to read directory` with a traceback — so a project carrying its own `plugins/` folder with no marketplace installed, such as `ai-workflow`, warned on every `zrb llm chat`. A missing directory now contributes nothing and says nothing; one that exists and cannot be read is still reported.
- **Refactor: the last of the 4.0 layering moved, and several imports moved with it** (`src/zrb/llm/`): `UIConfig`, the prompt reader, the output buffer's two helpers, the steering helper and the tool-name resolver all went down to `llm/contracts/`; a sub-agent's identity is read from `HasActivityTracking` rather than from `BufferedUI`; a tool registry read before its seed arrives is no longer frozen empty, and an agent hook resolves its tools from the engine's own seed; an interactive chat is presented from `presentation/`; and a resumed session is built in `llm/resumed_session.py`, so `subagent/` and `task/` no longer import each other. **`import zrb.llm.ui.ui_config`, `zrb.llm.prompt.prompt`, `zrb.llm.ui.output_chunk`, `zrb.llm.ui.tracked_spans` and `zrb.llm.subagent.tool_resolver` no longer work: import them from `zrb.llm.contracts.*`.** With the last cycle gone, `KNOWN_UPWARD_EDGES` and both layer-0 allowlists are empty, and the ratchets refuse a new entry either way. `ToolRegistry` gained `tools_by_name()`; the API snapshot was regenerated in the same diff. No behaviour change.
- **Tests: the output buffer's boundaries are pinned, not only its middle** (`test/cmd/test_command_output_capture.py`, `scripts/mutation_ratchet.py`, `test/llm/screenshot/backend/test_tool.py`): a 39-mutant sample of `cmd` left twenty alive, eight of them in the five comparisons that bound a child's output, because every test fed output that stayed comfortably inside the limits — one survivor being the trailing-byte escape ADR-0097's calibration had already named. Five tests now sit on the boundaries, `cmd`'s kill rate rose from 49% to 69%, and `FLOORS["cmd"]` from 30 to 64, with `SAMPLE_SIZES` pinning the 39. The screenshot hang test's 50 ms capture budget became one second, because a loaded Windows runner spent it creating a temporary directory before spawning anything.
