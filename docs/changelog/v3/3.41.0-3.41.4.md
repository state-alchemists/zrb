## 3.41.0–3.41.4 (November 17, 2026–November 19, 2026)

- **Feature: one run can name the chat settings it starts with** (`src/zrb/builtin/llm/chat.py`, `src/zrb/builtin/llm/chat_flags.py`): `zrb chat` gained `--voice`, `--volume`, `--thinking`, `--profile`, `--memory`, `--self-review` and `--judge`, so a quieter voice, a cheaper thinking level or a session with no memory no longer costs an exported variable that outlives the try. One rule, the one `--sandbox` already followed: an empty flag leaves the deployment's value alone, a value overrides it for this run. Values are cast through `CFG` as `/set` casts them, so a flag and a command refuse the same strings; `--volume` is held to 0-200 rather than clamped, and `--profile` is checked against the profile names, because both would otherwise be accepted and silently do nothing.
- **Feature: a safe shell command can be auto-approved for one run** (`src/zrb/llm/approval/judge_state.py`, `src/zrb/llm/ui/default/output.py`): `--judge off|on|auto-approve` reaches the half of ADR-0141 that was a deployment setting only, as a command line typed in full rather than a keystroke. `/judge on` now withdraws that half for its own session, so a keystroke can move the judge towards asking and none can hand a prompt away, and the info bar says `AUTO` in the red pair when a `safe` verdict may skip the prompt.
- **Improvement: the approval prompt says what the judge saw** (`src/zrb/llm/agent/shell_judge.py`, `src/zrb/llm/tool_call/judge_note.py`): the judge line carried its level and one sentence, never the facts the judge was given, so a reader saw the conclusion without the basis. It now names the ones that raise the risk — `sandbox off`, a non-empty uncommitted count — and they come from the call's arguments and `git status` rather than from the model, staying silent where the sandbox is on and the tree is clean.
- **Documentation: ADR-0141 gains the launch grant and loses a stale consequence** (`docs/adr/adr-0141.md`): the record now says why a launch may reach the second grant where a keystroke may not, and its claim that the judge's tokens never reach `/usage` is corrected — they have been counted under `shell_judge` since `27ae01c34`.
- **Improvement: the reviewer writes a decision, not a report** (`src/zrb/llm/prompt/markdown/memory_reviewer.md`): a claim was "what is true", so the injected block read as a pile of statements written by someone else, and the reason behind each one was pushed into `body`, which is never injected. A claim is now one sentence carrying what is true, or what was decided, and the reason the turn gave for it — in the first person when the decision is the assistant's, and plainly when it is a fact about the project or a preference the user stated, because a fact narrated as `I` is a lie in that voice. A turn that already called `Remember` or `Forget` is now the priority item rather than a second claim: the reviewer searches that subject and revises its id instead of filing a second answer beside it, which is how one subject came to hold two files. Its sentence is kept where it already says what is true, and the reviewer may still answer `skip` when the flagged turn shows nothing durable.
- **Fix: a full day is handed to the reviewer, not refused silently** (`src/zrb/llm/hook/builtin/memory_reviewer.py`, `src/zrb/llm/agent/hook_agent.py`, `src/zrb/llm/tool/memory.py`): a diary is written one paragraph per turn into a page capped at 8,000 characters, and the reviewer holds one turn's transcript, never the page. Once the day filled, every later append came back refused to a reviewer that could not tell a full page from a day that had not changed — on 2026-11-17 the body reached 7,962 characters at half past ten in the morning and recorded nothing for the rest of the day. Every turn now opens with the date and how much room the page has left, and once 600 characters or fewer remain the reviewer is handed the body and asked for the whole day back, shorter, keeping every quoted moment and the reason behind a decision. That rewrite is the one write that can lose another's work — two sessions compacting the same day replaced each other's paragraph — so `Remember` takes `body_digest`, the digest shown beside the body, and refuses a rewrite of a day that moved, handing back the day as it is now to merge into. `AgentHookConfig` gained `input_note` for the hand-over: a config is built once and outlives the day it describes, so the note is a function of the context and the store rather than a string fixed at registration.
- **Tests: the hang test's budget outlasts its own start-up** (`test/llm/screenshot/backend/test_tool.py`): the capture budget was 50ms, and a loaded Windows runner spent it creating the temporary directory before the program was spawned, so the test failed on "no time left for this capture" — a real branch, but not the timeout it was asserting. One second leaves room for the start-up overhead while staying far under the five-second hang, and the spent-deadline branch keeps its own test.
- **Fix: the reviewer is told the hour, so a diary paragraph stops inventing one** (`src/zrb/llm/hook/builtin/memory_reviewer.py`, `src/zrb/llm/prompt/markdown/memory_reviewer.md`): the note handed to the reviewer carried the day's date and how much room its page had, and no clock — while a paragraph is written about a moment that has already passed. With no hour to check, it named one from the shape of the turn, and on 2026-11-18 three paragraphs about events between six and seven in the morning said "late in the morning", "late in the evening" and "late in the night". The note now reads ``Today is `2026-11-18` and the clock reads 06:56``, and the prompt says the clock is the hour the review runs rather than the hour the moment happened, so a turn that carries no time gets "then" and nothing more. The date and the hour come from one read of the clock, so a turn that crosses local midnight cannot be filed under yesterday's date beside today's hour. The note grows by about six tokens a turn.
- **Fix: a plugin directory that is not there is no longer reported as unreadable** (`src/zrb/util/dir_search.py`, `test/util/test_dir_search.py`): every plugin scan also walked `<plugins root>/marketplaces/`, and a directory that does not exist raised `FileNotFoundError`, which the shared helper reported as `Failed to read directory` with a full traceback. Almost no checkout has that directory: a project carrying its own `plugins/` folder with no marketplace installed, such as `ai-workflow`, warned on every `zrb llm chat`, which reads as a broken zrb rather than as an optional tier that is absent. A missing directory now contributes nothing and says nothing; a directory that exists and cannot be read is still reported, because that one is news.
- **Refactor: the sandbox-escape argument is read through one helper** (`src/zrb/llm/tool_call/shell_call.py`, `test/llm/tool_call/test_shell_call.py`): the argument formatter, the auto-approve policy, the sandbox gate and the deferred-approval cascade each compared the raw `dangerously_skip_sandbox` argument themselves. ADR-0141 moved that shape into `shell_call.py`, and four readers kept their own copy — one of them in a file that already imported `is_sandbox_off` sixty lines below. All four now call `is_sandbox_off`, and a test fails if the name is typed as a quoted string anywhere else under `src/zrb`. No behaviour change: the same argument is recognized as before.
- **`UIConfig` moves out of the UI package** (`src/zrb/llm/ui/ui_config.py` → `src/zrb/llm/contracts/config/ui_config.py`, `test/llm/ui/test_ui_config.py` → `test/llm/contracts/config/test_ui_config.py`): the module imports `CFG` and the standard library and nothing from `zrb.llm.ui`, yet it sat in the presentation layer, so `LLMChatTask` — an orchestration-layer task — reached up into `ui/` to type its own `ui_config` slot. It now lives in `llm/contracts/config/` beside the other configuration objects, and that upward edge is deleted from `KNOWN_UPWARD_EDGES`. **Importing `zrb.llm.ui.ui_config` directly no longer works; import `zrb.llm.contracts.config.ui_config` instead.** `from zrb.llm.ui import UIConfig` is unchanged.
- **A sub-agent's identity is read from a contract, not from the UI class** (`src/zrb/llm/contracts/shared/agent_activity.py`, `src/zrb/llm/subagent/parent_message.py`): the "message the main agent" tool asked `isinstance(ui, BufferedUI)` to decide whether the current UI belongs to a delegated sub-agent that has a parent, so the sub-agent package imported the presentation layer to name a class it never used for anything else. `HasActivityTracking` — the read-only protocol `tool/delegate/runner.py` already probes to ask "can this UI feed the activity panel" — now also names `agent_id` and `session_id`, and the tool asks the protocol instead. A UI backend answering those five members is trackable whatever its class is called; one that does not is refused exactly as before.
- **A delegation's buffer comes from the buffer's own module, and `ui/buffered/` is a floor** (`src/zrb/llm/ui/output_chunk.py` → `src/zrb/llm/contracts/shared/output_chunk.py`, `src/zrb/llm/ui/tracked_spans.py` → `src/zrb/llm/contracts/shared/tracked_spans.py`, `test/architecture/test_llm_layering_ratchet.py`, `test/architecture/test_circular_import_allowlist.py`): `tool/delegate/runner.py` names `BufferedUI` in seven annotations, one `isinstance` probe and two constructions, and `background.py` borrowed the class back from it — so a layer-1 tool reached into the presentation layer, and the borrowing made the two modules import each other, deferred by two `# lazy: circular` workarounds. A registered factory was the other way out, but the UI package loads nothing eagerly, so a delegation would have been the first caller to find that registry empty. The ratchet now scores `ui/buffered/` as a floor, as it already scores `ui/fallback/`, and the two stdlib-only helpers a buffer needs have moved to `llm/contracts/shared/` so that everything a buffer imports is L0. With the cycle gone, `background.py` imports the class from its own module, `runner.py` imports the background registry at module level, and both allowlist lines are deleted. **`zrb.llm.ui.output_chunk` and `zrb.llm.ui.tracked_spans` have moved: import them from `zrb.llm.contracts.shared`.** No behaviour change.
- **Steering a live run no longer needs the UI package** (`src/zrb/llm/contracts/shared/live_delivery.py`, `src/zrb/llm/subagent/live_session.py`, `src/zrb/llm/ui/base/queue_delivery.py`): the "message the chosen sub-agent" path reached into `ui/base/message_queue.py` for `steer_into_live_run`, a twenty-line helper whose only requirement of its argument is an `enqueue` method, so the sub-agent registry imported the presentation layer for a function that never touches a UI. It now lives in `llm/contracts/shared/` beside the other L0 leaf helpers; the queue's own send-now path imports it from there too, and the upward edge is deleted from `KNOWN_UPWARD_EDGES`. Its three tests moved to `test/llm/contracts/shared/test_live_delivery.py`. No behaviour change.
- **Tool-name resolution moves below the sub-agent package** (`src/zrb/llm/subagent/tool_resolver.py` → `src/zrb/llm/contracts/shared/tool_resolver.py`, `test/llm/subagent/test_tool_resolver.py` → `test/llm/contracts/shared/test_tool_resolver.py`): the module imports nothing at all — it maps Claude's `Bash` to zrb's `Shell`, reads a tool's registered name, and resolves a name list against a registry and a set of factories — yet it sat in the orchestration layer, so the agent package imported layer three to resolve an agent hook's `tools:`. It now lives in `llm/contracts/shared/` beside `tool_registry.py`, and the upward edge is deleted from `KNOWN_UPWARD_EDGES`. **Importing `zrb.llm.subagent.tool_resolver` directly no longer works; import `zrb.llm.contracts.shared.tool_resolver` instead.** The architecture pages that name it follow the move. No behaviour change.
- **A tool registry read before its seed arrives is no longer frozen empty** (`src/zrb/llm/contracts/shared/tool_registry.py`, `test/llm/contracts/shared/test_tool_registry.py`): the three lists materialized on the first read whether or not a seed had been installed, and `set_seed` then refused — so a caller that ran early, before `zrb.llm.common_tools` had been imported, silently froze every built-in tool out of the process, for the main agent as well as itself. A read now closes the door only once a seed has been folded in, and a seed that arrives late goes in front of whatever was registered in the meantime, so `append_tool` still means "runs last". No behaviour change for a process that imports the built-ins before it reads the registry, which is every command zrb ships. Whatever was registered before the seed keeps its meaning when it lands: an append still runs last, a prepend still runs first, a `remove_tool` stays removed, and a list replaced by `set_tools` — or a factory list replaced by `set_tool_factories` — is not reopened by the built-ins.
- **The built-in tool surface belongs to the engine, and an agent hook reads it from there** (`src/zrb/llm/agent/tool_seed.py`, `src/zrb/llm/agent/hook_agent.py`, `src/zrb/llm/common_tools.py`, `src/zrb/llm/contracts/shared/tool_registry.py`): resolving an `AgentHookConfig`'s `tools:` list asked the sub-agent manager, so the engine package imported the orchestration package to answer a question that was never about sub-agents — and did it inside the function, because the manager's own import pulls the agent package back. The two surfaces are the same one: the manager's registry is `shared/tool_registry.py` plus whatever a host registered on itself, and the manager adds no name the registry lacks. What made the edge hard to delete was loading order, not capability — the registry's seed was installed by `common_tools.py`, three layers up, so an early read found it empty. The set and its lazy seed now live in `agent/tool_seed.py`, which installs the seed when it is imported; `common_tools.py` keeps the host glue that hands the set on. `resolve_agent_hook_tools` reads `tool_registry.tools_by_name()` and `tool_registry.get_tool_factories()`, the deferred import is gone, and `KNOWN_UPWARD_EDGES` is empty. A hook resolves against what zrb ships plus whatever a host registered on the delegation manager — `append_tool` and `append_tool_factory` still reach a hook, and they win a name collision as they do for a sub-agent — reading that manager through `shared/delegation_api.py`, so the agent package still never imports the subagent package. No behaviour change: the same names resolve to the same tools. **`ToolRegistry` gains one public method, `tools_by_name()`,** which is how a hook asks for the set without walking the list itself; the API snapshot is regenerated in this diff. It is an addition — no member is removed, renamed or reordered.
- **An interactive chat is presented from the presentation layer** (`src/zrb/llm/task/chat/running.py`, `src/zrb/llm/ui/session.py`, `src/zrb/llm/contracts/shared/session_presentation.py`, `src/zrb/llm/contracts/shared/feature_config.py`, `src/zrb/builtin/llm/chat.py`): `run_interactive_session` built a UI from the task's own values, replayed the stored conversation onto it, ran its loop and read its display back — and did all of it from the orchestration layer, so `task/chat/running.py` imported `ui/assembly.py`. The one-shot session beside it needs no UI beyond the ones already attached, so the module splits at that line: the interactive half moves to `ui/session.py`, which imports `task/` downward, and `ChatRunning` asks `shared/session_presentation.py` for it. `zrb llm chat` — the only command that offers an interactive chat — registers the runner, as `subagent/manager` registers itself into the delegation facade. `bound_session_ui` moves beside the three functions it wraps in `shared/feature_config.py`, since both halves bind the session's UI. The upward edge is deleted from `KNOWN_UPWARD_EDGES`. No behaviour change for `zrb llm chat`; a task asked to run interactively with no runner registered raises a `RuntimeError` that says so instead of presenting nothing.
- **Prompt text is read below the tools that ask for it** (`src/zrb/llm/prompt/prompt.py` → `src/zrb/llm/contracts/shared/prompt_text.py`, `src/zrb/llm/prompt/markdown/` → `src/zrb/llm/contracts/shared/markdown/`, `test/architecture/test_llm_layering_ratchet.py`): `prompt/` and `tool/` imported each other. A tool that builds its own small agent — the file, code, web and multimodal helpers — read its system prompt with `get_prompt`, while the per-turn live context read the todo manager and the background registry out of `tool/`. Reading a section by name and filling its placeholders needs `CFG` and the filesystem and knows nothing about section order, so that half moves to L0 with its bundled section files, and the edge from `tool/` to `prompt/` is gone; the ratchet's `prompt <-> tool` cycle line is deleted in the same diff. `prompt/` keeps composition. **`zrb.llm.prompt.prompt` no longer exists: import `get_prompt` and `get_default_prompt` from `zrb.llm.contracts.shared.prompt_text`.** No behaviour change — same files, same override chain, same placeholders.
- **A resumed sub-agent session is built in a third unit, and the last import cycle is gone** (`src/zrb/llm/resumed_session.py` new, `src/zrb/llm/contracts/shared/sub_agent_build.py` new, `src/zrb/llm/subagent/building.py`, `src/zrb/llm/task/chat/task.py`, `test/architecture/test_llm_layering_ratchet.py`): resuming a delegated session in the web UI built an `LLMChatTask` inside `subagent/`, while the chat task reached that same manager for its roster and its `@mentions` — so the two packages imported each other, the last entry in `KNOWN_SAME_LAYER_CYCLES`. Neither may name the other now: `resumed_session.py` names `task/` (lazily, when a session is actually resumed), `subagent/` names `resumed_session.py`, and `task/` names neither. The resolved persona both builders share moved to L0 as `shared/sub_agent_build.SubAgentBuild`. Behaviour is unchanged: `SubAgentManager.create_llm_chat_task` still answers with the same `LLMChatTask` and the same persona, and `None` for a definition built from a pre-made agent — including for a caller outside the web route, which is what the lazy import inside the old method used to cover. Both layer-0 allowlists are now empty, and the ratchets refuse a new entry either way.
- **Tests: the output buffer's boundaries are pinned, not only its middle** (`test/cmd/test_command_output_capture.py`, `scripts/mutation_ratchet.py`): a 39-mutant sample of `cmd` left twenty alive, eight of them in the five comparisons that bound a child's output — because every test fed output that stayed comfortably inside the limits. `test_command_kill_pid.py` exceeds `CFG.CMD_BUFFER_LIMIT` by a factor of two and `test_white_label_notices.py` exceeds the line cap by one, so neither could tell `>` from `>=` at the bound. One of those survivors is the escape ADR-0097's calibration named (`decode(b"", final=True)` → `False`, which loses a command's trailing bytes), so the gap was known and had never been pinned. Five tests now sit on the boundaries: a line of exactly the bound is still one line, a chunk holding two lines is printed line by line, a stream ending mid-character flushes it as the replacement character, the cap drops from the front and reports the exact count, and a cap of zero keeps every line without reporting one. `cmd`'s kill rate went from 49% to 69% over the same 39 mutants, and `FLOORS["cmd"]` rises with it, from 30 to 64. A floor justified by a wider sample has to be checked against that sample, so the ratchet now carries `SAMPLE_SIZES`: `python scripts/mutation_ratchet.py cmd` draws 39 mutants, where before it drew the default 25 and would have scored a set the floor was never measured on; `--mutants` still overrides every package. No behaviour change in zrb: every test asserts what the code already did.
