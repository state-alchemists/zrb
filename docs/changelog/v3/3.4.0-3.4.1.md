## 3.4.0 (September 13, 2026)

- **Feature: a pasted markdown, LaTeX or Mermaid message renders instead of echoing raw** (`src/zrb/llm/ui/base/{user_echo,message_queue,replay}.py`, `src/zrb/llm/ui/{base/ui,multi_ui}.py`, `docs/llm/llm-custom-ui.md`, `test/llm/ui/base/{test_user_echo,test_message_queue}.py`, `test/architecture/{test_facade_size_budget,test_multi_ui_fanout_surface}.py`): the user echo printed submissions verbatim, so a pasted table, diagram or fenced block sat in the transcript as source beside the model's rendered reply. A message carrying an explicit markdown construct now goes through the same `render_markdown` path an assistant response uses, live and on replay. Line count is deliberately *not* the signal — a traceback, a log dump and unfenced code are multi-line and plain, and rendering one collapses its line breaks into a paragraph — so `should_render_user_markdown` matches constructs (fences, ATX headings, blockquotes, list items, table rows, `**`, links, `$$`, `\begin{`) anywhere in the text. It omits `__`, since `__main__` and `__init__` appear in every pasted Python traceback and mangling one costs more than losing bold. The echo mechanics live once in `ui/base/user_echo.py` rather than in both the live and replay paths; a rendered echo is a header plus a rendered body rather than one verbatim chunk, so it claims no echo span and editing a queued message stays effective without rewriting the echoed line. `MultiUI.append_markdown` fans the source text to children that render markdown themselves and the pre-rendered text to the rest, and is now listed among the optional enrichment hooks a custom UI may implement.
- **Feature: the `AskUserQuestion` widget wraps at word boundaries and gives each description its own lines** (`src/zrb/llm/ui/default/selection.py`, `test/llm/ui/default/test_selection.py`): the choice window left prompt_toolkit's `wrap_lines` at its default `False`, so a long question or description was clipped at the float's width. Turning wrapping on exposed more: prompt_toolkit wraps at the column, not at spaces, splitting words mid-token (`technolog/y`, `optio/n`), and continuation lines started at column 0, left of the radio gutter, where a wrapped description reads as the next option. The widget now wraps its own text with `textwrap` at the measured float width (terminal columns less the `Frame`'s four), puts each label on its own line with the description wrapped and indented beneath it to the label's column, separates options with a blank line, and pads every line of the highlighted row to full width so the selection bar is one solid block. `wrap_lines` stays on as a backstop for a mis-measured line (a wide glyph, a resize between render and paint). The same missing `wrap_lines` clipped the sub-agent picker (`src/zrb/llm/ui/default/agent_picker.py`, `test/llm/ui/default/test_agent_picker.py`), fixed there too.
- **Fix: output written while a thinking or final-text block streamed was swallowed when that block collapsed** (`src/zrb/llm/ui/output_chunk.py`, `src/zrb/llm/ui/{buffered_ui.py,default/output.py}`, `test/llm/ui/default/test_output_collapse.py`, `test/llm/ui/test_buffered_ui_collapse.py`, `test/architecture/test_collapsible_block_kinds.py`): `mark_thinking_block_start` / `mark_text_block_start` recorded one offset and the collapse spliced from it to the buffer end — "everything after my mark is mine". With a second writer appending, a trigger line, background task output or a sub-agent's forwarded text landing during a live block vanished into the collapsed summary. The tracker shipped in 2.67.0; the keyed live lines rejected this shape one release later, when two concurrent Shell commands were found devouring each other's output (see `update_shell_output`'s note), but the single-slot tracker kept it. A block now tracks its own `[start, end)` as an `OpenCollapsibleBlock` and absorbs only chunks of its own `append_to_output` kind — `"thinking"` or `"streaming"`, each unique to its stream — merging them at the block's end rather than the buffer tail, so a concurrent writer's line stays outside the span. This also keeps `\r` handling honest: a status rewrite erases back to the block's last line, never into a foreign line below. Offset bookkeeping is shared by both paths that rewrite the buffer away from the tail: `replace_output_span` rebased `rendered_blocks` and both keyed span maps but not the block mark, so a shell line growing below an open block left the mark mid-line and the collapse spliced over that line's tail; and absorbing a chunk shifts whatever a concurrent writer put *after* the block, so a live shell or tool-prepare line there must move with it or its next update lands inside the streamed block. Both now go through one `_rebase_tracked_spans`, shifting the open block only for a foreign edit above it, never its own growth. `UIOutput` and `BufferedUI` had the identical shape and both are fixed. Since the collapse keys off the chunk's kind, a streamer printing block content under another kind would silently stop collapsing, so `test_collapsible_block_kinds.py` pins `StreamEventHandler`'s printed kinds against what both UIs register.
- **Improvement: an error with no message is identifiable instead of blank** (`src/zrb/util/exception.py`, `src/zrb/llm/ui/{base/ui,base/exec_commands,base/triggers,multi_ui,default/lifecycle}.py`, `src/zrb/runner/chat/chat_session_runner.py`, `src/zrb/task/base/execution.py`, `test/util/test_exception.py`, `test/llm/ui/base/test_commands_shell.py`, `test/llm/ui/default/test_lifecycle.py`): every UI error path and `BaseTaskExecution`'s retry log formatted the exception as `str(e)`, empty for a bare `raise SomeError()` — yielding `[Error: ]` in the pane and `Attempt 1/3 failed: ` in the log. `exception_summary` prefixes the type name, keeping the message after it only when it does not already quote the class (many provider errors do). Visible change: `[Error: OSError: no shell]` where it used to read `[Error: no shell]`.
- **Tests: the `MultiUI` child-hook guard covers both dispatch shapes, and the API retry budget is pinned end to end** (`test/architecture/test_multi_ui_fanout_surface.py`, `docs/llm/llm-custom-ui.md`, `test/llm/agent/run/test_runner_retry.py`): `test_every_fanout_name_is_recorded` parsed only `_fanout("name")` call sites, leaving the optional child hooks dispatched as `getattr(ui, "name", None)` outside the typo guard and the doc table it calls canonical. It now reads both shapes, bringing `record_tool_call_block` and `update_system_info` under the guard alongside the new `append_markdown`; `start_event_loop` is excluded by name, being `EventDrivenUI`'s alone rather than an output hook. `LLM_API_MAX_RETRIES` was covered only at the unit level (`handle_stream_error`), so `run_agent` is now driven against a provider returning 503: the knob is a *total* attempt count (default 3 = one request plus two retries; `0` and `1` both mean try once), and a run that fails twice then succeeds makes exactly three requests without the task layer seeing the error.

## 3.4.1 (September 16, 2026)

- **Fix: error classifier now treats transient 5xx as retryable even when the message mentions context length** (`src/zrb/llm/agent/run/error_classifier.py`): the priority order was `is_prompt_too_long_error` first, then status codes — so an Ollama 500 with "Maximum context length exceeded" was classified as a permanent `context_length` error and never retried. Transient statuses (429, ≥500) now win over keyword guesses, matching the intent of `handle_stream_error` which already checked `is_retryable_error` first.
- **Improvement: `readiness_check_delay` defaults to `CFG.TASK_READINESS_DELAY` instead of a hardcoded `0.5`** (`src/zrb/task/base/base_task.py`, `src/zrb/task/base/execution.py`, all task subclasses): the pause before the first readiness check is now tunable via env (`TASK_READINESS_DELAY`, default 500ms) without touching individual task definitions. Behavior is unchanged for users who never set the knob.
- **Fix: session graph registration rewritten iteratively** (`src/zrb/session/session.py`): `_register_task_graph` and `get_root_tasks` replaced recursive traversals with stack-based iterations, eliminating exponential blowup on diamond dependency graphs and interpreter stack overflow past ~950 levels.
- **Tests: replace flaky `asyncio.sleep` with polling in chat session runner** (`test/runner/chat/test_chat_session_runner.py`) and pin the e2e tool-policy integration test against `TestModel` (`test/llm/tool_call/test_tool_policy_integration.py`).
- **Chore: remove ~60 lines of redundant comments** across `layout.py`, `ui.py`, `system_info.py`, `match.py`, `history_splitter.py`, `output.py`, `mcp.py`, `dot_dict.py`, `message_processor.py`, `common.py`, `any_custom_command.py`, and `file_history_manager.py`. One copy-paste docstring bug on `AnyCustomCommand.args` fixed along the way.
- **CI: coverage threshold updated** (`.github/workflows/test.yml`): 90% → 94%.
