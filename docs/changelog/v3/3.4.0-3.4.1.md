## 3.4.0 (September 13, 2026)

- **Feature: a pasted markdown, LaTeX or Mermaid message renders instead of echoing raw** (`src/zrb/llm/ui/base/{user_echo,message_queue,replay}.py`, `src/zrb/llm/ui/{base/ui,multi_ui}.py`, `docs/llm/llm-custom-ui.md`): a user message carrying an explicit markdown construct — a fence, ATX heading, blockquote, list item, table row, `**`, link, `$$` or `\begin{` — now goes through the same `render_markdown` path as an assistant reply, live and on replay. Line count is deliberately not the signal, so a traceback or log dump stays plain, and `__` is ignored because `__main__` and `__init__` appear in every Python traceback. Editing a queued message still works with a rendered echo. `MultiUI.append_markdown` sends the source text to children that render markdown themselves and the pre-rendered text to the rest, and is listed among the optional enrichment hooks.
- **Feature: the `AskUserQuestion` widget wraps at word boundaries and gives each description its own lines** (`src/zrb/llm/ui/default/{selection,agent_picker}.py`, `test/llm/ui/default/{test_selection,test_agent_picker}.py`): a long question or description was clipped at the float's width (prompt_toolkit's `wrap_lines` defaulted to `False`), and turning wrapping on alone split words mid-token and started continuation lines left of the radio gutter. The widget now wraps its own text with `textwrap` at the measured float width, puts each label on its own line with its description indented beneath, separates options with a blank line, and pads the highlighted row so the selection bar is one solid block; `wrap_lines` stays on as a backstop. The sub-agent picker had the same clipping and is fixed too.
- **Fix: output written while a thinking or final-text block streamed was swallowed when that block collapsed** (`src/zrb/llm/ui/output_chunk.py`, `src/zrb/llm/ui/{buffered_ui.py,default/output.py}`, `test/llm/ui/default/test_output_collapse.py`, `test/llm/ui/test_buffered_ui_collapse.py`, `test/architecture/test_collapsible_block_kinds.py`): the collapse spliced from the block's start mark to the buffer end, so a trigger line, background task output or a sub-agent's forwarded text arriving during a live block vanished into the collapsed summary — broken since the tracker shipped in 2.67.0. A block now tracks its own `[start, end)` span (`OpenCollapsibleBlock`) and absorbs only chunks of its own kind (`"thinking"` or `"streaming"`), so a concurrent writer's line stays outside it and a `\r` status rewrite never erases into a foreign line. Span rebasing is shared with `replace_output_span`, so a live shell or tool-prepare line near an open block no longer corrupts the collapse or lands inside the block. `UIOutput` and `BufferedUI` are both fixed; `test_collapsible_block_kinds.py` pins the streamer's printed kinds against what both UIs register.
- **Improvement: an error with no message is identifiable instead of blank** (`src/zrb/util/exception.py`, `src/zrb/llm/ui/{base/ui,base/exec_commands,base/triggers,multi_ui,default/lifecycle}.py`, `src/zrb/runner/chat/chat_session_runner.py`, `src/zrb/task/base/execution.py`, `test/util/test_exception.py`, `test/llm/ui/base/test_commands_shell.py`, `test/llm/ui/default/test_lifecycle.py`): every UI error path and `BaseTaskExecution`'s retry log formatted the exception as `str(e)`, empty for a bare `raise SomeError()` — yielding `[Error: ]` in the pane and `Attempt 1/3 failed: ` in the log. `exception_summary` prefixes the type name, keeping the message after it only when it does not already quote the class (many provider errors do). Visible change: `[Error: OSError: no shell]` where it used to read `[Error: no shell]`.
- **Tests: the `MultiUI` child-hook guard covers both dispatch shapes, and the API retry budget is pinned end to end** (`test/architecture/test_multi_ui_fanout_surface.py`, `docs/llm/llm-custom-ui.md`, `test/llm/agent/run/test_runner_retry.py`): the typo guard now also reads `getattr(ui, "name", None)` dispatches, bringing `record_tool_call_block`, `update_system_info` and the new `append_markdown` under it (`start_event_loop` is excluded as `EventDrivenUI`'s own). `run_agent` is now driven against a provider returning 503, pinning `LLM_API_MAX_RETRIES` as a *total* attempt count (default 3 = one request plus two retries; `0` and `1` both mean try once); a run that fails twice then succeeds makes exactly three requests without the task layer seeing the error.

## 3.4.1 (September 16, 2026)

- **Fix: error classifier now treats transient 5xx as retryable even when the message mentions context length** (`src/zrb/llm/agent/run/error_classifier.py`): the priority order was `is_prompt_too_long_error` first, then status codes — so an Ollama 500 with "Maximum context length exceeded" was classified as a permanent `context_length` error and never retried. Transient statuses (429, ≥500) now win over keyword guesses, matching the intent of `handle_stream_error` which already checked `is_retryable_error` first.
- **Improvement: `readiness_check_delay` defaults to `CFG.TASK_READINESS_DELAY` instead of a hardcoded `0.5`** (`src/zrb/task/base/base_task.py`, `src/zrb/task/base/execution.py`, all task subclasses): the pause before the first readiness check is now tunable via env (`TASK_READINESS_DELAY`, default 500ms) without touching individual task definitions. Behavior is unchanged for users who never set the knob.
- **Fix: session graph registration rewritten iteratively** (`src/zrb/session/session.py`): `_register_task_graph` and `get_root_tasks` replaced recursive traversals with stack-based iterations, eliminating exponential blowup on diamond dependency graphs and interpreter stack overflow past ~950 levels.
- **Tests: replace flaky `asyncio.sleep` with polling in chat session runner** (`test/runner/chat/test_chat_session_runner.py`) and pin the e2e tool-policy integration test against `TestModel` (`test/llm/tool_call/test_tool_policy_integration.py`).
- **Chore: remove ~60 lines of redundant comments** across `layout.py`, `ui.py`, `system_info.py`, `match.py`, `history_splitter.py`, `output.py`, `mcp.py`, `dot_dict.py`, `message_processor.py`, `common.py`, `any_custom_command.py`, and `file_history_manager.py`. One copy-paste docstring bug on `AnyCustomCommand.args` fixed along the way.
- **CI: coverage threshold updated** (`.github/workflows/test.yml`): 90% → 94%.
