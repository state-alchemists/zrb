## 3.25.0 (October 22, 2026)

- **Feature: every submitted message is queued, so a mid-turn message stays editable** (`src/zrb/llm/ui/base/message_queue.py`, `src/zrb/llm/ui/base/queue_delivery.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/multi_ui.py`, `src/zrb/llm/ui/default/output.py`, `test/llm/ui/base/test_message_queue.py`, `test/llm/ui/base/test_queue_delivery.py`): a message typed while a turn ran was absorbed into that turn at its next model request since 2.61.0, so Up Arrow had nothing to recall and a mistyped correction could not be taken back — and whether it queued at all depended on where the agent's run context happened to be. Submissions now always join the queue: `↑`/`Enter` edit in place, `Ctrl+X` drops, `Ctrl+G` sends into the running turn now, and the panel above the input names all three keys (`📥 2 queued · ↑ edit · Ctrl+X drop · Ctrl+G send now`). A delivered message's echo line changes from `⏳` to `⏩` rather than vanishing, so the transcript still says what the model read. `Ctrl+G` keeps its ladder; submit-time steering is withdrawn (ADR-0078, revised; ADR-0116).
- **Feature: `/btw` answers in a panel above the input instead of scrolling the transcript** (`src/zrb/llm/ui/default/side_question.py` new, `src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/base/exec_commands.py`, `src/zrb/llm/ui/default/keybindings.py`, `src/zrb/llm/ui/default/app/style.py`, `src/zrb/llm/ui/default/confirmation.py`, `test/llm/ui/default/test_side_question.py`): a side question is answered off to the side and never saved to history, yet its answer used to land in the middle of the conversation the user was reading. It now appears in the same full-width framed float the choice widget uses, docked above the input: the question, then the rendered answer, at twelve scrollable rows; `Esc` closes it and returns focus to the input, and a second `/btw` replaces it. The display is a UI capability — `BaseUI.begin_side_question`/`end_side_question`/`fail_side_question`/`cancel_side_question` keep rendering into the transcript for UIs without a panel, and the terminal UI overrides only the destination — and the panel never takes the focus from the input, so the user can keep typing (a second `/btw`, or any message) while the answer arrives. Each question carries a token, so a slow answer cannot fill a newer question's panel or close it when cancelled, and a free-text prompt that arrives while another widget holds the focus takes the input back for its answer.
- **Feature: compaction archives what it replaces and triggers on tokens, not a message count** (`src/zrb/llm/summarizer/verbatim_archive.py` new, `src/zrb/llm/summarizer/history_splitter.py`, `src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/config/mixins/llm_content.py`, `src/zrb/llm/subagent/building.py`, `src/zrb/llm/task/chat/execution.py`, `src/zrb/llm/task/llm_task.py`, `test/llm/summarizer/test_verbatim_archive.py` new, `test/llm/summarizer/test_summarization_policy.py` new): a summary is lossy, and the compacted history overwrote the session file, so the text a summary replaced was gone. It is now appended word for word, human-readably, to `<LLM_HISTORY_DIR>/verbatim/<session>.md` — append-only, one file per conversation — and the summary names that path in a paragraph zrb writes itself, never the summarizer model. Compaction now triggers at 75% of the prompt budget instead of 60%, and keeps the newest turns that fit 40% of that threshold instead of 70%: the old tail ate the headroom, so a compaction could be followed by another almost at once, and the count-based target disagreed with the token budget often enough that the splitter searched for a split point it could not find. `LLM_HISTORY_SUMMARIZATION_WINDOW` becomes a 300-message backstop for many small messages rather than the rule that decides the split; a turn boundary is preferred only while it keeps at least half the tail budget, so one long tool loop is not summarized whole to reach a user message. The archive follows the history manager that stores the conversation rather than the global default, holds the history as the conversation held it — the processor snapshots it before oversized tool results become summaries — and a caller that passes no session name gets an archive keyed by the conversation's opening message instead of one file shared by every unnamed conversation.
- **Fix: a compacted summary is fenced, named as derived data, and capped** (`src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/config/mixins/llm_content.py`, `test/llm/summarizer/history_processor/test_summary_handoff.py` new, ADR-0041 revised): a summary was injected as a user turn whose text began `# SYSTEM: Automated Context Restoration`, and role alternation then merged the real user messages into that same turn — on a real conversation the merged message carried four parts, the summary plus three user turns, so nothing marked where the automation ended and the user's own words began, and a stale `<live-context>` block from an earlier hour rode along inside it. The block now says it is derived data rather than the user speaking and closes with an explicit end marker, so a claim inside it can be checked against the words that follow. Its size is bounded too: `LLM_SUMMARY_MAX_TOKENS` (2000, the budget the summarizer prompt already asked for and nothing measured — a real one came back at about 3000) is measured on the block as it will be inserted, zrb's framing and the journal index and the archive pointer included. A block over the cap is shortened at most twice and then truncated by exactly what it overflows by; a summary that lost its `<state_snapshot>` schema is capped on the same rule rather than dropped, since too much prose costs the same as too much snapshot; and if the framing and notes fill the cap on their own the snapshot is dropped with a warning to raise the cap, because an over-cap block is the failure the cap exists to prevent. An empty summary now leaves the history untouched, and the archive holds whatever a truncation drops. ADR-0041 records the handoff rules with the rest of the compaction decision.
