## 3.25.0 (October 22, 2026)

- **Feature: compaction archives what it replaces and triggers on tokens, not a message count** (`src/zrb/llm/summarizer/verbatim_archive.py` new, `src/zrb/llm/summarizer/history_splitter.py`, `src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/config/mixins/llm_content.py`, `src/zrb/llm/subagent/building.py`, `src/zrb/llm/task/chat/execution.py`, `src/zrb/llm/task/llm_task.py`, `test/llm/summarizer/test_verbatim_archive.py` new, `test/llm/summarizer/test_summarization_policy.py` new): a summary is lossy, and the compacted history overwrote the session file, so the text a summary replaced was gone. It is now appended word for word, human-readably, to `<LLM_HISTORY_DIR>/verbatim/<session>.md` — append-only, one file per conversation — and the summary names that path in a paragraph zrb writes itself, never the summarizer model. Compaction now triggers at 75% of the prompt budget instead of 60%, and keeps the newest turns that fit 40% of that threshold instead of 70%: the old tail ate the headroom, so a compaction could be followed by another almost at once, and the count-based target disagreed with the token budget often enough that the splitter searched for a split point it could not find. `LLM_HISTORY_SUMMARIZATION_WINDOW` becomes a 300-message backstop for many small messages rather than the rule that decides the split; a turn boundary is preferred only while it keeps at least half the tail budget, so one long tool loop is not summarized whole to reach a user message.
