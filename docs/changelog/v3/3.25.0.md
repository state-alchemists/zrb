## 3.25.0 (October 23, 2026)

- **Feature: every submitted message is queued, and the running turn reads the queue at each checkpoint** (`src/zrb/llm/ui/base/message_queue.py`, `src/zrb/llm/ui/base/queue_delivery.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/ui/default/message_editing.py`): since 2.61.0 a message typed mid-turn was absorbed at the next model request, so `↑` had nothing to recall and mistakes were unrecoverable. Submissions now join the queue, where `↑`/`Enter` edit in place, `Ctrl+X` drops and `Ctrl+G` sends now, all three named in the panel above the input. The run loop hands ready entries over at each checkpoint without interrupting the turn: the entry being edited and any younger than a second wait, while the entries behind them still go. A delivered echo is re-marked `⏩` rather than vanishing. Submit-time steering is withdrawn — [ADR-0078](../../adr/adr-0078.md) (revised), [ADR-0116](../../adr/adr-0116.md).
- **Feature: `/btw` answers in a panel above the input instead of scrolling the transcript** (`src/zrb/llm/ui/default/side_question.py`, `src/zrb/llm/ui/base/ui.py`): a side answer is never saved to history, yet it used to land mid-conversation. It now fills a full-width panel above the input at twelve scrollable rows; `Enter` closes it without sending the draft already in the input, `Esc` also closes it, and a second `/btw` replaces it. The panel holds the focus, so `↑`/`↓`/`PageUp`/`PageDown` scroll the answer instead of recalling a queued message, while a typed non-control character — Unicode separators and joiners included — still starts a message. A pending prompt keeps the focus, and `BaseUI`'s `*_side_question` methods still render into the transcript for UIs without a panel ([ADR-0117](../../adr/adr-0117.md)).
- **Fix: the `/btw` panel's answer stayed wrapped for the terminal width it arrived at, and a resize could strand the reader on the wrong line** (`src/zrb/llm/ui/default/side_question.py`, `src/zrb/llm/ui/default/ui.py`): `UISideQuestion.end()` rendered the answer's markdown to plain styled lines once, at the width current when it arrived. Unlike the main transcript (`UIOutput.rewrap_output`, already re-run from the app's after-render hook), nothing re-rendered the panel on a resize, so its answer stayed wrapped for a width the terminal no longer had; `rewrap()` now does that from the same hook, a no-op unless an answer is showing and the width changed. Replacing the text naively moved the reader, because a raw character offset is not a stable anchor across a re-wrap — the same count of characters can precede different content once line lengths change: a reader scrolled to the bottom of a long streamed-in answer could land mid-buffer, or anywhere scrolled to could land on an unrelated line, after a resize. The cursor is now re-anchored before the new text exists to re-measure it against: `None` for a reader who was at the old text's end, so they keep tracking the end as it grows; otherwise the `(line, column)` they were on, resolved back to an offset in the new text — not an exact character match, since a word that moves lines still lands at the start of wherever its line went, but close enough that the reader stays on the content they were reading.
- **Feature: hands-free speech is delivered at the earliest safe point; push-to-talk submits like typing** (`src/zrb/llm/dictation/feature.py`, `src/zrb/llm/ui/base/ui.py`): with every submission queued, an utterance waited for a turn the speaker could not see end (the microphone has no `Ctrl+G`). A `TriggerReply` marked `send_now` now goes through `submit_message_now`, which skips the grace for its own new entry only: a message being edited and other drafts inside their grace still wait, and `may_interrupt=False` keeps speech from stopping the turn, which stays `Esc`, `Ctrl+G` or a stop word. Another trigger's reply still only queues a turn, so no remote source steers the conversation. Push-to-talk is unchanged: it submits as typing does, answering a prompt already on screen — [ADR-0076](../../adr/adr-0076.md) (revised), [ADR-0078](../../adr/adr-0078.md).
- **Feature: compaction archives what it replaces, and names the file only when the write succeeded** (`src/zrb/llm/summarizer/verbatim_archive.py`, `src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/llm/history_manager/file_history_manager.py`): a summary is lossy and compaction overwrote the session file, so the replaced text was gone. It is now appended verbatim to `<history dir>/verbatim/<session>.md`, append-only; zrb's own paragraph names that path only on success, never the summarizer model. A failed write is cut back to its starting length and gets no pointer, only a warning. The directory is created `0700`, the file `0600`, appends serialise under `LLM_ARCHIVE_LOCK_TIMEOUT` (30s), and an archive is deleted only once no history — a sub-agent transcript included — refers to it and it outlives retention ([ADR-0041](../../adr/adr-0041.md)).
- **Fix: a directory written before the private modes is narrowed once, and a lock that blocked a write says so** (`src/zrb/util/owner_only.py`): the archive and the journal are created `0700`/`0600`, but an older directory kept whatever mode it had, and a transcript or a note there may be readable by others. On first use zrb narrows the tree it owns — skipping symlinks, leaving anything it cannot change — and records that beside the directory (`<dir>.owner-only`), so a mode you set back afterwards stays as you set it. A lock that prevented a write now says so: the archive warning and the journal's busy error name the setting and the wait instead of a bare failure ([ADR-0041](../../adr/adr-0041.md), [ADR-0055](../../adr/adr-0055.md)).
- **Feature: compaction triggers on tokens, not a message count** (`src/zrb/llm/summarizer/history_splitter.py`, `src/zrb/config/mixins/llm_content.py`): it triggered at 60% of the prompt budget and kept the newest turns fitting 70% of that, so the tail ate the headroom and a compaction could be followed by another almost at once. It now triggers at 75% and keeps what fits 40%; `LLM_HISTORY_SUMMARIZATION_WINDOW` (300 messages) became a backstop for histories of many small messages rather than the rule that decides the split, and a turn boundary is preferred only while it keeps at least half the tail budget, so one long tool loop is not summarized whole to reach a user message ([ADR-0041](../../adr/adr-0041.md)).
- **Performance: the tail split is found by bisection instead of a walk** (`src/zrb/llm/summarizer/history_splitter.py`): only candidates at or after the first one that fits can be selected, so with the shipped char/4 counter that index is bisected, and every candidate from there still gets the tool-pair and turn-start checks. A synthetic 400-message history whose split landed at 368 counted 975 messages instead of 79,704 — 12 `count_tokens` calls, down from 369 — and picked the same split. A tiktoken or third-party limiter keeps the linear walk, whose counts are not monotonic ([ADR-0041](../../adr/adr-0041.md)).
- **Fix: a compacted summary is fenced, named as derived data, and capped** (`src/zrb/llm/summarizer/history_summarizer.py`): the block arrived as a user turn labelled `# SYSTEM: Automated Context Restoration`, and role alternation merged the real user messages into it, with a stale `<live-context>` riding along and nothing marking where it ended. It now says it is derived data and ends with a marker, and `LLM_SUMMARY_MAX_TOKENS` (2000) is measured on the block as inserted — framing, journal index and archive pointer included: over the cap it is shortened at most twice, then truncated, giving up the journal index, then the pointer, then the snapshot; framing that cannot fit alone leaves the history as it is, warning to raise the cap ([ADR-0041](../../adr/adr-0041.md), revised).
- **Tests: the stutter warning is read against the count it named, not the final one** (`test/llm/speech/test_pcm_player_underrun.py`): the line is said once, from the playing thread, at the first stutter it hears, so a block counted after that moment is not in the sentence — the assertion compared it with the count at the end of playback and failed on a loaded CI runner (3 blocks logged, 4 counted). It now reads the number out of the line and checks it lies between one and the final count, which is what the sentence promises.
- **Feature: the journal separates what is true of the agent from what is true of the user** (`src/zrb/llm/tool/journal_write.py`, `src/zrb/config/mixins/llm_content.py`): a standing choice an agent kept about itself — its appearance, how to address it — had to be filed under `preferences`, beside what the user stated, so a fact about the assistant read as one about the user. `agent/` is now a category with its own root-index section between `Preferences` and `Active Constraints`; an older journal is migrated under the root lock, gaining the section in its place and its `## Directories` link. That wait is bounded by `LLM_JOURNAL_LOCK_TIMEOUT` (30 seconds; `<= 0` fails at once), reporting a busy journal instead of an endless wait ([ADR-0055](../../adr/adr-0055.md), revised).
- **Fix: one knob names every journal index, for the writers and the reader alike** (`src/zrb/llm/tool/journal_write.py`, `src/zrb/llm/prompt/live_context.py`): the writers created `index.md` whatever `LLM_JOURNAL_INDEX_FILE` said, while `render_journal_index` read the configured name, so setting it left the written index unreadable and the journal uninjected. The writers, the directory links, the HUD lines pinned into the root index and the reader now resolve the same name, and a value carrying a directory component is refused with a suggestion rather than written outside the journal ([LLM Configuration](../../configuration/llm-context.md)).
- **Tests: the Windows drive-letter attachment test no longer imports a deprecated module** (`test/llm/util/test_attachment.py`): it imported `nturl2path` to get the Windows `url2pathname`, which emits a `DeprecationWarning` on every suite run and disappears in Python 3.19 — taking the test with it. The converter is stood up locally instead, so the test keeps pinning zrb's own half of the work (the `/C:/x` and `//server/share/x` it hands over) and the warning is gone; the file now passes with `-W error::DeprecationWarning`.
- **Fix: `SendMessageToSubagent`/`SendMessageToParent` were exposed to the model under their raw snake_case Python names** (`src/zrb/llm/tool/delegate_message.py`, `src/zrb/llm/subagent/parent_message.py`): every other tool overrides `__name__` to a PascalCase display name; these two were missed. Renamed to match.
- **Fix: the compaction trigger, `fit_context_window` and the final force-prune safety net all capped every model's context budget at the generic 128,000-token default** (`src/zrb/llm/config/limiter.py`, `src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/llm/util/capabilities.py`, `src/zrb/llm/agent/run/runner.py`): `LLM_MAX_TOKEN_PER_REQUEST`/`LLM_MAX_TOKEN_PER_MINUTE` are free-tier-safe rate-limit knobs, not context-window estimates, yet their 128,000 default was taken as the context budget outright — DeepSeek 4.1 Flash's real 1,000,000-token window (already registered) was silently discarded, triggering compaction, and its lossy truncation, at under a tenth of what the model could actually hold. `LLMLimiter.effective_context_window` (was private) now prefers a known model's real window over that default, only falling back to `min()` with it once the caller has actually chosen `LLM_MAX_TOKEN_PER_REQUEST` (env var or the limiter's own setter) as a deliberate ceiling. The conversational-summarization trigger, previously a static `CFG`-derived number captured once at task build time, is now recomputed from the run's actual model (`/model` included) on every call, the same way the summarizer's own agent already is — unless `LLM_CONVERSATIONAL_SUMMARIZATION_TOKEN_THRESHOLD` is itself pinned by an explicit env var. `_prepare_history`'s own last-resort force-prune, which ran after the trigger and compared against the same flat cap regardless of its own fix, now consults `effective_context_window` too — a 200,000-token history the trigger correctly left alone for a 1,000,000-window model no longer gets discarded down to its last message. Qwen, previously absent from the context-window table entirely, is now registered too.
