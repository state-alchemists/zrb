## 3.20.0 (October 14, 2026)

- **Feature: prefix an MCP server's tool names** (`src/zrb/llm/tool/mcp.py`, `docs/llm/mcp-support.md`, `test/llm/tool/test_mcp.py`): an `mcp-config.json` entry may set `"prefix": "<name>"`, which exposes each of that server's tools as `<name>_<tool>`. Before this, two servers sharing a tool name (chrome-devtools-mcp and a desktop server both offering `type_text`) aborted every run with a pydantic-ai `UserError`, and the only fix was editing a server. An invalid prefix skips its server with a warning, and a tool whose prefixed name exceeds 64 characters is skipped rather than failing the request.
- **Feature: WSL takes photos through Windows' ffmpeg** (`src/zrb/llm/camera/backend/ffmpeg.py`, `docs/llm/voice-photo-troubleshooting.md`, `test/llm/camera/backend/test_ffmpeg.py`): with `ffmpeg.exe` on WSL's `PATH` (`winget install Gyan.FFmpeg` on Windows), `/photo` and `TakePhoto` capture through dshow on the Windows side. The camera is open only for the photo, so Windows apps keep using it, and no usbipd-win attach or custom kernel is needed. A `/dev/video*` device, no `ffmpeg.exe`, or a camera attached to WSL through usbipd (which Windows then stops listing) still uses the Linux ffmpeg.
- **Documentation: what to check when `/photo` finds no ffmpeg or no camera** (`docs/llm/voice-photo-troubleshooting.md`, `docs/llm/voice-camera.md`): after `winget install Gyan.FFmpeg`, restart WSL from a terminal opened after the install and check `which ffmpeg.exe`, with a symlink as the fallback. A camera Windows itself does not list (Device Manager Code 45, "not connected") is named as a Windows-side fault, and a virtual camera such as OBS's has to be named, since auto-detection takes only devices ffmpeg tags `(video)`. A camera left behind by `usbipd bind --force` (`usbipd list` shows `Shared (forced)`) is released with `usbipd unbind`. A black photo with the camera light on is traced to a hardware privacy switch, and an empty capture to another app holding the camera.
- **Fix: tasks sharing a readiness check all became ready** (`src/zrb/task/base/execution.py`, `src/zrb/task/base/monitoring.py`, `test/task/base/test_execution_readiness.py`): when two tasks used one readiness check (several services waiting on one "db-ready"), every task but the first failed with `Readiness checks for task '<name>' did not complete`. Later tasks now wait for the check the first one started.
- **Fix: a crash beside a monitored task ended the run instead of hanging it** (`src/zrb/session/session.py`, `test/session/test_session_deferred.py`): with one task on `monitor_readiness=True`, another long-running task crashing after it became ready left the run hanging with no error. The session now watches deferred actions and monitoring loops together and raises the first failure.
- **Fix: fallbacks, successors and readiness checks got their inputs** (`src/zrb/task/base/context.py`, `test/task/base/test_context_inputs.py`): an input declared only on one of them never received a value (`'DotDict' object has no attribute ...`). The main task now offers them with its own inputs, prompted and passed like the rest; name one for its task (`deploy-channel`). The task's own and its upstreams' inputs win a name clash.
- **Fix: an input default could not read `ctx.env`** (`src/zrb/task/base/lifecycle.py`, `src/zrb/runner/common_util.py`): `default=Tpl("{ctx.env.HOME}/x")` raised because inputs were resolved before the OS environment was loaded, in a run and in CLI default prompts. Environment comes first now.
- **Fix: `--key -5` passed a negative number** (`src/zrb/runner/cli.py`, `test/runner/test_cli.py`): a value starting with `-` was parsed as a new flag (`Unknown option '--5'`). A negative number is now a value, as in argparse; other dash-prefixed values still need `--key=value`, which the unknown-option error now says.
- **Fix: `ctx.args` held only the leftover positionals** (`src/zrb/runner/cli.py`, `src/zrb/runner/common_util.py`): positionals consumed as input values were repeated in `ctx.args`; `zrb greet alice extra` now gives `['extra']`.
- **Fix: `CmdResult.output` kept the command's output** (`src/zrb/cmd/command.py`, `test/cmd/test_command_unrecommended.py`): blank lines were dropped, trailing whitespace stripped and lines joined with `\r\n`. Output is now the raw lines joined with `\n`, with only trailing newlines removed, like `$(...)`. The live display is unchanged.
- **Behavior change: a `{ctx.` placeholder in a plain-string `cmd` raises** (`src/zrb/task/cmd_task.py`, `docs/adr/adr-0005.md`, `test/task/test_cmd_task.py`): it used to warn (`UntemplatedCmdWarning`, now removed) and run a command the shell received literally. `CmdTask(...)` now raises `ValueError` naming the fix: wrap the command in `Tpl(...)`.
- **Improvement: a `zrb_init.py` that fails to load points at your line** (`src/zrb/__main__.py`, `src/zrb/util/load.py`, `test/util/test_load.py`): a misspelled keyword reported the zrb frame that raised (`cmd_task.py:116`). The report now names your file and line with its source, then where zrb raised.
- **Improvement: `zrb config explain` says where a value came from** (`src/zrb/builtin/config.py`, `src/zrb/config/env_field.py`, `test/builtin/test_explain_config.py`): each setting is marked `(set)` or `(default)`, and a single setting's view shows its default when it was set.
- **Documentation: tested LLM recipes, and corrected examples** (`docs/llm/recipes.md`, `test/architecture/test_recipes_run.py`, `README.md`, `docs/configuration/llm-collections.md`, `docs/task-types/custom-tasks.md`): a new page covers a gateway, a tool on `zrb llm chat`, the persona, an extra instruction, a skill, a sub-agent and your own chat task, each run by a test. The README's tool example now extends `zrb llm chat` rather than building an agent without its prompt or `--message`; a `def tool(ctx)` example no longer sends the model a `ctx` argument; `PromptManager(prompts=...)` examples that claimed to replace the prompt now pass `include_sections=[]`.
- **Tests: the doc-prose checks are gone** (`AGENTS.md`, `docs/contributing/maintainer-guide.md`): `test_doc_density`, `test_documented_counts` (with `scripts/doc_counts.py`) and `test_doc_code_style` failed on wording rather than on anything a reader could get wrong. `AGENTS.md` now lists which conventions fail the build and which are review guidance.
