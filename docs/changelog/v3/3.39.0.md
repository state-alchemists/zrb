## 3.39.0 (November 14, 2026)

- **Feature: a judge says what a shell command risks, before the prompt** (`src/zrb/llm/agent/shell_judge.py`, `src/zrb/llm/agent/run/deferred_calls.py`, `src/zrb/llm/tool_call/judge_note.py`, `src/zrb/llm/tool_call/shell_call.py`, `src/zrb/llm/prompt/markdown/shell_judge.md`, `src/zrb/config/mixins/llm_content.py`, `docs/adr/adr-0141.md`): the approval prompt had stopped being read — Anthropic measures a human block rate falling from ~17% to ~5% after fifty prompts in a session — and the cheapest half of that problem is to make the prompt worth reading. `LLM_SHELL_JUDGE_ENABLED=on` puts one small-model call between the rules and the prompt, and it writes one line above the command: `safe`, `caution`, `dangerous`, or `unknown`. `LLM_SHELL_JUDGE_AUTO_APPROVE_ENABLED=on` lets a `safe` verdict skip the prompt entirely; both default to `off`, and the second is meaningless without the first. It sits at the last position where nobody has been asked yet, below every rule: a permission `ask` someone wrote down, a `PreToolUse` hook's `permissionDecision: "ask"`, `force_ask`, and a call carrying `dangerously_skip_sandbox` all still reach a person, however ordinary the command is. Only `safe` **with a reason** may skip — `SAFE:` alone parses to `unknown`, because a truncated answer is a judge that did not decide — and a judge that times out (20s) or fails answers `unknown` too, so the prompt says the command went unjudged instead of passing it. It is deliberately reasoning-blind: the command, the working directory, the sandbox flag and the repository's uncommitted-file count, never the conversation, since the model being judged would be writing part of its own input. It is not a security boundary — the sandbox is — and the two knobs are now documented in [LLM Tools & Extensions](../../configuration/llm-tools.md#shell-command-judge), the cascade in [Permission Policy](../../llm/permission-policy.md#the-precedence-chain) and the line itself in [Customizing Tool Approval](../../llm/tool-approval.md). Three review findings shaped it: it is recognised by the tool's name rather than a capability tag (a deferred `ToolCallPart` carries none, so the first version judged nothing at all), a level with no reason is not a verdict, and the line is released on a cancelled approval too — the registry is process-global, so a note left behind would outlive the prompt it belonged to. The verdict carries no emoji on purpose: a glyph's width is the terminal's to choose, so four of them landed at four different offsets on four machines.

- **Feature: every usage line says which model call spent the tokens** (`src/zrb/llm/shared/usage_log.py`, `src/zrb/llm/hook/execution/creator.py`, `src/zrb/llm/subagent/live_session.py`, `src/zrb/llm/tool/delegate/runner.py`, `src/zrb/llm/history_manager/conversation_naming.py`, `src/zrb/llm/hook/builtin/memory_week.py`, `src/zrb/llm/dictation/interrupt_judge.py`, `src/zrb/llm/speech/summary.py`, `src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/llm/ui/base/exec_commands.py`, `test/llm/shared/test_every_model_run_is_attributed.py`): a line said what was spent and never who spent it, so "the turn cost 120k" and "the memory reviewer cost 40k of it" were the same number in the same log. Every record now carries a `component` — `main_agent`, `summarizer`, `hook_agent`, `auto_namer`, `shell_judge`, `subagent`, `other` — set by the call site or by a `usage_component()` block a nested run opens, and inherited rather than restated by everything the run writes underneath. A line written before the field existed reads back by its `kind`, which names it without a guess: a compaction line was the summarizer, everything else was the turn runner. A test drives every model call zrb makes and fails when one is filed under no component, so the vocabulary cannot quietly grow a hole. One correction rode along: a hook's line names the model from the response rather than from the config, which is what the provider actually answered with.

- **Feature: `/usage` says who spent it, and where a turn's input went** (`src/zrb/llm/custom_command/usage/command.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/agent/run/turn_cursor.py`, `src/zrb/llm/config/limiter.py`, `src/zrb/llm/shared/usage_log.py`, `docs/adr/adr-0142.md`, `docs/configuration/llm-tui.md`): the table above the sections is per model, because a model is what a provider bills for; the new **Who spent it** section is per caller, one row each with its runs, input, output and share — and it is omitted entirely when one thing spent everything, since a single row saying "it was the conversation" is a line to read and nothing to learn. The **Where the input went** section prints the round that opens a turn: the system prompt's tokens, the fitted history's and the user's own message, beside the provider's own `input_tokens` for that same request, so a counter that drifts from what was billed shows up as a growing gap rather than a quiet wrong total. Only the first round of a turn carries a composition — later rounds have grown by the answer the first one produced, so a copy on them would describe a request that was never sent — and `TurnCursor.take_composition()` hands it out once and clears on read. Tool definitions are deliberately outside the split: they are constant per configuration and priced by tool count (ADR-0058), so folding them in would make a fixed cost look like a moving one.

- **Feature: `/volume` takes a level, not only a run of signs** (`src/zrb/llm/speech/feature.py`, `test/llm/speech/test_feature.py`, `docs/adr/adr-0128.md`, `docs/configuration/llm-tui.md`, `docs/configuration/llm-voice-camera.md`, `docs/llm/programming-the-voice.md`): the command could only move the level — `+++` three steps up, `--` two down — which answers "a bit quieter" and nothing else. What it could not answer is the one thing its own reply prints: a specific percentage. `/volume 15`, or `15%`, now sets it outright. The two forms are kept apart by where the number sits: digits are a level only when they are the whole argument, so `-15` — neither a bare number nor a run of signs — is refused like any other typo, and no command that worked yesterday means something else today. Both pass the same clamp, so `/volume 500` stops at the 200% ceiling the way ten steps do, and the named level lands on the next sentence rather than fading the one being spoken ([ADR-0128](../../adr/adr-0128.md), decision 4).

- **Improvement: a turn fits its history once, and each stage has a name** (`src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/config/limiter.py`, `src/zrb/llm/agent/run/turn_cursor.py`): `_prepare_history` did four jobs under a name that implied none of them, so it is now four named stages over a small `_PreparedRequest` that carries the measured sizes between them — reserve the system prompt, let the processors compact, fit what survived, pace the request. The second fit is gone: `_acquire_rate_limit` was handed the history the fit had just produced, fitted it again, and serialized the whole thing into a dict to estimate a request whose size was already measured; `_wait_for_rate_limit` replaces it and only paces, and `LLMLimiter.acquire` takes an optional `estimated_tokens` instead of a second method. Measured on a 20-pair history: 85 counter calls and two full walks per turn before, 45 calls and one walk after. What the single walk made free is the per-turn composition `/usage` now prints — all three numbers were already measured on the way to fitting. The one part no fit had seen is a `PostCompact` hook's own context, which joins the history *after* the event so the counts a hook is given describe what is sent; the fit now runs once more when a hook adds one, because an injection larger than the headroom left would put the request over the window, which a provider refuses outright rather than trims.

- **Improvement: the archive pointer has one home** (`src/zrb/llm/history_manager/archive_layout.py`, `src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/llm/history_manager/file_history_manager.py`, `test/llm/history_manager/test_archive_layout.py`): deleting the only copy of a conversation was decided by regexing prose another module writes, with nothing joining the writer to the reader — a wording change would have kept the test green while the collector stopped recognising archives. `archive_layout.py`, which already owned `verbatim/`, the tool-results suffix and the lock path, now also owns the pointer (`render_archive_pointer`, `archive_names_in`, `tool_results_names_in`). The prose is byte-identical, so nothing already on disk changes, and the new test renders with the writer and searches with the reader in one assertion — a plain name, a name with a space, a Windows path and a `.tool-results` directory.

- **Fix: an archive is written only where a summary still names it** (`src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/llm/history_manager/archive_layout.py`, `test/llm/summarizer/test_summary_handoff.py`): "archive written" and "archive pointed at" were decided in two places and could disagree — the summary cap could drop the pointer while the write happened anyway, leaving an unpinned archive that a later cleanup could delete. The verbatim archive is now written only when the fitted block still carries its pointer, and where the pointer had to go the warning says the summary is the only copy. A `.pinned` sidecar beside each archive was rejected: it would teach retention one more rule, and an over-cap summary losing its archive entirely is the cheaper failure.

- **Fix: a run's usage is read, not called** (`src/zrb/llm/shared/usage_log.py`, `test/llm/shared/test_usage_components.py`): `record_agent_usage` read `result.usage` and then called it whenever it was callable, which is a shape pydantic-ai no longer has. In the pinned 2.65.0 `usage` is a property returning a `RunUsage`, and a `RunUsage` is *also* callable through a V1 shim that returns itself — so `callable(usage)` was true on the modern shape, and the call did nothing but print `usage is a property, not a method` on every judge, hook, namer, side question and `/exec` line. Two test fakes had modelled the method shape, which is why the suite never noticed; they set the attribute now, and one test asserts the line is still written and no such warning is raised.

- **Improvement: one turn behind both names** (`src/zrb/llm/ui/turn_execution.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/multi/`, `docs/architecture/1-spine/llm-turn.md`): the interactive turn existed twice and the copies had already drifted — the multi cleared `last_result_data` at turn start and had a test for it, the base did not, so after a failed turn `display.last_output` still returned the previous answer. Both are now `run_turn(ui, llm_task, user_message, attachments)` and `build_turn_session(...)`, and the two hosts reach an `AnyUI` role rather than a child, which is why it can be a function rather than the `TurnRunner` class the sketch proposed.

- **Improvement: one recipe for a sub-agent's turn** (`src/zrb/llm/shared/subagent_turn.py`, `src/zrb/llm/tool/delegate/runner.py`, `src/zrb/llm/subagent/live_session.py`): "run a subagent turn" was written twice and had drifted in six ways. It is one `run_subagent_turn(SubAgentTurn)` at L0, imported downward by both callers, with the limiter passed as a field rather than looked up — resolving it inside the turn created a `config <-> shared` cycle the ratchet caught on the first run.

- **Improvement: the engine no longer imports the CLI** (`src/zrb/group/root_group.py`, `src/zrb/runner/cli.py`, `src/zrb/llm/tool/zrb_task.py`, `test/architecture/test_llm_layering_ratchet.py`): `llm/tool/zrb_task.py` reached into `zrb.runner.cli` for the `cli` singleton, so every process that built an agent also imported the CLI stack. The tree is registered in `zrb/group/root_group.py` and read back through `get_root_group()`, and the ratchet now says no module under `llm/` may import `zrb.runner` at runtime — including the two spellings the first version of the rule could not see (`from zrb import cli`, and an `import_module` with a string literal). The listing a handover, not an extension point: `run_zrb_task` executes the `zrb` command in a child process, which knows only the tree the command itself builds.

- **Improvement: four procedures leave the objects that did not own them** (`src/zrb/runner/web_bind.py`, `src/zrb/llm/agent/run/checkpoint_writer.py`, `src/zrb/llm/history_manager/message_repair.py`, `src/zrb/llm/snapshot/restore.py`, `src/zrb/llm/history_manager/file_history_manager.py`, `src/zrb/llm/snapshot/store.py`): 90 lines of web-bind security policy lived inside CLI dispatch; `CheckpointWriter` lived in the 1,183-line runner; ~150 lines of provider-payload repair lived inside a file store, so the store changed whenever a provider's part kind did; and a repository also decided what a restore may touch. Each now lives in a file named for the question it answers — `web_bind.py`, `run/checkpoint_writer.py`, `message_repair.py`, `snapshot/restore.py` — with `file_history_manager.py` 861 → 711 and `store.py` 1,027 → 836. `restore()` stayed on the store on purpose: its every step is that store's own plumbing, and moving it would have meant one module reaching into another object's private members.

- **Improvement: a package grows the modules it lacked** (`src/zrb/llm/ui/assembly.py`, `src/zrb/llm/dictation/microphone.py`, `src/zrb/llm/task/chat/teardown.py`, `src/zrb/llm/task/chat/message_expansion.py`, `src/zrb/llm/task/chat/persistence.py`, `src/zrb/llm/history_manager/conversation_edits.py`): the UI assembly reached `ui/` internals from two methods in another package, and it now sits in `ui/assembly.py` — with the import moved below the early return, so a session that brings its own UI (the web/SSE path, a programmatic one) no longer loads `prompt_toolkit` for nothing. `dictation/listen.py` gives up its 240-line PortAudio device layer to `dictation/microphone.py` (1,031 → 843). `task/chat` gains `teardown.py` (the six steps a quit releases, now clearing `active_hook_manager` so a repeated teardown cannot fire `SessionEnd` twice on a finished run), `message_expansion.py` (the three shapes a typed message becomes) and `persistence.py` (where a conversation is written, which was five places). Two of them came out as functions rather than the classes the sketches proposed, because the class would have held one object and nothing else.

- **Improvement: `any_ui.py` says which roles are parts and which are the host** (`src/zrb/llm/ui/any_ui.py`): the docstring promised that five accessors exist "because a backend swaps the writer, the widget and the queue"; reading every override showed `display` and `picker` are parts and `input`, `session` and `tools` return the object itself. The words now say two and three, with the reason, and the correction that `picker` is a real part was found while writing them. No code changed.

- **Behaviour change: a hook's context is fitted around, never trimmed away** (`src/zrb/llm/agent/run/runner.py`): a `PostCompact` hook may add context after the fit, and what it adds is counted against the window like everything else. The trim takes whole turns off the front — and the hook's context was the first of them, so the second fit could delete silently the one thing the hook existed to say. Its cost is now reserved while the history is fitted, and the context is prepended afterwards, where no trim can reach it; the history gives way instead. Only when the context alone cannot fit beside any history is it dropped, and that prints a line rather than happening quietly. Before #916 the same second fit always ran, so the bound itself is restored rather than introduced.

- **Documentation: the release's own gaps are closed** (`docs/adr/README.md`, `docs/configuration/llm-tools.md`, `docs/configuration/llm-tui.md`, `docs/configuration/llm-config.md`, `docs/llm/permission-policy.md`, `docs/llm/tool-approval.md`): ADR-0142 sat between ADR-0127 and ADR-0130, out of numeric order. The shell judge appeared in no configuration table, in no precedence chain, and in no approval-prompt example — its two knobs existed only in the `EnvField` docstrings. `/usage`'s component and composition sections were documented only in ADR-0142, while the TUI page still described the command without them.
