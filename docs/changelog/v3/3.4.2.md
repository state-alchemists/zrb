## 3.4.2 (September 18, 2026)

- **Performance: LSP server detection is O($PATH) instead of O(servers × $PATH)** (`src/zrb/llm/lsp/configs.py`): `detect()` called `shutil.which` once per configured server, and every *miss* walks the whole of `$PATH` — 21 servers against 53 entries is ~1100 stat calls. Measured 788ms warm and 2.04s cold on WSL2, where 18 of those entries are `/mnt/c/...` mounts at ~5ms per stat, and it sat on the `zrb llm chat` startup path. Detection now lists each `$PATH` directory once to prefilter, then calls `shutil.which` only on the names that could match; `which` remains the authority on what counts as executable (PATHEXT on Windows, the exec bit on POSIX). Measured 788ms → 44ms warm with an identical result, and a one-shot `zrb llm chat` against a local server went from 6.0–10.3s to 3.2s. The comment in `common_tools.py` calling this "a cheap shutil.which scan (no startup)" was wrong and is corrected.
- **Tests: a hang now fails as a hang** (`pyproject.toml`): added `pytest-timeout` with `timeout = 60` and `timeout_method = "thread"` (`signal` needs SIGALRM, which is POSIX-main-thread only — incompatible with `pytest-xdist` and Windows). Found by a mutation run where one flipped boolean turned a fast failure into a >20 minute stall; with no per-test cap that reads as a slow CI run rather than a failure.
- **Tests: mutation-kill-rate ratchet** (`scripts/mutation_ratchet.py`, `.github/workflows/mutation.yml`, `test/scripts/test_mutation_ratchet.py`, ADR-0097): coverage measures whether a line ran, not whether a test would notice it being wrong. Measured under a 94% coverage gate: 51 of 98 mutants killed across four packages (`task/base` 56%, `util/cmd` 35%, `llm/skill` 60%, `llm/prompt` 56%), with survivors including a process-tree snapshot that let SIGTERM-ignoring grandchildren leak and a constructor fallback that silently discarded a caller-supplied `skill_manager`. Each mutant runs only its package's mirrored tests, which is a harder question than a whole-suite pass: a mutant killed by an unrelated integration test shows the system noticed, not that the package is asserted on. The ratchet scores a seeded sample per package against a `FLOORS` table in the same only-ever-goes-up form as `FACADE_BUDGETS`, and runs nightly rather than in `zrb-test.sh` — a pass is minutes, and the per-commit gate stays at 117s.
- **Tests: LSP detection tests now control `$PATH` instead of mocking `shutil.which`** (`test/llm/lsp/test_configs.py`): detection probes the filesystem twice (a listing per `$PATH` entry, then `which` on the survivors), so a test that mocks only `which` describes a world that cannot exist — it would pass while the prefilter dropped every server. A `lsp_on_path` fixture installs real executable stubs on a `$PATH` holding only them, which puts the prefilter under test alongside the resolution. Verified by sabotage: breaking the prefilter in either direction (too narrow, too wide) now fails the suite; under the old mocks it did not.
