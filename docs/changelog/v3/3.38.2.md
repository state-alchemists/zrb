## 3.38.2 (November 12, 2026)

- **Feature: a config dir list may name an absolute path, so zrb can follow `$CLAUDE_CONFIG_DIR`** (`src/zrb/util/dir_search.py`, `src/zrb/config/mixins/llm_search.py`, `src/zrb/llm/skill/manager.py`, `src/zrb/llm/subagent/manager/search.py`, `src/zrb/llm/hook/hook_loader.py`, `src/zrb/llm/prompt/claude.py`, `test/util/test_dir_search.py`, `test/llm/skill/test_skill_manager_search_dirs.py`, `test/llm/subagent/manager/test_manager_search.py`, `test/llm/hook/test_hook_loader.py`, `test/llm/prompt/test_claude.py`, `docs/llm/claude-compatibility.md`, `docs/configuration/llm-tools.md`): Claude Code reads its config directory from `$CLAUDE_CONFIG_DIR` when it is set and from `~/.claude` otherwise, so a user who moved it was invisible to zrb — skills, sub-agents, hooks and the user-level `CLAUDE.md` all stayed on the old path. An entry in `LLM_CONFIG_DIR_NAMES` that is absolute is now a root in its own right: it is scanned once, as a user tier, and never appended to a project directory, where it would come after the project's own config dirs and let a user skill win a name collision the documented order gives to the project. `~` is expanded, so either spelling reaches the same directory. One `export ZRB_LLM_CONFIG_DIR_NAMES=".claude:.zrb:$CLAUDE_CONFIG_DIR"` now covers all four readers. Two things about that line are stated in the docs because both bite silently: the variable *replaces* the default list rather than extending it, so `.claude` and `.zrb` have to be named to keep them — appending to an unset variable drops both; and zrb's own `.<ROOT_GROUP_NAME>` hooks are still read when the list omits that name, since they are zrb's config, not the user's to switch off. Hook discovery previously ignored the list altogether and looked for `.claude` only.
- **Feature: a compaction says why it ran, in the log and in `/usage`** (`src/zrb/llm/shared/usage_log.py`, `src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/llm/custom_command/usage/command.py`, `src/zrb/llm/task/llm_task.py`, `test/llm/shared/test_usage_log.py`, `test/llm/summarizer/test_compaction_fire_log.py`, `test/llm/custom_command/usage/test_usage_command_sections.py`): `/usage` could say what a compaction cost and never why it ran, and a compaction fires on three different things — the token threshold (the configured trigger *less the system prompt*), a message-count window that can fire on its own, and `/compress`, which answers no limit at all. Every compaction now writes a WARNING line when it fires, and a limit-triggered one that replaced something logs a second line saying how much smaller the history came out; a fire that reached no model says the history was left as it was, so a fire in the log with no line in `/usage` is explained rather than missing. Its record carries the reason beside the history size and the room the system prompt had already spent: `forced`, `token`, `message`, or both when a history crosses both checks at once. `/usage` prints the last five fire lines. A forced compaction has no limit to report, so its token fields are zero and are rendered as unknown rather than as nothing — a zero that meant "not measured" would read as a compaction that cost nothing. Recorded as decision 11 in ADR-0127.
- **Behaviour change: the verbatim tail kept after a compaction is capped at 12,000 tokens** (`src/zrb/config/mixins/llm_content.py`, `docs/configuration/llm-context.md`, `test/llm/summarizer/test_summarization_policy.py`): the kept tail is the smaller of `LLM_HISTORY_TAIL_BUDGET_RATIO × trigger` and `LLM_HISTORY_TAIL_MAX_TOKENS`, and on the default 200,000-token trigger the ratio allows 80,000 — so the ceiling, not the ratio, is what decides how much conversation survives a compaction, and every later round re-reads all of it. The default ceiling is now 12,000 instead of 24,000, which halves that handover. Nothing is lost by it: the messages the tail drops are summarized, and the originals stay archived under `LLM_HISTORY_DIR/verbatim/`. A value you set still wins, and `0` still leaves the ratio in charge.
- **Improvement: the batch reminder counts a streak that mixes lookups** (`src/zrb/llm/tool_call/batch_nudge.py`, `test/llm/tool_call/test_batch_nudge.py`, `docs/configuration/llm-context.md`): three lookups issued one round apart are the same waste whether or not they use the same tool, so `Read` then `Grep` then `Glob` — invisible to the old rule, which asked for one tool throughout — now counts. Replayed over three weeks of real transcripts (256 conversations, 14,970 rounds), the conversations a streak qualifies in rise from 24 to 36. The tool is part of what was asked: `Grep x` after `Glob x` is two lookups even though their arguments render identically, while the same tool on the same arguments is still one lookup repeated. Writes and shell commands still end a streak.
- **Improvement: `Grep`, `Glob` and `LS` ask for their calls to be batched where the tool is chosen** (`src/zrb/llm/tool/file/search.py`, `src/zrb/llm/tool/file/listing.py`): `Read` already ended with that sentence; the other three lookups now say it too, so the four are consistent. It sits in the text a model reads immediately before it emits the call — the one place an instruction can land before the wasted round rather than after it, which is why it exists beside the reminder rather than instead of it. It costs about a hundred tokens on every request, and a model whose System Context has withdrawn the batch rule is told so in the same sentence.
- **Chore: the prose added since the October sweep is swept of narration** (`src/zrb/llm/{agent,config,custom_command,dictation,emotion,hook,memory,prompt,shared,skill,speech,subagent,summarizer,tool,tool_call,ui}/`, `src/zrb/config/`, `src/zrb/builtin/llm/`): the standard is the one the three October commits set — mechanism in, narration out — so the unswept prose was whatever has landed since `30973d838`, 539 files carrying 4,518 added comment and docstring lines, and every added block was read against that standard. Removed: the incident that produced a constant retold end to end (`src/zrb/llm/summarizer/chunk_processor.py`), the alternative a decision passed over re-argued inside the docstring that made the decision (`src/zrb/llm/hook/builtin/memory_reviewer.py`, `src/zrb/llm/memory/migrate.py`), a rationale that had been copied into five files and is now stated once where the placement is computed (`src/zrb/llm/ui/default/app/layout.py`), past-tense narration of a fixed bug turned back into the constraint it states (`src/zrb/llm/prompt/memory_context.py`), and the word-level residue — "only ever" (5), emphatic "very"/"really" (6), "simply" (3), "the whole point"/"the whole reason" (3), "robust" as a compliment (2), filler "just" (1). Kept on purpose: "deliberately", "entirely" where it is precise, "no longer"/"used to" about runtime state rather than history, tool-schema docstrings, and the "X rather than Y" clauses that name an ordering, a cap or a placement a future editor could violate. Nothing executable changed, and that is checked rather than asserted: in each of the 39 files the AST equals the previous commit's with every bare string statement removed, `flake8 --select=F` is clean, and `pytest test/llm test/architecture test/test_public_api_docs.py` gives 8,622 passed and 29 skipped. One defect fell out of the read: `memory/migrate.py` promised "Four rules" over a list of five.
