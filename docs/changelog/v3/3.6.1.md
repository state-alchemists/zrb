## 3.6.1 (September 22, 2026)

- **Fix: a write that breaks the file no longer reports itself as `Successfully`** (`src/zrb/llm/tool/post_write_check.py`, `src/zrb/llm/tool/file_edit.py`, `src/zrb/llm/tool/file_write.py`, `test/llm/tool/test_post_write_check.py`): `Write` and `Edit` appended the `[DIAGNOSTIC]` block to their own success line, producing `Successfully updated foo.py … the file is now broken — treat this as a failed edit`. One result asserted success and failure at once, and the first words of a tool result frame everything after them, so the model was free to believe the half that let it move on. That is the shape behind the 81 consecutive `Successfully updated … [DIAGNOSTIC]` results answered with another blind edit that `format_post_write_diagnostics` already records in its own docstring — the earlier fix added actionable guidance to the *body* without changing what the result *led with*. A new `compose_write_result` puts the failure first and demotes the outcome line to `What landed: …`; the verdict sentence now lives in the diagnostic block and nowhere else, so the two halves can no longer drift apart. The outcome line is demoted rather than dropped, because the replacement count and any fuzzy-match note are real signal for choosing the next move. A clean write is unchanged and still returns exactly its outcome line. Both docstrings say the same thing the result does — the bytes did reach disk, so do not re-send them; read the file and make a targeted fix, and the requested change is not complete until the errors are gone. "The write is not done" would have read as "nothing happened", inviting the blind rewrite-from-memory this bullet exists to stop.
- **Improvement: `Edit` says what its `count` default and its whitespace-tolerant fallback actually do** (`src/zrb/llm/tool/file_edit.py`): `count` defaults to `-1`, which replaces *every* occurrence in the file, and its description said only "-1 (default) replaces every occurrence; 1 replaces only the first" — a restatement of the signature with no guidance on which to pick, so a short `old_text` (`return None`, `self.name`) silently became a file-wide replacement. It now leads with the consequence and says to pass `count=1` unless `old_text` has been confirmed unique. The fuzzy-match note changed from reassurance ("whitespace differences were normalized") to what happened: the fallback can match a block at a *different* indentation level, and `new_text` is then written with the indentation the model supplied rather than the file's. For Python a wrongly-indented but syntactically valid block passes both `ast.parse` and the pyflakes undefined-name filter, so the post-write check reports nothing. The `count=-1` default itself is unchanged.
- **Improvement: the verification bar and the removal proof are on the always-on path, not behind a skill activation** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm_plugin/core_skills/core-coding/SKILL.md`): workflow step 4 read "a change is not done until its checks pass **or you can state plainly that none could run**" — an always-available exit from verification, in the most-read section of the prompt. The clause is gone, and the two rules that previously required `ActivateSkill("core-coding")` to reach are now stated unconditionally: a change is done when a focused test, lint or type check has run and passed, and a removal is proved by searching the changed files for what was removed. `core-coding` states both self-contained rather than pointing at "Workflow step 4" — every prompt section is swappable through `LLM_INCLUDE_SECTIONS` and `LLM_PROMPT_DIR`, so a cross-section pointer dangles the moment one is replaced, the same failure `skill.py` already avoids for the skill catalogue. Duplication *across* that swappable boundary is what keeps each layer independently replaceable.
- **Improvement: tool docstrings stop restating their own parameter schemas** (`src/zrb/llm/tool/{file_list,file_read,file_write,file_edit,file_search,code,journal}.py`, `src/zrb/llm/common_tools.py`): pydantic-ai serializes a tool's docstring into `description` and every `Annotated[..., Field(description=...)]` into `parameters_json_schema`, and both ship in the same request — so a docstring explaining an argument pays for it twice and leaves the model to pick a canonical phrasing when the two drift. `LS` and `Glob` were the worst: three sentences each that were their own `Field` descriptions reworded (the auto-exclusions, the `exclude_patterns=[]` escape, the `include_hidden` default), roughly 85% of each docstring. `Read` dropped "Returns lines [start_line, end_line], 1-indexed and inclusive; end_line=-1 means the last line", verbatim its two `Field`s. `Write` leads with tool choice instead of restating how to pick a `mode`, while still naming all three things it does (create, replace, append) so the summary stays accurate. `Edit` keeps only what a schema cannot express — read the result, not just its status, since the replacement count and the fuzzy-match note are properties of the outcome, not of any parameter. `SearchJournal` loses the clause naming "all journal files in the configured journal directory", which its own name and `path` already carry. The division of labour is documented in `common_tools.py` where tools are registered: the `Field` owns the argument, the docstring owns the tool. This does not revisit ADR-0058 — the lever on tool-definition weight is still tool *count*, and this removes duplication rather than trimming prose to buy budget; the 1062 → 990 word drop across registered-tool docstrings is a side effect, not the reason.
- **Improvement: the prompt states each rule once, and the examples teach the ask-versus-proceed threshold** (`src/zrb/llm/prompt/markdown/{principle,workflow,example,profile.minimal,profile.standard,profile.capable}.md`): the honesty-and-uncertainty rule was stated three times across `persona`, `principle` and `workflow`, and "preserve unrelated changes" twice; `principle` now owns both and the `workflow` copies are gone. Skill activation no longer restates the trigger conditions that every `SKILL.md` description already opens with — it points at them, so the catalogue stays the single source. The batching clause "System Context may explicitly disable batching for this model; that override wins" is removed: the System Context line already asserts precedence over "every batching instruction elsewhere, in the workflow rules and in any tool description", and it renders only for deny-listed models, so the forward reference announced an absence to every other model — the same coupling that once made every model serialize its calls. `example.md` trades two generic formatting demos for the judgment calls the prose could not teach: adding a `--verbose` flag (proceed alone — the existing code determines the name, the parse site and the test) versus "clean up the old migration files" (stop and ask — ambiguous between delete, archive and squash, and destructive under one reading). The three operating profiles name a distinguishing behaviour instead of a posture adjective.
- **Improvement: `Shell`'s timeout and permission-denied suggestions name the next action instead of a generic gesture** (`src/zrb/llm/tool/shell.py`): the timeout suggestion said the process was "often still running in the background" and to check with `ps aux` before killing it — but the tool has already terminated it, so there is nothing to kill and the advice sent the model after a corpse. It now separates the two real cases: work that was meant to keep running belongs under `background=True` with `MonitorProcess`, and work that was meant to finish should not be re-run unchanged but scoped, summarized or given a non-interactive flag. Permission-denied no longer leads with `sudo`; it asks for a user-level fix first (user prefix, non-privileged port or path, owner and group) and treats `sudo` as a last resort.
- **Docs: ADR-0099 — factual-claim hardening against generative-engine-optimized content** (`docs/adr/adr-0099.md`, `src/zrb/llm/prompt/markdown/web_summarizer.md`, `src/zrb/llm/prompt/markdown/principle.md`, `src/zrb/llm_plugin/core_skills/core-research/SKILL.md`, `src/zrb/llm_plugin/agents/researcher.agent.md`, `src/zrb/llm/tool/web.py`): content shaped for answer-engine retrieval leans on decorative quotations and statistics, and zrb told the agent nothing it could act on. The strongest source-quality wording lived only in the optional `researcher` sub-agent, so a normal chat session never saw it; `web_summarizer.md` listed benchmarks and security warnings as always-high-extract with no attribution test; and the *default* summarized `WebFetch` path returned derived untrusted content with no `content_is` note, though the opt-in raw path carried one. A figure whose origin the page does not name is now recorded as unverifiable rather than relayed, a page shaped for extraction is flagged rather than echoed as neutral fact, corroboration of contested or consequential claims moves onto always-on `principle` and on-demand `core-research`, and both web paths carry the untrusted framing — extending ADR-0048 rather than revising it. The corroboration rule is scoped to contested or consequential claims so it does not force redundant fetching on every mundane fact. `open_web_page`'s unreachable-page hint also gains the colon the `[SYSTEM SUGGESTION]:` convention uses everywhere else.
- **Improvement: the `generalist` sub-agent drops shouted mandates for plain statements** (`src/zrb/llm_plugin/core_agents/generalist.agent.md`): `SHALL NOT`, `MUST` and `NO context` are now ordinary prose ("you do not delegate further", "your first tool calls are `ActivateSkill`"). The instructions are unchanged; only the register is. `core-coding` gains the re-read-before-Edit rule in its execution phase: apply every `Edit` against a `Read`'s output visible in the conversation rather than against memory, since a stale block either fails to match or edits the wrong region, and each miss costs more than the re-read would have.
- **Docs: part-accessibility guidance and the duplicate-basename example** (`AGENTS.md`, `docs/adr/adr-0034.md`, `poetry.lock`): clarifies that parts outside code reaches directly (`usage`, `confirmation`, `voice`, `persona`) stay bare rather than taking the `_base_` prefix, corrects the `X/X.py` path count from 18 to 17, and updates the duplicate-basename example to `test_registry.py` under the `llm/` packages. ADR-0034's consequences are synced with the updated example. `poetry.lock` regenerated with Poetry 2.5.1.
- **Tests: a web-search assertion that measured wall-clock now measures what it meant, and the hook pid file is written atomically** (`test/llm/tool/test_web_tool_open_page.py`, `test/llm/hook/test_manager_plugin_roots.py`): `test_search_internet_does_not_block_the_event_loop` asserted `heartbeat_done_at - overall_start < 0.2`, which conflates an event-loop block with ordinary OS descheduling — under a busy test run a free loop reads as blocked. It now asserts that the sync backend executes on a different thread than the loop, which proves off-loop dispatch directly and is load-independent, *and* keeps a concurrent heartbeat that must fire while the backend is still running, since the thread check alone would pass a dispatch that off-loads to a worker and then synchronously joins it from the loop. The backend holds an explicit "running" flag open until the heartbeat releases it, so the responsiveness regression is caught without the wall-clock flakiness. In the hook test, `_assert_recorded_process_stops` parsed the child's pid file the moment it appeared, but `Path.write_text` is not atomic: a kill landing between `open()` and `write()` leaves an empty file and `int('')` raises. The child now writes to a temp file and `os.replace()`s it into place, so the pid file is either absent or complete — guarding only against an empty read would still have treated a nonempty prefix of the pid as the whole value.
