## 3.38.5 (November 13, 2026)

- **Fix: an MCP server's tools carry the `purpose` line and never receive it** (`src/zrb/llm/tool/mcp.py`, `src/zrb/llm/tool/purpose.py`, `src/zrb/llm/agent/common.py`, `test/llm/tool/test_mcp.py`, `docs/llm/mcp-support.md`, `docs/architecture/3-peripheral-flow/mcp-and-lsp.md`): 3.38.4 gave every tool zrb builds a slot for `purpose`, the line the narrator reads aloud instead of the tool's generic sentence — by extending the function's `inspect.signature` in `create_safe_wrapper`. An MCP server's tools were the one edge that could not reach. Their schema is JSON the server publishes, not a Python signature, so there was nothing to extend, and zrb forwarded the model's arguments to the server untouched: a call that obeyed the standing instruction came back as `1 validation error for call[echo] · purpose · Unexpected keyword argument`, which costs the round and re-sends the whole context with it. `add_purpose_to_mcp_tools` now wraps each `MCPToolset` that `load_mcp_config` builds. On the way in it rewrites every tool definition whose `inputSchema` is an object and does not already declare `purpose`, adding a **required** string property with the shared description and marking the definition (`DECLARED_PURPOSE_KEY`); on the way out it drops the argument before forwarding, but only for a definition it marked. Required rather than optional for two reasons: the description says "Always fill this", and a schema with an optional property is not strict-compatible, which turns a provider's strict mode off for that whole tool. A server that declares `purpose` itself is left alone — its schema is not touched and the value is forwarded, because that parameter is the server's own meaning, which is why the drop is keyed to what zrb added rather than to the argument's name. A schema that cannot be extended safely is also left alone: a `$ref` or a union, or properties that are not a mapping. The wrapper forwards the server's `id`, so its tools keep the name the server gave them. Measured against a FastMCP 3.4.11 stdio server with two tools, `echo(text)` and `log(text, purpose: str = "")`, driven by a `FunctionModel` so the arguments were chosen rather than sampled: declaring alone was still refused, dropping alone left the model no reason to write the line, and both together returned `echo: hi`; `log`'s own `purpose` kept its schema (`{"default": "", "type": "string"}`, no description added) and received `Probing`. Eight tests, none needing a live server.
- **Feature: the approval prompt says what the call is for** (`src/zrb/llm/tool_call/handler.py`, `src/zrb/llm/util/tool_args.py`, `src/zrb/llm/speech/progress.py`, `test/llm/tool_call/test_handler.py`, `docs/llm/tool-approval.md`, `docs/llm/mcp-support.md`): a listener already heard the `purpose`, and a person deciding whether to allow a call did not. `Shell`, `Write` and `Edit` each replace the arguments section with a body of their own — a fenced command, a diff — so `purpose` sat in the part of the section they throw away, and the three tools where a wrong answer costs the most were exactly the three that never showed the line. The prompt now reads `🎯 Deleting the build directory before a clean rebuild` under the tool's name, before the body: drawn in `format_approval_message` above the section and outside it, so every formatter keeps it without knowing about it, and any tool that carries a purpose shows one rather than only the three with a custom body. It is taken out of the arguments below (`without_purpose`), so the prompt says it once instead of twice for a tool whose arguments are shown as YAML. It is flattened to a single line with its control characters dropped before it is shown — a purpose spread over several lines would read as another argument, and an escape sequence could repaint the prompt that is about to be answered — and cut at 200 characters, so a paragraph written into the field cannot push the command off the screen. `read_purpose` moved to `llm/util/tool_args.py`, where the prompt and the spoken line both reach it, and `speech/progress.describe_purpose` now delegates to it instead of holding a second copy: what a listener hears and what a reader approves cannot disagree about what counts as a purpose. Arguments a provider streamed as JSON are read and stripped the same way. Seven tests, and the duplicated import block in `test/llm/tool_call/test_handler.py` that `flake8 --select=F` reported is gone.
