## 3.36.0 (November 6, 2026)

- **Fix: the injected memory block names its store and its own budget** (`src/zrb/llm/memory/render.py`, `src/zrb/llm/prompt/memory_context.py`, `docs/technical-specs/llm-memory.md`): the block tells the model to read `facts/<id>.md` when one line is not enough, and `SearchMemory` returns the same relative path, while the root those paths are relative to appeared nowhere — so both routes into the store handed over half a path no tool could open, and opening a claim meant guessing a directory. The block now says where the store is, and reports the core's budget (`Core: 3412 of 4000 characters (85%), 9 pinned claims and 12 open loops, nothing cut`) so a session planning a pin can see the room instead of learning it from the refusal at write time. The budget line appears only when the core holds a claim, and its `cut` count is the only mention of a claim the cap dropped, since the block simply does not carry it.
- **Security: a store path cannot steer the block it sits in** (`src/zrb/llm/memory/render.py`, `docs/technical-specs/llm-memory.md`): the block writes the store root verbatim on its own line, with any line break folded to a space, so a backtick in the path has no span to close and a newline cannot add one, and a root carrying an instruction marker is withheld the way a claim is — checked after the collapse, since a marker split by a line break is invisible before it and whole again after. The same read-side check now runs on the collapsed text for claims too, so a hand-edited claim cannot do what a written one is refused for. The path is configuration rather than a claim, but the model reads it in the same block the claims arrive in, and that block is data only while nothing in it can end the span it sits in.
- **Feature: reading the worktree a session entered asks nothing** (`src/zrb/builtin/llm/chat_tool_policy.py`, `src/zrb/builtin/llm/chat.py`, `docs/llm/llm-integration.md`): `EnterWorktree` puts its tree outside the checkout, so the `Read`/`LS`/`Glob`/`Grep` auto-approvals — registered against the process's working directory — stopped covering the files the session was actually working on, and every read there waited on a prompt unless YOLO was on. `is_path_inside_active_worktree` resolves the path and approves it when it falls inside the active worktree, beside the working-directory rule and for the same five read tools (`AnalyzeFile` included). A call that names no path still goes to the working-directory rule: `LS`, `Glob` and `Grep` default to `"."`, so approving a pathless call would approve every listing in the session. Writes and edits keep asking, as they do inside the working directory.
- **Improvement: the compaction trigger stops at 200,000 tokens by default** (`src/zrb/config/mixins/llm_content.py`, `test/config/test_config_llm.py`, `docs/configuration/llm-context.md`): every round re-sends the whole conversation, and the trigger was 75% of whatever window the model reported — 375,000 tokens for the half-million-token models zrb knows, so a long turn carried a quarter-million tokens into each of the rounds that followed it. The default is now the smaller of `200000` and that 75%, and an explicitly configured threshold is untouched, so a run that wants the larger window still gets it.
- **Improvement: Shell asks for one call where the sequence is already known** (`src/zrb/llm/tool/shell.py`, `test/llm/tool/test_shell_prompt.py`): each round-trip re-sends the conversation, so the docstring now asks for steps that are already known to run in order to go into one call — `&&` in bash/zsh/sh and cmd, a `;` sequence in PowerShell 5 (which has no `&&`), one small script for node/ruby/php — and names what may not be chained: a step that needs this command's output. The example now shows a chain (`git fetch && git rebase origin/main`) instead of single commands only. The docstring tests moved to `test_shell_prompt.py`, since that file had reached the 500-line test ratchet.
