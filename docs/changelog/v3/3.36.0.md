## 3.36.0 (November 6, 2026)

- **Fix: the injected memory block names its store and its own budget** (`src/zrb/llm/memory/render.py`, `src/zrb/llm/prompt/memory_context.py`, `docs/technical-specs/llm-memory.md`): the block tells the model to read `facts/<id>.md` when one line is not enough, and `SearchMemory` returns the same relative path, while the root those paths are relative to appeared nowhere — so both routes into the store handed over half a path no tool could open, and opening a claim meant guessing a directory. The block now says where the store is, and reports the core's budget (`Core: 3412 of 4000 characters (85%), 9 pinned claims and 12 open loops, nothing cut`) so a session planning a pin can see the room instead of learning it from the refusal at write time. The budget line appears only when the core holds a claim, and its `cut` count is the only mention of a claim the cap dropped, since the block simply does not carry it.
- **Feature: reading the worktree a session entered asks nothing** (`src/zrb/builtin/llm/chat_tool_policy.py`, `src/zrb/builtin/llm/chat.py`, `docs/llm/llm-integration.md`): `EnterWorktree` puts its tree outside the checkout, so the `Read`/`LS`/`Glob`/`Grep` auto-approvals — registered against the process's working directory — stopped covering the files the session was actually working on, and every read there waited on a prompt unless YOLO was on. `is_path_inside_active_worktree` resolves the path and approves it when it falls inside the active worktree, beside the working-directory rule and for the same five read tools (`AnalyzeFile` included). A call that names no path still goes to the working-directory rule: `LS`, `Glob` and `Grep` default to `"."`, so approving a pathless call would approve every listing in the session. Writes and edits keep asking, as they do inside the working directory.
