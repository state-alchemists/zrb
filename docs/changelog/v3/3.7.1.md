## 3.7.1 (September 24, 2026)

- **Fix: the retry summary no longer pairs one tool call's arguments with another's result** (`src/zrb/llm/agent/run/partial_run.py`, `test/llm/agent/run/test_partial_run.py`): `PartialRunAccumulator` held a single "current call" slot and matched results by tool name. Parallel calls stream every `ToolCallEvent` before any result, so two parallel `Read`s were recorded as one entry — the second call's arguments beside the first call's content — and the second was dropped. The `[SYSTEM: PREVIOUS ATTEMPT FAILED]` block then told the model it had read files it had not, and vice versa. Pending calls are now keyed by `tool_call_id`. The test that pinned the dropped call as intended behaviour now asserts both calls survive. The summary also says its results are cut at 500 characters, and that an interruption is usually the user's — so the model follows the user's new message instead of resuming the approach that was interrupted.
- **Fix: retitling or revising a journal note no longer leaves a contradicting duplicate in the indexes** (`src/zrb/llm/tool/journal_write.py`, `test/llm/tool/test_journal_notes.py`): index registration skipped only an identical `- [label](target)` line, so a new title added a second entry for the same file; `hud_line` appended rather than replaced, so a revised finding sat beside the stale one in the always-injected index. Index lines are now relabelled in place by link target, and a HUD line carries a trailing link to its note, which a revision uses to replace the note's earlier line.
- **Improvement: the journal index says how the journal may be changed** (`src/zrb/llm/prompt/live_context.py`, `docs/adr/adr-0055.md`): the journal tools are registered with `defer_loading`, so their docstrings — where ADR-0055 put the journal's rules — are invisible until the model searches for them. A session edited the journal with Read/Edit for twenty calls because nothing visible said otherwise, and then patched the resulting duplicates by hand, leaving uncommitted changes. The `<journal-index>` header now names the three writers, says a direct edit breaks their index, backlink and git bookkeeping, and says to search for them when they are not visible. The writers' docstrings add the same rule for a model that searched first, record only what the session verified, and drop the unconditional "do not announce it", which contradicted reporting the outcome when the user asked for the write. A zero-hit `SearchJournal` is now described as weak evidence of absence.
- **Improvement: the prompt ranks truth above speed and resolves the ask-versus-proceed conflict** (`src/zrb/llm/prompt/markdown/{principle,workflow,profile.standard,profile.capable}.md`): `principle` states one priority order — protect the user's work, then truth, then completeness, then speed — and adds two rules: a claim about something not seen (a prior version, a diff not in hand) is inference to label or omit, and a diagnosis must re-read what it blames. Workflow step 4 now requires reading what a check printed and treating contradicting output as unverified; step 5 reports what was not verified. Tool Discovery's closing "do not search for what visible tools already cover" let a model decide Read/Edit covered journaling despite the bullet naming it; the bullet now says a generic tool approximating a dedicated one does not count, and the exemption is narrowed to a visible tool that is plainly right for the job. `profile.standard` said to raise risks "rather than pausing on them" while `principle` requires confirmation before destructive actions; it now names both stopping conditions. Both profiles activate methodologies on what the *work* matches, the same condition the workflow states.
