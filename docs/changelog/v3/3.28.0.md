## 3.28.0 (October 26, 2026)

- **Feature: the journal grew a day tier, and the compliance judge now checks a long conversation** (`src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/hook/journal_compliance.py`, `src/zrb/llm/hook/turn_evidence.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/config/mixins/llm_content.py`, `test/llm/prompt/test_live_context_day_block.py`, `test/llm/hook/test_journal_compliance.py`, `test/llm/hook/test_turn_evidence.py`, `test/llm/agent/run/test_runner_hooks.py`): the journal held standing knowledge and nothing episodic, so a day could end with its last state written nowhere — measured on 2026-10-26, a working session closed at 17:16 naming two items parked for tomorrow while its own open-items note had last been written at 15:12, and the only surviving copy was a 1.4 MB transcript no prompt can carry. A journal's day tier is the activity log it already had — `activity-log/YYYY/YYYY-MM/YYYY-MM-DD.md` — rather than a second file layout: `LogActivity` already writes one file per day there, under a year/month index hierarchy, git-backed, so the tier is that file read back. Its lines now carry an optional `· imp N` (`LogActivity(importance=...)`, held to 1–10), which is what lets a later session rank a day instead of taking its last five lines; the ranking key is stripped from the block, since it orders lines rather than saying anything to the reader. The first turn of a session renders a `<day>` block beside the journal index — the handover verbatim first, then today's five most important lines and yesterday's two, capped at 1,500 characters — because recognition at the seam is what makes a fresh session resume instead of start: `importance` beats line order, so a trivial last line cannot push out the morning's constraint, and the handover leads because it is the one part no later reader can reconstruct. A section longer than the block allows is cut mid-paragraph rather than at its last line break, which for a one-paragraph handover is the newline right after its heading and would have delivered a heading with nothing under it. The block is rendered only on the first turn, only when `LLM_JOURNAL_ENABLED` is on, and returns nothing when no day file exists, so a journaled setup without a day tier reads exactly as before. **Nothing writes a day file automatically, and that is deliberate.** An earlier revision of this entry flushed one from a `POST_COMPACT` hook; it was dropped before release. A compaction is a conversation-history event, so the only thing a hook on it can know is how many messages and tokens were replaced — telemetry, not anything that happened in the day — and it fires only for sessions long enough to compact, which is not the case it was meant to cover. The `## Handover` section is in the same position: the block reads it, and no tool writes one yet — that writer, and the live-context nudge that makes a day line exist at all, are the next piece. What the day tier needed was a gate that notices a conversation, which is the other half of this change: the built-in journal-compliance judge now runs on `event_data.journal_due` — a turn that wrote files or stated a standing preference, as before, **or** every `LLM_JOURNAL_COMPLIANCE_TURNS` (default 12) user turns — because a conversation that touches no file and says nothing matching a preference pattern was never due on those two counts however long it ran, and that is exactly the session whose work reached no file. The periodic check counts the turns the run has taken, not the prompts its history still holds: a summariser or a prune shortens that history, so counting in it was how a long conversation kept reporting the same number and never came due. It is `turn_evidence.count_user_turn`, LLM-free and bounded. `POST_COMPACT` keeps its before/after counts and its `compacted` flag, and those are now measured against the history that is actually sent: the runner's last-resort force-prune and `_acquire_rate_limit`'s fit to 90% of the window both run before the event, and the "before" side starts after a `PreCompact` hook's own context has joined the history, so one message out and one in can no longer look like nothing happened. Not done, deliberately: no model-written "keep the five lines that matter" pass, and no day→week→year rollup — the first belongs in a slower hook, the second is a sweep with its own failure modes.
- **Feature: the day tier now carries moments, ranks them, and can be recalled mid-conversation** (`src/zrb/llm/prompt/markdown/journal_compliance.md`, `src/zrb/llm/tool/journal_write.py`, `src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/common_tools.py`, `test/llm/test_common_tools.py`, `test/llm/prompt/test_live_context_day_block.py`): the day tier shipped able to hold a day, and nothing wrote the half of a day that is not work. Every criterion the compliance judge had was work-shaped — a decision, a root cause, a stated preference, a non-obvious fact — so a turn that touched no file produced no line, and personal conversation was the one kind of day the journal could not hold; measured on 2026-10-26, a lunch conversation recalled the next morning had left nothing behind anywhere the harness keeps. The judge's criteria now include a moment between the agent and the user — the user's own words quoted, plus one line of why they mattered — which is the format the day tier was designed around and never received. The same prompt now spends `importance`, which was wired and never fed: a later session's first turn shows the highest lines from today and yesterday, so the judge ranks a constraint, a decision still in force, or a moment worth carrying at 7-10 and leaves an ordinary line unranked, where before every line ranked 0 and "today's five most important" was the last five — an evening's file bookkeeping outranking the morning's moment. `LogActivity`'s own text says the same from its side: a line may be a moment rather than work, and a conversation that touched no file still earns one, because that line is the only copy. `SearchJournal` alone is no longer `defer_loading`: recalling something is a decision made mid-conversation, and a schema behind `search_tools` asks the model to think of a search before it can search — the hop that gets skipped, and one that no prompt reminder covers, since the pointer to those tools rides a conversation's first turn only. Its schema costs about 340 tokens on every turn; the four writers stay deferred, because the judge covers the write path and their schemas are the expensive half. The `<day>` block also says how to read itself now — "your memory of the last day or two, not a briefing: use a detail from it where it fits, and never announce or recite this block" — because the block lands in a user turn with nothing else explaining it, and a model that reports what it read ("according to the day block") is the handover the seam exists to avoid. Still not built, and now deliberately: the `## Handover` writer. The block reads that section if one exists, but a writer would make a second place to record where a session left off beside the per-project open-items note, and the measured failure was a note left three hours stale — two places to write makes staleness likelier, not rarer. The judge's own runs are traceable now, in the journal usage log #747 introduced: `judging` on dispatch and `judged` on return, carrying how many journal calls the run made and whether it failed, which `/usage` renders as runs, skips, failures and dispatches that never came back. That pair exists because the judge is spawned fire-and-forget and its result reaches no other surface — measured on 2026-10-27, when a preference stated in a session produced no line, the turn had changed files so the gate was open either way, and nothing recorded whether the judge ran, skipped, or was cut off, which made the miss undiagnosable rather than merely wrong.
- **Fix: a day line carries one timestamp, not two** (`src/zrb/llm/tool/journal_write.py`, `test/llm/tool/test_journal_notes.py`): `LogActivity` derives the line's time and writes it, so an agent that puts a time in the summary gets both — the log held `19:32 — 19:35 — Go tested cross-session memory…` and `23:01 — 2026-10-26 23:01: …`, which reads back as two events at two minutes past each other. A leading time is now dropped from the summary before the line is composed, with or without the ISO date and with or without the dash an agent copies from the file it was reading; the match needs colons and only looks at the start of the line, so `2.5 kg` and a `3:1` ratio survive. A summary ending its own sentence no longer doubles the full stop the tool adds before `Files:`, which is how `refuses..` got into the same log. The tool's own description says the time is derived and a leading one is dropped, because the cheapest fix is the model not writing it at all.
- **Fix: a long handover no longer empties the day block** (`src/zrb/llm/prompt/live_context.py`, `test/llm/prompt/test_live_context_day_block.py`): the block fits its sections in order against a 1,500-character cap, so the handover — which leads it — could fill the cap on its own. On 2026-10-27 a 2,300-character handover produced a 1,484-character block with no Today and no Yesterday in it, the two sections the day tier exists for. Every later section now keeps room for its heading and one line, and the handover takes what is left; a section cut short is still followed by the sections after it. The handover keeps the larger share deliberately: it is the one part no later reader can reconstruct, while a day line a cut drops is one `SearchJournal` away.
- **Feature: a session can leave a handover where the next one reads it** (`src/zrb/llm/tool/journal_write.py`, `src/zrb/llm/common_tools.py`, `test/llm/tool/test_journal_handover.py`): the day block has led with a `## Handover` section since the day tier landed, and nothing in the product wrote one — the only handover in use was typed by hand, so a fresh session read what happened and nothing about the state the last session stopped in. `WriteDayHandover` writes that section into today's activity log, under the day's lines and above any `## Open` list, replacing the earlier handover rather than appending a second one, so a session that changes its mind before leaving can say so. It refuses instead of truncating: over 700 characters, empty, or carrying a `#` heading of its own (which would end the section on the next read and strand the text underneath) each come back with a `[SYSTEM SUGGESTION]` and no write.
