## 3.28.0 (October 26, 2026)

- **Feature: the journal grew a day tier, and the compliance judge now checks a long conversation** (`src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/hook/journal_compliance.py`, `src/zrb/llm/hook/turn_evidence.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/config/mixins/llm_content.py`, `test/llm/prompt/test_live_context_day_block.py`, `test/llm/hook/test_journal_compliance.py`, `test/llm/hook/test_turn_evidence.py`, `test/llm/agent/run/test_runner_hooks.py`): the journal held standing knowledge and nothing episodic, so a day could end with its last state written nowhere — measured on 2026-10-26, a working session closed at 17:16 naming two items parked for tomorrow while its own open-items note had last been written at 15:12, and the only surviving copy was a 1.4 MB transcript no prompt can carry. A journal's day tier is the activity log it already had — `activity-log/YYYY/YYYY-MM/YYYY-MM-DD.md` — rather than a second file layout: `LogActivity` already writes one file per day there, under a year/month index hierarchy, git-backed, so the tier is that file read back. Its lines now carry an optional `· imp N` (`LogActivity(importance=...)`, held to 1–10), which is what lets a later session rank a day instead of taking its last five lines; the ranking key is stripped from the block, since it orders lines rather than saying anything to the reader. The first turn of a session renders a `<day>` block beside the journal index — the handover verbatim first, then today's five most important lines and yesterday's two, capped at 1,500 characters — because recognition at the seam is what makes a fresh session resume instead of start: `importance` beats line order, so a trivial last line cannot push out the morning's constraint, and the handover leads because it is the one part no later reader can reconstruct. A section longer than the block allows is cut mid-paragraph rather than at its last line break, which for a one-paragraph handover is the newline right after its heading and would have delivered a heading with nothing under it. The block is rendered only on the first turn, only when `LLM_JOURNAL_ENABLED` is on, and returns nothing when no day file exists, so a journaled setup without a day tier reads exactly as before. **Nothing writes a day file automatically, and that is deliberate.** An earlier revision of this entry flushed one from a `POST_COMPACT` hook; it was dropped before release. A compaction is a conversation-history event, so the only thing a hook on it can know is how many messages and tokens were replaced — telemetry, not anything that happened in the day — and it fires only for sessions long enough to compact, which is not the case it was meant to cover. The `## Handover` section is in the same position: the block reads it, and no tool writes one yet — that writer, and the live-context nudge that makes a day line exist at all, are the next piece. What the day tier needed was a gate that notices a conversation, which is the other half of this change: the built-in journal-compliance judge now runs on `event_data.journal_due` — a turn that wrote files or stated a standing preference, as before, **or** every `LLM_JOURNAL_COMPLIANCE_TURNS` (default 12) user turns — because a conversation that touches no file and says nothing matching a preference pattern was never `journal_worthy` however long it ran, and that is exactly the session whose work reached no file. The periodic check counts user prompts, not messages, since a `ModelRequest` also carries a system prompt, tool returns and retry feedback. It is computed by `turn_evidence.user_turn_count`, which is LLM-free and reads parts rather than message types. `POST_COMPACT` keeps its before/after counts and its `compacted` flag, and those are now measured against the history that is actually sent: the runner's last-resort force-prune and `_acquire_rate_limit`'s fit to 90% of the window both run before the event, and the "before" side starts after a `PreCompact` hook's own context has joined the history, so one message out and one in can no longer look like nothing happened. Not done, deliberately: no model-written "keep the five lines that matter" pass, and no day→week→year rollup — the first belongs in a slower hook, the second is a sweep with its own failure modes.
