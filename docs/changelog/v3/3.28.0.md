## 3.28.0 (October 26, 2026)

- **Feature: the journal grew a day tier, and a compaction flushes into it** (`src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/hook/journal_day_flush.py` new, `src/zrb/llm/hook/journal_compliance.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/config/mixins/llm_content.py`, `test/llm/prompt/test_live_context_day_block.py`, `test/llm/hook/test_journal_day_flush.py`, `test/llm/hook/test_hook_enablement.py`): the journal held standing knowledge and nothing episodic, so a day could end with its last state written nowhere — measured on 2026-10-26, a working session closed at 17:16 naming two items parked for tomorrow while its own open-items note had last been written at 15:12, and the only surviving copy was a 1.4 MB transcript no prompt can carry. A journal now has `days/YYYY-MM-DD.md`: one line per event (`time · where · what · imp N`), a `## Handover` section written by the departing agent for whoever takes over, and an `## Open` list. The first turn of a session renders a `<day>` block beside the journal index — the handover verbatim first, then today's five most important lines and yesterday's two, capped at 1,500 characters — because recognition at the seam is what makes a fresh session resume instead of start: `importance` beats line order, so a trivial last line cannot push out the morning's constraint, and the handover leads because it is the one part no later reader can reconstruct. A section longer than the block allows is cut mid-paragraph rather than at its last line break, which for a one-paragraph handover is the newline right after its heading and would have delivered a heading with nothing under it. The block is rendered only on the first turn, only when `LLM_JOURNAL_ENABLED` is on, and returns nothing when no day file exists, so a journaled setup without a day tier reads exactly as before. `journal-day-flush` runs once the history has been processed and appends the line a compaction would otherwise erase: how many messages and tokens went away, what is left, and the last thing the user asked — the prompt that caused the compaction, which `_prepare_history` sends with the event because it joins the history only afterwards, and failing that the newest user turn in history. It writes only when the history was actually replaced: both compaction events fire on every turn, so a hook that wrote on each would put a line in the day file per turn, which is noise wearing a record's shape. The quote is the user's own words above the injected `<live-context>` block, read through a prompt that may be a string, a flat list carrying an attachment, a `ModelRequest` whose user part holds either, or a JSON replay of one; an attachment contributes nothing, since `str` of an image part is the repr of its bytes rather than anything anyone typed. The heading is written with the first line in one append rather than in a separate create step, so two sessions compacting into the same new day cannot have one write a heading over the other's line. The quote is only ever the user's own parts: a `ModelRequest` carries a system prompt and tool returns beside the user's turn, and those are not things anybody asked. It takes no model call and makes no judgement about what mattered — a flush rides on the most expensive moment of a session — and a failed write is logged and swallowed rather than raised into the compaction path. Because a built-in hook that cannot be switched off alone forces `HOOKS_ENABLED=off` for all of them, the flush and the compliance judge each got their own boolean — `LLM_JOURNAL_DAY_FLUSH_ENABLED` and `LLM_JOURNAL_COMPLIANCE_ENABLED`, both `on`, beside `LLM_JOURNAL_GIT_ENABLED` and shaped like `LLM_SELF_REVIEW_ENABLED` — rather than a second list of names beside the existing `LLM_HOOKS` allowlist: a name list has no schema, is invisible in a config listing, and a typo in it silently disables nothing. The flush still answers to `journal-day-flush` in that allowlist, because it is a callable carrying that name rather than a function carrying its Python one. Not done, deliberately: no model-written "keep the five lines that matter" pass, and no day→week→year rollup — the first belongs in a slower hook if it belongs anywhere, the second is a sweep with its own failure modes.
