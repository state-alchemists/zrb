## 3.22.0 (October 17, 2026)

- **Feature: emotion** (`src/zrb/llm/emotion/`, `src/zrb/llm/prompt/markdown/emotion_live.md`, `src/zrb/config/mixins/llm_emotion.py`, `src/zrb/builtin/llm/chat.py`, ADR-0112): with `ZRB_LLM_EMOTION_ENABLED=on`, the model opens each reply with an emoji for how it feels (😊 😢 😠 😮 😌 🙂). zrb strips the emoji from the streamed and the stored reply, so the user never sees it, and keeps the emotion as `current_reply_emotion`. The user's dictated tone reaches the model as `InputProvenance.tone` and `tone_score`, on the live context's Input line. Off by default.
- **Feature: `Emotion` hook event** (`src/zrb/llm/hook/types.py`, `interface.py`, `creator.py`, `matcher.py`): an observe-only, zrb-specific event fired with each reply's emotion and each prompt's tone. `HookContext` gains `emotion` (VRM 1.0 preset expression names) and `emotion_source` (`user` or `assistant`), exported to command hooks as `CLAUDE_EMOTION` and `CLAUDE_EMOTION_SOURCE`; matchers match on `emotion_source`. An avatar such as zrb-face can show it.
- **Feature: dictation hears the speaker's tone** (`src/zrb/llm/dictation/emotion.py`, `src/zrb/llm/dictation/feature.py`, `src/zrb/config/mixins/llm_dictation.py`): with `ZRB_LLM_DICTATION_DETECT_EMOTION=on`, emotion2vec+ (`ZRB_LLM_DICTATION_EMOTION_MODEL`, `ZRB_LLM_DICTATION_EMOTION_MIN_SCORE`) classifies each hands-free utterance alongside any transcription backend. A confident happy, sad, angry or surprised becomes the turn's tone, never part of the user's words. It was right 97% of the time on RAVDESS, at ~0.3 s a clip on a CPU. It needs funasr and torch; without them, or when the model fails on a clip, dictation carries on without a tone.
- **Feature: a voice per emotion** (`src/zrb/llm/speech/feature.py`, `player.py`, `backend/pipecat.py`, `pipecat_tts.py`, `src/zrb/config/mixins/llm_speech.py`): `ZRB_LLM_SPEECH_EMOTION_VOICES` maps an emotion to the voice a reply with that emotion is read in; everything else uses `ZRB_LLM_SPEECH_VOICE`. The Pipecat services (pocket, kokoro, piper) honor it; with pocket, a `.wav` spoken in that emotion carries its tone over. `Speaker.say` takes a `voice`, which backends read from the ambient `current_speech_voice`.
- **Feature: `sensevoice` dictation backend** (`src/zrb/llm/dictation/backend/sensevoice.py`, `src/zrb/llm/dictation/backend/builtin.py`, `src/zrb/config/mixins/llm_dictation.py`): SenseVoice on sherpa-onnx, local and fast on a CPU. It downloads its model (`ZRB_LLM_DICTATION_SENSEVOICE_MODEL`) from Hugging Face on first use and starts from the cache afterwards, listening ~7 s after launch. Its built-in emotion tag is ignored: it was right 18% of the time on English speech. Needs `pip install sherpa-onnx huggingface_hub`.
- **Feature: capability factories on `LLMChatTask`** (`src/zrb/llm/task/chat/task.py`, `src/zrb/llm/task/chat/execution.py`): `append_capability_factory`, `prepend_capability_factory`, `set_capability_factories` and `remove_capability_factory` build pydantic-ai capabilities per run from the task context, like tool factories. A factory returning an empty list adds none.
- **Improvement: a local voice loads when the chat starts** (`src/zrb/llm/speech/player.py`, `src/zrb/llm/speech/feature.py`, `src/zrb/llm/speech/backend/`): with speech on, `Speaker.warm_up()` synthesizes one unplayed word through a local Pipecat voice (pocket, kokoro, piper), so the first sentence no longer waits up to 2.6 s for the model. A remote voice, one a backend's `is_local` does not claim, is never warmed, since it would bill for the word. Quitting does not wait for a voice still loading or downloading.
- **Fix: Ctrl+C could not stop a session whose microphone was opening** (`src/zrb/llm/dictation/listen.py`): on WSL2, opening the microphone could stall the event loop for seconds. It now opens on a daemon thread, a microphone that finishes opening after cancellation is closed, and a reopened microphone's audio is no longer joined to the previous stream's.
- **Fix: Ctrl+C during a turn could leave zrb running forever** (`src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/multi_ui.py`, `src/zrb/llm/ui/base/message_queue.py`): quitting while the model was answering cancelled the turn, the turn handled the cancel and returned, and the message loop took that as an ordinary finish and waited for the next message while teardown waited for the loop. The terminal stayed blank and Ctrl+C did nothing. The loop now ends whenever it was cancelled, however the turn ended; Esc still cancels only the turn. Present in 3.21.0 and earlier.
- **Fix: Pipecat's debug lines wrote over the chat** (`src/zrb/llm/voice/manager.py`): loguru's default stderr sink, which Pipecat logs through, is replaced by one that forwards to `logging`, so its records are filtered like zrb's own. Sinks a project added to loguru are left in place.
