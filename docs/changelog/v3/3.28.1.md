## 3.28.1 (October 28, 2026)

- **Fix: a redirect's target is one path, not the rest of the line** (`src/zrb/llm/ui/base/conversation_commands.py`, `test/llm/ui/test_ui_command_handlers_output.py`): `> ` and `/redirect ` took everything after them as a filename, so a paragraph pasted after the command was written to a file named after the paragraph — and because a terminal pastes text in one go, the paste landed in the input field whole and the redirect consumed it silently. A target is now read the way a shell reads one: exactly one word, quoted or backslash-escaped when it has spaces, and `> a b` is not a redirect at all, which is what a shell calls an ambiguous redirect. A line that fails that test is left alone and goes to the agent as the text it is, which is what a paste was for. The bare command still copies the last output to the clipboard, and `> "my notes.txt"` still writes to the file with the space in its name.
