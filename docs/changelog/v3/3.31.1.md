## 3.31.1 (November 1, 2026)

- **Fix: a tag named in code opens nothing** (`src/zrb/llm/util/spoken.py`): a reply that wrote `<spoken>` inside backticks or a fenced block — saying what the syntax is, or showing an example — had that tag obeyed as a real marker. The block it opened never closed, so the rest of the reply was rendered as a blockquote on screen and the prose meant for the eye was read aloud; the reply that reported this had half of itself swallowed by a quotation of its own syntax. Markers are now found by a scanner that knows an inline code span and a fenced block, and it keeps its state across deltas, so the whole-reply and the streaming copies of a reply still decide with one rule. A tag in code stays where the reply put it, in both copies. An indented code block is not recognized, no more than it is by `clean_for_speech`.
- **Fix: a quote the reply writes is shown, never spoken** (`src/zrb/llm/speech/text.py`, `src/zrb/llm/speech/feature.py`): only a `<spoken>` block reaches the ear, so a blockquote in the reply is typography — set off on screen, and now silent. A reply that opened no block used to have its quotes read out with only the `>` stripped, so quoting the documentation, a changelog line or a user's own words meant hearing them; `without_blockquotes` takes those paragraphs out first. A quote *inside* a block is still heard: there the model asked for it.
