## 3.40.0 (November 15, 2026)

- **Feature: `/sandbox` flips containment from inside the conversation** (`src/zrb/llm/sandbox/state.py`, `src/zrb/llm/ui/base/model_commands.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/ui/default/output.py`, `docs/llm/sandbox.md`): `LLM_SANDBOX_ENABLED` had no switch a conversation could reach: the environment, or a `/set` typed in the middle of an answer. `/sandbox` (`LLM_UI_COMMAND_SANDBOX`) flips it, and `/sandbox on|off` names the state. The choice belongs to the session: it is read per tool call, so a flip reaches a turn already running, another session in the same process keeps its own, and the deployment's setting is left as written. The runner no longer freezes a config-derived policy into the gate's `deps` — an explicit run policy still passes through, the rest resolves per call — and it publishes what the run was given. The info bar's `Sandbox:` and the status bar's `🐚 sandboxed` ask the resolver a tool call gets, so a session started with the sandbox on, or a task passing `sandbox=True` over a deployment that has it off, now shows it. A route may also say which arguments it accepts, so `/sandbox maybe` stays a message instead of vanishing into "not available while the model is thinking".
- **Feature: `/judge` switches the shell judge for one session** (`src/zrb/llm/approval/judge_state.py`, `src/zrb/llm/agent/run/deferred_calls.py`, `src/zrb/llm/ui/base/model_commands.py`, `src/zrb/llm/ui/default/app/completion/completer.py`, `docs/adr/adr-0141.md`): `LLM_SHELL_JUDGE_ENABLED` was the same kind of setting, so wanting the judge for one careful stretch meant editing config mid-answer. `/judge` (`LLM_UI_COMMAND_JUDGE`) flips it for the session that typed it, and `/judge on|off` names the state; the cascade asks the session, read per command, so a flip reaches a turn already running. Only consultation is reachable: `LLM_SHELL_JUDGE_AUTO_APPROVE_ENABLED` stays a deployment setting, because letting a `safe` verdict skip the prompt removes a person from the loop. The info bar carries `🔨 Judge:`, the completion menu offers all four toggles (closing a `/yolo` gap older than this release), and the judge settles above the `PermissionRequest` hook, so a command its verdict skips is never announced.
- **Feature: the shell judge answers in a schema, and its verdict is coloured** (`src/zrb/llm/agent/shell_judge.py`, `src/zrb/llm/tool_call/judge_note.py`, `src/zrb/llm/prompt/markdown/shell_judge.md`, `docs/adr/adr-0141.md`): the judge answered in prose that a regular expression read, so a model that ignored the format still looked like a verdict until the parse said otherwise. It is asked for a `JudgeVerdict` now — a `level` from `safe`, `caution` and `dangerous`, plus a `reason` — and the model call enforces the shape; an answer that does not fit is a failed call, which is `unknown`, which asks. A provider without tool calling still goes through the regular expression, failing closed as before. The prompt line leads with one wide circle per level — 🟢, 🟡, 🔴, ⚪ — with the word beside it, and a test pins the glyphs at two columns so a fifth cannot be added carelessly. ADR-0141's consequence was rewritten rather than contradicted.
- **Feature: the voice can live in the page a face server serves** (`src/zrb/config/mixins/llm_voice.py`, `src/zrb/llm/dictation/remote_microphone.py`, `src/zrb/llm/speech/remote_output_stream.py`, `src/zrb/llm/util/face_server.py`, `docs/configuration/llm-voice-camera.md`): `ZRB_LLM_VOICE_REMOTE_URL` moves both halves of the voice at once — dictation reads the microphone from the server's `GET /audio/in`, and every sentence speech says goes to its `POST /say` — so this machine opens neither a microphone nor an output stream and the voice belongs to the page: a phone held across the room. The switch is exclusive by design: no sentence is handed to a local player program, a backend that made no audio leaves the sentence unsaid rather than speaking it twice, and a server that cannot be reached is reported rather than stood in for. Echo cancellation is the browser's, and `ZRB_LLM_VOICE_REMOTE_TOKEN` — or the server's own `ZRB_AVATAR_TOKEN` — rides every route. Unset, both devices stay where they were.
- **Feature: a camera that is not on this machine is the page's** (`src/zrb/llm/camera/backend/remote.py`, `src/zrb/llm/camera/backend/auto.py`, `src/zrb/llm/camera/backend/builtin.py`, `src/zrb/llm/util/face_server.py`, `docs/llm/voice-camera.md`): `RemoteCameraBackend` turns the face server's page into a camera — `GET /frame` takes one photo and `GET /frame/devices` lists the names the page gives its lenses — and is exported from `zrb.llm.camera` like the other built-in backends. With `ZRB_LLM_VOICE_REMOTE_URL` set, `auto` offers the page's cameras beside this machine's, so `phone-back` reaches the phone while `0` still reaches the laptop, and a name this machine does not have is asked of the page; `remote` is that page alone. A named camera never becomes another camera's photo: when the page does not answer there is no photo, and the failure hint names the backend that was asked. The device list is cached and refreshed behind the completion, and a scheme other than `http`/`https` is refused where the setting is read.
- **Feature: a memory day line names the file behind it** (`src/zrb/llm/memory/render.py`, `docs/technical-specs/llm-memory.md`): the block promises that every line names the file to read, and the day lines were the ones that did not — the week note and a fact ended with a path while today's claim, the handover and the last day written carried the sentence alone. A body is never injected, since the block is capped and a day is a page, so the path is the only thing that lets a later session read the day rather than its claim. Each of the three now ends with `[diary/<id>.md, body <n> chars]`, or the file alone when the day was written without a body, and a day another line already named is not named twice.
- **Improvement: a day's page holds 8,000 characters** (`src/zrb/config/mixins/llm_content.py`, `docs/technical-specs/llm-memory.md`): the diary body cap was 5,000 characters and a day grows through the day — three ordinary morning appends were refused whole, so the last paragraph written was the one lost. The body is never injected, so the number costs nothing until someone reads the day. The default is 8,000 now, still about one page at roughly thirteen hundred words, and the cap is still enforced by refusal rather than truncation. A value you set still wins.
- **Fix: the transcript stays where the reader put it** (`src/zrb/llm/ui/default/app/follow.py`, `src/zrb/llm/ui/default/lifecycle.py`, `src/zrb/llm/ui/default/output.py`): the refresh loop repaints while the input has focus, and every tick pulled the output pane to the bottom — so reading a reply and typing the next message could not happen together, because the input has focus exactly while the next message is typed. Following the tail is now remembered from before the text grew: `OutputFollow` records whether the pane was following, the append path writes it, the wheel and paging keys write it when the reader moves, and a submitted message resumes it. The rule lives in `UILifecycle.scroll_output_to_bottom`, where a test can reach it, rather than in the loop's condition.
- **Fix: the page's speaker survives a real network** (`src/zrb/llm/speech/remote_output_stream.py`, `test/llm/speech/test_remote_output_stream.py`): four ways the remote voice would have failed once it left this machine. The page's speaker was never counted as an open stream, so the count went negative on the first sentence and a process ending after the voice had been on the page would have hung at exit. An `https` base URL was opened with the cleartext connection class, sending the token and the audio in the clear; the scheme now picks the class, and each keeps its own default port. A route that refused a sentence — 415 for a rate the page cannot play, 401 for a token it does not know — was dropped without a word, and is now said with its status. And one lock covers a whole chunked write, so `close` cannot race the writer onto the body.
- **Fix: a page's camera answers inside its deadline, or not at all** (`src/zrb/llm/camera/backend/remote.py`, `test/llm/camera/backend/test_remote.py`): the request's timeout bounded one socket read, not the body, so a page that trickled a byte at a time could hold a capture open indefinitely, and a timed-out capture left its thread blocked in `read()`, one per photo. The deadline now covers the whole call, the request is hung up on when it passes, and the `IncompleteRead` that wakes the thread becomes the reported failure every other refusal already was. A timeout of `0` is read as no limit, the rule the rest of the package follows, instead of putting the socket in non-blocking mode. And a device name is only called absent once this machine's slow listing has settled, so a cold Windows probe cannot spend the page's share of the deadline on a local camera.
- **Fix: a delegated turn is not the user's turn** (`src/zrb/llm/tool/delegate/runner.py`, `test/llm/tool/delegate/test_delegate_tool_run.py`): a delegation built its first `SubAgentTurn` without the `nested` mark, and the default is `False`, so a sub-agent's `Stop` said `nested_run: false`. Speech, which skips a reply that is not this session's or not the user's turn, then read the sub-agent's report aloud; the same mark keeps a sub-agent out of self-review and off the published sandbox policy. The delegation now passes `nested=True`, as the live-session continuation already did.
- **Documentation: the agent guide points at the pages that own each rule** (`AGENTS.md`, `docs/contributing/coding-conventions.md`, `docs/contributing/code-map.md`, `docs/contributing/agent-workflow.md`): `AGENTS.md` had grown to 82 lines and already duplicated documents that owned the same rules, while the sections other pages cited had been removed, so every pointer to them was stale. It is a 47-line entry point now — what a change must satisfy, one line each, with a link — and the detail lives on the page that owns it. Every live reference to a removed section was repointed, including ADR-0033/0034/0035/0050/0057/0058/0098/0104, and two pre-existing drifts were fixed on the way: R1–R12 is R1–R13, and ADR-0033's four lazy-import categories are five.
- **Documentation: each maintainer job has its own page, and every config knob a named home** (`docs/contributing/maintainer-guide.md`, `docs/contributing/releasing.md`, `docs/contributing/performance.md`, `docs/contributing/evaluating-the-agent.md`, `test/architecture/test_config_docs_cover_every_knob.py`): the maintainer guide carried ten jobs in 321 lines, so a reader looking for one paid for the other nine. The changelog and publishing, the two measurements behind a lazy import, and the agent evaluation are now `releasing.md`, `performance.md` and `evaluating-the-agent.md`. A new architecture test walks the `EnvField`s in the `CFG` MRO and fails on a canonical key no live page names; it found two real gaps, `LLM_MEMORY_DIARY_MAX_CHARS` and `LLM_MEMORY_HANDOVER_MAX_CHARS`. The maps now say what they are for — architecture is the why, the Code Map the where, the Change Map the symptom-to-file lookup — and a glossary gives the load-bearing terms one line each.
- **Documentation: `/volume`'s help names the number it accepts** (`src/zrb/config/mixins/llm_ui_commands.py`): `LLM_UI_COMMAND_VOLUME`'s help described only `+++` and `--`, so the generated config reference taught a smaller command than the one that exists — `/volume 15` and `/volume 15%` have set the level outright since 3.39.0. The docstring now says so, matching the command's own help, the TUI page and ADR-0128.
