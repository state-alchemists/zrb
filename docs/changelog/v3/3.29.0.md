## 3.29.0 (October 30, 2026)

A release about being understood: what the agent shows, what it says out loud, what a decision needs in order to be made, and what the screen can hold while it waits. Six changes, each usable on its own.

- **Feature: a reply can say which part is heard, and the rest stays for the eye** (`llm/util/spoken.py`, `llm/speech/streamed_reply.py`, `llm/speech/feature.py`, `llm/prompt/markdown/speech_live.md`): a reply may put what should be read aloud in one `<spoken>...</spoken>` block; everything outside it is shown and never spoken, and the markers reach neither. A reply with **no block is read aloud whole**, exactly as before, so a model that forgets the block degrades to the old behaviour instead of falling silent. While a reply streams, only a block is said — nothing outside one is said on the chance that no block follows — and a reply that keeps no block is read whole when the turn ends. The prompt asks for the block to be written for the ear rather than the eye: "three dot seven", never "3.7", because a speech engine drops the dot and puts a long pause there. The emoji still goes inside the block as its first character, and still chooses the emotion's voice.
- **Fix: prose written before a tool call stays on screen** (`llm/util/stream_response.py`, `llm/ui/default/output.py`, `llm/ui/tracked_spans.py`): a turn that went text → tool call → text collapsed the first text to a `💬 Response (N chars)` placeholder, and only the last message was rendered in full. The text was never lost — it was behind Ctrl+O — but reading it meant scrolling up, or knowing the key. An intermediate text block now settles under its own muted `💬 Response (N chars)` marker, with the rendered prose below it and Ctrl+O folding it back to the marker; the run's final block still collapses, because the turn-end render would otherwise show it twice. Thinking blocks collapse as before.
- **Feature: a tool call can carry the purpose it is being run for** (`llm/tool/shell.py`, `llm/speech/progress.py`): `Shell` takes an optional `purpose`, and the spoken progress line says it verbatim instead of the fixed per-tool template — "getting the biggest file", not "running a command", and never the raw command. Every unusable purpose (absent, empty, non-string, unparseable) falls back to the template, and a silent tool stays silent.
- **Feature: a question carries the context to answer it, and an option can be recommended** (`llm/tool/ask.py`, `llm/ui/default/selection.py`, `llm/ui/any_ui.py`): `AskUserQuestion` questions may carry a short `context` — the few facts the answer depends on — rendered above the question in the choice panel, and recorded in full in the scrollback echo, so a long one lives there rather than in the panel; options may carry `recommended`, shown as a `★` in the row's gutter and named in the key hint when one is present. Picking a recommended option still resolves to the plain label.
- **Feature: the panels dock instead of floating over the transcript** (`llm/ui/default/app/docking.py`, `llm/ui/default/app/layout.py`, `llm/ui/default/app/keybinding.py`, `llm/ui/default/selection.py`, `llm/ui/default/agent_picker.py`, `llm/ui/default/side_question.py`; ADR-0133): the choice, the `/btw` answer and the agent picker were floats — they covered whatever was underneath, and while one held the focus the transcript could not even be scrolled. They take their rows out of the layout now: the choice and the picker in the input frame's place, because they own the typing while they are up, and `/btw` above the frame, because a character typed there starts a message. A panel may take a third of the screen and never more than the layout can spare; content longer than that is a window which follows the cursor with the key hint pinned, and PageUp/PageDown walk the transcript whichever pane has the focus. Where there are not enough rows to paint one, the panel does not open: the question with its options, the picker's notice, a `/btw` question with whatever answer it already carried, and every command reply go to the transcript instead.
- **Feature: a send-now key moves a running delegation aside, so the message is read in the same turn** (`llm/tool/delegate.py`, `llm/tool/delegate_background.py`; ADR-0132): a synchronous `DelegateToAgent` held the turn for as long as its sub-agent ran — a whole agent loop, an hour and nine minutes in the session that prompted this. The sub-agent now runs as a task raced against the send-now key: a cut hands it to the background registry under a handle and reports it as still running, so `GetDelegationResult(handle=...)` collects it later, and a fan-out moves every sibling still in flight. Nothing is cancelled by the move; a turn cancelled before any move still stops what it started.
