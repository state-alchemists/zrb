## 3.29.0 (October 30, 2026)

Ten changes: what the agent shows, what it says aloud, what a decision needs, and what the screen can hold while it waits. Each is usable on its own.

- **Feature: a reply can mark the part that is heard, and keep the rest for the eye** (`llm/util/spoken.py`, `llm/speech/streamed_reply.py`, `llm/speech/feature.py`, `llm/prompt/markdown/speech_live.md`): a reply may put the spoken text in one `<spoken>...</spoken>` block. Everything outside it is shown and never spoken, and the markers reach neither. A reply with **no block is read aloud whole**, exactly as before, so a model that forgets the block degrades to the old behaviour instead of falling silent. While a reply streams, only a block is said; a reply that keeps no block is read whole when the turn ends. The prompt asks for the block to be written for the ear rather than the eye — "three dot seven", never "3.7", because a speech engine drops the dot and inserts a long pause. The emoji stays inside the block as its first character and still chooses the emotion's voice.
- **Fix: prose written before a tool call stays on screen** (`llm/util/stream_response.py`, `llm/ui/default/output.py`, `llm/ui/tracked_spans.py`): a text → tool call → text turn collapsed the first text to a `💬 Response (N chars)` placeholder, and only the last message was rendered in full. The text was behind Ctrl+O, but reading it meant scrolling up or knowing the key. An intermediate block now settles under its own muted marker, with the prose below it; Ctrl+O folds it back to the marker. The run's final block still collapses, because the turn-end render would otherwise show it twice. Thinking blocks collapse as before.
- **Feature: a tool call can carry the purpose it runs for** (`llm/tool/shell.py`, `llm/speech/progress.py`): `Shell` takes an optional `purpose`, and the spoken progress line says it verbatim instead of the fixed per-tool template — "getting the biggest file", not "running a command", and never the raw command. Every unusable purpose (absent, empty, non-string, unparseable) falls back to the template, and a silent tool stays silent.
- **Fix: an approval request is read aloud as its purpose, not its command** (`llm/speech/feature.py`, `llm/speech/progress.py`): a listener was asked to approve `find . -type f | xargs ls -S | head -1`, the raw command, because `purpose` reached the progress line but not the approval line. `describe_tool_call` now fills its `{target}` slot with the purpose, and `{action}` is unchanged. One reading of a purpose (`describe_purpose`) serves both lines, so they cannot disagree about what counts as one. Every no-purpose shape falls back to the first `LLM_SPEECH_APPROVAL_TARGET_KEYS` entry exactly as before, and `LLM_SPEECH_APPROVAL_TARGET_MAX_CHARS` still cuts `{target}`; `0` still leaves it out.
- **Feature: a question carries the context to answer it, and an option can be recommended** (`llm/tool/ask.py`, `llm/ui/default/selection.py`, `llm/ui/any_ui.py`): `AskUserQuestion` questions may carry a short `context` — the few facts the answer depends on — shown above the question in the choice panel and recorded in full in the scrollback echo, so a long one lives there rather than in the panel. Options may carry `recommended`, shown as a `★` in the row's gutter and named in the key hint when one is present. Picking a recommended option still resolves to the plain label.
- **Feature: panels dock instead of floating over the transcript** (`llm/ui/default/app/docking.py`, `llm/ui/default/app/layout.py`, `llm/ui/default/app/keybinding.py`, `llm/ui/default/selection.py`, `llm/ui/default/agent_picker.py`, `llm/ui/default/side_question.py`; ADR-0133): the choice panel, the `/btw` answer and the agent picker were floats that covered what was underneath and blocked transcript scrolling while focused. They now take rows out of the layout: the choice and the picker take the input frame's place because they own typing while up, and `/btw` sits above the frame because typing there starts a message. A panel may take a third of the screen and never more than the layout can spare; longer content becomes a window that follows the cursor with the key hint pinned. PageUp/PageDown walk the transcript whichever pane has focus. When there are too few rows to paint a panel, it does not open: the question and its options, the picker's notice, a `/btw` question with any answer it already carried, and every command reply go to the transcript instead.
- **Feature: a send-now key moves a running delegation aside, so the message is read in the same turn** (`llm/tool/delegate.py`, `llm/tool/delegate_background.py`; ADR-0132): a synchronous `DelegateToAgent` held the turn for as long as its sub-agent ran — a whole agent loop, an hour and nine minutes in the session that prompted this. The sub-agent now runs as a task raced against the send-now key: a cut hands it to the background registry under a handle and reports it as still running, so `GetDelegationResult(handle=...)` collects it later, and a fan-out moves every sibling still in flight. Nothing is cancelled by the move; a turn cancelled before any move still stops what it started. A session's teardown cancels only the delegations it started, so another chat session exiting in the same process no longer leaves this one's handle answering `Unknown handle`.
- **Fix: every line of run prose lands in the column the run streams at** (`llm/ui/default/output.py`, `llm/ui/base/ui.py`, `llm/ui/base/replay.py`, `llm/ui/multi_ui.py`, `llm/ui/std_ui.py`, `llm/ui/buffered_ui.py`, `llm/ui/default/side_question.py`, `llm/task/chat/running.py`, `llm/util/stream_response.py`): the answer appended at the end of a turn went through `append_markdown` and landed at the margin, while the copy it replaced had streamed five columns in, so the block jumped left exactly when the turn ended. `append_answer` is now the hook for that text, and the rule lives in one place: `_render_at_column` is the only reader of `stream_indentation` and the only code that narrows the render and prefixes the column. The settled block, the turn's answer, both `/btw` paths, a replayed history, `MultiUI`'s answer append and a non-interactive turn's finalization all go through it. A UI written before the hook still receives the answer — `append_answer`, then `append_markdown`, then the pre-rendered text — so the layout may differ but the text never disappears. A replayed answer that arrives before any run reports its column starts in `DEFAULT_STREAM_INDENTATION`. A settled block's marker takes the icon's line, so it starts in the icon's column — one continuation pad left of the prose — instead of at the margin. A whole-turn transcript test drives the real wiring and fails by naming the line that left the column; an architecture test fails on a second reader of the column.
- **Feature: an interrupting message ends a monitoring wait, and says so** (`llm/shell_cut.py`, `llm/tool/shell_background.py`, `llm/tool/delegate_background.py`): `MonitorProcess(wait=N)` and `GetDelegationResult(wait=N)` blocked for up to five minutes, so a message that needed the turn either waited behind them or came back as an ordinary status report with no sign the wait was cut short. A wait is not work, so an interrupting message now ends it: the result starts with `[interrupted]`, says the process or sub-agent is still running, names the call that picks the same wait up again with its `wait=N`, and warns that a retry which restarts the work would be a second copy. Nothing is cancelled — the process keeps draining into its captures, the sub-agent keeps running, the handle is untouched — and the cut is the run's own signal, so one session's send-now cannot end another session's wait. A wait that settles in the same pass as the cut reports the finished work instead of the interruption, because the retry would point at a handle `poll` has already consumed. `Shell`'s adopt-to-background behaviour is unchanged (ADR-0132).
- **Fix: a sentence that made no audio is asked for again, and one spoken chunk has a length you can set** (`llm/speech/player.py`, `llm/speech/feature.py`, `config/mixins/llm_speech.py`): a local voice that renders audio for zrb to play sometimes returns none — "audio context completed with no audio (1 in a row)" — and the sentence was dropped mid-reply, taking the rest of that reply's speech with it. A local voice is now asked twice before it is given up on, and a remote voice once, because a render nobody hears is still billed. Failures are still counted per sentence, so a service that is really gone is replaced after three; where both attempts make nothing, the warning carries the start of the sentence so it can be found and said again by hand. `LLM_SPEECH_CHUNK_MAX_CHARS` sets the longest run of prose said as one piece — 250 characters by default, as before — because an engine with a smaller token window drops the words past it: Pocket TTS takes 50 tokens and says so in its log, and 180 characters stays inside that.
