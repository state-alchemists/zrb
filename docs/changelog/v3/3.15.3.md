## 3.15.3 (October 10, 2026)

- **Fix: `SearchJournal` parses ripgrep matches on a Windows path** (`src/zrb/llm/tool/journal.py`, `test/llm/tool/test_journal.py`): a match line is `path:line:content`, and the parser split it on the first two colons, so `C:\notes\2024-01-02.md:7:text` became the file `C`, the line `\notes\2024-01-02.md` and the content `7:text`. The line is now matched as `path:<digits>:content`, which keeps the drive letter in the path.
- **Tests: the ripgrep journal test no longer needs the `rg` binary** (`test/llm/tool/test_journal.py`): `test_find_matches_with_ripgrep` faked `shutil.which` but still ran the real `rg`, so it failed on the Windows runner whenever the package install was missing (`[WinError 2]`). It now mocks `subprocess.run` with ripgrep's output, like its neighbours, and a new case covers the drive-letter output.
- **CI: the ripgrep install retries and fails loudly** (`.github/workflows/test.yml`): Chocolatey answered 503, installed 0 of 0 packages and the step still passed, leaving the Windows job without `rg`. The step now retries up to three times and ends with `rg --version`, so a missing binary fails at its cause.
