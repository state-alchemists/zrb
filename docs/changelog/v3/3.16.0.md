## 3.16.0 (October 10, 2026)

- **Feature: `zrb remote run` and `zrb remote check`** (`src/zrb/remote/`, `src/zrb/builtin/remote.py`, `src/zrb/util/cmd/remote.py`, `docs/adr/adr-0110.md`): `Host` (`CmdTask`'s `remote_*` plus `labels`; no `remote_host` means localhost) and `Target` (host, port, `tcp`/`http`, url, `labels`) are registered in `zrb_init.py` with `host_inventory.add(...)` / `target_inventory.add(...)`. `run` executes a command on every host matching `--host-labels` and `check` probes every selected target from every selected host over one SSH session per host (no Python needed on the host). Both print a rendered table or, with `--format markdown`, raw markdown. `get_remote_cmd_script` no longer emits `@host` when `remote_user` is empty.
- **Fix: `SearchJournal` no longer parses `path:line:content`** (`src/zrb/llm/tool/journal.py`, `test/llm/tool/test_journal.py`): the parser split ripgrep's output on colons, so `C:\notes\2024-01-02.md:7:text` became the file `C`, and a Unix file `note:12:archive.md` was read as `note`, line 12. ripgrep now runs with `--json` and the `os.walk` fallback hands over tuples, so no delimiter is parsed at all.
- **Tests: the ripgrep journal test no longer needs the `rg` binary** (`test/llm/tool/test_journal.py`): `test_find_matches_with_ripgrep` faked `shutil.which` but still ran the real `rg`, so it failed on the Windows runner whenever the package install was missing (`[WinError 2]`). It now mocks `subprocess.run` with ripgrep's output, like its neighbours, and new cases cover a drive-letter path and a `note:12:archive.md` filename.
- **CI: the ripgrep install retries and fails loudly** (`.github/workflows/test.yml`): Chocolatey answered 503, installed 0 of 0 packages and the step still passed, leaving the Windows job without `rg`. The step now retries up to three times and ends with `rg --version`, so a missing binary fails at its cause.
- **Feature: a long reply can be spoken as a summary** (`src/zrb/llm/speech/summary.py`, `src/zrb/llm/speech/feature.py`, `src/zrb/llm/speech/config.py`, `src/zrb/config/mixins/llm_speech.py`, `src/zrb/llm/prompt/markdown/speech_summarizer.md`, `src/zrb/config/retired.py`, `docs/advanced-topics/upgrading-guide.md`, ADR-0103, `test/llm/speech/test_summary.py`, `test/llm/speech/test_feature_summary.py`): speech read every reply whole, however long. `ZRB_LLM_SPEECH_SUMMARIZE_ABOVE_CHARS` (`SpeechConfig.summarize_above_chars`, default `0`: off) now has the small model (`ZRB_LLM_SPEECH_SUMMARY_MODEL`, else `ZRB_LLM_SMALL_MODEL`) summarize a reply whose speakable text is longer than that, and the summary is spoken instead; the reply on screen is unchanged. A summary needs the finished reply, so while the knob is set the reply is not streamed, whatever `ZRB_LLM_SPEECH_STREAM` says. A model that fails, returns nothing or a longer text, or takes longer than `ZRB_LLM_SPEECH_SUMMARY_TIMEOUT` (15 seconds) leaves the reply read whole. The summarizer's prompt is `speech_summarizer`, overridable like any internal prompt. The summary is made on a worker thread (`SpeechSummarizer`), so neither the turn nor the speaker's queue waits for it. The reply is heard exactly once: the summary, or the reply whole when the model fails, returns nothing shorter, or is not done within `ZRB_LLM_SPEECH_SUMMARY_TIMEOUT`. A timer outside the worker keeps that deadline, so a model call that cannot be cancelled still ends in the reply being read, and its late result is dropped. A summary is also dropped if speech is interrupted or switched off, the session closes, or a newer reply comes first; every turn's `Stop`, even one with no reply, invalidates a summary still being made. A session runs one worker at a time and reads later long replies whole while one is alive, so a stuck model call costs one thread per session until it returns or the process exits.
- **Feature: the main agent and a delegated sub-agent can message each other** (`src/zrb/llm/tool/delegate_message.py`, `src/zrb/llm/agent/subagent/live_session.py`, `src/zrb/llm/agent/subagent/building.py`, `src/zrb/builtin/llm/chat.py`, `src/zrb/config/mixins/llm_content.py`, `docs/adr/adr-0108.md`). `send_message_to_subagent` (main agent) and `send_message_to_parent` (sub-agent) deliver through the live-session registry and name their sender; `ZRB_LLM_AGENT_MESSAGE_LIMIT` (default 20) bounds agent-to-agent exchanges per delegation.
- **Feature: a conversation with a generated name is renamed from its first message** (`src/zrb/llm/util/conversation_naming.py`, `src/zrb/llm/ui/base/conversation_commands.py`, `src/zrb/llm/history_manager/file_history_manager.py`, `src/zrb/llm/prompt/markdown/conversation_namer.md`, `docs/adr/adr-0109.md`). `trim-coil-1234` becomes `trim-coil-1234-greetings`; sub-agent transcripts and live sessions keep the generated name as their key, so the rename moves one file. Each delegated sub-agent gets a topic title in the picker. `ZRB_LLM_AUTO_NAME_ENABLED` (default on) switches it off; `ZRB_LLM_AUTO_NAME_MODEL` picks the model. `ZRB_LLM_HISTORY_RETENTION` still prunes it, because the generated name stays as its prefix.
- **Feature: `/load` restores a conversation's sub-agent sessions** (`src/zrb/llm/ui/base/conversation_commands.py`, `src/zrb/llm/agent/subagent/live_session.py`). Saved sub-agent transcripts come back as idle sessions you can message; they run under the permissions in force when they continue.
