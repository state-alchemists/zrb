## 3.16.0 (October 10, 2026)

- **Fix: `zrb remote` runs without a pseudo-terminal, caps output, keeps stderr apart; IPv6 hosts work** (`src/zrb/util/cmd/remote.py`, `src/zrb/task/rsync_task.py`, `src/zrb/remote/`): `get_remote_cmd_script` takes `tty=False` (`-T`), which `zrb remote` uses so servers with `PermitTTY no` accept its commands (`CmdTask` keeps `-t`). Each host's output is capped at the trailing 1000 lines per stream, as `CmdTask` does, and a failed run keeps stdout and stderr on separate lines. `zrb remote check` and every remote host run their script under `sh` whatever `Host.shell` says, since the probe and the `ssh` command line are POSIX; `Host.shell` now applies only to a local `remote run` command. A new `bracket_ipv6` wraps an IPv6 literal for URLs, so an http `Target` on `2001:db8::1` is checked at `https://[2001:db8::1]:443/`; `RsyncTask` uses it too, since `user@2001:db8::1:path` is not a valid rsync path.
- **Feature: `zrb remote run` and `zrb remote check`** (`src/zrb/remote/`, `src/zrb/builtin/remote.py`, `src/zrb/util/cmd/remote.py`, `docs/adr/adr-0110.md`): `Host` (`CmdTask`'s `remote_*` plus `labels`; no `remote_host` means localhost) and `Target` (host, port, `tcp`/`http`, url, `labels`) are registered in `zrb_init.py` with `host_inventory.add(...)` / `target_inventory.add(...)`. `run` executes a command on every host matching `--host-labels` and `check` probes every selected target from every selected host over one SSH session per host (no Python needed on the host). Both print a rendered table, raw markdown (`--format markdown`) or JSON (`--format json`). `get_remote_cmd_script` no longer emits `@host` when `remote_user` is empty.
- **Tests: the suite runs warning-free** (`test/conftest.py`, `pyproject.toml`, `test/llm/util/test_conversation_naming.py`, `test/llm/ui/base/test_base_ui_conversation_naming.py`, `test/llm/agent/subagent/test_live_session_naming.py`): the delegate tests started the sub-agent title task, a real small-model agent run that outlived the test and left `coroutine 'AbstractCapability.for_run' was never awaited`. Auto-naming is now off for every test, like the journal judge, and its own tests turn it on. Two third-party deprecations zrb cannot change (pipecat's `AudioContextTTSService`, starlette's `anyio.abc.BlockingPortal`) are filtered in `pyproject.toml`. The barge-in tests (`test/llm/dictation/test_feature_barge_in.py`) no longer call a real model: the interrupt judge is off in their sessions, where it made real HTTPS requests to OpenAI with a fake key and leaked the sockets. The `Shell` tool now closes its subprocess transport when a command times out (`src/zrb/llm/tool/shell.py`, `close_transport` in `src/zrb/util/cmd/command.py`): the timeout cancelled the drain before it closed the pipes, so they stayed open until GC and warned `unclosed transport` / `Event loop is closed` on whichever later test collected them.
- **Fix: `SearchJournal` no longer parses `path:line:content`** (`src/zrb/llm/tool/journal.py`, `test/llm/tool/test_journal.py`): the parser split ripgrep's output on colons, so `C:\notes\2024-01-02.md:7:text` became the file `C`, and a Unix file `note:12:archive.md` was read as `note`, line 12. ripgrep now runs with `--json` and the `os.walk` fallback hands over tuples, so no delimiter is parsed at all.
- **Tests: the ripgrep journal test no longer needs the `rg` binary** (`test/llm/tool/test_journal.py`): `test_find_matches_with_ripgrep` faked `shutil.which` but still ran the real `rg`, so it failed on the Windows runner whenever the package install was missing (`[WinError 2]`). It now mocks `subprocess.run` with ripgrep's output, like its neighbours, and new cases cover a drive-letter path and a `note:12:archive.md` filename.
- **CI: the ripgrep install retries and fails loudly** (`.github/workflows/test.yml`): Chocolatey answered 503, installed 0 of 0 packages and the step still passed, leaving the Windows job without `rg`. The step now retries up to three times and ends with `rg --version`, so a missing binary fails at its cause.
- **Feature: a long reply can be spoken as a summary** (`src/zrb/llm/speech/summary.py`, `src/zrb/llm/speech/feature.py`, `src/zrb/llm/speech/config.py`, `src/zrb/config/mixins/llm_speech.py`, `src/zrb/llm/prompt/markdown/speech_summarizer.md`, `src/zrb/config/retired.py`, `docs/advanced-topics/upgrading-guide.md`, ADR-0103, `test/llm/speech/test_summary.py`, `test/llm/speech/test_feature_summary.py`): speech read every reply whole, however long. `ZRB_LLM_SPEECH_SUMMARIZE_ABOVE_CHARS` (`SpeechConfig.summarize_above_chars`, default `0`: off) now has the small model (`ZRB_LLM_SPEECH_SUMMARY_MODEL`, else `ZRB_LLM_SMALL_MODEL`) summarize a reply whose speakable text is longer than that, and the summary is spoken instead; the reply on screen is unchanged. A summary needs the finished reply, so while the knob is set the reply is not streamed, whatever `ZRB_LLM_SPEECH_STREAM` says. A model that fails, returns nothing or a longer text, or takes longer than `ZRB_LLM_SPEECH_SUMMARY_TIMEOUT` (15 seconds) leaves the reply read whole. The summarizer's prompt is `speech_summarizer`, overridable like any internal prompt. The summary is made on a worker thread (`SpeechSummarizer`), so neither the turn nor the speaker's queue waits for it. The reply is heard exactly once: the summary, or the reply whole when the model fails, returns nothing shorter, or is not done within `ZRB_LLM_SPEECH_SUMMARY_TIMEOUT`. A timer outside the worker keeps that deadline, so a model call that cannot be cancelled still ends in the reply being read, and its late result is dropped. A summary is also dropped if speech is interrupted or switched off, the session closes, or a newer reply comes first; every turn's `Stop`, even one with no reply, invalidates a summary still being made. A session runs one worker at a time and reads later long replies whole while one is alive, so a stuck model call costs one thread per session until it returns or the process exits.
- **Feature: the main agent and a delegated sub-agent can message each other** (`src/zrb/llm/tool/delegate_message.py`, `src/zrb/llm/agent/subagent/live_session.py`, `src/zrb/llm/agent/subagent/building.py`, `src/zrb/builtin/llm/chat.py`, `src/zrb/config/mixins/llm_content.py`, `docs/adr/adr-0108.md`). `send_message_to_subagent` (main agent) and `send_message_to_parent` (sub-agent) deliver through the live-session registry and name their sender; `ZRB_LLM_AGENT_MESSAGE_LIMIT` (default 20) bounds agent-to-agent exchanges per delegation.
- **Feature: a conversation with a generated name is renamed from its first message** (`src/zrb/llm/util/conversation_naming.py`, `src/zrb/llm/ui/base/conversation_commands.py`, `src/zrb/llm/history_manager/file_history_manager.py`, `src/zrb/llm/prompt/markdown/conversation_namer.md`, `docs/adr/adr-0109.md`). `trim-coil-1234` becomes `trim-coil-1234-greetings`; sub-agent transcripts and live sessions keep the generated name as their key, so the rename moves one file. Each delegated sub-agent gets a topic title in the picker. `ZRB_LLM_AUTO_NAME_ENABLED` (default on) switches it off; `ZRB_LLM_AUTO_NAME_MODEL` picks the model. `ZRB_LLM_HISTORY_RETENTION` still prunes it, because the generated name stays as its prefix.
- **Feature: `/load` restores a conversation's sub-agent sessions** (`src/zrb/llm/ui/base/conversation_commands.py`, `src/zrb/llm/agent/subagent/live_session.py`). Saved sub-agent transcripts come back as idle sessions you can message; they run under the permissions in force when they continue.
- **Fix: user-facing messages name settings by the configured env prefix, not `ZRB_`** (`src/zrb/__init__.py`, `src/zrb/llm/dictation/listen.py`, `src/zrb/llm/speech/feature.py`, `src/zrb/llm/speech/backend/audio.py`, `src/zrb/llm/voice/builtin.py`, `src/zrb/llm/voice/manager.py`): nine messages and service descriptions hardcoded `ZRB_…`, so a white-labeled build pointed users at variables it does not read. They now use `CFG.ENV_PREFIX`, as the other runtime messages already did.
- **Refactor: one model-hook validator, one UUID-report helper, typing ABCs from `collections.abc`** (`src/zrb/llm/config/model_resolver.py`, `src/zrb/llm/task/llm_task.py`, `src/zrb/llm/task/chat/task.py`, `src/zrb/builtin/uuid.py`, `src/zrb/llm/ui/base/usage.py`): the `model_getter`/`model_renderer` callable check existed in six copies and is now `require_model_hook`; the five UUID validate tasks share one report helper; `BaseUIUsage.__init__` calls `reset()`. `Callable`, `Iterable` and the other ABC aliases (deprecated in `typing` since Python 3.9) are imported from `collections.abc` in 78 more files; two keep `typing.Callable` because pyflakes reads string forward references only inside it.
- **Documentation: changelog bullets carry user-facing changes, not mechanism** (`docs/contributing/maintainer-guide.md`, `docs/changelog/README.md`, `docs/changelog/v3/3.8.0-3.8.3.md`): bullet medians grew from 5–7 words (2.0–2.32) to 50–186 (2.50 onward). The entry rule now sends mechanism to the cited ADR or doc; the 750-word `/rewind` entry became 239 words with every dropped detail already in ADR-0101; index ranges use one spelling.
- **Refactor (breaking for deep imports): packages no longer import each other at runtime** (`test/architecture/test_circular_import_allowlist.py`, `docs/adr/adr-0088.md`, `AGENTS.md`): package pairs importing each other at runtime fell from 21 to 1, and the new `test_packages_do_not_import_each_other` keeps it there; the remaining `zrb.context`/`zrb.util` pair is allowlisted with its reason. Annotation-only imports moved under `TYPE_CHECKING`; misplaced modules moved to the package that owns them. Top-level `zrb` exports are unchanged; a deep import of a moved module needs the new path listed in [Upgrading to 3.16.0 → Moved modules](../../advanced-topics/upgrading-guide.md#moved-modules).
- **Refactor: the agent, tool and task layers name no concrete UI class** (`src/zrb/llm/ui/multi_ui.py`): `resolve_ui` (combine the given UIs, else the stdout UI) and `get_main_ui` replace six `StdUI()`/`MultiUI` constructions and checks in `agent/run/setup.py`, the delegate tools and `task/chat/execution.py`.
- **Documentation: the 9,761-word LLM configuration page is an index of seven feature pages** (`docs/configuration/llm-config.md`, `llm-models.md`, `llm-prompts.md`, `llm-context.md`, `llm-tools.md`, `llm-tui.md`, `llm-limits.md`, `llm-voice-camera.md`): every section moved unchanged, and the 32 inbound links in 13 files point at the new pages.
- **Documentation: changelog bullets from 2.50 to 3.15 carry user-facing changes, with mechanism left to the ADRs and docs they cite** (`docs/changelog/v2/`, `docs/changelog/v3/`): the changelog fell from 98,958 to about 80,800 words. A detail was dropped only where an ADR or doc records it; benchmark numbers, retired settings and APIs no current doc describes stayed.
