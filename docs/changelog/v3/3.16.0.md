## 3.16.0 (October 10, 2026)

- **Feature: a long reply can be spoken as a summary** (`src/zrb/llm/speech/summary.py`, `src/zrb/llm/speech/feature.py`, `src/zrb/llm/speech/config.py`, `src/zrb/config/mixins/llm_speech.py`, `src/zrb/llm/prompt/markdown/speech_summarizer.md`, `src/zrb/config/retired.py`, ADR-0103, `test/llm/speech/test_summary.py`, `test/llm/speech/test_feature_summary.py`): speech read every reply whole, however long. `ZRB_LLM_SPEECH_SUMMARIZE_ABOVE_CHARS` (`SpeechConfig.summarize_above_chars`, default `0`: off) now has the small model (`ZRB_LLM_SPEECH_SUMMARY_MODEL`, else `ZRB_LLM_SMALL_MODEL`) summarize a reply whose speakable text is longer than that, and the summary is spoken instead; the reply on screen is unchanged. A summary needs the finished reply, so while the knob is set the reply is not streamed, whatever `ZRB_LLM_SPEECH_STREAM` says. A model that fails, returns nothing or a longer text, or takes longer than `ZRB_LLM_SPEECH_SUMMARY_TIMEOUT` (15 seconds) leaves the reply read whole. The summarizer's prompt is `speech_summarizer`, overridable like any internal prompt. The summary is made on a thread of its own, so neither the turn nor the speaker's queue waits for it, and it is dropped if speech is interrupted meanwhile. This brings back the opt-in summary that 3.14.0 removed; `ZRB_LLM_SPEECH_SUMMARY_MODEL` is a setting again, and `ZRB_LLM_SPEECH_SUMMARIZE` now names `ZRB_LLM_SPEECH_SUMMARIZE_ABOVE_CHARS` when it is found set.
