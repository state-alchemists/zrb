## 3.3.0 (September 13, 2026)

- **Chore: the coverage gate is 94%** (`zrb-test.sh`, `AGENTS.md`, `docs/adr/{adr-0034,README}.md`, `docs/contributing/maintainer-guide.md`, `docs/advanced-topics/testing-tasks.md`): the full run has measured above 94% for some time, so `--cov-fail-under` now sits at the number the suite actually holds rather than four points below it, where a real regression could hide. Every place that stated the old bar — ADR-0034's title and Decision, its index entry, the maintainer guide's gate table, the testing guide's prose, and AGENTS.md's test principles — names 94 now. Scoped runs (`./zrb-test.sh <path>`) still skip the gate entirely, since they exercise only part of the tree.

- **Refactor: the agent barrel resolves lazily, and import safety is asserted per module** (`src/zrb/llm/agent/__init__.py`, `test/architecture/test_circular_import_allowlist.py`, `.coveragerc`, `AGENTS.md`, `docs/llm/llm-chat-lifecycle.md`, `docs/adr/{adr-0086,adr-0088,adr-0096}.md`): a package `__init__` runs before any of its submodules, so `zrb/llm/agent/__init__.py`'s four eager re-exports meant `common.py`, `run/runner.py` and `summarizer.py` — and through them most of `zrb.llm` — loaded whenever *anything* under `zrb.llm.agent` was imported. Measured over the module graph (`if TYPE_CHECKING:` excluded), that made the tree's largest strongly connected component 87 modules spanning `llm.tool`, `llm.ui`, `llm.agent`, `llm.task`, `runner.chat` and `runner.cli` — every one able to reach every other. Deferring each package barrel in turn showed it was almost entirely this one file: `zrb.llm.agent` lazy takes the number to 23, `zrb.llm.ui` to 82, `zrb.llm.tool` to 87 (no change at all — which is why restoring it to eager in 2.67.0 was right). The blocker was the safety net, not the barrel: `test_every_package_imports_with_its_parents_stubbed` imported 27 packages and nothing deeper, so the tree's 419 other modules were reachable by it only through whatever their barrel re-exported, and any barrel made lazy silently shrank the check. That check now parametrizes over modules — 417 targets, every `*.py` whose path parts are identifier-legal, which excludes exactly the hyphenated skill tool scripts under `llm_plugin/*_skills/<skill>/tools/` — so it asserts directly what it used to assert by proxy. The agent barrel then resolves through PEP 562 `__getattr__`, caching into `globals()`, with the names mirrored under `if TYPE_CHECKING:` for pyright; `hook_agent`'s builder registration moved into that same `__getattr__`, firing on first use of an agent name instead of on package load — still earlier than any hook-manager read, since every entry point resolves one of the four while building its agent. Import spellings are unchanged everywhere: `from zrb.llm.agent import create_agent` is an attribute access, which is what `__getattr__` answers, and all 14 call sites are untouched. Net: largest SCC 87 → 23, modules in any cycle 102 → 23, `zrb.llm.agent`'s eager closure 338 of 447 modules → 1, isolated-import coverage 27 packages → 417 modules (+392 tests, 5,774 → 6,166). `import zrb` is unchanged at 0.22s — the win is structural, not latency. `.coveragerc`'s skill-tool-script omit named only `skills/` and now also names `core_skills/`; the per-module check surfaced the gap. See ADR-0096.

- **Feature: a chat trigger can attach files and photos, not just text** (`src/zrb/llm/ui/trigger.py`, `src/zrb/llm/ui/base/triggers.py`, `src/zrb/llm/ui/{__init__,base/ui}.py`, `src/zrb/{__init__.py,llm/task/chat/task.py}`, `examples/chat-gpio-ptt/`, `examples/README.md`, `test/llm/ui/base/test_base_ui.py`, `test/architecture/test_facade_size_budget.py`): `LLMChatTask(triggers=[...])` lets an external source — a GPIO button, a webhook, a message queue — drive a chat session by yielding items that become user turns, but `trigger_loop` submitted every item as `str(result)`, so text was all a trigger could ever send. A trigger that wanted the agent to *look* at something had no way to say so; the only workaround was reaching a UI reference through `ui_factory` to stage `pending_attachments` by hand. An item may now also be a `TriggerMessage(text, attachments)` — a `NamedTuple`, so a bare `(text, attachments)` tuple works without importing anything — whose attachments are staged on the UI and drained by the same `submit_user_message` path `/attach` and `/photo` use. That means the attachments accept whatever those commands accept: a file path, resolved and size-checked and PDF-extracted and image-scaled at submit time, or an already-built `BinaryContent`. Attachments without text are valid (`TriggerMessage(attachments=[photo])` submits an empty turn carrying the image), and an item with neither text nor attachments is skipped, so a voice trigger can yield its transcription unguarded and silence costs nothing. Plain strings behave exactly as before. Running the loops moved out of `BaseUI` into a `BaseUITriggers` part, re-exposed as the same `trigger_loop` method, which drops `ui.py` from 1330 lines to 1307 and tightens its facade budget to match. The new `examples/chat-gpio-ptt/` drives the built-in chat task from two Raspberry Pi buttons — one push-to-talk, one that attaches a camera frame to the turn it was held for — and is the worked version of all of the above.
