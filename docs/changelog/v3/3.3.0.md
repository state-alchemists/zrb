## 3.3.0 (September 13, 2026)

- **Fix: upload storage names, Windows write safety, trigger teardown, and two wrong install commands** (`src/zrb/runner/chat/chat_api_route.py`, `src/zrb/llm/ui/base/triggers.py`, `examples/chat-gpio-ptt/{README.md,zrb_init.py}`, `examples/chat-telegram/README.md`, `test/architecture/test_posix_mode_assertions.py`): on Windows the upload write now creates its file exclusively (`O_EXCL`) instead of following or truncating a planted entry. A stored upload no longer carries the client's filename: only a length-capped, character-checked extension survives, and the original is returned as a display name. Expected upload failures map to 400 (`ValueError`) or 507 (`OSError` such as ENOSPC) instead of 500. `trigger_loop` closes the async iterator it drives in a `finally` and re-raises `CancelledError`; its attachment rollback removes its own staged items by identity, not a tail slice of the list every trigger shares. Both examples said `pip install zrb[llm]`, an extra that does not exist: GPIO needs `zrb[voice]`, Telegram no extra. A new architecture test requires a test asserting POSIX permission bits to carry a platform guard.
- **Fix: four input-handling defects on the chat API and the trigger loop** (`src/zrb/runner/chat/chat_api_route.py`, `src/zrb/llm/ui/{trigger.py,base/triggers.py}`, `test/runner/chat/{conftest,test_chat_api,test_chat_api_uploads}.py`): (1) the attachment route read a whole upload before checking `LLM_MAX_ATTACHMENT_BYTES`; it now reads one byte past the cap and refuses on overflow. (2) `save_uploaded_attachment` validated the upload directory by path and then opened by path; on POSIX the write is now relative to a descriptor on the validated directory with `O_NOFOLLOW`/`O_EXCL`, closing the symlink-swap window. (3) A non-string `message` (`null`, `123`) in `post_chat_message` returns 400 instead of 500. (4) A trigger tuple must be exactly `(text, attachments)` with a non-string attachment sequence (`None` reads as none); a 3-tuple, a bare string or an int was mangled or ended the trigger for good, and a malformed item is now reported alone while the loop carries on.
- **Fix: a chat session id from the request path could place uploads outside the upload root** (`src/zrb/runner/chat/chat_api_route.py`, `test/runner/chat/test_chat_api_uploads.py`): `POST /api/v1/chat/sessions/{session_id}/attachments` joined `session_id` into the upload path unvalidated, so `..` wrote into the shared temp directory and reset its mode to 0700, locking every other local user out. The id now goes through `to_safe_filename` (alphanumerics, `-`, `_`), an empty result is rejected, and the joined path must sit directly under the root.
- **Fix: the GPIO example reused one photo path, and web-chat uploads trusted a fixed temp directory** (`examples/chat-gpio-ptt/{zrb_init.py,README.md}`, `src/zrb/runner/chat/chat_api_route.py`): `capture_photo` wrote every frame to one `zrb-gpio-photo.jpg` in shared temp. An attachment path is read when the turn reaches the model, not at submit, so a second press while the first turn was queued swapped its photo, and a local user could pre-create the name as a symlink. Each capture now gets its own `tempfile.mkstemp` file (mode 0600); a path is kept over `BinaryContent`, which skips the size check and image scaling. The example docs, which said resolution happened at submit time, are corrected. Web-chat uploads had the same pattern (`<tmp>/zrb_web_chat_uploads/<session>`): each level is now created 0700, and a root that is not a real directory owned by the current user is refused.
- **Fix: a failed trigger submission no longer leaves its attachments staged for the next turn** (`src/zrb/llm/ui/base/triggers.py`, `test/llm/ui/base/test_base_ui.py`): `submit_user_message` drained `pending_attachments` only after echoing the message, so when the echo raised (under `MultiUI`, a failing Telegram send or SSE write) a failed GPIO trigger's camera frame could arrive on a message typed minutes later. `trigger_loop` now truncates the list back to its pre-trigger length on failure.
- **Refactor: four `BaseUI` state parts are public attributes instead of 22 forwarders** (`src/zrb/llm/ui/base/{ui,voice_state,confirmation_state,persona_state,usage}.py`, `src/zrb/llm/ui/default/{output,keybindings,lifecycle,agent_picker}.py`, `AGENTS.md`, `test/architecture/test_facade_size_budget.py`): the voice, confirmation, persona and usage parts are now `ui.voice`, `ui.confirmation`, `ui.persona` and `ui.usage` (`ui.voice.mode_active`, `ui.confirmation.current`) instead of forwarding properties such as `ui.voice_mode_active`; 60 of `BaseUI`'s 102 public names had no caller outside `llm/ui`. `BaseUI.accumulate_usage` stays, as a documented enrichment hook. The `getattr` shims for non-`BaseUI` UIs now reach the part, so `StdUI` and `MultiUI` are unaffected, and `AnyUI` is unchanged at 16 methods. `ui.py` drops 1307 → 1206 lines and 102 → 89 public names; repo-wide pure delegators fall 636 → 621.
- **Chore: the coverage gate is 94%** (`zrb-test.sh`, `AGENTS.md`, `docs/adr/{adr-0034,README}.md`, `docs/contributing/maintainer-guide.md`, `docs/advanced-topics/testing-tasks.md`): the full run has measured above 94% for some time, so `--cov-fail-under` now sits at that number rather than four points below, where a real regression could hide. Every statement of the old bar (ADR-0034's title and Decision, its index entry, the maintainer guide's gate table, the testing guide, AGENTS.md) now says 94. Scoped runs (`./zrb-test.sh <path>`) still skip the gate.
- **Refactor: the agent barrel resolves lazily, and import safety is asserted per module** (`src/zrb/llm/agent/__init__.py`, `test/architecture/test_circular_import_allowlist.py`, `.coveragerc`, `AGENTS.md`, `docs/llm/llm-chat-lifecycle.md`, `docs/adr/{adr-0086,adr-0088,adr-0096}.md`): the eager re-exports in `zrb/llm/agent/__init__.py` loaded most of `zrb.llm` on any import under `zrb.llm.agent`; the barrel now resolves names on first use, which is also when `hook_agent`'s builder registers (see ADR-0096). The isolated-import test, which covered only 27 packages and so would have silently shrunk, now covers 444 targets (417 modules plus 27 packages). Import spellings are unchanged. Net: largest import cycle 87 → 23 modules, modules in any cycle 102 → 23, `zrb.llm.agent`'s eager closure 338 of 447 modules → 1, tests 5,774 → 6,166; `import zrb` stays at 0.22s. `.coveragerc`'s skill-tool-script omit now covers `core_skills/` as well as `skills/`.
- **Feature: a chat trigger can attach files and photos, not just text** (`src/zrb/llm/ui/trigger.py`, `src/zrb/llm/ui/base/triggers.py`, `src/zrb/__init__.py`, `src/zrb/llm/task/chat/task.py`, `examples/chat-gpio-ptt/`, `docs/task-types/llmchat-task.md`): an item yielded by an `LLMChatTask(triggers=[...])` source may now be a `TriggerMessage(text, attachments)` or a bare `(text, attachments)` tuple. Attachments take what `/attach` takes: a file path (resolved, size-checked, PDF-extracted and image-scaled at submit time) or a `BinaryContent`. Attachments without text are valid; an item with neither is skipped. Plain strings behave as before. Trigger handling moved into a `BaseUITriggers` part (`ui.py` 1330 → 1307 lines). The new `examples/chat-gpio-ptt/` drives the chat task from two Raspberry Pi buttons: one push-to-talk, one attaching a camera frame to the turn.
