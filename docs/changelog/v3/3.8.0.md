## 3.8.0 (September 26, 2026)

- **Feature: an opt-in self-review gate reviews each file-changing turn before it ends** (`src/zrb/llm/hook/self_review.py`, `src/zrb/llm/prompt/markdown/self_review.md`, `src/zrb/llm/agent/run/turn_snapshot.py`, `src/zrb/llm/hook/turn_evidence.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/agent/run/turn_cursor.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/config/mixins/llm_content.py`, `docs/adr/adr-0100.md`, `docs/llm/hooks.md`, `docs/configuration/llm-config.md`): PR #534 needed three review rounds, each a CI finding the user pasted back into the chat. With `ZRB_LLM_SELF_REVIEW_ENABLED=on`, a synchronous Stop hook runs that review inside the turn. The runner snapshots the working directory at turn start and the gate diffs it against a second snapshot at Stop, so the review covers exactly what the turn changed — `Shell` edits and mid-turn commits included, the user's earlier uncommitted work excluded — in every repository under the directory: nested clones, submodules, a folder of repositories, and repositories the parent ignores (such as `EnterWorktree`'s worktrees). A repository that appears mid-turn (a new worktree, a clone) is diffed against the commit it started from. Snapshots go to a private, owner-only temporary store deleted when the turn ends, so untracked files such as a `.env` never reach any `.git/objects`. The gate only reads that store and diffs in one of its own, so a cancelled turn deleting it mid-review cannot break the review; a directory too large to snapshot within git's 30-second cap is not retried for the rest of the process. A fresh-context reviewer agent gets that diff — not the author's transcript — and read-only `Read`/`Grep`/`Glob`. It is also given, to read, paths the file tools named that the diff does not cover, and files the turn left unreadable (not shown as deleted; a turn whose only change is one is still reviewed). Without a snapshot it gets those paths alone — never `git diff HEAD`, which would include the user's earlier uncommitted work. A closing `Request changes` blocks the Stop, so the agent checks each finding against the code, fixes the real ones, and restates its answer; `LGTM`, an unclear verdict, or a failed review never blocks. `ZRB_LLM_SELF_REVIEW_MAX_ROUNDS` (default 2) caps consecutive blocking reviews per turn, so concurrent sessions never reset each other's count; `ZRB_LLM_SELF_REVIEW_MODEL` picks a separate reviewer model; `ZRB_LLM_SELF_REVIEW_TIMEOUT` (default 240s) bounds each whole review — git commands are killed at the deadline, and the reviewer is cancelled inside the hook's own event loop so its model request actually stops. A delegated sub-agent's run is not reviewed on its own; the parent's diff covers it. The Stop payload gains `turn_start_snapshot`, `changed_paths`, `run_scope`, `turn_id` and `nested_run` for any hook that needs the turn's scope.
- **Improvement: `/rewind` snapshots are git trees in a private store, on by default, and cover nested repositories** (`src/zrb/util/git/snapshot_listing.py`, `src/zrb/util/git/snapshot_store.py`, `src/zrb/util/git/snapshot_command.py`, `src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/default/lifecycle.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/base/conversation_commands.py`, `src/zrb/config/mixins/llm_content.py`, `docs/adr/adr-0101.md`, `docs/configuration/llm-config.md`, `docs/llm/llm-custom-ui.md`): each snapshot used to copy the whole project into a per-session shadow folder and commit it there — every file stored twice per session, 994 MB across 11 sessions here — and the TUI waited for the first copy before drawing. A snapshot is now a tree in a private bare repository whose work tree is the working directory: one store per directory under `ZRB_LLM_SNAPSHOT_DIR`, one ref per conversation. Zrb lists the files — each git repository under the directory by its own `.gitignore`, recursively, including nested ones, submodules and ones the parent ignores — and `git update-index` hashes them, keeping git's stat cache. On this repository the first snapshot takes 0.58 s and 9 MB instead of 1.2 s and 85 MB, a later one 0.02 s, and it runs in the background. **Default change:** `ZRB_LLM_ENABLE_REWIND` is now `on`. Outside every repository a directory may hold at most 5,000 files or 200 MB; past that (a chat started in `~`, say) rewind turns itself off for the session and says why. **Behaviour change:** gitignored files (a `.env`, build output) are no longer snapshotted or restored, and a `.gitignore` outside any repository has no effect, as in git. Old shadow folders in `ZRB_LLM_SNAPSHOT_DIR` are not migrated and can be deleted. Restore rewrites, recreates and removes files, nested repositories' included, but never a path ignored since the snapshot and never a repository's `HEAD`, and accepts only the session's own snapshots. It is byte-exact whatever `.gitattributes` say (git-lfs included). It removes a file only when the snapshot shows it did not exist: each commit records what its snapshot left out — every ignored path, whichever rule ignored it (`.gitignore`, `info/exclude`, global excludes), every unreadable directory, every file git could not read — plus the repositories it listed, and a restore reads that record rather than reconstructing the past. It leaves a worktree or clone made since as it is rather than hollowing it out. It never writes over a file it cannot read now, nor over anything unlisted in the way of what it writes (a directory holding an ignored file where the snapshot has a file, a FIFO) that `read-tree --reset` would remove — it reports that path instead. On macOS and Windows a case-only rename is restored rather than deleted. A write the filesystem refuses (a locked file, a read-only folder) no longer fails the whole rewind: the rest is restored, the chat rewinds, and `/rewind` names what was left behind via the `RestoreOutcome` that `restore_snapshot` returns; a restore that stops partway (a git command timing out mid-write) reports every file it meant to change the same way. A file git cannot read is skipped rather than failing the snapshot — detected by opening it, not by parsing git's message, which is translated and reworded across versions. A FIFO or socket is never opened, so it cannot hang a snapshot; a Windows junction is not followed. The store is owner-only (`0700`), and a store inside the directory is excluded from its own snapshots. Each snapshot or restore uses its own index file, so a git command killed at its timeout leaves no lock that breaks later snapshots and never takes another process's lock with it. A snapshot label can no longer pass for commit metadata: the message count ends the subject and the record sits in the body; a commit without a readable record is not restored. A file that becomes unreadable leaves the next snapshot instead of keeping stale content. A working directory its repository ignores (a scratch folder) is snapshotted instead of listed as empty. Rewind history belongs to the conversation — `/load` switches to the loaded conversation's snapshots, and `/save` copies them to the new name with the chat, before the next snapshot can be taken so that snapshot builds on it. A `ZRB_LLM_SNAPSHOT_DIR` equal to the working directory, a store that cannot be set up (directory not writable, git not installed), or a directory too large to snapshot within git's 30-second cap turns rewind off for the session with that reason instead of failing every turn, and `/rewind` says why. Snapshots and restores of one directory take turns under an OS lock on a file in its store (`src/zrb/util/file_lock.py`) — across sessions and processes, released if its holder dies, waited for at most 60 seconds, and never taken by `/rewind`'s listing, which runs on the UI's thread — so two rewinds never interleave writes and no snapshot catches a half-written restore.
- **Breaking: `SnapshotProgress` drops its `copied` field, and `restore_snapshot` returns a `RestoreOutcome`** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/default/lifecycle.py`): `copied` counted files copied into the shadow folder, which no longer exists, so it has no successor; a progress handler that unpacks the event by position (`stage, copied, skipped, reason = event`) fails, while one reading `event.stage`, `event.skipped` and `event.reason` keeps working. `restore_snapshot` returned a bool and now returns `RestoreOutcome(restored, left_behind)`, naming the files a refused write left behind; it is truthy exactly when the restore ran, so `if await manager.restore_snapshot(sha):` reads as before.

- **Improvement: the prompt ranks truth above speed and resolves the ask-versus-proceed conflict** (`src/zrb/llm/prompt/markdown/{principle,workflow,profile.standard,profile.capable}.md`): `principle` states one priority order — protect the user's work, then truth, then completeness, then speed — and adds two rules: a claim about something not seen (a prior version, a diff not in hand) is inference to label or omit, and a diagnosis must re-read what it blames. - **Fix: the project-documentation listing no longer points at a section that does not exist** (`src/zrb/llm/prompt/claude.py`, `test/llm/prompt/test_claude.py`, `docs/adr/adr-0047.md`): **Documentation Files Found** said "See Project Documentation for when to read these", and **User-Level Guidance** said "not part of the mandatory read" — both referring to a prompt section removed in August. The journal writers' docstrings also shed prose the model never needed — `DeleteJournalNote`'s defence of textual scrubbing over graph bookkeeping lives in ADR-0055 — without dropping any instruction.
- **Fix: a cancelled or timed-out synchronous hook stops instead of running on** (`src/zrb/llm/hook/executor.py`, `test/llm/hook/test_executor.py`, `docs/llm/hooks.md`): the executor runs a synchronous hook in its own event loop on a pool thread, and on timeout — or when its caller was cancelled, as when the user cancels the turn — it only stopped waiting, so the hook ran to its end: an agent hook's model request, a command hook's process for up to its 600-second default. It now cancels the hook inside that loop and waits up to `cancel_grace_seconds` (default 5) for it to finish, after which a hook blocked in a synchronous call is left to finish with a warning. A command hook's process is thus killed and the self-review reviewer stops before the turn goes on; the gate also resolves its scope through `run_in_worker`, so a cancelled review starts no further git command and deletes its store before returning.
- **Fix: a journal title containing `]` no longer survives its own delete, and one note's pinned line no longer replaces another's** (`src/zrb/llm/tool/journal_write.py`, `test/llm/tool/test_journal_notes.py`, `test/llm/tool/test_journal_backlinks.py`, `docs/adr/adr-0055.md`): a note's title is free-form model text, so `Fixes [nested] brackets` matched no line at all where `_register_link` and `_scrub_links_to` read a label as `[^\]]*` — retitling such a note registered a second index entry beside the first, and deleting it left its category and root index entries, and every backlink to it, pointing at a file that was gone. Labels are now matched greedily with the target taken from the end of the line. `_upsert_hud_line` also keyed its replacement on the note's path appearing anywhere in a line, so revising one note dropped another's pin that merely cited it, and two notes compressing the same fact (`projects` and `technical` share a section) kept one pin between them; it now matches the whole trailing ` ([note](path))`, the key ADR-0055 specifies, and a hand-pinned line with no note link is left to the section cap.
- **Fix: a synchronous hook runs in the caller's context, so the self-review gate reviews on the run's model** (`src/zrb/llm/hook/executor.py`, `test/llm/hook/test_executor.py`, `docs/contributing/maintainer-guide.md`): `ThreadPoolHookExecutor` submitted the hook to a pool thread, which starts with an empty `contextvars.Context`, so every per-run value the turn had set was gone by the time the hook ran — `current_model` among them, and the gate's reviewer therefore resolved `CFG.LLM_MODEL` rather than the run's own model, whatever `--model` or a `/model` switch had chosen; with `ZRB_LLM_MODEL` unset every review failed and the gate was silently off. Dispatch now copies the caller's context and runs the hook inside it — less the UI, the tool confirmation and the approval channel, which belong to the caller's event loop and cannot be driven from the hook's own, so a hook tool falls back as it did before.
- **Fix: `/save` carries the conversation's rewind history to the new name, before any snapshot of it can land** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/base/conversation_commands.py`, `test/llm/snapshot/test_manager_copies.py`, `test/llm/snapshot/test_manager_store.py`, `test/llm/ui/base/test_base_ui_conversation_commands.py`, `docs/adr/adr-0101.md`): `copy_history` queued the copy for the next snapshot to apply, and a copy that failed stayed queued, failing every later snapshot until a restart. It now registers the copy when it is called — before `/save` switches the session to the new name — so no snapshot of that name can land first and be overwritten, not even one a queued message starts in the same task; it returns a coroutine that applies the copy at once, which a custom UI should run (left unawaited, the next operation applies it). A copy git refuses is dropped with a warning. A copy of a copy not applied yet takes that copy's source when registered, so a later `/save` over the name in between cannot change it. The copy is kept in memory only: a session that ends before it lands — possible only while another process holds the store — leaves the saved name with no rewind history, its chat history saved either way. A record of pending copies beside the store, which a later session would apply, was built and dropped: each process interleaving needed a guard of its own, and it covered only that one corner (ADR-0101).
- **Fix: a rewind operation is bounded as a whole, and a cancelled one stops waiting for the store** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/util/file_lock.py`, `src/zrb/util/git/snapshot_command.py`, `test/llm/snapshot/test_manager_concurrency.py`, `test/util/test_file_lock.py`, `docs/adr/adr-0101.md`): each git command has a 30-second cap, but the sequence around it did not, so a directory too large to hash held a turn up one command at a time and failed only at the end. Once it holds the store's lock, every operation — the listing's walks, every command — now runs within `LLM_SNAPSHOT_OPERATION_TIMEOUT` (120 s), and running out is a `SnapshotTimeoutError`, which turns rewind off for the session. The wait for the lock, at most `LLM_SNAPSHOT_LOCK_TIMEOUT` (60 s), comes before the budget rather than out of it: a store another process holds is contention, and must not turn rewind off as a directory too slow to snapshot. The wait watches the worker's cancellation, since no git command runs while it waits, so a turn the user cancelled no longer sits it out. A cancelled caller raises `SnapshotCancelledError`, a `SnapshotError` that says nothing about the store: cancelled while the store was being set up — waiting for its lock, or in `git init` — an operation used to mark the store unusable and turn rewind off for the rest of the session. `hold_file_lock` takes the `cancel` event, checked before every attempt to take the lock — the first included, so a caller cancelled already never holds even a free one — and raises `FileLockCancelled`.
- **Improvement: a working directory outside every repository says its rewind is shallower than usual, and a missing git says nothing at startup** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/default/lifecycle.py`, `test/llm/snapshot/test_manager_taking.py`, `test/llm/snapshot/test_manager_availability.py`, `test/llm/ui/default/test_lifecycle.py`, `docs/adr/adr-0101.md`): the store lists loose files there, up to its budget, and no ignore rule applies — a `.gitignore` such a directory holds means nothing to git either — so a rewind there reaches less far than one in a repository, and the chat said nothing about it. The first snapshot of such a conversation now carries one `notice` progress event, which the TUI folds into the snapshot's own line (`✅ Initial workspace snapshot taken (no git repository here, …)`) rather than adding one. Without git on `PATH` rewind is off from the start with `GIT_MISSING_REASON`, which the TUI does not print — it is not news every session — and `/rewind` still says why.
- **Improvement: rewind, chat history and task session logs no longer grow without end** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/util/git/snapshot_store.py`, `src/zrb/llm/history_manager/file_history_manager.py`, `src/zrb/session_state_logger/file_session_state_logger.py`, `src/zrb/session_state_logger/session_state_logger_factory.py`, `src/zrb/util/string/name.py`, `src/zrb/config/mixins/{llm_content,foundation}.py`, `test/llm/snapshot/test_manager_housekeeping.py`, `test/util/git/test_snapshot_store_{restore,lifecycle}.py`, `test/llm/history_manager/test_file_history_manager_retention.py`, `test/session_state_logger/test_file_session_state_logger_retention.py`, `docs/adr/adr-0101.md`, `docs/configuration/llm-config.md`): with rewind on by default, every untracked file a turn saw went into `~/.zrb/llm-snapshots` and stayed there, as did every conversation's snapshots, and the chat histories and task session logs beside them were never pruned either. Three retention knobs, in the `TODO_RETENTION` duration format, with `0` keeping everything: `ZRB_LLM_SNAPSHOT_RETENTION` (30d) drops a conversation's rewind history once its newest snapshot is that old, never the current one's, when a session starts in the same directory, and `git gc --auto` then packs the store and, detached, prunes what no history holds — a timed-out snapshot's objects included; `ZRB_LLM_HISTORY_RETENTION` (30d) prunes a conversation's history and backups on the first save of a session, but only an auto-named one (`bold-arch-1234`, `is_random_name`) — a conversation named with `/save` or a session name of your own is kept, and a name typed in the generated shape is indistinguishable from one; `ZRB_SESSION_LOG_RETENTION` (30d) prunes task session logs and their timeline entries, at most once per `ZRB_SESSION_LOG_PRUNE_INTERVAL` (1d) per directory, since every `zrb` command is a process of its own. A file over `ZRB_LLM_SNAPSHOT_FILE_MAX_MB` (50) is left out of every snapshot as if ignored — a restore neither writes over it nor removes it, and self-review does not diff it — so a dataset nobody ignored is not copied into the store in full. The store's `info/attributes` is rewritten only when it differs, and by rename: another process's snapshot hashing while it was truncated would have seen no byte-exact rule and let the project's git-lfs filter store a pointer.
- **Fix: a Stop hook fired as the chat exits gets to finish** (`src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/default/lifecycle.py`, `test/llm/ui/base/test_base_ui_surface.py`, `test/llm/ui/default/test_lifecycle.py`, `docs/llm/hooks.md`): Ctrl+C fires Stop fire-and-forget and exits, and teardown cancelled every background task — now that a cancelled synchronous hook really stops, a slow "done" notification was killed mid-run. `BaseUI` tracks its hook tasks (`hook_tasks`), `on_exit` leaves them running, and teardown gives them `ZRB_HOOKS_EXIT_TIMEOUT` (10000 ms) through `drain_hook_tasks` before cancelling the rest with a warning.

- **Fix: a revised journal HUD line replaces a pre-3.8 line reading exactly as it does** (`src/zrb/llm/tool/journal_write.py`, `test/llm/tool/test_journal_notes.py`): HUD lines pinned before this release carry no note link and are left for the section cap to retire, but one with the very text of the new line is the same fact, and was left beside it as a duplicate.
- **Improvement: every limit this release adds is a `CFG` knob, read when it applies** (`src/zrb/config/mixins/{llm_content,hooks}.py`, `src/zrb/util/git/{snapshot_listing,snapshot_store,snapshot_command}.py`, `src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/default/lifecycle.py`, `docs/configuration/llm-config.md`, `docs/llm/hooks.md`, `docs/adr/adr-0101.md`): the limits were module constants, so changing one meant patching zrb.
