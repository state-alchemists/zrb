## 3.8.0 (September 24, 2026)

- **Feature: an opt-in self-review gate reviews each file-changing turn before it ends** (`src/zrb/llm/hook/self_review.py`, `src/zrb/llm/prompt/markdown/self_review.md`, `src/zrb/util/git/worktree.py`, `src/zrb/llm/hook/turn_evidence.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/agent/run/turn_cursor.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/config/mixins/llm_content.py`, `docs/adr/adr-0100.md`, `docs/llm/hooks.md`, `docs/configuration/llm-config.md`): PR #534 needed three review rounds, each one a CI finding the user pasted back into the chat. With `ZRB_LLM_SELF_REVIEW_ENABLED=on`, a synchronous Stop hook now runs that review inside the turn. The runner snapshots the working tree into a throwaway git index at turn start, and the gate diffs that against a second snapshot at Stop — so the review covers exactly what the turn changed, `Shell` edits and mid-turn commits included, the user's earlier uncommitted work excluded, writing nothing into the repository: snapshots keep their index and objects in a private, owner-only temporary store deleted when the turn ends, so untracked files such as a `.env` are never copied into `.git/objects`. A reviewer agent with a fresh context gets that diff — not the author's transcript — and read-only `Read`/`Grep`/`Glob`; outside git, or when a snapshot fails, it gets the file tools' paths with no diff — never `git diff HEAD`, which would include the user's earlier uncommitted work. A closing `Request changes` blocks the Stop, so the agent checks each finding against the code, fixes the real ones, and restates its answer. `LGTM`, an unclear verdict, or a failed review never blocks. `ZRB_LLM_SELF_REVIEW_MAX_ROUNDS` (default 2) caps reviews per user turn, `ZRB_LLM_SELF_REVIEW_MODEL` picks a separate reviewer model, and `ZRB_LLM_SELF_REVIEW_TIMEOUT` (default 240s) bounds each review as a whole: the git commands that resolve its scope are killed at the deadline, and the reviewer is cancelled inside the hook's own event loop so its model request actually stops, since the hook executor's own timeout only abandons its worker thread. The Stop payload gains `turn_start_snapshot` (taken only while the gate is on) and `changed_paths`, for this and any other hook that needs the turn's scope. The gate builds its reviewer through the existing agent-hook registration seam, so it adds no `# lazy: circular` workaround.
- **Improvement: `/rewind` snapshots no longer copy the working directory** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/default/lifecycle.py`, `src/zrb/util/git/worktree.py`, `docs/adr/adr-0101.md`, `docs/configuration/llm-config.md`): each snapshot used to copy the whole project into a per-session shadow folder and commit it there, so every file was stored twice per session — 994 MB across 11 sessions here — and the TUI waited for the first copy before it drew. A snapshot is now a commit in a private bare repository whose work tree is the project: one repository per project under `ZRB_LLM_SNAPSHOT_DIR`, a ref and an index per session and directory, and restore is `git read-tree -u --reset`. On this repository the first snapshot drops from 1.2 s and 85 MB to 0.4 s and 14 MB, and it now runs in the background. **Behaviour change:** `.gitignore` is honoured, so gitignored files (a `.env`, build output) are no longer snapshotted or restored — a file ignored after a snapshot captured it included, for rewind and self-review alike. Store and session names carry a hash, since sanitized paths alone collide (`a:b` and `a?b`). A `ZRB_LLM_SNAPSHOT_DIR` inside the project is excluded from its own snapshots — before, a restore rewrote the store mid-restore and lost the session's rewind history — and a relative one resolves against the process's working directory rather than the repository root. A file git cannot read, or a nested repository with no commit, is skipped instead of failing the snapshot — for the self-review snapshots too, which also keep their index between the turn's two snapshots instead of re-hashing the tree. The progress event `SnapshotProgress` loses its `copied` field. Old shadow folders in `ZRB_LLM_SNAPSHOT_DIR` are not migrated and can be deleted. **Default change:** `ZRB_LLM_ENABLE_REWIND` now defaults to `auto` — on inside a git repository, off outside one, where no `.gitignore` bounds a snapshot; set it to `off` to keep the old behaviour.
- **Improvement: `core-coding` checks the two places the #534 defects hid** (`src/zrb/llm_plugin/core_skills/core-coding/SKILL.md`): the discovery step already required finding call sites before a signature change; it now covers data formats and promised behavior too, naming the readers people forget (a parser, a cleanup routine, a migration). The validation step adds that a promised invariant must hold for state written before the change, and that a doc or docstring line is such a promise.
- **Fix: the retry summary no longer pairs one tool call's arguments with another's result** (`src/zrb/llm/agent/run/partial_run.py`, `test/llm/agent/run/test_partial_run.py`): `PartialRunAccumulator` held a single "current call" slot and matched results by tool name. Parallel calls stream every `ToolCallEvent` before any result, so two parallel `Read`s were recorded as one entry — the second call's arguments beside the first call's content — and the second was dropped. The `[SYSTEM: PREVIOUS ATTEMPT FAILED]` block then told the model it had read files it had not, and vice versa. Pending calls are now keyed by `tool_call_id`. The test that pinned the dropped call as intended behaviour now asserts both calls survive. The summary also says its results are cut at 500 characters, and that an interruption is usually the user's — so the model follows the user's new message instead of resuming the approach that was interrupted.
- **Fix: retitling or revising a journal note no longer leaves a contradicting duplicate in the indexes** (`src/zrb/llm/tool/journal_write.py`, `test/llm/tool/test_journal_notes.py`, `test/llm/tool/test_journal_backlinks.py`; the `SearchJournal` tests moved to `test/llm/tool/test_journal.py` to keep the notes file under the 500-line split rule): index registration skipped only an identical `- [label](target)` line, so a new title added a second entry for the same file; `hud_line` appended rather than replaced, so a revised finding sat beside the stale one in the always-injected index. Index lines are now keyed by link target: the first line for a note is relabelled in place and any later ones — including duplicates earlier retitles already left behind — are dropped, so exactly one survives. A HUD line carries a trailing link to its note, which a revision uses to replace the note's earlier line and `DeleteJournalNote` uses to scrub it. HUD lines pinned before this release carry no link, so they are neither replaced nor scrubbed; they age out under `LLM_JOURNAL_HUD_MAX_ENTRIES_PER_SECTION` (20 by default). Matching them by text was rejected — it could delete a different fact.
- **Improvement: the journal index says how the journal may be changed** (`src/zrb/llm/prompt/live_context.py`, `docs/adr/adr-0055.md`): the journal tools are registered with `defer_loading`, so their docstrings — where ADR-0055 put the journal's rules — are invisible until the model searches for them. A session edited the journal with Read/Edit for twenty calls because nothing visible said otherwise, and then patched the resulting duplicates by hand, leaving uncommitted changes. The `<journal-index>` header now names the three writers, says a direct edit breaks their index, backlink and git bookkeeping, and says to search for them when they are not visible. The writers' docstrings add the same rule for a model that searched first, record only what the session verified, and drop the unconditional "do not announce it", which contradicted reporting the outcome when the user asked for the write. A zero-hit `SearchJournal` is now described as weak evidence of absence.
- **Improvement: the prompt ranks truth above speed and resolves the ask-versus-proceed conflict** (`src/zrb/llm/prompt/markdown/{principle,workflow,profile.standard,profile.capable}.md`): `principle` states one priority order — protect the user's work, then truth, then completeness, then speed — and adds two rules: a claim about something not seen (a prior version, a diff not in hand) is inference to label or omit, and a diagnosis must re-read what it blames. Workflow step 4 now requires reading what a check printed and treating contradicting output as unverified; step 5 reports what was not verified. Tool Discovery's closing "do not search for what visible tools already cover" let a model decide Read/Edit covered journaling despite the bullet naming it; the bullet now says a generic tool approximating a dedicated one does not count, and the exemption is narrowed to a visible tool that is plainly right for the job. `profile.standard` said to raise risks "rather than pausing on them" while `principle` requires confirmation before destructive actions; it now names both stopping conditions. Both profiles activate methodologies on what the *work* matches, the same condition the workflow states.
- **Improvement: the agent pursues the goal when the direct route is closed, and the prompt says it in fewer words** (`src/zrb/llm/prompt/markdown/{principle,workflow,profile.standard,example}.md`): asked for the weather "at my current location", an agent replied that it had no GPS and asked for the city — then, told "try your best", found the location from the network and answered with a caveat in three tool calls. Nothing in the prompt told it to try the next-best evidence before handing the question back. `principle` now does, and limits asking the user to what no available tool can supply or a decision that is theirs to give; `profile.standard` counts "find out with your tools" among what the agent must exhaust before stopping, and Tool Discovery's last trigger widens from "about to report a capability does not exist" to "about to say something cannot be done". `example.md` trades the library-changelog example, whose lesson `principle` already states, for this one, and compresses the LaTeX/mermaid rendering example without dropping either rule. The sentence restating the priority order, workflow's "use reliable sources" (covered by `principle`) and the skill-batching paragraph (covered by workflow step 2) are gone: the always-on sections shrink from 1,341 to about 1,290 words while gaining a rule and an example.
- **Fix: the project-documentation listing no longer points at a section that does not exist** (`src/zrb/llm/prompt/claude.py`, `test/llm/prompt/test_claude.py`, `docs/adr/adr-0047.md`): the file list under **Documentation Files Found** said "See Project Documentation for when to read these", and **User-Level Guidance** said "not part of the mandatory read" — both referring to a prompt section removed in August. An agent handed a list of files and a pointer to rules that were not there read all of them, including a one-line `CLAUDE.md` that only imports `AGENTS.md`. The listing now states its own rule: the files are not loaded into the prompt; read the ones that bear on the work before editing, and they outrank user-level guidance. The journal writers' docstrings also shed prose the model never needed — `DeleteJournalNote`'s defence of textual scrubbing over graph bookkeeping lives in ADR-0055 — without dropping any instruction.
