## 3.8.0 (September 24, 2026)

- **Feature: an opt-in self-review gate reviews each file-changing turn before it ends** (`src/zrb/llm/hook/self_review.py`, `src/zrb/llm/prompt/markdown/self_review.md`, `src/zrb/llm/agent/run/turn_snapshot.py`, `src/zrb/llm/hook/turn_evidence.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/agent/run/turn_cursor.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/config/mixins/llm_content.py`, `docs/adr/adr-0100.md`, `docs/llm/hooks.md`, `docs/configuration/llm-config.md`): PR #534 needed three review rounds, each a CI finding the user pasted back into the chat. With `ZRB_LLM_SELF_REVIEW_ENABLED=on`, a synchronous Stop hook runs that review inside the turn. The runner snapshots the working directory at turn start and the gate diffs it against a second snapshot at Stop, so the review covers exactly what the turn changed — `Shell` edits and mid-turn commits included, the user's earlier uncommitted work excluded — in every repository under the directory: nested clones, submodules, a folder of repositories, and repositories the parent ignores (such as `EnterWorktree`'s worktrees). A repository that appears mid-turn (a new worktree, a clone) is diffed against the commit it started from. Snapshots go to a private, owner-only temporary store deleted when the turn ends, so untracked files such as a `.env` never reach any `.git/objects`. The gate only reads that store and diffs in one of its own, so a cancelled turn deleting it mid-review cannot break the review; a directory too large to snapshot within git's 30-second cap is not retried for the rest of the process. A fresh-context reviewer agent gets that diff — not the author's transcript — and read-only `Read`/`Grep`/`Glob`. It is also given, to read, paths the file tools named that the diff does not cover, and files the turn left unreadable (not shown as deleted; a turn whose only change is one is still reviewed). Without a snapshot it gets those paths alone — never `git diff HEAD`, which would include the user's earlier uncommitted work. A closing `Request changes` blocks the Stop, so the agent checks each finding against the code, fixes the real ones, and restates its answer; `LGTM`, an unclear verdict, or a failed review never blocks. `ZRB_LLM_SELF_REVIEW_MAX_ROUNDS` (default 2) caps consecutive blocking reviews per run, so concurrent sessions never reset each other's count; `ZRB_LLM_SELF_REVIEW_MODEL` picks a separate reviewer model; `ZRB_LLM_SELF_REVIEW_TIMEOUT` (default 240s) bounds each whole review — git commands are killed at the deadline, and the reviewer is cancelled inside the hook's own event loop so its model request actually stops. A delegated sub-agent's run is not reviewed on its own; the parent's diff covers it. The Stop payload gains `turn_start_snapshot`, `changed_paths`, `run_scope` and `nested_run` for any hook that needs the turn's scope.
- **Improvement: `/rewind` snapshots are git trees in a private store, on by default, and cover nested repositories** (`src/zrb/util/git/snapshot_listing.py`, `src/zrb/util/git/snapshot_store.py`, `src/zrb/util/git/snapshot_command.py`, `src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/default/lifecycle.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/base/conversation_commands.py`, `src/zrb/config/mixins/llm_content.py`, `docs/adr/adr-0101.md`, `docs/configuration/llm-config.md`, `docs/llm/llm-custom-ui.md`): each snapshot used to copy the whole project into a per-session shadow folder and commit it there — every file stored twice per session, 994 MB across 11 sessions here — and the TUI waited for the first copy before drawing. A snapshot is now a tree in a private bare repository whose work tree is the working directory: one store per directory under `ZRB_LLM_SNAPSHOT_DIR`, one ref per conversation. Zrb lists the files — each git repository under the directory by its own `.gitignore`, recursively, including nested ones, submodules and ones the parent ignores — and `git update-index` hashes them, keeping git's stat cache. On this repository the first snapshot takes 0.58 s and 9 MB instead of 1.2 s and 85 MB, a later one 0.02 s, and it runs in the background. **Default change:** `ZRB_LLM_ENABLE_REWIND` is now `on`. Outside every repository a directory may hold at most 5,000 files or 200 MB; past that (a chat started in `~`, say) rewind turns itself off for the session and says why. **Behaviour change:** gitignored files (a `.env`, build output) are no longer snapshotted or restored, and a `.gitignore` outside any repository has no effect, as in git. Old shadow folders in `ZRB_LLM_SNAPSHOT_DIR` are not migrated and can be deleted. Restore rewrites, recreates and removes files, nested repositories' included, but never a path ignored since the snapshot and never a repository's `HEAD`, and accepts only the session's own snapshots. It is byte-exact whatever `.gitattributes` say (git-lfs included). It removes a file only when the snapshot shows it did not exist: each commit records what its snapshot left out — every ignored path, whichever rule ignored it (`.gitignore`, `info/exclude`, global excludes), every unreadable directory, every file git could not read — plus the repositories it listed, and a restore reads that record rather than reconstructing the past. It leaves a worktree or clone made since as it is rather than hollowing it out. It never writes over a file it cannot read now, nor over anything unlisted in the way of what it writes (a directory holding an ignored file where the snapshot has a file, a FIFO) that `read-tree --reset` would remove — it reports that path instead. On macOS and Windows a case-only rename is restored rather than deleted. A write the filesystem refuses (a locked file, a read-only folder) no longer fails the whole rewind: the rest is restored, the chat rewinds, and `/rewind` names what was left behind via the `RestoreOutcome` that `restore_snapshot` returns; a restore that stops partway (a git command timing out mid-write) reports every file it meant to change the same way. A file git cannot read is skipped rather than failing the snapshot — detected by opening it, not by parsing git's message, which is translated and reworded across versions. A FIFO or socket is never opened, so it cannot hang a snapshot; a Windows junction is not followed. The store is owner-only (`0700`), and a store inside the directory is excluded from its own snapshots. Each snapshot or restore uses its own index file, so a git command killed at its timeout leaves no lock that breaks later snapshots and never takes another process's lock with it. A snapshot label can no longer pass for commit metadata: the message count ends the subject and the record sits in the body; a commit without a readable record is not restored. A file that becomes unreadable leaves the next snapshot instead of keeping stale content. A working directory its repository ignores (a scratch folder) is snapshotted instead of listed as empty. Rewind history belongs to the conversation — `/load` switches to the loaded conversation's snapshots, and `/save` copies them to the new name with the chat, before the next snapshot can be taken so that snapshot builds on it. A `ZRB_LLM_SNAPSHOT_DIR` equal to the working directory, a store that cannot be set up (directory not writable, git not installed), or a directory too large to snapshot within git's 30-second cap turns rewind off for the session with that reason instead of failing every turn, and `/rewind` says why. Snapshots and restores of one directory take turns under an OS lock on a file in its store (`src/zrb/util/file_lock.py`) — across sessions and processes, released if its holder dies, waited for at most 60 seconds, and never taken by `/rewind`'s listing, which runs on the UI's thread — so two rewinds never interleave writes and no snapshot catches a half-written restore.
- **Breaking: `SnapshotProgress` drops its `copied` field, and `restore_snapshot` returns a `RestoreOutcome`** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/default/lifecycle.py`): `copied` counted files copied into the shadow folder, which no longer exists, so it has no successor; a progress handler that unpacks the event by position (`stage, copied, skipped, reason = event`) fails, while one reading `event.stage`, `event.skipped` and `event.reason` keeps working. `restore_snapshot` returned a bool and now returns `RestoreOutcome(restored, left_behind)`, naming the files a refused write left behind; it is truthy exactly when the restore ran, so `if await manager.restore_snapshot(sha):` reads as before.
- **Improvement: `core-coding` checks the two places the #534 defects hid** (`src/zrb/llm_plugin/core_skills/core-coding/SKILL.md`): the discovery step's requirement to find call sites before a signature change now covers data formats and promised behavior too, naming the readers people forget (a parser, a cleanup routine, a migration). The validation step adds that a promised invariant must hold for state written before the change, and that a doc or docstring line is such a promise.
- **Fix: the retry summary no longer pairs one tool call's arguments with another's result** (`src/zrb/llm/agent/run/partial_run.py`, `test/llm/agent/run/test_partial_run.py`): `PartialRunAccumulator` held a single "current call" slot and matched results by tool name. Parallel calls stream every `ToolCallEvent` before any result, so two parallel `Read`s became one entry — the second call's arguments beside the first call's content — and the second was dropped; the `[SYSTEM: PREVIOUS ATTEMPT FAILED]` block then told the model it had read files it had not, and vice versa. Pending calls are now keyed by `tool_call_id`, and the test that pinned the dropped call as intended now asserts both survive. The summary also says its results are cut at 500 characters and that an interruption is usually the user's, so the model follows the user's new message instead of resuming the interrupted approach.
- **Fix: retitling or revising a journal note no longer leaves a contradicting duplicate in the indexes** (`src/zrb/llm/tool/journal_write.py`, `test/llm/tool/test_journal_notes.py`, `test/llm/tool/test_journal_backlinks.py`; the `SearchJournal` tests moved to `test/llm/tool/test_journal.py` to keep the notes file under the 500-line split rule): index registration skipped only an identical `- [label](target)` line, so a new title added a second entry for the same file, and `hud_line` appended rather than replaced, so a revised finding sat beside the stale one in the always-injected index. Index lines are now keyed by link target: the first line for a note is relabelled in place and later ones — including duplicates left by earlier retitles — are dropped. A HUD line carries a trailing link to its note, which a revision uses to replace the note's earlier line and `DeleteJournalNote` uses to scrub it. HUD lines pinned before this release have no link, so they are neither replaced nor scrubbed; they age out under `LLM_JOURNAL_HUD_MAX_ENTRIES_PER_SECTION` (default 20). Matching them by text was rejected — it could delete a different fact.
- **Improvement: the journal index says how the journal may be changed** (`src/zrb/llm/prompt/live_context.py`, `docs/adr/adr-0055.md`): the journal tools are registered with `defer_loading`, so their docstrings — where ADR-0055 put the journal's rules — are invisible until the model searches for them. One session edited the journal with Read/Edit for twenty calls, then patched the resulting duplicates by hand, leaving uncommitted changes. The `<journal-index>` header now names the three writers, says a direct edit breaks their index, backlink and git bookkeeping, and says to search for them when not visible. The writers' docstrings add the same rule for a model that searched first, record only what the session verified, and drop the unconditional "do not announce it", which contradicted reporting the outcome when the user asked for the write. A zero-hit `SearchJournal` is now described as weak evidence of absence.
- **Improvement: the prompt ranks truth above speed and resolves the ask-versus-proceed conflict** (`src/zrb/llm/prompt/markdown/{principle,workflow,profile.standard,profile.capable}.md`): `principle` states one priority order — protect the user's work, then truth, then completeness, then speed — and adds two rules: a claim about something not seen (a prior version, a diff not in hand) is inference to label or omit, and a diagnosis must re-read what it blames. Workflow step 4 now requires reading what a check printed and treating contradicting output as unverified; step 5 reports what was not verified. Tool Discovery's closing "do not search for what visible tools already cover" let a model decide Read/Edit covered journaling despite the bullet naming it; the bullet now says a generic tool approximating a dedicated one does not count, and the exemption is narrowed to a visible tool plainly right for the job. `profile.standard` said to raise risks "rather than pausing on them" while `principle` requires confirmation before destructive actions; it now names both stopping conditions. Both profiles activate methodologies on what the *work* matches, the condition the workflow states.
- **Improvement: the agent pursues the goal when the direct route is closed, and the prompt says it in fewer words** (`src/zrb/llm/prompt/markdown/{principle,workflow,profile.standard,example}.md`): asked for the weather "at my current location", an agent replied it had no GPS and asked for the city — then, told "try your best", found the location from the network and answered with a caveat in three tool calls. `principle` now says to try the next-best evidence before handing the question back, and limits asking the user to what no available tool can supply or a decision that is theirs; `profile.standard` counts "find out with your tools" among what the agent must exhaust before stopping, and Tool Discovery's last trigger widens from "about to report a capability does not exist" to "about to say something cannot be done". `example.md` trades the library-changelog example, whose lesson `principle` already states, for this one, and compresses the LaTeX/mermaid rendering example without dropping either rule. Removed as redundant: the sentence restating the priority order, workflow's "use reliable sources" (covered by `principle`), and the skill-batching paragraph (covered by workflow step 2). The always-on sections shrink from 1,341 to about 1,290 words while gaining a rule and an example.
- **Fix: the project-documentation listing no longer points at a section that does not exist** (`src/zrb/llm/prompt/claude.py`, `test/llm/prompt/test_claude.py`, `docs/adr/adr-0047.md`): **Documentation Files Found** said "See Project Documentation for when to read these", and **User-Level Guidance** said "not part of the mandatory read" — both referring to a prompt section removed in August. Given a file list and a pointer to absent rules, an agent read every file, including a one-line `CLAUDE.md` that only imports `AGENTS.md`. The listing now states its own rule: the files are not loaded into the prompt; read the ones that bear on the work before editing; they outrank user-level guidance. The journal writers' docstrings also shed prose the model never needed — `DeleteJournalNote`'s defence of textual scrubbing over graph bookkeeping lives in ADR-0055 — without dropping any instruction.
- **Fix: a cancelled or timed-out synchronous hook stops instead of running on** (`src/zrb/llm/hook/executor.py`, `test/llm/hook/test_executor.py`, `docs/llm/hooks.md`): the executor runs a synchronous hook in its own event loop on a pool thread, and on timeout — or when its caller was cancelled, as when the user cancels the turn — it only stopped waiting, so the hook ran to its end: an agent hook's model request, a command hook's process for up to its 600-second default. It now cancels the hook inside that loop and waits up to `cancel_grace_seconds` (default 5) for it to finish, after which a hook blocked in a synchronous call is left to finish with a warning. A command hook's process is thus killed and the self-review reviewer stops before the turn goes on; the gate also resolves its scope through `run_in_worker`, so a cancelled review starts no further git command and deletes its store before returning.
- **Refactor: comment and duplication cleanup across `src/zrb`, no behavior change**: narrating and restating comments were compressed to their reason (ADR references kept), and repeated logic now lives in one place — `focus_widget`/`invalidate_app` (`src/zrb/llm/ui/default/app/focus.py` new), `take_pre_turn_snapshot` (`src/zrb/llm/ui/turn_snapshot.py` new), `rebase_tracked_spans` (`src/zrb/llm/ui/output_chunk.py`, shared by `UIOutput` and `BufferedUI`), `get_shell_flag` (`src/zrb/util/cmd/command.py`), `start_process` (`src/zrb/llm/tool/shell.py`, now also used by the worktree tools), one search-backend path in `src/zrb/llm/tool/web.py`, and one pull/push loop in `src/zrb/builtin/git_subtree.py`. The ADRs, v3 changelog and guides were tightened the same way, and 12 broken same-page anchors were fixed.
