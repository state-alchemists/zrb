## 3.32.0 (November 3, 2026)

- **Changed default: rate-limit pacing is opt-in** (`src/zrb/config/mixins/llm_limits.py`, `src/zrb/llm/config/limiter.py`): `ZRB_LLM_ENABLE_RATE_LIMIT` now defaults to off. The governor charges every request the whole context it sends, so a long session against a 128k-token budget paced itself down to roughly one step a minute, while providers already answer 429 and the client retries. **Migration:** a deployment that sets `ZRB_LLM_MAX_REQUEST_PER_MINUTE` or `ZRB_LLM_MAX_TOKEN_PER_MINUTE` and expects pacing must also set `ZRB_LLM_ENABLE_RATE_LIMIT=on`; while it is off those two values change nothing.
- **Changed default: one tool result is pruned at 8,000 tokens, not half the context** (`src/zrb/config/mixins/llm_content.py`, `src/zrb/llm/summarizer/tool_result_pruner.py`): `ZRB_LLM_MESSAGE_SUMMARIZATION_TOKEN_THRESHOLD` used to default to half the conversational trigger — 48,000 tokens at the stock 128k budgets — so a result was pruned only near the whole context window, which in practice meant it almost never was, and one 60k-token `cat` stayed in the transcript for every turn after it. The default is now 8,000. Pruning is deterministic: a token-budgeted head, a budgeted tail, a marker for the removed middle, and a pointer to the verbatim text in the session's history archive. No model is asked to summarize the output, and the head and tail are never truncated to fit the pointer.
- **Changed default: `AGENTS.md`, `CLAUDE.md` and `GEMINI.md` are inlined into the system prompt** (`src/zrb/llm/prompt/claude.py`, `src/zrb/config/mixins/llm_prompt.py`): the project's rules used to arrive as a list of paths, and an agent that did not open them worked without its conventions. The nearest file is inlined first and gets the byte budget first (`ZRB_LLM_PROJECT_INSTRUCTIONS_MAX_BYTES`, 24,000 by default), a broader file is dropped rather than inlined past a dropped narrower one, a pure pointer (`CLAUDE.md` holding `@AGENTS.md`) costs nothing and never starves the file it names, and a symlinked or hardlinked instruction file is listed but never read. `ZRB_LLM_INJECT_PROJECT_INSTRUCTIONS=off` restores the list-only behaviour.
- **Feature: linked worktrees live outside the checkout, and their tools are always visible** (`src/zrb/llm/tool/worktree.py`, `src/zrb/llm/sandbox/policy.py`, `src/zrb/llm/sandbox/bwrap.py`, `src/zrb/llm/agent/gates.py`): `EnterWorktree`, `ExitWorktree` and `ListWorktrees` are no longer deferred tools in a git repository, and a worktree is created under `ZRB_LLM_WORKTREE_DIR` (default `~/.zrb/wt/<repo>-<digest>/`) instead of inside the checkout — a nested worktree is a second copy of the repository that every search has to learn to skip. The sandbox judges the repository the worktree is created in as well as its destination, so a model-chosen `cwd` cannot write another repository's `.git`, and a writable root that does not exist yet is skipped when the Linux `bwrap` profile is built, so a fresh sandboxed Linux host no longer fails every command waiting for `~/.zrb/wt` to appear.
- **Feature: a paid agent evaluation harness, opt-in** (`test/eval/`, `zrb-test.sh`): `./zrb-test.sh eval` runs real `zrb llm chat` turns against sixteen fixture repositories and scores them by behaviour — does the module import, does the suite pass — rather than by prose. It spends money and time, so it is its own mode: no coverage pass, no pyright, one worker. `LLM_EVAL_MODEL` picks the model.
- **Feature: the day block gains a week gist** (`src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/tool/journal_index.py`): a session's first turn now carries the shape of the week — which days held what, and each day's dominant project — not only yesterday's two lines, so an agent arriving after three quiet days can tell "nothing happened" from "nothing about this".
- **Feature: a journal note says which repository it is about** (`src/zrb/llm/tool/journal_scope.py`, `src/zrb/llm/tool/journal_index.py`, `src/zrb/llm/prompt/live_context.py`): notes carry a `repo:` tag, the injected index shows the notes for the checkout in hand, and the rest are compressed under `## Other projects` with their counts. `SearchJournal` is never filtered: scoping is about what arrives unasked.
- **Feature: a handover is dated, and the next session looks back a week** (`src/zrb/llm/tool/journal_write.py`, `src/zrb/llm/prompt/live_context.py`): the `## Handover` section now names the day it was written and a session reads the most recent one within seven days, instead of only today's — a handover written on Friday is still the state of the work on Monday morning.
- **Feature: a note can say what would disprove it, in a form a machine checks** (`src/zrb/llm/tool/journal_expiry.py`, `src/zrb/llm/tool/journal_write.py`, `src/zrb/llm/prompt/live_context.py`): `applies_when` accepts `file:<path>`, `version:<3.29` / `version:>=3.29.1`, `setting:<NAME>=<value>` and `date:<YYYY-MM-DD>`. A `file:` condition is read inside the work tree the note was written in — a linked worktree's own checkout, not the main one — and the digest is stored beside the condition with the checkout it came from, so a note from another checkout is uncheckable rather than wrong. Paths may not leave the repository, reads are bounded, and a condition this machine cannot evaluate keeps its note: expiry hides what is disproved, never what is merely unchecked.
- **Chore: queue-closure fixes, dead code and duplicated logic swept** (`src/zrb/llm/`): the sweep is behaviour-preserving; every public name, signature and `test/public_api_snapshot.json` entry is unchanged.
