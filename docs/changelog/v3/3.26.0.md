## 3.26.0 (October 23, 2026)

- **Feature: compaction renders the kept tail to text instead of resending it as structured messages, so the split no longer has to dodge a tool call/return pair** (`src/zrb/llm/summarizer/history_splitter.py`, `src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/llm/message.py`): a pair spanning nearly the whole history (a call near the start, its return near the end) could leave no split point both within the tail budget and safe for the pair, so the fallback search degenerated into summarizing the entire history as one chunk. The kept tail is now rendered with the same lossless `message_to_text` conversion used to prepare a summarized chunk, folded into the compaction turn as its own section after the `<state_snapshot>` and uncapped by `LLM_SUMMARY_MAX_TOKENS`, so the split is a plain token-budget cut — `find_safe_split_index`, `find_best_effort_split` and `is_split_safe` are gone. A tool call still awaiting its result (a pending deferred call) is the one exception: `pending_tail_start` finds it and the kept tail is widened to cover it, so it still reaches the model as a real `ToolCallPart`, resumable as before. A tail that fails even the tight 40% budget now gets a second attempt at a looser 80% (`FALLBACK_BUDGET_RATIO`) before falling back to keeping nothing ([ADR-0041](../../adr/adr-0041.md), revised).
