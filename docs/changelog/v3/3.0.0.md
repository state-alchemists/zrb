- **Fix: `/model small` and `/model multimodal` now reach every consumer, because the tier precedence lives in the resolver instead of at each call site** (`src/zrb/llm/config/model_resolver.py`, `src/zrb/llm/summarizer/history_summarizer.py` via `src/zrb/llm/agent/summarizer.py`, `src/zrb/llm/hook/journal_compliance.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/voice/engine.py`, `src/zrb/llm/hook/creator.py`): `/model small <name>` reached only the journal-compliance hook, which passed `get_current_small_model()` by hand. An agent hook with no model of its own now inherits the run's model too (`hook/creator.py`), instead of jumping to `CFG.LLM_MODEL`.
- **Fix: switching the main model no longer leaves the summarizer on the old provider** (`src/zrb/llm/agent_state.py`, `src/zrb/contextvars.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/config/model_resolver.py`): `zrb llm chat --model deepseek:deepseek-chat` failed every turn with pydantic-ai's *"Set the `OPENAI_API_KEY` environment variable"*. The main agent was built on deepseek, but the per-turn summarizer resolved its own model through `resolve_configured_small_model()`, whose chain was `CFG.LLM_SMALL_MODEL or CFG.LLM_MODEL` — landing on the shipped OpenAI default. A new `current_model` ambient var (indexed in `contextvars.py`) carries the model `run_agent` was handed, and the chain is now *explicit argument* → `CFG.LLM_SMALL_MODEL` → `get_current_model()` → `CFG.LLM_MODEL`, so `/model`, `--model` and `LLMChatTask(model=...)` carry the summarizer and journal judge with them. Present since 2.69.0 and earlier.
- **Fix: an unbuildable summarizer no longer fails the turn** (`src/zrb/llm/summarizer/history_summarizer.py`): `_summarize_fat_messages` and `_maybe_compress_history` each return the original messages when summarization fails, but the two `create_*_summarizer_agent()` calls ran *before* those guards — so a construction error (a small model whose provider has no credentials) propagated out of the history processor and failed the whole `chat-process` task after three retries. Construction now runs inside the same guard: one warning line, history left unsummarized. Present since 2.69.0 and earlier.
- **Fix: a mid-session `/model <name>` switch is now resolved through `ModelResolver`** (`src/zrb/llm/task/shared_getters.py`, `src/zrb/llm/ui/base/exec_commands.py`): `resolve_model()` returned an explicitly set model as-is and sent only the `CFG` fallback through `resolve_configured_model()`. Since `/model <name>` stores the typed name on `BaseUI.model` and hands it to the core task as `ctx.input["model"]`, the switched-to model reached pydantic-ai as a bare string — `CFG.LLM_API_KEY`/`LLM_BASE_URL` dropped, an explicit `CFG.LLM_PROVIDER` ignored, and `model_resolver.model_getter`/`model_renderer` never fired. `/btw` had the same hole. Note `LLMTask(model=...)` and `--model` are resolved the same way now, so `get_model(ctx)` returns a resolved `Model` where it previously echoed the string back.
- **Fix: `./zrb-test.sh` failed roughly one run in five with an `ImportError` in `test/llm/voice/test_engine.py`** (`test/conftest.py`, `test/architecture/test_sys_modules_patch_allowlist.py`): `patch.dict("sys.modules", ...)` restores by `clear()` + `update(snapshot)`, so a module first imported *inside* the block is absent from the snapshot and evicted on exit. `VoiceEngine.record` lazily imports numpy inside such a block; the eviction left numpy's single-phase-init C extension loaded but unlisted, so the next `import numpy` raised `cannot load module more than once per process` (a hard error since CPython 3.12). Intermittent because `--dist load` distributes tests individually — whether the one `TestRecord` test that imports numpy before the patch landed on the same worker was a coin flip. Fixed by warming numpy once per worker, folding in the existing `pydantic_ai.toolsets` warm-up (same bug, fixed pointwise earlier); the new `test_sys_modules_patch_allowlist.py` ratchet requires each shadowed module name to be listed, and found three a manual grep had missed.
- **Fix: an `lru_cache` keyed more narrowly than its inputs leaked a stubbed `shutil.which` across a worker** (`src/zrb/llm/prompt/system_context.py`): `_which(cmd)` memoized tool availability without `$PATH` in the key, so `test_system_context.py`'s stub left a fabricated answer memoized for every later test on that worker. The cache moved one level up, onto `_resolve_available_tools(project_types, infra_types, path)`, where every key component is genuinely read; `$PATH` is threaded from the caller into `shutil.which(path=...)`, so it is both the key and the lookup, and one entry per (project, infra, PATH) shape replaces ~21 per-command ones. `PATH` unset passes through as `None`, not `""`, keeping `shutil.which`'s `CS_PATH`/`os.defpath` fallback (bpo-35755). A `$PATH` change now re-detects in production too.
- **Fix: three more sources of cross-test state leakage** (`test/llm/lsp/test_configs.py`, `test/llm/lsp/test_manager.py`, `test/conftest.py`, `test/llm/util/test_llm_git.py`): the two LSP fixtures cleared `lsp_server_configs` on entry with no teardown, leaking their own registrations into whichever test ran next — both now clear on the way out. `current_agent_mode`'s default is a shared mutable instance that `set_current_agent_mode` mutates in place, so a test calling it without a run-local scope left the whole worker in plan mode, flipping `get_effective_policy()`; an autouse fixture now binds a fresh `AgentModeState` per test. And `set_active_worktree`/`set_interactive_mode` joined `set_current_session` in `conftest.py`'s restore list — all three are unscoped, and the other two were safe only because callers happened to restore the default. Verified with ten consecutive `-n auto --dist load` runs plus eight module-order-shuffled runs; `--dist loadfile` was rejected as a fix (it masks the numpy bug rather than fixing it, at +31% wall time).

## 3.0.0a2

- **New capability: `model_resolver.model_getter`/`model_renderer` — a global fallback for the task-scoped hooks of the same name** (`src/zrb/llm/config/model_resolver.py`): the per-task `model_getter`/`model_renderer` 3.0.0a1 moved onto `LLMTask`/`LLMChatTask` only reach that one task's own agent — sub-agent delegation (`SubAgentBuilding.resolve_agent_build`) and any other `resolve_configured_model`/`resolve_configured_small_model`/`resolve_configured_multimodal_model` call site had, and still have, no per-task hook to set. `model_resolver` (the already-exported singleton whose job this extends) gained the same settable, type-checked pair — `model_resolver.model_getter = f` / `model_resolver.model_renderer = f` — applied inside `ModelResolver.resolve()` after ordinary provider resolution, so every one of those call sites picks it up with no code change of its own. This is not `LLMConfig` reborn: it is two callable slots on a resolver, not a scalar-override object, so it does not trip the R12 "exactly one configuration object" ratchet (`model_resolver` does not end in `_config`). A task's own `model_getter`/`model_renderer`, when set, still applies on top of (after) this global default for that task, matching the existing `model_getter`-then-`model_renderer` order. See [Upgrading to 3.0.0](../../advanced-topics/upgrading-guide.md#upgrading-to-300).

New ratchet: `test_mutation_surface.py::test_managers_expose_the_same_roster_api`, with `PromptManager` excluded per ADR-0090 Part 1.

- **Breaking: the UI contract is `AnyUI`, and lives where it types things** (Phase 8, R9): `UIProtocol` → `AnyUI`, matching the thirteen other `Any<Thing>` extension points, moved from `src/zrb/llm/tool_call/ui_protocol.py` to `src/zrb/llm/ui/any_ui.py` (with its `ChoiceOption`/`ChoiceSpec` support types) — it types the `ui` slot on every task, so it belongs to `llm/ui/`; tool confirmation being its first consumer was a historical accident. Exported from `zrb` for the first time (`from zrb import AnyUI`); see [Upgrading to 3.0.0](../../advanced-topics/upgrading-guide.md#upgrading-to-300) for the import migration. Writing the R9 ratchet surfaced two more violations: `AnyCmdVal` lived in `cmd_val.py` rather than `any_cmd_val.py` (split out), and `ApprovalChannel` — a genuine extension point per its own docstring — was missing the prefix entirely, so it became `AnyApprovalChannel` in `any_approval_channel.py` (`ApprovalContext`/`ApprovalResult` moved with it; the `current_approval_channel` `ContextVar` stayed put). Both landed as `Protocol`s and were converted to ABCs in this same unreleased version, once checking showed the other twelve `Any*` types are all ABCs and every real implementer already satisfies all six methods concretely; `BaseUI`, `StdUI`, `MultiUI`, `TerminalApprovalChannel` and `NullApprovalChannel` gained explicit bases. **Side effect, not a regression:** `SimpleUI`'s and `EventDrivenUI`'s `@abstractmethod` decorators were previously inert without `ABCMeta` in the MRO — an incomplete subclass constructed fine and failed later with `NotImplementedError`; it now fails at instantiation with `TypeError`, naming the missing methods. New ratchet: `test_boundaries.py::test_every_extension_point_is_named_any_thing_in_any_thing_py`, with three named exemptions for `isinstance`-probe Protocols and a structural one for callback-signature Protocols. **Known, not fixed:** `LLMTask.uis` has no R5 verb set while `LLMChatTask.uis` does — internally consistent, mutually inconsistent.

- **Fix: typed errors and one config-mixin naming convention** (Phase 9, R10/R11): 13 `raise Exception(...)` sites are gone. The 12 internet-search-backend raises (`llm/tool/search/http_errors.py`, `brave.py`, `serpapi.py`, `searxng.py`, `google_rss.py`) already carried real `[SYSTEM SUGGESTION]` context and just needed a type — the new `SearchToolError(RuntimeError)`; `builtin/changelog.py`'s `git tag` failure is a maintainer error, not an agent one, so it raises plain `RuntimeError`. Six constant-string error messages under 40 characters now name the offending value and the fix: `builtin/git_subtree.py` (×2), `util/todo/model.py`, `xcom/xcom.py`, `llm/ui/multi_ui.py`, and `llm/task/chat/running.py`'s "No UI available" — which turned out to be dead code (`_resolve_ui` never returns `None`, per its own return annotation and 0% branch coverage) and was deleted rather than reworded. Two of the six were found by the new ratchets rather than the manual audit, whose grep covered only three exception types and messages under 25 characters: `test_boundaries.py::test_no_bare_exception_is_raised` and `test_no_error_message_is_shorter_than_forty_characters` (both AST-walk `ast.Raise`; the message check only inspects a bare constant first argument, since an f-string or variable is assumed to carry context). Six config mixins were renamed to match the other 13 (`ConfigLLMContent` → `LLMContentMixin` and siblings, `ConfigCLIStyle` → `CLIStyleMixin`), guarded by `test_config_mixins_share_one_naming_convention`; `Config`'s ~200-character trailing `# noqa: E501` comment moved into the class docstring.

- **Docs: the ADR log is reflowed, not rewritten — no content dropped** (Phase 10, prose only): average ADR paragraph had tripled from 226 characters (ADR-0001-0030) to 615 (ADR-0061-0091), with 126 paragraphs across 42 files over 700 characters and one (ADR-0079) at 4,357 — roughly 700 words with no break. Each was reflowed with one of three moves: a numbered list that was really sub-decisions became bold-lead sub-sections, prose enumerating alternatives became a table, and an em-dash sentence-chain split where the subject changes. New maximum: 692 characters, verified word-for-word against the committed text both by reading `git diff --word-diff=porcelain` in full and by an independent bag-of-words diff. Also fixed while sweeping: four stale `**Where it lives**` citations (ADR-0043, ADR-0077, ADR-0072), one code example still showing the removed `ApprovalChannel` name, one 1,090-character paragraph in `docs/configuration/llm-collections.md`, and a Table of Contents for the three long non-ADR pages missing one (`llm-custom-ui.md`, `installation.md`, `programming-the-prompt.md`). `docs/adr/README.md` now opens by saying the log is a lookup table, not a read-through. New ratchet: `test/architecture/test_doc_density.py` — paragraph caps for ADRs (700) and other docs (900, changelogs excluded as append-only history), plus a TOC check for pages over 150 lines. Its splitter is fence-aware, unlike the quick diagnostic scripts that produced the original counts.

- **Cleanup: two `hasattr`/`isinstance` checks left over from before `AnyUI` became an ABC are now dead code, deleted** (`src/zrb/llm/tool/ask.py`, `src/zrb/llm/task/chat/running.py`): `ask_user_question` no longer falls back from `ask_user_choice` to `ask_user` for a "custom UI predating `ask_user_choice`" — every `AnyUI` implementer is guaranteed to have it now. `run_interactive_session` no longer branches on `isinstance(ui, BaseUI) or hasattr(ui, "run_async")` with a dead `raise ValueError` else-branch — `run_async` is unconditionally abstract on `AnyUI` too. A repo-wide sweep for the same pattern against every other `Any*` extension point found no other gaps: the remaining `hasattr`/`isinstance` checks in `multi_ui.py` and friends are legitimate progressive-enhancement probes over a heterogeneous `MultiUI` fan-out (some members are full `BaseUI`, some are minimal custom `AnyUI`s), not contract gaps — promoting any of those methods to `AnyUI` would force TUI-only state onto every custom UI.
- **Docs: examples and reference docs swept for the Phase 8 renames** (`examples/chat-minimal-ui/`, `examples/chat-sse/`, `examples/chat-telegram/`, `docs/task-types/llmchat-task.md`, `docs/advanced-topics/maintainer-guide.md`, `docs/advanced-topics/llm-custom-ui.md`): stale `UIProtocol`/bare `ApprovalChannel` references updated to `AnyUI`/`AnyApprovalChannel`, including two box-drawing diagrams whose padding had drifted out of alignment since the rename shortened the label. `llm-custom-ui.md`'s "BaseUI Optional Methods" table gained the `ask_user_choice()` row it was missing (it already documented `stream_to_parent()`'s default; the "5 items to implement" required list was already correct — both methods have working defaults on `BaseUI`, so a `BaseUI` subclasser was never required to implement them).
- **Renamed to 3.0.0.** The accumulated breaking changes above — a removed configuration object, a constructor-parameter consolidation, three renamed API families, and two contracts converted to ABCs — go well past what a minor release should carry.
