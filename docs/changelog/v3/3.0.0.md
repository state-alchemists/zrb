## 3.0.0b10

- **Fix: the install scripts silently installed a beta; `--pre` is now opt-in** (`install.sh`, `install.ps1`, `docs/installation/installation.md`): both scripts hard-coded `pipx install --pip-args='--pre'`, so anyone running the documented one-liner got the newest pre-release rather than the newest stable — and because `--pip-args` persists in pipx's metadata, their later `pipx upgrade zrb` kept tracking betas too, with nothing in the output saying so. `install.sh` now takes `--pre` and `install.ps1` takes `-Pre`; without it, the install resolves to the latest stable. Passing the flag logs which channel was chosen, and both scripts document their flags in a usage header. Piping from GitHub needs the `--` separator (`bash -c "$(curl -fsSL ...)" -- --pre`) so the flag reaches the script instead of `bash`, which the installation guide now shows.

- **Chore: the install-script banner follows the b9 tagline reframe** (`install.sh`, `install.ps1`): 3.0.0b9 swept "Your Automation Powerhouse" out of the README, the startup banner, `ROOT_GROUP_DESCRIPTION`, `WEB_JARGON` and the OpenAPI summary, but missed the two installers — so the very first thing a new user saw still greeted them with the old positioning. Both now print `Coding Agent + Task Engine`, which is 26 characters and fits the existing 28-column box unchanged.

- **Fix: colon-separated path config broke every Windows path, and `colon_list` is now `path_list`** (`src/zrb/config/env_field.py`, `src/zrb/config/mixins/{foundation,hooks,web,llm_search,llm_sandbox}.py`, `test/config/test_env_field.py`, `test/llm/sandbox/test_policy.py`): `colon_list` split unconditionally on `:`, so a Windows value like `C:\skills;D:\skills` parsed as `['C', '\skills;D', '\skills']` — the drive letter became its own entry and every path was garbage. It now splits on `os.pathsep`, which *is* the platform answer (`;` on Windows, `:` elsewhere), and the serializer joins with the same separator so `zrb config explain` and the `CFG` setters round-trip. This affects `ZRB_INIT_SCRIPTS`, `ZRB_HOOKS_DIRS`, `ZRB_WEB_CSS_PATH`, `ZRB_WEB_JS_PATH`, `ZRB_LLM_PLUGIN_DIRS`, `ZRB_LLM_BASE_SEARCH_DIRS`, `ZRB_LLM_EXTRA_SKILL_DIRS`, `ZRB_LLM_EXTRA_AGENT_DIRS`, `ZRB_LLM_CONFIG_DIR_NAMES`, `ZRB_LLM_SANDBOX_WRITABLE_PATHS` and `ZRB_LLM_SANDBOX_DENY_READ_PATHS`. `LLM_CONFIG_DIR_NAMES` also hard-coded its default as the literal string `".claude:.zrb"`, which would have collapsed to one entry under the new split; it now builds the default through the serializer. Since the separator is no longer always a colon, the three helpers are renamed to match: **`colon_list` → `path_list`, `colon_join` → `path_list_join`, `expanduser_colon_list` → `expanduser_path_list`**. These are internal to `zrb.config.env_field` — never exported from `zrb` — so there is no compatibility shim; a `zrb_init.py` importing them directly must update the name. `comma_or_colon_list` keeps its name: it parses module names for `ZRB_INIT_MODULES`, where `:` is a documented legacy delimiter and never a drive letter. Every affected knob's `doc=` and doc-table row now says "semicolon on Windows" instead of only "Colon-separated".

## 3.0.0b8

- **`UIDefaultsMixin` is now `UIStateDefaultsMixin`, in `llm/ui/state_defaults.py`** (`src/zrb/llm/ui/state_defaults.py` renamed from `defaults.py`, `any_ui.py`, `base/ui.py`, `std_ui.py`, `multi_ui.py`, `buffered_ui.py`, `test/llm/ui/test_state_defaults.py` renamed, `test_buffered_ui.py`): `UIConfig` lives in the same package and holds the user-facing defaults — assistant name, greeting, slash-command aliases — so `UIDefaults` read like a second one. It defaults the other half of `AnyUI` entirely: the ten state members and side-effect hooks `MultiUI` broadcasts to children, where a UI that keeps none of that state answers `None`/`False`/no-op. The name now says which half. The `Mixin` suffix stays and is earned under ADR-0035: every value read is a `_uidefaults_`-prefixed attribute the class declares and sets itself, there is no `__init__` a host must call, and `background_tasks` builds its own set on first access — so any class can genuinely mix it in. Class-only rename; no behavior change, and nothing was exported from `zrb.llm.ui`.

- **Fix: `create_ui_factory` raised `TypeError` for two of the three documented UI extension levels** (`src/zrb/llm/ui/ui_factory.py`, `src/zrb/llm/ui/simple_ui_base.py`, `src/zrb/llm/ui/event_driven_ui.py`, `src/zrb/runner/chat/http_ui.py`, `src/zrb/llm/ui/ui_config.py`, `test/llm/ui/test_extension_levels.py` new, `test/llm/ui/test_ui_factory.py`, `docs/llm/llm-custom-ui.md`): the factory passed `config=`, which only `SimpleUI` accepted — `BaseUI` and everything built on it takes `ui_config=`, so the documented one-line registration failed for a Level-3 backend with `BaseUI.__init__() got an unexpected keyword argument 'config'`. The keyword is now `ui_config` everywhere, including `create_ui_factory`'s own parameter (`create_ui_factory(MyUI, config=cfg)` becomes `ui_config=cfg`) and `SimpleUI`/`EventDrivenUI`'s constructors. `SimpleUI` also stops keeping a second reference to the same object under `self._config`; `BaseUI.ui_config` was always the accessor. 5641 tests missed this because `test_ui_factory.py` used `SimpleUI` three times and `BaseUI` zero.

- **Docs: the custom-UI contract is executable instead of counted** (`test/llm/ui/test_extension_levels.py` new, `src/zrb/llm/ui/base/ui.py`, `docs/llm/llm-custom-ui.md`): `BaseUI`'s docstring carried an ASCII "Extension Levels" box that contradicted `docs/llm/llm-custom-ui.md` — `BaseUI` was Level 1 in the source and Level 3 in the guide — and advertised `AnyUI` as "minimal, 4 methods" when a 4-method subclass will not instantiate (it needs 6, or 16 without `UIDefaultsMixin`). Its "Required Methods (must be implemented by subclasses)" list was wrong in the other direction: `BaseUI.__abstractmethods__` is empty, so all four ship working implementations and are overrides, not requirements. The guide meanwhile told readers to call `_process_messages_loop()`, `_submit_user_message()`, `_stream_ai_response()`, `self._initial_message`, `self._llm_task` and `self._process_messages_task` — six names that exist only without the underscore, so the Level-3 example raised `AttributeError` as written. The box, the counts and the private names are gone; the new test builds a minimal subclass at each documented level, implementing exactly what that level's row lists and registering it the documented way, so a changed requirement fails in CI rather than in a user's `zrb_init.py`. Reverting the `ui_config` fix above fails 7 of its 12 cases.

- **Breaking: `LLMChatTask`'s four `ui_*` text parameters moved into `UIConfig`** (`src/zrb/llm/ui/ui_config.py`, `src/zrb/llm/task/chat/task.py`, `src/zrb/llm/task/chat/running.py`, `src/zrb/llm/ui/default/ui.py`, `src/zrb/builtin/llm/chat.py`, `test/architecture/test_constructor_surface.py`, `test/llm/ui/conftest.py`, `test/llm/task/chat/test_running_sessions.py`, `test_running_history_and_commands.py`, `docs/task-types/llmchat-task.md`, `docs/llm/llm-integration.md`, `docs/llm/permission-policy.md`, `docs/llm/programming-the-prompt.md`): the assistant's name was settable three ways — `CFG.LLM_ASSISTANT_NAME`, `UIConfig(assistant_name=)`, and `LLMChatTask(ui_assistant_name=)` — and greeting/banner/tagline two ways, with the two paths disagreeing on *when* the value resolves (`UIConfig.assistant_name` was a plain `str`; `ui_assistant_name` was a `StrAttr` resolved per run) and on *who* receives it (`assistant_name` reached every UI through `ui_config`; `greeting`/`ascii_art`/`jargon` were extra kwargs only the default terminal `UI` accepted, so a custom `BaseUI`/`SimpleUI` backend could not be given a greeting at all). `UIConfig` now carries all four as `default_factory` fields reading the same `CFG` knobs — the deferral the `StrAttr` form existed for, which `LLMChatTask` already had because it materializes its `UIConfig` lazily on first access. `ui_greeting`, `ui_assistant_name`, `ui_jargon` and `ui_ascii_art` are gone; pass `ui_config=UIConfig(greeting=...)`. `LLMChatTask.ui_texts` is gone with them, as is the per-run `get_str_attr` loop in `running.py` and three parameters on `UI.__init__` (20 → 17). `LLMChatTask` 62 → 58 params. No in-tree or documented caller used the callable form — every example passed a literal — so the deferred-per-`ctx` variant is dropped rather than widened.

- **Fix: `UIConfig.merge_commands` silently dropped any non-command field added to the dataclass** (`src/zrb/llm/ui/ui_config.py`): it rebuilt the config by hand-listing all 22 fields, so a new field was carried over only if someone remembered to extend the list — and the three fields above would have been reset to their `CFG` defaults on every `create_ui_factory` call. It is now `dataclasses.replace` over the command keys actually passed, guarded by a frozenset of the real `*_commands` field names so an unknown key is ignored rather than written. 37 lines → 8.

- **Docs: the two architecture budget files say which direction they move** (`test/architecture/test_constructor_surface.py`, `test/architecture/test_facade_size_budget.py`): both pin the current maximum, but nothing said a bump was meant to be exceptional — so the ratchet read as a drift detector rather than a debt ledger. Lowering a ceiling now needs only the diff that earns it; raising one needs an ADR. `test_constructor_surface.py` also records what its numbers are *not*: 20 of `LLMChatTask`'s and `LLMTask`'s parameters are `BaseTask`'s, re-declared on purpose so the signature documents itself, and `PARENT_OF`/`INTENTIONAL_OMISSIONS` exist to keep exactly those in sync.

## 3.0.0b7

- **Fix: `/rewind` was invisible by default, and typing it sent "/rewind" to the model** (`src/zrb/llm/ui/base/conversation_commands.py`, `src/zrb/llm/ui/base/commands.py`, `src/zrb/llm/ui/default/ui.py`, `test/llm/ui/base/test_commands_rewind.py` new, `conftest.py` new, `test/llm/ui/test_ui_command_handlers.py`): rewind availability was expressed in three places — the handler returned `False` without a snapshot manager, `default/ui.py` blanked `rewind_commands` before building the completer, and the help panel wrapped its row in `if base_ui.snapshot_manager is not None`. Since `LLM_ENABLE_REWIND` defaults to off, the shipped default hid the command from both `/help` and tab-completion, and the handler's `False` let `dispatch_command` forward the literal text to the LLM as a chat message — so the feature was undiscoverable and misbehaved when found. It now follows `/voice`: one gate, in the handler, after the token match, printing a warning and consuming the input. The message names `{ENV_PREFIX}_LLM_ENABLE_REWIND` when that knob is the reason and points at the session/`LLM_SNAPSHOT_DIR` requirement when it is not. `default/ui.py` no longer knows any command name, and `dataclasses.replace` is gone from it.
- **Tests: the `llm/ui/base` command tests share one `MockUI`** (`test/llm/ui/base/conftest.py` new, `test_commands_basics.py`, `test_commands_shell.py`, `test_commands_voice.py`): three byte-identical 95-line copies of the `BaseUI` stand-in had accumulated. `test_get_help_text_empty_commands` was also passing for the wrong reason — it cleared thirteen command lists but not `rewind_commands`, and only stayed green because the help row used to be gated on `snapshot_manager`.

- **Breaking: the terminal UI stopped threading 16 slash-command parameters through three layers** (`src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/ui/default/app/layout.py`, `src/zrb/llm/ui/default/app/completion/completer.py`, `test/llm/ui/default/app/test_layout.py`, `test/llm/ui/default/app/completion/test_completer_arguments.py`, `test_completer_commands.py`): every command's alias list was a separate named parameter passed `UI` → `create_input_field` → `InputCompleter` — `layout.py` declared 16 of them and immediately forwarded all 16 without reading any, and the two model-visibility toggles rode along the same way. All three signatures now take the `UIConfig` that already holds those fields (`BaseUI.<x>_commands` is a property reading and writing `_ui_config`, so the values are identical), leaving `layout.py` a one-line forward. Adding a slash command no longer touches `layout.py` or `default/ui.py` at all: 8 files down to 5. `InputCompleter.__init__` and `create_input_field` drop their per-command parameters and the two `show_*_models` toggles for a single `ui_config: UIConfig`; `InputCompleter` is exported from `zrb.llm.ui.default.app.completion`, so a caller constructing it directly passes a `UIConfig` instead. Every class in `zrb.llm.ui.__all__` keeps its full public surface and gains a `commands` accessor.

- **Fix: overriding a slash-command handler on a custom UI did nothing** (`src/zrb/llm/ui/base/commands.py`, `src/zrb/llm/ui/base/ui.py`, `test/architecture/test_command_dispatch_surface.py` new, `docs/llm/llm-custom-ui.md`): `BaseUI` publishes a `handle_<name>_command` method per slash command and is the documented Level-3 extension point, but `_command_table()` bound each handler to the sub-part that owns the code (`self._conversation.handle_save_command`) rather than to the UI instance. That resolves the method once, at table-build time, off an object the subclass is not in the MRO of — so a subclass overriding `handle_save_command` saw its code run when it called the method itself and silently skipped when a user typed `/save`. All 15 table entries now bind `base_ui.handle_<name>_command`, including the `handle_custom_command` fallback and `handle_toggle_voice` (which was bound to the dispatcher). `_command_table` is now public `command_table`, reachable via a new `BaseUI.commands` property so a subclass can reorder or extend it; `BaseUICommands` gained `conversation`/`models`/`exec` properties for the same reason. With dispatch going through the facade, `BaseUICommands`' 24 pass-through methods had one caller each and are deleted (608 → 551 lines); `BaseUI`'s delegators now forward straight to the owning part. Guarded by a new architecture ratchet asserting every `command_table()` handler satisfies `handler.__self__ is ui`, plus a behavioural test that a subclass override actually runs on `dispatch_command`.

- **New: `ZRB_INIT_STRICT` makes a failed init source fatal, for CI** (`src/zrb/config/mixins/foundation.py`, `src/zrb/__main__.py`, `docs/configuration/env-vars.md`, `docs/advanced-topics/ci-cd.md`, `test/test_main.py`): 3.0.0a1 landed `_load_or_die`, reverted it to `_load_or_warn` in the same unreleased version, and recorded why — at a prompt, the error already names file, line and type, so refusing to run costs a retry and saves nothing. That reasoning holds for a human and inverts for an unattended run: a `zrb_init.py` that raises *after* `cli.add_task(deploy)` leaves `deploy` callable, so CI runs it and reads exit `0` against configuration that was never finished. Rather than re-litigating the default, the behavior is now a knob — **off by default**, unchanged interactively. With it on, every init source is still attempted and every failure still reported (one run lists them all), then zrb aborts before `cli.run()` and exits `1`. The abort message names the active env prefix, so a white-labeled distribution reads `ACME_INIT_STRICT`.

## 3.0.0b6

- **Fix: env/input inheritance was exponential on a diamond DAG, and `zrb <task>` never returned past ~40 tasks** (`src/zrb/task/base/context.py`, `src/zrb/task/any_task.py`, `src/zrb/task/base/base_task.py`, `test/task/test_dag_shape.py` new, `test/task/base/test_context_cycle.py`, `docs/adr/adr-0092.md` new, `adr-0009.md`): `BaseTask.inputs` and `.envs` recursed by reading the *same aggregated property* on each upstream, so every node re-derived its whole closure once per incoming edge. One `.inputs` read cost O(n³) on a chain (1.0s at 800 tasks) and O(2\*\*depth) on a diamond — 13.0s for 44 tasks over 22 levels, and a 40-task lattice made `zrb deploy` run past 300s without returning, because `runner/cli.py` reads `task.inputs` while building kwargs, before the task starts. `_combine_envs` also had no dedupe, so the returned list itself doubled per level: 131,070 entries for 32 distinct envs at 16 levels. Aggregation is now one iterative post-order walk (`_upstream_closure`) that visits each task once, with two new `AnyTask` members — `own_inputs` and `own_envs` — for what a node contributes on its own; the aggregated properties could not answer that. Same lattice read: **13,019ms → 0.12ms**; the 41-task pipeline runs in 2.1s; env lists are one entry per env. Being iterative also retires the `RecursionError` that hit past ~450 levels of chaining — a 50,000-deep chain resolves. The `_walking_envs`/`_walking_inputs` re-entrancy flags are deleted, replaced by the walk's own on-path set, which is what tells a diamond from a cycle. Nothing is cached: a closure walk is O(n) and a read returns O(n) items, so a cache would buy an invalidation contract and no asymptotics. It went unnoticed because zrb's own `zrb_init.py` peaks at 97 tasks and depth 6. See ADR-0092.

  **Breaking, and a fix:** a task's own envs now override every env it inherits, at any graph shape. Across a diamond the old form re-appended a shared ancestor's envs *after* the other branch's, so the ancestor could beat the downstream task that overrode it — which task won depended on branch enumeration order. Inputs are unchanged (first-per-name, and post-order yields the identical order). Also breaking for a third-party `AnyTask` implementation: add `own_inputs`/`own_envs`; `BaseTask` is the only implementer in-tree.

- **Breaking: `zrb <task>` exits with the command's own exit code** (`src/zrb/task/cmd_task.py`, `src/zrb/__main__.py`): `CmdTask` raised a bare `RuntimeError` carrying the code only inside its message, and `__main__` exited 1 for everything, so `CmdTask(cmd="pytest")` reported failure but not *which* failure — the distinction CI acts on. The new `CmdTaskError` carries `return_code`, and `_handle_uncaught` reads it off the exception with `getattr` rather than importing the task type, so any error that knows a meaningful process exit code can carry one. `zrb sh42` on `cmd="exit 42"` now exits 42; a Python-level task failure still exits 1.

- **Refactor: `is_path_included` and `is_path_excluded` were the same function under opposite names** (`src/zrb/util/file.py`, `src/zrb/llm/tool/code_constants.py`, `src/zrb/llm/tool/code.py`, `file_list.py`, `file_search.py`, `test/util/test_file_util.py`): byte-identical bodies in two modules, called two lines apart in `analyze_code` — one to reject a path, one to accept it. Both are now `matches_any_pattern` in `zrb.util.file`, named for the predicate rather than for what a caller does with the answer. `code_constants.py` lost its `fnmatch`/`os` imports with the copy.

- **Docs: the terminal UI class is documented, and `BaseUI`'s ladder no longer names a class that does not exist** (`src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/ui/base/ui.py`): `UI` — the prompt_toolkit TUI every `zrb llm chat` instantiates — was the only class in `llm/ui/` without a docstring, while `BaseUI`, `SimpleUI`, `EventDrivenUI`, `StdUI`, `BufferedUI`, `MultiUI` and `UIDefaultsMixin` all had one. It now says what it is, what it adds over `BaseUI` (the `Application`, width-dependent re-wrapping via `_rendered_blocks`/`rewrap_output`, collapsible blocks, `GlobalStreamCapture`), which seven parts it composes, and that `MultiUI`/`BufferedUI` are wrappers that compose with it rather than alternatives to it — the two the custom-UI guide's three-level ladder does not cover. `BaseUI`'s own ladder box called level 3 `MultiplexerUI`, a name that appears nowhere else in the tree; the class is `MultiUI`.

- **Refactor: the mccabe complexity ratchet drops 22 → 19, by hoisting one closure out of `run_chat_session`** (`src/zrb/runner/chat/chat_session_runner.py`, `test/architecture/test_complexity_ratchet.py`): the ratchet sat at 22 because of exactly one function. `run_chat_session` scored mccabe 22 against radon 15 — the seven-point gap was its nested `run_llm_message`, whose branches mccabe sums into the enclosing score. It did not qualify for the `# noqa: C901` escape the ratchet documents (that needs radon ≤ 4; 15 is genuine complexity), so the closure moved to a module-level `_run_llm_message` instead. It captured only `run_chat_session`'s own three parameters, so hoisting costs three explicit arguments and no restructuring. `run_chat_session` is now mccabe 17 / radon 15, the helper is mccabe 5 / radon 4, and the ceiling moves to the three functions that actually sit at 19 — `strip_to_text_only`, `_execution_loop`, `_load_or_reindex`. `RADON_LIMIT` stays 20: it was already pinned to its exact maximum, held by `_execution_loop` and `LLMLimiter.to_str`, and neither is closure-inflated, so lowering it means refactoring rather than renumbering. Both limits now carry the no-headroom rule the facade and constructor budgets use.

- **Chore: the constructor-surface budgets are pinned to the exact current counts** (`test/architecture/test_constructor_surface.py`): `LLMChatTask` 71 → 62 and `LLMTask` 53 → 48, which is what they actually take after the rendering parameters left. A budget carrying nine slots of headroom silently absorbs the next few additions — the drift the file exists to make visible.

## 3.0.0b5

- **Breaking: rendering is opt-in — a bare `str` is now a literal, and the `render_*`/`auto_render` flags are gone** (`src/zrb/attr/tpl.py` new, `src/zrb/attr/type.py`, `src/zrb/util/attr.py`, plus every task/input/env/callback that carried a flag; `test/attr/test_tpl.py` new): `get_attr` used to render any plain string against the context, so a command containing shell `${VAR}` or `awk '{print}'` was an f-string expression by default and each such parameter needed a paired escape hatch to opt *out*. That is 47 `render_x: bool` parameters across `CmdTask` (9), `RsyncTask` (13), `Scaffolder` (4), `LLMChatTask` (9), `LLMTask` (5), `HttpCheck`, `TcpCheck`, `Callback`, `PromptManager`, plus `auto_render` on `Cmd`, `CmdPath`, `Env`, `EnvMap`, `EnvFile`, `ContentTransformer` and every `Input`. Rendering is now requested by wrapping the template in the new `Tpl`: `CmdTask(cmd=Tpl("echo {ctx.input.name}"))`. `Tpl.__call__(ctx)` returns the rendered string, so it resolves through `get_attr`'s existing `callable(attr)` branch and needed no new machinery — every `*Attr` alias already had a `Callable[..., str]` arm. With no implicit rendering left, the opt-out flags have nothing to opt out of and were deleted rather than deprecated. `ctx.render()` and `fstring_format` are unchanged; only the *implicit* application of them is gone, so a task body calling `ctx.render(...)` itself still works. The `fstring` alias is removed from `zrb.__all__` (it was `= str`, documenting a "renders as a template" meaning that no longer holds) and `Tpl` takes its place.

  `BaseTask.action` is covered by the same rule. It never went through `get_attr` — `BaseTaskExecution.run_default_action` had its own unconditional `ctx.render(action)` — so it was the one attribute where a bare string was still implicitly rendered. That branch also stopped assuming `action.__name__`, which a `Tpl` (or any callable object) does not have.

  Migrating: a string that was meant as a template becomes `Tpl("...")`; a string that was meant literally loses its `render_x=False`. `Tpl` is also the better answer inside a loop — `Tpl(f"echo {n}")` binds `n` eagerly, where `lambda ctx: f"echo {n}"` captures the variable and yields the last value for every task.

Six constant-string error messages under 40 characters now name the offending value and the fix: `builtin/git_subtree.py` (×2), `util/todo/model.py`, `xcom/xcom.py`, `llm/ui/multi_ui.py`, and `llm/task/chat/running.py`'s "No UI available" — which turned out to be dead code (`_resolve_ui` never returns `None`, per its own return annotation and 0% branch coverage) and was deleted rather than reworded. Two of the six were found by the new ratchets rather than the manual audit, whose grep covered only three exception types and messages under 25 characters: `test_boundaries.py::test_no_bare_exception_is_raised` and `test_no_error_message_is_shorter_than_forty_characters` (both AST-walk `ast.Raise`; the message check only inspects a bare constant first argument, since an f-string or variable is assumed to carry context). Six config mixins were renamed to match the other 13 (`ConfigLLMContent` → `LLMContentMixin` and siblings, `ConfigCLIStyle` → `CLIStyleMixin`), guarded by `test_config_mixins_share_one_naming_convention`; `Config`'s ~200-character trailing `# noqa: E501` comment moved into the class docstring.

- **Docs: the ADR log is reflowed, not rewritten — no content dropped** (Phase 10, prose only): average ADR paragraph had tripled from 226 characters (ADR-0001-0030) to 615 (ADR-0061-0091), with 126 paragraphs across 42 files over 700 characters and one (ADR-0079) at 4,357 — roughly 700 words with no break. Each was reflowed with one of three moves: a numbered list that was really sub-decisions became bold-lead sub-sections, prose enumerating alternatives became a table, and an em-dash sentence-chain split where the subject changes. New maximum: 692 characters, verified word-for-word against the committed text both by reading `git diff --word-diff=porcelain` in full and by an independent bag-of-words diff. Also fixed while sweeping: four stale `**Where it lives**` citations (ADR-0043, ADR-0077, ADR-0072), one code example still showing the removed `ApprovalChannel` name, one 1,090-character paragraph in `docs/configuration/llm-collections.md`, and a Table of Contents for the three long non-ADR pages missing one (`llm-custom-ui.md`, `installation.md`, `programming-the-prompt.md`). `docs/adr/README.md` now opens by saying the log is a lookup table, not a read-through. - **Cleanup: two `hasattr`/`isinstance` checks left over from before `AnyUI` became an ABC are now dead code, deleted** (`src/zrb/llm/tool/ask.py`, `src/zrb/llm/task/chat/running.py`): `ask_user_question` no longer falls back from `ask_user_choice` to `ask_user` for a "custom UI predating `ask_user_choice`" — every `AnyUI` implementer is guaranteed to have it now. `run_interactive_session` no longer branches on `isinstance(ui, BaseUI) or hasattr(ui, "run_async")` with a dead `raise ValueError` else-branch — `run_async` is unconditionally abstract on `AnyUI` too.
