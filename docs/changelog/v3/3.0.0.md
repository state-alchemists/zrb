## 3.0.0 (September 11, 2026)

_Includes the 3.0.0a1–3.0.0b11 pre-release line._

First stable 3.x release. It opened as 2.70.0 and was renamed because the accumulated breaking changes — a removed configuration object, a constructor-parameter consolidation, three renamed API families, two contracts converted to ABCs, and opt-in template rendering — exceed what a minor release should carry. [Upgrading to 3.0.0](../../advanced-topics/upgrading-guide.md#upgrading-to-300) has the consolidated migration tables.

- **Breaking: `LLMConfig`/`llm_config` are gone — `CFG` is the only LLM configuration object** (`src/zrb/llm/config/config.py` deleted, `src/zrb/llm/config/model_resolver.py` new, `src/zrb/llm/agent_state.py`, R12): every scalar it held is a plain `CFG` knob (`CFG.LLM_MODEL`, `LLM_SMALL_MODEL`, `LLM_MULTIMODAL_MODEL`, `LLM_API_KEY`, `LLM_BASE_URL`, and the new `LLM_PROVIDER`/`ZRB_LLM_PROVIDER`); `llm_config.model_settings` had no reader and is dropped. `resolve_model()` became `resolve_configured_model` / `resolve_configured_small_model` / `resolve_configured_multimodal_model` on the new `ModelResolver`, with the `model_resolver` singleton exported from `zrb`. `model_getter`/`model_renderer` are settable properties on `LLMTask`/`LLMChatTask` (replacing the `llm_config=` parameter), and `model_resolver.model_getter`/`model_renderer` are a settable, type-checked global fallback applied in `ModelResolver.resolve()`, so sub-agent delegation (`SubAgentBuilding.resolve_agent_build`) and other call sites without a per-task hook pick it up; a task's own hooks still apply after the global default. `/model small` and `/model multimodal` no longer write a shared singleton that leaked between concurrent chat sessions: they travel as per-run `ContextVar`s (`current_small_model`, `current_multimodal_model`) bound at the start of `run_agent()`. `MultiUI` does not yet proxy those two attributes, so `/model small` through a fanned-out `MultiUI` falls back to `CFG`.
- **Fix: model tiers follow the model actually in use** (`src/zrb/llm/config/model_resolver.py`, `src/zrb/llm/agent/summarizer.py`, `src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/llm/hook/journal_compliance.py`, `src/zrb/llm/hook/creator.py`, `src/zrb/llm/voice/engine.py`, `src/zrb/llm/task/shared_getters.py`, `src/zrb/llm/ui/base/exec_commands.py`, `src/zrb/contextvars.py`): tier precedence now lives in the resolver, not at each call site. Small resolves *explicit argument* → `get_current_small_model()` → `CFG.LLM_SMALL_MODEL` → `get_current_model()` → `CFG.LLM_MODEL`; multimodal resolves *explicit argument* → `get_current_multimodal_model()` → `CFG.LLM_MULTIMODAL_MODEL` → `None` (never the main model). A new `current_model` ambient var carries the model `run_agent` was handed, so `--model deepseek:deepseek-chat`, `/model` and `LLMChatTask(model=...)` carry the summarizer and journal judge with them instead of failing every turn asking for `OPENAI_API_KEY` (present since 2.69.0 and earlier), and `/model small` now reaches the summarizer, not only the journal-compliance hook. An agent hook with no model inherits the run's model. A mid-session `/model <name>`, `/btw`, `LLMTask(model=...)` and `--model` now resolve through `ModelResolver` (so `CFG.LLM_API_KEY`/`LLM_BASE_URL`, an explicit `CFG.LLM_PROVIDER` and `model_getter`/`model_renderer` apply), and `get_model(ctx)` returns a resolved `Model`. An unbuildable summarizer (e.g. a small model's provider lacking credentials) logs one warning and leaves history unsummarized instead of failing the turn.
- **Fix: API keys reach only the provider they were configured for** (`src/zrb/llm/config/model_resolver.py`, `docs/adr/adr-0094.md` new, `docs/configuration/llm-config.md`): `ZRB_LLM_API_KEY` belongs to the provider named by `ZRB_LLM_PROVIDER`, else by `ZRB_LLM_MODEL`'s prefix; the `resolve_configured_*` functions withhold it from a model naming a *different* provider (so `ZRB_LLM_MODEL=openai:gpt-5` plus `ZRB_LLM_SMALL_MODEL=anthropic:…` no longer sends the OpenAI key to Anthropic), returning the bare name so pydantic-ai reads that vendor's own variable. A forgotten exported vendor variable cannot displace an explicitly set `ZRB_LLM_API_KEY`, and `ModelResolver` uses the credentials handed to `resolve()` literally (ADR-0023). An explicit `ZRB_LLM_BASE_URL` disables the withholding (one gateway serving every tier, e.g. LiteLLM/OpenRouter), and a bare model name has no vendor to mismatch. An explicit `ZRB_LLM_PROVIDER` supplies the prefix for an unprefixed model and no longer drops `ZRB_LLM_API_KEY`/`ZRB_LLM_BASE_URL` (a gateway user was silently sent to the vendor's public endpoint); a `Provider` instance counts as a credential; a `base_url` a native provider cannot accept (`DeepSeekProvider`) builds the OpenAI-compatible provider explicitly. A prefixed non-openai model on a custom `ZRB_LLM_BASE_URL` gets pydantic-ai's `api-key-not-set` placeholder instead of silently inheriting `OPENAI_API_KEY`; an unprefixed name still inherits it (ADR-0037). The configuration reference gained a "Which API Key Gets Used" section with a decision flowchart (also in ADR-0094) and tables for single-vendor, native non-OpenAI and mixed-vendor setups.
- **Behavior change: `CFG` assignments fail fast, and import-time reads are gone** (`src/zrb/config/config.py`, `src/zrb/config/env_field.py`, `src/zrb/builtin/todo.py`, `src/zrb/builtin/searxng/start.py`, `src/zrb/runner/cli.py`, R3): assigning an unknown `CFG.UPPERCASE` name raises `AttributeError` naming the closest real knob and the real `{ROOT_GROUP_NAME} config explain` command; a value the field's `cast` cannot round-trip raises `ValueError` at assignment. `DEFAULT_*` constants and read-write properties like `ROOT_GROUP_NAME` are unaffected. `CFG.TODO_VISUAL_FILTER` and `CFG.SEARXNG_PORT` now respond to `zrb_init.py` (they were read at import), and `start-server`'s `--help` description no longer bakes in a stale root group name.
- **Behavior change: init-script failures are reported precisely, and `ZRB_INIT_STRICT` makes them fatal** (`src/zrb/__main__.py`, `src/zrb/util/load.py`, `src/zrb/config/mixins/foundation.py`, `docs/configuration/env-vars.md`, `docs/advanced-topics/ci-cd.md`, `docs/contributing/framework-conventions.md`): a broken `zrb_init.py` or `ZRB_INIT_SCRIPTS`/`ZRB_INIT_MODULES` entry now prints file, line and exception type to stderr and the CLI continues (`load_file` gained opt-in `raise_on_error`, default `False`, so plugin/skill/hook discovery stays lenient); R4's rule text now says the same. For CI, `ZRB_INIT_STRICT` (off by default) attempts every source, reports every failure, then exits `1` before `cli.run()`, so a script failing after `cli.add_task(deploy)` no longer lets `deploy` run and exit `0`. The message names the active env prefix (`ACME_INIT_STRICT` in a white-labeled build).
- **Breaking: path-list config splits on `os.pathsep`, and `colon_list` is `path_list`** (`src/zrb/config/env_field.py`, `src/zrb/config/mixins/{foundation,hooks,web,llm_search,llm_sandbox}.py`): splitting on `:` broke every Windows path (`C:\skills;D:\skills`). Lists now split and join on `;` on Windows, `:` elsewhere, affecting `ZRB_INIT_SCRIPTS`, `ZRB_HOOKS_DIRS`, `ZRB_WEB_CSS_PATH`, `ZRB_WEB_JS_PATH`, `ZRB_LLM_PLUGIN_DIRS`, `ZRB_LLM_BASE_SEARCH_DIRS`, `ZRB_LLM_EXTRA_SKILL_DIRS`, `ZRB_LLM_EXTRA_AGENT_DIRS`, `ZRB_LLM_CONFIG_DIR_NAMES` (default now built through the serializer), `ZRB_LLM_SANDBOX_WRITABLE_PATHS` and `ZRB_LLM_SANDBOX_DENY_READ_PATHS`. Helpers renamed with no shim: `colon_list` → `path_list`, `colon_join` → `path_list_join`, `expanduser_colon_list` → `expanduser_path_list`; a `zrb_init.py` importing them from `zrb.config.env_field` must update. `comma_or_colon_list` (for `ZRB_INIT_MODULES`) keeps its name.
- **Security: `CmdTask`'s DEBUG log redacts secret environment values** (`src/zrb/util/secret.py` new, `src/zrb/task/cmd_task.py`, `src/zrb/config/mixins/foundation.py`, `docs/configuration/env-vars.md`): the environment map logged under `ZRB_LOGGING_LEVEL=DEBUG` printed every API key and token. Values whose name matches `CFG.SECRET_ENV_PATTERNS` (default `KEY`, `SECRET`, `TOKEN`, `PASSWORD`, `PASSWD`, `CREDENTIAL`, `AUTH`, `PRIVATE`, `SIGNATURE`, `SALT`, case-insensitive substrings) now show as `***`, names kept; `ZRB_SECRET_ENV_PATTERNS=""` opts out.
- **Breaking: rendering is opt-in — a bare `str` is a literal, and every `render_*`/`auto_render` flag is gone** (`src/zrb/attr/tpl.py` new, `src/zrb/attr/type.py`, `src/zrb/util/attr.py`, `src/zrb/task/`, `src/zrb/env/`, `src/zrb/input/`, `src/zrb/llm/task/chat/task.py`, `src/zrb/llm/prompt/manager.py`): implicit rendering made shell `${VAR}` or `awk '{print}'` an f-string by default and needed 47 `render_x: bool` opt-outs (`CmdTask`, `RsyncTask`, `Scaffolder`, `LLMChatTask`, `LLMTask`, `HttpCheck`, `TcpCheck`, `Callback`, `PromptManager`) plus `auto_render` on `Cmd`, `CmdPath`, `Env`, `EnvMap`, `EnvFile`, `ContentTransformer` and every `Input` — all deleted, not deprecated. Request rendering with `Tpl`: `CmdTask(cmd=Tpl("echo {ctx.input.name}"))`; it resolves through `get_attr`'s callable branch. `BaseTask.action` follows the same rule (a bare string is returned verbatim; a callable object without `__name__` works). `ctx.render()` and `fstring_format` are unchanged; the `fstring` alias leaves `zrb.__all__` and `Tpl` takes its place. `EnvMap(vars=...)` is now `dict[str, StrAttr]`. Migrating: a template becomes `Tpl("...")`; a literal drops its `render_x=False`; in a loop, `Tpl(f"echo {n}")` binds `n` eagerly where a lambda would capture the last value.
- **Breaking and fix: env/input inheritance is linear on any DAG shape, and a task's own envs always win** (`src/zrb/task/base/context.py`, `src/zrb/task/any_task.py`, `src/zrb/task/base/base_task.py`, `docs/adr/adr-0092.md` new, `adr-0009.md`): `BaseTask.inputs`/`.envs` re-derived each upstream's closure per incoming edge — O(n³) on a chain and O(2\*\*depth) on a diamond, so a 40-task lattice made `zrb deploy` run past 300s before starting, and env lists doubled per level. Aggregation is now one iterative post-order walk visiting each task once (13,019ms → 0.12ms on that lattice), with no `RecursionError` on deep chains, and a cycle (`a >> b >> a`) reports `Circular task dependency detected involving '<name>'` instead of a `RecursionError` naming neither task. Across a diamond a task's own envs now override every inherited env regardless of branch order; inputs are unchanged (first-per-name). A third-party `AnyTask` implementation must add the new `own_inputs`/`own_envs` members. See ADR-0092.
- **Breaking: `zrb <task>` exits with the command's own exit code** (`src/zrb/task/cmd_task.py`, `src/zrb/__main__.py`): the new `CmdTaskError` carries `return_code`, which the CLI reads with `getattr` (any error may carry one), so `cmd="exit 42"` exits 42; a Python-level task failure still exits 1.
- **Improvement: failures print one clean line, with the way to get more** (`src/zrb/task/base/execution.py`, `src/zrb/__main__.py`): a permanently failed task no longer prints a raw traceback twice (once from the retry loop, once escaping `serve_cli()`); both go through `log_debug`/`_handle_uncaught`, visible with `ZRB_LOGGING_LEVEL=DEBUG`. The failure line now names that variable, spelled from the active prefix (`ACME_LOGGING_LEVEL=DEBUG`).
- **Behavior change: an unrecognized `--flag` raises instead of being discarded** (`src/zrb/runner/common_util.py`, `src/zrb/util/string/suggestion.py` new, `src/zrb/group/group.py`): `zrb greet --nmae bob` ran at exit 0 with `name` unset; unknown keys now raise in CLI mode with a `difflib` suggestion and the accepted options (positional args still reach `ctx.args`; web mode is unaffected). An unresolved subcommand (`zrb base64 encoode`) suggests the closest child of the node where the walk stopped. `Group.add_task` documents that a duplicate alias deliberately replaces the existing task (how a project shadows a built-in, per [CI/CD](../../advanced-topics/ci-cd.md)).
- **Fix: a missing input no longer dies with `EOFError` when stdin is closed** (`src/zrb/input/base_input.py`): under CI, cron or `< /dev/null`, `prompt_cli_str` now uses the declared default, resolves an `allow_empty=True` input empty, or fails with `Cannot read input '<name>': ... Pass it explicitly with --<name> <value>`. Covers `OptionInput` too; piping, explicit flags and blank-answer retry on a tty are unchanged.
- **Fix: constructor annotations match what they forward** (`src/zrb/task/{cmd_task,rsync_task,scaffolder,base_trigger,scheduler,http_check,tcp_check}.py`, `src/zrb/llm/task/llm_task.py`, `src/zrb/llm/task/chat/task.py`): the `readiness_*` parameters accept `None` again at type-check level (23 annotations now match `BaseTask`), `execute_condition` accepts the full `BoolAttr`, and `LLMTask(model="openai:gpt-4o")`/`LLMChatTask(model=...)` type-check as documented. `TcpCheck` names the eight `BaseTask` parameters it deliberately does not forward (`retries`, `retry_period`, the `readiness_*`/`monitor_readiness` knobs) and `HttpCheck` drops its false parity claim.
- **Fix: the unrecommended-command linter stopped flagging everyday commands** (`src/zrb/util/cmd/command.py`): banned words match whole words, so `npm test`, `pip install open-source-lib` and `aws s3 ls s3://…` pass; the `ls` rule requires command position; the `" test"` and grep-long-option rules are gone; a plain `echo 'text'` passes while `echo -n`/`-e` and backslash escapes are still flagged. Real violations (`source ./env.sh`, `which python`, `eval $x`, `diff <(a) <(b)`, `ls -la`, `realpath .`) still trigger.
- **Improvement: `zrb config explain` prints full descriptions** (`src/zrb/builtin/config.py`): the truncating three-column table is now a definition list (name and value on one line, wrapped description beneath); values collapse to one line in the listing, and a filter matching exactly one knob prints it in full. 2822 → 857 lines.
- **Refactor: `is_path_included`/`is_path_excluded` are one `matches_any_pattern`** (`src/zrb/util/file.py`, `src/zrb/llm/tool/code_constants.py`, `src/zrb/llm/tool/code.py`, `file_list.py`, `file_search.py`): two byte-identical functions under opposite names, now one predicate in `zrb.util.file`.
- **Windows: the default shell is a real POSIX shell** (`src/zrb/config/helper.py`, `src/zrb/util/cmd/command.py`, `src/zrb/task/cmd_task.py`, `src/zrb/llm/ui/default/app/completion/completer.py`, `docs/adr/adr-0095.md` new): `CFG.SHELL` resolved to `pwsh`/`powershell`/`cmd` though nearly everything zrb runs is POSIX. It now prefers Git for Windows' `bash` via memoized `get_windows_posix_shell()` — never `System32\bash.exe`, the WSL launcher — checking Git's prefix, then standard install roots, then PATH outside the Windows directory. Shell settings are compared by `get_shell_name()`, so a path value (`C:\Program Files\Git\bin\bash.exe`) keeps the unrecommended-command lint on and gets the right flag (`-c`, `-Command`, `/c`). Set `ZRB_SHELL` to keep PowerShell. Path completion treats a drive letter or leading `\` as a path start only on Windows.
- **Windows: console detection, headless UI construction and journal links fixed** (`src/zrb/util/cli/terminal.py`, `src/zrb/context/shared_context.py`, `src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/tool/journal_write.py`): `is_tty` was true with stdin redirected from NUL, so `zrb … < NUL` prompted into a void; `is_real_console()` disambiguates with `GetConsoleMode`. `UI(...)` builds its prompt_toolkit `Application` on first access to `application`, so constructing a `UI` no longer raises `NoConsoleScreenBufferError` under Git Bash, mintty or redirected runs. The journal's `## Related` links use forward slashes.
- **Breaking: `UIConfig` is the single UI configuration object** (`src/zrb/llm/ui/ui_config.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/ui/default/app/{layout.py,completion/completer.py}`, `src/zrb/llm/ui/simple_ui_base.py`, `src/zrb/llm/ui/event_driven_ui.py`, `src/zrb/llm/ui/ui_factory.py`, `src/zrb/llm/task/chat/{task,running,execution}.py`, `src/zrb/runner/chat/http_ui.py`, `docs/llm/llm-custom-ui.md`, `docs/task-types/llmchat-task.md`): `BaseUI.__init__` replaced its 16 `*_commands` parameters plus `yolo_xcom_key`, `assistant_name`, `is_yolo` and `conversation_session_name` with one `ui_config: UIConfig | None` (public property); `UI`, `SimpleUI` and `EventDrivenUI` follow. `LLMChatTask` replaced `yolo_xcom_key`, `ui_commands`, `show_ollama_models` and `show_pydantic_ai_models` with the same settable slot, and its `ui_greeting`, `ui_assistant_name`, `ui_jargon` and `ui_ascii_art` parameters (and `LLMChatTask.ui_texts`) moved into `UIConfig` fields defaulting from the same `CFG` knobs, so every UI backend can receive a greeting — pass `ui_config=UIConfig(greeting=...)`. `InputCompleter` (exported from `zrb.llm.ui.default.app.completion`) and `create_input_field` take `ui_config: UIConfig` instead of per-command lists and `show_*_models` toggles. `create_ui_factory`'s keyword is `ui_config=` (was `config=`, which made Level-3 `BaseUI` registrations raise `TypeError`), as are `SimpleUI`/`EventDrivenUI`'s. `UICommands`, `UI_COMMAND_CFG_ATTRS` and `UIConfig.minimal()` are deleted. Command-list defaults come from `CFG` (`ZRB_LLM_UI_COMMAND_*`, `ZRB_LLM_ASSISTANT_NAME`): `exit_commands` gains `/q`, `:q`, `/bye`; `info_commands` gains `/info` and drops `/?`. New `rewind_commands`, `btw_commands` and `voice_commands` fields make `/rewind`, `/btw` and `/voice` work in the `SimpleUI` family. `yolo_xcom_key` defaults to `"yolo"`. `UIConfig.merge_commands` uses `dataclasses.replace`, so it no longer resets non-command fields.
- **Breaking: the UI and approval contracts are ABCs named `AnyUI`/`AnyApprovalChannel`** (`src/zrb/llm/ui/any_ui.py`, `src/zrb/llm/ui/state_defaults.py`, `src/zrb/llm/approval/any_approval_channel.py`, `src/zrb/cmd/any_cmd_val.py`, `src/zrb/llm/ui/any_agent_output.py` new, `src/zrb/llm/tool_call/`, R9): `UIProtocol` (`llm/tool_call/ui_protocol.py`) → `AnyUI` in `llm/ui/any_ui.py` with `ChoiceOption`/`ChoiceSpec`, exported from `zrb`; `ApprovalChannel` → `AnyApprovalChannel` (with `ApprovalContext`/`ApprovalResult`; the `current_approval_channel` `ContextVar` is unchanged); `AnyCmdVal` moved to `any_cmd_val.py`. Both contracts are ABCs, so `SimpleUI`/`EventDrivenUI` subclasses missing an abstract method now fail at instantiation with `TypeError`. `AnyUI` also declares the ten state members callers used to probe with `hasattr` (`is_thinking`, `yolo`, `model`, `llm_task`, `tool_call_handler`, `multi_ui_parent`, `background_tasks`, `invalidate_ui`, `cancel_pending_confirmations`, `flush_to_parent`), with inert defaults in `UIStateDefaultsMixin` (`llm/ui/state_defaults.py`); a third-party UI subclassing `AnyUI` directly must mix it in, while UIs built on `SimpleUI`/`EventDrivenUI`/`BaseUI` are unaffected. `MultiUI.__init__` takes `list[AnyUI]`. `ToolPolicy`, `ArgumentFormatter` and `ResponseHandler` type their `ui` as the narrow `AnyAgentOutput` protocol (`append_to_output`, `ask_user`, `run_interactive_command`), which any `AnyUI` satisfies. Known gap: `LLMTask.uis` lacks the R5 verb set `LLMChatTask.uis` has.
- **Breaking: `PollingUI`, `create_bot_ui_factory()` and `create_http_ui_factory()` are removed from `zrb.llm.ui`** (`src/zrb/llm/ui/polling_ui.py` deleted, `src/zrb/llm/ui/ui_factory.py`, `src/zrb/llm/ui/__init__.py`, `docs/llm/llm-custom-ui.md`): the factories were pass-throughs to `create_ui_factory`, and `zrb.llm.ui.create_http_ui_factory` shadowed the real one in `zrb.runner.chat.http_ui`. `EventDrivenUI` covers `PollingUI`'s queue pattern; the custom-UI ladder is `SimpleUI`/`EventDrivenUI`/`BaseUI`, and its docs, examples and docstrings now match the code (the old guide named six underscore-prefixed members that do not exist, and `BaseUI`'s docstring named a nonexistent `MultiplexerUI`).
- **Fix: slash-command dispatch honors subclass overrides, and `/rewind` is always visible** (`src/zrb/llm/ui/base/commands.py`, `src/zrb/llm/ui/base/conversation_commands.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/default/ui.py`, `docs/llm/llm-custom-ui.md`): the command table bound handlers to internal parts, so an overridden `handle_save_command` never ran when the user typed `/save`; all 15 entries now bind `base_ui.handle_<name>_command`, and the table is public as `command_table` via a new `BaseUI.commands` property. With `LLM_ENABLE_REWIND` off (the default), `/rewind` was hidden from `/help` and completion and typing it sent "/rewind" to the model; it now appears and prints a warning naming `{ENV_PREFIX}_LLM_ENABLE_REWIND` or the session/`LLM_SNAPSHOT_DIR` requirement.
- **Fix: an unbalanced quote in a slash command no longer sends the raw text to the model** (`src/zrb/llm/custom_command/resolver.py`): `resolve_custom_command` catches shlex's `ValueError` and falls back to whitespace splitting, so `/greet "alice` renders `Hello "alice!`.
- **Breaking: uniform mutation verbs and settable component slots on `LLMChatTask`** (`src/zrb/llm/task/chat/task.py`, `docs/task-types/llmchat-task.md`, R5–R8): every ordered collection (tools, tool factories, toolsets, toolset factories, history processors, triggers, custom commands, hook factories, tool policies, response handlers, argument formatters, UIs) has `append_X`/`prepend_X`/`set_X`/`remove_X` (`remove_X` is a no-op on an absent item). Old → new: `set_ui(x)` → `set_uis([x])`; `set_ui_factory(x)` → `ui_factories = [x]`; `set_approval_channel(x)` → `approval_channels = [x]`; `set_history_manager(x)` → `history_manager = x`. `prompt_manager`, `hook_manager`, `llm_limiter` and `markdown_theme` are settable, type-checked properties (wrong type raises `TypeError`), so a `zrb_init.py` can replace one on the built-in `llm_chat`; `tool_confirmation` stays read-only. `has_prompt_manager` is removed (it was always `True`): use `task.prompt_manager`.
- **Breaking: hook and manager API renames** (`src/zrb/llm/hook/{registry,manager}.py`, `src/zrb/llm/skill/manager.py`, `src/zrb/llm/agent/subagent/manager.py`, R6/R7): `HookRegistry.register`/`HookManager.register` → `add_hook`; `HookRegistry.clear_manual()` → `clear()`. `get_search_directories()` is gone from `HookManager`, `SkillManager` and `SubAgentManager` in favor of one `search_dirs` property (override if set, else computed defaults; assigning invalidates a completed scan; now settable on all three). `SubAgentManager.root_dir` → `scan_root`.
