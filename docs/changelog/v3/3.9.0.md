## 3.9.0 (September 27, 2026)

- **Feature: slash commands that run code** (`src/zrb/llm/custom_command/action_command.py`, `src/zrb/llm/custom_command/any_custom_command.py`, `src/zrb/llm/custom_command/resolver.py`, `src/zrb/llm/ui/base/exec_commands.py`, `src/zrb/llm/ui/queue_based_input.py`): `ActionCommand("/name", action)` runs a Python callable and starts no LLM turn; the callable's return value is shown to the user. Underneath, `AnyCustomCommand` gains `handle(kwargs)`: `None` (the default) sends `get_prompt(kwargs)` to the LLM as before, a string handles the command in-process. `run_custom_command` dispatches both kinds and `get_custom_command_match` matches without running anything; the TUI and event-driven UIs use them, and an action command given as the initial `--message` shows its reply and runs no turn. A duck-typed command without `handle` keeps working.
- **Fix: `Stop` command hooks receive the response text** (`src/zrb/llm/hook/interface.py`, `src/zrb/llm/hook/creator.py`, `src/zrb/llm/agent/run/runner.py`): the response lived only in `CLAUDE_EVENT_DATA`, next to the full history, and that variable is dropped once it passes 16 KiB, which a real chat always does; stdin never carried it. `HookContext.last_assistant_message` now carries it on stdin and as `CLAUDE_LAST_ASSISTANT_MESSAGE`.
- **Fix: `PermissionRequest` hooks receive `tool_input`** (`src/zrb/llm/agent/run/deferred_calls.py`): the tool's arguments were only in the event data; they are now the Claude-compatible `tool_input` field, on stdin and as `CLAUDE_TOOL_INPUT`.
- **Feature: voice interaction example** (`examples/voice-interaction/`): `zrb chat` started in that folder reads responses, approval prompts and questions aloud through project-level hooks (`.zrb/hooks.json`; macOS `say`, `espeak-ng`, OpenAI or Gemini TTS, stdlib only; a `0600` side log that never records the spoken text) and listens through `zrb_init.py`: push-to-talk via `/voice`, or hands-free listening toggled by `/handsfree`, which mutes the microphone while the agent speaks. The README records a transcription comparison recommending `ZRB_LLM_VOICE_MODE=openai` with `gpt-4o-transcribe` over the vosk default.
- **Documentation: custom commands and hook payloads** (`docs/task-types/llmchat-task.md`, `docs/llm/hooks.md`): `CustomCommand`, `ActionCommand` and `handle()` are documented with an example, and the hook docs name `last_assistant_message`, `tool_input` on `PermissionRequest`, and the 16 KiB limit on `CLAUDE_EVENT_DATA`.
