## 3.41.4 (November 18, 2026)

- **Refactor: the sandbox-escape argument is read through one helper** (`src/zrb/llm/tool_call/shell_call.py`, `test/llm/tool_call/test_shell_call.py`): the argument formatter, the auto-approve policy, the sandbox gate and the deferred-approval cascade each compared the raw `dangerously_skip_sandbox` argument themselves. ADR-0141 moved that shape into `shell_call.py`, and four readers kept their own copy — one of them in a file that already imported `is_sandbox_off` sixty lines below. All four now call `is_sandbox_off`, and a test fails if the name is typed as a quoted string anywhere else under `src/zrb`. No behaviour change: the same argument is recognized as before.
- **`UIConfig` moves out of the UI package** (`src/zrb/llm/ui/ui_config.py` → `src/zrb/llm/config/ui_config.py`, `test/llm/ui/test_ui_config.py` → `test/llm/config/test_ui_config.py`): the module imports `CFG` and the standard library and nothing from `zrb.llm.ui`, yet it sat in the presentation layer, so `LLMChatTask` — an orchestration-layer task — reached up into `ui/` to type its own `ui_config` slot. It now lives in `llm/config/` beside the other configuration objects, and that upward edge is deleted from `KNOWN_UPWARD_EDGES`. **Importing `zrb.llm.ui.ui_config` directly no longer works; import `zrb.llm.config.ui_config` instead.** `from zrb.llm.ui import UIConfig` is unchanged.
- **A sub-agent's identity is read from a contract, not from the UI class** (`src/zrb/llm/shared/agent_activity.py`, `src/zrb/llm/subagent/parent_message.py`): the "message the main agent" tool asked `isinstance(ui, BufferedUI)` to decide whether the current UI belongs to a delegated sub-agent that has a parent, so the sub-agent package imported the presentation layer to name a class it never used for anything else. `HasActivityTracking` — the read-only protocol `tool/delegate/runner.py` already probes to ask "can this UI feed the activity panel" — now also names `agent_id` and `session_id`, and the tool asks the protocol instead. A UI backend answering those five members is trackable whatever its class is called; one that does not is refused exactly as before.
- **A delegation's buffer comes from the buffer's own module, and `ui/buffered/` is a floor** (`src/zrb/llm/ui/output_chunk.py` → `src/zrb/llm/shared/output_chunk.py`, `src/zrb/llm/ui/tracked_spans.py` → `src/zrb/llm/shared/tracked_spans.py`, `test/architecture/test_llm_layering_ratchet.py`, `test/architecture/test_circular_import_allowlist.py`): `tool/delegate/runner.py` names `BufferedUI` in seven annotations, one `isinstance` probe and two constructions, and `background.py` borrowed the class back from it — so a layer-1 tool reached into the presentation layer, and the borrowing made the two modules import each other, deferred by two `# lazy: circular` workarounds. A registered factory was the other way out, but the UI package loads nothing eagerly, so a delegation would have been the first caller to find that registry empty. The ratchet now scores `ui/buffered/` as a floor, as it already scores `ui/fallback/`, and the two stdlib-only helpers a buffer needs have moved to `llm/shared/` so that everything a buffer imports is L0. With the cycle gone, `background.py` imports the class from its own module, `runner.py` imports the background registry at module level, and both allowlist lines are deleted. **`zrb.llm.ui.output_chunk` and `zrb.llm.ui.tracked_spans` have moved: import them from `zrb.llm.shared`.** No behaviour change.
- **Steering a live run no longer needs the UI package** (`src/zrb/llm/shared/live_delivery.py`, `src/zrb/llm/subagent/live_session.py`, `src/zrb/llm/ui/base/queue_delivery.py`): the "message the chosen sub-agent" path reached into `ui/base/message_queue.py` for `steer_into_live_run`, a twenty-line helper whose only requirement of its argument is an `enqueue` method, so the sub-agent registry imported the presentation layer for a function that never touches a UI. It now lives in `llm/shared/` beside the other L0 leaf helpers; the queue's own send-now path imports it from there too, and the upward edge is deleted from `KNOWN_UPWARD_EDGES`. Its three tests moved to `test/llm/shared/test_live_delivery.py`. No behaviour change.
- **Tool-name resolution moves below the sub-agent package** (`src/zrb/llm/subagent/tool_resolver.py` → `src/zrb/llm/shared/tool_resolver.py`, `test/llm/subagent/test_tool_resolver.py` → `test/llm/shared/test_tool_resolver.py`): the module imports nothing at all — it maps Claude's `Bash` to zrb's `Shell`, reads a tool's registered name, and resolves a name list against a registry and a set of factories — yet it sat in the orchestration layer, so the agent package imported layer three to resolve an agent hook's `tools:`. It now lives in `llm/shared/` beside `tool_registry.py`, and the upward edge is deleted from `KNOWN_UPWARD_EDGES`. **Importing `zrb.llm.subagent.tool_resolver` directly no longer works; import `zrb.llm.shared.tool_resolver` instead.** The architecture pages that name it follow the move. No behaviour change.
- **An interactive chat is presented from the presentation layer** (`src/zrb/llm/task/chat/running.py`, `src/zrb/llm/ui/session.py`, `src/zrb/llm/shared/session_presentation.py`, `src/zrb/llm/shared/feature_config.py`, `src/zrb/builtin/llm/chat.py`): `run_interactive_session` built a UI from the task's own values, replayed the stored conversation onto it, ran its loop and read its display back — and did all of it from the orchestration layer, so `task/chat/running.py` imported `ui/assembly.py`. The one-shot session beside it needs no UI beyond the ones already attached, so the module splits at that line: the interactive half moves to `ui/session.py`, which imports `task/` downward, and `ChatRunning` asks `shared/session_presentation.py` for it. `zrb llm chat` — the only command that offers an interactive chat — registers the runner, as `subagent/manager` registers itself into the delegation facade. `bound_session_ui` moves beside the three functions it wraps in `shared/feature_config.py`, since both halves bind the session's UI. The upward edge is deleted from `KNOWN_UPWARD_EDGES`. No behaviour change for `zrb llm chat`; a task asked to run interactively with no runner registered raises a `RuntimeError` that says so instead of presenting nothing.
