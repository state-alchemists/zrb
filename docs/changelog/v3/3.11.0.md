## 3.11.0 (September 28, 2026)

- **Feature: the status bar shows what the microphone is doing** (`src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/listen.py`, `src/zrb/llm/ui/`, ADR-0102): hands-free dictation shows `🎤 listening`, `🎙️ hearing you…`, `✍️ transcribing…`, `🎤 heard "…"` and `🔇 mic paused while speaking`; push-to-talk shows `🎙️ recording…` and `✍️ transcribing…` in place of the "Listening..." output line. The output was the wrong place: it is held back while an approval is pending mid-turn, when knowing your answer was heard matters most. `listen()` takes `on_state`, called with a `MicState` when the state changes.
- **Breaking: `AnyUI.set_status_badge(key, text)`** (`src/zrb/llm/ui/any_ui.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/multi_ui.py`, `src/zrb/llm/ui/state_defaults.py`, `src/zrb/llm/ui/default/output.py`): shows a feature's one-line state in the status bar; `None` removes it. `BaseUI` stores it in `status_badges` and the default UI draws it; `MultiUI` forwards it; `UIStateDefaultsMixin` ignores it. A class implementing `AnyUI` directly, not through `BaseUI` or the mixin, must add it.
- **Feature: `get_session_ui()`** (`src/zrb/llm/util/feature_config.py`, `src/zrb/llm/task/chat/running.py`): the UI serving the current chat session, bound for the length of a run (the main UI in the terminal, the first attached UI in a non-interactive or web run) and cleared with `close_feature_sessions`. Hooks run with the ambient UI cleared and triggers get no arguments; this is how a feature reaches its session's UI from either.
- **Fix: an answered approval is no longer read aloud** (`src/zrb/llm/speech/feature.py`, `src/zrb/llm/speech/player.py`): the approval request is skipped if it is answered before its turn, and cut off if it is answered while being read. `Speaker.say` takes `is_stale`, checked before playing and every 0.1 s during playback. `BaseUI.is_prompt_answered_since(asked_at)` (implemented by the default UI and `EventDrivenUI`) says whether the first prompt asked after the approval request has ended, so a prompt answered between two checks, or answered from a sub-agent's view out of order, is judged by itself.
- **Fix: OpenAI speech starts sooner** (`src/zrb/llm/speech/backend/openai.py`, `src/zrb/llm/speech/backend/utterance.py`, `src/zrb/llm/speech/backend/http.py`): the audio plays as it arrives, piped into `paplay`, `aplay` or `ffplay`, instead of after the whole file has downloaded; for one short sentence that is 1.3 s instead of 2.4 s, and a longer reply no longer waits longer. A custom `ZRB_LLM_SPEECH_WAV_PLAYER`, or `afplay`, still gets a file. The play timeout and `stop` cover the download as well as playback: `stop` shuts down the connection under a stalled read, and a download that stalls with no `timeout` set gives up after 30 s.
