## 3.7.0 (September 24, 2026)

- **Feature: a terminal without bracketed paste no longer turns a multi-line paste into one LLM turn per line** (`src/zrb/llm/ui/base/message_queue.py`, `src/zrb/config/mixins/llm_ui_runtime.py`, `docs/configuration/llm-config.md`, `test/llm/ui/base/test_message_queue_paste_merge.py`, `test/llm/ui/base/test_message_queue_paste_reflect.py`): such a terminal splits a paste into one submit per Enter keystroke, so each pasted line was enqueued as its own message and the model answered every line separately. `submit_user_message_via_queue` now coalesces a submission that arrives within `CFG.LLM_UI_PASTE_MERGE_WINDOW` (new env knob `ZRB_LLM_UI_PASTE_MERGE_WINDOW`, default `100`, `0` disables) of a still-queued, still-editable message into that message — the pasted block reaches the model as one message. The window rolls forward from each merged line so a long paste's tail stays in the same burst, merging is bounded by an intervening queued `/exec` job (only the newest queue entry may absorb a line), steering into a connected live run outranks merging (and a submission whose steer fails still lands in the same burst), and the model-facing text is preserved exactly — the `QueuedMessage.text` is the raw submissions joined with a newline, with indentation, trailing spaces and intentional blank lines intact.
- **Feature: `AnyUI` gains the echo-splice contract, so any UI with an output buffer redraws edited and merged messages itself** (`src/zrb/llm/ui/any_ui.py`, `src/zrb/llm/ui/state_defaults.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/default/ui.py`, `test/public_api_snapshot.json`): the default TUI's private `_track_echo_span`/`_redraw_echo` hooks are now public `track_echo_span`/`redraw_echo` abstract members of `AnyUI`, implemented by `BaseUI` (a no-op returning `None`, since it has no buffer to splice) and given inert defaults by `UIStateDefaultsMixin` so `StdUI`, `BufferedUI` and `MultiUI` construct unchanged. `QueuedMessage.echo_span`/`echo_text` become a per-target `echo_spans: dict[Any, EchoSpan]` keyed by the UI that owns the buffer, so a `MultiUI` fan-out records one span per child and one child's redraw never invalidates another's. The snapshot picks up the two new contract names.
- **Fix: a queued echo redraw cannot splice into a foreign transcript, and merged Markdown renders as one block instead of a fragment** (`src/zrb/llm/ui/default/message_editing.py`, `src/zrb/llm/ui/default/output.py`, `test/llm/ui/default/test_message_editing.py`, `test/llm/ui/default/test_output_collapse.py`): `redraw_echo` is now the single splice path behind both an edit and a paste merge and re-decides the body from the entry's *current* text, so the two can never draw the message differently. Each echo registers as a re-renderable `RenderedEcho` block (a weak `QueuedMessage` handle plus header/text/`rendered`), and that block — not the `EchoSpan` — is where offsets live, so a terminal resize, re-wrap or collapse keeps them current; `_validated_echo_span` verifies the region still holds the recorded line before splicing, so a shifted or re-wrapped echo falls back to a fresh echo through the target's own output path instead of corrupting the transcript. `UIOutput.set_rendered_block` enforces the two `rendered_blocks` invariants — position order and non-overlap — that a plain `append` broke for a collapsed span or re-registered echo. When a merged paste's combined text turns Markdown, a spliceable target renders the whole message in place of the plain opening echo (a fenced block or list reads as one block); one with nothing to splice gets the merged line verbatim, so a lone fence or bare `- item` never appears as a half-render.
- **Fix: `AskUserQuestion` choice navigation is routed through whichever pane has focus** (`src/zrb/llm/ui/default/keybindings.py`, `src/zrb/llm/ui/default/app/keybinding.py`, `src/zrb/llm/ui/default/app/layout.py`, `src/zrb/llm/ui/default/selection.py`, `test/llm/ui/default/test_keybindings_choice.py`): while a choice widget is active, Up/Down drive it from the output pane or the input pane alike (`move_choice_cursor`), Space activates the current choice, the input field goes read-only (`focus_on_click` off), and viewing a sub-agent supersedes the widget so its live view's Enter routes to the agent confirmation first — the output pane's escape/type-redirect bindings and the input field's history bindings are all gated off while a choice is active. `confirm_choice` is re-typed as an action (void) rather than a probe.
- **Fix: UI construction no longer builds the lazy console-bound `Application`** (`src/zrb/llm/ui/default/ui.py`, `test/llm/ui/default/app/test_layout.py`): `output_field_width` read the application via `getattr(self._ui, "application", None)`, which runs the lazy getter and therefore *builds* the `Application` — the console requirement that getter's docstring promises to defer, breaking a console-less run (e.g. non-TTY Windows). It now checks the new `is_application_built` predicate first, and `_application` is initialized before the parts construct so `layout`/`output` setup sees it defined from the start.
- **Improvement: the TUI status bar is drawn as centered prompt-toolkit fragments instead of HTML** (`src/zrb/llm/ui/default/output.py`, `test/llm/ui/default/test_output_status_bar.py`): the bar is built as `(style, text)` fragment lines (`_model_name`, `_sub_agent`, `_plan`/`_yolo` fragments) centered over the terminal width, so the `LLM_UI_STATUS_*` style fields hold full prompt-toolkit style strings (e.g. `ansired bold`) and runtime strings (model, cwd, git branch) can never break HTML markup. `UIOutput.render_markdown` becomes a public width-aware API (`width` defaults to the current output width, the same call a resize re-wrap uses) as the counterpart to `append_markdown` for the echo-splice caller.
- **Refactor: the chat HTTP surface is split out of the `serve_chat_api` registration closure** (`src/zrb/runner/chat/chat_api_route.py`): the endpoint closures became module-level `_handle_*` helpers (`_require_auth` reusing the `can_access_task` gate on every route, `_read_json_body`, `_handle_list_chat_sessions`, `_handle_upload_chat_attachment`, …), cutting one ~500-line `noqa: C901` function into testable units. An empty or malformed request body now reads as `{}` instead of an unhandled 500, and the upload path reads one byte past the size cap rather than materializing the whole (spooled-to-disk) multipart body so an oversized file is rejected without a full allocation.
- **Tests: LSP and UI coverage reorganized into feature-group files** (`test/llm/lsp/test_server.py`, `test/llm/lsp/{test_server_lifecycle,test_server_operations,test_server_queries,test_manager_query}.py`, `test/llm/ui/base/{test_base_ui_conversation_commands,test_base_ui_surface,test_message_queue_paste_merge,test_message_queue_paste_reflect}.py`, `test/llm/ui/default/{test_keybindings_choice,test_layout,test_message_editing,test_output_collapse}.py`, `test/llm/ui/test_ui_delegators.py`): the old `test_server.py` is split by feature group into lifecycle, operations and query files with new manager-query coverage; the UI suite grows suite-sized tests for the echo-contract surface, paste-merge coalescing and reflection, choice keybindings and message-editing redraw paths.
- **Tests: the architecture ratchets tighten** (`zrb-test.sh`, `test/architecture/test_bool_naming_ratchet.py`, `test/architecture/test_facade_size_budget.py`): the coverage floor rises from 94% to 95% on the full run, the `-> bool` naming debt drops 199 → 197, and the facade budget for `llm/ui/default/ui.py` is raised 653 → 671 for the echo-contract entry points and the hoisted `_application` initialization.
