## 3.14.0 (October 5, 2026)

- **Feature: hands-free hears the room it is in, and stops taking it for the user** (`src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/config.py`, `src/zrb/llm/dictation/backend/vosk.py`, `src/zrb/llm/dictation/backend/builtin.py`, `src/zrb/config/mixins/llm_dictation.py`, `docs/llm/voice-camera.md`, `docs/llm/voice-photo-troubleshooting.md`, `docs/configuration/llm-config.md`, `docs/architecture/3-peripheral-flow/dictation-barge-in.md`, ADR-0105): speech heard while zrb is silent must now be `ZRB_LLM_DICTATION_NOISE_MARGIN` (2) times the quietest the room was heard at over the last three seconds, the same bar the microphone already held speech to over zrb's own voice, fed by every block heard while zrb was silent so a room that never falls quiet is measured at its own level. `ZRB_LLM_DICTATION_MIN_WORDS` (1) is that bar's counterpart for an utterance that interrupts nothing, which `ZRB_LLM_DICTATION_BARGE_IN_MIN_WORDS` only applied while interrupting, so a public place can be made to need more than a single stray word. With the `vosk` backend, `ZRB_LLM_DICTATION_VOSK_CONFIDENCE` (0: off) drops a hands-free transcript whose words vosk heard too faintly on average, from the per-word confidence zrb discarded before; push-to-talk keeps every word. None of these tells a stranger's request from the user's (only a wake word does), so hands-free now says when the microphone opens that without `ZRB_LLM_DICTATION_WAKE_WORDS` everything it hears is taken for the user.
- **Feature: the queued messages are listed above the input, and Ctrl+X drops one** (`src/zrb/llm/ui/default/output.py`, `src/zrb/llm/ui/default/app/layout.py`, `src/zrb/llm/ui/default/message_editing.py`, `src/zrb/llm/ui/default/keybindings.py`, `src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/ui/base/message_queue.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/any_ui.py`, `src/zrb/llm/ui/state_defaults.py`, `docs/llm/llm-integration.md`, `docs/architecture/2-extension-surface/ui.md`, `docs/adr/adr-0077.md`, `test/public_api_snapshot.json`): a message submitted while a turn runs is queued for the next turn and could already be recalled with Up Arrow for editing, but nothing said what was waiting or in what order. `UIOutput.get_queued_messages_text` now lists them oldest-first in a panel docked above the input (the message Up Arrow has recalled marked `▸`, a queue longer than five summarized, each message's first line only), reading `MessageQueue.pending()`, the public seam that lists what is waiting without popping it. `Ctrl+X` drops the recalled message outright instead of editing it: `UIMessageEditing.handle_delete_queued` calls the new `BaseUI.delete_queued_message`, which takes the entry out of the shared queue and has every UI holding an echo splice that line out. `remove_echo` is now the third member of the `AnyUI` echo contract, beside `track_echo_span`/`redraw_echo`, with an inert `UIStateDefaultsMixin` default so non-terminal channels construct unchanged, and both hooks broadcast through one best-effort `_broadcast_echo`. Removal is per UI because each output buffer holds its own echo, so a `MultiUI` sibling would otherwise keep a line for a message that never runs. While a sub-agent's live view is up, the main transcript is parked, so `remove_echo` splices the parked copy, which the view restores. Dropping the line's tracked block with it keeps a later resize from drawing it back, and the input always returns to the pre-recall draft, including when the message's turn started under the recall, so the recalled text cannot be submitted again.
- **Feature: Up Arrow recalls earlier messages, from the loaded conversation and from past sessions** (`src/zrb/llm/ui/default/previous_message_history.py`, `src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/ui/default/message_editing.py`, `src/zrb/config/mixins/llm_content.py`): after the queued messages, Up Arrow in the chat input walks the user messages of the conversation `/load` or `--session` opened, newest first, then the messages submitted in earlier sessions. `PreviousMessageHistory` persists them under `ZRB_LLM_PREVIOUS_MESSAGE_HISTORY_DIR`, capped at `ZRB_LLM_PREVIOUS_MESSAGE_HISTORY_MAX_ENTRIES` (1000; 0 keeps everything), behind a file lock so concurrent sessions do not lose each other's lines; a damaged history file reads as empty, and a failed write is logged, never raised.
- **Feature: `/set <name> <value>` changes any setting for the session** (`src/zrb/llm/ui/base/model_commands.py`, `src/zrb/llm/ui/default/app/completion/args.py`, `src/zrb/config/config.py`, `src/zrb/config/env_field.py`, `src/zrb/config/mixins/llm_ui_commands.py`): both arguments complete — the name from the new `Config.get_settable_field_names()`, the value from known model names, `on`/`off` for a boolean, and the current value — and the value goes through the field's own conversion (`Config.convert_setting_value`), so a list or a boolean round-trips as it reads from the environment. `model`, `small_model` and `multimodal_model` switch the live model the way `/model` does, which still works. An unknown name or a value the field cannot take is reported, not raised, and `/set` is refused while a turn is thinking, like `/model`.
- **Feature: the status bar shows how long zrb has been working, and how long the running tool has taken** (`src/zrb/llm/ui/default/output.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/util/stream_response.py`, `src/zrb/config/mixins/llm_ui_runtime.py`): while a turn runs, the status bar shows the elapsed time of the current working period, reset when zrb stops, and `🧰 <tool> <elapsed>` for the tool call in flight, so a hanging tool is visible and can be killed. Running tools are keyed by call id, so parallel calls keep their own timers, cleared at the end of the run. Both use `time.monotonic()`; `ZRB_LLM_UI_SHOW_RUNTIME_TIMERS=off` hides them.
- **Feature: `EnterWorktree` resumes an existing worktree** (`src/zrb/llm/tool/worktree.py`, `src/zrb/llm/agent/gates.py`): the tool takes `worktree_path`, as `ListWorktrees` reports it, to continue in a linked worktree that is already registered instead of creating one. A path that is not a registered linked worktree, the main worktree, or a path given together with `branch_name` is rejected, the sandbox's path checks apply to it, and the requested subdirectory is kept when resuming.
- **Fix: barge-in holds zrb's voice the moment it is talked over, and the words decide whether it stays held** (`src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/interrupt_judge.py`, `src/zrb/llm/prompt/markdown/barge_in.md`, `src/zrb/config/mixins/llm_dictation.py`, ADR-0105): the hold was taken on the words, so with a transcriber that finishes a sentence at a time (`gpt-4o-transcribe`, or any batch backend) zrb talked through the whole interruption and stopped seconds after the user had finished asking it to. Speech over zrb holds its voice again, before anything about it is known, and what the words ask is answered from them: a stop word said alone is exact, free and final, and anything else that interrupts is put to a small model (`ZRB_LLM_DICTATION_INTERRUPT_JUDGE_MODEL`, else `ZRB_LLM_SMALL_MODEL`), which answers with a typed verdict, `stop` or `ask`, so "please fucking stop", the same stop said twice, or a stop in another language cancels the turn instead of reaching the model as a message. `ZRB_LLM_DICTATION_INTERRUPT_JUDGE_ENABLED=off` leaves the word lists deciding, and they stand when the model is slow, unconfigured or unsure. A hold taken for zrb's own voice is given back with `resume_speech`, as before, and a phrase said twice with a wake word in front is no longer dropped as the transcriber guessing at noise. One small-model call per interrupting utterance, none for a stop word, and none while a tool approval is pending. A judge that fails in any way is logged and leaves the word lists deciding; only cancellation propagates.
- **Breaking: six voice settings retired, and the small model answers what a stop asks** (`src/zrb/config/mixins/llm_dictation.py`, `src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/words.py`, `src/zrb/config/retired.py`, ADR-0105, ADR-0076): `ZRB_LLM_DICTATION_BARGE_IN_ACTION` and the `_TURN_END_TIMEOUT` it alone used are gone: anything said over zrb steers the turn and a stop cancels it, so there is no `cancel` left to configure. `ZRB_LLM_DICTATION_ECHO_COOLDOWN`, `_SELF_ECHO_MATCH` and `_SELF_ECHO_TAIL` are gone: the cooldown made the microphone deaf after zrb stopped speaking, where barge-in holds zrb's own voice by loudness against `ZRB_LLM_DICTATION_BARGE_IN_MARGIN`, and the transcript-level guards were a patch for the same audio-level problem that only caught echo that had already cleared the loudness bar, which `ZRB_LLM_DICTATION_BARGE_IN_MIN_WORDS` and the judge answer anyway. `ZRB_LLM_DICTATION_TRAILING_WORDS` is gone: an utterance ends after `ZRB_LLM_DICTATION_MIN_SILENCE` once it has words, with no end-of-turn word list. `ZRB_LLM_DICTATION_POLITE_WORDS` narrows to approvals: a yes or a no may carry one ("yes please", "no thanks"), a stop may not, so "stop please" is put to the small model rather than matched. `spoken_log`, which only the self-echo guard read, is deleted. A setting still present is reported at startup with what replaced it. The cost is deliberate: with the self-echo guard gone, zrb's own last word can open a turn where it was once dropped, so keep the playback volume down or use headphones, and set `ZRB_LLM_DICTATION_BARGE_IN_MARGIN` higher if it trips.
- **Breaking: speech reads the whole reply, and the four settings that shortened it are gone** (`src/zrb/llm/speech/feature.py`, `src/zrb/llm/speech/streamed_reply.py`, `src/zrb/llm/speech/text.py`, `src/zrb/llm/speech/config.py`, `src/zrb/config/mixins/llm_speech.py`, `src/zrb/config/retired.py`, `src/zrb/llm/prompt/markdown/`, ADR-0103): a reply was read up to `ZRB_LLM_SPEECH_MAX_CHARS` (400) characters (the sentence crossing the limit spoken whole, then "The full answer is on screen.") or, with `ZRB_LLM_SPEECH_SUMMARIZE`, replaced by a small-model summary. Everything is read now: `_MAX_CHARS`, `_SUMMARIZE`, `_SUMMARY_MODEL` and `_ON_SCREEN_NOTE` are retired and reported at startup with what replaced them, `StreamedReply` speaks every sentence, `fit_for_speech` and the `speech_summarizer` prompt file are gone, and `ZRB_LLM_SPEECH_STREAM=off` reads the finished reply whole instead of cutting it at 400 characters.
- **Feature: the captured audio is handed to a Pipecat pipeline, behind a flag** (`src/zrb/llm/dictation/pipecat_input.py`, `src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/teardown.py`, `src/zrb/config/mixins/llm_dictation.py`, `src/zrb/llm/dictation/config.py`, `pyproject.toml`, ADR-0107): stage 1 of the voice migration ([Voice on Pipecat](../../architecture/3-peripheral-flow/voice-on-pipecat.md)). With `ZRB_LLM_DICTATION_PIPECAT_ENABLED=on`, hands-free hands every block the microphone captures to a Pipecat pipeline beside the hand-rolled path, which still decides everything (the pipeline ends at a counter, so what zrb hears and says is unchanged). `listen` gains `on_captured`, fed from a tap of its own filled by the audio callback and drained by a task, so a slow pipeline delays neither capture nor listening; the tap holds at most ten seconds, dropping the oldest, and is drained on close. `AudioPipeline.start`/`push`/`close` own the pipeline for as long as the listening lasts; `start` waits for the transport's `set_transport_ready`, which pipecat's base `start` omits, before a block is pushed. The pipeline is best-effort: one that cannot start, or fails a hand-over, is reported once, closed and not retried; its teardown never raises (`close_quietly`), and a task that will not stop after cancellation is named in the log rather than waited on (`cancel_and_wait`). The sink keeps a count, not the audio. Pipecat (`pipecat-ai>=1.12.0,<1.13.0`) is in the `voice` extra; without it the setting says so and hands-free listens on.
- **Fix: hands-free retries a microphone that will not start, says which device it tried, and can be pointed at another** (`src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/config.py`, `src/zrb/config/mixins/llm_dictation.py`): PortAudio gives the ALSA thread it starts one second to come up and reports `paTimedOut` (`Error starting stream: Wait timed out`, `PaErrorCode -9987`) when it misses, as a WSL2 VM stalling on I/O does, and hands-free ended for the whole session on a stall that was over by the time the call returned. The open is now tried three times, a stream that never started is closed best-effort before the next try, and the failure names the device PortAudio was asked for (its own default, what `sd.default.device` resolves to) together with the new `ZRB_LLM_DICTATION_DEVICE`, which names another by name or by index (`pulse` and `default` on a Linux or WSL machine are not the same microphone).
- **Fix: a yes or a no said with a polite word counts as an answer** (`src/zrb/llm/dictation/words.py`, `src/zrb/llm/dictation/feature.py`): `_is_answer_or_stop` read the stop, approve and deny words as one list through `is_said_alone`, which allows no polite word beside a phrase, so "yes please" and "no thanks" were not answers: with `ZRB_LLM_DICTATION_MIN_WORDS` above two they were dropped as too short before the approval they answer saw them. Stop words stay strict (a stop is one only when said alone, or "stop please" would cancel a turn), and approvals and denials gain the new `is_answer`, the same reading `to_answer` makes of them. `_get_why_not_the_user` loses the utterance it was passed and never read, the last trace of the own-voice check.
- **Fix: a side question answers from the conversation instead of claiming tools it does not have** (`src/zrb/llm/ui/base/exec_commands.py`, `src/zrb/llm/prompt/markdown/side_question.md`, `docs/adr/adr-0106.md`, `test/llm/ui/base/test_commands_shell.py`, `test/llm/prompt/test_prompt_mandates.py`): `/btw`'s agent is built with no tools, which lets it run beside an in-flight turn, yet it was prompted with `llm_task.get_system_prompt()`, the main agent's prompt, whose `workflow` section says to batch independent tool calls and closes on the live skill catalogue to activate with `ActivateSkill`; the history it inherits also keeps every `ToolCallPart` and `ToolReturnPart`. An empty toolset renders nothing (pydantic-ai omits the schemas), so the prompt was the model's only evidence about its capabilities, and side answers narrated tool calls that never ran. The side agent is now prompted from `side_question.md`, loaded through `get_prompt` like the summarizer prompts: the toolset is empty, a tool call may not be emitted or narrated, and a question that needs a file or a command gets one sentence naming what the main conversation would have to do instead. The main prompt never reaches this path. ADR-0106 records the decision, and that Claude Code's `/btw` is tool-less for the same reason.
- **Chore: pyright pinned to 1.1.414** (`pyproject.toml`).
