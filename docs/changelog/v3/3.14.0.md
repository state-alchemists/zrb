## 3.14.0 (October 4, 2026)

- **Feature: hands-free hears the room it is in, and stops taking it for the user** (`src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/config.py`, `src/zrb/llm/dictation/backend/vosk.py`, `src/zrb/llm/dictation/backend/builtin.py`, `src/zrb/config/mixins/llm_dictation.py`, `docs/llm/voice-camera.md`, `docs/llm/voice-photo-troubleshooting.md`, `docs/configuration/llm-config.md`, `docs/architecture/3-peripheral-flow/dictation-barge-in.md`, ADR-0105): speech heard while zrb is silent must now be `ZRB_LLM_DICTATION_NOISE_MARGIN` (2) times the quietest the room was heard at over the last three seconds — the same measure-the-thing-you-compete-with bar the microphone already held speech to over zrb's own voice, fed by every block heard while zrb was silent so a room that never falls quiet is measured at its own level and the bar sits above it. `ZRB_LLM_DICTATION_MIN_WORDS` (1) is that bar's counterpart for an utterance that interrupts nothing, which `ZRB_LLM_DICTATION_BARGE_IN_MIN_WORDS` only ever applied while interrupting, so a public place can be made to need more than a single stray word. With the `vosk` backend, `ZRB_LLM_DICTATION_VOSK_CONFIDENCE` (0: off) drops a hands-free transcript whose words vosk heard too faintly on average, from the per-word confidence zrb discarded before; push-to-talk keeps every word. None of these tells a stranger's request from the user's — only a wake word does — so hands-free now says when the microphone opens that without `ZRB_LLM_DICTATION_WAKE_WORDS` everything it hears is taken for the user.
- **Feature: the queued messages are listed above the input, and Ctrl+X drops one** (`src/zrb/llm/ui/default/output.py`, `src/zrb/llm/ui/default/app/layout.py`, `src/zrb/llm/ui/default/message_editing.py`, `src/zrb/llm/ui/default/keybindings.py`, `src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/ui/base/message_queue.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/any_ui.py`, `src/zrb/llm/ui/state_defaults.py`, `docs/llm/llm-integration.md`, `docs/architecture/2-extension-surface/ui.md`, `docs/adr/adr-0077.md`, `test/public_api_snapshot.json`): a message submitted while a turn runs is queued for the next turn, and could already be recalled with Up Arrow for editing, but nothing said what was waiting or in what order. `UIOutput.get_queued_messages_text` now lists them oldest-first in a panel docked above the input — the message Up Arrow has recalled marked `▸`, a queue longer than five summarized, each message's first line only since the transcript holds the whole of it — reading `MessageQueue.pending()`, the public seam that lists what is waiting without popping it. `Ctrl+X` drops the recalled message outright instead of editing it: `UIMessageEditing.handle_delete_queued` calls the new `BaseUI.delete_queued_message`, which takes the entry out of the shared queue and has every UI holding an echo splice that line out — `remove_echo` is now the third member of the `AnyUI` echo contract, beside `track_echo_span`/`redraw_echo`, with an inert `UIStateDefaultsMixin` default so non-terminal channels construct unchanged, and both hooks broadcast through one best-effort `_broadcast_echo`. Removal is per UI because each output buffer holds its own echo, so a `MultiUI` sibling would otherwise keep a line for a message that never runs. While a sub-agent's live view is up, the main transcript is parked and the pane holds that agent's text, so `remove_echo` splices the parked copy — the text the view restores, where a line left behind would come back on screen. Dropping the line's tracked block with it keeps a later resize from drawing it back, and the input always returns to the pre-recall draft, including when the message's turn started under the recall, so the recalled text cannot be submitted again.
- **Fix: hands-free no longer stutters when it hears zrb's own voice, and holds nothing for it** (`src/zrb/llm/dictation/feature.py`, `docs/llm/voice-camera.md`, `docs/llm/voice-photo-troubleshooting.md`, `docs/configuration/llm-config.md`, `docs/architecture/3-peripheral-flow/dictation-barge-in.md`, ADR-0105): with `ZRB_LLM_DICTATION_WAKE_WORDS` set, zrb's voice is no longer held the moment the microphone hears loud speech over it. Its own voice reaches the microphone too, so a hold taken on loudness alone was released again as soon as the transcript said the words were zrb's — heard as a stutter, with zrb talking on, and the more so the louder the room. The words take the hold now: zrb goes quiet when a wake word is heard in the live words while it speaks (a streaming backend, `vosk`), or when the transcript turns out to be meant for it (every other backend, a moment later). Talk in the room no longer touches playback at all, and a barge-in meant for zrb — a wake word, a stop word, an answer to a prompt — still stops it. Without wake words nothing changes, since loudness is the only signal there is.
