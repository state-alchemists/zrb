## 3.14.0 (October 4, 2026)

- **Feature: hands-free hears the room it is in, and stops taking it for the user** (`src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/config.py`, `src/zrb/llm/dictation/backend/vosk.py`, `src/zrb/llm/dictation/backend/builtin.py`, `src/zrb/config/mixins/llm_dictation.py`, `docs/llm/voice-camera.md`, `docs/llm/voice-photo-troubleshooting.md`, `docs/configuration/llm-config.md`, `docs/architecture/3-peripheral-flow/dictation-barge-in.md`, ADR-0105): speech heard while zrb is silent must now be `ZRB_LLM_DICTATION_NOISE_MARGIN` (2) times the quietest the room was heard at over the last three seconds — the same measure-the-thing-you-compete-with bar the microphone already held speech to over zrb's own voice, fed by every block heard while zrb was silent so a room that never falls quiet is measured at its own level and the bar sits above it. `ZRB_LLM_DICTATION_MIN_WORDS` (1) is that bar's counterpart for an utterance that interrupts nothing, which `ZRB_LLM_DICTATION_BARGE_IN_MIN_WORDS` only ever applied while interrupting, so a public place can be made to need more than a single stray word. With the `vosk` backend, `ZRB_LLM_DICTATION_VOSK_CONFIDENCE` (0: off) drops a hands-free transcript whose words vosk heard too faintly on average, from the per-word confidence zrb discarded before; push-to-talk keeps every word. None of these tells a stranger's request from the user's — only a wake word does — so hands-free now says when the microphone opens that without `ZRB_LLM_DICTATION_WAKE_WORDS` everything it hears is taken for the user.
- **Feature: the queued messages are listed above the input, and Ctrl+X drops one** (`src/zrb/llm/ui/default/output.py`, `src/zrb/llm/ui/default/app/layout.py`, `src/zrb/llm/ui/default/message_editing.py`, `src/zrb/llm/ui/default/keybindings.py`, `src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/ui/base/message_queue.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/any_ui.py`, `src/zrb/llm/ui/state_defaults.py`, `docs/llm/llm-integration.md`, `docs/architecture/2-extension-surface/ui.md`, `docs/adr/adr-0077.md`, `test/public_api_snapshot.json`): a message submitted while a turn runs is queued for the next turn, and could already be recalled with Up Arrow for editing, but nothing said what was waiting or in what order. `UIOutput.get_queued_messages_text` now lists them oldest-first in a panel docked above the input — the message Up Arrow has recalled marked `▸`, a queue longer than five summarized, each message's first line only since the transcript holds the whole of it — reading `MessageQueue.pending()`, the public seam that lists what is waiting without popping it. `Ctrl+X` drops the recalled message outright instead of editing it: `UIMessageEditing.handle_delete_queued` calls the new `BaseUI.delete_queued_message`, which takes the entry out of the shared queue and has every UI holding an echo splice that line out — `remove_echo` is now the third member of the `AnyUI` echo contract, beside `track_echo_span`/`redraw_echo`, with an inert `UIStateDefaultsMixin` default so non-terminal channels construct unchanged, and both hooks broadcast through one best-effort `_broadcast_echo`. Removal is per UI because each output buffer holds its own echo, so a `MultiUI` sibling would otherwise keep a line for a message that never runs. While a sub-agent's live view is up, the main transcript is parked and the pane holds that agent's text, so `remove_echo` splices the parked copy — the text the view restores, where a line left behind would come back on screen. Dropping the line's tracked block with it keeps a later resize from drawing it back, and the input always returns to the pre-recall draft, including when the message's turn started under the recall, so the recalled text cannot be submitted again.
- **Fix: barge-in holds zrb's voice the moment it is talked over, and the words decide whether it stays held** (`src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/interrupt_judge.py`, `src/zrb/llm/prompt/markdown/barge_in.md`, `src/zrb/config/mixins/llm_dictation.py`, ADR-0105): the hold was taken on the words, so with a transcriber that finishes a sentence at a time — `gpt-4o-transcribe`, or any batch backend — zrb talked through the whole interruption and stopped seconds after the user had finished asking it to. Speech over zrb holds its voice again, before anything about it is known, and what the words ask is answered from them: a stop word said alone is exact, free and final, and anything else that interrupts is put to a small model (`ZRB_LLM_DICTATION_INTERRUPT_JUDGE_MODEL`, else `ZRB_LLM_SMALL_MODEL`), which answers with a typed verdict — `stop` or `ask` — so "please fucking stop", the same stop said twice, or a stop in another language cancels the turn instead of reaching the model as a message; `ZRB_LLM_DICTATION_INTERRUPT_JUDGE_ENABLED=off` leaves the word lists deciding, and they stand when the model is slow, unconfigured or unsure. A hold taken for zrb's own voice is given back with `resume_speech`, as before, and a phrase said twice with a wake word in front is no longer dropped as the transcriber guessing at noise — saying stop twice is what someone does when the first one went unheard. One small-model call per interrupting utterance, none for a stop word, and none while a tool approval is pending.
- **Breaking: six voice settings retired, and the small model answers what a stop asks** (`src/zrb/config/mixins/llm_dictation.py`, `src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/words.py`, `src/zrb/config/retired.py`, ADR-0105, ADR-0076): `ZRB_LLM_DICTATION_BARGE_IN_ACTION` and the `_TURN_END_TIMEOUT` it alone used are gone — anything said over zrb steers the turn, and a stop cancels it, so there is no `cancel` left to configure. `ZRB_LLM_DICTATION_ECHO_COOLDOWN`, `_SELF_ECHO_MATCH` and `_SELF_ECHO_TAIL` are gone: the transcript-level guards for zrb's own voice were a patch for an audio-level problem, they only ever caught the echo that had already cleared the loudness bar, and what they caught is what `ZRB_LLM_DICTATION_BARGE_IN_MIN_WORDS` and the judge answer anyway. `ZRB_LLM_DICTATION_TRAILING_WORDS` is gone: an utterance ends after `ZRB_LLM_DICTATION_MIN_SILENCE` once it has words, with no end-of-turn word list. `ZRB_LLM_DICTATION_POLITE_WORDS` narrows to approvals — a yes or a no may carry one ("yes please", "no thanks"), a stop may not, so "stop please" is put to the small model rather than matched. A setting that is still present is reported at startup with what replaced it. The cost is taken deliberately: with the self-echo guard gone, zrb's own last word can open a turn where it was once dropped, so keep the playback volume down or use headphones, and set `ZRB_LLM_DICTATION_BARGE_IN_MARGIN` higher if it trips.
- **Feature: the captured audio is handed to a Pipecat pipeline, behind a flag** (`src/zrb/llm/dictation/pipecat_input.py`, `src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/feature.py`, `src/zrb/config/mixins/llm_dictation.py`, `src/zrb/llm/dictation/config.py`, ADR-0107): stage 1 of the voice migration ([Voice on Pipecat](../architecture/3-peripheral-flow/voice-on-pipecat.md)) lands, and with it the first thing Pipecat does inside zrb. With `ZRB_LLM_DICTATION_PIPECAT_ENABLED=on`, hands-free hands every block the microphone captures to a Pipecat pipeline besides the hand-rolled path — which still decides everything, since the pipeline ends at a counter, so what zrb hears and says is unchanged and the flag cannot break the voice. `listen` gains `on_captured`, awaited with each block as it is read, as the 16 kHz mono 16-bit PCM `push_audio` takes; `AudioPipeline.start`/`push`/`close` own the pipeline and the task driving it for exactly as long as the listening lasts, on the loop the chat session already runs; and a frame pushed before the transport has processed its `StartFrame` has nowhere to go, so `start` waits for the transport's own `set_transport_ready` (the call pipecat's base `start` omits, and the reason the subclass exists) before it returns. Pipecat stays the `voice` extra: an install without it is a setting that says so and listens on, not a broken run.
- **Fix: a judge that cannot answer leaves the word lists deciding, whatever went wrong** (`src/zrb/llm/dictation/interrupt_judge.py`, `src/zrb/llm/ui/base/system_info.py`, ADR-0105): `judge_barge_in` promised never to raise, but caught only pydantic-ai's own errors, its own timeout and `OSError` — so anything else (a model zrb cannot turn into a provider, an adapter mismatch raising `TypeError`) reached the dictation loop's outer handler, which stops hands-free for the session, instead of falling back to the word lists as documented. It now contains every failure at all and logs it, and re-raises cancellation, since a cancelled turn is not a judge that failed. Containing everything costs one of the 314 swallowed broad `except` handlers the architecture ratchet allows; that was paid in the same change by narrowing `communicate_or_reap`'s best-effort `proc.kill()` to `OSError`, which is all `Popen.kill` can raise.
- **Fix: hands-free retries a microphone that will not start, says which device it tried, and can be pointed at another** (`src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/config.py`, `src/zrb/config/mixins/llm_dictation.py`): PortAudio gives the ALSA thread it starts one second to come up and reports `paTimedOut` (`Error starting stream: Wait timed out`, `PaErrorCode -9987`) when it misses, which a WSL2 VM stalling on I/O does — and hands-free ended for the whole session on a stall that was over by the time the call returned. The open is now tried three times before it is given up on, a stream that never started is closed before the next try is made, and the failure names the device PortAudio was asked for (its own default, what `sd.default.device` resolves to) together with the new `ZRB_LLM_DICTATION_DEVICE`, which names another — `pulse` and `default` on a Linux or WSL machine are not the same microphone, and which of them is opened is the usual difference between one that starts and one that times out.
- **Breaking: speech reads the whole reply, and the four settings that shortened it are gone** (`src/zrb/llm/speech/feature.py`, `src/zrb/llm/speech/streamed_reply.py`, `src/zrb/llm/speech/text.py`, `src/zrb/llm/speech/config.py`, `src/zrb/config/mixins/llm_speech.py`, `src/zrb/config/retired.py`, `src/zrb/llm/prompt/markdown/`, ADR-0103): a reply was read up to `ZRB_LLM_SPEECH_MAX_CHARS` (400) characters — the sentence crossing the limit spoken whole, then "The full answer is on screen." once the next sentence showed something had been left unsaid — or, with `ZRB_LLM_SPEECH_SUMMARIZE`, replaced by a small-model summary. Everything is read now: `_MAX_CHARS`, `_SUMMARIZE`, `_SUMMARY_MODEL` and `_ON_SCREEN_NOTE` are retired and reported at startup with what replaced them, `StreamedReply` speaks every sentence and says nothing about caps, `fit_for_speech` and the `speech_summarizer` prompt file are gone, and `ZRB_LLM_SPEECH_STREAM=off` reads the finished reply whole instead of cutting it at 400 characters.
- **Fix: a microphone that will not start is closed best-effort, and the dead record behind the retired echo guard is gone** (`src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/teardown.py`, `src/zrb/llm/speech/player.py`, `src/zrb/llm/speech/spoken_log.py`, `src/zrb/config/retired.py`): `_open_microphone` closed the stream that never started from inside its own `except`, so a `close()` that raised — sounddevice's `ignore_errors` default swallows PortAudio's own errors, and was the only thing that ever did — took the retry with it, and the message naming the device. It goes through `close_quietly` now, which the abandoned transcription stream and the Pipecat pipeline already used, and which takes a sync closer as well as an async one. `spoken_log` is deleted: the transcript-level guard it existed for was retired in 3.14.0 and nothing has read it since, so the module, its writes in `Speaker` — and the `_ready` queue's `text`, which they were the only use of — and their tests are gone, with the architecture pages and ADR-0107 no longer describing it.
- **Fix: a Pipecat teardown that fails no longer ends hands-free, and the guide stops promising a badge for zrb's own voice** (`src/zrb/llm/dictation/pipecat_input.py`, `src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/teardown.py`, `docs/llm/voice-camera.md`, `docs/adr/adr-0105.md`, `docs/architecture/3-peripheral-flow/voice-on-pipecat.md`, `docs/architecture/3-peripheral-flow/dictation-barge-in.md`): `AudioPipeline.close` promises never to raise, but it awaited `worker.cancel()` directly — that ask travels over the worker's bus, and a pipeline already in trouble can fail it — and `_listen` awaited the close in its `finally` without containing it, so a failure there reached the dictation loop's outer handler and switched hands-free off for the session. Both ends close best-effort now, through one `close_quietly` that logs what failed instead of raising it, and a cancel that does not go through is followed by cancelling the task driving the pipeline outright: the teardown leaves nothing running either way. That helper also closes a transcription stream that was given up on, replacing the copy of the pattern in `feature.py`. The voice guide, meanwhile, still documented the `🎤 ignored "…" (Zrb's own voice)` badge and the transcript-level own-voice check behind it, both retired in 3.14.0 with the self-echo guards — the row is gone, and the page now says outright that the words heard are never compared against what zrb was saying.
- **Fix: the capture is handed to the Pipecat pipeline as it is captured, not as the listening reads it** (`src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/feature.py`, `test/llm/dictation/test_listen.py`, `docs/architecture/3-peripheral-flow/voice-on-pipecat.md`): `on_captured` was called from the loop that reads utterances, so the hand-off stopped for as long as an utterance took to transcribe and answer — the pipeline received the capture a turn late, and once `ZRB_LLM_DICTATION_MAX_BACKLOG` filled the backlog dropped blocks the hand-off never saw, where what stage 1 promises is every captured block. `listen` feeds a tap of its own now, filled by the audio callback beside the backlog and drained by a task, bounded at ten seconds of capture with the oldest dropped when it falls further behind than that, and drained on close so the last blocks of a listening are not lost. A hand-over that raises ends the tap for the rest of the listening and is reported once, rather than ending the listening with it, since the pipeline decides nothing yet.
- **Fix: the Pipecat sink counts and holds nothing** (`src/zrb/llm/dictation/pipecat_input.py`, `test/llm/dictation/test_pipecat_input.py`): `AudioCounter` appended every `InputAudioRawFrame` and summed them for `bytes_received`, so a hands-free session running for hours grew by the whole of its own audio, block by block, until the process died. It keeps `frame_count` and a running `bytes_received` — stage 1's exit criterion is a count, and no production code read anything else — and the frames it held for inspection are gone. What it proves is unchanged: fifty blocks pushed from outside are all counted at the sink, byte for byte.
- **Fix: a yes or a no said with a polite word counts as an answer** (`src/zrb/llm/dictation/words.py`, `src/zrb/llm/dictation/feature.py`): `_is_answer_or_stop` read the stop, approve and deny words as one list through `is_said_alone`, which allows no polite word beside a phrase, so "yes please" and "no thanks" were not answers at all: with `ZRB_LLM_DICTATION_MIN_WORDS` above two they were dropped as too short before the approval they answer ever saw them. Stop words stay strict — a stop is one only when it is said alone, or "stop please" would cancel a turn — and approvals and denials gain the new `is_answer`, the same reading `to_answer` makes of them, so the two agree on what an answer is. `_get_why_not_the_user` loses the utterance it was passed and never read, the last trace of the own-voice check that used to need it.

- **Fix: a side question answers from the conversation instead of claiming tools it does not have** (`src/zrb/llm/ui/base/exec_commands.py`, `src/zrb/llm/prompt/markdown/side_question.md`, `docs/adr/adr-0106.md`, `test/llm/ui/base/test_commands_shell.py`, `test/llm/prompt/test_prompt_mandates.py`): `/btw`'s agent is built with no tools — that is what lets it run beside an in-flight turn — yet it was prompted with `llm_task.get_system_prompt()`, the main agent's own prompt, whose `workflow` section says to batch independent tool calls and closes on the live skill catalogue to activate with `ActivateSkill`; the history it inherits keeps every `ToolCallPart` and `ToolReturnPart` (only the system-prompt parts were stripped), so the side agent also read its own earlier turns where it had grepped and edited. An empty toolset renders nothing — pydantic-ai simply omits the schemas — so the prompt was the model's only evidence about its own capabilities, and side answers narrated tool calls that never ran. The side agent is now prompted from `side_question.md`, loaded through `get_prompt` like the summarizer prompts: the toolset is empty, a tool call may not be emitted or narrated, and a question that needs a file or a command gets one sentence naming what the main conversation would have to do instead. The main prompt never reaches this path. ADR-0106 records the decision, and that Claude Code's `/btw` is tool-less for the same reason — tools arrive there only through an explicit fork into a subagent.
- **Fix: `ZRB_LLM_DICTATION_DEVICE` opens the device its index names** (`src/zrb/llm/dictation/listen.py`, `src/zrb/config/mixins/llm_dictation.py`, `docs/configuration/llm-config.md`): the setting is documented as a name or an index, but its value is a string and `sounddevice` reads a string as a name to match among the devices it finds — so "2" was searched for as a name, matched nothing, and the documented index selection never opened a device (PR #561 review). It is read as the index it is before PortAudio sees it now, a non-numeric value passes through as the name it is, and empty or unset stays PortAudio's own default.
- **Fix: a Pipecat pipeline whose hand-over fails is closed instead of left running** (`src/zrb/llm/dictation/feature.py`): when a captured block could not be pushed, the session marked the pipeline abandoned and gave up on it — but left it running, holding its worker and its transport for the rest of a hands-free listening that can last hours, while reporting that it had stopped (PR #561 review). It is detached and closed there and then, through the same best-effort teardown the listening's own end uses, and no other is opened for the session. Closing it cannot deadlock the hand-over: what is closed is the Pipecat pipeline, never the tap delivering the block.
