## 3.23.0 (October 17, 2026)

- **Feature: pasting file paths attaches the files** (`src/zrb/llm/ui/default/keybindings.py`, `src/zrb/llm/util/attachment.py`): a paste that is only file paths now attaches each file to the next message, as `/attach` does, instead of typing the paths. This covers iTerm2's "Save to Temp File and Paste Path" for a clipboard image and files dragged into the terminal; quoted, backslash-escaped and `file://` paths are understood, several to a paste. An image is read at paste time, so a cleaned-up temp file is no loss. Any other paste, a path inside a sentence, or a path to a text file (`.md`, `.txt`, `.csv`, `.html`) is still inserted as text.
- **Fix: an Ollama model with a tag was taken for text-only** (`src/zrb/llm/util/capabilities.py`): the capability lookup stripped a model object's name up to its first colon, so `deepseek-v4.1-flash:cloud` was looked up as `cloud`. Every image was then sent to `LLM_MULTIMODAL_MODEL` for a text description first, which added seconds to minutes to the turn, or dropped when none was set. Any tagged Ollama model (`qwen3-vl:8b`, `llama3.2-vision:11b`) was affected.
- **Fix: an image was counted as hundreds of thousands of tokens** (`src/zrb/llm/config/limiter.py`): the token estimate counted an attachment's raw bytes as text, so a 333 KB screenshot came to ~240k tokens. The turn could then drop the whole conversation history to fit the context window and wait out the per-minute token budget. A binary attachment now counts as `ATTACHMENT_TOKEN_ESTIMATE` (1,600 tokens), whatever its size.
- **Fix: an image in a saved conversation became text** (`src/zrb/llm/history_manager/file_history_manager.py`): saving history flattened any user prompt with an attachment into one string, the image's base64 included. From the next turn on, the model got ~450k characters of base64 instead of the image. Attachments pydantic-ai can load back (`binary`, `image-url`, and the other `UserContent` kinds) are now kept; only unrecognized items are still flattened.
- **Fix: a request over the whole per-minute token budget waited forever** (`src/zrb/llm/config/limiter.py`): "Rate Limit reached … Waiting 1.0s" repeated with no end, because the request could never fit. It now waits until the minute's window is empty, then goes. A budget of 0 still blocks everything.
- **Improvement: quitting the chat waits on hooks for one short budget** (`src/zrb/llm/task/chat/execution.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/config/mixins/hooks.py`): the waits at exit each had their own limit and ran one after another, so one slow synchronous SessionEnd hook could hold the terminal for its own timeout (600 s for a command hook). SessionEnd and the detached (`async`) hooks now share `ZRB_HOOKS_EXIT_TIMEOUT`, whose default drops from 10000 to 2000 ms. An agent hook, such as the journal-compliance judge, still gets its own timeout. `HookManager.shutdown` gains `drain_seconds`.
- **Fix: the emotion model asked Hugging Face for its files on every start** (`src/zrb/llm/dictation/emotion.py`, `src/zrb/llm/dictation/hub.py`): with `LLM_DICTATION_DETECT_EMOTION` on, each `zrb llm chat` printed "Fetching 9 files" and contacted the Hub even with emotion2vec+ already cached, and without a network it waited for the request to fail. The cached copy is now used first, as `sensevoice` already did, and a download happens only when nothing is cached. Both share one helper.
- **Fix: a model's loading line never said it had loaded** (`src/zrb/llm/dictation/load_report.py`, `src/zrb/llm/dictation/feature.py`): "Loading the sensevoice model…", "Loading the emotion model…" and the other transcribers' loading lines were never followed by anything. Each is now followed by `✅ <name> ready`, or `❗ <name> failed to load: <reason>`, as the initial workspace snapshot's line is. vosk's separate "Voice model ready" line is replaced by the same mark.
- **Feature: the chat can capture your screen** (`src/zrb/llm/screenshot/`, `src/zrb/config/mixins/llm_screenshot.py`, `src/zrb/builtin/llm/chat.py`, `docs/llm/voice-camera.md`, `docs/adr/adr-0113.md`): `/screenshot [display]` (or `/ss`) attached a capture of the screen to the next message, scaled like a pasted image. It used `screencapture` on macOS, Pillow or PowerShell on Windows, `powershell.exe` on WSL, `grim`/`gnome-screenshot`/`spectacle` on Wayland, and Pillow/`scrot`/`import` on X11; a failure said what to install or which permission to grant. In the web chat or on Telegram the command refused, since it would capture the server's screen, not the user's. With `ZRB_LLM_SCREENSHOT_ENABLE_TOOL=on` (default off) the agent also got a `TakeScreenshot` tool, tagged `EXECUTE` so every capture asks for approval. `enable_screenshot(chat, ScreenshotConfig(...))` switched the command and the tool on or off separately.
- **Feature: `Read` shows the model an image file** (`src/zrb/llm/tool/file_read.py`, `src/zrb/llm/agent/run/multimodal_describe.py`, `src/zrb/llm/util/image_scale.py`, `src/zrb/config/mixins/llm_limits.py`): reading a PNG, JPEG, GIF or WebP file now attaches the image to the tool result, scaled as `/attach` scales it, instead of a "binary file" error. A text-only model gets a description from `LLM_MULTIMODAL_MODEL`, or is told to ask for one. An oversized, mislabelled or undecodable image is refused with a hint. An image over 40M pixels is refused before decoding, by `Read`, `/attach`, a pasted path and Ctrl+V alike; a large JPEG is decoded at reduced scale and still fits. `LLM_ENABLE_READ_IMAGE` (default on) turns the feature off. `read_file` is now async.
- **Performance: `import zrb` no longer loads the agent stack** (`src/zrb/__init__.py`, `src/zrb/__main__.py`, `test/architecture/test_facade_import_cost.py`): every public export now resolves through a PEP 562 `__getattr__`, so importing the package loads no `zrb.*` submodule. `import zrb` fell from ~0.52 s to ~0.04 s, and `from zrb import CFG` from ~0.51 s to ~0.13 s — the ~0.53 s that every import spent inside `zrb.builtin`, where `llm_chat` pulls pydantic and pydantic-ai. The one eager side effect that had to move, `zrb.builtin` registering the built-in tasks on `cli`, now rides on `zrb.__main__`, so `zrb --help` and every command behave as before. A test pins both halves, because each fails silently on its own: a slow import nobody attributes to zrb, and a `zrb --help` missing every built-in task with exit code 0.
