## 3.23.0 (October 17, 2026)

- **Feature: pasting file paths attaches the files** (`src/zrb/llm/ui/default/keybindings.py`, `src/zrb/llm/util/attachment.py`): a paste that is only file paths now attaches each file to the next message, as `/attach` does, instead of typing the paths. This covers iTerm2's "Save to Temp File and Paste Path" for a clipboard image and files dragged into the terminal; quoted, backslash-escaped and `file://` paths are understood, several to a paste. An image is read at paste time, so a cleaned-up temp file is no loss. Any other paste, a path inside a sentence, or a path to a text file (`.md`, `.txt`, `.csv`, `.html`) is still inserted as text.
- **Fix: an Ollama model with a tag was taken for text-only** (`src/zrb/llm/util/capabilities.py`): the capability lookup stripped a model object's name up to its first colon, so `deepseek-v4.1-flash:cloud` was looked up as `cloud`. Every image was then sent to `LLM_MULTIMODAL_MODEL` for a text description first, which added seconds to minutes to the turn, or dropped when none was set. Any tagged Ollama model (`qwen3-vl:8b`, `llama3.2-vision:11b`) was affected.
- **Fix: an image was counted as hundreds of thousands of tokens** (`src/zrb/llm/config/limiter.py`): the token estimate counted an attachment's raw bytes as text, so a 333 KB screenshot came to ~240k tokens. The turn could then drop the whole conversation history to fit the context window and wait out the per-minute token budget. A binary attachment now counts as `ATTACHMENT_TOKEN_ESTIMATE` (1,600 tokens), whatever its size.
- **Fix: an image in a saved conversation became text** (`src/zrb/llm/history_manager/file_history_manager.py`): saving history flattened any user prompt with an attachment into one string, the image's base64 included. From the next turn on, the model got ~450k characters of base64 instead of the image. Attachments pydantic-ai can load back (`binary`, `image-url`, and the other `UserContent` kinds) are now kept; only unrecognized items are still flattened.
- **Fix: a request over the whole per-minute token budget waited forever** (`src/zrb/llm/config/limiter.py`): "Rate Limit reached … Waiting 1.0s" repeated with no end, because the request could never fit. It now waits until the minute's window is empty, then goes. A budget of 0 still blocks everything.
- **Improvement: quitting the chat waits on hooks for one short budget** (`src/zrb/llm/task/chat/execution.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/config/mixins/hooks.py`): the waits at exit each had their own limit and ran one after another, so one slow synchronous SessionEnd hook could hold the terminal for its own timeout (600 s for a command hook). SessionEnd and the detached (`async`) hooks now share `ZRB_HOOKS_EXIT_TIMEOUT`, whose default drops from 10000 to 2000 ms. An agent hook, such as the journal-compliance judge, still gets its own timeout. `HookManager.shutdown` gains `drain_seconds`.
- **Feature: the chat can capture your screen** (`src/zrb/llm/screenshot/`, `src/zrb/config/mixins/llm_screenshot.py`, `src/zrb/builtin/llm/chat.py`, `docs/llm/voice-camera.md`, `docs/adr/adr-0113.md`): `/screenshot [display]` (or `/ss`) attached a capture of the screen to the next message, scaled like a pasted image. It used `screencapture` on macOS, Pillow or PowerShell on Windows, `powershell.exe` on WSL, `grim`/`gnome-screenshot`/`spectacle` on Wayland, and Pillow/`scrot`/`import` on X11; a failure said what to install or which permission to grant. With `ZRB_LLM_SCREENSHOT_ENABLE_TOOL=on` (default off) the agent also got a `TakeScreenshot` tool, tagged `EXECUTE` so every capture asks for approval. `enable_screenshot(chat, ScreenshotConfig(...))` switched the command and the tool on or off separately.
