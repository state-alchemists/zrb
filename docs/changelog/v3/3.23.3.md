## 3.23.3 (October 20, 2026)

- **Fix: a reply's emotion voice lasted only until its first tool round** (`src/zrb/llm/emotion/reply.py`, `src/zrb/llm/emotion/feature.py`): Present since 3.22.0. `ReplyEmotion` read the leading emoji once per run and set `current_reply_emotion` to `""` when a run's text opened with none, so the first round after a tool call dropped the reply's emotion and speech fell back to `LLM_SPEECH_VOICE` for the rest of the turn. A run that opens without an emoji now leaves the emotion alone, and `EmotionSession` clears it once per turn, as the turn's first stream starts, so a reply still never inherits the last turn's emotion.
- **Fix: a speech service that died while the local voice spoke was never rebuilt** (`src/zrb/llm/speech/player.py`): Present since 3.23.2. The three-failures-in-a-row counter reset on every successful render, the player program's included, so a dead Pipecat service never reached the count while the fallback spoke the sentences, `restart_backends()` never dropped it, and the local voice kept the rest of the session. The streak now belongs to one backend: only its own successful render clears it, and another backend speaking says nothing about it.
- **Fix: an output device that failed to open was given up on for the rest of the session** (`src/zrb/llm/speech/player.py`, `src/zrb/llm/speech/pcm_player.py`): Present since 3.12.0. One failed open — a headset handed over, a device still busy — set a flag that nothing cleared, so every later sentence went to a player program until zrb restarted, taking the emotion voice with it. A failure now records when it happened: sentences stay off the device for 3 seconds, then one tries it again, and the warning says so once. `PcmUtterance` asks just before it opens the device, so a sentence prepared before the failure and played during the cooldown goes to the player program too.
