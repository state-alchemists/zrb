## 3.1.0 (September 12, 2026)

- **Reliability: the initial readiness wait is bounded by default** (`src/zrb/task/base/execution.py`, `src/zrb/task/base/base_task.py`, `src/zrb/config/mixins/task_runtime.py`, `src/zrb/task/{cmd_task,rsync_task,scaffolder,scheduler,base_trigger,make_task}.py`, `test/task/base/test_execution_readiness.py`, `docs/core-concepts/make-task.md`): a task whose readiness check never succeeded waited forever with no output — measured at 180s and still running against a `TcpCheck` on a closed port — so a hung health check held a CI job indefinitely. Neither knob bounded that wait: `readiness_timeout` defaulted to `60` but was read only by the `monitor_readiness` re-check loop in `monitoring.py`, while the initial wait in `execution.py` read `CFG.TASK_READINESS_TIMEOUT`, default `0` ("no cap"); 2.50.0 documented the split rather than closing it. Both paths now read `task.readiness_timeout`, whose default moved into `ZRB_TASK_READINESS_TIMEOUT` (now `60000` ms, was `0`); the constructor parameter defaults to `None` across all nine task classes — `BaseTask`, `CmdTask`, `RsyncTask`, `Scaffolder`, `Scheduler`, `BaseTrigger`, `make_task`, `LLMTask` and `LLMChatTask` — so the environment variable is a real global default, not shadowed by a re-declared `60`. An explicit `0` or negative value still removes the cap. **Breaking:** a readiness check that never completes now fails its task after 60s instead of hanging; set `ZRB_TASK_READINESS_TIMEOUT=0` to restore the unbounded behavior.
- **Security: `zrb server start` refuses an unsecured non-loopback bind** (`src/zrb/runner/cli.py`, `test/runner/test_cli.py`, `docs/advanced-topics/web-ui.md`): binding beyond `127.0.0.1` publishes task execution — arbitrary command execution — to anyone who can route to the host, and `_warn_if_insecure_bind` only warned ("Warn (never refuse)") before starting, so `ZRB_WEB_HTTP_HOST=0.0.0.0` served on the documented `admin`/`admin` credentials and `zrb` signing key. `_refuse_insecure_bind` now exits `1` before the app is built when a non-loopback bind has authentication off or still carries the default `WEB_SUPER_ADMIN_PASSWORD` or `WEB_SECRET_KEY`, naming the offending knobs and the two supported fixes. It inspects the effective `WebAuthConfig`, so programmatic overrides are honored; because that config treats only `None` as "fall back to CFG", an explicitly empty password is a real override that would pass a mere changed-from-default check. Credentials are therefore validated, not compared: empty or whitespace-only is rejected, as is anything below 12 characters for `WEB_SUPER_ADMIN_PASSWORD` or 32 for the JWT-signing `WEB_SECRET_KEY`, and every failing requirement is listed in one message rather than one restart at a time. Loopback is decided by parsing the address (`ipaddress.ip_address().is_loopback`) rather than matching three strings, so `127.0.0.2` and the expanded `0:0:0:0:0:0:0:1` are recognised; a hostname that cannot be proven loopback-only fails closed. There is deliberately no override flag. **Breaking:** an existing unauthenticated public deployment stops starting until auth is enabled with unique credentials or the bind moves back to loopback.
- **Fix: `SystemExit` from an action body is no longer retried as a task failure** (`src/zrb/task/base/execution.py`, `test/task/base/test_execution_task_chain.py`): the retry loop passed `CancelledError`, `KeyboardInterrupt` and `GeneratorExit` through, but `SystemExit` fell into the generic `except BaseException`, so a deliberate `sys.exit(1)` was logged as `Attempt 1/N failed: 1` (the exit *code* where the error message goes), retried up to `retries` times, and marked permanently failed. It now joins the passthrough tuple, which lets the refused-bind message above read cleanly.
- **Tests: `./zrb-test.sh` is hermetic** (`zrb-test.sh`): coverage fragments landed in the repo root as gitignored `.coverage.*` files, one per xdist worker, and pytest-cov combined whatever it found, so an interrupted or concurrent run could fail the command with `Can't combine branch coverage data with statement data` *after* the tests passed. The script now points `COVERAGE_FILE` at a per-run temporary directory removed on exit; fragments are written and combined there, and anything left in the repo root by an older run or another tool is ignored rather than deleted. `--cov-report=html` still writes to the shared `./htmlcov` so the report stays at a predictable path.
