## 3.8.1 (September 26, 2026)

- **Fix: journal writes lock on Windows too** (`src/zrb/llm/tool/journal_write.py`): the journal's multi-file write lock was a hand-rolled `fcntl.flock` that silently did nothing on Windows, so concurrent writers there (a sub-agent and the main session, or the compliance judge) could lose an update. It now uses `util/file_lock.hold_file_lock`, the lock the snapshot store already uses, on every platform.
- **Fix: constructor docs agree with the code** (`src/zrb/llm/task/llm_task.py`, `src/zrb/llm/task/chat/task.py`, `test/architecture/test_constructor_surface.py`): `LLMTask`'s `hook_manager` was documented as defaulting to a task-local manager; it defaults to the process-wide `hook_manager`. Six other parameters shared by `LLMTask` and `LLMChatTask` had drifted to shorter or different wording and now match; a new test fails when a shared parameter's docs diverge without a recorded reason.
- **Improvement: truncated previews stay within their limit** (`src/zrb/llm/agent/run/history_utils.py`, `src/zrb/llm/agent/run/partial_run.py`, `src/zrb/llm/tool/file_edit.py`): sanitized-history tool results, failed-attempt summaries and `Edit`'s not-found message used hand-rolled `text[:n] + "..."` (n + 3 characters); they now share `util/truncate.truncate_display`, which caps at n including the ellipsis.
- **Refactor: `get_truncated_event_part_args` and `get_full_event_part_args` are one function** (`src/zrb/llm/util/stream_response.py`): the internal pair is now `get_event_part_args(event, full=False)`; neither was part of the public API.
- **Refactor: duplicated logic consolidated** (`src/zrb/llm/util/layered_registry.py`, `src/zrb/llm/ui/tracked_spans.py`, `src/zrb/llm/util/roster.py` new): `SkillRegistry` and `SubAgentRegistry` were the same 153-line class under two names and now compose one `LayeredRegistry` (public API unchanged); `BufferedUI` and `UIOutput` share span and collapsible-block tracking through `TrackedSpans`; streamed thinking and response blocks share one `StreamedBlock`; the six capped "+N more" listings and two search tools share `cap_items`/`search_roster`; plus `get_first_heading` (`util/markdown.py`, 4 copies, now CommonMark-aware: a `# ` line in an indented or fenced code block is not a heading), `render_indented_diff` (2 argument formatters), `create_combined_ui` (`llm/ui/multi_ui.py`), `get_install_packages_cmd` (3 setup helpers), `BROWSER_USER_AGENT` (4 copies), `resolve_real` (sandbox), `suggest_name` (3 direct `difflib` calls), the hook loader's directory walk (now `scan_files`), and `HTTPUI.run_async` (now the base method with `propagates_cancellation`).
- **Documentation: docs match the gates, and internals leave the contributor path** (`AGENTS.md`, `docs/`): the documented coverage floor is 95% (what `zrb-test.sh` enforces; four places said 94%) and ADR-0097's complexity limits are the enforced 15/15. The maintainer guide's context-propagation and history-sanitization internals moved to `docs/technical-specs/`, voice/photo troubleshooting to its own page, and journal, hooks and prompt configuration each have one canonical page. `3.0.0.md` and the 2.62/2.65/2.67 range files were compacted per the changelog rule, and ADR-0101, 0100 and 0055 were tightened (ADR-0101 6,570 → 3,390 words).
- **Fix: Ctrl+C and SIGTERM stop a run the way the shell expects** (`src/zrb/__main__.py`, `src/zrb/runner/cli.py`, `test/test_main_process.py`, `docs/advanced-topics/ci-cd.md`): an interrupted run exited `0`, so `zrb build && zrb deploy` deployed after Ctrl+C; it now exits `130`. `SIGTERM` (sent by `docker stop`, systemd and CI cancellation) killed zrb outright and left its running command orphaned; it now takes Ctrl+C's cancellation path, stops the command and exits `143`. `Task.run()` still returns `None` on interrupt for library callers. A stopped long-running task (`docker stop`, `systemctl stop`) now reports `143` rather than `0`; a systemd unit that should treat that as a clean stop needs `SuccessExitStatus=143`. New process-level tests run `python -m zrb` and check exit codes, child cleanup and output streams; the signal and colour tests fail against 3.8.0.
- **Fix: color follows `NO_COLOR` and the terminal** (`src/zrb/util/cli/style.py`): every styled string carried ANSI codes, even into pipes, files and CI logs, and with `NO_COLOR` set. Styling is now off when neither stdout nor stderr is a terminal; any non-empty `NO_COLOR` disables it and `FORCE_COLOR` enables it (`is_color_enabled`).
- **Fix: `OptionInput` rejects a value outside its `options` from every source** (`src/zrb/input/option_input.py`): the interactive prompt already refused one, but `--role admin` was accepted as-is. It now fails naming the allowed values, so a caller passing a value its `options` list never covered must add it there.
- **Fix: `zrb llm chat` takes a piped prompt** (`src/zrb/builtin/llm/chat.py`, `src/zrb/runner/chat/chat_session_runner.py`): `echo "..." | zrb llm chat` failed with a blank `EOFError`, because `--interactive` defaulted to true without a terminal. It now defaults to whether stdin is a terminal, and without `--message` a piped stdin becomes the message.
- **Improvement: a missing API key explains zrb's own key** (`src/zrb/llm/agent/run/error_classifier.py`, `src/zrb/llm/agent/common.py`, `src/zrb/llm/agent/run/runner.py`): pydantic-ai's message, which names the vendor variable that would work (`OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, ...), now gains one line: `<PREFIX>_LLM_API_KEY` is sent only to the provider `<PREFIX>_LLM_PROVIDER` or `<PREFIX>_LLM_MODEL`'s prefix names, spelled with the active env prefix, with a pointer to "Which API Key Gets Used".
- **Improvement: the "To run again" line drops empty flags that match an empty default** (`src/zrb/runner/cli.py`): `zrb llm chat` echoed `--model "" --session "" --yolo "" ...`; an empty value overriding a non-empty default is still shown.
- **Documentation: docs match what zrb does** (`docs/`): the CI guide explains that inputs read piped stdin without a terminal and lists the exit codes; `CmdTask`'s XCom value is documented as a `CmdResult`; a multi-line `cmd` is documented as one shell script (`set -e` to stop at the first failure); three snippets that failed as written now run; the installation guide shows the real output, and its Docker commands use `latest`; aliases, the prompt format and `ctx.log_info`'s visibility at the default log level are described as they behave.
