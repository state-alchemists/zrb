## 3.38.4 (November 13, 2026)

- **Feature: `/usage` says what picking a large conversation back up costs, instead of leaving it to a habit** (`src/zrb/llm/custom_command/usage/resume.py`, `src/zrb/llm/custom_command/usage/command.py`, `src/zrb/config/mixins/llm_ui_commands.py`, `test/llm/custom_command/usage/test_usage_resume.py`, `docs/adr/adr-0127.md`, `docs/configuration/llm-limits.md`, `docs/configuration/llm-context.md`): every number `/usage` printed described a turn already paid for, so the one decision that costs the most had no measurement behind it. Past a provider's prompt-cache lifetime the whole history is re-sent as fresh input: on the 2026-11-12 log, three turns began 37, 21 and 127 minutes after the previous one, at 67.0%, 49.9% and 49.8% cached, and paid 351,517 fresh input tokens to produce 5,484 output — a fifth of that day's fresh input — where a cold session pays 18–24k before the first word. When the conversation's saved history holds more than `ZRB_LLM_UI_USAGE_RESUME_HISTORY_TOKENS` (default 100,000) and its newest message is older than `ZRB_LLM_UI_USAGE_RESUME_GAP_SECONDS` (default 1,200 — four times the five-minute lifetime a prompt cache has by default), `/usage` adds one line under the footer: `resume  last turn 2h 7m ago · 405.0k tokens of history · ~405.0k fresh to resume vs ~20.0k to start over`. It is computed from what is already in hand — the saved history and the timestamp on its newest message, scanned back past an unstamped `ModelRequest` — so it costs no model call and never touches the usage log, and it answers after a restart, which is when the question gets asked. The gap is judged before the history is counted, because counting is the expensive half; a turn still running gets no line; and the estimate charges the whole history, so a provider that still holds part of the prefix cached makes resuming cheaper than the line says, never dearer. Either knob at `0` turns the line off. Recorded as decision 12 in ADR-0127.
- **Fix: the batch reminder is said at most once per user turn, and no longer goes quiet at a turn boundary** (`src/zrb/llm/tool_call/batch_nudge.py`, `test/llm/tool_call/test_batch_nudge.py`, `docs/configuration/llm-context.md`): the module promises to say the reminder "once rather than every round after", and the walk behind it delivered neither half. `_single_call_streak_tools` collected three consecutive single-call rounds and returned `None` the moment it met the injected marker on the way, so a turn that kept issuing one lookup per round was reminded again every third round — the marker only suppressed a reminder while it still sat within three rounds of the tail — and a streak that crossed a new user prompt never reached the model at all: two rounds, the reminder they earned, a new prompt, one more lookup, and the old marker stopped the walk before it had its three. A reminder now silences the rest of its own turn and nothing past it. The turn is the boundary the limiter prunes by, the summarizer splits by and the retry prunes to — a request carrying a `UserPromptPart` and no `ToolReturnPart` (`is_turn_start`) — which is why a `UserPromptSubmit` hook's injected context and the `<live-context>` block count as part of the person's own message: they ride inside the same part. A prompt merged with tool returns does not start a turn. The scan now covers the whole turn rather than the three rounds the streak walk collects, since the walk stops as soon as it has its three. `_message_texts` became `_prompt_texts` at the same time: it read the text of every part of every message, so `NUDGE_MARKER` appearing in a tool result — including a `Read` of the module's own source — silenced the reminder for the rest of the session. Everything else about the streak is untouched. Replaying the real function over the 645 non-empty transcripts in `~/.zrb/llm-history` gives 57 reminders across 48 conversations instead of 80, and of those 57 none arrives with no prompt since the previous one, where 23 of the 80 did.
- **Fix: every tool accepts the `purpose` line a model sends, so a tool that never asked for one stops refusing the call** (`src/zrb/llm/agent/common.py`, `src/zrb/llm/tool/purpose.py`, `src/zrb/llm/tool/skill.py`, `src/zrb/llm/tool/delegate/background.py`, `src/zrb/llm/tool/delegate/message.py`, `test/llm/tool/test_purpose.py`, `test/llm/tool/test_skill.py`): `purpose` is the line the narrator reads aloud in place of a tool's generic sentence, and its field description says "Always fill this" once — so a model fills it on every call it makes, including calls to a tool that has never heard of the narrator. A schema with nowhere to put the argument answered that obedience with `extra_forbidden`: pydantic refused the call before the body ran, the work did not happen, and the round was spent again with the whole context re-sent. On the 2026-11-12 log that was 7 of the 13 tool errors in 517 calls, 5 of them `SearchSkill`'s. Every tool a run can reach passes through `create_safe_wrapper`, which builds the schema pydantic-ai reads; it now adds an optional `purpose` to any tool that does not declare one, and drops the argument again before calling a body that never asked for it — so a tool you write tomorrow, or one a plugin ships, accepts the line instead of refusing the call. `ActivateSkill`, `SearchSkill`, `GetDelegationResult` and `SendMessageToSubagent` declare it themselves as well, because a tool built directly by a caller — which is exactly what those tools' tests do — never passes through the wrapper. Two edges cost a test each: a context tool whose signature is otherwise empty keeps the signature it had, since the added parameter would be read as the run context, and the wrapper sets its annotations explicitly, because a second wrap of an already wrapped tool came back with none at all under Python 3.14 while pydantic-ai reads each parameter's type from there rather than from the signature object. The module docstring also stops naming a guard test that does not exist and points at `test_every_tool_outside_the_harness_says_what_the_call_is_for`.
