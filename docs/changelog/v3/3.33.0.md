## 3.33.0 (November 3, 2026)

- **Feature: persistent memory replaces the journal** (`src/zrb/llm/memory/`, `src/zrb/llm/tool/memory.py`, `src/zrb/llm/prompt/memory_context.py`, `src/zrb/llm/hook/memory_reviewer.py`): the store is four file kinds — `facts/<id>.md` (one claim per subject), `diary/<YYYY-MM-DD>.md`, `log/<YYYY-MM-DD>.md` and a generated `core.md` — and the interface is three tools. `SearchMemory` returns the claim and the path that holds it, never the body. `Remember` writes a fact, a loop, a diary entry or a day's handover in one call, and re-using an id revises that claim: deduplication is identity, not a merge pass. `Forget` retires with `wrong`, `stale` or `done` and keeps the file, so "what did I believe, and why did I stop" is answerable through `SearchMemory(scope='retired')`. `core.md` is rendered from pinned facts and open loops, sorted so the same store is the same bytes twice, and the cap is enforced by **refusal**: a pin that would exceed `ZRB_LLM_MEMORY_CORE_MAX_CHARS` (4,000) writes nothing and returns the deficit plus the current core, so forgetting happens in that turn. A conversation's first turn carries the core and `## Recent` (≤1,600 characters: the newest handover, today's claim, the last log lines) in a `<memory>` block; every later turn carries a `<memory-delta>` of at most three claims recorded or revised since. A Stop hook reviews each completed turn with the three tools and appends the turn's log line — its normal answer is nothing. The write transaction takes the store lock *before* it reads, so two sessions revising one subject cannot drop each other's revision; every write is a git commit. This is [ADR-0138](../adr/adr-0138.md); the specification is [LLM Memory](../technical-specs/llm-memory.md).
- **Changed default: memory is the only store** (`src/zrb/llm/common_tools.py`, `src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/hook/manager.py`): `ZRB_LLM_MEMORY_ENABLED` defaults to `on`, and with the journal deleted there is no second store behind it — `off` means the session reads and writes no memory at all. **Migration:** an existing notes directory is copied into the new store with `zrb memory migrate` (`--dry_run=true` counts first), which reads `~/.zrb/llm-notes` and never modifies it, and merges its lines into any log day the new store already holds. A note becomes a fact whose claim is the note's own `hud_line`, a superseded note becomes a retired fact, a day's `## Handover` becomes that day's diary entry, and the activity log becomes `log/` — one line per event, its journal-only metadata dropped.
- **Feature: a memory write can be refused, and the refusal is actionable** (`src/zrb/llm/tool/memory.py`): the cap is checked before anything is written, on the rendered core, and the refusal names the deficit and prints the core as it is today. `Remember` merges: an argument left out keeps its stored value, so a reviewer restating a claim cannot silently drop its pin, and `pin=False` is an explicit unpin rather than a default.
- **Security: memory is validated at the boundary** (`src/zrb/llm/memory/model.py`): an id is kebab-case and at most 64 characters, so a model-chosen id can never name a path; `claim`, `body` and `handover` are length-bounded and refused if they carry a prompt-injection marker, because every pinned claim is read back inside a future prompt; and the injected block says in its own first lines that its lines are data, not instructions.
- **Removed: the journal, its code and its tests** (`src/zrb/llm/tool/journal.py`, `journal_write.py`, `journal_note.py`, `journal_index.py`, `journal_index_migration.py`, `journal_expiry.py`, `journal_scope.py`, `src/zrb/llm/prompt/journal_core.py`, `journal_claims.py`, `journal_nearby.py`, `src/zrb/llm/hook/journal_compliance.py`, `src/zrb/llm/journal_usage_log.py`, `src/zrb/llm/journal_index_name.py`, `src/zrb/llm/custom_command/usage_command_journal.py`): once memory is the only store, the second one is code nobody runs, and leaving it in the tree would keep two vocabularies for one act alive. `SearchJournal`, `LogActivity`, `WriteJournalNote`, `SupersedeJournalNote` and `DeleteJournalNote` no longer exist; `SearchMemory`, `Remember` and `Forget` are the three tools. `live_context.py` renders no journal index, day block, week block or per-turn claims — the `<memory>` block and its delta are the whole of it — `render_carried_context()` always returns the memory block, and `inject_journal_index` is now `inject_memory` (the `first_message` argument went with the auto-search it fed). `/usage` keeps its Tools section and loses the Journal one, replaced by the Memory section below. `docs/technical-specs/llm-context.md` is now a historical page: it describes only the notes layout an existing `~/.zrb/llm-notes` holds, which is what the migration reads.
- **Feature: `/usage` reports the memory store** (`src/zrb/llm/custom_command/usage_command_memory.py`): the Journal section's replacement, four lines in the old column and `·` style, and each absent when it has no data. `core` (characters spent of `ZRB_LLM_MEMORY_CORE_MAX_CHARS`, pins, open loops) and `store` (active facts, retired ones, diary days) describe the store as it is now; `writes` (`Remember`, `Forget`, `SearchMemory` counts) and `recall` (searches per run) come from the usage log's per-tool counts for the window asked for. Reading it never creates a store, so a machine that never used memory sees no section at all. Two journal lines do not return: a search's outcome is recorded nowhere, and the reviewer's own runs never reach the usage log. `ZRB_LLM_MEMORY_ENABLED=off` removes the section whole.
- **Changed: fourteen `ZRB_LLM_JOURNAL_*` settings are retired, and `ZRB_LLM_MEMORY_ENABLED` is the privacy switch** (`src/zrb/config/retired.py`): a start that still exports one names it and what to set instead — `ZRB_LLM_JOURNAL_DIR` → `ZRB_LLM_NOTES_DIR`, `_GIT_ENABLED` → `ZRB_LLM_MEMORY_GIT_ENABLED`, `_COMPLIANCE_ENABLED` → `ZRB_LLM_MEMORY_REVIEWER_ENABLED`, `_LOCK_TIMEOUT` → `ZRB_LLM_MEMORY_LOCK_TIMEOUT`, the other ten to nothing because the system they configured is gone. `ZRB_LLM_MEMORY_ENABLED` survives unchanged and now means one thing: off is a session that reads and writes no memory, not a choice of store. Auto-approval policies that covered the journal directory cover `CFG.LLM_NOTES_DIR`, and the STOP payload keeps `wrote_files`, `changed_paths` and `turn_states_preference` while `journal_due`, `count_user_turn` and `has_turn_logged_activity` go, replaced by `memory_due`.
- **Fixed: a memory commit names its own files, and only uses its own repository** (`src/zrb/llm/memory/store.py`): the audit commit passed no pathspec, so it committed the whole index — work the human had staged rode along, under a message authored `zrb-memory` — and it used whatever repository sat above the store, which could be a project checkout holding their `.env`. A commit now names exactly the files it staged, and it commits only into the store's own marked repository or into the notes directory itself. A notes directory that is merely *inside* some other checkout gets no memory commits, and work the human had staged is left staged.
- **Security: mutating the memory store asks, reading it does not** (`src/zrb/builtin/llm/chat.py`, `src/zrb/builtin/llm/chat_tool_policy.py`): the store lives inside `LLM_NOTES_DIR`, and the notes directory had been auto-approved for `Write`, `Edit`, `RM` and `MV` since the journal needed it. Memory changes go through `Remember` and `Forget`, which enforce the id, the claim's length, the injection markers and the core's cap — a raw write or delete is the same act with none of them, and `RM` destroys a claim `Forget` would have retired. Those four tools no longer auto-approve a path inside `LLM_MEMORY_DIR`, and the containment check resolves symlinks — a link inside the notes directory is judged by the file it points at, not by its name. `Read`, `LS`, `Glob` and `Grep` still do.
- **Migration: `zrb memory migrate`** (`src/zrb/builtin/memory.py`, `src/zrb/llm/memory/migrate.py`): the CLI task is renamed from `migrate-journal` and reads `CFG.LLM_NOTES_DIR`. An existing `~/.zrb/llm-notes` is still read into the store once — on first use when the store lives inside it, or on demand with `zrb memory migrate` (`--dry_run=true` counts first) for a store pointed somewhere else. The notes are never modified: the store is written beside them, `.version` at the notes root records that the conversion ran, and a second run changes nothing. What each note becomes is [LLM Memory → From the journal notes](../technical-specs/llm-memory.md#91-from-the-journal-notes).
- **Feature: `/usage` reports what compaction cost, and files a delegated run under the conversation that paid for it** (`src/zrb/llm/usage_log.py`, `src/zrb/llm/summarizer/history_summarizer.py`, `text_summarizer.py`, `chunk_processor.py`, `src/zrb/llm/ui/buffered_ui.py`, `src/zrb/llm/custom_command/usage_command.py`, `docs/adr/adr-0127.md`): the summarizer calls the model from a history processor, outside the loop that writes a usage line, so a compaction read a whole conversation and reported nothing — the largest hidden charge there was, landing exactly when the history is big. A compaction now writes one line of its own, `kind="summarization"`, summed over the calls it made (one per chunk, plus any consolidation and shortening), and `/usage` shows it in a `Compaction` section with the table's own columns: kept out of the turn rows because it is a separate charge, often carried by the small model `/model small` set, and always reading a cache the turns had left cold. Separately, a delegated sub-agent's run was filed under an empty session name, so `/usage session` showed only the main thread of a fan-out; a `BufferedUI` now reports the conversation it belongs to. `/usage <tab>` also completes the four windows, which until now existed only in the command's description.
