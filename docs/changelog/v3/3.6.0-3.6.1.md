## 3.6.0 (September 19, 2026)

- **Fix: a custom UI in `MultiUI`'s primary slot no longer loses snapshots, rewind, plan mode and model overrides in silence** (`src/zrb/llm/ui/{any_ui,state_defaults,multi_ui}.py`, `test/llm/ui/test_state_defaults.py`, `test/architecture/test_multi_ui_fanout_surface.py`, `docs/llm/llm-custom-ui.md`): `MultiUI` read seven state members off its primary child by string name — `snapshot_manager`, `history_manager`, `conversation_session_name`, `plan_mode_active`, `small_model`, `multimodal_model`, `last_output` — none declared in `AnyUI`, so a UI written to the documented contract silently fell back to defaults (`/rewind` did nothing, the `/plan` badge never moved, `/model small ...` was dropped). They are now part of `AnyUI`, with inert defaults in `UIStateDefaultsMixin`. **Breaking for custom UIs that bypass the mixin:** a class implementing `AnyUI` directly must add the seven, and since `last_output`, `snapshot_manager` and `history_manager` are read-only in the contract, assigning `self.last_output = ...` raises `AttributeError` unless the class declares a setter. `MultiUI`'s `small_model`/`multimodal_model` now write through to the primary. The run's session name, approval mode, model and fallback tool-call handler came from the first child rather than the primary, so `main_ui_index=1` ran under the wrong child's settings; they now read the primary, and a `MultiUI` with no child raises instead of an `IndexError`. Two architecture tests forbid string-keyed and literal-index reads of the primary.
- **Refactor: `AnyTask.cli_only` is `AnyTask.is_cli_only`** (`src/zrb/task/any_task.py`, `src/zrb/task/base/base_task.py`, `src/zrb/group/group.py`, `test/public_api_snapshot.json`, ADR-0098): ADR-0098's own worked example of a boolean that reads as a value was still named the old way in the public API. Renamed on `AnyTask`, `BaseTask` and the twelve task classes inheriting it. The `cli_only=` constructor keyword is unchanged (a parameter, not a `-> bool` function), so `CmdTask(name="serve", cli_only=True)` and every `zrb_init.py` keep working; only code reading `task.cli_only` needs the new name.
- **Tests: the `-> bool` half of ADR-0098 is enforced as a ratchet** (`test/architecture/test_bool_naming_ratchet.py`, ADR-0098, `AGENTS.md`): the rule shipped in 3.5.0 as review vocabulary, and 199 of the 303 `-> bool` functions in `src/zrb` do not follow it, so a gate would have failed on its first run. The count is pinned instead, in the same only-goes-down form as the complexity and facade ratchets. A paired tightness test fails when a rename lands without lowering the number. It needs no allowlist: the `-> bool` annotation is the trigger and the vocabulary is closed. ADR-0098 is rewritten to record the reversal.
- **Tests: a facade budget must be lowered when its file shrinks** (`test/architecture/test_facade_size_budget.py`, `test/architecture/test_constructor_surface.py`): `FACADE_BUDGETS` ceilings "only ever go DOWN", but nothing checked it, so reclaimed space could grow back unremarked. A budget more than 5% above its file's real line count now fails. `PARAM_BUDGETS` had the same drift and is tightened: `LLMChatTask` 41 → 40.

## 3.6.1 (September 22, 2026)

- **Fix: a write that breaks the file no longer reports itself as `Successfully`** (`src/zrb/llm/tool/{post_write_check,file_edit,file_write}.py`, `test/llm/tool/test_post_write_check.py`): `Write` and `Edit` appended the `[DIAGNOSTIC]` block to their success line, so one result asserted success and failure at once and the model could believe the half that let it move on (81 consecutive `Successfully updated … [DIAGNOSTIC]` results answered with another blind edit, as `format_post_write_diagnostics`' docstring records). A failing check now leads the result, and the outcome line is demoted to `What landed: …`, kept for its replacement count and fuzzy-match note. A clean write is unchanged. Both docstrings now say the bytes reached disk, so do not re-send them: read the file, make a targeted fix, and treat the change as incomplete until the errors are gone.
- **Improvement: `Edit` says what its `count` default and its whitespace-tolerant fallback actually do** (`src/zrb/llm/tool/file_edit.py`): `count` defaults to `-1` (every occurrence), so a short `old_text` such as `return None` silently became a file-wide replacement; its description now leads with that and says to pass `count=1` unless `old_text` is confirmed unique. The fuzzy-match note now says the fallback can match a block at a different indentation level and writes `new_text` with the model's indentation, which for Python can pass the post-write check unnoticed. The `count=-1` default is unchanged.
- **Improvement: the verification bar and the removal proof are on the always-on path, not behind a skill activation** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm_plugin/core_skills/core-coding/SKILL.md`): workflow step 4's exit clause "**or you can state plainly that none could run**" is gone, and two rules that needed `ActivateSkill("core-coding")` are now unconditional: a change is done when a focused test, lint or type check has run and passed, and a removal is proved by searching the changed files for what was removed. `core-coding` states both itself rather than pointing at "Workflow step 4", since any section can be replaced through `LLM_INCLUDE_SECTIONS` or `LLM_PROMPT_DIR`.
- **Improvement: tool docstrings stop restating their own parameter schemas** (`src/zrb/llm/tool/{file_list,file_read,file_write,file_edit,file_search,code,journal}.py`, `src/zrb/llm/common_tools.py`): a tool's docstring and its `Field` descriptions travel in the same request, so explaining an argument in both paid twice and invited drift. `LS` and `Glob` (about 85% restatement), `Read` and `SearchJournal` drop the duplicated wording; `Write` now leads with when to choose it, and `Edit` keeps only what a schema cannot say (read the result, not just its status). `common_tools.py` documents the split: the `Field` owns the argument, the docstring owns the tool. Registered-tool docstrings drop from 1062 to 990 words as a side effect; ADR-0058's lever on tool-definition weight is still tool count.
- **Improvement: the prompt states each rule once, and the examples teach the ask-versus-proceed threshold** (`src/zrb/llm/prompt/markdown/{principle,workflow,example,profile.minimal,profile.standard,profile.capable}.md`): `principle` now solely owns the honesty-and-uncertainty rule (previously stated three times) and "preserve unrelated changes" (twice). Skill activation points at the trigger conditions each `SKILL.md` description opens with instead of restating them. The batching forward reference ("System Context may explicitly disable batching for this model; that override wins") is removed, since it announced an absence to every model not on the deny-list (see ADR-0050). `example.md` swaps two formatting demos for judgment calls: adding a `--verbose` flag (proceed) versus "clean up the old migration files" (ask — ambiguous, and destructive under one reading). The three profiles name a distinguishing behaviour instead of a posture adjective.
- **Improvement: `Shell`'s timeout and permission-denied suggestions name the next action instead of a generic gesture** (`src/zrb/llm/tool/shell.py`): the timeout suggestion claimed the process was often still running, though the tool had already terminated it. It now points work meant to keep running to `background=True` with `MonitorProcess`, and work meant to finish to scoping, summarizing or a non-interactive flag rather than an unchanged re-run. Permission-denied asks for a user-level fix (user prefix, non-privileged port or path, owner and group) before `sudo`.
- **Docs: ADR-0099 — factual-claim hardening against generative-engine-optimized content** (`docs/adr/adr-0099.md`, `src/zrb/llm/prompt/markdown/{web_summarizer,principle}.md`, `src/zrb/llm_plugin/core_skills/core-research/SKILL.md`, `src/zrb/llm_plugin/agents/researcher.agent.md`, `src/zrb/llm/tool/web.py`): a figure whose origin the page does not name is now recorded as unverifiable rather than relayed, and a page shaped for extraction is flagged rather than echoed as neutral fact. Corroboration of contested or consequential claims moves from the optional `researcher` sub-agent onto always-on `principle` and on-demand `core-research`, and the default summarized `WebFetch` path now carries the untrusted-content framing the raw path already had (extending ADR-0048). `open_web_page`'s unreachable-page hint gains the colon of the `[SYSTEM SUGGESTION]:` convention.
- **Improvement: the `generalist` sub-agent drops shouted mandates for plain statements** (`src/zrb/llm_plugin/core_agents/generalist.agent.md`): `SHALL NOT`, `MUST` and `NO context` are now ordinary prose ("you do not delegate further", "your first tool calls are `ActivateSkill`"); only the register changed. `core-coding` gains the re-read-before-Edit rule in its execution phase: apply every `Edit` against a `Read`'s output visible in the conversation, not memory, since a stale block either fails to match or edits the wrong region.
- **Docs: part-accessibility guidance and the duplicate-basename example** (`AGENTS.md`, `docs/adr/adr-0034.md`, `poetry.lock`): clarifies that parts outside code reaches directly (`usage`, `confirmation`, `voice`, `persona`) stay bare rather than taking the `_base_` prefix, corrects the `X/X.py` path count from 18 to 17, and updates the duplicate-basename example to `test_registry.py` under the `llm/` packages, syncing ADR-0034's consequences. `poetry.lock` regenerated with Poetry 2.5.1.
- **Tests: a web-search assertion that measured wall-clock now measures what it meant, and the hook pid file is written atomically** (`test/llm/tool/test_web_tool_open_page.py`, `test/llm/hook/test_manager_plugin_roots.py`): `test_search_internet_does_not_block_the_event_loop` timed a heartbeat against 0.2s, conflating a blocked loop with OS descheduling; it now asserts the sync backend runs off the loop thread, plus a heartbeat that must fire while it runs. The hook test's child writes its pid file to a temp file and `os.replace()`s it, so a kill mid-write cannot leave an empty file for `int('')` to choke on.
