## 3.6.0 (September 19, 2026)

- **Fix: a custom UI in `MultiUI`'s primary slot no longer loses snapshots, rewind, plan mode and model overrides in silence** (`src/zrb/llm/ui/any_ui.py`, `src/zrb/llm/ui/state_defaults.py`, `src/zrb/llm/ui/multi_ui.py`, `test/llm/ui/test_state_defaults.py`, `test/architecture/test_multi_ui_fanout_surface.py`, `docs/llm/llm-custom-ui.md`, `test/public_api_snapshot.json`): `MultiUI` reads seven state members off its *primary* child (`main_ui`, chosen by the `main_ui_index` constructor argument) — `snapshot_manager`, `history_manager`, `conversation_session_name`, `plan_mode_active`, `small_model`, `multimodal_model` and `last_output` — each through `getattr(self.main_ui, "name", default)`. None was declared in `AnyUI` or in the custom-UI guide, so a UI written to the documented contract fell back to the defaults in that slot: `/rewind` did nothing, the `/plan` badge never moved, and `/model small ...` was dropped, with no error and nothing for pyright to see. The members are now part of `AnyUI` with inert defaults in `UIStateDefaultsMixin`, so a UI mixing that in constructs unchanged, while one declaring them wrong is a `TypeError` at construction instead of a missing feature at runtime. **Breaking, twice, for custom UIs that bypass the mixin:** a class inheriting `AnyUI` *directly* and implementing every member by hand (no zrb doc shows this, but 3.5.0 allowed it) fails to instantiate until it adds the seven; and `last_output`, `snapshot_manager` and `history_manager` are read-only in the contract, so a mixin user assigning `self.last_output = ...` as a plain attribute now raises `AttributeError` and must declare its own setter, as `MultiUI` does. Declaring them also fixed a latent inconsistency: `MultiUI` exposed `small_model`/`multimodal_model` read-only, which `AnyUI` says they are not; nothing reached that (`/model small ...` is handled by `BaseUICommands` against a `BaseUI` child, never the wrapper), but both now write through to the main child rather than raising. The eleven probes are replaced by attribute access: the four testing for members `AnyUI` already guaranteed (`llm_task`, `model`, `tool_call_handler`, `yolo`) are gone, the rest are plain `main_ui is None` checks — the only thing ever in question. `test_the_primary_child_is_read_through_the_declared_contract` fails the suite on a string-keyed lookup against `self.main_ui` or `self._uis[...]`, with the fix in the message. Three reads took the wrong child: the run's session name, approval mode and model, plus the fallback tool-call handler, came from `self._uis[0]` rather than `self.main_ui` — the same child only at the default index — so `MultiUI(uis, main_ui_index=1)` ran the session under the *first* child's name, approval mode and model while the second drove the event loop. Latent (nothing inside zrb passes a non-zero index), but `main_ui_index` is public. All three now read the primary, `create_session_for_llm_task` raises instead of an `IndexError` when there is no child, and `test_the_primary_child_is_not_reached_by_a_literal_index` fails on any `self._uis[<literal>].attr` read. The twelve optional enrichment hooks are unchanged: they fan out to *every* child and legitimately degrade, so they stay out of `AnyUI`.
- **Refactor: `AnyTask.cli_only` is `AnyTask.is_cli_only`** (`src/zrb/task/any_task.py`, `src/zrb/task/base/base_task.py`, `src/zrb/group/group.py`, `test/public_api_snapshot.json`, ADR-0098): the property ADR-0098 used as its own worked example of a boolean that reads as a value (`if task.cli_only:` versus `if task.is_cli_only:`) was still named the old way in the public API. Renamed on `AnyTask`, `BaseTask` and the twelve task classes inheriting it. The `cli_only=` constructor keyword is unchanged — it is a parameter, not a `-> bool` function, and the rule does not reach it — so `CmdTask(name="serve", cli_only=True)` and every `zrb_init.py` using it keep working; only code *reading* `task.cli_only` needs the new name.
- **Tests: the `-> bool` half of ADR-0098 is enforced as a ratchet** (`test/architecture/test_bool_naming_ratchet.py`, ADR-0098, `AGENTS.md`): the rule shipped in 3.5.0 as review vocabulary with the fitness test explicitly deferred, and 199 of the 303 `-> bool` functions in `src/zrb` do not follow it — a gate would have failed on its first run and been deleted or exempted within a day. The count is pinned instead, in the same only-ever-goes-down form as the complexity and facade ratchets, so new code cannot add to the debt. A paired tightness test fails when a rename lands without lowering the number, so the debt cannot be repaid and then quietly re-borrowed. It needs no allowlist: the `-> bool` annotation is the trigger and the vocabulary is closed, which is what made this half cheap to check and the action-verb half not. ADR-0098 is rewritten to record the reversal rather than superseded.
- **Tests: a facade budget must be lowered when its file shrinks** (`test/architecture/test_facade_size_budget.py`, `test/architecture/test_constructor_surface.py`): `FACADE_BUDGETS` documents ceilings that "only ever go DOWN", but nothing checked that they did — a file that lost 200 lines kept its old ceiling, leaving the reclaimed space free to grow back unremarked. A budget sitting more than 5% above its file's real line count now fails, with enough slack that ordinary edits do not trip it. `PARAM_BUDGETS` had the same drift in miniature and is tightened: `LLMChatTask` 41 → 40, its actual count.

## 3.6.1 (September 22, 2026)

- **Fix: a write that breaks the file no longer reports itself as `Successfully`** (`src/zrb/llm/tool/post_write_check.py`, `src/zrb/llm/tool/file_edit.py`, `src/zrb/llm/tool/file_write.py`, `test/llm/tool/test_post_write_check.py`): `Write` and `Edit` appended the `[DIAGNOSTIC]` block to their success line, producing `Successfully updated foo.py … the file is now broken — treat this as a failed edit`. One result asserted success and failure at once, and since a tool result's first words frame the rest, the model could believe the half that let it move on — the shape behind the 81 consecutive `Successfully updated … [DIAGNOSTIC]` results answered with another blind edit that `format_post_write_diagnostics`' docstring records. The earlier fix added guidance to the *body* without changing what the result *led with*. A new `compose_write_result` puts the failure first and demotes the outcome line to `What landed: …`; the verdict sentence lives only in the diagnostic block, so the halves cannot drift. The outcome line is demoted rather than dropped because the replacement count and any fuzzy-match note help choose the next move. A clean write is unchanged and returns exactly its outcome line. Both docstrings match the result: the bytes did reach disk, so do not re-send them; read the file and make a targeted fix; the change is not complete until the errors are gone. ("The write is not done" would have read as "nothing happened", inviting the blind rewrite-from-memory this fix exists to stop.)
- **Improvement: `Edit` says what its `count` default and its whitespace-tolerant fallback actually do** (`src/zrb/llm/tool/file_edit.py`): `count` defaults to `-1`, replacing *every* occurrence, and its description ("-1 (default) replaces every occurrence; 1 replaces only the first") only restated the signature, so a short `old_text` (`return None`, `self.name`) silently became a file-wide replacement. It now leads with the consequence and says to pass `count=1` unless `old_text` is confirmed unique. The fuzzy-match note changed from reassurance ("whitespace differences were normalized") to what happened: the fallback can match a block at a *different* indentation level, and `new_text` is then written with the model's indentation rather than the file's. For Python a wrongly-indented but syntactically valid block passes both `ast.parse` and the pyflakes undefined-name filter, so the post-write check reports nothing. The `count=-1` default is unchanged.
- **Improvement: the verification bar and the removal proof are on the always-on path, not behind a skill activation** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm_plugin/core_skills/core-coding/SKILL.md`): workflow step 4 read "a change is not done until its checks pass **or you can state plainly that none could run**" — an always-available exit from verification in the most-read section of the prompt. The clause is gone, and two rules that previously required `ActivateSkill("core-coding")` are stated unconditionally: a change is done when a focused test, lint or type check has run and passed, and a removal is proved by searching the changed files for what was removed. `core-coding` states both self-contained rather than pointing at "Workflow step 4": every prompt section is swappable through `LLM_INCLUDE_SECTIONS` and `LLM_PROMPT_DIR`, so a cross-section pointer dangles once one is replaced — the failure `skill.py` already avoids for the skill catalogue. Duplication *across* that swappable boundary keeps each layer independently replaceable.
- **Improvement: tool docstrings stop restating their own parameter schemas** (`src/zrb/llm/tool/{file_list,file_read,file_write,file_edit,file_search,code,journal}.py`, `src/zrb/llm/common_tools.py`): pydantic-ai serializes a tool's docstring into `description` and every `Annotated[..., Field(description=...)]` into `parameters_json_schema`, both in the same request, so a docstring explaining an argument pays twice and leaves the model to reconcile drift. `LS` and `Glob` were worst: three sentences each rewording their own `Field` descriptions (the auto-exclusions, the `exclude_patterns=[]` escape, the `include_hidden` default), roughly 85% of each docstring. `Read` dropped "Returns lines [start_line, end_line], 1-indexed and inclusive; end_line=-1 means the last line", verbatim its two `Field`s. `Write` leads with tool choice instead of restating how to pick a `mode`, while still naming all three things it does (create, replace, append). `Edit` keeps only what a schema cannot express — read the result, not just its status, since the replacement count and fuzzy-match note describe the outcome, not a parameter. `SearchJournal` loses the clause naming "all journal files in the configured journal directory", which its name and `path` already carry. `common_tools.py`, where tools are registered, documents the division: the `Field` owns the argument, the docstring owns the tool. This does not revisit ADR-0058 — the lever on tool-definition weight is still tool *count*; the 1062 → 990 word drop across registered-tool docstrings is a side effect of removing duplication.
- **Improvement: the prompt states each rule once, and the examples teach the ask-versus-proceed threshold** (`src/zrb/llm/prompt/markdown/{principle,workflow,example,profile.minimal,profile.standard,profile.capable}.md`): the honesty-and-uncertainty rule was stated three times across `persona`, `principle` and `workflow`, and "preserve unrelated changes" twice; `principle` now owns both and the `workflow` copies are gone. Skill activation points at the trigger conditions every `SKILL.md` description opens with instead of restating them, so the catalogue stays the single source. The batching clause "System Context may explicitly disable batching for this model; that override wins" is removed: the System Context line already asserts precedence over "every batching instruction elsewhere, in the workflow rules and in any tool description" and renders only for deny-listed models, so the forward reference announced an absence to every other model — the coupling that once made every model serialize its calls. `example.md` trades two generic formatting demos for judgment calls the prose could not teach: adding a `--verbose` flag (proceed — the existing code determines the name, parse site and test) versus "clean up the old migration files" (ask — ambiguous between delete, archive and squash, and destructive under one reading). The three operating profiles name a distinguishing behaviour instead of a posture adjective.
- **Improvement: `Shell`'s timeout and permission-denied suggestions name the next action instead of a generic gesture** (`src/zrb/llm/tool/shell.py`): the timeout suggestion said the process was "often still running in the background" and to check `ps aux` before killing it — but the tool has already terminated it, so the advice sent the model after a corpse. It now separates the real cases: work meant to keep running belongs under `background=True` with `MonitorProcess`; work meant to finish should not be re-run unchanged but scoped, summarized or given a non-interactive flag. Permission-denied no longer leads with `sudo`: it asks for a user-level fix first (user prefix, non-privileged port or path, owner and group) and treats `sudo` as a last resort.
- **Docs: ADR-0099 — factual-claim hardening against generative-engine-optimized content** (`docs/adr/adr-0099.md`, `src/zrb/llm/prompt/markdown/web_summarizer.md`, `src/zrb/llm/prompt/markdown/principle.md`, `src/zrb/llm_plugin/core_skills/core-research/SKILL.md`, `src/zrb/llm_plugin/agents/researcher.agent.md`, `src/zrb/llm/tool/web.py`): content shaped for answer-engine retrieval leans on decorative quotations and statistics, and zrb gave the agent nothing to act on. The strongest source-quality wording lived only in the optional `researcher` sub-agent, unseen in a normal chat; `web_summarizer.md` listed benchmarks and security warnings as always-high-extract with no attribution test; and the *default* summarized `WebFetch` path returned derived untrusted content with no `content_is` note, though the opt-in raw path had one. Now a figure whose origin the page does not name is recorded as unverifiable rather than relayed, a page shaped for extraction is flagged rather than echoed as neutral fact, corroboration moves onto always-on `principle` and on-demand `core-research` — scoped to contested or consequential claims so mundane facts need no redundant fetching — and both web paths carry the untrusted framing, extending ADR-0048 rather than revising it. `open_web_page`'s unreachable-page hint gains the colon the `[SYSTEM SUGGESTION]:` convention uses elsewhere.
- **Improvement: the `generalist` sub-agent drops shouted mandates for plain statements** (`src/zrb/llm_plugin/core_agents/generalist.agent.md`): `SHALL NOT`, `MUST` and `NO context` are now ordinary prose ("you do not delegate further", "your first tool calls are `ActivateSkill`"); only the register changed. `core-coding` gains the re-read-before-Edit rule in its execution phase: apply every `Edit` against a `Read`'s output visible in the conversation, not memory, since a stale block either fails to match or edits the wrong region, and each miss costs more than the re-read.
- **Docs: part-accessibility guidance and the duplicate-basename example** (`AGENTS.md`, `docs/adr/adr-0034.md`, `poetry.lock`): clarifies that parts outside code reaches directly (`usage`, `confirmation`, `voice`, `persona`) stay bare rather than taking the `_base_` prefix, corrects the `X/X.py` path count from 18 to 17, and updates the duplicate-basename example to `test_registry.py` under the `llm/` packages, syncing ADR-0034's consequences. `poetry.lock` regenerated with Poetry 2.5.1.
- **Tests: a web-search assertion that measured wall-clock now measures what it meant, and the hook pid file is written atomically** (`test/llm/tool/test_web_tool_open_page.py`, `test/llm/hook/test_manager_plugin_roots.py`): `test_search_internet_does_not_block_the_event_loop` asserted `heartbeat_done_at - overall_start < 0.2`, conflating an event-loop block with OS descheduling, so under a busy run a free loop read as blocked. It now asserts the sync backend runs on a different thread than the loop (load-independent proof of off-loop dispatch) *and* keeps a concurrent heartbeat that must fire while the backend runs, since the thread check alone would pass a dispatch that off-loads to a worker and then synchronously joins it from the loop; the backend holds an explicit "running" flag until the heartbeat releases it. In the hook test, `_assert_recorded_process_stops` parsed the child's pid file the moment it appeared, but `Path.write_text` is not atomic: a kill between `open()` and `write()` leaves an empty file and `int('')` raises. The child now writes a temp file and `os.replace()`s it into place, so the pid file is absent or complete — guarding only against an empty read would still accept a nonempty prefix of the pid.
