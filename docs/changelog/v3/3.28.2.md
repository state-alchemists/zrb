## 3.28.2 (October 28, 2026)

- **Fix: a handover no longer deletes the day lines written since the previous one** (`src/zrb/llm/tool/journal_write.py`, `test/llm/tool/test_journal_handover.py`): `LogActivity` added its line above the Backlinks block, and once a handover exists that spot is inside the `## Handover` section — which `WriteDayHandover` owns from its heading to the next one, so a second handover in a day removed every line logged since the first. On 2026-10-28 that was twenty-three lines, a morning and an afternoon, and the day file kept no trace of them: the block a fresh session reads showed a day that had stopped at breakfast. A day line now lands above the first section heading, and a rewrite lifts a day line it finds stranded inside an old handover back into the day's own lines rather than discarding it, so a file already written by the broken version keeps its hours on the next write. Only a line ending the way `LogActivity` ends one is lifted — `Files: …`, or the older `· imp N` — so a `- 12:34 — …` step inside a handover stays in the section it belongs to, rather than arriving in the day's lines as an event that never happened. A handover carrying such a line is now refused rather than written, because a step and an event are the same shape and the same model writes both; the refusal asks for the step without the leading clock. Both cases are pinned by name in the handover test file.
