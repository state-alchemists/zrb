## 3.17.0 (October 11, 2026)

- **Feature: `zrb remote check` says why a probe failed** (`src/zrb/remote/execution.py`, `src/zrb/builtin/remote.py`, `docs/adr/adr-0110.md`): a failed cell reads `refused` (the host answered, nothing listens), `timeout` (no answer, usually a firewall) or `dns` (the name did not resolve) instead of a bare `fail`, for TCP and HTTP targets alike; an unrecognised error is still `fail`. `--format json` carries the same words, so a script comparing against `"fail"` must now accept the new ones. The probe leaves one trapped scratch file on the host rather than one per probe, and a host with no `mktemp` reports a plain `fail` instead of falling back to a predictable path.
- **Feature: speaking over zrb reads stop, hush and redirect without a model** (`src/zrb/llm/dictation/words.py`, `src/zrb/llm/dictation/feature.py`, `docs/adr/adr-0105.md`): fillers, polite words and a sentence said twice are set aside before the word lists match, so "stop please" and "wait wait" cancel the turn exactly as "stop" does. A new `hush` outcome (`ZRB_LLM_DICTATION_HUSH_WORDS`: "okay", "I got it", "enough") quiets zrb's voice, lets the turn go on and sends nothing to the agent. A stop that carries on ("hold on, use postgres") cancels the turn and sends the words. The judge is asked only about short words the lists cannot read (`ZRB_LLM_DICTATION_INTERRUPT_JUDGE_MAX_WORDS`, 5), can now answer `hush`, and a longer utterance is a request. Behavior change: `no`, `nope`, `deny` and `don't` are no longer default stop words, since they deny a tool approval; add them to `ZRB_LLM_DICTATION_STOP_WORDS` to restore the old behavior.
- **Feature: the barge-in judge's time budget is a setting** (`src/zrb/config/mixins/llm_dictation.py`): `ZRB_LLM_DICTATION_INTERRUPT_JUDGE_TIMEOUT` (seconds, default 2.0) replaces the hard-coded constant.
- **Fix: speech could deadlock CoreAudio on macOS and make zrb impossible to quit** (`src/zrb/llm/speech/pcm_player.py`, `src/zrb/llm/speech/player.py`, `src/zrb/llm/util/portaudio_exit.py`): the playback callback raised `sd.CallbackStop`, which makes PortAudio stop the stream from its own audio thread while the playing thread stopped the same stream, so the two deadlocked inside CoreAudio. Speech then stopped for good, and Ctrl+C could not quit because sounddevice's exit handler (`Pa_Terminate`) blocked on the same lock. This is present in 3.15.0 and reproduces there with a plain stop-while-playing loop (it hung in 4 of 4 runs). The callback now fills silence and only the playing thread stops the stream. Stopping runs under a 2-second watchdog: a stream that will not stop is abandoned and a player program takes over for the rest of the session. sounddevice's exit handler is replaced by one that gives up after 2 seconds, in speech and in dictation. The speaker imports sounddevice before registering its own exit handler, so that handler runs first; a stream counts as open from before it is constructed, and closing or exiting waits for one still being stopped.
