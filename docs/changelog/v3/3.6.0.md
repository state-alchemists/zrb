## 3.6.0 (September 19, 2026)

- **Fix: a custom UI in `MultiUI`'s primary slot no longer loses snapshots, rewind, plan mode and model overrides in silence** (`src/zrb/llm/ui/any_ui.py`, `src/zrb/llm/ui/state_defaults.py`, `src/zrb/llm/ui/multi_ui.py`, `test/llm/ui/test_state_defaults.py`, `test/architecture/test_multi_ui_fanout_surface.py`, `docs/llm/llm-custom-ui.md`, `test/public_api_snapshot.json`): `MultiUI` reads seven state members off its *primary* child (`main_ui`, chosen by the `main_ui_index` constructor argument) — `snapshot_manager`, `history_manager`, `conversation_session_name`, `plan_mode_active`, `small_model`, `multimodal_model` and `last_output` — each through `getattr(self.main_ui, "name", default)`. None was declared in `AnyUI` or in the custom-UI guide, so a UI written to the documented contract fell back to the defaults in that slot: `/rewind` did nothing, the `/plan` badge never moved, and `/model small ...` was dropped, with no error and nothing for pyright to see. The members are now part of `AnyUI` with inert defaults in `UIStateDefaultsMixin`, so a UI mixing that in constructs unchanged, while one declaring them wrong is a `TypeError` at construction instead of a missing feature at runtime. **Breaking, twice, for custom UIs that bypass the mixin:** a class inheriting `AnyUI` *directly* and implementing every member by hand (no zrb doc shows this, but 3.5.0 allowed it) fails to instantiate until it adds the seven; and `last_output`, `snapshot_manager` and `history_manager` are read-only in the contract, so a mixin user assigning `self.last_output = ...` as a plain attribute now raises `AttributeError` and must declare its own setter, as `MultiUI` does. Declaring them also fixed a latent inconsistency: `MultiUI` exposed `small_model`/`multimodal_model` read-only, which `AnyUI` says they are not; nothing reached that (`/model small ...` is handled by `BaseUICommands` against a `BaseUI` child, never the wrapper), but both now write through to the main child rather than raising. The eleven probes are replaced by attribute access: the four testing for members `AnyUI` already guaranteed (`llm_task`, `model`, `tool_call_handler`, `yolo`) are gone, the rest are plain `main_ui is None` checks — the only thing ever in question. `test_the_primary_child_is_read_through_the_declared_contract` fails the suite on a string-keyed lookup against `self.main_ui` or `self._uis[...]`, with the fix in the message. Three reads took the wrong child: the run's session name, approval mode and model, plus the fallback tool-call handler, came from `self._uis[0]` rather than `self.main_ui` — the same child only at the default index — so `MultiUI(uis, main_ui_index=1)` ran the session under the *first* child's name, approval mode and model while the second drove the event loop. Latent (nothing inside zrb passes a non-zero index), but `main_ui_index` is public. All three now read the primary, `create_session_for_llm_task` raises instead of an `IndexError` when there is no child, and `test_the_primary_child_is_not_reached_by_a_literal_index` fails on any `self._uis[<literal>].attr` read. The twelve optional enrichment hooks are unchanged: they fan out to *every* child and legitimately degrade, so they stay out of `AnyUI`.
- **Refactor: `AnyTask.cli_only` is `AnyTask.is_cli_only`** (`src/zrb/task/any_task.py`, `src/zrb/task/base/base_task.py`, `src/zrb/group/group.py`, `test/public_api_snapshot.json`, ADR-0098): the property ADR-0098 used as its own worked example of a boolean that reads as a value (`if task.cli_only:` versus `if task.is_cli_only:`) was still named the old way in the public API. Renamed on `AnyTask`, `BaseTask` and the twelve task classes inheriting it. The `cli_only=` constructor keyword is unchanged — it is a parameter, not a `-> bool` function, and the rule does not reach it — so `CmdTask(name="serve", cli_only=True)` and every `zrb_init.py` using it keep working; only code *reading* `task.cli_only` needs the new name.
- **Tests: the `-> bool` half of ADR-0098 is enforced as a ratchet** (`test/architecture/test_bool_naming_ratchet.py`, ADR-0098, `AGENTS.md`): the rule shipped in 3.5.0 as review vocabulary with the fitness test explicitly deferred, and 199 of the 303 `-> bool` functions in `src/zrb` do not follow it — a gate would have failed on its first run and been deleted or exempted within a day. The count is pinned instead, in the same only-ever-goes-down form as the complexity and facade ratchets, so new code cannot add to the debt. A paired tightness test fails when a rename lands without lowering the number, so the debt cannot be repaid and then quietly re-borrowed. It needs no allowlist: the `-> bool` annotation is the trigger and the vocabulary is closed, which is what made this half cheap to check and the action-verb half not. ADR-0098 is rewritten to record the reversal rather than superseded.
- **Tests: a facade budget must be lowered when its file shrinks** (`test/architecture/test_facade_size_budget.py`, `test/architecture/test_constructor_surface.py`): `FACADE_BUDGETS` documents ceilings that "only ever go DOWN", but nothing checked that they did — a file that lost 200 lines kept its old ceiling, leaving the reclaimed space free to grow back unremarked. A budget sitting more than 5% above its file's real line count now fails, with enough slack that ordinary edits do not trip it. `PARAM_BUDGETS` had the same drift in miniature and is tightened: `LLMChatTask` 41 → 40, its actual count.
