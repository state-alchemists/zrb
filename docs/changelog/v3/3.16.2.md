## 3.16.2 (Unreleased)

- **Security: `multidict` is pinned to the patched release** (`pyproject.toml`, `poetry.lock`): the dependency floor is now `multidict>=6.9.1`, and the lock file resolves `6.9.1` instead of the vulnerable `6.7.1`.
- **Fix: a mistyped `CFG` read or a bad env value names the setting** (`src/zrb/config/config.py`, `src/zrb/config/env_field.py`, `test/config/test_config_assignment_safety.py`): only assignment suggested a close name, so `CFG.LLM_MAX_REQUESTS_PER_MINUTE` raised a bare `AttributeError` and `ZRB_LLM_MAX_REQUEST_PER_MINUTE=nope` raised `invalid literal for int()` without saying which setting. An unknown uppercase read now raises the same did-you-mean as an assignment (hidden from pyright, so a typo in `CFG.X` is still a type error), and an uncastable value reads `ZRB_LLM_MAX_REQUEST_PER_MINUTE='nope': invalid literal for int() …`. `getattr(CFG, name, default)` and `hasattr` behave as before.
