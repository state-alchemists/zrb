## 3.5.0 (September 19, 2026)

- **Refactor: the complexity ratchets drop from mccabe 19 / radon 20 to 15 / 15** (`test/architecture/test_complexity_ratchet.py`, `test/architecture/test_facade_size_budget.py`, and 22 modules across `llm/`, `task/`, `runner/` and `util/`): both limits sit at the exact current maximum, so every function above the new number was reshaped by responsibility rather than exempted. `_execution_loop` (20) became a loop over five named per-round phases (`_stream_one_round`, `_recover_from_stream_error`, `_resolve_deferred_requests`, `_retry_empty_completion`, `_finish_turn`); `handle_stream_error` (19) became a dispatch chain where each error class owns one handler and returns `None` to pass the error on; `LLMLimiter.to_str` (20) split by the type it flattens. Three table-driven functions are now tables: `_parse_hook_result`'s ten `if "key" in modifications` branches became a key→attribute map, `handle_special_cron_patterns`' `elif` chain a pattern→predicate map, and the lexer's SGR attribute codes two small dicts. `strip_to_text_only` and `_resolve_inner_task_config` were inflated by a nested `def` that mccabe sums into its enclosing scope; their helpers are hoisted rather than `# noqa`-ed. The three riskiest rewrites were checked side by side over generated inputs (`to_str` over 40 case/flag combinations, `_extract_args` over 20 placeholder strings, `handle_special_cron_patterns` over 9,280 pattern/datetime pairs) with identical results. `LLMChatTask.__init__` (radon 18) lost its fifteen `or []` guards to three `_init_*_surface` helpers, shrinking three facade budgets (`llm_task.py` 879 → 839, `chat/task.py` 1072 → 1068, `ui/base/ui.py` 1208 → 1200). Coverage stays at 94.2% and the per-commit gate at ~95s. The functions left at 15 are a broad tail across eight files; splitting further would be splitting to hit a number, which AGENTS.md's Code Style section rules out.
- **Refactor: task subclasses forward their parent's constructor keywords instead of re-declaring them** (`src/zrb/task/base/params.py`, `src/zrb/task/{cmd_task,rsync_task,scaffolder,scheduler,http_check,tcp_check,base_trigger}.py`, `src/zrb/llm/task/llm_task.py`, `src/zrb/llm/task/chat/task.py`, `test/architecture/test_constructor_surface.py`, `test/test_public_api_docs.py`, `test/public_api_snapshot.json`, `AGENTS.md`): nine task classes spelled out 163 parameters they only passed to `super().__init__`, each a place a child could drift from its parent, and a keyword added to `BaseTask` meant editing every subclass ("add print_fn to BaseTask" touched seven files, "Retire fstring and render_something/auto_render parameter" ten). The shared sets now live once as `TypedDict`s in `task/base/params.py`, and a subclass takes `**kwargs: Unpack[BaseTaskParams]`. Constructor parameters: `RsyncTask` 39 → 7, `LLMChatTask` 59 → 40, `LLMTask` 49 → 30, `CmdTask` 36 → 17, `Scaffolder` 25 → 6, `Scheduler` 24 → 3, `BaseTrigger` 24 → 4, `HttpCheck`/`TcpCheck` 15 → 5; the nine `__init__` bodies drop from 1021 lines to 486. Call sites are unchanged (`CmdTask(name="build", cmd="make", retries=0)` binds as before), and so is editor completion, verified through pyright's language server: `CmdTask(` offers all 35 keywords (15 own, 20 forwarded), `HttpCheck(` only its 14. A misspelled keyword is still a type error at the call site and a `TypeError` at runtime. Each deliberate narrowing is expressed twice, because a `TypedDict` binds only callers pyright sees and a hand-written `zrb_init.py` is not type-checked: `HttpCheck`/`TcpCheck` forward the narrower `CheckTaskParams` (no retry or readiness settings, since a check polls on its own `interval`), `RsyncTask` excludes `cmd`/`warn_unrecommended_command` (it builds its command by overriding `_get_cmd_script`), and both call a `reject_*_params` guard so an excluded keyword raises an explanatory `TypeError` instead of being accepted and ignored. `TcpCheck`'s and `RsyncTask`'s docstrings claimed to accept every `BaseTask`/`CmdTask` parameter while omitting ten and two; both now state what they exclude and why. `test_constructor_surface.py`'s fidelity tests have nothing left to check (`PARENT_OF` is empty); two structural tests replace them: a class in `FORWARDS_TO` may not re-declare a parent parameter, and must declare `**kwargs: Unpack[...]`. Deliberate shadowing is an explicit entry: `LLMChatTask` lowers `retries` to 0 via `kwargs.setdefault`, since pyright rejects a keyword parameter that also appears in the unpacked `TypedDict`. `test_public_api_docs.py` gains `test_a_forwarding_constructor_names_the_set_it_forwards`, because `help(CmdTask)` shows only `**kwargs`. Three constructors gave a forwarded keyword a different default inside `super().__init__` (`BaseTrigger` substitutes cyan and ✨ for `color`/`icon`; `LLMTask`/`LLMChatTask` default `retry_if` to `retry_unless_permanent` so a missing API key does not burn the retry budget). Each is now a `kwargs` fallback applied on the way in and has a test (only `LLMChatTask`'s was covered before).
- **Performance: `import zrb` drops from 258ms to 225ms** (`src/zrb/llm/tool/__init__.py`, `src/zrb/llm/tool/{ambient_state,ask,worktree}.py`, `src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/common_tools.py`): two eager-import paths ran on every CLI invocation, including `zrb --help`. First, `llm/tool/__init__.py` re-exported 12 modules eagerly, so `from zrb.llm.tool.file_read import read_file` cost 29 modules. It now resolves through PEP 562 `__getattr__`, as ADR-0096 does for `zrb.llm.agent`; the file tools resolve through `file.py` rather than their leaf modules, since `file.py` rewrites each one's `__name__` to the schema name the model sees (`Read`, `Write`, `Edit`). Second, `prompt/live_context.py` (eager via `prompt/manager.py`) reached `ask.py`, `worktree.py` and `plan.py` for ambient state, each importing `pydantic` for its tool signatures. The two `ContextVar`s (`interactive_mode`, `active_worktree`) now live in `tool/ambient_state.py`, which imports nothing heavier than `contextvars`, and `todo_manager` resolves at render time. Measured as the median of seven `python -X importtime` runs per revision; tool modules pulled by `import zrb` drop from 29 to 8. `pydantic.main` stays out of the closure as `test_eager_pydantic_models.py` requires.
- **Performance: LSP server detection is O($PATH) instead of O(servers × $PATH)** (`src/zrb/llm/lsp/configs.py`): `detect()` called `shutil.which` once per configured server, and every miss walks all of `$PATH` (21 servers against 53 entries, ~1100 stat calls, 788ms warm and 2.04s cold on WSL2 where 18 entries are `/mnt/c/...` mounts) on the `zrb llm chat` startup path. Detection now lists each `$PATH` directory once to prefilter, then calls `shutil.which` only on names that could match; `which` remains the authority on what is executable. 788ms → 44ms warm with an identical result; a one-shot `zrb llm chat` against a local server went from 6.0–10.3s to 3.2s. The `common_tools.py` comment calling this "a cheap shutil.which scan (no startup)" is corrected.
- **Improvement: `add_task`/`add_group` reject a wrong type instead of raising `AttributeError`** (`src/zrb/group/group.py`, `test/group/test_group.py`): `cli.add_task(my_function)`, the shape a reader expects to work and the one `@make_task` exists for, failed with `AttributeError: 'function' object has no attribute 'name'`, as did `None` or a string. Both methods now raise `TypeError` naming what was passed and the nearest thing that works: a callable is pointed to `@make_task` or `Task(action=...)`, anything else to building a task first. Pyright needs an ignore on both checks because the annotations already rule this out, but a hand-written `zrb_init.py` is not type-checked.
- **Improvement: `ZRB_INIT_STRICT` defaults to `auto`, which is strict wherever stderr is not a terminal** (`src/zrb/config/mixins/foundation.py`, `docs/configuration/env-vars.md`, `docs/advanced-topics/ci-cd.md`, `test/test_main.py`): the knob landed in 3.0.0 defaulting to `off`, an opt-in that unattended CI users were least likely to read about. Continuing past a broken init source only makes sense when someone reads the error, so a terminal stderr continues startup; anything else (CI, cron, a piped run) reports every failure and exits `1` rather than running a task against unfinished configuration. It resolves per read rather than at import, so a test can drive both sides. `ZRB_INIT_STRICT=1`/`off` still pin it either way, and `auto` is writable as the default's name.
- **Fix: the `Unpack` fitness checks were reading a CPython repr, and found nothing on Python 3.11** (`test/architecture/test_constructor_surface.py`, `test/test_public_api_docs.py`): both checks matched `"Unpack[" in str(annotation)`, but CPython renders that object as `*X` before 3.12, so on 3.11 `test_every_forwarding_subclass_declares_unpacked_kwargs` failed for all seven task classes and `FORWARDING_CLASSES` in `test_public_api_docs.py` came out empty, silently collecting zero of its nine cases. `llm_task.py` and `chat/task.py` use `from __future__ import annotations`, so their annotation is the string `'Unpack[BaseTaskParams]'`, which the old check matched only by accident. `_is_unpack` now handles both forms, and `test_forwarding_classes_were_actually_detected` fails when detection finds nothing. The forwarding itself was never broken: pyright at `pythonVersion 3.11` accepts `CmdTask(retries=0, print_fn=None)` and rejects `CmdTask(retrie=0)` and `HttpCheck(retries=3)`.
- **Docs: a fixed action vocabulary, and boolean names that read as questions** (ADR-0098, `AGENTS.md`): the R5–R7 collection verbs stop at collections, and the other 5,507 functions in `src/zrb` answer to 596 distinct leading tokens, 43% used once (nine verbs for "retrieve a value": `get` 375, `resolve` 68, `read` 28, `load` 25, `find` 19, `extract` 19, `collect` 11, `fetch` 4, `retrieve` 1; six for "produce"; six for "take out"). Only 153 of the 490 `-> bool` functions (31%) carry a boolean prefix. There is now one verb per meaning from a closed list, with `resolve` kept distinct from `get` because it names deferred-attribute evaluation (ADR-0005), and a `-> bool` function is named `is_`/`has_`/`should_`/`can_`/`needs_`. Adapted from [kettanaito/naming-cheatsheet](https://github.com/kettanaito/naming-cheatsheet), whose "avoid contractions" rule is rejected: `ctx` appears 363 times in user-facing docs as the parameter name in every user task, so expanding it would break every `zrb_init.py`. Deliberately not a fitness test: ADR-0097 names mutation kill rate as the property worth the next increment of test effort, and `test/architecture/` already carries 22 files and 89 hand-maintained allowlist entries.
- **Tests: a hang now fails as a hang** (`pyproject.toml`): added `pytest-timeout` with `timeout = 60`, leaving the method to the plugin's per-platform default (`signal` where SIGALRM exists, `thread` elsewhere). A mutation run found one flipped boolean turning a fast failure into a >20 minute stall that reads as a slow CI run.
- **Tests: mutation-kill-rate ratchet** (`scripts/mutation_ratchet.py`, `test/scripts/test_mutation_ratchet.py`, ADR-0097): coverage measures whether a line ran, not whether a test would notice it being wrong. Under a 94% coverage gate, 51 of 98 mutants were killed across four packages (`task/base` 56%, `util/cmd` 35%, `llm/skill` 60%, `llm/prompt` 56%); survivors included a process-tree snapshot that let SIGTERM-ignoring grandchildren leak and a constructor fallback that silently discarded a caller-supplied `skill_manager`. Each mutant runs only its package's mirrored tests. The ratchet scores a seeded sample per package against a `FLOORS` table in the same only-goes-up form as `FACADE_BUDGETS`, and runs on demand rather than from `zrb-test.sh`: a pass takes minutes, and the per-commit gate stays at 117s.
- **Tests: LSP detection tests now control `$PATH` instead of mocking `shutil.which`** (`test/llm/lsp/test_configs.py`): detection probes the filesystem twice (a listing per `$PATH` entry, then `which` on the survivors), so mocking only `which` describes an impossible world and would pass while the prefilter dropped every server. A `lsp_on_path` fixture installs real executable stubs on a `$PATH` holding only them. Breaking the prefilter in either direction now fails the suite; under the old mocks it did not.
