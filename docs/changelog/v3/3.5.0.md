## 3.5.0 (September 19, 2026)

- **Refactor: the complexity ratchets drop from mccabe 19 / radon 20 to 15 / 15** (`test/architecture/test_complexity_ratchet.py`, `test/architecture/test_facade_size_budget.py`, `docs/contributing/maintainer-guide.md`, and 22 modules across `llm/`, `task/`, `runner/` and `util/`): every function above the new limit was reshaped by responsibility rather than exempted — the agent's `_execution_loop` into five named per-round phases, `handle_stream_error` into a dispatch chain with one handler per error class, `LLMLimiter.to_str` by the type it flattens, and three branch chains (`_parse_hook_result`, `handle_special_cron_patterns`, the lexer's SGR codes) into tables. The riskiest rewrites were checked side by side over generated inputs (including 9,280 cron pattern/datetime pairs) with identical results. `LLMChatTask.__init__`'s fifteen `or []` guards moved into helpers, shrinking three facade budgets (`llm_task.py` 879 → 839, `chat/task.py` 1072 → 1068, `ui/base/ui.py` 1208 → 1200). Coverage stays at 94.2% and the per-commit gate at ~95s.
- **Refactor: task subclasses forward their parent's constructor keywords instead of re-declaring them** (`src/zrb/task/base/params.py`, `src/zrb/task/{cmd_task,rsync_task,scaffolder,scheduler,http_check,tcp_check,base_trigger}.py`, `src/zrb/llm/task/{llm_task,chat/task}.py`, `test/architecture/test_constructor_surface.py`, `test/test_public_api_docs.py`, `AGENTS.md`): nine task classes re-declared 163 parameters only to pass them to `super().__init__`, so a keyword added to `BaseTask` meant editing every subclass. The shared sets now live once as `TypedDict`s taken as `**kwargs: Unpack[BaseTaskParams]` (see AGENTS.md → Task Constructors). Constructor parameters: `RsyncTask` 39 → 7, `LLMChatTask` 59 → 40, `LLMTask` 49 → 30, `CmdTask` 36 → 17, `Scaffolder` 25 → 6, `Scheduler` 24 → 3, `BaseTrigger` 24 → 4, `HttpCheck`/`TcpCheck` 15 → 5; the `__init__` bodies drop from 1021 lines to 486. Call sites, editor completion and misspelled-keyword errors are unchanged. `HttpCheck`/`TcpCheck` (no retry or readiness settings) and `RsyncTask` (no `cmd`/`warn_unrecommended_command`) reject an excluded keyword with an explanatory `TypeError`, and their docstrings, which claimed every parent parameter, now state the exclusions. Changed forwarded defaults (`BaseTrigger`'s cyan/✨ `color`/`icon`, `retry_if` on `LLMTask`/`LLMChatTask`, `LLMChatTask`'s `retries=0`) are `kwargs` fallbacks, each tested.
- **Performance: `import zrb` drops from 258ms to 225ms** (`src/zrb/llm/tool/__init__.py`, `src/zrb/llm/tool/{ambient_state,ask,worktree}.py`, `src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/common_tools.py`, `docs/adr/adr-0096.md`): every CLI invocation, `zrb --help` included, paid for two eager-import paths. `llm/tool/__init__.py` now resolves its 12 re-exports lazily, as ADR-0096 does for `zrb.llm.agent`; the file tools resolve through `file.py`, which gives them their model-facing names (`Read`, `Write`, `Edit`). The `interactive_mode` and `active_worktree` `ContextVar`s moved to the dependency-free `tool/ambient_state.py`, so `prompt/live_context.py` no longer pulls in `pydantic`-importing tool modules. Tool modules loaded by `import zrb` drop from 29 to 8 (median of seven `python -X importtime` runs).
- **Performance: LSP server detection is O($PATH) instead of O(servers × $PATH)** (`src/zrb/llm/lsp/configs.py`): `detect()` ran `shutil.which` per configured server on the `zrb llm chat` startup path — 21 servers against 53 `$PATH` entries, 788ms warm and 2.04s cold on WSL2 with `/mnt/c/...` entries. It now lists each `$PATH` directory once to prefilter and calls `which` only on possible matches: 788ms → 44ms warm with an identical result, and a one-shot `zrb llm chat` against a local server went from 6.0–10.3s to 3.2s.
- **Improvement: `add_task`/`add_group` reject a wrong type instead of raising `AttributeError`** (`src/zrb/group/group.py`, `test/group/test_group.py`): `cli.add_task(my_function)`, the shape a reader expects to work and the one `@make_task` exists for, failed with `AttributeError: 'function' object has no attribute 'name'`, as did `None` or a string. Both methods now raise `TypeError` naming what was passed and the nearest thing that works: a callable is pointed to `@make_task` or `Task(action=...)`, anything else to building a task first. Pyright needs an ignore on both checks because the annotations already rule this out, but a hand-written `zrb_init.py` is not type-checked.
- **Improvement: `ZRB_INIT_STRICT` defaults to `auto`, which is strict wherever stderr is not a terminal** (`src/zrb/config/mixins/foundation.py`, `docs/configuration/env-vars.md`, `docs/advanced-topics/ci-cd.md`, `test/test_main.py`): the knob shipped in 3.0.0 defaulting to `off`. Under `auto`, a terminal stderr continues past a broken init source; anything else (CI, cron, a piped run) reports every failure and exits `1`. It is resolved on each read, not at import. `ZRB_INIT_STRICT=1`/`off` still pin it either way, and `auto` can be written explicitly.
- **Fix: the `Unpack` fitness checks were reading a CPython repr, and found nothing on Python 3.11** (`test/architecture/test_constructor_surface.py`, `test/test_public_api_docs.py`): both matched `"Unpack[" in str(annotation)`, which CPython renders as `*X` before 3.12, so on 3.11 one check failed for all seven task classes and the other silently collected zero of its nine cases. `_is_unpack` now handles both forms, including string annotations under `from __future__ import annotations`, and `test_forwarding_classes_were_actually_detected` fails when detection finds nothing. The forwarding itself was never broken.
- **Docs: a fixed action vocabulary, and boolean names that read as questions** (ADR-0098, `AGENTS.md`): one verb per meaning from a closed list, with `resolve` kept distinct from `get` for deferred-attribute evaluation (ADR-0005), and a `-> bool` function named `is_`/`has_`/`should_`/`can_`/`needs_`. At adoption, the 5,507 functions in `src/zrb` used 596 distinct leading tokens, 43% of them once, and only 153 of 490 `-> bool` functions (31%) carried a boolean prefix. Adapted from [kettanaito/naming-cheatsheet](https://github.com/kettanaito/naming-cheatsheet) minus its "avoid contractions" rule, since `ctx` is the parameter name in every user task. Review vocabulary, deliberately not a fitness test (see ADR-0098).
- **Tests: a hang now fails as a hang** (`pyproject.toml`): added `pytest-timeout` with `timeout = 60`, leaving the method to the plugin's per-platform default (`signal` where SIGALRM exists, `thread` elsewhere). A mutation run found one flipped boolean turning a fast failure into a >20 minute stall that reads as a slow CI run.
- **Tests: mutation-kill-rate ratchet** (`scripts/mutation_ratchet.py`, `test/scripts/test_mutation_ratchet.py`, ADR-0097): under a 94% coverage gate, 51 of 98 mutants were killed across four packages (`task/base` 56%, `util/cmd` 35%, `llm/skill` 60%, `llm/prompt` 56%); survivors included SIGTERM-ignoring grandchildren escaping SIGKILL and a silently discarded caller-supplied `skill_manager`. The ratchet scores a seeded sample per package against an only-goes-up `FLOORS` table and runs on demand rather than from `zrb-test.sh`: a pass takes minutes, and the per-commit gate stays at 117s.
- **Tests: LSP detection tests now control `$PATH` instead of mocking `shutil.which`** (`test/llm/lsp/test_configs.py`): mocking only `which` would pass while the prefilter dropped every server. An `lsp_on_path` fixture installs real executable stubs on a `$PATH` holding only them, so breaking the prefilter in either direction now fails the suite.
