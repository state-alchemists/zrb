## 3.41.0 (November 17, 2026)

- **Feature: one run can name the chat settings it starts with** (`src/zrb/builtin/llm/chat.py`, `src/zrb/builtin/llm/chat_flags.py`): `zrb chat` gained `--voice`, `--volume`, `--thinking`, `--profile`, `--memory`, `--self-review` and `--judge`, so a quieter voice, a cheaper thinking level or a session with no memory no longer costs an exported variable that outlives the try. One rule, the one `--sandbox` already followed: an empty flag leaves the deployment's value alone, a value overrides it for this run. Values are cast through `CFG` as `/set` casts them, so a flag and a command refuse the same strings; `--volume` is held to 0-200 rather than clamped, and `--profile` is checked against the profile names, because both would otherwise be accepted and silently do nothing.
- **Feature: a safe shell command can be auto-approved for one run** (`src/zrb/llm/approval/judge_state.py`, `src/zrb/llm/ui/default/output.py`): `--judge off|on|auto-approve` reaches the half of ADR-0141 that was a deployment setting only, as a command line typed in full rather than a keystroke. `/judge on` now withdraws that half for its own session, so a keystroke can move the judge towards asking and none can hand a prompt away, and the info bar says `AUTO` in the red pair when a `safe` verdict may skip the prompt.
- **Improvement: the approval prompt says what the judge saw** (`src/zrb/llm/agent/shell_judge.py`, `src/zrb/llm/tool_call/judge_note.py`): the judge line carried its level and one sentence, never the facts the judge was given, so a reader saw the conclusion without the basis. It now names the ones that raise the risk — `sandbox off`, a non-empty uncommitted count — and they come from the call's arguments and `git status` rather than from the model, staying silent where the sandbox is on and the tree is clean.
- **Documentation: ADR-0141 gains the launch grant and loses a stale consequence** (`docs/adr/adr-0141.md`): the record now says why a launch may reach the second grant where a keystroke may not, and its claim that the judge's tokens never reach `/usage` is corrected — they have been counted under `shell_judge` since `27ae01c34`.
