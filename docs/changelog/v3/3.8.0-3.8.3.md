## 3.8.0 (September 26, 2026)

- **Feature: an opt-in self-review gate reviews each file-changing turn before it ends** (`src/zrb/llm/hook/self_review.py`, `src/zrb/llm/prompt/markdown/self_review.md`, `src/zrb/llm/agent/run/turn_snapshot.py`, `src/zrb/llm/hook/turn_evidence.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/agent/run/turn_cursor.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/config/mixins/llm_content.py`, `docs/adr/adr-0100.md`, `docs/llm/hooks.md`, `docs/configuration/llm-config.md`): PR #534 needed three review rounds, each a CI finding the user pasted back into the chat. With `ZRB_LLM_SELF_REVIEW_ENABLED=on`, a synchronous Stop hook runs that review inside the turn. The runner snapshots the working directory at turn start and the gate diffs it against a second snapshot at Stop, so the review covers exactly what the turn changed (`Shell` edits and mid-turn commits included, the user's earlier uncommitted work excluded) in every repository under the directory: nested clones, submodules, a folder of repositories, and repositories the parent ignores (such as `EnterWorktree`'s worktrees). A repository that appears mid-turn is diffed against the commit it started from. Snapshots go to a private, owner-only temporary store deleted when the turn ends, so untracked files such as a `.env` never reach any `.git/objects`. The gate only reads that store and diffs in one of its own, so a cancelled turn deleting it mid-review cannot break the review; a directory too large to snapshot within git's 30-second cap is not retried for the rest of the process. A fresh-context reviewer agent gets that diff, not the author's transcript, and read-only `Read`/`Grep`/`Glob`. It is also given, to read, paths the file tools named that the diff does not cover, and files the turn left unreadable (not shown as deleted; a turn whose only change is one is still reviewed). Without a snapshot it gets those paths alone, never `git diff HEAD`, which would include the user's earlier uncommitted work. A closing `Request changes` blocks the Stop, so the agent checks each finding against the code, fixes the real ones, and restates its answer; `LGTM`, an unclear verdict, or a failed review never blocks. `ZRB_LLM_SELF_REVIEW_MAX_ROUNDS` (default 2) caps consecutive blocking reviews per turn, so concurrent sessions never reset each other's count; `ZRB_LLM_SELF_REVIEW_MODEL` picks a separate reviewer model; `ZRB_LLM_SELF_REVIEW_TIMEOUT` (default 240s) bounds each whole review: git commands are killed at the deadline, and the reviewer is cancelled inside the hook's own event loop so its model request stops. A delegated sub-agent's run is not reviewed on its own; the parent's diff covers it. The Stop payload gains `turn_start_snapshot`, `changed_paths`, `run_scope`, `turn_id` and `nested_run` for any hook that needs the turn's scope.
- **Improvement: `/rewind` snapshots are git trees in a private store, on by default, and cover nested repositories** (`src/zrb/util/git/snapshot_listing.py`, `src/zrb/util/git/snapshot_store.py`, `src/zrb/util/git/snapshot_command.py`, `src/zrb/llm/snapshot/manager.py`, `src/zrb/util/file_lock.py`, `docs/adr/adr-0101.md`, `docs/configuration/llm-config.md`, `docs/llm/llm-custom-ui.md`): each snapshot used to copy the whole project into a per-session shadow folder (994 MB across 11 sessions here) and the TUI waited for the first copy. A snapshot is now a tree in one private bare repository per directory under `ZRB_LLM_SNAPSHOT_DIR`, one ref per conversation, listed per repository by its own `.gitignore` (nested repositories and submodules included) and hashed in the background: the first snapshot takes 0.58 s and 9 MB instead of 1.2 s and 85 MB, a later one 0.02 s. **Default change:** `ZRB_LLM_ENABLE_REWIND` is now `on`; outside every repository a directory over 5,000 files or 200 MB, an unwritable store, missing git, or a directory too slow to hash turns rewind off for the session and `/rewind` says why. **Behaviour change:** gitignored files (a `.env`, build output) are no longer snapshotted or restored. Old shadow folders are not migrated and can be deleted. Restore is byte-exact, removes a file only when the snapshot recorded it absent, never touches `HEAD`, an ignored path or anything it cannot read, and reports what it left behind (`RestoreOutcome`) instead of failing the rewind. Rewind history follows the conversation through `/load` and `/save`, and snapshots and restores of one directory take turns under an OS lock across processes. The full rules are in ADR-0101.
- **Breaking: `SnapshotProgress` drops its `copied` field, and `restore_snapshot` returns a `RestoreOutcome`** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/default/lifecycle.py`): `copied` counted files copied into the shadow folder, which no longer exists, so it has no successor; a progress handler that unpacks the event by position (`stage, copied, skipped, reason = event`) fails, while one reading `event.stage`, `event.skipped` and `event.reason` keeps working. `restore_snapshot` returned a bool and now returns `RestoreOutcome(restored, left_behind)`, naming the files a refused write left behind; it is truthy exactly when the restore ran, so `if await manager.restore_snapshot(sha):` reads as before.
- **Improvement: `core-coding` checks the two places the #534 defects hid** (`src/zrb/llm_plugin/core_skills/core-coding/SKILL.md`): the discovery step's requirement to find call sites before a signature change now covers data formats and promised behavior too, naming the readers people forget (a parser, a cleanup routine, a migration). The validation step adds that a promised invariant must hold for state written before the change, and that a doc or docstring line is such a promise.
- **Fix: the retry summary no longer pairs one tool call's arguments with another's result** (`src/zrb/llm/agent/run/partial_run.py`, `test/llm/agent/run/test_partial_run.py`): `PartialRunAccumulator` held a single "current call" slot and matched results by tool name. Parallel calls stream every `ToolCallEvent` before any result, so two parallel `Read`s became one entry (the second call's arguments beside the first call's content) and the second was dropped; the `[SYSTEM: PREVIOUS ATTEMPT FAILED]` block then told the model it had read files it had not, and vice versa. Pending calls are now keyed by `tool_call_id`, and the test that pinned the dropped call as intended now asserts both survive. The summary also says its results are cut at 500 characters and that an interruption is usually the user's, so the model follows the user's new message instead of resuming the interrupted approach.
- **Fix: retitling or revising a journal note no longer leaves a contradicting duplicate in the indexes** (`src/zrb/llm/tool/journal_write.py`, `test/llm/tool/test_journal_notes.py`, `test/llm/tool/test_journal_backlinks.py`; the `SearchJournal` tests moved to `test/llm/tool/test_journal.py` to keep the notes file under the 500-line split rule): index registration skipped only an identical `- [label](target)` line, so a new title added a second entry for the same file, and `hud_line` appended rather than replaced, so a revised finding sat beside the stale one in the always-injected index. Index lines are now keyed by link target: the first line for a note is relabelled in place and later ones (including duplicates left by earlier retitles) are dropped. A HUD line carries a trailing link to its note, which a revision uses to replace the note's earlier line and `DeleteJournalNote` uses to scrub it. HUD lines pinned before this release have no link, so they are neither replaced nor scrubbed; they age out under `LLM_JOURNAL_HUD_MAX_ENTRIES_PER_SECTION` (default 20). Matching them by text was rejected, since it could delete a different fact.
- **Improvement: the journal index says how the journal may be changed** (`src/zrb/llm/prompt/live_context.py`, `docs/adr/adr-0055.md`): the journal tools are registered with `defer_loading`, so their docstrings, where ADR-0055 put the journal's rules, are invisible until the model searches for them. One session edited the journal with Read/Edit for twenty calls, then patched the resulting duplicates by hand, leaving uncommitted changes. The `<journal-index>` header now names the three writers, says a direct edit breaks their index, backlink and git bookkeeping, and says to search for them when not visible. The writers' docstrings add the same rule for a model that searched first, record only what the session verified, and drop the unconditional "do not announce it", which contradicted reporting the outcome when the user asked for the write. A zero-hit `SearchJournal` is now described as weak evidence of absence.
- **Improvement: the prompt ranks truth above speed and resolves the ask-versus-proceed conflict** (`src/zrb/llm/prompt/markdown/{principle,workflow,profile.standard,profile.capable}.md`): `principle` states one priority order (protect the user's work, then truth, then completeness, then speed) and adds two rules: a claim about something not seen (a prior version, a diff not in hand) is inference to label or omit, and a diagnosis must re-read what it blames. Workflow step 4 requires reading what a check printed and treating contradicting output as unverified; step 5 reports what was not verified. Tool Discovery's closing "do not search for what visible tools already cover" let a model decide Read/Edit covered journaling despite the bullet naming it; the bullet now says a generic tool approximating a dedicated one does not count, and the exemption is narrowed to a visible tool plainly right for the job. `profile.standard` said to raise risks "rather than pausing on them" while `principle` requires confirmation before destructive actions; it now names both stopping conditions. Both profiles activate methodologies on what the *work* matches, the condition the workflow states.
- **Improvement: the agent pursues the goal when the direct route is closed, and the prompt says it in fewer words** (`src/zrb/llm/prompt/markdown/{principle,workflow,profile.standard,example}.md`): asked for the weather "at my current location", an agent replied it had no GPS and asked for the city; told "try your best", it found the location from the network and answered in three tool calls. `principle` now says to try the next-best evidence before handing the question back, and limits asking the user to what no available tool can supply or a decision that is theirs; `profile.standard` counts "find out with your tools" among what the agent must exhaust before stopping, and Tool Discovery's last trigger widens from "about to report a capability does not exist" to "about to say something cannot be done". `example.md` trades the library-changelog example, whose lesson `principle` already states, for this one, and compresses the LaTeX/mermaid rendering example without dropping either rule. Removed as redundant: the sentence restating the priority order, workflow's "use reliable sources" (covered by `principle`), and the skill-batching paragraph (covered by workflow step 2). The always-on sections shrink from 1,341 to about 1,290 words while gaining a rule and an example.
- **Fix: the project-documentation listing no longer points at a section that does not exist** (`src/zrb/llm/prompt/claude.py`, `test/llm/prompt/test_claude.py`, `docs/adr/adr-0047.md`): **Documentation Files Found** said "See Project Documentation for when to read these", and **User-Level Guidance** said "not part of the mandatory read", both referring to a prompt section removed in August. Given a file list and a pointer to absent rules, an agent read every file, including a one-line `CLAUDE.md` that only imports `AGENTS.md`. The listing now states its own rule: the files are not loaded into the prompt; read the ones that bear on the work before editing; they outrank user-level guidance. The journal writers' docstrings also shed prose the model never needed (`DeleteJournalNote`'s defence of textual scrubbing over graph bookkeeping lives in ADR-0055) without dropping any instruction.
- **Fix: a cancelled or timed-out synchronous hook stops instead of running on** (`src/zrb/llm/hook/executor.py`, `test/llm/hook/test_executor.py`, `docs/llm/hooks.md`): the executor runs a synchronous hook in its own event loop on a pool thread, and on timeout, or when its caller was cancelled (the user cancels the turn), it only stopped waiting, so the hook ran to its end: an agent hook's model request, a command hook's process for up to its 600-second default. It now cancels the hook inside that loop and waits up to `cancel_grace_seconds` (default 5) for it to finish, after which a hook blocked in a synchronous call is left to finish with a warning. A command hook's process is thus killed and the self-review reviewer stops before the turn goes on; the gate also resolves its scope through `run_in_worker`, so a cancelled review starts no further git command and deletes its store before returning.
- **Fix: a journal title containing `]` no longer survives its own delete, and one note's pinned line no longer replaces another's** (`src/zrb/llm/tool/journal_write.py`, `test/llm/tool/test_journal_notes.py`, `test/llm/tool/test_journal_backlinks.py`, `docs/adr/adr-0055.md`): a note's title is free-form model text, so `Fixes [nested] brackets` matched no line where `_register_link` and `_scrub_links_to` read a label as `[^\]]*`: retitling such a note registered a second index entry beside the first, and deleting it left its category and root index entries, and every backlink to it, pointing at a file that was gone. Labels are now matched greedily with the target taken from the end of the line. `_upsert_hud_line` also keyed its replacement on the note's path appearing anywhere in a line, so revising one note dropped another's pin that merely cited it, and two notes compressing the same fact (`projects` and `technical` share a section) kept one pin between them; it now matches the whole trailing ` ([note](path))`, the key ADR-0055 specifies, and a hand-pinned line with no note link is left to the section cap.
- **Fix: a synchronous hook runs in the caller's context, so the self-review gate reviews on the run's model** (`src/zrb/llm/hook/executor.py`, `test/llm/hook/test_executor.py`, `docs/contributing/maintainer-guide.md`): `ThreadPoolHookExecutor` submitted the hook to a pool thread, which starts with an empty `contextvars.Context`, so every per-run value the turn had set (`current_model` among them) was gone, and the gate's reviewer resolved `CFG.LLM_MODEL` rather than the run's own model, whatever `--model` or a `/model` switch had chosen; with `ZRB_LLM_MODEL` unset every review failed and the gate was silently off. Dispatch now copies the caller's context and runs the hook inside it, less the UI, the tool confirmation and the approval channel, which belong to the caller's event loop and cannot be driven from the hook's own, so a hook tool falls back as before.
- **Fix: `/save` carries the conversation's rewind history to the new name, before any snapshot of it can land** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/base/conversation_commands.py`, `test/llm/snapshot/test_manager_copies.py`, `test/llm/snapshot/test_manager_store.py`, `test/llm/ui/base/test_base_ui_conversation_commands.py`, `docs/adr/adr-0101.md`): `copy_history` queued the copy for the next snapshot to apply, and a copy that failed stayed queued, failing every later snapshot until a restart. It now registers the copy when called, before `/save` switches the session to the new name, so no snapshot of that name can land first and be overwritten, not even one a queued message starts in the same task; it returns a coroutine that applies the copy at once, which a custom UI should run (left unawaited, the next operation applies it). A copy git refuses is dropped with a warning. A copy of a copy not applied yet takes that copy's source when registered, so a later `/save` over the name in between cannot change it. The copy is kept in memory only: a session that ends before it lands (possible only while another process holds the store) leaves the saved name with no rewind history, its chat history saved either way. A record of pending copies beside the store, which a later session would apply, was built and dropped: each process interleaving needed a guard of its own, and it covered only that one corner (ADR-0101).
- **Fix: a rewind operation is bounded as a whole, and a cancelled one stops waiting for the store** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/util/file_lock.py`, `src/zrb/util/git/snapshot_command.py`, `test/llm/snapshot/test_manager_concurrency.py`, `test/util/test_file_lock.py`, `docs/adr/adr-0101.md`): each git command has a 30-second cap, but the sequence around it did not, so a directory too large to hash held a turn up one command at a time and failed only at the end. Once it holds the store's lock, every operation (the listing's walks, every command) now runs within `LLM_SNAPSHOT_OPERATION_TIMEOUT` (120 s), and running out is a `SnapshotTimeoutError`, which turns rewind off for the session. The wait for the lock, at most `LLM_SNAPSHOT_LOCK_TIMEOUT` (60 s), comes before the budget rather than out of it: a store another process holds is contention, and must not turn rewind off as a directory too slow to snapshot. The wait watches the worker's cancellation, so a turn the user cancelled no longer sits it out. A cancelled caller raises `SnapshotCancelledError`, a `SnapshotError` that says nothing about the store: cancelled while the store was being set up (waiting for its lock, or in `git init`), an operation used to mark the store unusable and turn rewind off for the rest of the session. `hold_file_lock` takes the `cancel` event, checked before every attempt to take the lock, the first included, so a caller cancelled already never holds even a free one, and raises `FileLockCancelled`.
- **Improvement: a working directory outside every repository says its rewind is shallower than usual, and a missing git says nothing at startup** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/default/lifecycle.py`, `test/llm/snapshot/test_manager_taking.py`, `test/llm/snapshot/test_manager_availability.py`, `test/llm/ui/default/test_lifecycle.py`, `docs/adr/adr-0101.md`): the store lists loose files there, up to its budget, and no ignore rule applies (a `.gitignore` such a directory holds means nothing to git either), so a rewind there reaches less far than one in a repository, and the chat said nothing about it. The first snapshot of such a conversation now carries one `notice` progress event, which the TUI folds into the snapshot's own line (`✅ Initial workspace snapshot taken (no git repository here, …)`). Without git on `PATH` rewind is off from the start with `GIT_MISSING_REASON`, which the TUI does not print (it is not news every session), and `/rewind` still says why.
- **Improvement: rewind, chat history and task session logs no longer grow without end** (`src/zrb/llm/snapshot/manager.py`, `src/zrb/util/git/snapshot_store.py`, `src/zrb/llm/history_manager/file_history_manager.py`, `src/zrb/session_state_logger/file_session_state_logger.py`, `src/zrb/session_state_logger/session_state_logger_factory.py`, `src/zrb/util/string/name.py`, `src/zrb/config/mixins/{llm_content,foundation}.py`, `test/llm/snapshot/test_manager_housekeeping.py`, `test/util/git/test_snapshot_store_{restore,lifecycle}.py`, `test/llm/history_manager/test_file_history_manager_retention.py`, `test/session_state_logger/test_file_session_state_logger_retention.py`, `docs/adr/adr-0101.md`, `docs/configuration/llm-config.md`): with rewind on by default, every untracked file a turn saw went into `~/.zrb/llm-snapshots` and stayed there, as did every conversation's snapshots, and the chat histories and task session logs beside them were never pruned either. Three retention knobs, in the `TODO_RETENTION` duration format, with `0` keeping everything: `ZRB_LLM_SNAPSHOT_RETENTION` (30d) drops a conversation's rewind history once its newest snapshot is that old, never the current one's, when a session starts in the same directory, and `git gc --auto` then packs the store and, detached, prunes what no history holds (a timed-out snapshot's objects included); `ZRB_LLM_HISTORY_RETENTION` (30d) prunes a conversation's history and backups on the first save of a session, but only an auto-named one (`bold-arch-1234`, `is_random_name`); a conversation named with `/save` or a session name of your own is kept, and a name typed in the generated shape is indistinguishable from one; `ZRB_SESSION_LOG_RETENTION` (30d) prunes task session logs and their timeline entries, at most once per `ZRB_SESSION_LOG_PRUNE_INTERVAL` (1d) per directory, since every `zrb` command is a process of its own. A file over `ZRB_LLM_SNAPSHOT_FILE_MAX_MB` (50) is left out of every snapshot as if ignored (a restore neither writes over it nor removes it, and self-review does not diff it), so a dataset nobody ignored is not copied into the store in full. The store's `info/attributes` is rewritten only when it differs, and by rename: another process's snapshot hashing while it was truncated would have seen no byte-exact rule and let the project's git-lfs filter store a pointer.
- **Fix: a Stop hook fired as the chat exits gets to finish** (`src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/default/lifecycle.py`, `test/llm/ui/base/test_base_ui_surface.py`, `test/llm/ui/default/test_lifecycle.py`, `docs/llm/hooks.md`): Ctrl+C fires Stop fire-and-forget and exits, and teardown cancelled every background task, so now that a cancelled synchronous hook really stops, a slow "done" notification was killed mid-run. `BaseUI` tracks its hook tasks (`hook_tasks`), `on_exit` leaves them running, and teardown gives them `ZRB_HOOKS_EXIT_TIMEOUT` (10000 ms) through `drain_hook_tasks` before cancelling the rest with a warning.
- **Fix: the self-review round cap is per turn, and a sub-agent continued from the TUI is not reviewed on its own** (`src/zrb/llm/hook/self_review.py`, `src/zrb/llm/agent/run/{runner,turn_cursor}.py`, `src/zrb/llm/agent/subagent/live_session.py`, `test/llm/hook/test_self_review.py`, `test/llm/agent/run/test_runner_lifecycle.py`, `test/llm/agent/subagent/test_live_session_continuation.py`, `docs/llm/hooks.md`): the gate counted blocking reviews by `run_scope`, which is the conversation's name, so two sessions under one name shared a count, and a turn that ended mid-continuation (cancelled, capped) left its entry for good. The Stop payload gains `turn_id`, unique per turn, which the gate keys on, keeping at most `ZRB_LLM_SELF_REVIEW_MAX_TRACKED_TURNS` (64) counts. A message sent to a finished sub-agent from the TUI started a run no parent was bound to, so it took its own turn snapshot and was reviewed as a top-level run; `run_agent` takes `nested`, and the continuation passes `nested=True`.
- **Fix: a revised journal HUD line replaces a pre-3.8 line reading exactly as it does** (`src/zrb/llm/tool/journal_write.py`, `test/llm/tool/test_journal_notes.py`): HUD lines pinned before this release carry no note link and are left for the section cap to retire, but one with the very text of the new line is the same fact, and was left beside it as a duplicate.
- **Improvement: every limit this release adds is a `CFG` knob, read when it applies** (`src/zrb/config/mixins/{llm_content,hooks}.py`, `src/zrb/util/git/{snapshot_listing,snapshot_store,snapshot_command}.py`, `src/zrb/llm/snapshot/manager.py`, `src/zrb/llm/ui/default/lifecycle.py`, `docs/configuration/llm-config.md`, `docs/llm/hooks.md`, `docs/adr/adr-0101.md`): the limits were module constants, so changing one meant patching zrb. They are now `ZRB_LLM_SNAPSHOT_FILE_MAX_MB` (50), `ZRB_LLM_SNAPSHOT_LOOSE_MAX_FILES` (5000), `ZRB_LLM_SNAPSHOT_LOOSE_MAX_MB` (200), `ZRB_LLM_SNAPSHOT_COMMAND_TIMEOUT` (30 s), `ZRB_LLM_SNAPSHOT_OPERATION_TIMEOUT` (120 s), `ZRB_LLM_SNAPSHOT_LOCK_TIMEOUT` (60 s), `ZRB_LLM_SELF_REVIEW_MAX_TRACKED_TURNS` (64), `ZRB_SESSION_LOG_PRUNE_INTERVAL` (1d) and `ZRB_HOOKS_EXIT_TIMEOUT` (10000 ms, like `ZRB_HOOKS_TIMEOUT`), each read at the listing, command or operation it bounds, never at import, so `CFG.LLM_SNAPSHOT_FILE_MAX_MB = 200` in `zrb_init.py` takes effect for the next snapshot. The module constants they replace (`LARGE_FILE_BYTES`, `LOOSE_FILE_LIMIT`, `LOOSE_BYTE_LIMIT`, `GIT_COMMAND_TIMEOUT_SECONDS`, `STORE_LOCK_TIMEOUT_SECONDS`, `SNAPSHOT_OPERATION_TIMEOUT_SECONDS`) are gone. `LLM_ENABLE_REWIND`'s help text names the knobs instead of printing the values it was imported with.
- **Refactor: comment and duplication cleanup across `src/zrb`, no behavior change**: narrating and restating comments were compressed to their reason (ADR references kept), and repeated logic now lives in one place: `focus_widget`/`invalidate_app` (`src/zrb/llm/ui/default/app/focus.py` new), `take_pre_turn_snapshot` (`src/zrb/llm/ui/turn_snapshot.py` new), `rebase_tracked_spans` (`src/zrb/llm/ui/output_chunk.py`, shared by `UIOutput` and `BufferedUI`), `get_shell_flag` (`src/zrb/util/cmd/command.py`), `start_process` (`src/zrb/llm/tool/shell.py`, now also used by the worktree tools), one search-backend path in `src/zrb/llm/tool/web.py`, and one pull/push loop in `src/zrb/builtin/git_subtree.py`. The ADRs, v3 changelog and guides were tightened the same way, and 12 broken same-page anchors were fixed.

## 3.8.3 (September 26, 2026)

_Cumulative summary of the 3.8.1–3.8.3 patch line._

- **Fix: interrupts exit the way the shell expects** (`src/zrb/__main__.py`, `src/zrb/runner/cli.py`): Ctrl+C exits `130` instead of `0`, so `zrb build && zrb deploy` no longer deploys after an interrupt, and `SIGTERM` (`docker stop`, systemd, CI cancellation) takes the same cancellation path, stops the running command and exits `143`. A systemd unit that should treat that as a clean stop needs `SuccessExitStatus=143`. `Task.run()` still returns `None` on interrupt.
- **Fix: pipes work in both directions** (`src/zrb/builtin/llm/chat.py`, `src/zrb/runner/chat/chat_session_runner.py`, `src/zrb/input/base_input.py`, `src/zrb/input/option_input.py`): `echo "..." | zrb llm chat` takes the piped text as its message (`--interactive` defaults to whether stdin is a terminal); without a terminal an input prompt goes to stderr, so stdout carries only the result; `OptionInput` rejects a value outside its `options` from every source, not only the interactive prompt.
- **Fix: colour follows the terminal** (`src/zrb/util/cli/style.py`, `src/zrb/llm/ui/default/app/redirection.py`): styling is off when neither stdout nor stderr is a terminal, any non-empty `NO_COLOR` disables it and `FORCE_COLOR` enables it (`is_color_enabled`); the chat TUI, which captures its own output through a pipe, keeps the decision made before the capture (`set_color_enabled`).
- **Fix: journal writes lock on Windows** (`src/zrb/llm/tool/journal_write.py`): the lock was an `fcntl.flock` that did nothing on Windows; it now uses `util/file_lock.hold_file_lock` on every platform.
- **Improvement: clearer messages** (`src/zrb/llm/agent/run/error_classifier.py`, `src/zrb/runner/cli.py`, `src/zrb/util/truncate.py`): a missing API key explains which provider `<PREFIX>_LLM_API_KEY` is sent to; the "To run again" line drops empty flags that match an empty default; truncated previews cap at their limit including the ellipsis (`truncate_display`).
- **Refactor: duplicated logic consolidated** (`src/zrb/llm/util/layered_registry.py`, `src/zrb/llm/ui/tracked_spans.py`, `src/zrb/llm/util/roster.py`): `SkillRegistry` and `SubAgentRegistry` compose one `LayeredRegistry`, `BufferedUI` and `UIOutput` share `TrackedSpans`, and a dozen smaller copies (`get_first_heading`, `cap_items`, `render_indented_diff`, the hook loader's directory walk, ...) became one function each; public API unchanged.
- **Documentation: docs match the code** (`AGENTS.md`, `docs/`, `test/architecture/test_constructor_surface.py`): `LLMTask`/`LLMChatTask` constructor docs agree (a test now fails when a shared parameter's docs diverge), the documented coverage floor is the enforced 95%, the CI guide lists exit codes and piped-stdin behaviour, and internals moved from the maintainer guide to `docs/technical-specs/`.
