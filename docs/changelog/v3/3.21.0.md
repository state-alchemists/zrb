## 3.21.0 (October 15, 2026)

- **Behavior change: `Speaker.speak()` raises when nothing was said** (`src/zrb/llm/speech/player.py`, `test/llm/speech/test_player.py`): a direct `speak()` call used to log a failure and return as if it had spoken, so a caller such as zrb-extras' `speak` tool told the model it had talked when it had not. It now raises `RuntimeError` naming each backend's failure when no backend made the speech, `FileLockTimeout` when another session held the audio device, or the player's own error. Blank, stale, muted and interrupted text is still skipped without error. The queued path (`say()`, the chat's spoken replies) still logs and carries on, and `play()` now raises too, leaving the logging to that queue.
