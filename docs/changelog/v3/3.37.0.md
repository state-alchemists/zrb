## 3.37.0 (November 8, 2026)

- **Breaking: the UI contract is five roles, and each one is reached through an accessor** (`src/zrb/llm/ui/any_ui.py`, `src/zrb/llm/ui/any_ui_{display,input,picker,session,tools}.py`, `src/zrb/llm/ui/base/display.py`, `src/zrb/llm/ui/fallback/defaults/{display,input}.py`, `src/zrb/llm/ui/multi/`, `src/zrb/llm/ui/default/picker.py`, `docs/adr/adr-0140.md`, `docs/llm/llm-custom-ui.md`, `docs/advanced-topics/upgrading-guide.md`, `test/architecture/test_ui_contract_roles.py`): `AnyUI` was fifty-five names doing five unrelated jobs — writing output, holding the conversation's state, asking the user, rendering a choice, tracking a tool call — and `BaseUI` implemented all of them in one class of 141 method definitions, so a backend that wanted to change how a choice is asked accepted the other four. The contract is now five ABCs (`AnyUIDisplay` 21 members, `AnyUISession` 15, `AnyUIInput` 10, `AnyUITools` 5, `AnyUIPicker` 1) composed into `AnyUI`, and every role is handed out rather than inherited: what a caller sees on a `ui: AnyUI` drops from 55 to 9. The display role is the only one with a body of its own, because everything it writes is derived from two primitives it forwards to the host; `ui.session`, `ui.input` and `ui.tools` return the UI itself, so a subclass that overrides `ask_user` or `yolo` still wins, `super()` included, and `MultiUI`/`BufferedUI` keep answering for the child they wrap. **Breaking:** a class implementing `AnyUI` directly adds the five accessors — one line each, for a UI that is its own writer and its own input side — and a `BaseUI` subclass that overrode `append_markdown`, `last_output`, `replay_history` or a block marker now overrides it on the display part. `UIStateDefaultsMixin` supplies all five accessors plus an inert default for every member a UI leaves out, which is what keeps `StdUI`, `BufferedUI` and a console-less run working; `pending_answer_since` joins the input role, since dictation read it off three implementations and no contract.
- **Breaking: `zrb.llm` is organised by the package each module belongs to** (`src/zrb/llm/ui/`, `src/zrb/llm/shared/`, `src/zrb/llm/agent/`, `src/zrb/llm/subagent/`, `src/zrb/llm/tool/`, `src/zrb/llm/hook/`, `src/zrb/llm/dictation/backend/pipecat/`, `src/zrb/llm/speech/backend/pipecat/`, `src/zrb/llm/lsp/`, `src/zrb/llm/prompt/live_context/`, `AGENTS.md`, `docs/advanced-topics/upgrading-guide.md`): the module tree mirrored the order things were written rather than the shape of the system. The UI contracts sat at the top of `zrb.llm` beside `agent_state` and `usage_log`, the fallback pieces in a sibling `ui_fallback/`; thirty-two flat tool modules carried their domain as a name prefix (`file_read`, `shell_background`), so changing how a file is read meant finding the file tools by reading the directory listing; and `hook/` was eighteen modules holding the vocabulary, a parser, subprocess plumbing, two shipped hooks and the manager. Each is now a package: the six `any_ui*` contracts in `zrb.llm.ui` with the fallback in `ui/fallback/`, the fourteen layer-0 leaves in `zrb.llm.shared`, the agent and sub-agent contracts in the packages that name them, the tools grouped as `file/`, `delegate/`, `shell/`, `plan/`, `web/` and `code/` (a single-module tool stays a module), `hook/` as `contracts/`, `execution/`, `builtin/` and `manager/`, and one-module-per-job packages for the pipecat backends, the usage commands, the LSP, sub-agent and live-context facades, `buffered/`, `event_driven/` and `MultiUI`. Facades that became packages keep their own path, so `zrb.llm.tool.file`, `zrb.llm.hook.manager` and `zrb.llm.ui` resolve as before. **Breaking:** five paths are gone rather than moved, because a shim at each would rebuild the clutter this removes — `zrb.llm.any_ui`, `zrb.llm.ui_fallback`, `zrb.llm.hook.interface`, `zrb.llm.any_agent` and `zrb.llm.ui.std_ui` — and the upgrading guide carries an old-to-new table for every move, written as the moves landed rather than reconstructed here.
- **Improvement: the `Any` annotation ratchet falls from 1031 to 615** (`src/zrb/llm/agent/`, `src/zrb/llm/tool/`, `src/zrb/llm/hook/`, `src/zrb/llm/task/`, `src/zrb/llm/runner/chat/`, `test/architecture/test_any_annotation_ratchet.py`): six passes replaced the `Any` at each layer's boundary with the type that actually travels there — a history is `list[ModelMessage]`, a hook payload is `object` narrowed where a key is read, a tool argument bag is `dict[str, object]`, a deferred call's verdict is `ToolApproved | ToolDenied | None` — and `llm/tool` and `llm/hook` reach zero. `Any` stays where it is honest: a model's output chosen by `output_type` at runtime, and a tool's own return value. The model-facing half changed not at all, which was checked rather than assumed: every touched tool's `function_schema.json_schema` and `return_schema` were dumped on both branches and are byte-identical, 364 lines, because an `object` annotation generates the same schema as `Any`. Four contracts that were spelled out inline, or not at all, now have names — `ToolFactory`, `ModelAttr`, `UIFactory`, `SessionRunArgs`, `FileMatch`, `TodoDocument`, `DelegationTask`, `BackgroundProcessRow` — each beside the code that makes it true. Typing it found three annotations that promised what the code did not keep: the chat route's `handle_response` was declared to take text and was handed a decoded dict whenever an image edit arrived, which made its own `isinstance` guard dead code; `ui_factory` was declared to return an `AnyUI` while both runner paths branch on a list; and `capabilities` accepted a capability written for deps the run never supplies. The aliases live behind `TYPE_CHECKING`, so the layering ratchet sees no new runtime edge.
- **Feature: every tool that acts says what the call is for, and the schema requires it** (`src/zrb/llm/tool/purpose.py`, the 22 tool modules that carry it, `src/zrb/llm/speech/progress.py`, `test/llm/tool/test_purpose.py`, `test/llm/test_common_tools.py`): `purpose` was optional (`= ""`) on all twelve tools that declared it, so a model could leave it out and did — and the narrator then fell back to the phrase map, which names the arguments: "Editing llmtask.py." True of every call of that tool and of none of them. What a listener cannot infer is the intent, and only the model knows it. `requires_purpose` moves the parameter to the front without a default, which is the shape pydantic-ai reads from `inspect.signature` into the schema the model sees, while the Python default stays because nothing in a tool's body reads it — a test or another tool calls these functions directly. Applied to 22 tools; `Read`, `Grep`, `Glob`, `LS`, `SearchMemory`, `ListWorktrees`, `ListZrbTasks` and `MonitorProcess` gained the parameter, and the description now says to give the intent and never the arguments. The guard is `test_every_tool_outside_the_harness_says_what_the_call_is_for`: every registered tool whose capability is not `Capability.META` must require one. The language-server tools are exempt as a group, because `zrb.llm.lsp` may not import `zrb.llm.tool` where the alias lives; giving them one starts with moving the alias to a leaf.
- **Security: a pull request cannot run its own review with the model key** (`.github/workflows/code-review.yml`, `test/architecture/test_ci_workflows_are_not_pr_editable.py`): the review job ran on `pull_request` with the model key in its environment and executed the contributor-editable `zrb_init.py` — the step that posts the comment included. It now runs on `pull_request_target`, checks out the base branch by name, fetches the head only as git objects, wraps the run in `::stop-commands::`, and pins every action to a commit. Four rules in a guard test hold the shape rather than the intention: a secret beside `pull_request`, a head checkout, an unpinned action, and a `-latest` runner label.
- **Improvement: CI names its runner images, and the Poetry cache key names the image** (`.github/workflows/test.yml`, `test/architecture/test_ci_workflows_are_not_pr_editable.py`): the matrix asked for `ubuntu-latest` and friends, so the interpreter, the OS and the shell underneath could change on a Tuesday with no diff to show for it. The rows now name `ubuntu-26.04`, `windows-2025-vs2026` and `macos-26`, and the image is part of the poetry cache key — a venv restored onto another OS or interpreter patch fails as `ImportError: cannot import name 'OpenAIProvider'`, which reads like a defect in the code and is not one; it cost two CI runs and a cache purge to establish that. Per-row `test-args` replace the conditional steps, so Windows and macOS skip pyright and the coverage gate by argument rather than by a branch in the YAML.
- **Fix: the credential hint can no longer replace the error it decorates** (`src/zrb/llm/agent/run/error_classifier.py`, `src/zrb/llm/agent/common.py`): `add_credential_hint` wraps `create_agent`'s `except Exception`, and it imports `openai` and `pydantic_ai` to tell a missing key from any other failure. Both imports are lazy and heavy, and either can raise `ImportError` for reasons unrelated to the error being reported — a `sys.modules` entry shadowed by a test, or a module half-initialised while another thread imports it. When that happened the helper's own `ImportError` became what the caller saw, and a real cause took a log dig to find. A hint is a courtesy, so it may only improve an error, never substitute for it; the test installs a stub `openai` and asserts the original exception comes back unchanged.
- **Fix: the agent facade's annotations are postponed, so 3.11 can load it** (`src/zrb/llm/agent/__init__.py`, `test/architecture/test_typing_only_names_are_not_evaluated.py`): moving the agent contracts into `agent/` left `_EngineAgentRunner` annotated `-> Agent`, a name now bound only under `if TYPE_CHECKING:`. Without `from __future__ import annotations` Python evaluated that annotation while the class body ran and raised `NameError` on 3.13 and older — while the local run, on 3.14 where PEP 649 defers annotations by default, passed the whole suite. The new guard walks every module under `src/zrb` and fails when a signature evaluated at import names something bound only for the type checker, so the next move cannot pass here and fail on the oldest interpreter CI runs.
- **Improvement: the test tree mirrors `src/zrb`** (`test/`, `test/architecture/test_test_tree_mirrors_src.py`): a test lived wherever it was first written, so a reader looking for the suite of a module had to know the history rather than the path. 115 files moved beside the package they exercise, by an explicit map — an import-weighted vote counts 315 files and cannot tell a UI test patching `hook_manager` from a hook test. Two needed more than a move: the scaffolder's `template/` fixture, and a `parents[3]` that became `parents[4]`. The guard fails on a test whose directory has no matching package.
- **Improvement: an import names its module from the root, and a guard says so** (`src/zrb/`, `test/architecture/test_absolute_imports.py`): a relative `from .foo import bar` reads correctly and moves badly, and after a hundred file moves the two forms had mixed. Every `src/zrb` import now names its module absolutely, and the guard fails on the next dot — including inside `__init__.py`, where the shorthand is most tempting.
- **Improvement: the imports a live doc shows are checked against the tree** (`test/architecture/test_doc_imports.py`, `docs/llm/llm-custom-ui.md`): after the moves, a guide is the one file a reader copies from and nothing compiled it. The guard imports every `zrb` path a live doc shows, so a doc that names a module the release deleted fails the suite instead of the reader.
- **Improvement: the sub-agent loading test needs no provider that can fail to import** (`test/llm/subagent/test_manager_loading.py`): the assertion was about how a sub-agent definition is loaded, and it reached for a real model provider to get there — so a poisoned venv turned a loading test red and read as a defect in loading. It now asserts what loading does with the provider stubbed, which is the behaviour it was always about.
- **Improvement: the minimal-UI example names the roles** (`examples/chat-minimal-ui/README.md`, `examples/chat-minimal-ui/zrb_init.py`): the example is what a reader builds a UI from, and it still described one object with fifty members. It names the five accessors and the members each role actually needs, so a copy of it works against the contract this release ships.
- **Improvement: the imports are sorted, and `isort` says so** (`src/`, `test/`): a hundred and thirty-three files were left with import blocks the refactor had disturbed. `isort . --profile black --force-grid-wrap 0` — the formatter this repo already runs — was applied and `black` agrees afterwards. Import order only; no module gained or lost a name.
