## 3.10.0 (September 27, 2026)

- **Breaking: camera, dictation and speech are optional features outside the UI** (`src/zrb/llm/camera/`, `src/zrb/llm/dictation/`, `src/zrb/llm/speech/`, `src/zrb/builtin/llm/chat.py`, `src/zrb/llm/ui/`, ADR-0102): `/photo` and `/voice` moved out of `BaseUI`, the default UI's keybindings and status bar, `UIConfig` and the completer into `enable_camera(chat, CameraConfig)`, `enable_dictation(chat, DictationConfig)` and `enable_speech(task, SpeechConfig)`, built only on `LLMChatTask`'s public extension points; the built-in `llm_chat` calls all three. A config field left `None` reads its `CFG` knob when a session starts, so `zrb_init.py` may change settings after importing zrb, and calling `enable_*` again on a task replaces the earlier call. `ui.voice`, `BaseUIVoiceState`, `voice_commands`/`photo_commands`, `handle_toggle_voice`, `handle_photo_command`, `submit_photo` and the push-to-talk keybinding are gone.
- **Breaking: voice settings renamed without aliases** (`src/zrb/config/mixins/llm_dictation.py`, `src/zrb/config/mixins/llm_camera.py`, `src/zrb/config/mixins/llm_ui_commands.py`): `LLM_VOICE_MODE` → `LLM_DICTATION_BACKEND`, `LLM_VOICE_{OPENAI,GOOGLE}_MODEL` and `LLM_VOICE_VOSK_MODEL_{NAME,URL}` → `LLM_DICTATION_*`, `LLM_UI_COMMAND_VOICE` → `LLM_DICTATION_COMMANDS`, `LLM_UI_COMMAND_PHOTO` → `LLM_CAMERA_COMMANDS`. `LLM_VOICE_ENABLED` and `LLM_VOICE_PUSH_TO_TALK_KEY` were removed: `/voice` is always offered and reports a missing `zrb[voice]` extra with the install command (ADR-0093). The [upgrading guide](../../advanced-topics/upgrading-guide.md#upgrading-to-3100) has the full table.
- **Breaking: `ActionCommand` actions receive the UI** (`src/zrb/llm/custom_command/action_command.py`, `src/zrb/llm/custom_command/any_custom_command.py`, `src/zrb/llm/custom_command/resolver.py`, `src/zrb/llm/ui/base/exec_commands.py`, `src/zrb/llm/ui/base/commands.py`, `src/zrb/llm/ui/default/app/completion/completer.py`): an action is now `action(kwargs, ui)`, `AnyCustomCommand.handle` takes `ui`, and `run_custom_command` takes it too (`None` for the initial `--message`). An async action runs as a UI background task, cancelled on exit, with its result shown when it finishes; `can_run_while_thinking=True` lets a command through mid-turn; `complete_arg` completes the first argument in the TUI.
- **Feature: push-to-talk that stops on a pause, and hands-free dictation** (`src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/words.py`, ADR-0076): `/voice` starts recording and a pause or `/voice` again stops it, inserting the transcript at the cursor; the spacebar is no longer taken while voice is on. `/handsfree` (or `LLM_DICTATION_MODE=hands_free`) keeps the microphone open and submits each utterance, with optional wake words (`LLM_DICTATION_WAKE_WORDS`, `LLM_DICTATION_WAKE_WINDOW`). Audio is ignored while zrb speaks. Speech that arrives while an utterance is being transcribed is kept, up to `LLM_DICTATION_MAX_BACKLOG` seconds, so a slow transcriber neither loses the next sentence nor lets the backlog grow without bound. Thresholds, silence, pre-roll, echo cooldown and utterance limits are all settings.
- **Feature: hands-free answers tool approvals and questions** (`src/zrb/llm/ui/trigger.py`, `src/zrb/llm/ui/base/triggers.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/ui/default/confirmation.py`, `src/zrb/llm/ui/event_driven_ui.py`): a trigger may yield `TriggerReply(text)`, which `submit_answer`s the pending approval or question (`is_waiting_for_answer`) instead of starting a turn; a plain string never does, so no scheduled or remote trigger can approve a tool call. A short spoken "yes" (`LLM_DICTATION_APPROVE_WORDS`) approves, a deny phrase said alone (`LLM_DICTATION_DENY_WORDS`) denies, anything else denies with what was said as the reason, and an empty reply is never sent. An answer to a choice question naming an option by label or number resolves to that option, and a multi-select answer listing several ("1, 3", "red and blue") resolves to all of them. `TriggerReply` is exported from `zrb`.
- **Feature: speech reads replies, approvals and questions aloud** (`src/zrb/llm/speech/feature.py`, `src/zrb/llm/speech/player.py`, `src/zrb/llm/speech/text.py`, `src/zrb/llm/prompt/markdown/speech_summarizer.md`, ADR-0103): with `LLM_SPEECH_ENABLED` or `/speech`, the reply at `Stop` (not a sub-agent's), tool approvals and questions are spoken on a background thread, so a turn never waits on speech. A reply over `LLM_SPEECH_MAX_CHARS` is cut at a sentence end, else a clause break, else a whole word, and followed by "The full answer is on screen."; with `LLM_SPEECH_SUMMARIZE` the small model summarizes it instead. Sessions take turns through a lock file, which dictation also checks (every speaker's in the process, so a `SpeechConfig(lock_file=...)` still silences the microphone), and a failing cloud backend falls back to the local engine. This covers what peon-ping was installed for.
- **Feature: pluggable backends** (`src/zrb/llm/camera/backend/`, `src/zrb/llm/dictation/backend/`, `src/zrb/llm/speech/backend/`): each feature's `backend` is a built-in name or an `AnyCameraBackend` / `AnyDictationBackend` / `AnySpeechBackend`, one implementation per module: camera `auto`/`termux`/`ffmpeg`; dictation `vosk`/`openai`/`google`/`multimodal`, now with `LLM_DICTATION_OPENAI_BASE_URL`; speech `auto`/`termux`/`say`/`espeak-ng`/`openai`/`gemini`, where `auto` picks Termux:API's `termux-tts-speak` on Termux (`LLM_SPEECH_TERMUX_*`) and the cloud ones go over `urllib`, with `LLM_SPEECH_WAV_PLAYER`. `zrb.llm.util.camera` became `zrb.llm.camera.backend`, and `zrb.llm.voice.VoiceEngine` became the dictation backends plus `zrb.llm.dictation.record`/`listen`.
- **Feature: every voice and camera behavior is a setting** (`src/zrb/config/mixins/llm_camera.py`, `src/zrb/config/mixins/llm_dictation.py`, `src/zrb/config/mixins/llm_speech.py`): new `LLM_CAMERA_BACKEND`, `LLM_CAMERA_DEVICE`, `LLM_CAMERA_TIMEOUT`, the `LLM_DICTATION_*` and `LLM_SPEECH_*` families listed in [LLM configuration § 23](../../configuration/llm-config.md#23-voice-and-camera), each also a field on the feature's config dataclass.
- **Fix: dictation errors name the fix** (`src/zrb/llm/dictation/backend/google.py`, `src/zrb/llm/dictation/backend/vosk.py`, `src/zrb/llm/dictation/listen.py`): a missing `google-genai` or `vosk` package raised a bare `ImportError` because the package was imported before the install-hint check; the check now runs first. A microphone that will not open reports "Cannot open microphone", and the multimodal backend sends audio as WAV, as its media type says, instead of raw PCM.
- **Fix: coughs and clicks no longer count as speech in hands-free** (`src/zrb/llm/dictation/listen.py`): the pre-roll kept before an utterance counted toward its minimum length, so with the defaults a single click passed; speech is now measured from its first loud block to its last. Present in the 3.9.0 voice-interaction example.
- **Fix: a camera capture takes at most its timeout** (`src/zrb/llm/camera/backend/ffmpeg.py`, `src/zrb/llm/camera/backend/auto.py`, `src/zrb/llm/camera/backend/termux.py`, `src/zrb/llm/camera/backend/deadline.py`): on Linux a hung MJPEG attempt waited the full timeout and then the raw fallback waited it again, and on Termux a hung `termux-camera-photo` was waited on forever; one deadline now covers every attempt. Present since the camera capture landed in 2.x.
- **Fix: a failed Termux capture no longer returns an earlier photo** (`src/zrb/llm/camera/backend/termux.py`): every capture wrote the same file and read it if it existed, so a failed capture returned whatever the last one left, and two sessions shared it; each capture now writes and removes its own file. Present since the camera capture landed in 2.x.
- **Fix: the pre-roll keeps as much audio as it says** (`src/zrb/llm/dictation/listen.py`): the loud block that starts speech took one of the pre-roll's slots, so `pre_roll=0.3` kept 0.2 s. Present in the 3.9.0 voice-interaction example.
- **Fix: two sessions downloading the vosk model never load a half-extracted one** (`src/zrb/llm/dictation/backend/vosk.py`): the zip was extracted straight into `~/.cache/vosk`; it now extracts into a staging directory and moves into place with one rename. The download timeout is `LLM_DICTATION_VOSK_DOWNLOAD_TIMEOUT` instead of a fixed 120 s.
- **Fix: `0` means no limit for every time and size limit** (`src/zrb/llm/dictation/listen.py`, `src/zrb/llm/speech/backend/builtin.py`, `src/zrb/llm/speech/player.py`, `src/zrb/llm/camera/backend/`): `LLM_DICTATION_MAX_UTTERANCE=0` cut every utterance to one block, `LLM_SPEECH_PLAYER_TIMEOUT=0` stopped playback at once, and `0` for `LLM_SPEECH_TIMEOUT` or `LLM_CAMERA_TIMEOUT` failed immediately, while `LLM_SPEECH_MAX_CHARS=0` already meant no limit.
- **Fix: an unlabeled choice option has one name everywhere** (`src/zrb/llm/tool_call/choice_spec_format.py`, `src/zrb/llm/ui/default/selection.py`, `src/zrb/llm/ui/default/confirmation.py`, `src/zrb/llm/ui/std_ui.py`, `src/zrb/llm/tool/ask.py`): an option without a label was shown as `Option N` but answered as `str(i)` by the widget, as the typed token by `AskUserQuestion`, and as `""` by a typed answer; `get_option_label` makes it `Option N` in all of them.
- **Fix: on Windows, finding the default camera stays inside the capture timeout** (`src/zrb/llm/camera/backend/ffmpeg.py`): the dshow device listing had its own 5 s timeout on top of the capture's. Present since the camera capture landed in 2.x.
- **Fix: nothing voice or camera writes is named `zrb` in a white-labeled build** (`src/zrb/llm/camera/backend/termux.py`, `src/zrb/llm/speech/backend/utterance.py`, `src/zrb/config/mixins/llm_speech.py`): the Termux photo file, speech temp files, the speech lock file and the speech thread follow `ROOT_GROUP_NAME`.
- **Fix: voice and camera state belongs to a chat session, not a task** (`src/zrb/llm/util/feature_config.py`, `src/zrb/llm/speech/feature.py`, `src/zrb/llm/dictation/feature.py`): `enable_speech` and `enable_dictation` built one session per task, and the web runner holds one task for every chat connection, so the first session to switch speech off silenced the next and hands-free in one conversation opened the microphone in another. `get_feature_sessions` keys sessions by `(task, feature, session)` through `get_session_ownership_key()`.
- **Fix: a feature's hooks are taken back out** (`src/zrb/llm/speech/feature.py`, `src/zrb/llm/util/feature_config.py`): the hooks a session registered were never removed, so calling `enable_speech` again left the earlier set in place, re-applying the factory — which `execution.py` does on every run — registered another, and a long-lived process kept one set per session it had served. `SpeechSession.close` unregisters its own hooks by identity and closes its speaker, `FeatureSessions.close_all` runs it when a feature is replaced, and an idempotent `SESSION_END` teardown per manager runs it when a session ends.
- **Fix: enabling speech or dictation with hooks off says so** (`src/zrb/llm/speech/feature.py`, `src/zrb/llm/dictation/feature.py`): both register through the hook subsystem, so `ZRB_HOOKS_ENABLED=off` left a `/speech` command that never spoke; enabling one now logs a warning naming the knob.
- **Fix: hands-free drops the utterance in flight when it is switched off** (`src/zrb/llm/dictation/feature.py`): transcription takes seconds, so switching hands-free off mid-utterance still submitted what the microphone had heard, against the user having said stop. `DictationSession._transcribe_or_drop` races the transcription against the switch-off, and `close` does the same when a feature is replaced or the session ends.
- **Fix: a microphone is closed by its caller, not by the garbage collector** (`src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/listen.py`): `listen` yields inside a `with stream:` and waits on an audio read in between, so a caller returning early left it suspended somewhere it cannot be closed by resuming it, and the microphone stayed open until the generator was finalized. The three call sites use `contextlib.aclosing`.
- **Fix: speech does not mangle identifiers** (`src/zrb/llm/speech/text.py`): `clean_for_speech` stripped every `*` and `_` on its own, so `set_app_name`, `ZRB_HOOKS_ENABLED` and `2 * 3 = 6` were read as one run-together word. Emphasis markers are matched as pairs and never inside a word; `__strong__` is left alone, being indistinguishable from the dunder in `__init__.py`.
- **Fix: a closed speaker stops being probed** (`src/zrb/llm/speech/player.py`): `is_speaking` read every lock file a live `Speaker` had configured and nothing removed one, so a long-lived process went on re-checking a finished session's path and stayed muted whenever anything else held it. `Speaker.close` releases the claim, reference-counted, so the file is forgotten when the last speaker using it closes.
- **Fix: the camera device probe is not collected mid-run** (`src/zrb/llm/camera/backend/ffmpeg.py`): `list_devices` ignored the task `schedule_device_refresh` returned and asyncio holds tasks weakly, so a probe collected before it finished left `"refreshing"` True and wedged every later refresh. The backend holds it in `_refresh_task` and clears it in the probe's `finally`.
- **Fix: `option_text` requires the option's index** (`src/zrb/llm/ui/std_ui.py`): the parameter defaulted to `0`, so a caller leaving it out named every description-only option "Option 1" while `resolve_choice_selection` numbered it by position; the name has to be passed, so it is now required.
- **Fix: a re-enabled feature applies the config it was given** (`src/zrb/llm/util/feature_config.py`): `enable_speech` and `enable_dictation` found the session registry their first call made but never updated its factory, so a `zrb_init.py` calling either again — the documented way to replace the built-in call, as `enable_speech(llm_chat, SpeechConfig(backend=LocalTTS()))` — closed the old sessions and then built every later one from the config being replaced. `replace_feature_sessions` installs the new factory and closes what the earlier call left running.
- **Fix: a custom command with the previous `handle(kwargs)` signature dispatches again** (`src/zrb/llm/custom_command/resolver.py`): `run_custom_command` called every handler with `(kwargs, ui)`, so a command written against the one-argument form raised `TypeError` where it was invoked. The arity is read from the handler's signature, and a `TypeError` from inside a handler is left to propagate rather than read as a wrong arity.
- **Fix: a Vosk model download is bounded** (`src/zrb/llm/dictation/backend/vosk.py`, `src/zrb/config/mixins/llm_dictation.py`): the whole response was accumulated in memory and the archive extracted with no limit, so a configured or hijacked `LLM_DICTATION_VOSK_MODEL_URL` could exhaust memory and disk before the model loaded. The response is streamed to a file and stopped at `LLM_DICTATION_VOSK_MAX_DOWNLOAD_MB`; the archive is checked against `..._MAX_UNCOMPRESSED_MB`, `..._MAX_FILE_MB` and `..._MAX_FILES` before anything is written; the file and the staging directory are removed on every path out, cancellation included. Each limit is 0 for no limit, and the defaults (4 GB down, 8 GB unpacked, 4 GB per file, 10000 files) clear the largest published model.
- **Documentation: voice and camera guide** (`docs/llm/voice-camera.md`, `docs/configuration/llm-config.md`, `docs/task-types/llmchat-task.md`, `docs/advanced-topics/upgrading-guide.md`, `docs/adr/adr-0076.md`, `docs/adr/adr-0082.md`, `docs/adr/adr-0093.md`, `docs/adr/adr-0098.md`, `docs/adr/adr-0102.md`, `docs/adr/adr-0103.md`, `AGENTS.md`): a user guide covers the three features, custom backends and custom chat tasks; ADR-0098 adds `enable_X` to the action vocabulary; the `examples/voice-interaction` and `examples/chat-gpio-ptt` examples use the new APIs, the former reduced to switching speech on plus the `zrb voice say` and `zrb voice mic-test` tasks.
- **Documentation: per-session voice state and the hooks dependency** (`docs/llm/voice-camera.md`, `docs/adr/adr-0102.md`): the guide describes the per-session speaker, the lock file between processes and `ZRB_HOOKS_ENABLED`; ADR-0102 records the session key, the hook teardown and the reference-counted lock file as decisions 8 and 9.
