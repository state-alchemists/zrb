## 3.10.0 (September 27, 2026)

- **Breaking: camera, dictation and speech are optional features outside the UI** (`src/zrb/llm/camera/`, `src/zrb/llm/dictation/`, `src/zrb/llm/speech/`, `src/zrb/builtin/llm/chat.py`, `src/zrb/llm/ui/`, ADR-0102): `/photo` and `/voice` moved out of `BaseUI`, the default UI, `UIConfig` and the completer into `enable_camera(chat, CameraConfig)`, `enable_dictation(chat, DictationConfig)` and `enable_speech(task, SpeechConfig)`; the built-in `llm_chat` calls all three. A config field left `None` reads its `CFG` knob at session start, and calling `enable_*` again replaces the earlier call. Removed: `ui.voice`, `BaseUIVoiceState`, `voice_commands`/`photo_commands`, `handle_toggle_voice`, `handle_photo_command`, `submit_photo` and the push-to-talk keybinding.
- **Breaking: voice settings renamed without aliases** (`src/zrb/config/mixins/llm_dictation.py`, `src/zrb/config/mixins/llm_camera.py`, `src/zrb/config/mixins/llm_ui_commands.py`): `LLM_VOICE_MODE` → `LLM_DICTATION_BACKEND`, `LLM_VOICE_{OPENAI,GOOGLE}_MODEL` and `LLM_VOICE_VOSK_MODEL_{NAME,URL}` → `LLM_DICTATION_*`, `LLM_UI_COMMAND_VOICE` → `LLM_DICTATION_COMMANDS`, `LLM_UI_COMMAND_PHOTO` → `LLM_CAMERA_COMMANDS`. `LLM_VOICE_ENABLED` and `LLM_VOICE_PUSH_TO_TALK_KEY` were removed: `/voice` is always offered and reports a missing `zrb[voice]` extra with the install command (ADR-0093). The [upgrading guide](../../advanced-topics/upgrading-guide.md#upgrading-to-3100) has the full table.
- **Breaking: `ActionCommand` actions receive the UI** (`src/zrb/llm/custom_command/action_command.py`, `src/zrb/llm/custom_command/any_custom_command.py`, `src/zrb/llm/custom_command/resolver.py`, `src/zrb/llm/ui/base/exec_commands.py`, `src/zrb/llm/ui/base/commands.py`, `src/zrb/llm/ui/default/app/completion/completer.py`): an action is now `action(kwargs, ui)`, `AnyCustomCommand.handle` takes `ui`, and `run_custom_command` takes it too (`None` for a non-interactive `--message`; an interactive chat's initial action command runs once its UI exists). An async action runs as a UI background task, cancelled on exit, with its result shown when it finishes; `can_run_while_thinking=True` lets a command through mid-turn; `complete_arg` completes the first argument in the TUI.
- **Feature: push-to-talk that stops on a pause, and hands-free dictation** (`src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/words.py`, ADR-0076): `/voice` starts recording; a pause or `/voice` again stops it and inserts the transcript at the cursor. The spacebar is no longer taken. `/handsfree` (or `LLM_DICTATION_MODE=hands_free`) keeps the microphone open and submits each utterance, with optional wake words (`LLM_DICTATION_WAKE_WORDS`, `LLM_DICTATION_WAKE_WINDOW`). Audio is ignored while zrb speaks. Speech arriving during transcription is buffered up to `LLM_DICTATION_MAX_BACKLOG` seconds.
- **Feature: hands-free answers tool approvals and questions** (`src/zrb/llm/ui/trigger.py`, `src/zrb/llm/ui/base/triggers.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/default/confirmation.py`, ADR-0076): a trigger may yield `TriggerReply(text, approval, started_at)`, which answers an approval or question already pending when the user began speaking instead of starting a turn; a plain string never does, so no scheduled or remote trigger can approve a tool call. A spoken answer of only approve and polite words ("yes please", `LLM_DICTATION_APPROVE_WORDS`) approves, only deny phrases (`LLM_DICTATION_DENY_WORDS`) denies, and anything else ("yes, but wait") denies with the words as the reason; an empty reply is never sent. A choice answer may name options by label or number ("1, 3", "red and blue"). `TriggerReply` is exported from `zrb`.
- **Feature: speech reads replies, approvals and questions aloud** (`src/zrb/llm/speech/feature.py`, `src/zrb/llm/speech/player.py`, `src/zrb/llm/speech/text.py`, `src/zrb/llm/prompt/markdown/speech_summarizer.md`, ADR-0103): with `LLM_SPEECH_ENABLED` or `/speech`, the reply at `Stop` (never a sub-agent's), tool approvals and questions are spoken on a background thread, so a turn never waits on speech. A reply over `LLM_SPEECH_MAX_CHARS` is cut at a sentence end, clause break or whole word and followed by "The full answer is on screen."; with `LLM_SPEECH_SUMMARIZE` the small model summarizes it instead. Sessions take turns through a lock file that dictation also checks, and a failing cloud backend falls back to the local engine.
- **Feature: pluggable backends** (`src/zrb/llm/camera/backend/`, `src/zrb/llm/dictation/backend/`, `src/zrb/llm/speech/backend/`): each feature's `backend` is a built-in name or an `AnyCameraBackend` / `AnyDictationBackend` / `AnySpeechBackend`, one implementation per module: camera `auto`/`termux`/`ffmpeg`; dictation `vosk`/`openai`/`google`/`multimodal`, now with `LLM_DICTATION_OPENAI_BASE_URL`; speech `auto`/`termux`/`say`/`espeak-ng`/`openai`/`gemini`, where `auto` picks Termux:API's `termux-tts-speak` on Termux (`LLM_SPEECH_TERMUX_*`) and the cloud ones go over `urllib`, with `LLM_SPEECH_WAV_PLAYER`. `zrb.llm.util.camera` became `zrb.llm.camera.backend`, and `zrb.llm.voice.VoiceEngine` became the dictation backends plus `zrb.llm.dictation.record`/`listen`.
- **Feature: every voice and camera behavior is a setting** (`src/zrb/config/mixins/llm_camera.py`, `src/zrb/config/mixins/llm_dictation.py`, `src/zrb/config/mixins/llm_speech.py`): new `LLM_CAMERA_BACKEND`, `LLM_CAMERA_DEVICE`, `LLM_CAMERA_TIMEOUT`, the `LLM_DICTATION_*` and `LLM_SPEECH_*` families listed in [LLM configuration § 21](../../configuration/llm-voice-camera.md#voice-and-camera), each also a field on the feature's config dataclass.
- **Fix: dictation errors name the fix** (`src/zrb/llm/dictation/backend/google.py`, `src/zrb/llm/dictation/backend/vosk.py`, `src/zrb/llm/dictation/listen.py`): a missing `google-genai` or `vosk` package raised a bare `ImportError` because the package was imported before the install-hint check; the check now runs first. A microphone that will not open reports "Cannot open microphone", and the multimodal backend sends audio as WAV, as its media type says, instead of raw PCM.
- **Fix: coughs and clicks no longer count as speech in hands-free** (`src/zrb/llm/dictation/listen.py`): the pre-roll kept before an utterance counted toward its minimum length, so with the defaults a single click passed; speech is now measured from its first loud block to its last. Present in the 3.9.0 voice-interaction example.
- **Fix: a camera capture takes at most its timeout** (`src/zrb/llm/camera/backend/ffmpeg.py`, `src/zrb/llm/camera/backend/auto.py`, `src/zrb/llm/camera/backend/termux.py`, `src/zrb/llm/camera/backend/deadline.py`): on Linux a hung MJPEG attempt waited the full timeout and then the raw fallback waited it again, and on Termux a hung `termux-camera-photo` was waited on forever; one deadline now covers every attempt. Present since the camera capture landed in 2.x.
- **Fix: a failed Termux capture no longer returns an earlier photo** (`src/zrb/llm/camera/backend/termux.py`): every capture wrote the same file and read it if it existed, so a failed capture returned whatever the last one left, and two sessions shared it; each capture now writes and removes its own file. Present since the camera capture landed in 2.x.
- **Fix: the pre-roll keeps as much audio as it says** (`src/zrb/llm/dictation/listen.py`): the loud block that starts speech took one of the pre-roll's slots, so `pre_roll=0.3` kept 0.2 s. Present in the 3.9.0 voice-interaction example.
- **Fix: two sessions downloading the vosk model never load a half-extracted one** (`src/zrb/llm/dictation/backend/vosk.py`): the zip was extracted straight into `~/.cache/vosk`; it now extracts into a staging directory and moves into place with one rename. The download timeout is `LLM_DICTATION_VOSK_DOWNLOAD_TIMEOUT` instead of a fixed 120 s.
- **Fix: `0` means no limit for every time and size limit** (`src/zrb/llm/dictation/listen.py`, `src/zrb/llm/speech/backend/builtin.py`, `src/zrb/llm/speech/player.py`, `src/zrb/llm/camera/backend/`): `LLM_DICTATION_MAX_UTTERANCE=0` cut every utterance to one block, `LLM_SPEECH_PLAYER_TIMEOUT=0` stopped playback at once, and `0` for `LLM_SPEECH_TIMEOUT` or `LLM_CAMERA_TIMEOUT` failed immediately, while `LLM_SPEECH_MAX_CHARS=0` already meant no limit.
- **Fix: an unlabeled choice option has one name everywhere** (`src/zrb/llm/tool_call/choice_spec_format.py`, `src/zrb/llm/ui/default/selection.py`, `src/zrb/llm/ui/default/confirmation.py`, `src/zrb/llm/ui/std_ui.py`, `src/zrb/llm/tool/ask.py`): an option without a label was shown as `Option N` but answered as `str(i)` by the widget, as the typed token by `AskUserQuestion`, and as `""` by a typed answer; `get_option_label` makes it `Option N` in all of them.
- **Fix: on Windows, finding the default camera stays inside the capture timeout** (`src/zrb/llm/camera/backend/ffmpeg.py`): the dshow device listing had its own 5 s timeout on top of the capture's. Present since the camera capture landed in 2.x.
- **Fix: nothing voice or camera writes is named `zrb` in a white-labeled build** (`src/zrb/llm/camera/backend/termux.py`, `src/zrb/llm/speech/backend/utterance.py`, `src/zrb/config/mixins/llm_speech.py`): the Termux photo file, speech temp files, the speech lock file and the speech thread follow `ROOT_GROUP_NAME`.
- **Fix: voice and camera state belongs to a chat session, not a task** (`src/zrb/llm/util/feature_config.py`, `src/zrb/llm/speech/feature.py`, `src/zrb/llm/dictation/feature.py`): `enable_speech` and `enable_dictation` built one session per task, and the web runner holds one task for every chat connection, so the first session to switch speech off silenced the next and hands-free in one conversation opened the microphone in another. `replace_feature_sessions` keys sessions by `(task, feature, session)` through `get_session_ownership_key()`.
- **Fix: a feature's hooks are taken back out** (`src/zrb/llm/speech/feature.py`, `src/zrb/llm/util/feature_config.py`, ADR-0102): a session's hooks were never removed, so calling `enable_speech` again or re-applying the factory (done on every run) stacked another set, and a long-lived process kept one set per session served. A session now unregisters its hooks and closes its speaker when its feature is replaced or the session ends (interactive CLI teardown, the web runner's `remove_session`).
- **Fix: enabling speech with hooks off, or hidden by the hook allowlist, says so** (`src/zrb/llm/speech/feature.py`): speech registers through the hook subsystem, so `ZRB_HOOKS_ENABLED=off` left a `/speech` command that never spoke, and a `ZRB_LLM_HOOKS` allowlist without `handle_stop`, `handle_permission_request` or `handle_notification` silenced those events; each case now logs a warning naming what to change.
- **Fix: hands-free drops the utterance in flight when it is switched off** (`src/zrb/llm/dictation/feature.py`): transcription takes seconds, so switching hands-free off mid-utterance still submitted what the microphone had heard, against the user having said stop. `DictationSession._transcribe_or_drop` races the transcription against the switch-off, and `close` does the same when a feature is replaced or the session ends.
- **Fix: a microphone is closed by its caller, not by the garbage collector** (`src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/listen.py`): `listen` yields inside a `with stream:` and waits on an audio read in between, so a caller returning early left it suspended somewhere it cannot be closed by resuming it, and the microphone stayed open until the generator was finalized. The three call sites use `contextlib.aclosing`.
- **Fix: speech does not mangle identifiers** (`src/zrb/llm/speech/text.py`): `clean_for_speech` stripped every `*` and `_` on its own, so `set_app_name`, `ZRB_HOOKS_ENABLED` and `2 * 3 = 6` were read as one run-together word. Emphasis markers are matched as pairs and never inside a word; `__strong__` is left alone, being indistinguishable from the dunder in `__init__.py`.
- **Fix: a closed speaker stops being probed** (`src/zrb/llm/speech/player.py`): `is_speaking` read every lock file a live `Speaker` had configured and nothing removed one, so a long-lived process went on re-checking a finished session's path and stayed muted whenever anything else held it. `Speaker.close` releases the claim, reference-counted, so the file is forgotten when the last speaker using it closes.
- **Fix: the camera device probe is not collected mid-run** (`src/zrb/llm/camera/backend/ffmpeg.py`): `list_devices` ignored the task `schedule_device_refresh` returned and asyncio holds tasks weakly, so a probe collected before it finished left `"refreshing"` True and wedged every later refresh. The backend holds it in `_refresh_task` and clears it in the probe's `finally`.
- **Fix: `option_text` requires the option's index** (`src/zrb/llm/ui/std_ui.py`): the parameter defaulted to `0`, so a caller leaving it out named every description-only option "Option 1" while `resolve_choice_selection` numbered it by position; the name has to be passed, so it is now required.
- **Fix: a re-enabled feature applies the config it was given** (`src/zrb/llm/util/feature_config.py`): `enable_speech` and `enable_dictation` never updated the session registry's factory on a second call, so a `zrb_init.py` replacing the built-in call (`enable_speech(llm_chat, SpeechConfig(backend=LocalTTS()))`) closed the old sessions and then built every later one from the config being replaced. `replace_feature_sessions` installs the new factory and closes what the earlier call left running.
- **Fix: a custom command with the previous `handle(kwargs)` signature dispatches again** (`src/zrb/llm/custom_command/resolver.py`): `run_custom_command` called every handler with `(kwargs, ui)`, so a command written against the one-argument form raised `TypeError` where it was invoked. The arity is read from the handler's signature, and a `TypeError` from inside a handler is left to propagate rather than read as a wrong arity.
- **Fix: a Vosk model download is bounded** (`src/zrb/llm/dictation/backend/vosk.py`, `src/zrb/config/mixins/llm_dictation.py`): the response was held in memory and extracted with no limit, so a configured or hijacked `LLM_DICTATION_VOSK_MODEL_URL` could exhaust memory and disk. It is now streamed to a file and capped by `LLM_DICTATION_VOSK_MAX_DOWNLOAD_MB`, the archive is checked against `..._MAX_UNCOMPRESSED_MB`, `..._MAX_FILE_MB` and `..._MAX_FILES` before anything is written, and temporary files are removed on every exit path, cancellation included. Each limit is 0 for no limit; the defaults (4 GB down, 8 GB unpacked, 4 GB per file, 10000 files) clear the largest published model.
- **Fix: a denial or a hedge never approves a tool call** (`src/zrb/llm/dictation/words.py`): a transcript opening with an approve phrase approved whatever followed within three words, so "okay, no, stop", "yes, but don't" and "yes wait no" approved. An approval now needs every word to be an approve phrase or a polite word.
- **Fix: a spoken reply never answers a prompt that appeared after it was spoken** (`src/zrb/llm/ui/trigger.py`, `src/zrb/llm/ui/base/triggers.py`, `src/zrb/llm/dictation/feature.py`): a reply answered whatever was pending when its transcript arrived, so a "yes" said to nothing approved a tool call shown during the seconds of transcription. `TriggerReply.started_at` is checked against when the prompt appeared, and in a sub-agent's view, where the pending prompt may be another agent's, a spoken reply answers none.
- **Fix: dictation keeps what was said** (`src/zrb/llm/dictation/feature.py`, `src/zrb/llm/ui/base/triggers.py`): every hands-free utterance was collapsed to yes or no, so "ok run the tests" became the turn "yes" and "sure, use postgres" answered a question "yes". Only a tool approval gets the collapsed answer.
- **Fix: a mistyped dictation backend no longer breaks every chat** (`src/zrb/llm/dictation/feature.py`): the backend was built when a session started, so `ZRB_LLM_DICTATION_BACKEND=whisper` raised on every chat, voice or not. It is built on first use, and `/voice` reports the error.
- **Fix: Vosk decodes off the event loop** (`src/zrb/llm/dictation/backend/vosk.py`): recognition ran on the loop and froze the chat for each utterance.
- **Fix: hands-free reports what it is doing** (`src/zrb/llm/dictation/feature.py`): it never prepared its backend, so the first utterance silently waited on a model download, and download, microphone and transcription failures went only to the log. They go to the chat that switched hands-free on.
- **Fix: a short "yes" is heard, and odd listening settings work** (`src/zrb/llm/dictation/listen.py`, `src/zrb/config/mixins/llm_dictation.py`): `LLM_DICTATION_MIN_SPEECH` defaulted to 0.4 s, which dropped a short "yes" or "no" as a cough; it is 0.25 s. A negative duration counts as 0 instead of raising or deafening the microphone, and `LLM_DICTATION_SILENCE=0` is one block instead of never ending an utterance.
- **Fix: `/voice` cannot stick on "Stopping..."** (`src/zrb/llm/dictation/feature.py`): a recording cancelled before its first step never cleared its state.
- **Fix: a long reply is spoken when summarizing is on** (`src/zrb/llm/speech/feature.py`): the summary ran on the hook's event loop, which closes when the hook returns, so it was cancelled and nothing was spoken, not even the cut opening. It runs on the speaker's thread, in order with the rest, and `zrb chat --message` waits for it before exiting.
- **Fix: a session's speech stops with it** (`src/zrb/llm/speech/player.py`, `src/zrb/llm/speech/backend/utterance.py`): closing a speaker let the current utterance play on for up to `LLM_SPEECH_PLAYER_TIMEOUT` and waited up to `LLM_SPEECH_DRAIN_TIMEOUT`, and at exit a player outliving the drain kept talking after zrb was gone. Closing cuts playback off at once and plays nothing still being synthesized; the exit drain cuts off what outlives it. A player exiting non-zero is logged.
- **Fix: one session does not speak another's replies** (`src/zrb/llm/speech/feature.py`): with a task-level `hook_manager` shared by web sessions, every session's hooks spoke every session's events.
- **Fix: speech reads less that is not prose** (`src/zrb/llm/speech/text.py`, `src/zrb/llm/speech/feature.py`, `src/zrb/llm/speech/backend/termux.py`, `src/zrb/llm/speech/backend/gemini.py`): no longer read aloud or mishandled: `~~~` fences, an unclosed fence opening a line, `<https://...>` links, a URL swallowing the full stop after it, a stray full stop after a paragraph break following `?` or `:`, a cut treating its window end or "e.g." as a sentence end, a question read with its markdown and no length limit, and a reply starting with `-` taken by `termux-tts-speak` as an option. Gemini audio split across parts is no longer truncated to the first, and a Gemini reply with no audio falls back to the local engine instead of playing silence.
- **Fix: a numeric option label names itself** (`src/zrb/llm/ui/default/confirmation.py`, `src/zrb/llm/tool/ask.py`): an answer was read as a 1-based index before a label, and `AskUserQuestion` re-indexed any all-digit answer, so with options `10`, `5`, `1` the answer "1" chose "10"; and "C" chose "C++", which normalizes to the same word. An exact label wins.
- **Fix: a mid-turn command never answers a pending prompt** (`src/zrb/llm/ui/default/keybindings.py`): typing `/voice` to stop a recording, `/btw` or the YOLO toggle while an approval waited denied the tool with the command as the reason, and in a sub-agent view sent it to the sub-agent. It runs as a command.
- **Fix: every exit cancels running commands** (`src/zrb/llm/ui/default/lifecycle.py`): Ctrl+C and Ctrl+D left an async command — a `/photo` capture, a Vosk download — running after the chat closed. The UI's cleanup cancels them.
- **Fix: one failed trigger delivery does not end the trigger** (`src/zrb/llm/ui/base/triggers.py`): an error submitting a trigger's item stopped the trigger for the rest of the session, leaving hands-free reporting on while nothing listened. It is reported and the next item is delivered.
- **Fix: a cancelled camera capture stops the camera** (`src/zrb/llm/camera/backend/deadline.py`, `src/zrb/llm/camera/backend/ffmpeg.py`, `src/zrb/llm/camera/backend/termux.py`): ffmpeg, `termux-camera-photo` and the Windows device listing were killed on timeout but not on cancellation, so they ran on with the camera open. A negative `LLM_CAMERA_TIMEOUT` failed every capture and means no limit; an unreadable Termux photo raised instead of failing the capture; and the failure hint could show an earlier capture's ffmpeg error or a timeout other than the one that fired.
- **Documentation: voice and camera guide** (`docs/llm/voice-camera.md`, `docs/configuration/llm-config.md`, `docs/task-types/llmchat-task.md`, `docs/advanced-topics/upgrading-guide.md`, `docs/adr/adr-0076.md`, `docs/adr/adr-0082.md`, `docs/adr/adr-0093.md`, `docs/adr/adr-0098.md`, `docs/adr/adr-0102.md`, `docs/adr/adr-0103.md`, `AGENTS.md`): a user guide covers the three features, custom backends and custom chat tasks; ADR-0098 adds `enable_X` to the action vocabulary; the `examples/voice-interaction` and `examples/chat-gpio-ptt` examples use the new APIs, the former reduced to switching speech on plus the `zrb voice say` and `zrb voice mic-test` tasks.
- **Documentation: per-session voice state and the hooks dependency** (`docs/llm/voice-camera.md`, `docs/adr/adr-0102.md`): the guide describes the per-session speaker, the lock file between processes and `ZRB_HOOKS_ENABLED`; ADR-0102 records the session key, where a session is closed and the reference-counted lock file as decisions 8 and 9.
