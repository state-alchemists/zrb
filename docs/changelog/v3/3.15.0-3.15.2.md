## 3.15.2 (October 8, 2026)

_Cumulative summary of the 3.15.1–3.15.2 patch line._

- **Fix: the mistyped-variable warning no longer calls a project's own env vars typos** (`src/zrb/config/config.py`, `src/zrb/config/mixins/foundation.py`, `docs/configuration/env-vars.md`, `docs/advanced-topics/white-labeling.md`, `AGENTS.md`, `test/config/test_config_env_warnings.py`, `test/test_main.py`): the warning reported any `<ENV_PREFIX>_*` variable scoring 0.85 or better against a setting name, and no cutoff separates a real typo (`MAX_TOKEN_PER_MINUTE`, 0.92) from a variable the project reads itself (`LLM_PROXY_BASE_URL`, 0.864); 4 of the 29 `ARASAKA_*` variables bsim-agent reads were reported. The new `PROJECT_ENV_KEYS` setting takes prefix-relative names, exact (`LLM_PLUGIN_DIR`) or a `*` glob (`LLM_PROXY_*`), and both the mistyped and the retired report skip the names it claims. An unclaimed typo is still reported, and a claimed name never enters the suggestion pool. The warning runs after the init sources load, so a distribution can claim its keys from `zrb_init.py`; a test pins that ordering.
- **Fix: a `str` assigned to a config field is stored as the env text rather than serialized** (`src/zrb/config/env_field.py`, `src/zrb/config/mixins/foundation.py`, `test/config/test_env_field.py`, `test/config/test_config_env_warnings.py`): `EnvField.__set__` ran every assigned value through the field's `serialize`, so `CFG.LLM_TOOLS = "Shell,Read"` was stored as `S,h,e,l,l,,,R,e,a,d` (`",".join` iterates characters) and `CFG.LLM_SHOW_TOOL_CALL_DETAIL = "off"` read back as `True` (`on_off` turned the non-empty string into `"on"`), with no error or warning. It dated from the 3.0 configuration rewrite and affected every list- and mapping-valued setting (`LLM_TOOLS`, `LLM_SKILLS`, `LLM_AGENTS`, `LLM_HOOKS`, `LLM_PLUGIN_DIRS`, `INIT_MODULES`, `PROJECT_ENV_KEYS`, `LLM_SPEECH_PROGRESS_PHRASES`) and the path lists. A string is now stored as written and only a non-`str` value is serialized; the cast still validates (`CFG.WEB_HTTP_PORT = "abc"` fails loudly) and a tuple on a list field is still refused. No zrb code path reached the old behavior (env reads never call `__set__`, `/set` converts first, and `src/` assigns no `CFG.<NAME>`); the exposure was a project's own bootstrap code in `zrb_init.py` or a white label's init module.
- **Fix: a message to a live background sub-agent runs under the chat's tool policies** (`src/zrb/llm/agent/run/authority_snapshot.py`, `src/zrb/llm/agent/subagent/live_session.py`, `test/llm/agent/subagent/test_live_session_continuation.py`): a follow-up sent to a still-live sub-agent starts after the approval-handler scope ended, and `AuthoritySnapshot` carried only the permission policy, YOLO, sandbox and hook manager, so the continuation skipped the chat's tool policies (a `ToolDenied` policy did not bind it) and reached no approval channel. The snapshot now also captures the approval handler and channel, and each continuation passes them to `run_agent`.
- **Fix: `auto_approve` with an argument mapping requires every named argument** (`src/zrb/llm/tool_call/tool_policy/auto_approve.py`, `test/llm/tool_call/tool_policy/test_auto_approve.py`, `test/llm/tool_call/test_allow_tool.py`): a call that omitted a named argument was never tested and was approved, so `auto_approve("Bash", {"command": r"^ls\b"})` approved a `Bash` call with no `command`. An absent named argument now hands the call to the next policy, like one that does not match; unnamed arguments, predicates and an empty mapping behave as before. A policy that relied on approving when the argument is missing now prompts for those calls.
- **Fix: the built-in chat registered its `Write` and `Edit` diff formatters twice** (`src/zrb/builtin/llm/chat.py`, `test/builtin/llm/test_chat.py`): `LLMChatTask` already appends both, so each approval prompt computed both diffs twice. The second registration is removed.
- **Fix: a leftover `ZRB_LLM_INCLUDE_JOURNAL_REMINDER` is named at startup** (`src/zrb/config/retired.py`, `test/config/test_config_env_warnings.py`): the setting was removed in 2.54.0 without a `RETIRED_SETTINGS` entry, so it was silently ignored.
- **Fix: an `LLMTask` subclass's `is_context_length_error` is honored on a failed run** (`src/zrb/llm/task/history.py`, `test/llm/task/test_history.py`): `handle_run_error` asked the history part's own copy of the check, so overriding the documented hook on the task changed nothing and a provider's context-length error grew the history the retry failed on again. It now asks the task.
- **Fix: the help panel lists a feature command once, not once per alias** (`src/zrb/llm/ui/base/commands.py`, `test/llm/ui/base/test_commands_basics.py`): a feature registers one command per alias under a shared description, and the panel gave each its own row while built-in groups list `commands[0]` alone (5 rows for 3 commands: `/voice`, `/v`, `/handsfree`, `/photo`, `/p`). A custom command whose description was already emitted is now skipped, giving 3 rows, and the greeting's `GREETING_COMMAND_LIMIT` covers that many more distinct commands. Registered commands are untouched: `/v` and `/p` still dispatch and the completion menu offers every alias.
- **Chore: the skill command is registered after the optional chat features** (`src/zrb/builtin/llm/chat.py`): `append_custom_command(get_skill_custom_command(skill_manager))` moved below the `enable_camera` / `enable_dictation` / `enable_speech` calls, so the skill command lists after the feature commands in the help panel.
- **Docstrings: `system_prompt`, `prompt_manager`, `summarize_commands`, `BaseTask(color=)` and `CmdTask(cwd=)` say what they do** (`src/zrb/llm/task/llm_task.py`, `src/zrb/llm/task/chat/task.py`, `src/zrb/task/base/base_task.py`, `src/zrb/task/cmd_task.py`): `system_prompt` is ignored when `prompt_manager` is given; the default `prompt_manager` holds only `system_prompt` with no built-in sections; `summarize_commands` are whole messages that compress the history instead of calling the model; `color` takes one of the 16 codes in `VALID_COLORS` (others print uncolored) and defaults to the session's rotating palette; `cwd` is annotated `StrAttr`, since a `Tpl` or callable was always resolved against the context.
- **Documentation: the architecture section states one uniform contract, and every claim in it is true** (`docs/architecture/`, `docs/contributing/architecture.md`, `docs/contributing/maintainer-guide.md`): all 18 tier pages open with the same one-line `The one idea to take away`. `docs/architecture/README.md` documents the skeleton the guards enforce (the tier header's `Code:` and `Read first:` fields, one line naming the idea, `### Change it here` as the last subsection of `## Realization`, `## See Also` closing the page, a named test in every row) and gained a ten-minute reading path. The Task Model page gained `DotDict` (`src/zrb/dot_dict/dot_dict.py`) and `AnyContentTransformer` / `ContentTransformer` (`src/zrb/content_transformer/`), each with a change-map row. `docs/contributing/architecture.md` now says `any_task.py`, `any_session.py` and `any_context.py` live in `src/zrb/task/`, `src/zrb/session/` and `src/zrb/context/`, and cites R9.
- **Tests: the architecture guards were split by feature group and extended** (`test/architecture/architecture_docs.py`, `test/architecture/test_architecture_docs.py`, `test/architecture/test_architecture_doc_symbols.py`, `test/architecture/test_doc_code_references.py`): the guard file had reached 473 of the 500-line budget, so the truth check became `test_architecture_doc_symbols.py` and the shared corpus accessors became `architecture_docs.py`. Four shape rules were added (`Code:` and `Read first:` in the tier header, the one-line idea, `### Change it here` closing Realization, a test in every row), each checked for content as well as shape: `Code: nothing` fails and so does `Code: does/not-exist/`, and `## See Also` must be the only section after Realization, ending with its links and the closing breadcrumb. `test_doc_code_references.py` never opened a markdown link, so a moved page left its referrers looking correct; every relative link in a live doc is now resolved (1,429 targets, none unresolved), and a target counts only when it resolves inside the checkout, so a link escaping the tree or leaving through a symlink is drift. The destination is parsed rather than taken as the text between parentheses, so a titled link (`[Architecture](README.md "The overview")`) or `<a page.md>` is read as the path it names and a label holding brackets no longer hides its link. A target under any URI scheme is left alone, and a fenced block ends at the marker that opened it, so a tilde fence holding a ``` sample no longer swallows the live links after it. Two exemptions are deliberate: a link inside a fenced block belongs to the example, and `docs/adr/adr-0055.md` spells ` ([note](path))` to describe the journal's link format.
- **Documentation: using any Pipecat speech-to-text or text-to-speech provider** (`docs/llm/programming-the-voice.md`, `docs/llm/voice-camera.md`): registering a Pipecat service with `tts_manager` / `stt_manager` was shown only with a placeholder SDK. Programming the Voice now walks through it with Floe for both directions and Groq's speech-to-text for services built from Pipecat's `Settings` object (it needs its API key passed, and its `provider` names the Pipecat module, since the core-dependency `openai` client would pass the availability check without Pipecat). It links Pipecat's provider lists, says a backend name does not switch the feature on, names the backends zrb matches before the registry (a service registered as `openai` or `vosk` is never used), and states which services fit the pipeline: every Pipecat TTS service, segmented STT services as they are, and a streaming STT service only if it finalizes on the stop frame.
- **Tests: doc samples follow the source's bracket style** (`test/architecture/test_doc_code_style.py`, `README.md`, `docs/`): six samples hung arguments under an unclosed call (`register("x", Spec(` … `))`) where the black-formatted source opens the bracket at line end and indents each argument four spaces. They are rewritten, and a guard fails on any Python sample in a live doc that hangs its arguments.
- **Documentation and docstrings: tool-approval customization is documented, and statements the source contradicts are corrected** (`docs/llm/tool-approval.md`, `src/zrb/llm/task/chat/task.py`, `src/zrb/llm/ui/base/ui.py`, `README.md`, `docs/`): the new Tool Approval page covers `LLMChatTask`'s three public extension lists (tool policies, argument formatters, response handlers), including which sub-agent turns run under the chat's tool policies. The `response_handlers` docstrings described post-processing a tool's result; they interpret the user's answer to an approval prompt, and the first to return a verdict decides. `llm_limiter=None` uses the shared default limiter rather than removing it, and the `ask_user` sample has the signature a custom UI must implement. Corrected docs: the readiness parameters of `HttpCheck` / `TcpCheck`, the web server's refusal of an insecure bind, `ctx.log_error`, the manager registry fallback, `prompts=` on tasks, and the `ask_user` / `print` signatures. Capability tagging for user tools and the `ZRB_PROJECT_ENV_KEYS` row are added.
- **Documentation: the extension points the audit found unnamed are documented** (`docs/task-types/llm-task.md`, `docs/`): a new `LLMTask` reference page, plus `CmdTask`'s SSH and runtime parameters, `Cmd` / `CmdPath`, `RsyncTask` pulls, `append_*` wiring and running a task from Python, trigger queues and items, Xcom callbacks, CLI argument forms, custom inputs and envs, web-auth user lookup with hashed verification, manager and registry methods, the summarizer building blocks, `UNTRUSTED_DATA_NOTE`, `AnyHistoryManager`, input provenance, `AnyUI` state members and the permission state API. Four statements are corrected: `auto_approve`'s mapping reads as the fix above implements it, a hand-built task has no built-in prompt sections, `LLMTask` keeps its history under `conversation_name`, and the `CmdTask` testing example, which ran with no `PATH`, no longer runs under a mocked context.

## 3.15.0 (October 6, 2026)

- **Fix: a project or home skill or agent replaces a built-in one of the same name** (`src/zrb/llm/skill/manager.py`, `src/zrb/llm/agent/subagent/manager_search.py`, `docs/configuration/llm-config.md`, `test/llm/skill/test_skill_manager_scan.py`, `test/llm/agent/subagent/test_manager_search.py`): both scanners let a later directory override an earlier one but put the built-in `llm_plugin/` directories after home, project, plugin and extra directories, so a project `.claude/skills/core-coding/SKILL.md` or `.claude/agents/generalist.agent.md` was silently replaced by the built-in it was written to override, contrary to ADR-0052. The built-in directories now come first, the docstrings and documented search order say low → high (the docs ranked home above project, the reverse of the scan), and a test per scanner pins a project definition over a built-in one. A project skill that replaces a core skill is listed among the available skills rather than the core ones, since core status follows the built-in path.
- **Breaking: `BufferedOutputMixin`'s override hook is `send_buffered`** (`src/zrb/llm/ui/buffered_output.py`, `docs/llm/llm-custom-ui.md`, `examples/chat-telegram/zrb_init.py`, `test/llm/ui/test_buffered_output.py`, `test/llm/ui/test_ui_variants.py`): the method every subclass must override was named `_send_buffered`, and the class docstring's example overrode `send_text`, which nothing calls, so a UI written from it never sent any output. The hook is now public (ADR-0035) and the docstring overrides it. Migrating: rename your `_send_buffered` to `send_buffered`; there is no alias.
- **Documentation: three statements the code contradicts** (`src/zrb/task/base/base_task.py`, `src/zrb/llm/speech/feature.py`, `docs/adr/adr-0103.md`): `readiness_failure_threshold`'s docstring said the task is declared failed; the threshold is read only while `monitor_readiness` is on, and reaching it cancels and restarts the action. Speech listened for a `permission_prompt` notification zrb never fires (approvals reach it through `PermissionRequest`, as the `approval` event), so the dead entry is gone and ADR-0103 no longer lists it under `question`.
- **Documentation: every docs tree was audited against the code, then reorganised for readers** (`AGENTS.md`, `README.md`, `docs/README.md` new, `docs/llm/README.md` new, `docs/contributing/README.md` new, `docs/architecture/1-spine/task-model.md` new, `docs/architecture/2-extension-surface/skills-and-commands.md` new, `docs/adr/adr-0091.md` removed, and pages across `docs/`; three test comments that cited ADR-0091): paths and symbols were already held true by the doc-reference tests, so the audit went after behaviour claims, defaults, examples and counts. Fixed claims include the `LLM_PROFILE` default (`auto`, not `standard`, ADR-0049), the approval cascade order (tool policies run before the permission ruleset, so a hard `ask` overrides only yolo; ADR-0062's title and the architecture principle had it reversed), ADR-0005 describing implicit string rendering that 3.0.0 replaced with opt-in `Tpl`, ADR-0035 describing the forwarding pattern AGENTS.md forbids, a Scaffolder XCom example that raised on its second file, a CI example that ran `pytest` in an image built without it, Claude-format hooks documented as loading `prompt`/`agent` types and a 600 s timeout, a custom UI `async on_exit` that is called synchronously, the maintainer guide's "green locally means green in CI", and an upgrading guide missing six 3.x breaks. For readers: a docs index and an LLM landing page with reading paths, breadcrumbs leading to the index, the first LLM chat added to installation, non-LLM settings moved from `llm-config.md` to `env-vars.md`, duplicated sections reduced to one owning page, contributor internals moved off user pages, AGENTS.md cut by a fifth with every rule kept, the ADR index re-themed, ADR-0091 merged into ADR-0090, and diary-style records, private helper names and point-in-time measurements taken out of the ADRs and architecture pages. The architecture docs gain the task model and the skills/commands surface.
- **Fix: a blocked STT initializer no longer keeps zrb alive after Ctrl+C** (`src/zrb/util/async_thread.py`, `src/zrb/llm/dictation/backend/pipecat.py`, `src/zrb/llm/dictation/backend/vosk.py`, `src/zrb/llm/hook/process_io.py`, `src/zrb/config/mixins/llm_dictation.py`, `docs/configuration/llm-config.md`, `test/util/test_async_thread.py`, `test/llm/dictation/backend/test_pipecat_backend.py`, `test/llm/dictation/backend/test_pipecat_backend_load.py`, `test/llm/dictation/backend/test_vosk_download.py`, `test/llm/dictation/test_feature_teardown.py`): Pipecat and vosk loaded models, decoded audio and downloaded or extracted models through `asyncio.to_thread()`, whose default-executor workers are non-daemon, so cancelling the coroutine left a blocking call that interpreter shutdown waited to join. Those calls now run on daemon threads through one shared runner, so a call still inside native code cannot hold process exit. Such a call cannot be stopped, so a result landing after its caller was cancelled is handed to whoever asked for it rather than dropped: a Pipecat service whose model finished loading for a cancelled `prepare` is cleaned up (`STTService.cleanup`), and a Vosk response opened after its download was cancelled is closed; only the call's own result is handed over, since a disposer has no use for the exception. A Pipecat service is closed on a loop of its own when the loop that waited for it is gone, and a service no pipeline could be started around is closed too: `prepare` owns the service from the moment its load returns until a pipeline adopts it. Vosk's model archive is removed by the extractor itself rather than only by the caller, which a cancellation returns past while the extractor still reads the file (a removal that fails silently wherever an open file cannot be deleted). The Vosk connection is bounded whatever the knob says: `ZRB_LLM_DICTATION_VOSK_DOWNLOAD_TIMEOUT=0` means the transfer is not capped, not that a socket may wait forever.
- **Feature: cloud dictation keeps the language it was spoken in, and takes a hint** (`src/zrb/config/mixins/llm_dictation.py`, `src/zrb/llm/dictation/config.py`, `src/zrb/llm/dictation/backend/builtin.py`, `src/zrb/llm/dictation/backend/openai.py`, `docs/configuration/llm-config.md`, `test/llm/dictation/backend/test_builtin.py`, `test/llm/dictation/backend/test_openai.py`): the `google` and `multimodal` backends were asked to "Transcribe this audio to text. Return only the transcription.", which a multilingual model may answer in translation. The default `ZRB_LLM_DICTATION_TRANSCRIBE_PROMPT` is now "Transcribe exactly what is spoken. Do not translate or paraphrase. Return only the transcription.", and the setting still replaces it. `ZRB_LLM_DICTATION_LANGUAGE` (empty: detect) is new: an ISO-639-1 code such as `en` or `id`, which `OpenAIDictationBackend` passes to the transcription API as its `language` hint so `whisper-1` and `gpt-4o-transcribe` no longer guess at a short utterance. It reaches the backend through `DictationConfig.language` and applies to streaming and whole-utterance calls alike.
- **Performance: a task run no longer pays the state logger's 100 ms tick** (`src/zrb/task/base/lifecycle.py`, `test/task/test_lifecycle.py`): `execute_root_tasks` terminated the session and then awaited `log_session_state`, which was parked in its 100 ms interval, so every `Task.run()` paid what was left of that tick (a no-op task paid all of it). The run now hands the logger an `asyncio.Event` set the moment the session terminates; the loop waits on it with the same 100 ms timeout, so the logging cadence is unchanged (a 0.55 s task still wrote 9 state lines), and a session terminated elsewhere keeps the `asyncio.sleep` fallback. On Python 3.14 a no-op `Task.run()` went from 103.0 ms median (n=20) to 1.3 ms, and an eight-task serial `CmdTask` DAG from 123 ms to 39 ms.
- **Documentation: the decision numbers and the editorial asides left the surfaces a user reads** (`docs/configuration/llm-config.md`, `docs/configuration/llm-collections.md`, `docs/llm/extending-the-llm.md`, `docs/llm/hooks.md`, `docs/llm/llm-chat-lifecycle.md`, `docs/llm/permission-policy.md`, `docs/llm/programming-the-prompt.md`, `docs/llm/sandbox.md`, `docs/llm/voice-camera.md`, `docs/task-types/llmchat-task.md`, `docs/advanced-topics/upgrading-guide.md`, `examples/themes/monokai/README.md`, and 37 then 44 files under `src/zrb`): `ADR-NNNN` citations were removed from everything a user reads and kept where a decision is defended (`docs/adr/`, `docs/architecture/`, `docs/contributing/`, `docs/technical-specs/`). Twelve went from the configuration pages, 29 from `docs/llm`, the `llmchat` task type and the upgrading guide, one from an example README, and 58 from comments and docstrings in 37 source files. A citation that was the whole sentence took the sentence with it; a trailing parenthetical went alone. The visible one was `ZRB_LLM_DICTATION_PIPECAT_ENABLED`, which described itself as "Stage 1 of the migration (ADR-0107)" in its doc and its `llm-config.md` row; the setting itself is removed below. A second sweep across 44 source files took comments that editorialize instead of stating mechanism: "the whole reason/point" (5 sites) now states the reason, "only ever" (22) became "only", and "simply", "truly" and emphatic "very"/"really" (21) were dropped. "Deliberately" (46) and a precise "entirely" stay, since they stop a future reader from "fixing" a decision. Every changed line is a comment, docstring or Markdown line (checked by comparing the code-only token streams of HEAD and the working tree), so no behavior changed.
- **Fix: a side question is told that "you" means the main agent** (`src/zrb/llm/prompt/markdown/side_question.md`): `/btw` asks about the user's conversation, and the side agent read "can you explain that?" as addressed to itself. `side_question.md` now says "you", "your" and anything else referring to the main agent mean the main agent in that conversation, and to answer from the inherited history.
- **Performance: the shell's live output and its console echo are capped lower** (`src/zrb/llm/tool/shell.py`, `src/zrb/config/mixins/llm_limits.py`, `docs/configuration/llm-config.md`): `_LIVE_UPDATE_INTERVAL`, how often the Shell tool repaints a running command's output, went from 0.1 s to 0.5 s, and `ZRB_LLM_MAX_CONSOLE_OUTPUT_CHARS` from 1,000,000 to 100,000, the cap the model already reads under. A build that scrolled in full still does; gone is the echo of output the model never sees, which a runaway command could spend minutes printing.
- **Fix: a recalled message that has already run needs a second Enter** (`src/zrb/llm/ui/default/message_editing.py`, `docs/adr/adr-0077.md`, `test/llm/ui/default/test_keybindings_history_nav.py`, `test/llm/ui/default/test_queued_messages.py`): Up Arrow recalls a queued message for editing and Enter submitted whatever the box held, so a recall made only to read a message sent it again, and when its turn had started the same text ran twice. The first Enter now warns and leaves recall mode with the text still editable; only a second, deliberate Enter resubmits an already-started or already-sent message. In-place editing of a queued message and `Ctrl+X` dropping the recalled one are unchanged, and ADR-0077 records the rule.
- **Fix: a hook that will not finish no longer holds the interpreter open** (`src/zrb/llm/hook/executor.py`, `test/llm/hook/test_executor.py`): hooks ran on a `concurrent.futures.ThreadPoolExecutor`, whose non-daemon workers keep the interpreter alive, so a cancelled or stuck hook left `zrb` needing a second Ctrl+C. The executor is now `_DaemonHookExecutor`, a fixed pool of daemon worker threads draining one `queue.Queue`, with the same `max_workers`, future-per-submission contract and refusal to schedule after shutdown. A subprocess test pins the shutdown behavior.
- **Fix: `/set` wrote a value the next read did not see** (`src/zrb/config/env_field.py`, `test/config/test_config_llm.py`): `EnvField.__set__` writes only the write key while reads resolve aliases in declared order, and `ZRB_LLM_MAX_TOKEN_PER_MINUTE` declares `[singular, plural]` with `write_key="LLM_MAX_TOKENS_PER_MINUTE"`. With `ZRB_LLM_MAX_TOKEN_PER_MINUTE=7`, `/set LLM_MAX_TOKEN_PER_MINUTE 11` wrote the plural key, reads kept returning `7`, and the command printed success. `__set_name__` now orders the write key first among the readable aliases without dropping any, so a written value is the value read, and a legacy alias is still read when nothing else is set.
- **Fix: speech queued before an interrupt is no longer played after it** (`src/zrb/llm/speech/player.py`, `test/llm/speech/test_player.py`): `Speaker.interrupt()` drops queued speech and bumps a generation for the stale check, but the worker read the current generation only after dequeuing, so an item dequeued just before the bump was stamped with the later generation and let through. The generation is now captured in `_enqueue` while it holds the speaker lock and carried with the item, and the stale check compares it with the current one. Pause, resume, drain, close, backend selection and the two-thread design are untouched.
- **Fix: background output that was dropped is reported** (`src/zrb/util/cmd/command.py`, `src/zrb/llm/tool/shell.py`, `src/zrb/llm/ui/base/exec_commands.py`, `test/llm/tool/test_shell_command.py`, `test/llm/ui/base/test_commands_shell.py`): when a command left a child holding the output pipes open (`(sleep 1; echo LATE) &`), `wait_for_exit_and_drain` waited at most `PIPE_DRAIN_GRACE_SECONDS` (0.5 s) for the readers, cancelled them and said nothing, so a run that lost output could be read as complete. It now takes an optional `reporter` and says what it dropped, which the Shell tool includes in its output and `/exec` writes to the UI. The exit code is still the return value, and the pipes are still not waited on longer.
- **Fix: a progress line queued by a turn is not read aloud after it** (`src/zrb/llm/speech/progress.py`, `test/llm/speech/test_progress.py`): `ProgressNarrator` discarded a call id only on `function_tool_result`, so a call interrupted or raising before a result left its id in `_running` and the queued line stayed eligible ("Running a command." spoken after the turn ended). `reset()` now clears the pending call ids and `handle_stop` calls it. Since a tool-call id can recur in a later turn, every queued line also carries its turn generation and `_is_finished` compares it, so a line from an earlier turn stays stale and one still being decided on when the turn stops is never queued. The announcement interval, silence check, silent-tool list and phrase templates are untouched.
