## 3.15.2 (October 8, 2026)

_Cumulative summary of the 3.15.1–3.15.2 patch line._

- **Fix: the mistyped-variable warning no longer calls a project's own env vars typos** (`src/zrb/config/config.py`, `src/zrb/config/mixins/foundation.py`, `docs/configuration/env-vars.md`, `docs/advanced-topics/white-labeling.md`): the warning flagged any `<ENV_PREFIX>_*` variable scoring 0.85 or better against a setting name, and no cutoff separates a real typo (`MAX_TOKEN_PER_MINUTE`, 0.92) from a project's own variable (`LLM_PROXY_BASE_URL`, 0.864); 4 of the 29 `ARASAKA_*` variables bsim-agent reads were reported. The new `PROJECT_ENV_KEYS` setting takes prefix-relative names, exact (`LLM_PLUGIN_DIR`) or `*` glob (`LLM_PROXY_*`), that both the mistyped and the retired report skip and never suggest. Unclaimed typos are still reported. The warning runs after the init sources load, so `zrb_init.py` can claim keys; a test pins that ordering.
- **Fix: a `str` assigned to a config field is stored as the env text rather than serialized** (`src/zrb/config/env_field.py`, `src/zrb/config/mixins/foundation.py`): since the 3.0 configuration rewrite, `EnvField.__set__` serialized every assigned value, so `CFG.LLM_TOOLS = "Shell,Read"` was stored as `S,h,e,l,l,,,R,e,a,d` and `CFG.LLM_SHOW_TOOL_CALL_DETAIL = "off"` read back as `True`, silently. It affected every list- and mapping-valued setting (`LLM_TOOLS`, `LLM_SKILLS`, `LLM_AGENTS`, `LLM_HOOKS`, `LLM_PLUGIN_DIRS`, `INIT_MODULES`, `PROJECT_ENV_KEYS`, `LLM_SPEECH_PROGRESS_PHRASES`) and the path lists. A string is now stored as written; casts still validate (`CFG.WEB_HTTP_PORT = "abc"` fails) and a tuple on a list field is still refused. No zrb code path was affected (env reads and `/set` never hit it); the exposure was project bootstrap code in `zrb_init.py` or a white label's init module.
- **Fix: a message to a live background sub-agent runs under the chat's tool policies** (`src/zrb/llm/agent/run/authority_snapshot.py`, `src/zrb/llm/agent/subagent/live_session.py`, `docs/architecture/2-extension-surface/sub-agents.md`): a follow-up to a still-live sub-agent starts after the approval-handler scope ended, and `AuthoritySnapshot` did not carry the approval handler or channel, so the continuation skipped the chat's tool policies (a `ToolDenied` policy did not bind it) and reached no approval channel. The snapshot now captures both, and each continuation passes them to `run_agent`.
- **Fix: `auto_approve` with an argument mapping requires every named argument** (`src/zrb/llm/tool_call/tool_policy/auto_approve.py`, `test/llm/tool_call/tool_policy/test_auto_approve.py`, `test/llm/tool_call/test_allow_tool.py`): a call that omitted a named argument was never tested and was approved, so `auto_approve("Bash", {"command": r"^ls\b"})` approved a `Bash` call with no `command`. An absent named argument now hands the call to the next policy, like one that does not match; unnamed arguments, predicates and an empty mapping behave as before. A policy that relied on approving when the argument is missing now prompts for those calls.
- **Fix: the built-in chat registered its `Write` and `Edit` diff formatters twice** (`src/zrb/builtin/llm/chat.py`, `test/builtin/llm/test_chat.py`): `LLMChatTask` already appends both, so each approval prompt computed both diffs twice. The second registration is removed.
- **Fix: a leftover `ZRB_LLM_INCLUDE_JOURNAL_REMINDER` is named at startup** (`src/zrb/config/retired.py`, `test/config/test_config_env_warnings.py`): the setting was removed in 2.54.0 without a `RETIRED_SETTINGS` entry, so it was silently ignored.
- **Fix: an `LLMTask` subclass's `is_context_length_error` is honored on a failed run** (`src/zrb/llm/task/history.py`, `test/llm/task/test_history.py`): `handle_run_error` asked the history part's own copy of the check, so overriding the documented hook on the task changed nothing and a provider's context-length error grew the history the retry failed on again. It now asks the task.
- **Fix: the help panel lists a feature command once, not once per alias** (`src/zrb/llm/ui/base/commands.py`): feature commands got one row per alias (5 rows for 3 commands: `/voice`, `/v`, `/handsfree`, `/photo`, `/p`), while built-in groups list only the first. A custom command whose description was already shown is now skipped, giving 3 rows, so the greeting's `GREETING_COMMAND_LIMIT` covers more distinct commands. Every alias still dispatches and appears in completion.
- **Chore: the skill command is registered after the optional chat features** (`src/zrb/builtin/llm/chat.py`): `append_custom_command(get_skill_custom_command(skill_manager))` moved below the `enable_camera` / `enable_dictation` / `enable_speech` calls, so the skill command lists after the feature commands in the help panel.
- **Docstrings: `system_prompt`, `prompt_manager`, `summarize_commands`, `BaseTask(color=)` and `CmdTask(cwd=)` say what they do** (`src/zrb/llm/task/llm_task.py`, `src/zrb/llm/task/chat/task.py`, `src/zrb/task/base/base_task.py`, `src/zrb/task/cmd_task.py`): `system_prompt` is ignored when `prompt_manager` is given; the default `prompt_manager` holds only `system_prompt`, with no built-in sections; `summarize_commands` are whole messages that compress the history instead of calling the model; `color` takes one of the 16 `VALID_COLORS` codes (others print uncolored) and defaults to the session's rotating palette; `cwd` is annotated `StrAttr`, since a `Tpl` or callable was always resolved.
- **Documentation: the architecture section states one uniform contract, and every claim in it is true** (`docs/architecture/`, `docs/contributing/architecture.md`, `docs/contributing/maintainer-guide.md`): all 18 tier pages open with the same one-line `The one idea to take away`. `docs/architecture/README.md` documents the guard-enforced page skeleton and gained a ten-minute reading path. The Task Model page gained `DotDict` and `AnyContentTransformer` / `ContentTransformer`, each with a change-map row. `docs/contributing/architecture.md` now places `any_task.py`, `any_session.py` and `any_context.py` in `src/zrb/task/`, `src/zrb/session/` and `src/zrb/context/`, and cites R9.
- **Tests: the architecture guards were split by feature group and extended** (`test/architecture/architecture_docs.py`, `test/architecture/test_architecture_docs.py`, `test/architecture/test_architecture_doc_symbols.py`, `test/architecture/test_doc_code_references.py`): the guard file (473 of 500 lines) was split into `test_architecture_doc_symbols.py` and shared `architecture_docs.py` accessors. Four page-shape rules were added and checked for content (`Code: nothing` and `Code: does/not-exist/` fail). `test_doc_code_references.py` now resolves every relative markdown link in a live doc (1,429 targets, none unresolved), counting only targets inside the checkout; it parses titled links and `<…>` destinations, lets a label hold brackets, skips URI schemes, and ends a fenced block at its own marker. Deliberate exemptions: links inside fenced blocks, and `docs/adr/adr-0055.md`'s description of the journal link format.
- **Documentation: using any Pipecat speech-to-text or text-to-speech provider** (`docs/llm/programming-the-voice.md`, `docs/llm/voice-camera.md`): registering a service with `tts_manager` / `stt_manager` was shown only with a placeholder SDK. Programming the Voice now walks through Floe for both directions and Groq speech-to-text for services built from Pipecat's `Settings` object (its API key passed, and `provider` naming the Pipecat module, since the core `openai` client would pass the availability check without Pipecat), links Pipecat's provider lists, and states that a backend name does not switch the feature on, which built-in names shadow the registry (`openai`, `vosk`), and which services fit the pipeline: every TTS service, segmented STT services as-is, and streaming STT only if it finalizes on the stop frame.
- **Tests: doc samples follow the source's bracket style** (`test/architecture/test_doc_code_style.py`, `README.md`, `docs/`): six samples hung arguments under an unclosed call (`register("x", Spec(` … `))`) where the black-formatted source opens the bracket at line end and indents each argument four spaces. They are rewritten, and a guard fails on any Python sample in a live doc that hangs its arguments.
- **Documentation and docstrings: tool-approval customization is documented, and statements the source contradicts are corrected** (`docs/llm/tool-approval.md`, `src/zrb/llm/task/chat/task.py`, `src/zrb/llm/ui/base/ui.py`, `README.md`, `docs/`): a new Tool Approval page covers `LLMChatTask`'s tool policies, argument formatters and response handlers, including which sub-agent turns run under the chat's policies. Corrected: `response_handlers` interpret the user's answer to an approval prompt (first verdict wins), not a tool's result; `llm_limiter=None` uses the shared default limiter; the `ask_user` sample and `ask_user` / `print` signatures; `HttpCheck` / `TcpCheck` readiness parameters; the web server's refusal of an insecure bind; `ctx.log_error`; the manager registry fallback; and `prompts=` on tasks. Capability tagging for user tools and the `ZRB_PROJECT_ENV_KEYS` row were added.
- **Documentation: the extension points the audit found unnamed are documented** (`docs/task-types/llm-task.md`, `docs/`): a new `LLMTask` reference page, plus `CmdTask` SSH and runtime parameters, `Cmd` / `CmdPath`, `RsyncTask` pulls, `append_*` wiring, running a task from Python, trigger queues and items, Xcom callbacks, CLI argument forms, custom inputs and envs, web-auth user lookup with hashed verification, manager and registry methods, summarizer building blocks, `UNTRUSTED_DATA_NOTE`, `AnyHistoryManager`, input provenance, `AnyUI` state members and the permission state API. Corrected: `auto_approve`'s mapping semantics, that a hand-built task has no built-in prompt sections, that `LLMTask` keeps history under `conversation_name`, and the `CmdTask` testing example, which ran with no `PATH` and no longer runs under a mocked context.

## 3.15.0 (October 6, 2026)

- **Fix: a project or home skill or agent replaces a built-in one of the same name** (`src/zrb/llm/skill/manager.py`, `src/zrb/llm/agent/subagent/manager_search.py`, `docs/configuration/llm-config.md`): both scanners let a later directory override an earlier one but scanned the built-in `llm_plugin/` directories last, so a project `.claude/skills/core-coding/SKILL.md` or `.claude/agents/generalist.agent.md` was silently replaced by the built-in it meant to override, contrary to ADR-0052. Built-ins now come first, pinned by a test per scanner; the docstrings and documented search order read low → high (the docs had ranked home above project, the reverse of the scan). A project skill replacing a core skill is listed among the available skills, not the core ones, since core status follows the built-in path.
- **Breaking: `BufferedOutputMixin`'s override hook is `send_buffered`** (`src/zrb/llm/ui/buffered_output.py`, `docs/llm/llm-custom-ui.md`, `examples/chat-telegram/zrb_init.py`, `test/llm/ui/test_buffered_output.py`, `test/llm/ui/test_ui_variants.py`): the method every subclass must override was named `_send_buffered`, and the class docstring's example overrode `send_text`, which nothing calls, so a UI written from it never sent any output. The hook is now public (ADR-0035) and the docstring overrides it. Migrating: rename your `_send_buffered` to `send_buffered`; there is no alias.
- **Documentation: three statements the code contradicts** (`src/zrb/task/base/base_task.py`, `src/zrb/llm/speech/feature.py`, `docs/adr/adr-0103.md`): `readiness_failure_threshold`'s docstring said the task is declared failed; the threshold is read only while `monitor_readiness` is on, and reaching it cancels and restarts the action. Speech listened for a `permission_prompt` notification zrb never fires (approvals reach it through `PermissionRequest`, as the `approval` event), so the dead entry is gone and ADR-0103 no longer lists it under `question`.
- **Documentation: every docs tree was audited against the code, then reorganised for readers** (`AGENTS.md`, `README.md`, `docs/README.md` new, `docs/llm/README.md` new, `docs/contributing/README.md` new, `docs/architecture/1-spine/task-model.md` new, `docs/architecture/2-extension-surface/skills-and-commands.md` new, `docs/adr/adr-0091.md` removed, and pages across `docs/`): the audit checked behaviour claims, defaults, examples and counts. Fixed: the `LLM_PROFILE` default (`auto`, not `standard`), the approval cascade order (tool policies run before the permission ruleset, so a hard `ask` overrides only yolo; ADR-0062 had it reversed), ADR-0005 and ADR-0035 describing replaced or forbidden patterns, a Scaffolder XCom example that raised on its second file, a CI example without `pytest`, Claude-format hooks wrongly documented as loading `prompt`/`agent` types with a 600 s timeout, a custom UI `async on_exit` that is called synchronously, "green locally means green in CI", and an upgrading guide missing six 3.x breaks. For readers: a docs index and LLM landing page with reading paths, breadcrumbs to the index, a first LLM chat in installation, non-LLM settings moved to `env-vars.md`, duplicates reduced to one owning page, contributor internals off user pages, AGENTS.md cut by a fifth with every rule kept, the ADR index re-themed, ADR-0091 merged into ADR-0090, diary-style records and point-in-time measurements removed from ADRs and architecture pages, and architecture pages for the task model and skills/commands surface.
- **Fix: a blocked STT initializer no longer keeps zrb alive after Ctrl+C** (`src/zrb/util/async_thread.py`, `src/zrb/llm/dictation/backend/pipecat.py`, `src/zrb/llm/dictation/backend/vosk.py`, `src/zrb/llm/hook/process_io.py`, `docs/configuration/llm-config.md`): Pipecat and vosk ran model loads, decoding and model downloads/extraction through `asyncio.to_thread()`, whose non-daemon workers interpreter shutdown waits to join. They now run on daemon threads through one shared runner. A result landing after its caller was cancelled is handed to a disposer instead of dropped: a late-loaded Pipecat service is cleaned up (`STTService.cleanup`), a late Vosk response is closed, a Pipecat service is closed on a loop of its own when its loop is gone, and one no pipeline could start around is closed. `prepare` owns a Pipecat service from load until a pipeline adopts it, and only a call's own result (never its exception) reaches the disposer. The extractor removes Vosk's archive itself, since a cancelled caller could return while it still read the file (and removal fails wherever an open file cannot be deleted). `ZRB_LLM_DICTATION_VOSK_DOWNLOAD_TIMEOUT=0` now means the transfer is uncapped, not that a socket may wait forever.
- **Feature: cloud dictation keeps the language it was spoken in, and takes a hint** (`src/zrb/config/mixins/llm_dictation.py`, `src/zrb/llm/dictation/backend/builtin.py`, `src/zrb/llm/dictation/backend/openai.py`, `docs/configuration/llm-config.md`): the `google` and `multimodal` backends' prompt let a multilingual model answer in translation. The default `ZRB_LLM_DICTATION_TRANSCRIBE_PROMPT` is now "Transcribe exactly what is spoken. Do not translate or paraphrase. Return only the transcription." (still overridable). The new `ZRB_LLM_DICTATION_LANGUAGE` (empty: detect) takes an ISO-639-1 code (`en`, `id`) that `OpenAIDictationBackend` passes as the API's `language` hint, so `whisper-1` and `gpt-4o-transcribe` no longer guess on short utterances, streaming or not.
- **Performance: a task run no longer pays the state logger's 100 ms tick** (`src/zrb/task/base/lifecycle.py`): every `Task.run()` waited out what was left of `log_session_state`'s 100 ms interval after the session terminated. The logger now wakes on an `asyncio.Event` set at termination, with the same 100 ms cadence (a 0.55 s task still wrote 9 state lines) and the `asyncio.sleep` fallback for a session terminated elsewhere. On Python 3.14 a no-op `Task.run()` went from 103.0 ms median (n=20) to 1.3 ms, and an eight-task serial `CmdTask` DAG from 123 ms to 39 ms.
- **Documentation: the decision numbers and the editorial asides left the surfaces a user reads** (`docs/configuration/`, `docs/llm/`, `docs/task-types/llmchat-task.md`, `docs/advanced-topics/upgrading-guide.md`, `examples/themes/monokai/README.md`, and 37 then 44 files under `src/zrb`): `ADR-NNNN` citations were removed from user-facing docs and kept where decisions are defended (`docs/adr/`, `docs/architecture/`, `docs/contributing/`, `docs/technical-specs/`): 12 from configuration pages, 29 from `docs/llm`, the `llmchat` page and the upgrading guide, one from an example README, and 58 from comments and docstrings in 37 source files, a citation that was the whole sentence taking the sentence with it, including `ZRB_LLM_DICTATION_PIPECAT_ENABLED`'s "Stage 1 of the migration (ADR-0107)". A second sweep over 44 source files replaced editorializing comments ("the whole reason/point", 5; "only ever", 22; "simply"/"truly"/emphatic "very"/"really", 21), keeping "deliberately" (46) and a precise "entirely". Only comments, docstrings and Markdown changed (verified by comparing code-only token streams).
- **Fix: a side question is told that "you" means the main agent** (`src/zrb/llm/prompt/markdown/side_question.md`): `/btw` asks about the user's conversation, and the side agent read "can you explain that?" as addressed to itself. `side_question.md` now says "you", "your" and anything else referring to the main agent mean the main agent in that conversation, and to answer from the inherited history.
- **Performance: the shell's live output and its console echo are capped lower** (`src/zrb/llm/tool/shell.py`, `src/zrb/config/mixins/llm_limits.py`, `docs/configuration/llm-config.md`): the Shell tool repaints a running command's output every 0.5 s (was 0.1 s), and `ZRB_LLM_MAX_CONSOLE_OUTPUT_CHARS` dropped from 1,000,000 to 100,000, the cap the model already reads under. A runaway command no longer spends minutes echoing output the model never sees.
- **Fix: a recalled message that has already run needs a second Enter** (`src/zrb/llm/ui/default/message_editing.py`, `docs/adr/adr-0077.md`): Enter submitted whatever the box held, so recalling a queued message just to read it sent it again, and one whose turn had started ran twice. The first Enter now warns and leaves recall mode with the text editable; only a second Enter resubmits an already-started or already-sent message. In-place editing and `Ctrl+X` are unchanged. See ADR-0077.
- **Fix: a hook that will not finish no longer holds the interpreter open** (`src/zrb/llm/hook/executor.py`): hooks ran on a `ThreadPoolExecutor` whose non-daemon workers kept the interpreter alive, so a stuck hook needed a second Ctrl+C. `_DaemonHookExecutor` is a fixed pool of daemon threads with the same `max_workers`, future-per-submission contract and refusal after shutdown; a subprocess test pins the shutdown.
- **Fix: `/set` wrote a value the next read did not see** (`src/zrb/config/env_field.py`): writes went to the write key while reads tried aliases in declared order, so with `ZRB_LLM_MAX_TOKEN_PER_MINUTE=7`, `/set LLM_MAX_TOKEN_PER_MINUTE 11` wrote the plural `LLM_MAX_TOKENS_PER_MINUTE`, reads kept returning `7`, and the command reported success. `__set_name__` now orders the write key first among the readable aliases, dropping none, so a written value is the value read and a legacy alias is still read when nothing else is set.
- **Fix: speech queued before an interrupt is no longer played after it** (`src/zrb/llm/speech/player.py`): `Speaker.interrupt()` bumps a generation to mark queued speech stale, but the worker read the generation after dequeuing, so an item dequeued just before the bump slipped through. The generation is now captured at enqueue under the speaker lock and carried with the item. Pause, resume, drain, close, backend selection and the two-thread design are unchanged.
- **Fix: background output that was dropped is reported** (`src/zrb/util/cmd/command.py`, `src/zrb/llm/tool/shell.py`, `src/zrb/llm/ui/base/exec_commands.py`): when a command left a child holding the output pipes open (`(sleep 1; echo LATE) &`), `wait_for_exit_and_drain` gave up after `PIPE_DRAIN_GRACE_SECONDS` (0.5 s) silently, so lost output looked complete. It now takes an optional `reporter` and says what it dropped; the Shell tool includes that in its output and `/exec` writes it to the UI. The exit code and the grace period are unchanged.
- **Fix: a progress line queued by a turn is not read aloud after it** (`src/zrb/llm/speech/progress.py`): `ProgressNarrator` forgot a call only on its result, so an interrupted or raising call left its line eligible ("Running a command." spoken after the turn ended). `reset()` now clears pending call ids and `handle_stop` calls it; since a call id can recur, each queued line also carries its turn generation, so an earlier turn's line stays stale and one decided on as the turn stops is never queued. Interval, silence check, silent-tool list and phrase templates are unchanged.
- **Fix: cancelling a turn stops the progress announcement it is speaking** (`src/zrb/llm/speech/feature.py`): the stop hook was registered only for sessions that speak replies, so with `progress` but no `reply` in `ZRB_LLM_SPEECH_EVENTS`, Escape or a barge-in dropped queued lines but not the one being spoken. A `progress`-only session now registers it, and `speaker.interrupt()` no longer depends on the reply event (`streamed_reply.reset()` still does).
- **Fix: history written while the file lock was held is flushed at teardown** (`src/zrb/llm/ui/default/previous_message_history.py`, `src/zrb/llm/ui/default/lifecycle.py`): the previous-message history tries its lock once, and a write that lost the race waited in memory for the next write, so a session ending first lost those messages. `PreviousMessageHistory.close()` makes one bounded (0.25 s) flush attempt at teardown, and the teardown's `finally` blocks are nested so capture stop, buffered output, background-task cleanup and the flush each run even if an earlier step fails (a closed stdout pipe used to skip cleanup and flush). Submitting stays non-blocking and persistence stays atomic, best-effort and non-raising.
- **Tests: the scheduler's minute-boundary flake is pinned out** (`test/task/test_scheduler.py`): `test_scheduler_triggers_on_match` failed on Windows when two calls 10 ms apart straddled a real minute boundary; its clock is now pinned inside one minute, with assertions as strict as before.
- **Feature: `prune` removes the merged branches' worktrees with them** (`src/zrb/builtin/git.py`, `src/zrb/util/git/commands.py`): `prune-local-git-branches` (alias `prune`) silently left behind any merged branch checked out in a linked worktree, since `git branch -d` refuses it. It now removes each merged branch's worktrees (`remove_worktree`, `git worktree remove`) before deleting the branch. Worktree listing (`get_worktrees`) is read whole, bypassing `run_command`'s output-line cap; decodes quoted non-ASCII paths (`-c core.quotePath=true`); parses `+`-prefixed branch lines; and keeps every worktree of a branch, not only the last.
- **Breaking: the stage-1 Pipecat input tap is removed** (`src/zrb/llm/dictation/listen.py`, `src/zrb/llm/dictation/feature.py`, `src/zrb/config/mixins/llm_dictation.py`, `src/zrb/config/retired.py`, `docs/adr/adr-0107.md`, `docs/architecture/3-peripheral-flow/voice-on-pipecat.md`, `docs/advanced-topics/upgrading-guide.md`): 3.14.0's `ZRB_LLM_DICTATION_PIPECAT_ENABLED` fed captured audio to a Pipecat pipeline that decided nothing; it existed to measure Pipecat's detector against `UtteranceCutter` for a later stage that was never built. The `_CaptureTap`, the `[transport, detector, metrics stage, counter]` pipeline, the `on_captured` hook, the line a listening ended with, `AudioPipeline` and `SpeechMetricsRecorder` are gone; nothing zrb hears or says changes. The setting is reported at startup for one release and in the upgrading guide. To check a device, use `zrb voice mic-test` in `examples/voice-interaction`. Pipecat STT/TTS behind `ZRB_LLM_DICTATION_BACKEND` / `ZRB_LLM_SPEECH_BACKEND` is unaffected; ADR-0107 records the detector-driven stages as abandoned.
- **Documentation: the guides and examples lost the marketing adjectives and empty emphasis no other page used** (`docs/llm/`, `docs/task-types/`, `docs/core-concepts/`, `docs/contributing/architecture.md`, `docs/advanced-topics/white-labeling.md`, `examples/chat-sse/README.md`, `examples/chat-telegram/README.md`, `examples/chat-minimal-ui/zrb_init.py`): an audit of every `src/zrb` comment and live page found the comments clean and fourteen empty lines of prose ("a powerful, built-in AI assistant", "a robust, first-match-wins permission system", `zrb_init.py` as "your magic file", `Scaffolder` as "a powerful templating engine", `Env` as "a powerful way to configure", a "Robust LLM Integration" heading), language `core-writing/templates/readme.md` forbids; no comment named a missing file, symbol, setting or test, or carried filler. The adjectives and contentless emphasis ("Just 2 methods to implement!", "Register - ONE line!", "first response wins!", "No polling, no missed messages!", a trailing "!" on four sentences) were removed; no page changed meaning.
- **Fix: the SSE example's UI could not be handed an input source** (`examples/chat-sse/zrb_init.py`): `SSEUI.handle_incoming_message` took one parameter where `EventDrivenUI` takes `(text, source=None)`, so a caller passing provenance would have raised. It now forwards `source` to `super()`. CI missed it because `pyright src/zrb` excludes `examples/`; `pyright examples/` now reports one error in this file instead of three (the `hasattr(msg, "model_dump")` guard is left as written).
- **Feature: dictation and speech run Pipecat services, chosen by name** (`src/zrb/llm/voice/`, `src/zrb/llm/dictation/pipecat_stt.py`, `src/zrb/llm/dictation/backend/pipecat.py`, `src/zrb/llm/speech/pipecat_tts.py`, `src/zrb/llm/speech/backend/pipecat.py`, `src/zrb/config/mixins/llm_dictation.py`, `src/zrb/config/mixins/llm_speech.py`, `docs/adr/adr-0107.md`, `docs/architecture/3-peripheral-flow/voice-on-pipecat.md`, `docs/configuration/llm-config.md`): `ZRB_LLM_DICTATION_BACKEND` now accepts a Pipecat speech-to-text service (`whisper`, `moonshine`, `funasr`) and `ZRB_LLM_SPEECH_BACKEND` a text-to-speech one (`kokoro`, `piper`, `pocket`), through `stt_registry` / `tts_registry` (ADR-0090's shape), so a project can register or replace a service from `zrb_init.py`. zrb still cuts utterances and plays audio, so every transcript guard and pause/resume/interrupt behave as with vosk (see ADR-0107); closing a sentence's audio interrupts its synthesis; vosk, OpenAI/Google/multimodal and `say`/espeak-ng/Termux are untouched. A segment a local service finds no words in answers as an empty transcript rather than waiting out the timeout. An unset `ZRB_LLM_SPEECH_VOICE` now falls back to `en_US-ryan-high` (`piper`) and `af_heart` (`kokoro`) instead of raising; models download once and run offline after. On Python 3.14: piper renders 24 kHz audio with a 0.31 s first chunk (115 MB cached); moonshine runs offline once cached (138 MB) if it resolves to the cached architecture (its default picks the newest, a download); kokoro-onnx declares `requires_python <3.14` (its pure-Python wheel imports under `--ignore-requires-python`); pocket installs and drags PyTorch.
- **Fix: a Pipecat pipeline is no longer taken away between utterances** (`src/zrb/llm/dictation/pipecat_stt.py`, `src/zrb/llm/speech/pipecat_tts.py`, `docs/adr/adr-0107.md`): Pipecat's `PipelineWorker` cancels itself after `IDLE_TIMEOUT_SECS` (300 s) with no frame from `idle_timeout_frames` (armed by the last `TranscriptionFrame` or `BotSpeakingFrame`), so both pipelines died five minutes after the last thing said and every later utterance failed with "the Pipecat worker stopped". Every worker zrb builds now passes `idle_timeout_secs=None` (`cancel_on_idle_timeout=False` would log "Idle timeout detected" every interval), and zrb closes the pipeline at session teardown. Reproduced from a real session log: two workers cancelled five minutes after their last activity, followed by three "Hands-free transcription failed" lines. See ADR-0107.
- **Fix: a Pipecat sentence that timed out is stopped, not abandoned** (`src/zrb/llm/speech/pipecat_tts.py`): a sentence whose first chunk missed the timeout only gave up its claim on the pipeline, so the service kept synthesizing and a late chunk played under the next sentence. A timeout now takes the talked-over path: the sentence is closed, the service told to stop, and only then is the claim given up.
- **Fix: a sentence a Pipecat service rendered survives a device that will not open** (`src/zrb/llm/speech/player.py`, `src/zrb/llm/speech/backend/pipecat.py`, `src/zrb/llm/speech/backend/any_speech_backend.py`): when the output device failed to open, in-process playback fell back to the backend's own `create_utterance`, which a Pipecat backend (it renders audio but plays nothing) can only refuse, so the sentence went unsaid. A backend now declares `needs_zrb_playback` (true for Pipecat), and one without a player program of its own hands the sentence to the speaker's next backend. With a player program configured, a Pipecat backend is stepped over rather than logged as a failure.
- **Fix: a speaker that never started its threads still lets its backends go** (`src/zrb/llm/speech/player.py`): `Speaker.speak` runs on the calling thread without the worker and player threads, yet creates the same backends (for Pipecat, a loaded model, a running pipeline and a loop thread). Ending the speaker returned early with no worker thread, so `close()` and the exit `drain()` leaked them for the life of the process. Backends are now closed either way, and only once on a double close.
- **Fix: a dictation backend is let go on the loop that owns its pipeline** (`src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/backend/any_dictation_backend.py`, `src/zrb/llm/dictation/backend/pipecat.py`, `docs/adr/adr-0107.md`): the synchronous teardown closed the backend on a loop of its own making, and the cross-loop error was only logged, so the session reported the backend closed while the Pipecat worker, model and pipeline ran on (re-enabling dictation mid-session reached this). Backends now expose `owner_loop` and the close runs there; a backend whose loop has stopped is released and the teardown names the worker it could not cancel. See ADR-0107.
- **Fix: a session that ends mid-recording builds no second backend** (`src/zrb/llm/dictation/feature.py`, `src/zrb/llm/dictation/backend/pipecat.py`): recording, hands-free listening and transcription each read the session's backend when reached, and after `close()` cleared it, released audio built a new one (for Pipecat, a second service and pipeline) for a finished session. Each operation now holds one backend for its whole length, a closed session refuses to build another, a recording whose session ended is not transcribed, and a let-go Pipecat backend refuses to restart its pipeline.
- **Documentation: the voice guide names the Pipecat services a session can listen or speak through, and what each takes to install** (`docs/llm/voice-camera.md`, `docs/llm/voice-photo-troubleshooting.md`, `examples/voice-interaction/README.md`): the backend tables omitted the offline Pipecat services and advised a cloud key for technical speech. Both tables now list `whisper`, `moonshine`, `funasr`, `kokoro`, `piper` and `pocket` with their installs (`zrb[voice]` brings Pipecat but no model packages: `pip install 'pipecat-ai[whisper]'`, `[moonshine]`, `[funasr]`, `[kokoro]`, `[piper]` or `[pocket-tts]`) and platform support (recorded in the guide; notably none has a native-Termux wheel, so Termux keeps vosk and local speech engines, and `kokoro` is uninstallable on Python 3.14). The guide also documents registering a service through `tts_manager`/`stt_manager`, and the troubleshooting page and example name a local service beside the cloud ones.
- **Fix: a Pipecat sentence is not cut off by the end of the session that spoke it** (`src/zrb/llm/speech/player.py`): synthesis runs ahead of playback, and the worker thread let the backends go when its queue ran out, while the player was still reading the last sentence. For Pipecat, `TTSPipeline.close` then cancelled the worker mid-sentence, so ending a session during its final sentence cut it off; the exit `drain` had the same hole. The player now flags when it stops reading and the worker waits for that before letting backends go; `speak`, which never starts a player, still closes them itself.
- **Fix: a segment that timed out does not answer the segment after it** (`src/zrb/llm/dictation/pipecat_stt.py`, `src/zrb/llm/dictation/backend/pipecat.py`): `STTPipeline.transcribe` released the pipeline after its 120 s timeout while the service was still transcribing, and since a `TranscriptionFrame` names no segment, the abandoned answer was taken as the next segment's: the user's previous words acted on as their current ones. Pipecat has no per-segment cancel (an `InterruptionFrame` only resets TTFB state, and cancelling the segment task would break the service for the session), so the timed-out pipeline is retired, cancelling the transcription in flight, and the backend starts another for the next segment.
- **Fix: a dictation pipeline whose worker stopped is replaced, not kept** (`src/zrb/llm/dictation/pipecat_stt.py`, `src/zrb/llm/dictation/backend/pipecat.py`, `docs/adr/adr-0107.md`): `STTPipeline.is_closed` answered only for pipelines zrb closed, so a worker Pipecat ended on its own (an upstream `EndWorkerFrame`, a fatal error, a failure its run task did not survive) stayed held, and every later segment failed with "the Pipecat worker stopped", ending hands-free for the session. The idle-timeout fix above covered one cause; this covers all. A stopped pipeline is now replaced before the next recording, at the cost of reloading the model; the recording in flight is unaffected. See ADR-0107.
- **Fix: a dictation teardown survives the loop that owns its backend stopping under it** (`src/zrb/llm/dictation/feature.py`, `docs/adr/adr-0107.md`): a loop that shut down between `DictationSession.close`'s is-running check and the hand-off made `call_soon_threadsafe` raise, escaping with the model and pipeline still running and ending the session's teardown. The hand-off now falls back to the release a stopped loop takes, keeping teardown best-effort; the warning naming the uncancelled worker is unchanged.
- **Fix: a sentence whose interruption fails does not take the speech pipeline with it** (`src/zrb/llm/speech/pipecat_tts.py`): dropping a sentence released the one-sentence lock only after the interruption was queued, and an exception other than `RuntimeError`/`TimeoutError` escaped with the lock held, so every later `speak` blocked for the session. The lock is now released in a `finally`, and the failure reaches the caller as a report about one sentence. The caught types are unchanged on purpose: `finally` also covers a cancelled future, and widening the handler would raise the broad-except count `test_broad_except_ratchet.py` pins at 313.
- **Fix: an ordinary previous-message recall submits on the first Enter again** (`src/zrb/llm/ui/default/message_editing.py`, `docs/adr/adr-0077.md`): the second-Enter rule above keyed on any recall, so Up Arrow onto an ordinary earlier message and Enter raised "Message is no longer waiting (already started or sent)" and swallowed the press. The note now fires only for a recalled queued entry whose turn started under the recall; an ordinary recall submits as before.
- **Fix: `.coveragerc` omitted `src/zrb/__main__.py` wherever that happened to resolve** (`.coveragerc`, `pyproject.toml`, `test/architecture/test_coverage_omit_patterns.py`): since 2.16.0 the omit entry was repo-relative, which coverage resolves against the process cwd; `test/test_main_process.py` runs `python -m zrb` from a scratch directory under `pytest-cov`'s subprocess coverage, so the file was reported at 74% (the cwd-independent `**/__init__.py` entry worked). The entry is now `**/__main__.py`, the `pyproject.toml` comment calling the relative form deliberate is gone, and a fitness test fails on any omit entry that is neither `**/`-prefixed nor absolute.
- **Feature: a `{ctx.` placeholder left in a plain-string `cmd` now warns** (`src/zrb/task/cmd_task.py`, `docs/task-types/basic-tasks.md`): rendering is opt-in, so `CmdTask(cmd="echo {ctx.input.name}")` passed the literal text to the shell and exited 0. A `CmdTask` whose plain-string `cmd` (or list entry) contains `{ctx.` now raises `UntemplatedCmdWarning` at construction, naming the task and `cmd` or `cmd[<index>]` and pointing at `Tpl`, without echoing the command (it may hold a credential). `Tpl`, `Cmd`, `CmdPath`, callables and placeholder-free strings (`${VAR}`, `awk '{print}'`) are untouched; a task defined in a loop warns once. It is the runtime half of `test/architecture/test_doc_tpl_placeholders.py`.
- **Tests: a setting can no longer be assigned where the next read cannot see it** (`test/architecture/test_env_field_write_key_is_readable.py`, `test/config/test_config_assignment_safety.py`): the `/set` fix above relies on every write key also being a read alias, which nothing checked. A fitness test now asserts it for all 338 `EnvField`s on `Config`'s MRO, and a round-trip test pins `LLM_MAX_TOKEN_PER_MINUTE` and `LLM_MAX_TOKEN_PER_REQUEST` (read singular or plural, written plural; `llm-config.md` advertises the singular).
- **Documentation: the counts `AGENTS.md` quotes are measured instead of remembered** (`scripts/doc_counts.py`, `test/architecture/test_documented_counts.py`, `AGENTS.md`): the verb rule cited "5,000 functions … 596 distinct leading tokens, 43% of them used once" while the tree measured 4,467 / 488 / 39.5%. `scripts/doc_counts.py` computes the three, `--check` compares them and `--write` restates the sentence (refusing, nonzero, when the sentence is missing); an architecture test holds the file to them and fails with that command as the fix.
- **Feature: barge-in can keep its stop without the hold that makes a loud room stutter** (`src/zrb/config/mixins/llm_dictation.py`, `src/zrb/llm/dictation/feature.py`, `docs/configuration/llm-config.md`, `docs/llm/voice-camera.md`, `docs/adr/adr-0105.md`, `docs/architecture/3-peripheral-flow/dictation-barge-in.md`): holding zrb's voice on loudness, then resuming when it was not the user, is heard as a stutter, worst in a loud room. The new `ZRB_LLM_DICTATION_BARGE_IN_HOLD` (on, the previous behaviour) can turn the hold off, so zrb speaks on until the words are known to be meant for it. Stops and steering are otherwise unchanged; with a live-transcribing backend (`vosk`) a stop or wake word stops zrb as soon as heard, with a batch backend after transcription. With the hold on, `pause_speech`, `resume_speech`, `interrupt_speech` and the four barge-in guards behave as before. See ADR-0105.
