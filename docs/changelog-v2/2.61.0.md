## 2.61.0 (August 13, 2026)

- **Feature: queued messages become editable, in-place entries** (`src/zrb/llm/ui/base/message_queue.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/default/message_editing.py`, `src/zrb/llm/app/layout.py`, `src/zrb/llm/ui/default/output.py`, plus tests): the message queue now holds structured `QueuedMessage` entries instead of bare closures, so a message typed while a turn is running can be recalled with Up/Down and edited in place — the turn streams the corrected wording when it starts, instead of requiring a corrective follow-up turn. Includes fixes for multi-line recalled messages and stale-recall edge cases. See ADR-0077.
- **Feature: mid-turn messages steer the live run instead of always queuing** (`src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/multi_ui.py`, `src/zrb/llm/ui/base/message_queue.py`): a same-second correction sent mid-turn is now injected into the live run via pydantic-ai's `RunContext.enqueue(priority="asap")` at the next safe boundary, instead of waiting for the whole turn — potentially many tool-call rounds — to finish. Falls back to the existing queue when no live run context exists or a tool approval is pending. See ADR-0078.
- **Fix: tool-approval prompts no longer discard an in-progress message** (`src/zrb/llm/ui/default/confirmation.py`, `src/zrb/llm/ui/default/selection.py`): whatever the user had typed is now stashed and restored when a tool-call confirmation dialog interrupts the input field, instead of being silently lost.
- **Fix: MultiUI (dual/multi-UI mode, e.g. chat-telegram) diverged from BaseUI's per-turn lifecycle** (`src/zrb/llm/ui/multi_ui.py`): token usage now reaches every child UI's status-bar meter, the final answer renders through the themed/re-wrappable markdown path, `last_output` is no longer empty in dual mode, the "working" animation and plan-mode badge stay in sync with the main UI, and a rewind snapshot plus git/system-info refresh now happen every turn like `BaseUI`.
- **Feature: conversation history checkpoints mid-turn, and crash/cancel recovery preserves real progress instead of a prose summary** (`src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/agent/run/partial_run.py`, `src/zrb/llm/agent/run/history_utils.py`, `src/zrb/llm/task/history.py`, `src/zrb/llm/task/llm_task.py`, `src/zrb/llm/history_manager/file_history_manager.py`): `zrb llm chat` now saves the conversation to disk at every safe tool-call round-trip boundary during a turn, not only at the end, so a crash or `Escape` cancellation preserves the actual tool calls made so far instead of losing them. A dangling tool call — one with no result recorded yet — is closed with a synthetic `ToolReturnPart` explaining why, via the new `close_dangling_tool_calls()` helper, so the resumed history stays valid for every provider.
