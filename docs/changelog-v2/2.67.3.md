## 2.67.3 (August 29, 2026)

- **Breaking/Security (ADR-0087): the web server now binds to loopback (`127.0.0.1`) by default instead of `0.0.0.0`** (`src/zrb/config/mixins/web.py` (`WEB_HTTP_HOST`), `src/zrb/runner/cli.py` (`start_server`, `_warn_if_insecure_bind`), `docs/advanced-topics/web-ui.md`, `docs/configuration/env-vars.md`): `start_server` hardcoded `host="0.0.0.0"` with no way to change it, so — combined with `WEB_AUTH_ENABLED` defaulting off and a documented default super-admin password — the "local development" server was in fact reachable from any interface able to run shell commands and user-defined tasks unauthenticated. A deployment that intentionally exposes the server still works, just requires setting the new `ZRB_WEB_HTTP_HOST` explicitly; either way, a non-loopback bind now prints a stderr warning naming whichever risk it still carries (auth off, or auth on with `WEB_SUPER_ADMIN_PASSWORD`/`WEB_SECRET_KEY` still at their default value). No alias, since there was no prior config key for this — an existing deployment relying on the implicit `0.0.0.0` bind must set `ZRB_WEB_HTTP_HOST` after upgrading.
- **Security: a continued live sub-agent session can no longer drift to broader authority than its delegation was granted** (`src/zrb/llm/agent/run/authority_snapshot.py`, `src/zrb/llm/agent/subagent/live_session.py`, `src/zrb/llm/agent/run/deferred_calls.py`, ADR-0069): `run_agent`'s permission-policy/yolo/sandbox inheritance relies on `asyncio.create_task` copying the current `ContextVar` context — correct only when the detached task is spawned while the originating scope is still bound. A human's follow-up message to an already-finished delegation (`live_session.py`'s `_continue_live_session`) spawns long after that scope exited, so it previously picked up whatever authority happened to be ambient at that later, unrelated point instead of what was actually granted. `LiveSubAgentSessionRegistry.add_session` now captures an `AuthoritySnapshot` at creation time, while the delegating turn's scope is still bound, and every later continuation passes its `permission_policy`/`yolo`/`sandbox_policy` explicitly to `run_agent()` instead of relying on ambient inheritance.
- **Fix: a web chat session's background `Shell` processes are now torn down when that session ends, and can no longer be reached from a different session** (`src/zrb/llm/tool/ambient_state.py` (`get_current_chat_session_id`, `get_session_ownership_key`), `src/zrb/llm/tool/shell_background.py` (`cancel_for_session`, `force_kill_all`), `src/zrb/runner/chat/chat_session_manager.py`, `src/zrb/runner/chat/chat_session_runner.py`, `src/zrb/llm/tool/delegate.py`, `src/zrb/llm/tool/delegate_background.py`, `src/zrb/llm/ui/default/{agent_picker.py,confirmation.py,keybindings.py,output.py}`): a background process a session started (directly or via a delegated sub-agent) previously outlived that session with no cleanup path, and the client-supplied display session name it and every live-sub-agent-session lookup keyed off was never guaranteed unique across concurrent web chat sessions, so two sessions sharing a display name could reach into each other's running sub-agents. Both are now keyed by `ChatSessionManager`'s own unique session id (bound around each message drive via a new `current_chat_session_id` ContextVar, `get_session_ownership_key` falling back to the display name for the interactive CLI, which has no such id): `ChatSessionManager.remove_session` now calls `cancel_for_session` to kill just that session's own background processes, and every live-sub-agent-session lookup in the TUI resolves through the same ownership key. A new `atexit`-registered `force_kill_all` also SIGKILLs any still-running background process at interpreter shutdown, when the event loop that owned its transport may already be closed.
- **Refactor: the last real import cycle in `zrb.llm.tool`/`zrb.llm.tool_call` is closed** (`src/zrb/llm/tool/__init__.py`, `src/zrb/llm/tool_call/__init__.py`, `src/zrb/llm/agent/subagent/{definition.py,manager.py,manager_loading.py,tool_resolver.py}`, `src/zrb/llm/tool/{web.py,file_analyze.py}`, `src/zrb/llm/tool_call/response_handler/default.py`, `src/zrb/llm/hook/turn_evidence.py`, `src/zrb/llm/common_tools.py`): `SubAgentDefinition` moved out of `agent/subagent/manager.py` into a new dependency-free leaf module (`agent/subagent/definition.py`), so `manager_loading.py` (which `manager.py` itself imports) can import it directly instead of reaching back into `manager.py` mid-load — the actual circular dependency `zrb.llm.tool/__init__.py` had briefly gone fully empty to sidestep. It's re-exporting again now, verified empirically (an `import zrb` from every plausible entry point must not raise) rather than by inspection, for every tool with no module-level dependency on `zrb.llm.agent`; `web.py`'s agent-dependent summarization step moved to a function-scoped import instead. **Breaking:** `analyze_code`, `create_delegate_to_agent_tool`, and `create_search_agent_tool` are no longer importable from `zrb.llm.tool` — those two modules delegate to the agent run loop for more than one call path each, so they stay import-from-their-own-module only (`from zrb.llm.tool.code import analyze_code`, `from zrb.llm.tool.delegate import create_delegate_to_agent_tool, create_search_agent_tool`). `tool_call/__init__.py` similarly no longer re-exports `replace_in_file_validation_policy` (import it from `zrb.llm.tool_call.tool_policy.replace_in_file_validation` instead) — it was the one tool-policy module reaching into `zrb.llm.tool`, and re-exporting it from `tool_call` closed a cycle back through `common_tools.py`.
- **Refactor: `BaseUI`'s persona-swap, voice-dictation, token-usage, and confirmation-queue state are now their own parts** (`src/zrb/llm/ui/base/{ui.py,confirmation_state.py,persona_state.py,usage.py,voice_state.py}`): each was a handful of attributes living directly on `BaseUI` alongside everything else; they're now `BaseUIConfirmationState`/`BaseUIPersonaState`/`BaseUIUsage`/`BaseUIVoiceState`, composed in as `self._base_confirmation`/`self._base_persona`/`self._base_usage`/`self._base_voice` per the `_base_<aspect>` convention `BaseTask` already used, reached only through `BaseUI`'s existing public properties. The 16 slash-command alias lists (`summarize_commands`, `attach_commands`, ...) are now backed by one `self._command_aliases` dict instead of 16 independent attributes, generated via a shared `_command_alias_property` helper instead of one hand-written getter/setter pair each.
- **Tests: five new architecture fitness-function tests enforce conventions AGENTS.md already documented but nothing previously checked mechanically** (`test/architecture/{test_boundaries.py,test_circular_import_allowlist.py,test_complexity_ratchet.py,test_facade_size_budget.py,test_private_test_access_ratchet.py}`): `test_boundaries.py` checks that a part reaches its owner/sibling only through a public property (never a raw `_private` attribute) and that business logic stays free of web/TUI framework imports; `test_circular_import_allowlist.py` fails if a new `# lazy: circular` deferral lands without being declared in its allowlist (every prior instance in the tree turned out to be a stale comment, a mislabeled heavy-dependency deferral, or a fixable eager re-export — none an irreducible cycle); `test_complexity_ratchet.py` caps flake8's mccabe score at 22 and radon's per-function score at 20 (registration/factory functions with trivial nested handlers are tagged `# noqa: C901` instead of inflating the mccabe ratchet); `test_facade_size_budget.py` caps `llm/ui/base/ui.py`, `llm/task/chat/task.py`, and `llm/task/llm_task.py` at a specific line count so a part extraction is required to actually shrink its owner; `test_private_test_access_ratchet.py` caps test-to-test private-attribute reaches at a documented baseline of 5. Bringing the tree under the new complexity ratchet split several functions that were tripping only the mccabe/closure-inflation false positive (`task/base/execution.py::execute_action_until_ready`, `util/cmd/command.py::run_command`'s cancellation path, `util/cli/latex_math.py::convert_math_to_unicode`, `llm/tool/{rag.py,shell.py,zrb_task.py}`, `llm/voice/engine.py::download_vosk_model`, `runner/web_route/{node_page/node_page_route.py,task_session_api_route.py}`) with a `# noqa: C901` and one-line reason rather than a real refactor.
- **Chore: permission/sandbox policy decisions are now inspectable as structured, DEBUG-only logs** (`src/zrb/llm/permission/observability.py` (`record_policy_decision`), `src/zrb/llm/agent/run/deferred_calls.py`, `src/zrb/llm/sandbox/os_sandbox.py`): each permission-policy decision (`_apply_permission_policy`) and sandbox decision (`build_sandboxed_argv`, `_fallback`) now emits one JSON line naming the layer, decision, tool name, and (for sandbox fallbacks) the reason and fallback mode — deliberately excluding tool arguments, credentials, prompts, and message content, so it stays diagnostic rather than becoming a secret store.
