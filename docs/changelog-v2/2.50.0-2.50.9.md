## 2.50.0 (July 8, 2026)

- **Named style themes via `ZRB_THEME`** (`src/zrb/config/theme.py`, `src/zrb/config/mixins/theme.py`, ADR-0084): a single theme preset now supplies the default value for every style knob across the LLM chat TUI, the markdown renderer, and the CLI semantic colors. Ships `dark` (the historical defaults — a default install looks identical) and `light` (a dark-on-light palette). Any individually set `ZRB_LLM_UI_STYLE_*` / `ZRB_CLI_*` env still overrides the theme, and `zrb.config.theme.register_theme(name, values)` lets `zrb_init.py` add or override themes — registered values are merged onto `dark`, so a partial theme only lists the knobs it changes and inherits the rest. See `examples/themes/monokai/` for a worked example. An unknown `ZRB_THEME` logs a warning and falls back to `dark`.
- **Markdown rendering colors are now configurable** (`src/zrb/util/cli/markdown.py`, `src/zrb/config/mixins/llm_ui_styles.py`): the previously hardcoded Rich theme is driven by new `ZRB_LLM_UI_STYLE_MARKDOWN_{LINK,LINK_URL,H1,CODE}` knobs.
- **Previously hardcoded TUI styles lifted into config** (`src/zrb/llm/app/layout.py`, `src/zrb/llm/app/style.py`, `src/zrb/llm/ui/default/output_mixin.py`): the title-bar background and input-prompt color are now `ZRB_LLM_UI_STYLE_TITLE_BAR_BG` and `ZRB_LLM_UI_STYLE_PROMPT`; the jargon, choice-widget, and `shift+tab` hint shades follow the theme's `FAINT`/`TEXT` knobs. This is what makes the `light` theme coherent.
- **Install scripts: softer legacy `~/.local-venv` cleanup** (`install.sh`, `install.ps1`): instead of deleting `~/.local-venv` and rewriting the user's rc files/PowerShell profile, the installers now only uninstall `zrb` from the old venv (so the `pipx` copy wins on PATH) and print how to remove the directory. This avoids editing user shell config; the leftover activation block is existence-guarded and keeps activating the venv until the user removes the directory, so the installer says so rather than claiming it's gone. The `zrb`-uninstalled log now fires only when `zrb` was actually present.

## 2.50.9 (July 29, 2026)

_Cumulative summary of the 2.50.1–2.50.9 patch line._

- **Breaking: `ActivateSkill`'s parameter is `skill`, not `name`** (`src/zrb/llm/tool/skill.py`): `name` on a tool called `ActivateSkill` answers "name of what?" only by inference, and models resolved it to the domain noun. Measured across an eight-model, 288-trial benchmark: of 167 calls, 68 named the field wrongly — `skill` (41), `skill_name` (26), `skill_id` (1) — across six of the eight models, each miss costing a validation retry that re-sent the whole conversation. Aliasing was rejected: accepting several spellings forces every field optional, dropping `required` and gutting `additionalProperties: false`, the check that catches a genuine typo. `ActivateSkill(name=...)` now raises a validation error.
- **Breaking: `LLMTask(summarize_command=...)` is `summarize_commands`** (`src/zrb/llm/task/llm_task.py`): the parameter was singular while holding a list, where the `LLMChatTask` equivalent and every sibling accessor were already plural. No alias — `LLMTask` is exported from the package root, so this raises `TypeError`.
- **Breaking: `*_mixin.py` modules renamed for what they are** (26 modules under `src/zrb/llm/`, 16 mirrored test files): a class that reads attributes only one host provides is a *part* of that host, not a mixin, so these are now `<Owner><Aspect>` in a file named for the aspect — `exec_mixin.py::ExecMixin` → `execution.py::ChatExecution`, `commands_mixin.py::CommandsMixin` → `commands.py::BaseUICommands`, and so on. The genuinely reusable `BufferedOutputMixin` keeps its suffix. Path stutter went with it (`hook/manager/manager.py` → `hook/manager.py`). Package-level imports are unaffected; deep module paths moved.
- **Feature: session token usage in the TUI status bar** (`src/zrb/llm/ui/`, `src/zrb/llm/util/stream_response.py`): accumulated input and output tokens across a session render as `💸 1.5k in · 34 out` beside the ready/working indicator, and reset on `/load`. The context gauge counts last-request input **plus** output — the reply just generated is history and is re-sent next turn — and no longer double-counts cache reads and writes, which pydantic-ai's usage contract already folds into `input_tokens`.
- **Feature: PDF fetching in `open_web_page`** (`src/zrb/llm/tool/web.py`): URLs are read as PDFs when they end in `.pdf` or when the response `Content-Type` says so — including extensionless viewer URLs, where the bytes come from the same response with no extra round-trip. Text is extracted with `pdfplumber` and skips the HTML→markdown converter. Plain HTTP is a shortcut only: on failure the fetch falls through to the browser, so a PDF behind a JS or cookie wall still works.
- **Reliability: fan-out failure semantics, in two shapes rather than one** (`src/zrb/util/run.py`, `src/zrb/session/session.py`, `src/zrb/task/base/execution.py`): plain `asyncio.gather` propagates the first exception and leaves siblings running unretrieved. `gather_isolated` lets every sibling settle, then re-raises the first exception — correct for peer work that must not be cut short by a peer's failure (successors, fallbacks, task chains, root tasks). Applying that everywhere lost `gather`'s fail-fast and hung any run whose siblings never return on their own (a `Scheduler` loop, a deferred long-running body, a polling `HttpCheck`), so `gather_fail_fast` is a separate helper: it fails fast, cancels the siblings, and bounds the cancellation settle. It awaits through `asyncio.wait` with `FIRST_COMPLETED` — `gather` would cancel its children and then *wait* for them, so a child that shields its cleanup kept the cancellation pending and `ZRB_TASK_READINESS_TIMEOUT` overshot (29.4s measured against a 200ms cap; 5.2s after). It is used exactly where a sibling may never return.
- **Reliability: command hooks no longer leak processes or outlive their session** (`src/zrb/llm/hook/hook_creators.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/llm/task/chat/execution.py`): the timeout path called `process.kill()`, which kills only the shell spawned by `shell=True` — a forked grandchild survived holding the inherited pipes and kept `communicate()` blocked in a worker thread. Hooks now start in their own session and are killed by process group, with a psutil recursive fallback for Windows. Because that same process group means Ctrl+C never reaches a fire-and-forget hook, `HookManager.shutdown()` cancels pending tasks at teardown, bounded by a grace period; it runs on the one-shot and web paths too, with `drain=True` there so a hook dispatched moments earlier gets its grace period first.
- **Reliability: cleanup inside cancellation handlers could mask the cancellation** (`src/zrb/llm/ui/`): an audit of every `except CancelledError`/`except TimeoutError` that runs cleanup found three sites where the cleanup itself could raise and convert a cancelled run into an ordinary failure. `/exec` reaps its child before writing to the UI, `MultiUI.run` guards the main-UI unwind, and the message-queue loop re-raises when the cancel was aimed at the loop itself instead of swallowing it.
- **Fix: unbounded tool payloads froze the TUI** (`src/zrb/llm/tool/web.py`, `mcp.py`, `code.py`): a tool return larger than the per-minute token budget could never be admitted by the rate limiter, livelocking the UI forever. Web pages, MCP results and oversized single files are capped to `LLM_MAX_OUTPUT_CHARS`. The MCP cap shares one budget across the whole structure — capping each item independently let N parts each just under the limit total N times it — while binary and rich content pass through untouched and uncharged. JSON truncation no longer produces invalid JSON: the dominant text field is truncated *inside* the dict and the payload re-serialized.
- **Fix: the TUI event loop is no longer blocked by the turn's hot path** (`src/zrb/llm/agent/common.py`, `src/zrb/llm/prompt/`, `src/zrb/llm/task/`, `src/zrb/llm/tool_call/`): `create_safe_wrapper` is a coroutine function, so pydantic-ai never applied its own executor offload for sync tools and they froze the UI for their duration — they now run via `asyncio.to_thread`, as do git subprocesses, history load and save, live-context rendering, argument formatting and diff rendering. `ModelRetry` is re-raised so pydantic-ai's retry protocol works instead of being flattened to an error string. Scroll-follow detection dropped an O(buffer) `Document` line-index rebuild per streamed chunk for an O(1) check.
- **Fix: config knobs that did nothing, and one that finally does** (`src/zrb/config/mixins/`, `src/zrb/llm/util/git.py`): `ZRB_HOOKS_DEBUG`, `ZRB_HOOKS_LOG_LEVEL`, `ZRB_LLM_PROJECT_DOC_MAX_CHARS` and `ZRB_LLM_UI_STYLE_PROMPT` were defined, defaulted, documented and round-trip tested, but nothing read them — the tests asserted `CFG.X` round-trips to `ZRB_X`, never that anything consumed it, which is how the gap survived. They are removed. `ZRB_LLM_GIT_CMD_TIMEOUT` had the same defect and is now applied: the live-context git calls hardcoded `timeout=5` and the `is-inside-work-tree` probe ran with no timeout at all, so a blocking git stalled every prompt compose. The default moved 1000 → 5000 to match what those calls already used, and a timed-out probe escapes the `lru_cache` rather than being memoized as "not a git dir" — a single cold-cache stall used to disable git context for the rest of the process.
- **Fix: style values crashed the TUI at startup** (`src/zrb/llm/app/layout.py`, `style.py`): the title-bar and prompt knobs are documented as prompt-toolkit styles but were interpolated into an HTML `color=` attribute, which accepts only a bare colour — anything with a space (`bold #ff0000`) raised while building the layout. They now resolve through the style dict. The title bar is built with `HTML(...).format()` so a title containing `<` or `&` is escaped rather than parsed.
- **Fix: web-chat approval and edit-mode races** (`src/zrb/runner/chat/`): decoded JSON args arriving with no edit slot fell through to the plain approval handler, which cannot parse a dict and denied the tool call outright; the miss is now reported and the pending approval left intact. A cancelled run left `is_waiting_for_edit()` permanently true, stranding every later approval; the slot is released on cancellation and a stale slot is cleared. Approval broadcasts keep a strong task reference so one cannot be garbage-collected mid-flight.
- **Fix: assorted correctness** (`src/zrb/llm/tool/shell.py`, `file_edit.py`, `mcp.py`, `src/zrb/llm/history_manager/`, `src/zrb/llm/util/clipboard.py`, `src/zrb/runner/web_route/static/`): the shell reader's 64 KB `StreamReader` line limit (which lost all output on a minified-JS or one-line-JSON line) is raised to 8 MB and a post-start stream error terminates the subprocess; conversation saves write to a sibling `.tmp` and rename, so a crash mid-write cannot truncate the live file; MCP `BinaryContent` is passed through instead of stringified and truncated; terminal width is read from stdin rather than the TUI's capture pipe; Termux clipboard support goes through `termux-clipboard-set` over stdin; and the refresh-token route serves an inert script when auth is disabled, ending a 401 on every page load.
- **Fix: agent-facing wording that cost real round-trips** (`src/zrb/llm/tool/shell.py`, `file_edit.py`): `Shell`'s docstring mentioned `timeout` three times without saying *seconds*, and `timeout: int = 120` reads as milliseconds to a model carrying a prior from agent shells that take them — five benchmark calls passed millisecond values, and one run whose deliverable passed all nine validator checks was recorded as a timeout because the model meant 15 seconds and got 15000. It now says `SECONDS, not milliseconds` and points long-running processes at `background=True`. A no-op `Edit` returned a bare `No changes made to <path>` — the one failure path without the `[SYSTEM SUGGESTION]` prefix — which read as a neutral status and invited the identical call again: one trial received it 76 times. Its three causes are now named separately with their own guidance.
- **Security: `fstring_format` sandbox escape via dunder traversal** (`src/zrb/util/string/format.py`): template expressions referencing a dunder name are rejected, closing the `().__class__.__bases__[0].__subclasses__()` route back to real builtins — plain attribute access is not governed by the `eval` globals, so a builtins whitelist alone could not stop it.
- **Performance: LSP detection, repo analysis, conversation save, and the test suite** (`src/zrb/llm/lsp/configs.py`, `src/zrb/llm/tool/code.py`, `src/zrb/llm/task/llm_task.py`, `test/`): LSP `detect()` ran one `shutil.which` per configured server on every call — and `get_for_file` runs on each agent `Write`/`Edit` — so a single edit paid up to ~1s of `$PATH` scanning; the probe is now cached for the process lifetime with an explicit invalidation hook. Repo analysis tokenized every fitting file twice and now returns the count it already computed. Summarization-path conversation saves are offloaded off the event loop. A full test run dropped ~118s → ~66s, most of it the hook process-group fix above, whose leaked grandchildren were being charged to whichever later test joined the thread pool.
- **Fix: the test suite ran the developer's real hooks** (`test/conftest.py`): the fixture pinned the module-level singleton's search dirs to `[]`, but two construction sites build a *bare* `HookManager()` per run, and a bare manager resolves its own search dirs — so a machine with `~/.claude/settings.json` hooks installed loaded and dispatched them for real. Both sites are now patched to build managers that never scan the filesystem, with a guard test.
- **Documentation: three claims that described features that did not exist** (`docs/core-concepts/make-task.md`, `docs/configuration/llm-config.md`, `docs/advanced-topics/maintainer-guide.md`, `AGENTS.md`): `readiness_timeout` was documented as a cap on the initial readiness wait, which it never applied — it is only read by the periodic re-check loop under `monitor_readiness=True`, and the initial wait is bounded by `ZRB_TASK_READINESS_TIMEOUT`, which defaults to off. `ZRB_THEME` had no documentation at all outside its ADR despite being the knob every style default resolves through. The maintainer guide specified nested changelog sub-bullets while every recent release used flat ones.
