## 2.67.5 (August 30, 2026)

- **Chore: pydantic-ai upgraded from 2.27 to 2.36, fastapi from 0.136 to 0.141** (`pyproject.toml`, `poetry.lock`, `docs/adr/adr-0041.md`): pydantic-ai-slim's own dependency floors moved with it — `openai>=3.0.0` (was `>=2.45.0`), `anthropic>=1.0.0` (was `>=0.108.0`), `google-genai>=2.18.0` (was `>=1.70.0`), `mistralai>=2.9.2` (was `>=2.4.2,!=2.4.6` — the version-2.36 floor also clears the PyPI quarantine that exclusion existed for), and a new core dependency, `httpx2>=2.7.0`, since pydantic-ai-slim's HTTP layer moved off `httpx` onto it. ADR-0041 rewritten: pydantic-ai 2.36.0 ships a native `ProcessHistory` capability that writes summarized history back into the live run (the shallow-copy write-back defect that originally justified zrb owning history in parallel), replacing the old `Agent(history_processors=...)` kwarg with `capabilities=`. zrb never passed that kwarg directly, so nothing broke on the bump, and zrb's two-tier summarization has no native equivalent yet, so the ADR's decision (zrb keeps owning history) stands — migrating any part of the pipeline onto the native capability is a separate, not-yet-scheduled evaluation.
- **Documentation: `LLMTask`/`LLMChatTask` constructor and builder-API reference filled in a dozen undocumented parameters, and corrected a misleading hook-system comparison** (`docs/task-types/llmchat-task.md`, `docs/advanced-topics/hooks.md`, `docs/advanced-topics/extending-the-llm.md`, `docs/configuration/llm-config.md`): the `LLMChatTask` constructor reference was missing `cli_only`, `attachment`, `hook_manager`, `history_processors`, `capabilities`, `yolo_xcom_key`, `custom_commands`, `triggers`, `tool_policies`/`response_handlers`/`argument_formatters`, `show_ollama_models`/`show_pydantic_ai_models`, `markdown_theme`, `enable_rewind`/`snapshot_dir`, `include_default_ui`/`interactive`, and the `ui_assistant_name`/`ui_jargon`/`ui_ascii_art` identity trio — all present in code and docstrings, none in the doc page. A new "Model, Model Settings & Capabilities" section explains that `model`/`model_settings`/`capabilities` are pydantic-ai's own types passed through unchanged (linking `ai.pydantic.dev` rather than re-documenting them), and disambiguates pydantic-ai's `capabilities` from two same-named zrb concepts it's easy to confuse it with: zrb's own `history_processors` pipeline and the unrelated per-model Model Capabilities registry (cross-referenced from both directions). The comparison table's "Hook system: Same" row was actively wrong — `LLMChatTask` replays hook factories onto a **fresh** manager every run while `LLMTask` applies onto a **persistent** one (ADR-0072) — corrected, and `hooks.md` gained a section documenting `append_hook_factory` and this isolation asymmetry, which previously appeared nowhere outside the ADR and the method's own docstring.
