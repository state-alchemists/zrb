## 2.49.0 (July 4, 2026)

- **Feature: deferred loading for rarely-used LLM tools** (`src/zrb/builtin/llm/chat.py`, `src/zrb/llm/common_tools.py`, `src/zrb/llm/agent/common.py`, `src/zrb/llm/agent/subagent/manager/manager.py`): Delegate tools, `analyze_code`/`analyze_file`, worktree tools, LSP tools, plan-mode tools, skill activation, process monitoring, and MCP toolsets are now wrapped with pydantic-ai's `defer_loading=True`, hiding their schemas from the model's context on every turn until it searches for them by name — the Tool Usage Guide still tells the model they exist, so nothing is lost except the standing token cost. `_wrap_tool` now threads `defer_loading` through when re-wrapping a `Tool`, and `SubAgentManager.add_tool`/`append_tool` accept `Tool` instances (not just plain callables) so deferred tools can be registered directly.

## 2.49.5 (July 8, 2026)

_Cumulative summary of the 2.49.1–2.49.5 patch line._

- **Performance: `pydantic_ai` is off the `import zrb` path** (`src/zrb/llm/common_tools.py`, `src/zrb/builtin/llm/chat.py`, `src/zrb/llm/task/`, `src/zrb/llm/agent/subagent/`): the `llm_chat` and `sub_agent_manager` singletons called `apply_common_tools` at module load, which transitively imported the LLM tool modules and with them `pydantic_ai` (~1.7s) — on every CLI invocation. New `defer_common_tools(host)` / `ensure_common_tools(host)` helpers register the tool surface lazily, and each host drains the deferred registration on its first run, so the heavy import lands on the first agent build. `import zrb` drops from ~5.3s to ~0.4s, with no public API change.
- **Install: `pipx` replaces the local virtualenv** (`install.sh`, `install.ps1`, `pyproject.toml`, `src/zrb/builtin/python.py`): the installers now use `pipx`, clean up a legacy `~/.local-venv`, register shell autocomplete, optionally install LSP servers, and accept `-y`/`--yes`. `black` and `isort` moved to the `[python]` extra, and `zrb python format` detects them with `importlib.util.find_spec` and runs them via `sys.executable -m`, so they resolve from zrb's own venv even when their binaries are not on PATH — the default under pipx. When the `python` extra is selected the installers re-inject them with `--include-apps` so the binaries also land in `~/.local/bin`.
- **Dependency: the `mistral` extra is back** (`pyproject.toml`, `install.sh`, `install.ps1`): restored with the same exclusion pydantic-ai-slim's own `mistral` extra uses, after the emergency removal that followed `mistralai==2.4.6` being quarantined on PyPI.
- **Improvement: `CFG.ROOT_GROUP_NAME` replaces hardcoded `"zrb"`** (`src/zrb/runner/cli.py`, `src/zrb/runner/chat/chat_api_route.py`, `src/zrb/llm/common_tools.py`, `src/zrb/llm/tool/zrb_task.py`): tool group names, error messages and server descriptions respect the configured root group name, which white-labeled distributions change.
- **Improvement: prompt and tool-guidance hygiene** (`src/zrb/llm/prompt/`, `src/zrb/llm/common_tools.py`, `src/zrb/llm/tool/plan.py`): skill-activation prose documents idempotency, project-documentation reads are re-scoped to code-touching turns, obsolete polling instructions are removed from the shell and process-monitoring guidance, and the todo tool's docstring gains a `replace=True` usage hint.
- **Docs: custom tools and the deferred pattern** (`docs/advanced-topics/llm-integration.md`): documented `add_tool_factory`, `defer_loading=True` for keeping rarely-used schemas out of every turn, and `defer_common_tools(host)` as the recommended way to equip a custom task with zrb's tool surface.
