## 2.53.1a1 (August 3, 2026)

- **Feature: `Read` numbers every line, so a `file:line` citation is read rather than counted** (`src/zrb/llm/tool/file_read.py`, `src/zrb/llm/common_tools.py`, `src/zrb/llm/prompt/markdown/persona.md`, `docs/advanced-topics/llm-integration.md`, `test/llm/tool/test_file.py`): `persona` requires an inline `file:line` on every code claim, but the tool that loads the code returned a bare body — the model had nothing to read the number *off*, so it counted, and the error compounds with depth into the file. `read_file` now emits each line in `cat -n` form: the 1-indexed number right-aligned in six columns, then a tab, then the line. That shape is what coding models are already trained on, so it needs no explaining, and the fixed-width numeric field reads as whitespace instead of welding itself to the content — a numbered-list file would otherwise render `15→4. **Scope.**`, two numbers with one glyph between them. A ranged read numbers from `start_line`, not from 1. The cost is roughly four tokens a line. Two things are deliberately excluded. **PDF text is not numbered**: its line breaks are produced by `extract_pdf_text`, not by the document, so a `report.pdf:412` citation would name a position in one extraction rather than in the file — precisely the false precision the change exists to remove. And the **char cap is measured on file content, before numbering**, so `LLM_MAX_OUTPUT_CHARS` still means what the header says it means; billing the prefixes to the budget would have spent ~13.5% of it on characters the file does not contain (measured at 15.6% overhead on a 674-line source file), while the header went on reporting the full figure. `persona`'s citation bullet gains the principle — a line number is a reading, never an estimate, so never count lines yourself — while the mechanics of *where* the number comes from stay in the `Read` tool guidance, which is the section that owns them and the one that disappears together with the tool.
- **Fix: `Edit` now tolerates `Read`'s line-number prefix instead of looping on it** (`src/zrb/llm/tool/file_edit.py`, `src/zrb/llm/prompt/markdown/file_extractor.md`, `test/llm/tool/test_file.py`): numbering `Read` created a new way for `replace_in_file` to fail — `old_text` copied straight out of the tool output carries a prefix that is not in the file — and the existing error path made it unrecoverable. The message read *"Use Read to get the exact file content, then copy old_text verbatim from it. Do not retry with guessed text"*, which is an instruction to repeat the action that just failed, with the one useful deviation explicitly forbidden. The `Similar lines found:` hint, the only diagnostic that would have shown the model the un-prefixed line, was dead on this path too: it tests `first_line in line`, and a prefixed first line is a substring of nothing. The prefix is also invisible in the model's own transcript, reading as the leading whitespace of the line it precedes. `_strip_read_line_numbers` is now tried as a last resort — after the exact match and both fuzzy strategies have failed, so a file that genuinely contains `cat -n` text still edits through the exact path — and only when *every* line carries the prefix, so a partial copy is never silently mangled. `new_text` is stripped alongside `old_text`, since a model that copied the prefix into one generally copied it into both, and writing that through would put line numbers into the file. The near-match hint now compares against the stripped text, and both failure messages name the prefix. `file_extractor.md` gets a matching note: `analyze_file` passes `read_file` output straight into its payload, so that sub-agent receives numbered input while its own few-shot examples show unnumbered files.
- **Fix: skill activation was matched against the turn's *output* instead of the turn's *work*** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm_plugin/agents/generalist.agent.md`, and the `description` of all five skills under `src/zrb/llm_plugin/core_skills/`): every activation rule was phrased around "the turn's deliverable", which reads as the final artifact. A turn that maps unfamiliar code in order to change it produces a code deliverable, so the phrasing pointed at `core-coding` alone and `core-research`'s methodology — the part actually governing the investigation that consumed most of the turn — went unactivated. The rule now matches **the work the turn requires**: a skill applies when its methodology is needed *anywhere* in the turn, including as a means to something else, and investigation done to reach a code change is still investigation. Each skill description was rewritten to state the triggering *activity* rather than the artifact (`core-research` explicitly covers investigation "whether that investigation is the deliverable or only the work needed to reach one"), so the catalogue the model matches against and the prose telling it how to match now agree. `generalist.agent.md` carried the same framing in its mandatory-activation list and gets the same treatment, with the distinction called out inline — *will need*, not *will produce* — since a delegated task is precisely where a missed research activation costs the most.
- **Fix: `ActivateSkill` was deferred, so the model could not see the tool it is required to call first** (`src/zrb/llm/common_tools.py`): the tool was registered with `defer_loading=True` on the rationale that activation happens rarely — once per skill rather than every turn. But *rarely* is not *late*: the Turn Sequence puts activation at step 2, before any task work, and a deferred tool's schema is not present until something loads it. The tool the workflow names as an early precondition is now loaded eagerly. `MonitorProcess` keeps deferred loading, which is where the original rationale actually holds — it is only reachable after a background process is already running.
- **Improvement: `/resume` and `/v` command aliases** (`src/zrb/config/mixins/llm_ui_commands.py`): `/load` accepts `/resume`, and `/voice` accepts `/v`. Both are additive — existing spellings are unchanged, and either default can still be overridden via `ZRB_LLM_UI_COMMAND_LOAD` / `ZRB_LLM_UI_COMMAND_VOICE`.
- **Fix: "activate each skill once" became an absolute whose exception lived in a separately-toggleable section** (`src/zrb/llm/prompt/markdown/workflow.md`): the Skill Activation rewrite compressed *"Re-activate only for a new deliverable, or when summarization dropped one you still need"* into *"stays in history for the rest of the session — so activate each skill once"*, which `mandate.md:30` contradicts two sections earlier by stating that history is auto-summarized as it grows. The surviving correction sat only in `ActivateSkill`'s `key_rule` in `common_tools.py` — inside `tool_guidance`, which `LLM_INCLUDE_SECTIONS` can drop and which the runtime tool-name filter suppresses independently. A config without it left the model holding a false absolute about its own context, with no way to recover a skill that summarization had removed. This is the cross-section coupling ADR-0094 exists to prevent, applied to a rule rather than a reference, and `<!--requires:-->` cannot gate it because tool-guidance text is not a markdown section — so the exception goes back into `workflow.md`, the section that owns activation.
- **Improvement: prompt tidy-ups in `workflow.md` and `journal_mandate.md`** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm/prompt/markdown/journal_mandate.md`, `test/llm/prompt/test_section_composition.py`): the Working Loop table's third column was headed "Steps before Verify" while its own caption already stated that Verify always runs — it is now "Loop steps to run", and the redundant "Every row ends the same way: **Verify, then reply.**" line below the table is gone. Step 1 asks whether you can tell "what work the turn needs" rather than "the turn's deliverable", matching the activation change above. The Skill Activation section drops the paragraph explaining that a first look may be needed to classify the deliverable, which the reworded step 1 now covers. `journal_mandate` loses "A missing directory is the ordinary first-run state: create it and write" — 2.53.0 made `search_journal` create the directory itself, so the instruction described a state the model can no longer encounter. The composition test's blanket `assert "requires" not in text` was tightened to `"requires:"` and `"/requires"`: "requires" is ordinary English and now appears in the reworded skill-matching prose, and an intact marker is already caught by the `<!--` assertion above it — these catch a half-stripped one.
