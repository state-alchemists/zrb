## 2.50.8 (July 28, 2026)

- **Breaking: `LLMTask(summarize_command=...)` is now `summarize_commands`** (`src/zrb/llm/task/llm_task.py`): the parameter was singular while holding a list, where the `LLMChatTask` equivalent (`ui_summarize_commands`) and every sibling accessor were already plural. `LLMTask` is exported from the package root, so this is a user-visible rename with no alias: `LLMTask(summarize_command=[...])` now raises `TypeError: unexpected keyword argument`. Pass `summarize_commands` instead. Nothing else in the public surface changed shape.
- **Change: `*_mixin.py` modules renamed for what they are** (26 modules under `src/zrb/llm/`, 16 mirrored test files): ADR-0085 reserves the `Mixin` suffix for classes that read no state they do not themselves set, so any class can mix them in. Most of these read attributes only one host provides — they are *parts* of that host, not mixins — so they are now named `<Owner><Aspect>` in a file named for the aspect: `exec_mixin.py::ExecMixin` → `execution.py::ChatExecution`, `commands_mixin.py::CommandsMixin` → `commands.py::BaseUICommands`, `output_mixin.py::OutputMixin` → `output.py::UIOutput`, and so on. The genuinely reusable `BufferedOutputMixin` keeps its suffix. Path stutter went with it: `hook/manager/manager.py` → `hook/manager.py`, with siblings as `manager_loading.py` / `manager_search.py` / `manager_query.py` / `manager_lifecycle.py`. Package-level imports are unaffected (`from zrb.llm.hook.manager import HookManager` still resolves, as do `zrb.llm.lsp.manager` and `zrb.llm.agent.subagent.manager`), but deep module paths moved — `zrb.llm.lsp.manager.symbol_utils` is now `zrb.llm.lsp.symbol_utils`.
- **Change: `LLMChatTask`'s constructor state declared once instead of three times** (`src/zrb/llm/task/chat/state.py`, `src/zrb/llm/task/chat/task.py`, `building.py`, `running.py`, `execution.py`): each of the three sibling classes carried its own `TYPE_CHECKING` block re-declaring the same `_*` attributes set in `__init__`, and the copies had already drifted — `ExecMixin`'s block typed 36 of them as bare `Any`, so the annotations were load-bearing for nothing. They now share one annotation-only `ChatState` base. Annotation-only is deliberate: a bare annotation creates no class attribute, so putting `ChatState` ahead of `BaseTask` in the MRO shadows nothing at runtime. Two constructor groups collapsed with it — fifteen `_ui_*_commands` attributes became a single `_ui_command_overrides` dict keyed the way `_get_ui_commands` already resolved them, and the four greeting/assistant-name/ascii-art/jargon `(value, render)` pairs became `_ui_texts`. The `add_*` aliases also gained docstrings saying which way they insert, because three of them (`add_response_handler`, `add_tool_policy`, `add_argument_formatter`) *prepend* rather than append, which the name does not suggest.
- **Change: blanket type suppressions replaced with targeted ones** (`src/zrb/`, 34 sites): every `# type: ignore` in `src/zrb` is gone. Fourteen became `# pyright: ignore[<rule>]` naming the specific rule; the rest were not suppressions worth keeping but modelling gaps the checker was right about — ad-hoc attributes on third-party objects now go through `setattr` (`agent.zrb_history_processors`, `zrb_is_delegate_tool`), `PromptManager._is_full_middleware` returns a `TypeGuard` so callers narrow instead of casting blind, and the class-level ignores on `LLMTask` / `LLMChatTask` / `UI` came off once the host-contract blocks declared `name`/`envs`/`yolo` as properties rather than variables. `pyright src/zrb` is clean in standard mode with no file- or class-level escape hatches.
- **Change: the shipped plugin directory is located by name, not by counting `.parent`** (`src/zrb/util/dir_search.py`, `src/zrb/llm/agent/subagent/manager_search.py`, `src/zrb/llm/hook/hook_loader.py`, `src/zrb/llm/skill/manager.py`): three call sites reached `zrb/llm_plugin/` with hand-counted `.parent` chains, which encode the caller's nesting depth rather than the target. The module rename above would have silently broken one of them: `manager/search_mixin.py` needed five hops to reach the package root, and from `manager_search.py` those same five land on `src/`, so the builtin sub-agents would have been looked up under a directory that does not exist — no error, just an empty result. All three now share `BUILTIN_PLUGIN_DIR`, which walks up to the `zrb` package by name and cannot be invalidated by moving a caller.
- **Change: `:q` now exits the chat TUI** (`src/zrb/config/mixins/llm_ui_commands.py`): added to `ZRB_LLM_UI_COMMAND_EXIT`'s default alias list alongside `/q`, `/bye`, `/quit`, and `/exit`, for the vim reflex. Setting the env var still replaces the whole list.
- **Fix: `ZRB_TASK_READINESS_TIMEOUT` was still not a real ceiling** (`src/zrb/util/run.py`, `test/util/test_run.py`): follow-up to the `gather_fail_fast` helper added in 2.50.7. It awaited its children through `asyncio.gather`, and a gather that is being cancelled cancels its children and then *waits* for them — so a child that shields its cleanup kept the cancellation pending and the enclosing `wait_for` overshot by however long that child took. The bounded settle the helper already had could never apply, because control never reached it. Measured on a readiness fan-out capped at 200ms with a non-unwinding check: 29.4s before, 5.2s now (the cap plus the settle allowance). The primary await is now `asyncio.wait`, which hands the cancellation straight back. `FIRST_COMPLETED` rather than `FIRST_EXCEPTION`: the latter does not treat a *cancelled* child as an exception and falls back to waiting for all of them, which would have hung `_wait_deferred_action` the moment a session teardown cancelled one deferred task — the exact hang the helper exists to prevent.
- **Fix: one-shot and web chat runs left their detached hooks running** (`src/zrb/llm/task/chat/execution.py`, `src/zrb/llm/hook/manager.py`, `test/llm/task/chat/test_llm_chat_task.py`, `test/llm/hook/test_manager_functionality.py`): the async-hook teardown added in 2.50.7 only ran on the interactive path, so `zrb llm chat -m "..."` and the web/SSE runner still leaked — an `async: true` hook's subprocess sits in its own process group, so nothing else reaps it once the run returns. Both paths now settle their own hooks. The rest of the interactive teardown (LSP servers, the worker pool) stays gated as before, because the web runner reuses the non-interactive path per message and tearing those down would restart them on every message. `HookManager.shutdown` gains `drain=True` for this caller: pending hooks get their grace period to finish before the stragglers are cancelled, because a *run*-end teardown fires moments after the hook was dispatched and cancelling up front would have effectively disabled async hooks for every non-interactive caller. Cancel-first remains the default, which is correct at *session* end. Note the cost: a one-shot run with a genuinely slow async hook now waits up to the grace period (2s) before exiting, where it previously exited immediately and orphaned the hook. Runs with no pending hooks are unaffected.
- **Fix: one slow git probe disabled git context for the rest of the process** (`src/zrb/llm/util/git.py`, `test/llm/util/test_llm_git.py`): follow-up to wiring `ZRB_LLM_GIT_CMD_TIMEOUT` into the `is-inside-work-tree` probe in 2.50.7. The probe is `lru_cache`d, so the timeout — unlike a missing git or a genuine non-repo directory — was memoized as "not a git dir": a single cold-cache stall (credential prompt, `index.lock` contention) silently switched off the live-context git block and the worktree tools for the remainder of the run, with nothing in the output to say why. A timeout is transient, so it now escapes the cached function rather than being answered False inside it; `lru_cache` does not memoize a raised exception, so the next call retries. Callers still see the same safe False. Real answers, including failures, stay cached.
- **Fix: a 401 on every web page load when auth is disabled** (`src/zrb/runner/web_route/static/static_route.py`, `test/runner/web_route/static/test_static_route.py`): `refresh-token.js` fires one unconditional `POST /api/v1/refresh-token` as soon as it loads. With `ZRB_WEB_AUTH_ENABLED` off — the default — there is no token to refresh and no cookie to send, so that request could only ever be rejected, and every page view logged `"POST /api/v1/refresh-token HTTP/1.1" 401 Unauthorized` next to the ordinary 200s. Nothing was broken, but a real auth failure was indistinguishable from the noise. The route now serves an inert script when auth is disabled. It still answers 200 rather than dropping the `<script>` tag, so a cached page that requests the URL does not start logging 404s instead.
- **Fix: a cleared edit slot was reported as still waiting** (`src/zrb/runner/chat/chat_api_route.py`, `test/runner/chat/test_chat_api.py`): follow-up to the raced-edit fix in 2.50.7. Detecting a stale edit slot clears it, but the route had already captured the edit state *before* calling `handle_approval_response`, so it answered a client that had just sent JSON args with `400 "Waiting for edit response, send JSON args"`. The state is re-read after the call, so the error now describes what is actually pending.
- **Fix: the hook tree-kill could raise despite being documented never to** (`src/zrb/llm/hook/hook_creators.py`): `_kill_process_tree`'s `psutil` fallback import sat outside its `try`. psutil is a hard dependency so this could not fire in practice, but "never raises" is exactly what makes the function safe to call from the cancellation path — an error escaping it is swallowed by the outer handler, turning a `CancelledError` that must propagate into an ordinary failed `HookResult`. The import moved inside the guard.
- **Test suite: per-run hook managers ran the developer's real hooks** (`test/conftest.py`, `test/llm/hook/test_manager_functionality.py`): the `_disable_real_filesystem_hooks` fixture pinned the module-level singleton's search dirs to `[]`, but `_create_llm_task_core` and `LLMTaskBuilding` each build a *bare* `HookManager()` per run, and a bare manager resolves its own search dirs — so on a machine with `~/.claude/settings.json` hooks installed (peon-ping, say) every chat test loaded 13 real hook configs and dispatched them for real. That is the failure the fixture's own docstring describes: the async ones spawn `peon.sh`, and with no audio device (CI/WSL) the subprocesses linger and hang asyncio's subprocess-transport teardown when the per-test event loop closes, so the suite crawls and the stall lands on whichever unrelated test the loop-close happens to fall in. The two construction sites are now patched to build managers that never scan the filesystem — rather than stubbing `get_search_directories`, which several `test/llm/hook/` tests legitimately exercise for real. A guard test asserts no hook fires from either site. Pre-existing, but the non-interactive teardown above reaches those managers on a far more common path, which is how it surfaced.
