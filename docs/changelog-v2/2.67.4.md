## 2.67.4 (August 30, 2026)

- **Refactor (ADR-0033, ADR-0088): two more leaf modules moved out of `zrb.llm.agent` to close the last real import cycles, and a new test audits every `# lazy:` comment's stated reason** (`src/zrb/llm/agent_state.py` (was `agent/run/runtime_state.py`), `src/zrb/llm/agent_tool_result.py` (was `agent/tool_result.py`), `src/zrb/contextvars.py`, `test/architecture/test_lazy_import_categories.py`, plus ~15 former importers across `llm/agent/`, `llm/hook/`, `llm/tool/`, `llm/ui/`, `llm/prompt/`): a closure walk found `zrb.llm.agent` and `zrb.llm.ui` each eagerly reach roughly 400 of this repo's ~430 `zrb.*` modules, so a shared leaf module nested inside either is reachable from many independent directions at once — deferring one import site's comment doesn't remove the module from the closure when others keep it reachable. Both modules (verified to have zero real dependency on `zrb.llm.agent`) moved to plain top-level siblings instead, deleting 5 `# lazy: circular` comments outright — there was no cycle left to defer around. Separately, an audit of all 291 `# lazy:` comments in the tree found 20 that didn't state a real reason (a bare "defer CFG load", vague hot-path notes, two unjustified deferrals now hoisted to module level); the new test classifies every comment into one of AGENTS.md's four categories and fails on any that don't fit. **Breaking (narrow):** `zrb.llm.agent.run.runtime_state` and `zrb.llm.agent.tool_result` no longer exist as import paths — use `zrb.llm.agent_state` / `zrb.llm.agent_tool_result` instead. Neither was re-exported from any package `__init__`, so this only affects code importing those internal paths directly; `zrb.contextvars`'s public re-exports are unchanged.
- **Refactor: pydantic-ai's `Agent`-adjacent types are re-exported from one internal module instead of imported from `pydantic_ai` directly at each call site** (`src/zrb/llm/agent/types.py`, plus ~40 call sites across `llm/agent/`, `llm/approval/`, `llm/history_manager/`, `llm/summarizer/`, `llm/task/`, `llm/tool_call/`, `llm/ui/`, `llm/util/`, `llm/voice/`): every zrb module that only needed a pydantic-ai type for an annotation, an `isinstance` check, or building a message part now imports it from `zrb.llm.agent.types` instead of `pydantic_ai` directly, so pydantic-ai stays reached from one gated module rather than ~40 independent points in the tree. `hook/creator.py::run_llm_hook` also now builds its judge agent through `create_agent()` (`resolve_model=False`, since the model is already resolved) instead of constructing a bare `pydantic_ai.Agent` — the one call site outside `create_agent()` itself still doing that, bypassing whatever `create_agent()` sets up for every other agent in the tree (ADR-0036).
- **Refactor (ADR-0069): the sandbox gate reads the run's already-resolved policy from `ctx.deps` instead of an ambient re-read** (`src/zrb/llm/agent/{common.py,gates.py}`, `src/zrb/llm/agent/run/runner.py`, `test/llm/sandbox/test_gate.py`): unlike the permission policy (which can change mid-run via `ExitPlanMode` and must keep reading its ambient `ContextVar` fresh), the sandbox policy is fixed for a run's whole lifetime. `SafeToolsetWrapper.call_tool` — the one chokepoint every tool call passes through — now hands `sandbox_gate` the policy `run_agent` already resolved once via pydantic-ai's native `ctx.deps`, falling back to the ambient read only at the one call site with no `RunContext` to offer.
- **Improvement (ADR-0055): the journal can retract notes, bounds its HUD entries, traces belief changes, and its compliance judge now fires on stated preferences too** (`src/zrb/llm/tool/{journal.py,journal_write.py}`, `src/zrb/llm/hook/{journal_compliance.py,turn_evidence.py}`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/prompt/live_context.py`, `src/zrb/config/mixins/llm_content.py`, `test/llm/{hook,tool,prompt}/...`): a new `DeleteJournalNote` tool removes a note and scrubs every markdown link resolving to it elsewhere in the tree; `WriteJournalNote`'s `hud_line` now evicts oldest-first past `LLM_JOURNAL_HUD_MAX_ENTRIES_PER_SECTION` instead of growing the always-injected index forever, and revising a note's Context/Finding now prepends the superseded version to a bounded `## History` block instead of discarding it. The Stop-hook journal-compliance judge previously fired only when a turn wrote files; it now also fires when the turn's own text states a preference or standing instruction (`turn_states_preference`) — the case `WriteJournalNote`'s own docstring already called highest-value and previously uncovered. All journal writes now hold a coarse-grained advisory lock over the journal root for the duration of one writer call, closing a lost-update race between a note, its backlinks, and its indexes.
- **Fix: a sub-agent's token usage now reaches the parent UI's session totals** (`src/zrb/llm/ui/buffered_ui.py`, `test/llm/ui/test_buffered_ui.py`): `BufferedUI` had no `accumulate_usage`, so a delegated sub-agent's token consumption was silently dropped instead of counting toward the displayed usage indicator. The new forwarding method deliberately drops `context_usage` (the sub-agent's own context-window occupancy, not the parent's), so the parent's context-window indicator keeps reflecting its own size rather than the sub-agent's.
