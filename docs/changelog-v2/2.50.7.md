## 2.50.7 (July 27, 2026)

- **Fix: a failing parallel task could hang the run instead of failing it** (`src/zrb/util/run.py`, `src/zrb/task/base/execution.py`, `test/util/test_run.py`, `test/task/base/test_execution.py`): regression introduced in 2.50.4 — affects 2.50.4 through 2.50.6. `gather_isolated` waited for every sibling to settle before re-raising, which loses `asyncio.gather`'s fail-fast. Siblings that never return on their own — a `Scheduler`/`BaseTrigger` monitoring loop, a long-running task body, an `HttpCheck`/`TcpCheck` that polls until it succeeds — kept the run alive forever after another task had already failed. Two long-running tasks where one crashes (a `frontend` + `backend` start, say) used to exit non-zero immediately and now blocked until the survivor also exited. It now fails fast *and* cancels the siblings, so neither the hang nor the orphaned-task problem remains. The readiness fan-out in `execute_action_until_ready` uses the same helper, restoring fail-fast there too (a cancelled readiness check is no longer silently ignored either).
- **Fix: timed-out command hooks leaked processes and exhausted the hook pool** (`src/zrb/llm/hook/hook_creators.py`, `test/llm/hook/test_hook_creators.py`): the timeout path called `process.kill()`, which kills only the shell spawned by `shell=True`. A forked grandchild survived it and — still holding the inherited stdout/stderr pipes — kept `communicate()` blocked in its worker thread until it exited on its own. Hooks are now started in their own session and killed by process group (with a psutil recursive-child fallback for Windows), so no descendant outlives the timeout and no pool worker stays pinned. The kill path can no longer raise either: an error escaping it was swallowed by the outer handler, turning a `CancelledError` that must propagate into an ordinary failed `HookResult`.
- **Fix: oversized MCP results were not actually bounded** (`src/zrb/llm/tool/mcp.py`, `test/llm/tool/test_mcp.py`): the cap added in 2.50.2 was incomplete. `cap_mcp_result` capped each item of a sequence independently, so N parts each just under `LLM_MAX_OUTPUT_CHARS` still totalled N times the budget — the same per-request overflow the cap exists to prevent, which the rate limiter can never admit. The budget is now shared across the whole structure (nested sequences included), with a single `...[TRUNCATED N more parts]` marker once it is spent. Binary and rich content parts still pass through untouched and uncharged.
- **Fix: a raced edit-args submission denied the pending approval** (`src/zrb/runner/chat/chat_session_manager.py`, `test/runner/chat/test_chat_session_manager.py`): when decoded JSON args arrived with no edit slot to consume them (a client racing edit-mode entry), the response fell through to the plain approval handler, which cannot parse a dict and denied the tool call outright. The miss is now reported to the caller and the pending approval is left intact to be answered normally.
- **Fix: HTTP-chat edit mode could strand the approval channel** (`src/zrb/runner/chat/http_chat.py`, `src/zrb/runner/chat/chat_session_manager.py`, `test/runner/chat/test_http_chat.py`): a cancelled run left `is_waiting_for_edit()` permanently true, so every later approval was routed down the edit path and its answer swallowed against the dead tool call. The edit slot is now released on cancellation, a stale slot is detected and cleared so a plain answer can still reach a genuinely pending approval, and the edit handlers report whether a pending call actually consumed the response instead of always claiming success while the tool call hung. Approval broadcasts also keep a strong task reference, so the loop can no longer garbage-collect one mid-flight and silently drop the client's update.
- **Fix: PDF URLs behind a JS or cookie wall failed outright** (`src/zrb/llm/tool/web.py`, `test/llm/tool/test_web_tool.py`): a narrowing introduced with PDF fetching in 2.50.2. The `.pdf` fast path skipped the browser entirely and was terminal, so a PDF served behind Cloudflare or a cookie/JS gate errored even though the Playwright path handles it. Plain HTTP is now a shortcut only — on failure the fetch falls through to the browser, which already routes `application/pdf` responses to the text extractor.
- **Fix: `copy_text` on Termux failed on large payloads** (`src/zrb/llm/util/clipboard.py`, `test/llm/util/test_clipboard.py`): follow-up to the Termux backend added in 2.50.6. The text was passed to `termux-clipboard-set` as a command-line argument, so copying anything sizeable (a whole transcript) could exceed `ARG_MAX` and fail the copy. It now goes over stdin.
- **Fix: `fstring_format` sandbox escape via dunder traversal** (`src/zrb/util/string/format.py`, `test/util/string/test_format.py`): template expressions are parsed and rejected when they reference a dunder name, closing the `().__class__.__bases__[0].__subclasses__()` route back to the real builtins — plain attribute access is not governed by the `eval` globals, so a builtins whitelist alone could not stop it. Single-underscore names remain allowed. Templates are still developer-authored; `data` values were never the trust boundary.
- **Performance: LSP server detection no longer rescans `$PATH` on every file edit** (`src/zrb/llm/lsp/configs.py`, `test/llm/lsp/test_configs.py`): `detect()` ran one `shutil.which` per configured server (~21) on every call, and `get_for_file` runs on each agent `Write`/`Edit` through the post-write diagnostics — which then probed a second time to build its no-server message. A miss walks every `$PATH` entry (~18ms where `PATH` includes WSL2's `/mnt/c/...`), so an edit paid up to ~1s of pure path scanning. The probe is now cached for the process lifetime, invalidated by `register()`/`clear()`, with a new `invalidate_detection()` for installing a language server mid-session.
- **Performance: repo analysis tokenized every file twice** (`src/zrb/llm/tool/code.py`, `test/llm/tool/test_code.py`): `_fit_file_payload` counted the payload's tokens to decide whether it fits, then the caller counted the returned string again. It now returns the count it already computed — one tokenizer pass per fitting file instead of two on every `AnalyzeCode`.
- **Performance: conversation save no longer blocks the event loop** (`src/zrb/llm/task/llm_task.py`): the summarization path's `history_manager.save` is now offloaded with `asyncio.to_thread`, matching the main turn path — it serializes, re-validates, and writes the whole conversation twice (with the backup), which must not stall the TUI.
- **Fix: `project.sh` autocomplete assumed `ps` exists** (`project.sh`): shell-completion setup probed the parent shell with `ps`, so `source project.sh` failed on minimal environments that ship without it. The probe is now guarded and skipped when `ps` is unavailable.
- **Test suite: ~45% faster** (`test/llm/hook/test_hook_creators.py`, `test/llm/lsp/test_configs.py`): a full run drops from ~118s to ~66s. Most of it is the hook process-group fix above — the leaked grandchildren were charged to whichever later test joined the thread pool, putting 28s on a five-line `test_executor_singleton` that runs in under 5ms on its own, and ~20s more on unrelated `test_hook_creators` teardowns. Three test doubles that slept 5s in a non-cancellable executor thread were also shortened to 0.3s, which is all their timeout/cancel assertions need.
