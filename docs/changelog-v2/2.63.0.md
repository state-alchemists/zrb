## 2.63.0 (August 15, 2026)

- **Feature: `/photo` captures a camera photo and attaches it to the conversation** (`src/zrb/llm/util/camera.py`, `src/zrb/llm/ui/base/conversation_commands.py`, `src/zrb/config/mixins/llm_ui_commands.py`, `src/zrb/llm/task/chat/ui_commands.py`, `src/zrb/llm/task/chat/running.py`, `src/zrb/llm/ui/ui_config.py`, `src/zrb/llm/ui/simple_ui_base.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/base/properties.py`, `src/zrb/llm/ui/base/commands.py`, `src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/app/layout.py`, `src/zrb/llm/app/completion/completer.py`, `docs/adr/adr-0082.md`): a one-shot `/photo [device]` command captures a JPEG from the system camera and attaches it to the next message, mirroring `/attach` rather than `/voice` since a snapshot has no start/stop lifecycle to toggle. Capture shells out to `ffmpeg` (v4l2 on Linux/WSL, avfoundation on macOS, dshow with auto-detected device on Windows) or `termux-camera-photo` on Termux -- no new Python dependency. `termux-camera-photo` writes to a fixed path under Termux's real home directory rather than `tempfile.gettempdir()`, so capture works identically from native Termux and from inside a `proot-distro` guest (field-tested: the guest's own `/tmp` isn't visible to the Termux:API app process that actually writes the file). Unlike `/voice`, there is no enable gate -- voice's gate exists specifically for its optional Python dependencies, a concern that doesn't apply to a dependency-free, subprocess-based feature. See ADR-0082.
- **Chore: three boolean `CFG` knobs renamed for ADR-0026 verb-first alignment** (`src/zrb/config/mixins/foundation.py`, `src/zrb/builtin/group.py`, `src/zrb/task/cmd_task.py`, `src/zrb/llm/config/limiter.py`): `LOAD_BUILTIN` → `ENABLE_BUILTIN_TASKS`, `WARN_UNRECOMMENDED_COMMAND` → `SHOW_UNRECOMMENDED_COMMAND_WARNING`, `USE_TIKTOKEN` → `ENABLE_TIKTOKEN`. Each old `ZRB_*` env var keeps working via `EnvField(aliases=[new, old])`; only the Python `CFG.*` attribute name changed. Also fixed `TIKTOKEN_ENCODING_NAME`'s alias order (new name now takes precedence over the old `ZRB_TIKTOKEN_ENCODING` when both are set, matching every other renamed knob's convention).
