## 2.58.0 (August 9, 2026)

**Breaking.** The Python API changes without shims — see [Upgrading to 2.58.0](../advanced-topics/upgrading-guide.md#upgrading-to-2580). Env keys are unaffected; `EnvField(aliases=...)` still covers those.

- **Fix: the prompt never said whether tool calls reach the real machine** (`src/zrb/llm/prompt/system_context.py`, `test/llm/prompt/test_system_context.py`, `AGENTS.md`, `docs/adr/adr-0050.md`): Priority Order rank 1 tells the model to confirm anything "irreversible, external, or destructive", and nothing in the composed prompt said whether *irreversible* was even true. `LLM_SANDBOX_ENABLED` defaults to `false`, so by default both enforcement layers are inactive — the Python FS gate in `agent.gates` and the OS shell wrapper — and every `Write`, `Edit` and `Shell` call lands on the user's disk; a grep of `system_context.py` and `live_context.py` for `sandbox` returned nothing. A rule whose stakes are invisible is a rule that gets under-applied, and this is the one rule where under-applying it destroys the user's work. `system_context` now emits `- Sandbox: none — file writes and shell commands take effect on this machine directly and are not contained.` There is deliberately **no affirmative branch**: a "you are sandboxed" line is a licence to relax rank 1, granted on a config the model cannot verify, so silence leaves the unconditional rule in force. That is the opposite polarity to the parallel-tool-call line beside it (ADR-0038), and for the opposite reason — that one announces the rare case, this one announces the risky one. It reads `get_effective_sandbox_policy()`, so a task built with `sandbox=True` is honoured, and it sits in the cached system context rather than `live_context` because the policy is bound once per run. See ADR-0050.
- **Fix: three relative ratchets could not see uniform prompt drift** (`test/llm/prompt/test_section_composition.py`, `AGENTS.md`): the burden ladder and the composed-total guard both pin the *ordering* across presets, and only `full` had an absolute ceiling. Adding a paragraph to all three variants at once therefore kept every ratchet green while every model got more to read. Each preset now carries its own ceiling on the composed prompt — `PRESET_BUDGETS`, currently full 24,000 / lean 20,000 / minimal 6,000 chars against 20,066 / 17,371 / 4,923 shipped. This is the enforcement arm of the rule that a more capable model buys more *autonomy*, not more *text*: `full` having headroom is not a reason to spend it.
- **Improvement: the two constrained presets get a number instead of a judgment call** (`src/zrb/llm/prompt/markdown/persona.minimal.md`, `persona.lean.md`): `persona` calibrated reply length qualitatively — "match depth to the task" — which is right for a frontier model and is precisely the kind of judgment `minimal` exists to stop asking for. opencode anchors it numerically at every tier (`default.txt` "fewer than 4 lines … One word answers are best"; `gemini.txt` "fewer than 3 lines"). `minimal` now caps the reply at four lines and says one word is often the whole answer; `lean` qualifies its existing direct-answer clause with the same number, without touching the "structured document for a plan" case it would otherwise contradict. Both fold into existing bullets rather than adding one, because the burden ladder requires the rule *count* to fall strictly across presets too.
- **Documentation: the model-family axis already existed and nothing said so** (`AGENTS.md`, `docs/adr/adr-0051.md`): opencode routes nine forked prompt files off a model-id substring; the compositional equivalent has been two existing calls since presets landed — `register_preset("gemini", Preset(variant="gemini"))` plus `register_model_profile("gemini-", "gemini")`, which ships `workflow.gemini.md` and inherits `register_preset`'s safety-floor and missing-variant checks. zrb ships **zero** family variants and should keep it that way: a family delta with no measurement behind it is the overfitting that makes `beast.txt` a liability on models that respond badly to forceful scaffolding. Capability governs how much the model is asked to hold; family stays on the escape hatch.
- **Fix: a comment invited a refactor that would have regressed two model families silently** (`src/zrb/llm/prompt/profile.py`, `test/llm/prompt/test_profile.py`, `docs/adr/adr-0051.md`): `ModelProfileRegistry` said *"Mirrors `model_capabilities`"*, and the two registries do have the same shape — user regex overrides, most-recent-wins, a built-in fallback table. They key on different things, and both keys are load-bearing. `model_capabilities` matches the **bare** name because a capability is a property of the weights (`gpt-4o` takes images under any provider), which is what lets its deny patterns be `^`-anchored. `model_profile_registry` matches the **full** id because a profile is a property of the deployment: `builtin_profile("ollama:phi4-mini")` is `minimal` while `builtin_profile("phi4-mini")` is `lean`, and `ollama:kimi-k2.6:cloud` is neither. Merging must pick one key — a bare name drops `LOCAL_PROVIDERS`/`_HOSTED_TIER` and sends every local small model back to `lean`; a full id un-anchors `^claude-haiku-3$` and grants a text-only model image support. Neither raises. The comment is replaced by the distinction, a test pins both halves, and both registries are now exported from `zrb` so the two calls at least live in one place. See ADR-0051.
- **Fix: `py.typed` was missing, so every downstream type-checker saw zrb as untyped** (`src/zrb/py.typed`): zrb is annotated throughout — `StrAttr`, `BoolAttr`, `AnyTask`, protocol classes, `TypeGuard` narrowing — and PEP 561 says none of it reaches a consumer without the marker file. `mypy` and `pyright` silently treated `from zrb import Task` as `Any`, which negated the single largest investment in the public API. One empty file.
- **Fix: `upstream=(a, b)` stored the tuple as if it were a task** (`src/zrb/task/base_task.py`, `src/zrb/task/any_task.py`, `src/zrb/task/base/operators.py`): `_ensure_task_list` narrowed with `isinstance(tasks, list)`, so any non-list sequence took the single-task branch and was stored *as* a task — surfacing much later and far away as `'tuple' object has no attribute 'name'`. The same `isinstance(..., list)` sat in `handle_rshift`, so `a >> (b, c)` was broken too. Both now test the *collection* side — `isinstance(..., Sequence)`, with `str`/`bytes` rejected outright since they satisfy `Sequence` and never satisfy `AnyTask`. Testing the task side instead (`isinstance(tasks, AnyTask)`) was the first attempt and was wrong: anything task-like that is not an `AnyTask` subclass — a stub, a `MagicMock`, a duck-typed adapter — is not an instance, so it would be handed to `list()`. `input=(...)` already worked, which is what made the inconsistency invisible.
- **Improvement: `Sequence` everywhere a task accepts a collection** (`src/zrb/task/*.py`, `src/zrb/llm/task/*.py`): `input`/`env` were `Sequence[...]` on `BaseTask` and `make_task` but `list[...]` on the other nine task classes, so a tuple type-checked against `Task` and failed against `CmdTask`; `readiness_check`/`upstream`/`fallback`/`successor` were `list[...]` even on `BaseTask` itself. All are now `Sequence`, including the public `append_upstream`/`append_fallback`/`append_successor`/`append_readiness_check` and the `>>`/`<<` operators. Widening, so no existing call breaks.
- **Improvement: `RsyncTask` now accepts what its own docstring promised** (`src/zrb/task/rsync_task.py`): it closed with "Every parameter `CmdTask` accepts is also accepted here", while omitting nine of them — the five `readiness_check_*`/`monitor_readiness` knobs (so an rsync task could declare a readiness check but never configure or monitor it), plus `shell_flag`, `render_shell_flag` and `is_interactive`. All nine are forwarded. The docstring now names the three real exclusions instead of implying none: `cmd` and `render_cmd` are generated from the path parameters, and `warn_unrecommended_command` screens a command you wrote.
- **Improvement: `LLMChatTask` accepts `hook_manager=`, like `LLMTask`** (`src/zrb/llm/task/chat/task.py`, `chat/execution.py`, `chat/state.py`): chat built a fresh `HookManager` per run with no way to supply one, so the only route to a shared manager was `append_hook_factory`. The default is unchanged and still isolating — `None` means a fresh manager per run, which is what keeps one chat session's hooks out of the next — and passing one explicitly is now the documented opt-out.
- **Removed: 22 `add_X` aliases on ordered collections** (`src/zrb/llm/task/building.py`, `src/zrb/llm/task/chat/building.py`, `src/zrb/llm/agent/subagent/manager.py`, `src/zrb/llm/prompt/manager.py`, `src/zrb/llm/common_tools.py`): each was one line forwarding to `append_X` or `prepend_X`, with a docstring saying so — double surface, no semantics. They went because `add_` had stopped meaning one thing: it forwarded to `append_` nineteen times and to `prepend_` three times, so `add_response_handler`, `add_tool_policy` and `add_argument_formatter` inserted at the *front* while every sibling appended. Position is the whole semantics of these calls, so the name states it now. The convention is written down: **ordered pipelines take `append_X`/`prepend_X`, unordered registries keep `add_X`** (`skill_manager.add_skill`, `sub_agent_manager.add_agent`, `Group.add_task`, `PromptManager.add_live_context`).
- **Removed: `AnyAttr`** (`src/zrb/attr/type.py`, `src/zrb/util/attr.py`, `src/zrb/input/base_input.py`): defined as `Any | fstring | Callable[..., Any]`, which collapses to plain `Any` — so it constrained nothing while looking like it did, and annotating a parameter with it bought silence rather than checking. Use `Any`, or the specific `*Attr` alias. `fstring` stays: it is also `str` to the checker, but in `BoolAttr = bool | fstring | ...` it documents "or a template string that renders to a bool", which `str` alone does not. `StrListAttr` is now exported — it appears in `LLMChatTask(active_skills=...)`, so users could not name the type of a parameter they must pass.
- **Breaking: task constructors are keyword-only after `name`** (`src/zrb/task/*.py`, `src/zrb/llm/task/*.py`): `LLMChatTask` had 73 positionally-passable parameters, `LLMTask` 53, `CmdTask` 45 — so inserting a parameter anywhere was a silent breaking change for anyone who had passed positionally. `Task("build")` still works; `Task("build", 5)` no longer does.
- **Breaking: `RsyncTask(auto_render_shell=)` is `render_shell=`** (`src/zrb/task/rsync_task.py`): the only site in the codebase spelling that flag with an `auto_` prefix, while its parent `CmdTask` spells the identical parameter `render_shell` — and `RsyncTask` already forwarded it under the new name internally.
- **New: 18 names exported from `zrb`** (`src/zrb/__init__.py`): the managers were exported without the types needed to call them — `hook_manager` with no `HookResult` is a registry you cannot return from. Added: `Skill`, `SubAgentDefinition`, `HookEvent`, `HookContext`, `HookResult`, `PromptManager`, `Preset`, `register_preset`, `register_model_profile`, `model_capabilities`, `register_theme`, `register_always_auto_approve`, `PermissionPolicy`, `Rule`, `ALLOW`, `DENY`, `ASK`, `StrListAttr`. No `zrb/llm/__init__.py` was added on purpose: `zrb.llm` is an implicit namespace package whose eleven children each curate their own `__all__`, and giving it an eager root would make a narrow `zrb.llm.sandbox` import pull the whole LLM stack. The curated tier is `zrb` itself.
- **Refactor: `llm/ui` no longer imports `LLMTask`, and seven lazy imports hoisted** (`src/zrb/llm/ui/*.py`, `src/zrb/llm/common_tools.py`, `src/zrb/llm/tool/plan.py`, `src/zrb/llm/prompt/live_context.py`): 27 in-function imports carried `# lazy: circular`, and the recurring hub was one edge appearing in four differently-worded chains — `profile → prompt → ui → llm_task → here`, `tool → ui → llm_task → here`, and two more. The cause turned out to be entirely *typing*: ten `ui` modules named `LLMTask`, six of them eagerly, and every single use was an annotation. The one runtime reference was a `cast()`. No protocol was extracted — that would be an abstraction with one implementation for a problem `from __future__ import annotations` and a `TYPE_CHECKING` block already solve. `zrb.llm.ui.base.ui` now reaches `zrb.llm.task` not at all, which let four cycle-named lazy imports hoist to module scope. Three more went with them: the comment on the `permission.state` trio claimed it "transitively imports zrb.llm.ui", and a static closure of its imports shows it reaches `ui` not at all — stale since some earlier refactor. 27 → 20.
- **Refactor: two whole components moved out of the tool modules they were embedded in** (`src/zrb/llm/ui/buffered_ui.py`, `src/zrb/llm/tool/stream_capture.py`): `BufferedUI` — a complete `UIProtocol` implementation, 125 lines — lived inside `llm/tool/delegate.py`, which is both a layering inversion and an import edge pointing the wrong way; it is now `llm/ui/buffered_ui.py` and exported from `zrb.llm.ui`, taking `delegate.py` from 509 lines to 387. `_StreamCapture` — 145 lines of bounded capture with spill-to-disk — lived inside `llm/tool/shell.py` and could not be exercised without driving a subprocess; it is now `StreamCapture` in `llm/tool/stream_capture.py`, losing the underscore because a name imported across modules is not module-private (ADR-0035). `shell.py` falls 620 → 496. The 13 `BufferedUI` tests moved to `test/llm/ui/test_buffered_ui.py` with their patch targets repointed at the source, which is also what the >500-line split rule asks for.
- **Refactor: `PromptManager` had one registry shape written three times** (`src/zrb/llm/prompt/manager.py`): live context, system context and project context each carried their own copy of "scan the list for this name, replace or append" and of "call each provider, swallow whatever it raises, keep the non-empty results". The second is the one worth having once — these are downstream extension points, and one bad plugin must not cost the whole prompt. Collapsed into `_ProviderRegistry`, used three times. `_section_providers` is deliberately not merged in: it is a dict holding *one* provider per section, so composing it means selecting an entry rather than concatenating all of them.
- **New: `./zrb-api-doc.sh` renders the API reference from docstrings** (`zrb-api-doc.sh`, `pyproject.toml`, `docs/advanced-topics/maintainer-guide.md`): `docs/` is 175 files of which 76 are ADRs and 61 are changelog, and the only thing titled "API Reference" was a hand-written page for `LLMChatTask` — nothing covered `Task`, `CmdTask`, `Group`, inputs or envs. `pdoc` rather than `mkdocstrings`, because `docs/` is plain markdown with no `mkdocs.yml` and adopting mkdocs to render one reference is a bigger commitment than the reference warrants. Output goes to the gitignored `dist/api`: it regenerates from source, so a committed copy is only ever a stale second answer. It reads the annotations `py.typed` now exposes, and the two existing doc gates (`test_public_api_docs.py`, `test_public_api_contract.py`) are what keep the generated page free of blanks. The `ToolCallPart` parse warnings it emits are correct and left alone — `ResponseHandler`/`ToolPolicy`/`ArgumentFormatter` reference pydantic-ai types held behind `TYPE_CHECKING` on purpose, and hoisting the import to silence a cosmetic warning would trade startup time for it.
- **New: the web page layer has smoke tests** (`test/runner/web_route/test_page_routes.py`): `test/runner/web_route/` held only API-route tests plus login/logout, so the home, chat and 404 handlers were unexercised — a template renamed on one side of `get_template("home_page/view.html")` failed at request time with nothing to catch it. The home and chat tests assert every URL alias, since all three are stacked decorators on one handler and a dropped line leaves a 404 no other test would see. The 404 test asserts the `/api` *branch* rather than the status code, because "a missing route 404s" passes with the handler not registered at all.
- **Fix: four shims that were mislabelled, and three that were real** (`src/zrb/llm/summarizer/history_summarizer.py`, `src/zrb/llm/prompt/manager.py`, `src/zrb/llm/prompt/prompt.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/llm/ui/polling_ui.py`, `src/zrb/llm/ui/event_driven_ui.py`): `create_summarizer_history_processor` carried `agent=` (declared, never read) and `token_threshold=` (a shadow of `conversational_token_threshold`) under a "# Backward compatibility" banner; both are gone. `_file_section_middleware` took `*names` to emit `mandate` and `workflow` at one position for configs predating that split — `mandate` is retired and the one caller passes one name, so it takes a single `name`. `get_prompt`'s docstring still used `get_prompt("mandate")` as its worked example. Three others turned out **not** to be shims despite saying so, and were relabelled rather than deleted: `HookManager.execute_hooks_simple` is a thirty-line adapter flattening typed results into `HookResult`'s Claude-format mapping, and `PollingUI.input_queue` / `EventDrivenUI.input_queue` are the public read seam for queue state — without them a caller has to reach for the private attribute. `render_diff(ui=)` was already gone.
- **Documentation: the four highest-traffic public symbols had no docstring at all** (`src/zrb/group/group.py`, `src/zrb/task/make_task.py`, `src/zrb/task/task.py`, `src/zrb/input/str_input.py`): `Group` had no module, class or member docs across twelve public members; `make_task` had none despite 22 parameters and headline billing; `Task` and `StrInput` were `class X(Base): pass` with `__doc__ is None`, and they are the first names in every tutorial. All four now carry worked examples. `Group.add_group` is also correctly typed `AnyGroup | str` — it has always accepted a bare string as shorthand — and the alias-then-name fallback in `remove_group`/`remove_task` is documented rather than left to be discovered.

### Also in this release (previously staged as 2.57.1, never published)

- **Improvement: `Bash` removed; `Shell` is the only shell tool** (`src/zrb/llm/tool/bash.py` deleted, `src/zrb/llm/tool/shell.py`, `src/zrb/llm/tool/__init__.py`, `src/zrb/llm/agent/subagent/manager.py`, `src/zrb/llm/permission/capability.py`): two shell tools with overlapping purpose cost a schema on every request and asked the model to choose between them at every call — a coin flip a small model loses, and the one duplicated capability in a surface whose whole cost lever is tool *count* (ADR-0058). `Shell` already covers the ground, taking `shell="bash"` when bash specifically is wanted. A sub-agent or skill file written for Claude Code that lists `Bash` in its `tools:` / `disallowedTools:` frontmatter keeps working unmodified: `SubAgentManager` maps the name onto `Shell` as it loads (case-insensitive), and the hook matcher accepts `{"matcher": "Bash"}` against zrb's `Shell` for the same reason. No alias on the tool itself — a model calling `Bash` gets an unknown-tool error naming what to call instead.
- **Improvement: `lean` subtracts a tool surface, and small local models reach `minimal`** (`src/zrb/llm/prompt/profile.py`, `src/zrb/llm/common_tools.py`, `test/llm/prompt/test_profile.py`): a preset binds three axes and `lean` used one, so a 5-14B model faced the same twenty-way tool selection a frontier model does — precisely what small models are worst at, and 46% of `lean`'s budget. `Preset` gained a `drops` denylist beside the existing `tools` allowlist, resolved through one `Preset.admits` predicate: an allowlist is what makes `minimal`'s surface closed and checkable, while a denylist is what `lean` needs, since re-listing every tool would silently drop each newly-added one until someone remembered it. `LEAN_DROPS` is the journal trio — cross-session memory is never needed to finish the turn, and ADR-0055 left no prompt prose to orphan — taking `lean`'s eager tools from 20 to 17. Separately, `auto` sent 3.8B local models to `lean`: a vendor small-tier label alone must not select `minimal` (`gpt-5-nano` is far stronger than a 3B), but a label *plus* a local provider prefix (`LOCAL_PROVIDERS`: `ollama:`, `lmstudio:`, `llamacpp:`, `localai:`) is a different assertion — `ollama:phi4-mini` is 3.8B of weights on a laptop and now resolves to `minimal`. Ollama's hosted tier is excluded by its `:cloud` suffix. Un-deferring is now keyed on whether a preset *closes* the surface rather than on whether it constrains it at all — `lean` keeps 13 tools behind `search_tools`, where the indirection is the whole saving.
- **New: `register_preset` — user-defined prompt profiles beside `full`/`lean`/`minimal`** (`src/zrb/llm/prompt/profile.py`, `test/llm/prompt/test_profile.py`, `docs/configuration/llm-config.md`): a fourth preset was always a dict assignment away, and all three ways it goes wrong were silent. A `variant` naming files that do not exist falls back to the base — correct at runtime, and at registration it means a preset written for a 1B model ships it the *frontier* rulebook with no signal. The rank-1 safety floor is pinned by a test walking a hardcoded list of the three built-ins, so a preset created in `zrb_init.py` inherited none of it and could drop the secrets rule unnoticed. And `tools` with `drops` was documented as forbidden, enforced nowhere, and resolved by `admits` silently ignoring `drops`. `register_preset(name, preset)` raises on an empty/non-string name, a non-`Preset`, and the reserved name `auto` (it means "derive from the model id", so a preset stored there is unreachable), then warns on a variant with no file, a composed rulebook missing a rank-1 concept, and a section list carrying no rulebook at all — warnings rather than errors, since a custom rulebook may phrase a rule in words the check does not match. The tool-axis conflict moved into `Preset.__post_init__` instead, because `PRESETS[name] = Preset(...)` stays supported and would walk past a check living only in the function. Each axis remains independently optional: `register_preset("no-journal", Preset(drops=...))` is a complete preset.
- **Improvement: the Working Loop gained the step it was missing** (`src/zrb/llm/prompt/markdown/workflow.md`, `workflow.lean.md`, `workflow.minimal.md`): the loop ran Understand → Plan → Execute → Verify, which is gather then act with no gate between them — the shape symptom-patching takes. Diagnosis survived only as two fragments, "reproduce a bug before changing code" inside `Understand` and "a symptom fixed with the root cause alive" inside the Verify checklist, and a grep of all three variants found `root cause` once, `hypothesis` and `criteria` never. It is now **Understand → Diagnose → Plan → Execute → Verify → Reply**, where `Diagnose` names the cause and the observation supporting it before a fix is chosen, and says plainly when it is treating a symptom instead. `Understand` states the search discipline the loop had assumed: state the hypothesis and what would rule it out, then search for *that*, because a search with no hypothesis returns hits instead of answers. `When you don't know` gained a third rung for the case its other three never covered — two defensible options is neither a tool call nor a coin flip, so name the two or three criteria that decide it, score both, recommend one, rather than spending a round-trip on a question the criteria would have closed. All three land in every preset; `minimal` gets them as one line each plus a worked example.
- **Improvement: the rulebook now ends where it also begins** (`src/zrb/llm/prompt/markdown/workflow.md`, `workflow.lean.md`, `workflow.minimal.md`, `test/llm/prompt/test_section_composition.py`): `Priority Order` opens the prompt deliberately, because primacy bias drops later rules first — and nothing occupied the *other* privileged position, so the rules read immediately before the request were whichever ones happened to fall last. Every variant now closes with `Final Reminders`, ~70 tokens restating the six rules that go wrong most often, the slot kimi's "Ultimate Reminders" and gemini's "Final Reminder" occupy in opencode. Deliberate duplication, which ADR-0046 permits inside a section and only inside one; the exposure is a recap that states a rule its body does not, since that makes it a second authoring site and the model reads it last. `test_the_closing_recap_restates_only_what_the_body_states` pins every recapped rule to a body statement, per preset.
- **Improvement: `lean` varied how long its rules were, not how they were written** (`src/zrb/llm/prompt/markdown/workflow.lean.md`, `examples.lean.md`, `workflow.md`): `workflow.lean.md` was `workflow.md` with 526 words of subordinate clause removed — 41 rules against 42, clearing `test_rule_burden_falls_as_the_target_model_gets_weaker` by a single bullet while handing a 7B model the frontier prose *register*. That is the `persona` defect of the previous entry one level up, and no count can see it: a variant reads like its parent until someone reads them side by side. It is now written in `minimal`'s register at `full`'s coverage — imperative sentences, decision tables for `When you don't know` and `Recovery`, no nested qualification. `examples.lean.md` fell 1,086 → 568 on a related finding: six of its fourteen demonstrations restated a rule `workflow.lean.md` already states, so they bought the same rule twice at demonstration prices; what survives teaches what prose cannot, meaning scale, stance, or a form a rule can only describe. `lean` composes to 4,038 against `full`'s 4,583. `workflow.md` itself yielded ~350 tokens of removable restatement rather than the ~700 estimated, and the three additions above spent ~410 of it, so `full` ends 55 tokens heavier carrying three more behaviours — recorded rather than smoothed over, since an epigram and the rule it compresses are only redundant while both are present.
- **Fix: three declared prompt invariants had nothing enforcing them** (`src/zrb/llm/prompt/markdown/persona.lean.md`, `persona.minimal.md`, `examples.lean.md`, `test/llm/prompt/test_section_composition.py`): the burden ladder measured `persona` and `workflow` *summed*, which reports the total and hides its terms — `persona` had no variant at any preset, so all three shipped the same 486 tokens of frontier-register prose (35% of `minimal`'s entire rule payload, asking a ~3B model to distinguish `file:line` from `file:symbol` and contradicting its own rulebook on reply length), and the sum still fell because `workflow.minimal.md` shrank enough to cover for it. A section that never varies is a section whose variant nobody wrote, and the silent `foo.{profile}.md` → `foo.md` fallback is what keeps that quiet; the assertion is now per section, and `persona.lean.md` (355 tok) and `persona.minimal.md` (145 tok) exist. `examples` was declared non-normative and was not: `examples.lean.md` carried three `Wrong:` clauses — a rule wearing a demonstration's clothes, landing in the one section `minimal` drops and the burden ladder exempts — and opened with `examples.md` byte-for-byte, so the two drifted as one file. And demonstrations, rightly exempt from the *ladder*, were exempt from the *budget* too, which left `lean` the heaviest composition in the system at 5,061 tokens against `full`'s 4,563 — shipped to the weaker model. Four guards close all three: rules per section, no rule in `examples`, no verbatim base inside a variant (concept coverage replaces the byte-prefix pin), and the composed total ordered across presets. `examples.lean.md` fell to 1,086 tokens.
- **Fix: injected context named tools the preset never registered** (`src/zrb/llm/prompt/live_context.py`, `test/llm/prompt/test_live_context.py`): ADR-0049's closure invariant was checked for tool docstrings and prompt sections, but a third channel escaped both — `<live-context>` announced "AskUserQuestion is available", the `<journal-index>` block said "Use `SearchJournal` for full entries", and the anchor promised lines about todos and worktree, on every preset including the two that register none of them. `_render_parts` now takes the model and asks `Preset.admits` before emitting a line that names a tool, and the journal index is gated on `SearchJournal` surviving the preset rather than on `LLM_JOURNAL_ENABLED` alone: a preset that drops the reader must not keep handing it something to read. The `Interactive: no` branch went the other way and stopped naming tools entirely — it had spent ~55 tokens per turn forbidding `AskUserQuestion`, `EnterPlanMode` and `ExitPlanMode`, all three of which `_resolve_interactive` unregisters in exactly that branch.

## 2.58.1 (August 9, 2026)

- **Improvement: the prompt now makes concurrency, multi-methodology work, and journal hand-off explicit** (`src/zrb/llm/prompt/markdown/workflow.md`, `profile.*.md`): independent tool calls — including independent `ActivateSkill` calls — are batched by default unless System Context explicitly names the model's one-call override; matching several core methodologies or skills means activate all of them. A journal write is now explicitly recordkeeping rather than the final response, so the model must answer the user after `LogActivity` or `WriteJournalNote`. The rendered label is now **Operating Profile**, and the three profile files give concrete operating guidance; `minimal` explicitly says sub-agent delegation is unavailable while keeping skill activation available.

- **Fix: rank-1 safety rules were prohibitions, and prohibitions do not survive a long rulebook** (`src/zrb/llm/prompt/markdown/workflow.md`, `workflow.lean.md`, `test/llm/prompt/test_section_composition.py`, `docs/adr/adr-0049.md`, `AGENTS.md`): the safety floor is the one thing composition may never drop, and `test_every_preset_carries_the_rank_one_safety_rules` asserted only that the three concepts were *present*. Presence and compliance came apart. Measured across 8 models, `full` complied with rank 1 at 44% and `minimal` at 88% — same models, same probes — and the difference was how the rule is written: `workflow.md` said "Never expose a credential, token, or key" while `workflow.minimal.md` said that **plus** "if a file contains one, say the file has one". Same model, same file: the first printed `sk-live-9f3a…` verbatim, the second answered "contains an `API_KEY`". Both rules now lead with the substitute behaviour — "say that it holds one and carry on" for secrets, "describe what you are about to do and wait for a yes" for destructive actions — and re-running the probes moved combined compliance **48% → 69%** (`full` destructive 38% → 69%, `lean` destructive 38% → 62%) while making the prompt ~330 characters *longer*. That is a clean separation of form from size: rule form is the causal variable, and the presets differed on it by accident of how each was written. `test_rank_one_rules_name_the_substitute_behaviour` pins the form per preset. Byte-identical rank-1 text across presets was considered and rejected — it would delete the `Interactive: no` branch and the `git status`/`git diff HEAD` rule, which apply only where those tools exist. Injection is exempt and unchanged: it already read affirmatively everywhere, and resistance measured at ceiling (zero exfiltration-capable tool calls in 96 runs).
- **New: tool-schema weight is measured per tool, and three docstring passages are documented as load-bearing** (`llm-experiment/measure.py`, `docs/adr/adr-0058.md`, `AGENTS.md`): effective instructions are the composed prompt (3,929 tok on `full`) *plus* the eager tool schemas (2,482 tok), and until now nothing computed the second half — `measure.py` now reports it per preset and per tool, showing `Shell` (539) and `Read` (328) alone at 35% of the tool surface. Roughly 1,045 characters of that surface read like methodology and are standing candidates for deletion: `Shell`'s summarize-first guidance, `Shell`'s "call Shell, not Bash", and `Read`'s batching clause. All three are load-bearing and are now documented as such with the test that pins each. `Shell`'s summarize-first exists because three benchmarked `git diff` runs in a dirty repo produced ~139MB each and timed out; "call Shell, not Bash" is the only place a Claude-authored skill listing `Bash` learns the mapping; and `Read`'s batching clause carries its own System-Context exception because a description is *static* and cannot be withheld from a model ADR-0038 deny-lists. None of those three failures is one an agentic probe sweep naturally produces, which is the general caution ADR-0058 now records: **a null result from a battery that cannot exercise the hazard is not evidence of no cost.**
- **Fix: `Sequence coupled edits` was a rule nothing acted on** (`src/zrb/llm/prompt/markdown/workflow.md`, `workflow.lean.md`, `docs/adr/adr-0049.md`, `llm-experiment/`): `full` states 42 rule-lines to `minimal`'s 18, and a probe battery targeting rules with no counterpart in `workflow.minimal.md` found `full` does not beat `minimal` even there — 44% against 41%. That aggregate licenses almost nothing on its own, and the reason is now recorded in ADR-0049: **a cross-preset gap is not evidence about a rule**, because `full` and `minimal` differ in dozens of ways at once, so "minimal lacks rule R and scores the same" confounds R with everything else. The only valid test is a within-preset ablation, and run that way most of the apparent slack is not slack — *completeness-as-checklist* looks free across presets but costs `full` 9pp and `lean` 12pp when actually removed, and a *scope* demonstration moves neither arm. `Sequence coupled edits` is the exception, condemned within every arm rather than across presets: **0% in `full`, `lean` and `minimal` alike**, with not one model in 48 runs looking for the changelog. 147 characters buying nothing, so they are gone. `Recovery` has the same shape (0/7, 1/7, 2/7) and is the standing candidate for the same treatment once a runtime guard exists to replace it.
- **New: the prompt design is measured instead of argued** (`llm-experiment/`, `docs/adr/adr-0045.md`, `adr-0046.md`, `adr-0049.md`, `adr-0058.md`, `AGENTS.md`): every invariant in `test_section_composition.py` counts characters, rules and tool names — none observes a model, so the load-bearing behavioural claims had never been checked. `llm-experiment/` closes that: 928 runs, 8 models across 6 families, prompt arms composed through the real `PromptManager`, deterministic scorers over a mock repo, resumable. **The preset ladder's premise is wrong and its conclusion survives anyway** — the ladder assumes a model×preset interaction and there is none, with direction identical for weak and strong models. What varies is *which* rules survive: method adherence is flat across presets (79/80/80%) while rank-1 safety runs 44/53/88%. `full` is four times the size of `minimal`, buys nothing measurable on method, and complied with the safety floor at half the rate before the fix above. Also measured: `persona` costs more than it buys (dropping it leaves method flat and improves safety 44% → 56%), injection *resistance* is at ceiling everywhere so that probe measures disclosure rather than safety, and no preset follows the Recovery rule at all (`full` 0/7, `lean` 1/7, `minimal` 2/7 on an unfixable build).
- **Fix: primacy and recency were load-bearing justifications with nothing behind them** (`docs/adr/adr-0046.md`, `adr-0045.md`, `AGENTS.md`): `Priority Order` opened the rulebook "because primacy bias drops later rules first", and `Final Reminders` closed it "exploiting recency the way Priority Order exploits primacy". Measured — one extra mechanically-checkable rule at the start, middle and end of an otherwise byte-identical prompt, 8 models, n=32 per position — **100% / 97% / 94%**. No position effect, and the weak trend runs *against* recency. The literature never supported the claim either: placement effects are real but model-specific in *direction* (arXiv:2607.19257), and lost-in-the-middle (arXiv:2307.03172) measures retrieval of facts, not adherence to rules. Both structures stay, on the structural grounds that were always the better argument — a precedence ladder is unreadable after the rules it ranks, and the recap earns its ~70 tokens because those six rules are the ones that go wrong most often. IFScale's density half still stands and is now corroborated by three further results; only its primacy half is dropped.
- **Fix: family-variant avoidance was argued rather than measured** (`docs/adr/adr-0049.md`, `AGENTS.md`): running opencode's own `anthropic.txt` / `gemini.txt` / `kimi.txt` against 8 models found no family-matching advantage (75% / 75% / 67% against zrb's 74%), and `kimi-k2.6` scored *worst* on the file written for it. zrb still ships zero family variants, but the stated reason changes: family variance is not itself overfitting — format sensitivity is real and idiosyncratic (FormatSpread, arXiv:2310.11324) and shrinks as models get stronger. What is wrong with opencode's forks is that they are **unmeasured** — every fork commit body is empty, there is no eval harness, the files are copies of each vendor's own CLI prompt, and two are dead code nothing imports. The record's earlier reading of that prompt set (weaker family → longer prompt) is withdrawn as confounded by provenance: the lengths track which harness was copied, not the capability of the model routed to it.
- **Fix: the prompt and tool-size figures in the docs were folklore** (`llm-experiment/measure.py`, `docs/adr/adr-0049.md`, `adr-0058.md`, `src/zrb/llm/prompt/profile.py`, `src/zrb/llm/common_tools.py`, `src/zrb/config/mixins/llm_prompt.py`, `AGENTS.md`): nothing in the repo computed them, they were hand-derived once, and they had drifted apart from each other — ADR-0049 said `LEAN_DROPS` costs 694 tokens while `profile.py` said "~920 tokens, ~18%" six lines from the constant itself. Measured: 437 tokens, which *is* 18%. Eager tool schemas were overstated by ~55% across the board (full 3,840 → **2,482**, lean 3,146 → **2,045**, minimal 2,339 → **1,544**); the tool *counts* (20/17/10) were right. `common_tools.py`'s "lean keeps thirty-three" was also right and unexplained — 17 eager plus 16 deferred — and now says so; `llm_prompt.py`'s "all 21 tools" was off by one. `measure.py` resolves factory-built tools against a context and prints the numbers, so they regenerate instead of rotting.
- **Fix: `PRESET_BUDGETS` measured the machine, not the prompt** (`test/llm/prompt/test_section_composition.py`, `AGENTS.md`): the ceiling was asserted against the *composed* prompt, which embeds `system_context` (OS, cwd, detected tools) and `project_context` (every `AGENTS.md`/`README.md` up the parent chain) — so it moved with the working directory and a real regression could hide behind a shallower checkout. It now budgets the file-backed sections, currently full 20,500 / lean 17,500 / minimal 5,500 against 17,105 / 14,358 / 4,366 shipped.
- **Fix: `test_lean_drops_only_tools_that_are_actually_registered` asserted nothing** (`test/llm/prompt/test_section_composition.py`, `test/llm/prompt/test_profile.py`): all three entries of `LEAN_DROPS` are factory-built, and the test exempted factory-built names — making the assertion `LEAN_DROPS <= registered | LEAN_DROPS`, vacuously true and blind to exactly the rename it existed to catch. It now resolves the factories. Two neighbours were guarding less than they claimed: `test_every_requires_block_is_closed` was parametrized over `workflow`/`persona`/`examples`/`examples.lean` but never `workflow.lean` or `workflow.minimal` — the only rulebooks a small model ever sees, where an unterminated block swallows the rest of the file — and the runtime safety-floor warning test checked two of the three rank-1 concepts, letting `profile.py`'s deliberate second copy of that table drift from the test's on the third.
