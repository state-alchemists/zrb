## 2.67.0 (August 27, 2026)

- **Feature: tool calls, tool results, and thinking blocks are collapsible in the default TUI** (`src/zrb/llm/ui/default/{output.py,keybindings.py,agent_picker.py,ui.py,app/layout.py}`, `src/zrb/llm/ui/{buffered_ui.py,multi_ui.py}`, `src/zrb/llm/util/stream_response.py`, `test/llm/ui/`): long tool-call arguments/results and thinking text now print collapsed by default; `Ctrl+O` expands/collapses the block at (or just before) the output cursor, following the tail when nothing is scrolled. Works both in the main transcript and inside a sub-agent's own live view (`Left`/`Right`), each tracked independently. Child UIs that don't support toggling (Telegram, SSE) keep receiving the untouched line via the existing `append_to_output` broadcast.
- **Feature: `LLM_THINKING` sets a cross-provider reasoning/thinking level** (`src/zrb/config/mixins/llm_core.py`): accepts `minimal`/`low`/`medium`/`high`/`xhigh` for a specific effort, or `true`/`false` to enable/disable at the provider's default effort, applied as pydantic-ai's unified `ModelSettings.thinking`. Unset (default) leaves each provider's own default behavior alone; a task's own `model_settings` (e.g. `openai_reasoning_effort`) still takes precedence.
- **Fix (ADR-0085): an edited tool call now tells the model what actually ran** (`src/zrb/llm/tool_call/override_registry.py`, `src/zrb/llm/agent/run/deferred_calls.py`, `src/zrb/llm/agent/common.py`, `test/llm/tool_call/test_override_registry.py`, `test/llm/agent/run/test_deferred_calls.py`, `test/llm/agent/test_common.py`): when a human edits a tool call's arguments during approval, pydantic-ai's `override_args` swaps in the edited values for execution but never rewrites the `ToolCallPart` the model already wrote to history — so the model's next turn saw its own original request next to a result that didn't match it, with no signal a human intervened. The result now carries a `[SYSTEM NOTE]` naming just the changed argument keys (a diff against the original call, not a full dump) so the model knows the result reflects edited values.
- **Fix: ANSI escape codes no longer leak into the model's context** (`src/zrb/util/cli/ansi.py::strip_ansi`, `src/zrb/llm/tool/shell.py`, `src/zrb/llm/tool/delegate_background.py`, `test/util/cli/test_ansi.py`): the `Shell` tool already stripped ANSI from captured output (now via a shared `strip_ansi` helper instead of an inline regex); a background sub-agent's buffered transcript did not, so its muted styling (added for the sub-agent's own live view) showed up as raw escape codes once folded into the parent model's tool-result text.
- **Security: shell autocomplete no longer writes its cache to a predictable, world-writable path** (`src/zrb/builtin/shell/autocomplete/{bash,zsh,fish,powershell}.py`, `test/builtin/shell/autocomplete/`): the generated completion scripts now cache the subcommand list for one minute (keyed by cwd + the command being completed) under the user's own cache dir (`$XDG_CACHE_HOME`/`~/.cache`, `chmod 700`, or `%LOCALAPPDATA%` on PowerShell) instead of a shared temp location, closing a symlink-hijack window and avoiding a fresh process spawn on every keystroke.
- **Feature: Fish shell autocomplete** (`src/zrb/builtin/shell/autocomplete/fish.py`, `install.sh`, `docs/installation/installation.md`, `docs/task-types/builtin-helpers.md`): `zrb shell autocomplete fish` generates a completion script for `~/.config/fish/config.fish`; `install.sh` now registers it automatically when `fish` is present, alongside the existing bash/zsh registration.
- **Feature: hooks report `CLAUDE_PLUGIN_ROOT`** (`src/zrb/llm/hook/hook_loader.py::get_plugin_root_for_path`, `src/zrb/llm/hook/{creator.py,manager_loading.py,schema.py}`, `test/llm/hook/`): a command hook loaded from the built-in or a user-registered plugin directory now exports its origin directory as `CLAUDE_PLUGIN_ROOT` in the hook's environment, matching Claude Code's behavior; hooks loaded from any other tier (home/project/custom) still get `""`.
- **Improvement: platform-aware setup defaults and idempotent tmux/zsh helper installs** (`src/zrb/builtin/setup/common_input.py`, `src/zrb/builtin/setup/tmux/{tmux.py,tmux_helper.py,tmux_config.sh}`, `src/zrb/builtin/setup/zsh/{zsh.py,zsh_helper.py}`): `zrb setup`'s package-manager/sudo defaults are now `brew`/no-sudo on macOS (`sudo brew` corrupts Homebrew's directory permissions) and `apt`/sudo elsewhere; `zrb setup tmux` installs TPM only when `~/.tmux/plugins/tpm` doesn't already exist and adds `H`/`J`/`K`/`L` pane-resize bindings; `zrb setup zsh`'s oh-my-zsh/zinit installers are similarly skipped when already present.
- **Refactor: `Xcom` callback registration renamed to match the ordered-collection naming convention** (`src/zrb/xcom/xcom.py`, `src/zrb/task/base_trigger.py`): `add_push_callback`/`add_pop_callback` are now `append_push_callback`/`append_pop_callback`, since callbacks fire in registration order. No back-compat alias — a pre-release rename.
- **Refactor: `QueueBasedInput` owns its input queue instead of reaching into `SimpleUI`'s private state** (`src/zrb/llm/ui/queue_based_input.py`, `src/zrb/llm/ui/{simple_ui_base.py,event_driven_ui.py,polling_ui.py}`, `docs/advanced-topics/llm-custom-ui.md`): a custom `EventDrivenUI`/`PollingUI`'s `get_input` should read `self.input_queue` (the public property), not `self._input_queue`, which no longer exists — the custom-UI guide's example is updated accordingly.
- **Documentation: stale YAML hook example removed** (`examples/llm-hooks/.zrb/hooks.yaml`, `examples/llm-hooks/README.md`, `docs/advanced-topics/hooks.md`): the 214-line `hooks.yaml` sample (duplicating `hooks.json`'s examples) is gone; the example README and `hooks.md` now point readers at `hooks.md` for YAML-format hooks instead of a second example file.

## 2.67.1 (August 28, 2026)

- **Feature: shell command output collapses live in the default TUI** (`src/zrb/llm/tool/shell.py`, `src/zrb/llm/tool/stream_capture.py`, `src/zrb/llm/ui/default/output.py`, `src/zrb/llm/ui/{buffered_ui.py,multi_ui.py,default/ui.py}`, `test/llm/tool/{test_shell.py,test_stream_capture.py}`, `test/llm/ui/`): a running `Shell` command's stdout/stderr now streams into its own throttled (10/s), collapsible line instead of a static "started" marker, and folds into a `🖥️ Output (N chars)` summary (Ctrl+O-expandable to the full echo) once the command finishes — including on timeout or cancellation. Each command tracks its own span in the output buffer rather than a single shared offset, fixing a bug where two commands running concurrently could have one command's collapse devour the other's interleaved output.
- **Feature: the assistant's own streamed reply is collapsible too** (`src/zrb/llm/util/stream_response.py`, `src/zrb/llm/agent/run/setup.py`, `src/zrb/llm/ui/{buffered_ui.py,multi_ui.py,default/ui.py}`, `test/llm/util/test_stream_response.py`, `test/llm/ui/`): the live-streamed final-text block now collapses into a `💬 Response (N chars)` line the same way thinking blocks already did, expandable with Ctrl+O; `BaseUI`'s separate markdown-rendered copy of the same reply is unaffected.
- **Feature: Gemini's thinking summary surfaces without opting in, and Anthropic requests default to prompt caching** (`src/zrb/llm/agent/common.py`, `src/zrb/llm/util/capabilities.py`, `test/llm/agent/test_common.py`, `test/llm/util/test_capabilities.py`): Gemini 2.5/3 already reason (and bill `thoughts_tokens`) on every call but stay silent unless a request sets `thinking_config.include_thoughts`; `create_agent` now defaults `thinking=True` for models flagged `supports_thinking_summary`, but only when `LLM_THINKING` is unset, so it never overrides an explicit choice or turns on Anthropic's opt-in extended thinking. Anthropic calls also gain a default `anthropic_cache="5m"` (the provider's own breakpoint TTL), so zrb's resend-the-whole-history pattern stops reprocessing the full conversation from scratch on every turn.
- **Fix: doubled blank lines and misaligned indentation removed from status output printed outside the streaming handler** (`src/zrb/llm/tool_call/handler.py`, `src/zrb/llm/tool_call/response_handler/{default.py,replace_in_file_response_handler.py}`, `src/zrb/llm/approval/terminal_approval_channel.py`, `src/zrb/llm/ui/default/confirmation.py`, `src/zrb/llm/tool/{plan.py,web.py}`, `test/llm/approval/test_approval_channel.py`): tool-approval prompts, edit-argument echoes, todo-progress updates, and web-fetch notices now share the same "two-space indent, one leading newline supplied by whoever prints next" convention as `StreamEventHandler`, instead of landing at column 0 or stacking an extra blank line after a confirmation answer.

## 2.67.2 (August 29, 2026)

- **Breaking: `web_auth_config.append_user()` renamed to `add_user()`** (`src/zrb/config/web_auth_config.py`, `test/config/test_web_auth_config.py`, `docs/advanced-topics/web-ui.md`): the user list is an unordered registry keyed by username (duplicate-checked by username, never by position), matching the `add_X` verb every other unordered registry in the codebase uses (`SkillManager.add_skill`, `SubAgentManager.add_agent`, `Group.add_task`). Update any `zrb_init.py` calling `web_auth_config.append_user(...)`.
- **Fix: `ZRB_WEB_ENABLE_SECURE_COOKIES` renamed to `ZRB_WEB_AUTH_SECURE_COOKIES`** (`src/zrb/config/mixins/web.py`, `src/zrb/config/web_auth_config.py`, `test/config/test_web_auth_config.py`, `docs/configuration/env-vars.md`, `docs/advanced-topics/web-ui.md`): the knob now carries the `WEB_AUTH_` prefix shared with its siblings (`WEB_AUTH_ENABLED`, `WEB_AUTH_ACCESS_TOKEN_EXPIRE_MINUTES`), instead of standing out as `WEB_ENABLE_*`. The old env var is still read (not written) via an alias, so existing deployments keep working unchanged.
- **Breaking/Fix: `set_current_permission_policy()`/`set_current_sandbox_policy()` removed — replaced by `permission_policy()`/`sandbox_policy()` context managers** (`src/zrb/util/contextvar_scope.py`, `src/zrb/llm/permission/state.py`, `src/zrb/llm/sandbox/state.py`, `src/zrb/llm/agent/run/setup.py`, `src/zrb/contextvars.py`, `docs/advanced-topics/permission-policy.md`, `test/llm/permission/test_state_and_gate.py`, `test/llm/sandbox/test_gate.py`, `test/llm/prompt/test_system_context.py`): the two setters were bare `ContextVar.set()` calls with no reset, and `permission-policy.md` documented calling `set_current_permission_policy(policy)` directly as the way to set policy dynamically — a policy (or sandbox policy) set this way leaked into every later agent run sharing that context if an exception skipped manual cleanup, which nothing ever did. Both are now `with permission_policy(policy): ...` / `with sandbox_policy(policy): ...`, built on a new shared `zrb.util.contextvar_scope.scoped()` primitive that always resets on exit, matching how `run_agent()` already binds these same ContextVars internally. Also added a defense-in-depth backstop in `run_agent()`: `active_worktree` is now snapshotted and restored at the run boundary, so a forgotten `ExitWorktree` call can no longer leak a worktree path past the run that set it.
- **Refactor: the hook/agent circular-dependency cluster is now a DAG** (`src/zrb/llm/hook/agent_hook_registry.py`, `src/zrb/llm/agent/hook_agent.py`, `src/zrb/llm/hook/creator.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/llm/agent/__init__.py`, `src/zrb/llm/task/llm_task.py`, ADR-0086, `test/llm/agent/test_hook_agent.py`, `test/llm/hook/test_creator_llm.py`): `hook/manager.py` built its `HookType.AGENT` hook by lazily importing the agent-building subsystem from inside `hook/creator.py::create_agent_hook`, `# lazy: circular`-tagged because that subsystem depends on `hook.manager` to fire `PreToolUse`/`PostToolUse` — a real circular dependency, not just a circular import, and the actual runtime call graph existed only in five scattered, partly stale comments. `create_agent_hook` (moved, unchanged, to new `agent/hook_agent.py`) now registers itself into a new dependency-free registry (`hook/agent_hook_registry.py`) as an import side effect of loading `zrb.llm.agent`; `hook/manager.py` reads it back from there instead of importing it directly, and falls back to a logged warning + failed `HookResult` if the agent package was never loaded. `hook/creator.py`'s internal `_run_llm_hook` is now public (`run_llm_hook`), since `agent/hook_agent.py` calls it from outside the file. Breaking only for code importing `create_agent_hook` from `zrb.llm.hook.creator` directly — it now lives at `zrb.llm.agent.hook_agent`.
- **Refactor: two more UI/tool import cycles closed by extracting the shared leaf they were fighting over** (`src/zrb/llm/ui/output_chunk.py`, `src/zrb/llm/ui/default/output.py`, `src/zrb/llm/ui/buffered_ui.py`, `src/zrb/llm/tool_call/choice_spec_format.py`, `src/zrb/llm/tool/ask.py`, `src/zrb/llm/ui/base/ui.py`, `test/llm/ui/test_buffered_ui.py`): `buffered_ui.py` and `ui/default/output.py` both needed `merge_output_chunk`/`CollapsibleBlockSource`, defined in the latter and reached by `buffered_ui.py` through four separate `# lazy: circular` imports; both now import them from a new stdlib-only `ui/output_chunk.py`. `ui/base/ui.py` and `tool/ask.py` had the same shape over `format_choice_spec`, now in a new `tool_call/choice_spec_format.py` — `ui/base/ui.py` no longer depends on `zrb.llm.tool` at all for this call site. Same rationale `zrb.llm.factory_resolver` already established for sharing a helper without risking a cycle.
- **Refactor: the agent run loop's turn state is now a `TurnCursor`, and `sanitize_history`'s step order is an explicit pipeline** (`src/zrb/llm/agent/run/turn_cursor.py`, `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/agent/run/history_utils.py`, `src/zrb/llm/agent/run/retry_loop.py`, `src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/hook/turn_evidence.py`, ADR-0040, `test/llm/agent/run/test_turn_cursor.py`, `test/llm/hook/test_turn_evidence.py`): `_execution_loop` threaded 7 loose variables across 5 exit paths, with two fragile invariants (never reapply the summarizer mid-deferral; accumulate each round's new messages rather than slicing once at turn end) enforced only by a comment each — the function's own comment admitted a "naive" simplification would silently drop approved tool calls. Both variables and both invariants now live on a new `TurnCursor` (sibling to `RetryState`/`ExtensionState`/`PartialRunAccumulator`), with `carry_forward()`/`commit_round()` as the only methods allowed to perform either transition. `drop_oldest_turn`'s `min_turns` is now a named `TurnPruneFloor` enum instead of a bare `0`/`1`. `sanitize_history`'s 4 steps are now an explicit `_SANITIZE_STEPS` tuple with a DEBUG-only postcondition check, so a broken step order surfaces as a log line instead of silent corruption. Along the way, `history_utils.py` lost two functions that never belonged to history sanitization: `_append_live_context` moved (renamed public) to `prompt/live_context.py`, and `turn_wrote_files`/`FILE_MUTATING_TOOL_NAMES` moved to new `hook/turn_evidence.py`.
- **Refactor: `BaseUI`/`MultiUI`'s duplicated `submit_user_message` logic is now one shared function** (`src/zrb/llm/ui/base/message_queue.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/multi_ui.py`, `test/llm/ui/base/test_message_queue.py`): `BaseUI.submit_user_message`'s own docstring admitted it was "mirroring `MultiUI.submit_user_message`" — two independently-maintained, ~20-line implementations of the same echo/attachment/queue mechanics, with nothing enforcing they stayed in sync. Both now call a new `submit_user_message_via_queue()`, parameterized by which targets to fan attachment-collection and echo-tracking out to (`[self]` for a standalone UI, the child list for `MultiUI`, which holds no attachments or echo buffer of its own) — `append_to_output`/`active_run_context`/`stream_ai_response` stay owner-called either way, since both classes already implement those polymorphically. Investigating the fuller `multi_ui_parent` back-reference this session's design also flagged: it's a widely-used public property (a production dependency of `default/message_editing.py`, and a named contract in several existing tests), so removing it in favor of an injected collaborator was judged too invasive for the payoff and left alone — the duplication was the part worth fixing, and is now fixed without touching that surface.
- **Refactor: `LLMTask`/`LLMChatTask`'s history knobs are also readable as one `HistoryConfig` group** (`src/zrb/llm/task/history_config.py`, `src/zrb/llm/task/llm_task.py`, `src/zrb/llm/task/chat/task.py`, `src/zrb/llm/task/chat/execution.py`, ADR-0072, `test/llm/task/test_history.py`, `test/llm/task/chat/test_llm_chat_task.py`): `history_manager`/`conversation_name`/`render_conversation_name` are still individual constructor arguments and properties on both classes (unchanged) — `HistoryConfig` is an additive `history_config` property grouping the three (recomputed on every read, so `history_manager`'s public setter stays immediately visible through it). `chat/execution.py`'s `_create_llm_task_core` now builds the inner task's history knobs via `dataclasses.replace(llm_chat_task.history_config, ...)` instead of listing each field individually — the same three fields still get explicit chat-specific overrides there (the inner task's conversation identity is always the active session, never `LLMChatTask`'s own setting), including a newly-explicit `render_conversation_name=True` that was previously an implicit default; behavior is unchanged.
- **Documentation: the `HookType.AGENT` registration seam is now traced, and the shipped agent-hook example no longer just duplicates the built-in judge** (`docs/advanced-topics/llm-chat-lifecycle.md`, `docs/advanced-topics/hooks.md`, `examples/llm-hooks/.zrb/hooks.json`, `examples/llm-hooks/README.md`): the previous entry's `hook/agent_hook_registry.py` seam was already documented file-by-file in code, but nothing walked the full call path (hook factory → `HookEvent.STOP` → registry lookup → import-side-effect registration → `run_llm_hook`) in one place, so debugging the built-in journal-compliance judge meant discovering that path cold. `llm-chat-lifecycle.md` gained a "Tracing an AGENT-type hook" subsection doing exactly that. Separately, `examples/llm-hooks/.zrb/hooks.json`'s `journal-compliance-judge-example` entry was a byte-for-byte copy of the built-in `Stop` hook and taught nothing beyond it; it's now `security-review-agent-example`, a `PreToolUse` agent hook matching the distinct use case `hooks.md`'s own "Agent Hooks" section already sketched but never shipped as a runnable file.

## 2.67.3 (August 29, 2026)

- **Breaking/Security (ADR-0087): the web server now binds to loopback (`127.0.0.1`) by default instead of `0.0.0.0`** (`src/zrb/config/mixins/web.py` (`WEB_HTTP_HOST`), `src/zrb/runner/cli.py` (`start_server`, `_warn_if_insecure_bind`), `docs/advanced-topics/web-ui.md`, `docs/configuration/env-vars.md`): `start_server` hardcoded `host="0.0.0.0"` with no way to change it, so — combined with `WEB_AUTH_ENABLED` defaulting off and a documented default super-admin password — the "local development" server was in fact reachable from any interface able to run shell commands and user-defined tasks unauthenticated. A deployment that intentionally exposes the server still works, just requires setting the new `ZRB_WEB_HTTP_HOST` explicitly; either way, a non-loopback bind now prints a stderr warning naming whichever risk it still carries (auth off, or auth on with `WEB_SUPER_ADMIN_PASSWORD`/`WEB_SECRET_KEY` still at their default value). No alias, since there was no prior config key for this — an existing deployment relying on the implicit `0.0.0.0` bind must set `ZRB_WEB_HTTP_HOST` after upgrading.
- **Security: a continued live sub-agent session can no longer drift to broader authority than its delegation was granted** (`src/zrb/llm/agent/run/authority_snapshot.py`, `src/zrb/llm/agent/subagent/live_session.py`, `src/zrb/llm/agent/run/deferred_calls.py`, ADR-0069): `run_agent`'s permission-policy/yolo/sandbox inheritance relies on `asyncio.create_task` copying the current `ContextVar` context — correct only when the detached task is spawned while the originating scope is still bound. A human's follow-up message to an already-finished delegation (`live_session.py`'s `_continue_live_session`) spawns long after that scope exited, so it previously picked up whatever authority happened to be ambient at that later, unrelated point instead of what was actually granted. `LiveSubAgentSessionRegistry.add_session` now captures an `AuthoritySnapshot` at creation time, while the delegating turn's scope is still bound, and every later continuation passes its `permission_policy`/`yolo`/`sandbox_policy` explicitly to `run_agent()` instead of relying on ambient inheritance.
- **Fix: a web chat session's background `Shell` processes are now torn down when that session ends, and can no longer be reached from a different session** (`src/zrb/llm/tool/ambient_state.py` (`get_current_chat_session_id`, `get_session_ownership_key`), `src/zrb/llm/tool/shell_background.py` (`cancel_for_session`, `force_kill_all`), `src/zrb/runner/chat/chat_session_manager.py`, `src/zrb/runner/chat/chat_session_runner.py`, `src/zrb/llm/tool/delegate.py`, `src/zrb/llm/tool/delegate_background.py`, `src/zrb/llm/ui/default/{agent_picker.py,confirmation.py,keybindings.py,output.py}`): a background process a session started (directly or via a delegated sub-agent) previously outlived that session with no cleanup path, and the client-supplied display session name it and every live-sub-agent-session lookup keyed off was never guaranteed unique across concurrent web chat sessions, so two sessions sharing a display name could reach into each other's running sub-agents. Both are now keyed by `ChatSessionManager`'s own unique session id (bound around each message drive via a new `current_chat_session_id` ContextVar, `get_session_ownership_key` falling back to the display name for the interactive CLI, which has no such id): `ChatSessionManager.remove_session` now calls `cancel_for_session` to kill just that session's own background processes, and every live-sub-agent-session lookup in the TUI resolves through the same ownership key. A new `atexit`-registered `force_kill_all` also SIGKILLs any still-running background process at interpreter shutdown, when the event loop that owned its transport may already be closed.
- **Refactor: the last real import cycle in `zrb.llm.tool`/`zrb.llm.tool_call` is closed** (`src/zrb/llm/tool/__init__.py`, `src/zrb/llm/tool_call/__init__.py`, `src/zrb/llm/agent/subagent/{definition.py,manager.py,manager_loading.py,tool_resolver.py}`, `src/zrb/llm/tool/{web.py,file_analyze.py}`, `src/zrb/llm/tool_call/response_handler/default.py`, `src/zrb/llm/hook/turn_evidence.py`, `src/zrb/llm/common_tools.py`): `SubAgentDefinition` moved out of `agent/subagent/manager.py` into a new dependency-free leaf module (`agent/subagent/definition.py`), so `manager_loading.py` (which `manager.py` itself imports) can import it directly instead of reaching back into `manager.py` mid-load — the actual circular dependency `zrb.llm.tool/__init__.py` had briefly gone fully empty to sidestep. It's re-exporting again now, verified empirically (an `import zrb` from every plausible entry point must not raise) rather than by inspection, for every tool with no module-level dependency on `zrb.llm.agent`; `web.py`'s agent-dependent summarization step moved to a function-scoped import instead. **Breaking:** `analyze_code`, `create_delegate_to_agent_tool`, and `create_search_agent_tool` are no longer importable from `zrb.llm.tool` — those two modules delegate to the agent run loop for more than one call path each, so they stay import-from-their-own-module only (`from zrb.llm.tool.code import analyze_code`, `from zrb.llm.tool.delegate import create_delegate_to_agent_tool, create_search_agent_tool`). `tool_call/__init__.py` similarly no longer re-exports `replace_in_file_validation_policy` (import it from `zrb.llm.tool_call.tool_policy.replace_in_file_validation` instead) — it was the one tool-policy module reaching into `zrb.llm.tool`, and re-exporting it from `tool_call` closed a cycle back through `common_tools.py`.
- **Refactor: `BaseUI`'s persona-swap, voice-dictation, token-usage, and confirmation-queue state are now their own parts** (`src/zrb/llm/ui/base/{ui.py,confirmation_state.py,persona_state.py,usage.py,voice_state.py}`): each was a handful of attributes living directly on `BaseUI` alongside everything else; they're now `BaseUIConfirmationState`/`BaseUIPersonaState`/`BaseUIUsage`/`BaseUIVoiceState`, composed in as `self._base_confirmation`/`self._base_persona`/`self._base_usage`/`self._base_voice` per the `_base_<aspect>` convention `BaseTask` already used, reached only through `BaseUI`'s existing public properties. - **Tests: five new architecture fitness-function tests enforce conventions AGENTS.md already documented but nothing previously checked mechanically** (`test/architecture/{test_boundaries.py,test_circular_import_allowlist.py,test_complexity_ratchet.py,test_facade_size_budget.py,test_private_test_access_ratchet.py}`): `test_boundaries.py` checks that a part reaches its owner/sibling only through a public property (never a raw `_private` attribute) and that business logic stays free of web/TUI framework imports; `test_circular_import_allowlist.py` fails if a new `# lazy: circular` deferral lands without being declared in its allowlist (every prior instance in the tree turned out to be a stale comment, a mislabeled heavy-dependency deferral, or a fixable eager re-export — none an irreducible cycle); `test_complexity_ratchet.py` caps flake8's mccabe score at 22 and radon's per-function score at 20 (registration/factory functions with trivial nested handlers are tagged `# noqa: C901` instead of inflating the mccabe ratchet); `test_facade_size_budget.py` caps `llm/ui/base/ui.py`, `llm/task/chat/task.py`, and `llm/task/llm_task.py` at a specific line count so a part extraction is required to actually shrink its owner; `test_private_test_access_ratchet.py` caps test-to-test private-attribute reaches at a documented baseline of 5.
