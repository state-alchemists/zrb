## 2.53.2a2 (August 4, 2026)

- **Fix: the Turn Sequence never asked the model to check the premise it was about to investigate from** (`src/zrb/llm/prompt/markdown/workflow.md`, `test/llm/prompt/test_section_composition.py`): the preconditions ran First look → Activate skills → Read docs → Search journal — turn-start steps about *what work* the turn needs, none about *what the work assumes*. Observed consequence: asked to explain a tool-behaviour question with the working directory held constant, a model adopted a wrong premise about which repo the tool had executed in, ran a ~15-call investigation under it, and the investigation stood on the assumption until the user corrected it in prose. Nothing in the Turn Sequence had invited the check, and the Working Loop's uncertainty ladder — which does contain the ask-versus-assume rule — never engaged, because the ladder fires on a *tool result*, not on a premise adopted before the first call. Step 1 is now **Check the premise**: name the load-bearing assumptions before starting — load-bearing meaning the plan differs materially under its alternatives — and when one is ambiguous, no tool settles it (it is the user's intent, not repo state), and guessing wrong is expensive, ask **one** targeted question naming the alternatives; when guessing wrong is cheap, name the assumption and proceed. The step is unconditional (no `requires:` block) and numbered first, so no `LLM_INCLUDE_SECTIONS` config can drop it and nothing else runs before it. Deliberately not duplicated elsewhere: `mandate.md` already carries the principle ("Under uncertainty: evidence > assumption. Still uncertain after that? Ask rather than guess") — the Turn Sequence now supplies the turn-level moment that actually gates an investigation — and `AskUserQuestion`'s `when_to_use` stays the tool-level trigger. The conditional journal step remains last in the run, preserving the no-numbered-gap invariant the 2.53.0 fix established; the existing subset test still walks every composed prompt, and a new test pins the premise check as step 1 and asserts it carries no `requires:` block.
