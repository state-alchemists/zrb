## 2.53.2a2 (August 4, 2026)

- **Fix: the Turn Sequence never asked the model to check the premise it was about to investigate from** (`src/zrb/llm/prompt/markdown/workflow.md`, `test/llm/prompt/test_section_composition.py`): the preconditions ran First look → Activate skills → Read docs → Search journal — turn-start steps about *what work* the turn needs, none about *what the work assumes*. Observed consequence: asked to explain a tool-behaviour question with the working directory held constant, a model adopted a wrong premise about which repo the tool had executed in, ran a ~15-call investigation under it, and the investigation stood on the assumption until the user corrected it in prose. Nothing in the Turn Sequence had invited the check, and the Working Loop's uncertainty ladder — which does contain the ask-versus-assume rule — never engaged, because the ladder fires on a *tool result*, not on a premise adopted before the first call. Step 1 is now **Check the premise**: name the load-bearing assumptions before starting — load-bearing meaning the plan differs materially under its alternatives — and when one is ambiguous, no tool settles it (it is the user's intent, not repo state), and guessing wrong is expensive, ask **one** targeted question naming the alternatives; when guessing wrong is cheap, name the assumption and proceed. The step closes on *"do this before the investigation rather than partway through it — a premise surfaced late invalidates everything built on it"*, replacing a first draft's *"never run a full investigation on an assumed premise"*, which set no threshold: the incident behind the rule ran ~15 calls, and nothing said whether three would have counted. The rule is about ordering, not volume, so it now says so. The step is unconditional (no `requires:` block) and numbered first, so no `LLM_INCLUDE_SECTIONS` config can drop it and nothing else runs before it. Deliberately not duplicated elsewhere: the step itself states the ask-versus-assume call at turn level, the Working Loop's uncertainty ladder states it for a premise that a tool result can still settle, and `AskUserQuestion`'s `when_to_use` stays the tool-level trigger — `mandate.md`'s one-line restatement of the same principle was dropped in this release as the third copy. The conditional journal step remains last in the run, preserving the no-numbered-gap invariant the 2.53.0 fix established; the existing subset test still walks every composed prompt, and a new test pins the premise check as step 1 and asserts it carries no `requires:` block.
- **Fix: the Working Loop table contradicted the sentence introducing it** (`src/zrb/llm/prompt/markdown/workflow.md`): the intro read *"**Verify always runs before you reply**"* while the table's `Loop steps to run` column gave `none` for a conversational turn — both cannot hold, and a model resolving the clash either way loses a rule. The column is now `Loop steps before Verify`, which is what it always meant, and the intro states that the `Turn Sequence` preconditions have already run, so `none` describes the loop rather than the turn.
- **Fix: skill activation was ordered before the step that decides which skills apply** (`src/zrb/llm/prompt/markdown/workflow.md`): `Turn Sequence` said *"Do these first, in this order… 2. **Activate skills**"*, placing activation ahead of the Working Loop — but the loop opens by framing the turn, and Skill Activation matches *"by **the work the turn requires**"*, so step 2 depended on a step the prompt scheduled after it. A recorded session resolved the circularity by ignoring the stated order, activating `core-research` and `core-writing` and reasoning about the table row in one block. Framing is now the explicit first act of the turn and the preconditions follow from it, ahead of the numbered run that the premise check above opens. That intro calls the preconditions *"silent"* and *"not deliverables"*, which step 1 can contradict — asking the user a question is neither, and it ends the turn — so it carries an explicit carve-out naming step 1 as the one step that may end the turn in a question. `First look` also lost the ambiguous *"Nothing else precedes step 3"* — the constraint is now stated as what it means: read what the framing needs and no more, the rest waits for skill activation. `Read project documentation` separately said *"code-touching turns only"* against its own detail section's *"code, files, conventions, or tasks"* — a turn about conventions touches no code but is in scope; the summary now matches the detail.
- **Fix: four precedence statements that never composed into an order** (`src/zrb/llm/prompt/markdown/mandate.md`, `src/zrb/llm/prompt/markdown/workflow.md`): the Operating Rules preamble gave precedence to *"a later section [that] covers one area in detail"*, Priority 5 gave `AGENTS.md` style and conventions, Skill Activation gave activated skills authority over the Working Loop but not the safety rules, and a trailing line gave it to the narrower rule — four rankings with no resolution between them. Taken literally the preamble made Journal Protocol, a later and more detailed section, outrank the Priority Order's timing. The preamble now states one ladder — Priority Order, then explicit user instructions, then `AGENTS.md` / `CLAUDE.md`, then the Verify gate, then an activated skill, then the rest of the prompt — with detail-beats-passing-mention and narrower-beats-broader as the within-prompt tiebreak. The trailing equal-rank line and Skill Activation's partial restatement were folded into it. The Verify gate is named explicitly because a first draft of the ladder omitted it: Skill Activation says a skill supersedes the Working Loop but **never** the safety rules or the Verify gate, while the ladder placed an activated skill above *"the rest of this prompt"* — which contains `Verify Before Done`. The two sentences cross-reference each other, so a model following the pointer landed on the contradiction rather than the order.
- **Fix: `6. Memory` was a task obligation living inside a conflict-precedence list** (`src/zrb/llm/prompt/markdown/mandate.md`): the list is explicitly *"**precedence, not sequence**: when two collide the lower number wins"*, and items 1–5 are all conflict rules, but *"a durable finding is recorded before the turn ends"* is a thing to do, not a thing that can lose a collision — "Memory loses to Scope" decodes to nothing. Because the item sat inside a `<!--requires:journal_mandate-->` block it also rendered with a blank line detaching it from the list it was numbered into. It is now an unnumbered line after the list, pointing at Journal Protocol, so dropping the `journal_mandate` section can no longer leave a numbering gap.
- **Improvement: the delegate-or-not decision had no guidance at the point it is made** (`src/zrb/llm/prompt/markdown/workflow.md`): every mention of delegation lived in `# Tool Usage Guide`, the last section of the prompt — a catalogue consulted once you have decided *which tool to reach for*, not *whether to do the work yourself*. A recorded run asked to research Kubernetes, Nomad and Docker Swarm and then compare them ran 6 `WebSearch` and 4 `WebFetch` calls inline; delegation appears in none of its six reasoning traces, so it was never rejected, only never considered. Main context grew 11,980 → 50,100 tokens as page text accumulated and was not referenced again, ~165k input tokens across the run. `core-research`'s *"Offload massive or speculative exploration to an isolated sub-agent"* (`SKILL.md:24`) was active and did not fire — three named topics do not read as massive or speculative. Routing guidance now sits immediately after the Working Loop table, in the read path the trace actually walked, with three triggers matching the harness's own rule: a named agent fits the work, the steps are independent, or the step reads far more than it reports. It carries two clamps — set the comparison axes yourself and give every sub-agent the same list, since reports built on different frames cannot be reconciled afterwards; and keep whatever you must quote verbatim or reason over step by step. Its timing line reads *"this is a framing decision: make it before the reading starts, not once it has landed"* rather than the first draft's *"decide while framing the turn"*, which pointed back at a moment that has already passed by the time the block is read — framing now opens the Turn Sequence, and the block sits inside the Working Loop.
- **Improvement: `tool_guidance` restated tool schemas that ship in the same request** (`src/zrb/llm/common_tools.py`): the file's own rule at the top of `_STATIC_TOOL_GUIDANCE` says an entry answers *"when do I reach for THIS tool instead of THAT one?"* and *"anything that doesn't reduce to a cross-tool choice belongs in the docstring"* — several entries had drifted past it. `GetDelegationResult`'s whole `key_rule` (`wait=N`, `kill=True`, handle consumption) was verbatim in its docstring; `DelegateToAgent` restated the schema's `FAN OUT` line, its `deliverable`/`non_goals` semantics and the `AVAILABLE AGENTS` roster; `DelegateToAgentBackground` restated the same two; `Read` carried a third copy of *"never count lines yourself"* already in `persona.md` and in `read_file`'s docstring. Reciprocal routing pairs (LS↔Glob↔Grep, WebSearch↔WebFetch, AnalyzeCode↔AnalyzeFile) each stated one choice from both sides, and `RM`/`MV` repeated the reference-hunting rule that Priority 4 already states for all three of rename, move and delete. `EnterPlanMode` reproduced the Working Loop's escalation triggers near-verbatim, and both it and `AskUserQuestion` carried *"skip when non-interactive"* text that can never render — the tool factories register them only under `_resolve_interactive(ctx)`, and the `tool_names` filter drops guidance for unregistered tools. `# Tool Usage Guide` went 1,321 → 1,194 tokens, `## Delegation` 490 → 362.
- **Fix: "an extra skill is cheap" was false by an order of magnitude** (`src/zrb/llm/prompt/markdown/workflow.md`): the line encouraging activation under uncertainty priced a spare skill at nothing, but activation returns the skill's full content into history — measured, `core-journaling` is 2,633 tokens, `core-coding` 1,519, `core-writing` 856, `core-design` 610, `core-research` 575. Two speculative activations cost more than the entire Journal Protocol section. It now reads *"a spare skill costs tokens, a missing one costs the method"*, which keeps the lean-toward-activating steer on a cost model that is true.
- **Improvement: compression in the always-on sections** (`src/zrb/llm/prompt/markdown/mandate.md`, `src/zrb/llm/prompt/markdown/journal_mandate.md`, `src/zrb/llm/prompt/markdown/examples.md`, `src/zrb/llm/prompt/markdown/examples.mini.md`): `mandate` carried *"Under uncertainty: evidence > assumption… **Ask rather than guess**"*, a lossy duplicate of the three-step uncertainty ladder in `workflow`, and a one-line `## Session Context` heading with its own rules; both were folded away. Journal Protocol's *"When to write"* and *"Writes are silent"* spent roughly 200 tokens explaining turn mechanics and were halved without losing a rule. `examples.md` lost a clause of meta-commentary, mirrored into `examples.mini.md` because `test_get_prompt_mini_profile_uses_variant_when_present` asserts the variant is a strict `startswith` prefix of the base. `AskUserQuestion`'s `key_rule` was *"Do not ask for permission to do obvious things"* — a bare negation whose only content is the behavior it suppresses, and redundant with the positive condition in its own `when_to_use`; it is now *"Make obvious calls yourself; reserve this for genuine ambiguity."* The shipped system prompt measures 7,370 → 7,627 tokens: the guidance dedup and prose trims (`# Tool Usage Guide` alone 1,321 → 1,194) partly funded this release's net additions — the premise check, the delegation routing and the precedence ladder — which together outweigh them.
- **Fix: `Edit` could silently write `Read`'s line numbers into a file** (`src/zrb/llm/tool/file_edit.py`, `test/llm/tool/test_file.py`): 2.53.2a1 added a last-resort path that strips `Read`'s `cat -n` prefix when `old_text` was copied verbatim out of numbered output. `_strip_read_line_numbers` returns `None` unless *every* line carries the prefix — correct for `old_text`, where a partial match means the guess was wrong and mangling it would edit the wrong region, but inverted for `new_text`, where `None` meant "leave the prefixes in". The common edit rewrites one line, so the replacement arrives with prefixes on the copied lines and none on the rewritten one; the all-or-nothing rule then declined to strip and wrote `     3\tsome text` into the file, reported as `Successfully updated`. Reproduced on a markdown file: `# Title\n\nsome text\nmore text\n` became `# Title\n\n     3\tsome text\nCHANGED text\n`. On a `.py` file the post-write diagnostics catch it (5 pyright errors); on markdown, YAML, JSON, or plain text nothing does, so the corruption ships. `new_text` now strips per line via a separate `_strip_prefix_per_line`, which is safe precisely where it is called: `old_text` has already *proved* the model was copying out of `Read`, and a file genuinely containing `cat -n` text matched on the exact path and never reached this branch. The existing test covered only the all-prefixed case; the mixed case is now pinned.
- **Fix: every background delegation built its sub-agent twice, the first time on the caller's turn** (`src/zrb/llm/tool/delegate_background.py`, `test/llm/tool/test_delegate_background.py`): the name check added in 2.53.2a1 called `sub_agent_manager.create_agent(agent_name)` and discarded the result, then `_run_agent_task` called it again inside the coroutine. `create_agent` (`agent/subagent/manager.py:217`) runs `ensure_common_tools`, every registered tool factory, `resolve_model`, guidance composition, and full prompt assembly — so the validation paid for a complete agent construction, synchronously, before detaching. That is the wait `DelegateToAgentBackground` exists to avoid. It now calls `get_agent_definition` (`manager.py:207`), which is the same lookup `create_agent` itself uses to decide its `None` return, so the check is exactly as strict at a fraction of the cost. A test asserts `create_agent` is never called on the validation path.
- **Fix: `AVAILABLE AGENTS` pinned an 8-space indent on the background-delegate tool description** (`src/zrb/llm/tool/delegate_background.py`): `agent_roster_doc` returns unindented lines, and appending them under an 8-space docstring makes `inspect.cleandoc` compute a common indent of zero — so nothing dedents and the whole description renders with its original indentation, the roster header floating at `        AVAILABLE AGENTS:`. The docstring is now normalized with `cleandoc` before the roster is joined.
- **Fix: `ZRB_LLM_JOURNAL_INDEX_MAX_CHARS=0` uncapped the injection instead of disabling it** (`src/zrb/llm/prompt/live_context.py`, `src/zrb/config/mixins/llm_content.py`, `test/llm/prompt/test_live_context.py`): the guard read `if limit > 0`, so zero fell through to "inject the whole file". `EnvField` also falls back to `0` on an unparseable value, which meant a typo'd env var silently removed the cap rather than failing — verified: `ZRB_LLM_JOURNAL_INDEX_MAX_CHARS="not-an-int"` resolves to `0`. Zero now suppresses the injection (`max 0 chars` reading as "nothing", which is what a user setting it means), and a negative value is the explicit uncapped escape hatch. The `doc` string states both.
- **Fix: `AnalyzeFile` spent part of its analysis window on line numbers the sub-agent is told to ignore** (`src/zrb/llm/tool/file_analyze.py`): `analyze_file` reads through the numbered `read_file` and then clips at `LLM_FILE_ANALYSIS_TOKEN_THRESHOLD * 4`. `read_file` deliberately measures its own cap against file content so the header's char count is honest, but this second clip ran on the numbered text — billing ~13% of the extractor's window (the overhead figure measured when numbering shipped) to characters that are not in the file. A local `_clip_numbered` now budgets each line by its payload, discounting the prefix; a line with no tab (the `[File: ...]` header, unnumbered PDF text) counts at full length.
- **Fix: the prompt carried two precedence systems that disagreed about `AGENTS.md`** (`src/zrb/llm/prompt/markdown/mandate.md`): An earlier draft in this release introduced an "Across sources" chain placing `AGENTS.md` *below* the entire Priority Order, while Priority 5 placed it *inside* the ladder at rank 5 — a model resolving one against the other has no fixed point. There is now a single eight-rank ladder, and the preamble states that nothing outside it outranks anything in it. Explicit user instruction enters as rank 3 (above quality and scope, below safety and destructive-action confirmation), project conventions move to 6 with the style/safety split stated as a clause rather than a separate chain, an activated skill's method becomes 7, and the rest of the prompt 8. The within-prompt tiebreaks — detail beats passing mention, narrower beats broader, content survives a brevity rule — fold into the same preamble.
- **Fix: the Turn Sequence could not be executed as written** (`src/zrb/llm/prompt/markdown/workflow.md`): An earlier draft in this release said *"**Frame the turn first** against the Working Loop table below"*, but step 2 was *"**First look** — only when you cannot frame the turn without one"* — framing required the look, and the look was gated on framing. Framing is now step 3, an explicit numbered step between the first look and skill activation, so the list runs start to finish with no forward dependency: check the premise (from the user's words alone, needing no tools) → first look → frame → activate skills → read project docs → search the journal. The premise check stays step 1 and unconditional, as `test_premise_check_is_first_and_unconditional` requires, and the conditional journal step stays last in the numbered run so no `LLM_INCLUDE_SECTIONS` subset leaves a gap.
- **Fix: the project-documentation trigger was grammatically ambiguous and cost ~10,300 tokens on a greeting** (`src/zrb/llm/prompt/markdown/workflow.md`): *"On the **first turn in a session** that touches the project's code, files, conventions, or tasks"* parses either as *(the first turn) if it touches* or *(the first turn that touches)*. A recorded session opened with `Hi my name is Go Frendi, you call me Go` and the model read `AGENTS.md`, `CLAUDE.md`, and `README.md` in full — input tokens 12,283 → 22,572 — with its own trace giving the reason as *"this is the first turn touching the project"*. It had already framed the turn as conversational. The section now leads *"**The trigger is the work, not the turn number**"* and states that being early in the session is not a trigger and being in a project directory is not a trigger, naming a greeting and a general knowledge question as non-qualifying however new the session is. The closing line changed from restating the negative case to the one thing that was missing: once read, they are read for the session.
- **Fix: a document deliverable defaulted to disk, and the write was rejected** (`src/zrb/llm/prompt/markdown/workflow.md`): the Working Loop table lists `"compare…"` under a conversational turn whose deliverable is *the answer in your reply*, while `core-design`'s description claims *"trade-off analysis"* as its own — and both directive rows hardcoded the deliverable as *"on disk"*. Asked to `Research about kubernetes, nomad, and docker swarm, then create a trade off analysis`, a model took a directive row and wrote `orchestration-tradeoff-analysis.md` into the zrb repository root, an unrelated document in a project it had nothing to do with. The user denied the write with *"Just show the markdown, no need to write to file"*; the model then regenerated the same content inline, ~2,900 output tokens of rework on top of the 4,787 that produced the denied call. Its trace shows the ambiguity was seen and dismissed: *"The user didn't specify a location… let me not overthink the location."* Both directive rows now say the change lands *where the deliverable rule sends it*, and that rule is stated below the table: producing a document is not the same as writing a file, the default destination is the reply, and disk is the destination only when the user named a path or filename, asked you to add to something already on disk, or the artifact is only useful as a file. **Execute** was reworded to match.
- **Improvement: one threshold for ask-versus-assume, replacing three that disagreed** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm/common_tools.py`): the same decision was priced three ways — *"guessing wrong is expensive"* in the premise check, *"the wrong pick would waste significant work"* in `AskUserQuestion`'s `when_to_use`, and *"the action is cheap to undo"* in the uncertainty ladder — and none of them said that writing a new file into the user's repository is not cheap, which is exactly the call the denied write got wrong. A `### Cost of guessing wrong` block now states it once: ask when the wrong pick wastes work already done or puts something on the user's disk or an external system that they then have to undo, assume-and-say-so when the pick is cheap to reverse and confined to your reply, and never silently — a proceed-on-assumption always names the assumption. The uncertainty ladder collapses from three steps to two, since its old steps 2 and 3 were the two sides of this test.
- **Fix: the Journal Protocol contradicted `core-journaling` about creating directories, and the HUD template never loaded** (`src/zrb/llm/prompt/markdown/journal_mandate.md`, `src/zrb/llm_plugin/core_skills/core-journaling/SKILL.md`): the skill's description triggered on *"creating a directory"* while *"The everyday shape is one line"* described creating `activity-log/YYYY/YYYY-MM/YYYY-MM-DD.md` as *"the whole ordinary path, and one `Write` covers it"* — the everyday path creates three directories on a fresh journal. A recorded first-run session took the everyday path, never activated the skill, and so never read `templates/journal-index.md` (shipped one release earlier): the resulting root index carried only a `## User` heading, with no `## Directories`, no `activity-log/index.md`, no `2026/index.md`, and no `2026-08/index.md` — every directory it had just created is an orphan by the skill's own lint rule. The protocol now names two cases that are *not* the everyday path and require activation first: the journal is empty or has no root index, or the entry must be findable by topic. Creating today's file inside an already-structured `activity-log/` stays the everyday path, stated explicitly so the carve-out does not swallow the rule. The skill's description drops the bare *"creating a directory"* for *"builds or reshapes the journal's structure"* plus *"the first write into an empty journal is always structural"*.
- **Fix: creating the journal tree was buried as an exception inside four repetitions of "silent"** (`src/zrb/llm/prompt/markdown/journal_mandate.md`): An earlier draft in this release added *"creating the journal tree… gets its usual one line"* directly beneath *"**Writes are silent.** Never announce one, before or after"*, and pointed at a *"usual"* line that no nearby text defines. In the recorded session the model created three directories and two files and closed with `Got it, Go. What are you working on?` — the silence rule won, as the stronger and more repeated of the two. The two cases are now separate claims rather than a rule and its exception: appending to an existing journal is silent, creating the tree is a filesystem change like any other and closes with one sentence naming what was created and where. The sentence no longer depends on `persona` being present in the composition.
- **Fix: the highest-priority journal write triggered on introductions only** (`src/zrb/llm/prompt/markdown/journal_mandate.md`): *"Who the user is, or a preference or convention they stated"* is rank one in the write list, and every example under it is introduction-shaped. In the recorded session the model correctly logged `call me Go` on turn 1, then on turn 2 received *"Just show the markdown, no need to write to file"* as a tool-call denial and recorded nothing — the most reusable fact the session produced, arriving in the shape of feedback rather than a statement. The rule now says a preference is defined by what it constrains, not by how it arrived, names a correction, a rejected tool call, an edit to your output, and an aside as equally qualifying, and gives the test: *would a future session do this differently knowing it?*
- **Fix: every switchable section now reads whole on its own** (`src/zrb/llm/prompt/markdown/git_mandate.md`, `src/zrb/llm/common_tools.py`, `test/llm/prompt/test_section_composition.py`): sections toggle independently through `LLM_INCLUDE_SECTIONS`, so a pointer at a sibling reads fine in the default composition and dangles the moment someone trims the list. `git_mandate.md`'s heading was `# Git Rules (Supplement to Operating Rules)`, naming a section that may not be present; `EnterPlanMode`'s `when_to_use` deferred to *"The Working Loop's escalation triggers"* and `ActivateSkill`'s to *"see Skill Activation table"*. Each now states its rule in place. `OWNED_VOCABULARY` in the subset test grew from three owners to six — adding `Priority Order`, `Operating Rules`, `Turn Sequence`, `Cost of guessing wrong`, `Response Calibration`, and `Requires Approval` — so the brute-force walk over all 63 section subsets catches the next one. A new `test_tool_guidance_is_self_contained` composes with `tool_guidance` as the only section and asserts no foreign vocabulary survives; that section is built in Python, so `filter_requires` never sees it and a `<!--requires:-->` guard is not available to it.
- **Improvement: delegation triggers stated once per section instead of two divergent lists** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm/common_tools.py`): the Working Loop gave three triggers (a named agent fits, the steps are independent, the step reads more than it reports) and `DelegateToAgent`'s `when_to_use` gave two different ones (reads more than it reports, your own context is the problem) — same decision, non-identical rules, and *"a named agent fits the work"* appeared only in the prompt while *"your own context is the problem"* appeared only in the tool schema. Both now carry all four, phrased for their own context and neither pointing at the other, since either section can be switched off.
- **Improvement: `Shell` guidance names the file-inspection commands** (`src/zrb/llm/common_tools.py`): the rule said *"For file I/O, use Read/Write/Edit/Grep/RM/MV — not Shell"*, which a model reasonably reads as covering writes and not lookups. The recorded session ran `test -f …/index.md` and `test -d …` as two separate `Shell` calls, 12 seconds of round trips where one `LS` answers both. The rule now covers *anything about files*, names `test -f`, `ls`, `cat`, `head`, `find`, and `wc -l` as the tool calls they should be, and states that one `LS` answers what two `test` invocations would.
- **Improvement: the always-on sections were rewritten for compactness and scanning** (`src/zrb/llm/prompt/markdown/persona.md`, `mandate.md`, `workflow.md`, `journal_mandate.md`, `src/zrb/llm/common_tools.py`): the consolidation above removed the contradictions but grew the text — self-containment means restating a rule rather than pointing at it, so the structural fix cost ~422 tokens. Three things were cut, none of them rules. **Meta-commentary explaining the prompt's own machinery**: *"they are preconditions, not deliverables"*, *"The single precedence ladder — everything that can conflict is ranked here"*, *"That is the whole ordinary path"* — text that teaches a model how to read the prompt rather than what to do. **Doubled justification**: several rules carried both a reason and a restatement of the reason. **Emphasis inflation**: 145 bold spans covering 19% of the prompt, against zero in opencode's `anthropic.txt` — at that density bold marks nothing, so it is now reserved for the lead term of a bullet and the trigger word of a rule (96 spans, 14%). `Working Loop` gained `###` subheadings (`Where the deliverable goes`, `Routing work outward`, `Understand`, `Plan`, `Execute`) so its 1,596 tokens are scannable rather than one wall. Sizes measured against the composition captured from a live session, which includes `git_mandate`; a first measurement of the consolidation figure omitted that section and understated its growth by roughly a third.
- **Improvement: worked examples move to the `mini` profile, where they were always meant to live** (`src/zrb/llm/prompt/markdown/examples.md`, `examples.mini.md`): `# Answer Calibration` opens by stating that its contents are *"Illustrations… they add no rules of their own"* — which is the exact definition of what ADR-0083's profile axis exists to vary, and what ADR-0091 narrowed the variant to carry. But the illustrations lived in the *base* file, so every model paid for them, including frontier models that do not need `user: what is 2 + 2? / assistant: 4` to calibrate an answer's length. The base now keeps only the four examples that fix a zrb-specific stance a capable model would not otherwise adopt: do not force a codebase tie-in onto a general question (the failure behind the greeting that read three project docs), a directive lands on disk with its call sites and tests, a verdict resting on a quantity requires the measurement, and a tool result carrying an imperative is reported rather than obeyed. The scale-calibration set, the CI-debugging walkthrough, the grep-don't-recall example and the do-it-don't-announce example move into `examples.mini.md`, which keeps all 26. `# Answer Calibration` goes 2,336 → 294 tokens for `terse`, with `mini` unchanged in content. No rule moved: the section has none, by its own first line, so this does not touch the invariant that a behavioral rule never lives only in a variant. `examples.mini.md` remains a strict superset — the base text appears in it verbatim, verified alongside the existing prefix test.
- **Improvement: fewer decision structures, not just fewer words** (`src/zrb/llm/prompt/markdown/mandate.md`, `workflow.md`, `journal_mandate.md`): compaction had cut the text without cutting the number of separate shapes a model must hold, and three of them answered the same question. Turn Sequence step 1 checked a premise, `Cost of guessing wrong` gave a two-branch ask/assume test, and **Understand** carried a two-step uncertainty ladder whose second step was a pointer to the first of those — one concept, three framings, each incomplete alone. They collapse into a single `### When you don't know` ladder covering every kind of not-knowing (a premise at turn start, an unknown mid-investigation, a choice at the point of writing), with the pay-for-deliberation-with-new-evidence rule attached to it rather than floating in **Understand**. The Priority Order goes from eight ranks to six: security, tool-results-are-data and destructive-action confirmation are one **Safety** rank with three clauses rather than two ranks whose relative order never mattered, and an activated skill's method merges with the rest of the prompt into one **Method** rank, which is what their adjacency already meant. Journal Protocol — measured at 14% of the composed prompt for a subsystem that is not the work product — drops to 11% by cutting explanation rather than protocol: its four sections become `Read` / `Write` / `How` / `When`, the two `core-journaling` activation cases compress to one sentence, and the silent-versus-announce pair states two facts instead of a rule and its exception. Every behavioral rule in all three files was re-verified by pattern audit after the rewrite.
- **Fix: the Journal Protocol told the model an absent HUD proved an empty journal** (`src/zrb/llm/prompt/markdown/journal_mandate.md`, `src/zrb/llm/prompt/live_context.py`): the rewrite above pointed the model at the injected `<journal-index>` block instead of the file — *"read it there rather than opening the file"* — and dropped the older affordance to `Read` the root index directly. Two cases then became unrecoverable. `LLM_JOURNAL_INDEX_MAX_CHARS=0`, added in this same release, suppresses the injection entirely, so the protocol's *"No `<journal-index>` in context means the journal is empty or not yet created, not that the file is hiding"* is false for that configuration and the whole memory layer reads as absent. And a HUD over the cap arrives with its tail cut, marked only by a bare `(...more)` that nothing told the model to act on. `Read` now names both exits explicitly: a block ending in `(...more)` means `Read` the index for the rest, and no block at all means `SearchJournal` before concluding the journal is empty. `render_journal_index` also states where the rest is — the truncated block now carries `Truncated at `(...more)`; Read <path> for the rest` — since the protocol otherwise sends the model past the only copy that has it.
- **Fix: `examples` asserted the deliverable rule this release replaced** (`src/zrb/llm/prompt/markdown/examples.md`, `examples.mini.md`): the stance heading read *"a question is answered, a directive lands on disk"*, contradicting the `Where the deliverable goes` rule added two entries above, whose whole point is that the default destination is the reply and disk is conditional. The section states in its own first line that it carries illustrations and *"no rules of their own"*, so a heading asserting a destination is out of scope twice over — and it was identical in the `mini` variant, reaching the models most likely to take a slogan over a qualified rule. It is now *"a directive is carried out"*; the examples beneath were already consistent (a rename is a source change, which does go to disk), so only the generalization changed.
- **Fix: `Skill Activation` stopped naming the tool it mandates, and the subset test stopped guarding two renamed headings** (`src/zrb/llm/prompt/markdown/workflow.md`, `test/llm/prompt/test_section_composition.py`, `AGENTS.md`): the compaction pass rewrote *"activate every skill the turn's work will need with `ActivateSkill`"* to *"activate every skill the work needs"*, leaving the section that requires the action with no mechanism named — recoverable only from `tool_guidance`, which is separately switchable. `ActivateSkill` is restored. The same rewrite renamed `Cost of guessing wrong` to `When you don't know` without updating `OWNED_VOCABULARY`, which still guarded the dead string; `ActivateSkill` had gone stale there the same way. Because the subset walk asserts a *negative*, both entries kept passing while protecting nothing, and the live headings `When you don't know`, `Where the deliverable goes` and `Routing work outward` were unguarded. The map now lists them, and `test_every_owned_term_still_exists_in_its_owner` asserts every term still appears in its owner, so the next rename fails at the moment it is made rather than a release later.
- **Fix: `Skill Activation` dropped the project-conventions half of a skill's precedence** (`src/zrb/llm/prompt/markdown/workflow.md`): the section had said an activated skill's instructions *"yield to explicit user instructions and to `AGENTS.md` / `CLAUDE.md`"*; the rewrite kept the user half and dropped the project-file half, leaving it stated only in `mandate`'s rank 5 > rank 6 ordering. Under ADR-0096 that is a section leaning on a sibling: trim `mandate` and nothing says a house convention beats a skill. The clause is restated in place, naming the files rather than the ranking.
- **Fix: three documents described an eight-rank Priority Order after it became six** (`docs/adr/adr-0096.md`, `docs/adr/README.md`, `AGENTS.md`): the collapse two entries above landed after ADR-0096 was accepted, and its Decision clause 2 still enumerated all eight ranks while its Evidence bullet asserted `mandate.md` contained "the eight-rank ladder" under a `[DOCUMENTED]` marker. The record now states the six and notes what merged, since the count was never the decision — one ladder that ranks everything is. `AGENTS.md`'s section table also still credited `workflow` with the `Cost of guessing wrong` section, which no longer exists.
- **Fix: `Turn Sequence` step 1 read as forbidding the tool call its own ladder prescribes** (`src/zrb/llm/prompt/markdown/workflow.md`): the premise check closed on *"Do this before investigating"* while routing to `When you don't know`, whose first rung is *"A tool can settle it → call the tool"* — opposite directions for a premise a tool can settle. The step now says to settle premises before the work they would invalidate, and that a tool call settling one belongs to the step rather than to the investigation it precedes.
- Cumulative effect of the prompt work in this release — consolidation, compaction, the examples split, and this structural pass — measured on the composition captured from a live session: 34,357 → 30,357 chars, ~8,589 → ~7,589 tokens, **11.6% smaller** than the prompt that shipped before this work, with every behavioral rule preserved and the contradictions removed. The compaction pass alone reached 29,895 chars (13.0%); the review fixes above added 462 back — restoring `ActivateSkill`, the project-conventions clause, and the two journal-index exits are all rules the compaction had dropped rather than words it had saved, which is the distinction that pass was supposed to hold. A self-review conducted from inside the prompt scored it 5/10 on efficiency and recommended a "~4,000-word version", on a stated length of "~8,500 words"; the composed prompt was 4,869 words at the time, so the target was an 18% trim rather than the halving the framing implied, and the diagnosis rested on a quantity the reviewer had not measured. The review's one independently useful finding — Journal Protocol being the heaviest subsystem relative to its value — is the change above, and it was found by measurement rather than by the review's own reasoning.
