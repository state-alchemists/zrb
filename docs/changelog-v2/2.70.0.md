## 2.70.0 (unreleased)

- **Behavior change: `CFG` assignments fail fast** (`src/zrb/config/config.py`, `src/zrb/config/env_field.py`): assigning an unknown `CFG.UPPERCASE` name now raises `AttributeError` naming the closest real knob (via `difflib`), instead of silently creating a new attribute that no reader ever consumes. Assigning a value the field's `cast` cannot round-trip (e.g. `CFG.LLM_MAX_REQUEST_PER_MINUTE = "nope"`) now raises `ValueError` at the assignment site instead of at the next unrelated read. `DEFAULT_*` constants and read-write properties like `ROOT_GROUP_NAME` are unaffected. The error message names the real CLI command (`{ROOT_GROUP_NAME} config explain`), so a white-labeled deployment sees its own command name, not `zrb`.
- **Fix: `CFG.TODO_VISUAL_FILTER` and `CFG.SEARXNG_PORT` now respond to `zrb_init.py`** (`src/zrb/builtin/todo.py`, `src/zrb/builtin/searxng/start.py`): both were read once at import time — before `zrb_init.py` loads — so assigning them from `zrb_init.py` was a silent no-op. Both are now resolved lazily via a callable default.
- **Fix: `start-server`'s CLI description no longer bakes in a stale root group name** (`src/zrb/runner/cli.py`): the same import-time-read bug, on the `start-server` task's `--help` text. The description is now static text; the branded name never rendered correctly there for a white-labeled CLI (it's imported before white-labeling's env override runs) even before this fix.
- **Behavior change: a broken `zrb_init.py` (or `ZRB_INIT_SCRIPTS`/`ZRB_INIT_MODULES` entry) now aborts the CLI** (`src/zrb/__main__.py`, `src/zrb/util/load.py`): previously the failure was logged as one line with no file/line/type and the CLI continued with a half-applied config — the worst outcome, since the symptom then shows up somewhere unrelated. It now prints the file, line and exception type and exits 1. `load_file` gained an opt-in `raise_on_error` parameter (default `False`, so its existing lenient callers — plugin/skill/hook discovery — are unaffected) that the init-loading call site uses.
- **New test architecture ratchet: no `CFG.*` read at import time** (`test/architecture/test_deferred_config_reads.py`, R3).
- **Breaking: `LLMChatTask` now exposes the full R5 verb set on every ordered collection** (`src/zrb/llm/task/chat/task.py`): tools, tool factories, toolsets, toolset factories, history processors, triggers, custom commands, hook factories, tool policies, response handlers, argument formatters and UIs each gained whichever of `append_X`/`prepend_X`/`set_X`/`remove_X` was missing (tool policies, response handlers and argument formatters previously had only `prepend_X`; the rest previously had only `append_X`). `remove_X` is a no-op on a not-present item, matching `PromptRegistry`. Old → new: `set_ui(x)` → `set_uis([x])`; `set_ui_factory(x)` → `ui_factories = [x]` (the property was already settable — R7, one name per concept); `set_approval_channel(x)` → `approval_channels = [x]`; `set_history_manager(x)` → `history_manager = x` (a single-value slot, so it is a property, not a `set_X()` method — R7). `docs/task-types/llmchat-task.md` and `docs/advanced-topics/llm-custom-ui.md` are updated throughout.
- **Breaking: the hook family drops `register`/`clear_manual` for `add_hook`/`clear`** (`src/zrb/llm/hook/registry.py`, `src/zrb/llm/hook/manager.py`): `HookRegistry.register` → `add_hook`, matching every other family's verb (R6); `HookManager.register` → `add_hook` likewise. `HookRegistry.clear_manual()` → `clear()` — the old name claimed to clear only manually-registered hooks but always cleared the entire collection; the new name says what it does.
- **Breaking: `get_search_directories()` is gone from `HookManager`, `SkillManager`, and `SubAgentManager`** (`src/zrb/llm/hook/manager.py`, `src/zrb/llm/skill/manager.py`, `src/zrb/llm/agent/subagent/manager.py`): each now has exactly one `search_dirs` property (R7) — reading it returns the explicit override if one was set (at construction or by later assignment), else the computed defaults; assigning it invalidates any completed scan, so the next read/scan picks it up. `SkillManager`/`SubAgentManager` gained the setter for the first time (previously `search_dirs` could only be set at construction). `SubAgentManager.root_dir` → `scan_root`, so it cannot be confused with `search_dirs` — a different concept, the recursive scan target.
- **New test architecture ratchet: a uniform mutation-verb surface** (`test/architecture/test_mutation_surface.py`, R5/R6/R7).
- **New capability: `llm_chat.prompt_manager = pm` now works** (`src/zrb/llm/task/chat/task.py`), along with `hook_manager`, `llm_config`, `llm_limiter`, and `markdown_theme` — every component slot `LLMChatTask` holds exactly one of is now a settable, type-checked property (R8), so a `zrb_init.py` can replace one wholesale on an already-defined task such as the built-in `llm_chat`. `history_manager`, `sandbox`, and `permissions` already worked this way. Assigning the wrong type raises `TypeError` naming the expected class, at the assignment site. `tool_confirmation` stays read-only for now: `AnyToolConfirmation` is not a real ABC (it resolves to plain `Any` at runtime), so it needs a proper type before it can be a type-checked slot — tracked for Phase 8 (R9).
- **Breaking (narrow): `LLMChatTask.has_prompt_manager` is removed.** It always returned `True` — the constructor already builds a default `PromptManager` whenever none is passed, so `self._prompt_manager` could never actually be `None`. `prompt_manager`'s getter no longer raises either, for the same reason; both were dead code, not a real optionality. Old → new: `task.prompt_manager if task.has_prompt_manager else None` → `task.prompt_manager` (always safe now).
- **New test architecture ratchet: every declared slot is settable and typed** (`test/architecture/test_mutation_surface.py`, R8).
