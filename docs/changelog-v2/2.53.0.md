## 2.53.0 (August 2, 2026)

- **Fix: every tool result was sent to the model twice, and each one presented as a new user turn** (`src/zrb/llm/agent/tool_result.py` added, `src/zrb/llm/agent/common.py`, `src/zrb/llm/agent/gates.py`, `src/zrb/llm/agent/truncate.py`, `test/llm/agent/test_tool_result.py` added): `ToolReturn` exposes two model-facing fields and they are additive, not alternative — `return_value` becomes the tool-result message, while `content` is documented as *"Content sent to the model as a separate `UserPromptPart`"*, reserved for payloads a tool result cannot carry natively. Every zrb wrapper populated both, passing the stringified result to `content` and the structured value to `return_value`, on the reading that one was "the model-facing string" and the other was "for programmatic consumers". There were no programmatic consumers: the only two readers of `.return_value` passed it straight into another `ToolReturn`. Measured on a real 9-turn session, that was 73,321 chars of `ToolReturnPart` against 74,025 chars of byte-identical `UserPromptPart` — **73.6k of 356.3k input tokens, 21%** — and because no sanitizer strips a `UserPromptPart` (`sanitize_history`, `filter_nil_content`, and `sanitize_orphaned_tool_calls` all key off `tool_call_id`, which a user part lacks) the duplicate persisted into saved history and was re-sent every following turn. The second consequence is worse than the cost: pydantic-ai appends all user parts after all tool-return parts, so each tool batch was followed by a `role: user` message containing the tool output. Over that session the model saw eight apparent user turns that were tool results, which is the shape of the observed re-analysis loops — a model that cannot locate the user's last turn re-derives its answer against what looks like fresh input. `content` is now left unset, and the invariant lives in one named place, `agent/tool_result.py::tool_return`, imported by both `common.py` and `gates.py`. `return_value` keeps the tool's **own** shape rather than a stringified copy: Google maps it through `model_response_object()` where a dict passes through as the native `functionResponse` but a string arrives wrapped as `{"return_value": "<escaped json>"}`, and `model_response_str_and_user_content()` (OpenAI, Anthropic, Mistral, …) extracts multimodal parts *out of* `return_value`, so stringifying replaces an image with a Python repr and drops the file entirely — the hazard `tool/mcp.py::cap_mcp_result` already refuses to take. A differential over 14 payload shapes against `model_response_str`, `model_response_object`, `files`, and `structured_content` reports **zero provider-visible deltas**; the only difference is the removed duplicate. Gate denials and tool errors also stop arriving as a literal `null` tool result with the explanation in a detached user turn. See ADR-0092.
- **Fix: a journal that had never been written to reported itself as broken** (`src/zrb/llm/tool/journal.py`, `test/llm/tool/test_journal.py`, `docs/technical-specs/llm-context.md`): `search_journal` returned `{"error": "Journal directory not found: …"}` when the configured directory was absent, and nothing anywhere created it. To the model that reads as "this feature is unavailable", not "nothing recorded yet" — so on a machine with a fresh journal the agent fell back to the `[journal-fallback]` protocol and asked the user to record entries by hand, without ever attempting a write that would have succeeded (`file_write.py:15` calls `os.makedirs(..., exist_ok=True)`). The whole memory layer was inert and could not bootstrap, because the only thing that would create the directory was a write the agent had already concluded was impossible. A missing directory is now created and reported as the same empty result an unmatched search returns; only a directory that cannot be created is an error. The technical spec, which stated that no code path under `src/zrb/llm/` calls `os.makedirs`, is corrected.
- **Fix: the Stop-hook `systemMessage` extension had no ceiling** (`src/zrb/llm/agent/run/session_extension.py`, `test/llm/agent/run/test_session_extension.py`): the Claude-style block-to-continue path is capped at `STOP_HOOK_BLOCK_CAP = 8`, but the `systemMessage` path immediately below it incremented no counter and checked no cap, and a `systemMessage` re-runs the turn. A hook returning one on every `Stop` would loop the agent without bound. The built-in journaling hook escaped only by accident — its `_stop_fired` guard is reset on `SESSION_START` rather than per turn, despite the docstring claiming otherwise — so any hook whose own guard behaved as documented would have looped. `STOP_HOOK_SYSTEM_MESSAGE_CAP` gives that path its own budget, independent of the block cap.
- **Feature: a cross-section reference is pruned when its target is not composed** (`src/zrb/llm/prompt/section_filter.py` added, `src/zrb/llm/prompt/manager.py`, `test/llm/prompt/test_section_filter.py` and `test_section_composition.py` added): prompt sections toggle independently via `LLM_INCLUDE_SECTIONS`, so every reference from one to another is conditional — a config omitting `journal_mandate` still received `workflow` telling the model to "search the journal" and `persona` explaining that journal writes are silent bookkeeping, instructions about a subsystem the prompt never described. The prior mitigation was prose hedging ("see *Skill Activation*, where present"; "Only if a *Journal Protocol* section appears in this prompt; that section is separately configurable…"), which costs tokens in every configuration and delegates to the model a fact the composer already knows. A referencing block is now marked `<!--requires:section-->` … `<!--/requires-->` and removed at compose time, with comma-separated dependencies all required. Two forms are supported because both read naturally in source: a marker alone on its line removes the line, while one mid-sentence removes only itself so a conditional clause can live inside a bullet. The set filtered against is what the prompt **actually** emits, not the configured list — `_emitted_sections` drops `git_mandate` outside a git repo and adds `workflow` when a pre-split config names only `mandate`. `test_section_composition.py` brute-forces all 63 combinations of the six file-backed sections in both profiles; it caught two real leaks during the rewrite, an inline marker the first regex did not match and `mandate`'s opening line enumerating sections by name. See ADR-0094.
- **Feature: `auto` selects the small-model profile from a declared size in the model id** (`src/zrb/llm/prompt/profile.py`, `test/llm/prompt/test_profile.py`, `docs/configuration/llm-config.md`, `AGENTS.md`): ADR-0083 established that zrb infers nothing from a model id, because family names span tiny instruct models through frontier models. True — but the registry ships empty and nothing in `src/` ever called `register_model_profile`, so `auto` resolved to `terse` for **every** model and ADR-0091's conclusion, that worked demonstrations are the one adaptation the evidence supports for weaker models, reached nobody. `examples.explicit.md` existed and shipped to zero sessions. `DEFAULT_MODEL_PROFILES` now matches two things and only two: a stated parameter count of 14B or less (`-7b`, `gemma-2-9b`, `qwen3-14b`; the regex accepts 1–14, so `-32b`, `-70b`, and `-405b` do not match) and a vendor's own small-tier label (`mini`, `nano`, `tiny`, `small`, `lite`, `haiku`). The ADR-0083 claim is preserved — a *family* name is still never read as capability — with the recognition that a parameter count is the vendor stating the size rather than a guess about it. `flash` is deliberately excluded as a latency tier that spans weak to strong. The risk is asymmetric in the safe direction: under ADR-0091 the variant adds demonstrations only, never rules, so a false positive costs example tokens while a false negative costs a weak model the one adaptation that helps it. User declarations are consulted before the built-ins, so one line overrides either way. See ADR-0093.
- **Breaking: the `explicit` prompt profile is renamed `mini`, with no alias** (`src/zrb/llm/prompt/markdown/examples.explicit.md` → `examples.mini.md`, `src/zrb/llm/prompt/profile.py`, `src/zrb/config/mixins/llm_prompt.py`, `docs/configuration/llm-config.md`, `docs/advanced-topics/programming-the-prompt.md`, `AGENTS.md`): ADR-0083 named the profile for a *writing style* — "a more directive register for weaker models". ADR-0091 then removed that style, having measured the directive re-phrasings at +638 tokens with 82% byte-identical lines and more of the prohibition phrasing that decays over context, narrowing the variant to demonstrations only. After that the name argues for exactly the behaviour the ADR forbids: a contributor reading `explicit` reasonably infers a licence to re-word rules more forcefully, which is the mistake the original variant made. `mini` names the model class the profile exists for — the size tier ADR-0093 detects. `ZRB_LLM_PROFILE=explicit` is no longer recognised and falls through to `auto`; `register_model_profile(..., "explicit")` raises `ValueError: Unknown profile`. ADR-0073's preserve-the-old-key rule covers released env *keys*, where a stale config silently loses a setting — this is a knob *value* whose two consumers both fail loudly, and on a small model `auto` now selects `mini` anyway, so the observable change is limited to forcing the variant onto a large model. See ADR-0095.
- **Improvement: the prompt is 18% smaller, journaling is opt-in by bar rather than mandatory, and demonstrations replace prohibitions** (all six files under `src/zrb/llm/prompt/markdown/`): measured across the composed markdown, 6,870 → 5,610 tokens, with worked `<example>` blocks going from 3 to 9 under `terse` and 25 under `mini` (0.4 → 3.6 per 1k tokens), standalone prohibitions from 3.8 to 2.0 per 1k, bold directives 122 → 93, and conditional constructs 47 → 32. The journal section carried most of the weight at 1,677 → 852 tokens: its default flipped from "when in doubt, log it" to "most turns record nothing", the five-row classification table became three bullets that earn an entry plus a skip list, and the everyday write is now one appended line — the insight-note format, directory indexes, and backlink graph move to `core-journaling`, which already owns structural work. That cascade was real: a conversational analysis turn was observed writing seven files, then six, and now one. Journaling also stopped being mentioned in four sections — Priority Order rule 6, a `persona` clause, and a Working Loop paragraph are gone, leaving `journal_mandate` as the single owner and one pointer from the Turn Sequence. The uncertainty ladder dropped from four rungs to three: rungs 2 and 4 both resolved to "ask", so the model was distinguishing two cases with identical actions. Eighteen standalone prohibitions were converted to affirmative form — "Never a third pass over the same evidence" became "On a third pass, go back to step 1 or take the exit the ladder gives you" — following the finding ADR-0091 cites that omission constraints decay over context while commission constraints persist. Contrastive phrasing ("precedence, not sequence") and the security prohibitions were left alone; they clarify rather than forbid.
- **Fix: the Turn Sequence left a numbering hole when journaling was disabled** (`src/zrb/llm/prompt/markdown/workflow.md`, `test/llm/prompt/test_section_composition.py`): the journal step sat mid-list, so a config without `journal_mandate` composed a sequence reading 1, 2, 4, 5. A gap reads as "step 3 was withheld from you" — the model has no way to tell that a step does not apply rather than being missing. Switching to bullets would have discarded the ordering the section exists to convey, so the conditional item moved to the end of the run instead and the Working Loop left the numbered list, being the work rather than a precondition. A test now walks every numbered run in all 63 subsets and fails on any hole.
- **Fix: a journal write rode along with the reply, so a filler line became the visible answer** (`src/zrb/llm/prompt/markdown/journal_mandate.md`, `src/zrb/llm/prompt/markdown/examples.mini.md`): the ordering rule said "log after the work and before the reply", which is well defined for a code turn but self-contradictory for a conversational one, where the work *is* the reply. The model resolved it the only way available — emitting the analysis and the `Write` in a single response — after which the leftover turn had to say something, and "Done" or "Journal created and note recorded" replaced a five-thousand-character answer as the turn's output. The rule is now anchored on verification, which has an unambiguous position: a finding is earned the moment it is verified, which is before it is written up, so the order is verify → log → answer, with the reply always last. The failure mode is named in the prompt, and `examples.mini.md` demonstrates the correct sequencing beside the exact wrong version, since the rule alone had already failed once.
- **Fix: a missing path told the model nothing about how to find the right one** (`src/zrb/llm/tool_call/tool_policy/read_file_validation.py`, `src/zrb/llm/tool_call/tool_policy/replace_in_file_validation.py`, `src/zrb/llm/tool/file_search.py`, `src/zrb/llm/tool/file_list.py`): four "not found" returns across the navigation tools carried no `[SYSTEM SUGGESTION]`, against the convention `AGENTS.md` documents for errors the model itself has to recover from. `Read`'s helpful message in `file_read.py:75` was unreachable on the path that mattered, because the pre-execution policy denial in `read_file_validation.py` short-circuits before the tool runs. Observed consequence: a model working from a directory one level above the repo guessed two paths, grepped a third, received three bare "not found" errors, and concluded the task was impossible — its Recovery reasoning was correct on a premise nothing had invited it to check. Each message now resolves the path and names the usual cause (a relative path resolving against the current directory rather than the project root), and points at `List`.
- **Fix: "this cannot be done" was the only claim in the prompt exempt from verification** (`src/zrb/llm/prompt/markdown/workflow.md`): Recovery's "task cannot succeed as stated → say so plainly and stop" carried no evidence requirement, while every other assertion in the prompt traces to something checked that session. A model that has guessed wrong twice satisfies the rule by halting, and halting looks like compliance. The clause now states that a failed guess is not evidence for impossibility, and that the actual state gets confirmed before the halt.
