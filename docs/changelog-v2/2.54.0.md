## 2.54.0 (August 4, 2026)

**Breaking.** The system prompt collapses from six rule sections to three, and the tool-guidance registry is removed. `ToolGuidance`, `add_tool_guidance`, `add_tool_guidance_factory`, `add_tool_guidance_section_factory`, `add_tool_group`, and `PromptManager.tool_names` are gone with no shim; `register_section` replaces them. A pinned `ZRB_LLM_INCLUDE_SECTIONS` naming a retired section still parses — it composes to nothing and logs a warning — but emits no content.

- **Improvement: the prompt carried its weight in a rulebook instead of next to the tools** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm/prompt/manager.py`, `src/zrb/config/mixins/llm_prompt.py`, ADR-0098): the composed default prompt measured **32,621 chars (~8,150 tok)** on this repo. The comparable rule prose in Claude Code and OpenCode's `anthropic.txt` is ~2,100 words (~2,800 tok). Totals were never the difference — with tool schemas included those harnesses sit at ~12–15k too — the *split* was: zrb ran ~5,200 tok of rule prose plus a ~1,300 tok generated tool catalogue against ~1,500 tok of tool docstrings, where the references run ~2,800 against ~8–12k. `workflow.md` alone was 2,167 words, 37 bullets and ~38 bolded directives, and IFScale (arXiv 2507.11538) finds instruction-following accuracy degrades with instruction density under a **primacy bias** — later instructions are dropped first, which is the shape of a long rulebook. Sections are now sorted by *what can enforce the rule*: the runtime first, then the tool's own docstring, then the prompt, then a skill. `DEFAULT_LLM_INCLUDE_SECTIONS` becomes `persona,workflow,examples,system_context,project_context` — three rule sections and two data sections. The composed default measures **19,478 chars (~4,870 tok)**, about 40% down; the eager tool docstrings grow ~450 tok, so the net context floor falls roughly 45%. Not the two-thirds a section count suggests: `workflow` had to *absorb* two sections, so its own file barely shrank while carrying three sections' content. A new `test_default_prompt_stays_within_its_budget` pins the composed prompt under 24,000 chars so the reduction cannot creep back one paragraph at a time.
- **Breaking: `mandate` folded into `workflow`; the back-compat shim is removed** (`src/zrb/llm/prompt/markdown/mandate.md` deleted, ADR-0098 supersedes ADR-0086): the Priority Order is the highest-value block in the prompt and primacy says it belongs first, so it now opens `workflow` rather than living in a separately-toggleable section that could be ordered away from it. The `manager.py` shim that emitted both files when a config named only `mandate` goes with it — there is no `mandate.md` left to emit. `OWNED_VOCABULARY` in `test_section_composition.py` gains `Priority Order` and `Operating Rules` under `workflow` rather than losing them, because `test_every_owned_term_still_exists_in_its_owner` asserts a positive and a term deleted from the map guards nothing.
- **Breaking: `git_mandate` deleted — the rule was already enforced in code, and had drifted** (`src/zrb/llm/prompt/markdown/git_mandate.md` deleted, `src/zrb/llm/common_tools.py`, `src/zrb/builtin/llm/chat.py`, ADR-0098): `bash_safe_command_policy()` (`llm/tool_call/tool_policy/bash_validation.py:19-80`) allowlists exactly `git status`, `git diff`, `git log`, `git show` and routes `add`/`commit`/`push`/`merge`/`rebase`/`reset`/`clean` to a user prompt — the section was restating a policy the runtime already applied. It had also gone stale in a way nothing caught: it listed `branch`, `remote -v` and `worktree list` as approval-free, which `_SAFE_PREFIXES` never granted, so the runtime asked anyway and the prompt said it would not. The one behaviour a policy cannot produce — show `git status` and `git diff HEAD` before requesting approval — is one line in `workflow`'s Priority 1. To make the deletion correct rather than merely convenient, the policy moved from `builtin/llm/chat.py` into `apply_common_tools`: enforcement now ships with the tools it guards, so a host that gains an approval channel gets it automatically, and hosts without one (programmatic `LLMTask`, `SubAgentManager`, which inherits the caller's confirmation via the `current_tool_confirmation` ContextVar) are skipped via a `getattr` check rather than a protocol requirement.
- **Breaking: `tool_guidance` and its four-host registry deleted** (`src/zrb/llm/prompt/tool_guidance.py` deleted, `manager.py`, `task/building.py`, `task/chat/building.py`, `task/chat/execution.py`, `agent/subagent/manager.py`, `src/zrb/__init__.py`, ADR-0100 supersedes ADR-0043/ADR-0086): the section composed to 5,178 chars from 24 static entries plus 6 dynamic factories, filtered at runtime against the resolved tool names. It duplicated by design what the docstrings also had to say, and the two were synced by hand — which had already failed: `AGENTS.md` records that `DelegateToAgent`'s guidance and the Working Loop shipped **two different trigger lists for one decision**. The 30 entries land in three places: genuine cross-tool forks append a line to the relevant docstring; turn-level policy becomes a four-rule `### Tool usage` block in `workflow`; and the rest (`TodoRead`, `ListWorktrees`, `LspFindDefinition`, …) are dropped because their docstrings already say what they do. The model-aware parallel-tool-call block moves into `system_context` as a `- Parallel tool calls: …` line — it is a stable fact about the model, changing only on `/model`, which recomposes the prompt anyway. `PromptManager.tool_names` is removed with the filter it existed for. **Migration:** `register_section(name, provider)` (ADR-0061) is the replacement and is strictly more capable — the provider sees the live context. Note the move does *not* save tokens on its own: pydantic-ai serializes every registered tool's docstring and schema into every request, so a docstring is not deferred context. What it buys is locality, and the honest lever on tool-definition weight remains the *number* of registered tools.
- **Breaking: the journal is three tools and no prose** (`src/zrb/llm/tool/journal_write.py` added; `journal_mandate.md`, `journal_reminder.md`, `llm/hook/journal.py`, and `llm_plugin/core_skills/core-journaling/` deleted, ADR-0099 supersedes ADR-0097): recording one line of memory cost an 838-token prompt section, an 11 KB skill, three templates, and a 295-line linter — all so the model could hand-construct a bidirectionally-linked markdown graph. The linter was the tell: its four invariants (broken-link, missing-backlink, orphan, missing-index) are properties of *how the file was written*, needing a check only because a model was writing them freehand from prose — and it had to remember to shell out to `journal-lint.py` afterwards, which nothing enforced. Two tools now own the format. `LogActivity(summary, files=None)` appends to `activity-log/YYYY/YYYY-MM/YYYY-MM-DD.md`, deriving the path **and the timestamp** server-side and creating every index down to the day file. `WriteJournalNote(category, slug, title, context, finding, source, links=None, hud_line=None)` writes a topic note, inserts the reciprocal `## Backlinks` entry in every file it links to, and registers itself in both its directory index and the root HUD; `hud_line` upserts a compressed line into the root-index section matching the category, which is how a stated preference reaches the always-injected HUD without a third tool. All four invariants are now unviolatable rather than checkable: a link is only written after its target is confirmed on disk, the reciprocal is inserted in the same call, and every note is registered in an index the root already links. Path traversal is closed by construction — `category` comes from a fixed set, `slug` must match a kebab-case regex, and a link resolving outside the journal root is refused with a `[SYSTEM SUGGESTION]` error. The judgment that *did* need a model — what earns an entry, and that the write happens before the reply — moved into the two docstrings, which pydantic-ai ships every turn anyway and which disappear with the tools when journaling is off. Legacy and hand-written journals still work: `SearchJournal` reads anything and the journal-dir auto-approvals for `Write`/`Edit`/`RM`/`MV` remain; what is gone is the machinery for building one freehand.
- **Breaking: `LLM_JOURNAL_ENABLED` moved from `active_sections` to tool registration** (`src/zrb/llm/prompt/manager.py`, `src/zrb/llm/common_tools.py`, `llm_task.py`, `task/chat/execution.py`, `agent/subagent/manager.py`, ADR-0099): ADR-0097 gated the flag at `PromptManager.active_sections` because a prompt section was the thing to suppress, and four separate `"journal_mandate" in active_sections` guards keyed off it. With no section left, the flag unregisters all three journal tools in `apply_common_tools`, and `render_journal_index` checks it directly for the `<live-context>` injection — the tools *are* the interface, so removing them is what makes the model unaware a journal exists. The four scattered guards are deleted. `ZRB_LLM_INCLUDE_JOURNAL_REMINDER` and its `STOP` hook are removed outright: the reminder existed to nudge a write that used to be expensive, and a single tool call is not.
- **Improvement: `examples` kept and made the third section** (`src/zrb/llm/prompt/markdown/examples.mini.md`): the collapse deliberately stopped at three rather than two. Demonstrations are the highest-value content per token for small models — the class the profile axis (ADR-0083/0091/0093/0095) exists to serve — so cutting rules *and* examples would have taken from the weakest models twice. The two journal blocks (`Reading the journal table`, `Sequencing a journal write`) are dropped from the `mini` variant: the first taught what earns an entry, which is now in the tool docstrings and disappears with them, and the second demonstrated a write sequenced into its own reply-less response, which a tool call no longer requires.
- **Fix: `test_section_composition.py` guarded a section it composed alone and can no longer reach** (`test/llm/prompt/test_section_composition.py`): `test_tool_guidance_is_self_contained` built a real `LLMTask` to compose the Python-built guidance section, because `filter_requires` never saw it and a `<!--requires:-->` guard was unavailable there. It goes with the section. `FILE_SECTIONS` drops from six to three, so the subset walk runs 7 combinations instead of 63, and exactly one `<!--requires:-->` guard remains in the whole prompt — `workflow`'s pointer at `project_context`.
