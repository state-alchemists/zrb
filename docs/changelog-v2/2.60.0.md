## 2.60.0 (August 11, 2026)

- **Improvement: the skill catalogue and agent roster are capped, with on-demand `SearchSkill` / `SearchAgent` standing behind them** (`src/zrb/config/mixins/llm_prompt.py`, `src/zrb/llm/prompt/claude.py`, `src/zrb/llm/tool/skill.py`, `src/zrb/llm/tool/delegate.py`, `src/zrb/llm/common_tools.py`, `src/zrb/builtin/llm/chat.py`, `test/config/test_config_llm.py`, `test/llm/prompt/test_claude.py`, `test/llm/tool/test_skill.py`, `test/llm/tool/test_delegate_tool.py`, `test/llm/test_common_tools.py`): the prompt's skill catalogue (`{CORE_SKILLS}`/`{AVAILABLE_SKILLS}`) and the delegation tools' AVAILABLE AGENTS roster grew without bound as the user accumulated skill and agent directories, making the rules section's weight a function of what was installed rather than a decision. Each list is now capped by a knob — `LLM_MAX_SKILLS_IN_CATALOG` and `LLM_MAX_AGENTS_IN_ROSTER`, both defaulting to 10 (0/negative lists nothing) — and a truncated list ends with a pointer to the new `SearchSkill` / `SearchAgent` tools. Both are registered on the axis they stand behind: `SearchSkill` sits next to `ActivateSkill` in `common_tools.py` (auto-approved in the built-in chat task), and `SearchAgent` is gated by the `DELEGATE` capability and the `minimal` profile exactly like `DelegateToAgent`, so a roster the model cannot see stays unreachable rather than dangling. Search results cap at 30 with a "refine the query" note. See ADR-0053, ADR-0058, ADR-0064.

- **Improvement: the journal-index header carries the absolute index path, and the prompt gains a `search_tools` discovery rule** (`src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/prompt/markdown/workflow.md`, `docs/technical-specs/llm-context.md`): the `<journal-index>` block now names `index.md` by its **absolute path**, so the agent can `Read` the file directly when it needs more than the cap allows; the truncation marker is reduced to `Truncated at (...more)` because the header now carries the "read the rest here" pointer. `workflow.md` gains a `Tool Discovery (search_tools)` section: deferred tool names stay visible but their schemas materialize only on search, so the model is told to search before concluding a capability is missing, to search with several specific queries in one call, and not to retry or search for what visible tools already cover.
