## 2.52.0 (August 1, 2026)

- **Feature: a message typed during a response now queues instead of being discarded** (`src/zrb/llm/ui/default/keybindings.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/default/output.py`, `test/llm/ui/default/test_keybindings.py`, `test/llm/ui/base/test_base_ui.py`): Enter was gated for *everything* while a turn was in flight — the keybinding returned early and left the text sitting in the buffer for the user to resubmit by hand once the response finished. That gate was broader than the hazard it existed for. The message loop already runs one job at a time, so a plain message submitted mid-turn is safe: it lands in the queue and runs when the current turn ends. Plain messages now submit while thinking; slash commands stay gated, because they mutate session or UI state (`/save`, `/load`, `/model`) and running one against a half-finished turn is genuinely unsafe — their buffer is still preserved for resubmission, so nothing is lost. `BaseUI` exposes `queued_message_count`, the thinking indicator renders ` 📥 N queued ` beside the working spinner, and the echoed user line switches its marker from `💬` to `⏳` when the message joined the queue rather than being sent, so the transcript never implies delivery that has not happened.
- **Feature: rendered markdown re-wraps when the terminal is resized** (`src/zrb/llm/ui/default/output.py`, `src/zrb/llm/ui/base/ui.py`, `src/zrb/llm/ui/default/ui.py`, `src/zrb/llm/ui/base/replay.py`, `src/zrb/llm/ui/base/exec_commands.py`, `test/llm/ui/default/test_output.py`): Rich hard-wraps markdown at render time, so every block already on screen kept the line breaks of whatever width it was painted at — widening a terminal left the transcript ragged at the old column and narrowing it overflowed, permanently. `append_markdown` is now the single entry point for markdown output (`replay.py` and `exec_commands.py` call it instead of rendering inline) and records `[start, end, source]` for each block it appends; `rewrap_markdown` splices a fresh render into the buffer at the new width and shifts the spans that follow. It hangs off prompt_toolkit's `after_render`, which already fires on SIGWINCH, and returns immediately unless the width actually changed. A block is tracked only when it landed verbatim — a pending confirmation buffers content rather than inserting it, which would make the recorded span a lie. Width detection was wrong under output capture besides: `get_terminal_size()` probes fds 1 and 2, which `GlobalStreamCapture` redirects to a pipe, so it fell through to stdin or `COLUMNS` and could disagree with what the renderer was painting; `output_field_width` now asks the running application's output first — that handle is a dup of the real stdout — and falls back to `get_terminal_size()` only if it cannot.
- **Improvement: post-write diagnostics now tell the model what to do *differently*** (`src/zrb/llm/tool/post_write_check.py`, `test/llm/tool/test_post_write_check.py`): `format_post_write_diagnostics` closed with `Fix these before continuing — the edit may have introduced a regression`, an instruction that is satisfied by issuing another edit. It was the highest-traffic recovery-needed tool result in the codebase carrying no `[SYSTEM SUGGESTION]`, the convention `AGENTS.md` reserves for errors the model itself has to recover from. One benchmark trial received 81 consecutive `Successfully updated … [DIAGNOSTIC]` results and answered every one with another blind edit. The suffix now states that the write landed but the file is broken — a failed edit, not a completed one — and names three next actions: `Read` the current state before the next edit rather than editing from memory; stop patching and rewrite the whole file with `Write` once a file has failed twice, since repeated partial edits are what produced the state; and fix the *other* file when the error names an import or symbol defined elsewhere.
- **Feature: `Turn Sequence` — the prompt now states what runs first** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm/prompt/markdown/journal_mandate.md`, `src/zrb/llm/prompt/markdown/mandate.md`): three sections each claimed primacy. Skill Activation said the classifying first look "is the only work permitted before activation"; the Journal Protocol headed its read section "`SearchJournal` before acting" and opened its order of operations with `Search → work → log → reply`; Project Documentation required `AGENTS.md`, `CLAUDE.md`, and `README.md` read in full "before you search or edit". All three are unconditional and mutually exclusive as written — a journal search and three full file reads are both work that would have to precede activation. A `Turn Sequence` block at the top of `workflow` fixes one order: classify with at most one look → activate skills → search the journal → read project docs on code-touching turns → Working Loop. Skill Activation's claim is narrowed to *task* work, and the journal states its two slots relative to the turn instead of asserting a competing sequence. Sections are individually configurable, so a sequence that names other sections can dangle under a trimmed `ZRB_LLM_INCLUDE_SECTIONS`. Only one step is actually exposed — Project Documentation, Skill Activation, and the Working Loop are headings *within* `workflow.md` and cannot be toggled apart from the sequence itself, while `Journal Protocol` is its own section — so step 3 carries the condition inline, at the point of use, rather than as a blanket disclaimer after the list. The remaining cross-file references (`workflow` → Journal Protocol in the Working Loop, `mandate` → Skill Activation) adopt the "where present" hedge `mandate` already used, and the new references inside `journal_mandate` were rewritten to stand alone instead of pointing back at the sequence.
- **Improvement: the `explicit` profile carries demonstrations, not re-phrasings** (`src/zrb/llm/prompt/markdown/persona.explicit.md` removed, `src/zrb/llm/prompt/markdown/examples.explicit.md`, `src/zrb/llm/prompt/markdown/examples.md`, `AGENTS.md`, `test/llm/prompt/test_manager.py`, `test/llm/prompt/test_prompt_mandates.py`): ADR-0049 framed `explicit` as "more directive, not shorter" for weaker models. Measured, it was **+638 tokens (+8.3%)** over `terse` with **37 negative phrasings against 27**, while **82% of its lines were byte-identical** — the abstractions a weak model actually trips on (the Priority Order's precedence-not-sequence framing, the Working Loop's four-column routing table, Skill Activation's 90- and 110-word paragraphs) had no variant at all. That is backwards on the evidence: added constraints reduce task performance *more* for smaller and weaker models ([arXiv 2601.22047](https://arxiv.org/pdf/2601.22047)), and prohibitions decay over context while affirmative steps persist ([arXiv 2604.20911](https://arxiv.org/pdf/2604.20911)), so the variant was adding the harmful kind and more of it. Few-shot demonstration is the one lever the literature supports. `persona.explicit.md` is deleted — `_load_prompt_for_profile` already falls back to the base, so no code changed — and it had in any case drifted, silently missing `persona.md`'s "Narrate only at key moments" rule, exactly the risk ADR-0049 accepted. The prose gloss under each block in `examples.explicit.md` is gone; every one restated a rule owned elsewhere. `explicit` is now `terse` plus worked examples: ~8,012 tokens against terse's ~7,676, 90% identical, and 28 negative phrasings against 26. `examples.md` also stopped being 0 bytes — it carries the answer-scale calibration blocks that no prose can pin down, so the section ships to every model rather than only under a profile nothing selects. See ADR-0049.
- **Fix: an uncertainty ladder replaces three overlapping and partly contradictory ask-rules** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm/prompt/markdown/mandate.md`): `mandate` said to ask rather than guess when still uncertain; Understand said to ask when two hypotheses fail to explain the evidence; Recovery said to ask after multiple approaches failed. Nothing said when to *stop* deliberating and act, which is the other half of the same decision — the failure mode is a turn that re-weighs the same evidence indefinitely without touching a tool. Understand now carries a four-step ladder, first match wins: a tool call can settle it → make the call; no tool discriminates and two hypotheses both fit or none does → ask; a judgment call whose action is cheap to undo → take the best-supported option, name the assumption, and act; irreversible → ask. A deliberation cycle must be paid for with new evidence, so a second pass over unchanged evidence is a stall rather than caution. The both-hypotheses-fit condition previously existed only in `examples.explicit.md`, and therefore reached nobody.
- **Fix: the closing-summary rule and the journal's silence rule contradicted each other on every logging turn** (`src/zrb/llm/prompt/markdown/persona.md`): `persona` required a closing sentence naming what changed whenever the turn changed files; the Journal Protocol requires writes to be silent bookkeeping kept out of the reply; and the Working Loop requires a durable finding to be journaled on *every* row, conversational ones included. A journal write is a file write, so a conversational turn that logged an insight was simultaneously required and forbidden to report it. The rule is now scoped to what the user can actually see — a project file, system state, an external side effect — and names the journal exemption inline.
- **Fix: two different sections were both titled `Project Documentation`** (`src/zrb/llm/prompt/claude.py`): the reading mandate in `workflow` and the generated file list from `project_context` carried the same heading roughly 240 lines apart, and the generated block cross-referenced the mandate *by that ambiguous name* ("See Project Documentation for when to read these"). The generated section is now `# Project Context`, matching the `project_context` key users pin in `ZRB_LLM_INCLUDE_SECTIONS` and in sub-agent `inherit_sections`, and correctly scoping the `## Custom Project Context` subsection that `add_project_context()` providers render into it. The `### Documentation Files Found` and `### User-Level Guidance` sub-headings are unchanged — the mandate references those, not the container.
- **Fix: the core-skill catalogue read as choose-one** (`src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm_plugin/core_skills/core-coding/SKILL.md`): the catalogue opened with "Tie-break by the **deliverable**, not the topic", which frames overlapping skills as a selection problem, while `core-coding` claimed "code analysis" and `core-research` claimed "analyzing unfamiliar code" with nothing to separate them. Skills are not mutually exclusive and the tie-break wording was the bug, not the overlap: the catalogue now says so outright and uses the collision as its example — analyzing unfamiliar code and then changing it activates both. `core-coding`'s description drops "code analysis" as a deliverable *file type* and names the analysis done in service of a change instead.
- **Refactor: repeated prompt rules consolidated to one owner each** (`src/zrb/llm/prompt/markdown/persona.md`, `src/zrb/llm/prompt/markdown/mandate.md`, `src/zrb/llm/prompt/markdown/workflow.md`, `src/zrb/llm/prompt/markdown/journal_mandate.md`): four rules were stated in full in two or three sections apiece rather than stated once and scoped. "Assert nothing you have not checked" was re-derived in Understand alongside `persona`'s canonical version and Verify's evidence criterion — Understand's copy is gone, and the two survivors keep only their scope deltas (source formats and inference labelling; the journal's negative-claims rule). "Ask rather than guess" went from three statements to one in `mandate`, with `workflow` supplying operational triggers instead of the slogan. The journal's re-derivation of "stating an action is not performing it" is trimmed to a single clause. "Correctness over speed" is stated once, in `persona`.
- **Fix: the verification window differed between profiles** (`src/zrb/llm/prompt/markdown/examples.explicit.md`): `persona.explicit.md` opened a bullet with "not verified **this session**" and closed it with "confirm it with a tool or a cited source **this turn**", and `examples.explicit.md` repeated the turn-scoped form — so switching `ZRB_LLM_PROFILE` silently changed whether a file read twenty turns ago still counts as verified. Profiles are meant to change phrasing, not rules. Both now say *this session*, matching the base; the Journal Protocol keeps its stricter *this turn* window for durable writes, which is a deliberate scope difference rather than drift.
