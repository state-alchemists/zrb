# ADR-0139 — A shipped tool may be approved by default, but only below the rules

- **Status:** Accepted
- **Date:** November 4, 2026

## Context

Before this, zrb had two answers to "does this tool ask?". A tool either self-registered as always-approved (`AskUserQuestion`, and nothing else), or appeared in `src/zrb/builtin/llm/chat.py`'s policy list — which only the chat runner applies. Everything else prompted.

Three things made that untenable in the week it shipped.

**The memory verbs.** `SearchMemory` was the only read of `LLM_NOTES_DIR` that asked, while `Read`, `LS`, `Glob` and `Grep` on the same directory had been approved for years: an inconsistency, not a protection. `Remember` and `Forget` asked everywhere, and the store's own specification says why that cannot work — git is the approval surface ("every write is a diff, every mistake a `git revert`"), `Forget` retires rather than deletes, and the core cap's refusal tells the model to `Forget` something to make room. A store that asks on write is a store nobody writes to; a store that asks on `Forget` jams at the cap.

**The reviewer, measured.** The memory reviewer is a `STOP` hook that writes what a turn taught, and the specification expects it to produce most writes. It builds its agent through `run_llm_hook` → `create_agent(yolo=False)` and runs with no UI, outside the cascade, so every `Remember` it called came back as `DeferredToolRequests`: counted as a tool call in `HookResult.tool_calls`, never executed. Checked with a scripted model before the fix — with `yolo=False` no fact file appears, with `yolo=True` one does.

**The ordinary tools.** `ReadToolResult` re-reads output the user already approved producing; `SendMessageToSubagent` and `SendMessageToParent` talk to a sub-agent already started; `EnterWorktree` creates the isolated tree that `ExitWorktree` deletes; an `LspRenameSymbol` dry run only reports.

Neither existing mechanism fit. `register_always_auto_approve` is priority 0, above the permission rules, which makes a tool un-denniable — right for a tool that *is* the user interaction, wrong for anything else. A `ToolPolicy` is the right strength but exists only on hosts that implement `prepend_tool_policy`, which `LLMTask` and `SubAgentManager` do not.

## Decision

Add a second registry, `_DEFAULT_AUTO_APPROVE`, and a cascade stage at priority 2c that reads it.

- **Below the rules.** The permission policy is reached first and its `ASK` or `DENY` is final; a `PreToolUse` hook's `ask` still forces the prompt. The stage removes a prompt nobody wanted, never a decision somebody made.
- **Above YOLO, not instead of it.** YOLO is the mode where nobody is watching. The prompt this removes is the one a careful user answers by hand every turn, so the default has to hold with YOLO off.
- **Populated by the tool surface, not by a runner.** `apply_common_tools` registers `DEFAULT_AUTO_APPROVED_TOOLS`, so every host that shares the tools shares the defaults — including the two with no policy list to append to.
- **An argument-gated case is a predicate, not a second mechanism.** `LspRenameSymbol` is approved only when `dry_run` is true. A tool policy would cover that on hosts with `prepend_tool_policy` and nowhere else — the same asymmetry this ADR exists to remove — so the registry stores a predicate per tool instead of a bare name.
- **A hook that must write says so.** `AgentHookConfig.auto_approve` (default `False`) reaches `create_agent(yolo=...)`. The memory reviewer sets it, which is safe because its own config fixes its tool list to the three memory verbs.
- **A sandbox escape still asks.** The stage refuses a call carrying `dangerously_skip_sandbox`, the same invariant the tool policies keep.

## Consequences

The memory verbs, `ReadToolResult`, both sub-agent messages and `EnterWorktree` no longer prompt, and the reviewer writes — which is what 3.33.0's notes had been claiming. A user who wants the prompt back writes `Remember:ask`.

Costs and limits, all deliberate:

- **Two approval registries are one more thing to know.** The rule lives in the module docstring: always-approved means above the rules and only for the user interaction; default-approved means below them and for anything else. A third strength would be a design smell.
- **`yolo` on a hook agent is coarse.** It approves every call that agent makes; it is safe only because the tool list is the hook's own config. A user-authored agent hook that sets it takes the same responsibility.
- **The prompt is gone before the write is seen.** `LLM_SHOW_TOOL_CALL_DETAIL` defaults to off, so a memory write shows as a tool name. The compensating record is the store's git history, `Forget`'s retire-don't-delete, and the `/usage` memory section's write count.
- **The reviewer's tool calls still run outside the cascade.** `auto_approve` makes the write land; it does not give the hook a rule engine. `Remember:deny` applies to the main agent, not to the reviewer.
