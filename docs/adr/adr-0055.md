# ADR-0055 — The journal is a markdown graph that only tools write, behind one master switch

**Status:** Accepted

**Context.** Agent long-term memory should be human-readable, organizable, and cheap on tokens — not everything belongs in every prompt. A single JSON note store could not grow into that.

The first design got the storage right and the *authoring* wrong. Recording one line of memory cost the model an 838-token prompt section, an 11 KB skill, three templates and a 295-line linter — all so it could hand-construct a bidirectionally-linked markdown graph with no orphans.

The linter is the tell. It checked four invariants: **broken-link** (a link whose target does not exist), **missing-backlink** (a forward link with no reciprocal entry), **orphan** (a note unreachable from the root index), and **missing-index** (a directory of notes with no index). Every one is a property of *how the file was written*. They needed checking only because a language model was writing freehand from prose instructions — and the model had to remember to shell out to the linter afterwards. Nothing enforced any of it. The observed failure was not malformed output but **deferral**: in a recorded session the agent said "I'll log your name preference now" and yielded the turn without a single tool call, which is the cheapest legal action when the write is expensive and unobservable.

Turning journaling *off* was also impossible. The journal reached the model through four independent surfaces — the prompt section, the index injection, the search tool, and the built-in skill — each behind a different lever, and no combination of them disabled it: the directory path has no "unset" value, dropping the prompt section left the skill advertised in the catalogue, and zeroing the index size made the protocol lie about an empty journal. A benchmark harness made the cost concrete: isolating each trial with an empty per-trial journal directory is precisely the trigger for structural work, so compliant models built a full tree of 9–10 files in most runs and then discarded it — a cost paid only by the models that follow the protocol.

Once deferral was closed by making the writers unforgeable, a second, quieter failure showed up: recall. A regex-only `SearchJournal` miss reads identical to "never documented," so a session that guessed the wrong keyword silently duplicated a note instead of finding the existing one. The HUD sections (`User`/`Preferences`/`Active Constraints`) had no eviction beyond the injected copy's char-count truncation, so a wrong preference recorded once could sit in the always-injected index indefinitely. A note revision fully overwrote its Context/Finding with no trace of what was believed before. And there was no way to retract a note at all — an orphan/broken-link invariant that only holds forward in time is a weaker guarantee than it sounds.

**Decision.** Store the journal as a hierarchical markdown directory (`ZRB_LLM_JOURNAL_DIR`). Only the index is injected into the conversation, at the two points ADR-0042 defines; detailed notes are read on demand. **Four tools own the format, and there is no prose:**

- `SearchJournal` reads. On a zero-hit search it fuzzy-matches the query against every note title (`difflib.get_close_matches`, stdlib) and returns near-misses under `did_you_mean` — a regex miss otherwise looks identical to "never documented," which just encourages an undiscoverable duplicate.
- `LogActivity(summary, files=None)` appends to `activity-log/YYYY/YYYY-MM/YYYY-MM-DD.md`. It derives the path **and the timestamp** itself, creates the day file with its heading and its backlink to the month index, and creates or extends the year, month and day indexes on the way down.
- `WriteJournalNote(category, slug, title, context, finding, source, links=None, hud_line=None)` writes `{category}/{slug}.md` with frontmatter and a Context/Finding/Source body, inserts the reciprocal backlink entry in every file it links to, and registers itself in the category index and under the root index's recent-insights section. `hud_line` upserts a compressed line into the root-index section matching the category — capped at `LLM_JOURNAL_HUD_MAX_ENTRIES_PER_SECTION` entries, oldest evicted first, so a stale preference does not sit in the always-injected index forever. Revising an existing slug prepends its superseded Context/Finding to a bounded `## History` block (capped at 3) instead of silently discarding it, so a belief change stays traceable.
- `DeleteJournalNote(category, slug)` removes a note and scrubs every markdown link resolving to it elsewhere in the tree — its entry in the category index, in the root index's Recent Insights, and any `## Related`/`## Backlinks` line another note held pointing here. This is a deliberate reversal of "without a third tool" below: an orphan/broken-link invariant that only ever holds *forward* in time — nothing could retract a note — turned out to be a worse guarantee than one more tool earns.

The five invariants become **unviolatable rather than checkable**: a link is only written after its target is confirmed on disk, the reciprocal backlink is inserted in the same call, every note is registered in its directory index, every directory index is linked from the root, and — **no lost update** — a coarse-grained advisory lock (`fcntl.flock` over the whole journal root, held for one writer call) makes each multi-file graph update atomic against a concurrent writer (a sub-agent, or the compliance judge below racing the turn it followed). The *judgment* — what earns an entry, and that the write happens before the reply rather than being deferred — lives in the tool docstrings, which pydantic-ai ships every turn anyway (ADR-0045) and which disappear with the tools when journaling is off.

**Widening compliance beyond file writes.** The Stop-hook journal-compliance judge (`journal_compliance.py`) only asked a small model to look back at a turn when `event_data.wrote_files` was true — leaving exactly the case `WriteJournalNote`'s own docstring calls highest-value uncovered: a stated preference or standing instruction with no file edit. `MatcherConfig` has no OR (matchers in a list are AND-only), and turn text isn't reachable as a matcher field, so the fix computes the combination once at dispatch (`runner.py`): `event_data.journal_worthy = wrote_files or turn_states_preference(turn)`, a cheap regex heuristic (`hook/turn_evidence.py`) over the turn's user-prompt text. `wrote_files` itself is untouched for any other consumer; the hook's single matcher now targets `journal_worthy`.

**One master switch.** `LLM_JOURNAL_ENABLED` (default on, state-last per ADR-0026 because `LLM_JOURNAL_*` already has siblings) gates tool registration in `apply_common_tools`, and `render_journal_index` checks it directly for the index injection — reachable from the summarizer, so it cannot rely on its callers. Two enforcement points, both the actual surface rather than a proxy for it. `LLM_JOURNAL_AUTO_SEARCH_ENABLED` is a separate, narrower switch (ADR-0042) for the first-turn recall addendum, off the same master gate but independently toggleable.

**Consequences.** Writing memory is one tool call, so the incentive and the mechanics finally agree. Format changes are code changes with tests rather than prose edits hoping for compliance, and path traversal is closed by construction: the category comes from a fixed set, the slug must match a kebab-case regex, and link targets resolving outside the journal root are rejected. Turning the journal off removes the tools, the index and the skill together. Legacy and hand-written journals still work — `SearchJournal` reads anything and the journal-directory write auto-approvals remain — but the machinery for the model to *build* one freehand is gone, and a journal edited by hand outside the tools is no longer checkable. That is accepted: a linter nobody was required to run was not providing the guarantee anyway. `DeleteJournalNote`'s full-tree scrub is `O(files)` per delete — accepted because the journal is personal notes, not a corpus.

**Alternatives rejected.** *A single JSON note file* — flat, and it cannot grow into a browsable graph. *Embed all notes in the prompt* — token waste for content most turns do not need. *An external database* — overkill, and less portable than files in a git repo. *One `WriteJournal(kind=...)` tool* — merges two genuinely different argument sets behind an enum, forcing every caller to read both halves of the schema. *Keep the linter as a CLI command* — nothing would call it: the writers cannot produce output that fails it, and legacy journals are explicitly not migrated. *Keep the skill for structural work* — two descriptions of one tree, free to diverge. *Gate the four surfaces independently* — what already existed, and the reason nothing could turn journaling off. *Treat an empty journal directory as "disabled"* — overloads a path with a mode, and silently disables journaling for anyone who cleared the variable expecting the documented default. *Give `core_skills/` a blanket toggle* — too broad; it would take the other core skills with it. *Turn a per-turn reminder hook on by default* — treats a nudge as a substitute for a followable rule, and pays a token cost every turn for a write most turns should not make; the compliance judge's widened trigger keeps this discipline — it is still evidence-gated, not a standing reminder. *Add an OR primitive to `MatcherConfig`* — a bigger blast radius (schema/matcher/types) for a combination only one hook currently needs; computing the combined field once at dispatch is cheaper and mirrors how `wrote_files` itself is already precomputed. *Precise Related/Backlinks bookkeeping for `DeleteJournalNote`* — requires reasoning about the asymmetry between a note's own Related section, the hardcoded index backlink, and index-registration entries; a full-tree textual scrub is as precise (every link is a deterministic markdown line) and far simpler. *A per-file lock around every internal write* — closes torn writes but not the multi-file race between a note, its backlinks, and two indexes; a single lock over the whole call is what makes the graph update atomic as a unit.

**Where it lives.** `src/zrb/llm/tool/journal.py` (`SearchJournal`, `did_you_mean` suggestion), `src/zrb/llm/tool/journal_write.py` (the writers, the journal lock, HUD eviction, the History block, `DeleteJournalNote`; its module docstring maps each behaviour to the invariant it replaces), `src/zrb/llm/hook/turn_evidence.py` (`turn_states_preference`), `src/zrb/llm/hook/journal_compliance.py` (the widened matcher), `src/zrb/llm/agent/run/runner.py` (`journal_worthy`), `src/zrb/llm/common_tools.py` (the registration gate), `src/zrb/llm/prompt/live_context.py` (`render_journal_index`), `src/zrb/config/mixins/llm_content.py`, `test/llm/tool/test_journal.py`, `test/llm/hook/test_journal_compliance.py`.
