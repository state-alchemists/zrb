# ADR-0055 — The journal is a markdown graph that only tools write, behind one master switch

**Status:** Accepted

**Context.** Agent long-term memory should be human-readable, organizable, and cheap on tokens — not everything belongs in every prompt. A single JSON note store could not grow into that.

A markdown graph got the storage right, but a prose-authored one got the *authoring* wrong. Recording one line of memory cost the model an 838-token prompt section, an 11 KB skill, three templates and a 295-line linter, so it could hand-construct a bidirectionally-linked graph with no orphans. The linter checked four invariants — **broken-link** (a link whose target does not exist), **missing-backlink** (a forward link with no reciprocal entry), **orphan** (a note unreachable from the root index), and **missing-index** (a directory of notes with no index).

Every one was a property of *how the file was written*. They needed checking only because the model wrote freehand from prose, and nothing made it run the linter afterwards.

The observed failures:

- **Deferral.** In a recorded session the agent said "I'll log your name preference now" and yielded without a tool call — the cheapest legal action when the write is expensive and unobservable.
- **No off switch.** The journal reached the model through four surfaces — the prompt section, the index injection, the search tool, and the built-in skill — each behind a different lever, and no combination disabled it: the directory path has no "unset" value, dropping the prompt section left the skill in the catalogue, and zeroing the index size made the protocol lie about an empty journal.
- **Cost paid by the compliant.** A benchmark harness isolating each trial with an empty journal directory triggered structural work every time: compliant models built a 9–10-file tree in most runs, then discarded it.
- **Recall.** A regex-only `SearchJournal` miss reads identical to "never documented," so a wrong keyword silently produced a duplicate note.
- **Staleness and loss.** The HUD sections (`User`/`Preferences`/`Active Constraints`) had no eviction beyond the injected copy's char-count truncation, so a wrong preference could sit in the always-injected index indefinitely. A revision overwrote Context/Finding with no trace, and nothing could retract a note — an orphan/broken-link invariant that only holds forward in time is weaker than it sounds.
- **Unbound parameter guidance.** pydantic-ai attaches docstring text to a parameter's schema `description` only when it parses a strict `Args:`-style block. `Tool(write_journal_note).function_schema.json_schema` had zero descriptions across all 8 parameters despite thorough prose, and a model reused an existing slug for unrelated content because nothing in the schema said reuse overwrites.
- **Narrow compliance trigger.** The Stop-hook journal-compliance judge ran only when `event_data.wrote_files` was true, missing what `WriteJournalNote`'s own docstring calls highest-value: a stated preference or standing instruction with no file edit.

**Decision.** Store the journal as a hierarchical markdown directory (`ZRB_LLM_JOURNAL_DIR`). Only the index is injected into the conversation, at the two points ADR-0042 defines; notes are read on demand. **Four tools own the format, and there is no prose:**

- `SearchJournal` reads. On a zero-hit search it fuzzy-matches the query against every note title (`difflib.get_close_matches`, stdlib) and returns near-misses under `did_you_mean`.
- `LogActivity(summary, files=None)` appends to `activity-log/YYYY/YYYY-MM/YYYY-MM-DD.md`. It derives the path **and the timestamp** itself, creates the day file with its heading and backlink to the month index, and creates or extends the year, month and day indexes on the way down.
- `WriteJournalNote(category, slug, title, context, finding, source, links=None, hud_line=None)` writes `{category}/{slug}.md` with frontmatter and a Context/Finding/Source body, inserts the reciprocal backlink in every file it links to, and registers itself in the category index and the root index's recent-insights section. Registration is keyed by link target, so retitling a note relabels its index lines instead of adding a second entry.
  - `hud_line` upserts a compressed line into the root-index section matching the category, keyed by a trailing link to its note, so a revision replaces the note's earlier line rather than leaving a contradicting one. The key is that whole trailing ` ([note](path))`, not any part of it, so two notes whose lines read alike each keep their own and a revision cannot replace another's line. A line pinned before the link existed has no key and is left to the cap (matching by text could delete a different fact). Each section is capped at `LLM_JOURNAL_HUD_MAX_ENTRIES_PER_SECTION` entries, oldest evicted first.
  - Revising an existing slug prepends its superseded Context/Finding to a bounded `## History` block (capped at 3), so a belief change stays traceable.
- `DeleteJournalNote(category, slug)` removes a note and scrubs every markdown link resolving to it elsewhere in the tree — its category-index entry, its root-index Recent Insights entry, and any `## Related`/`## Backlinks` line in another note. A label is free-form model text and may itself contain `]`, so a link's target is matched from the end of its line, where the closing bracket of the label is the last one the line has. A forward-only invariant that can never retract a note is a worse guarantee than one more tool costs.

The five invariants are **unviolatable rather than checkable**: a link is written only after its target is confirmed on disk, the reciprocal backlink is inserted in the same call, every note is registered in its directory index, every directory index is linked from the root, and — **no lost update** — a coarse advisory lock (`fcntl.flock` over the whole journal root, held for one writer call) makes each multi-file update atomic against a concurrent writer (a sub-agent, or the compliance judge racing the turn it followed).

**Guidance lives with the tools.** The *judgment* — what earns an entry, and that the write happens before the reply — lives in the tool docstrings (ADR-0045), which disappear with the tools when journaling is off. It is bound per parameter with `Annotated[T, Field(description="...")]`, which does not depend on docstring-format detection and, per ADR-0058, costs the same tokens as prose; `test/llm/test_common_tools.py::test_every_registered_tool_parameter_carries_a_description` pins every registered tool's parameters to a non-empty description. The four tools are registered with `defer_loading`, so their docstrings reach the model only after it searches for them. The one rule an agent needs before that — change the journal only through the writers, since a direct edit skips their index, backlink and git bookkeeping — sits in the `<journal-index>` header, the only always-present journal surface, gated by the same master switch. An observed session edited the journal with Read/Edit for twenty calls because nothing visible said otherwise.

**The journal root is git-backed (`LLM_JOURNAL_GIT_ENABLED`, default on).** The `## History` block is bounded and model-facing only: a wrong write followed by 3 more revisions evicts the original permanently, and `DeleteJournalNote` has no in-file fallback. So `ensure_journal_tree` `git init`s the root on first use (best-effort — a missing `git` binary or failed init leaves journaling working without it), and every `LogActivity`/`WriteJournalNote`/`DeleteJournalNote` call commits inside the same `_journal_lock` that makes its file changes atomic. That gives unbounded, diffable history, and a human can recover a delete or bad overwrite (`git log --diff-filter=D`, `git show <sha>:path`) independent of yolo, sandbox, or model behavior. The History block stays: it serves the model in-conversation via SearchJournal, git serves a human recovering out of band.

**Compliance covers stated preferences.** `MatcherConfig` has no OR (a matcher list is AND-only) and turn text is not a matcher field, so dispatch (`runner.py`) computes `event_data.journal_worthy = wrote_files or turn_states_preference(turn)` — a cheap regex heuristic (`hook/turn_evidence.py`) over the turn's user-prompt text. `wrote_files` is untouched for other consumers; the judge's single matcher targets `journal_worthy`.

**One master switch.** `LLM_JOURNAL_ENABLED` (default on, state-last per ADR-0026 because `LLM_JOURNAL_*` has siblings) gates tool registration in `apply_common_tools`, and `render_journal_index` checks it directly for the index injection — it is reachable from the summarizer, so it cannot rely on its callers. Both enforcement points are the actual surface rather than a proxy. `LLM_JOURNAL_AUTO_SEARCH_ENABLED` is a separate, narrower switch (ADR-0042) for the first-turn recall addendum, under the same master gate but independently toggleable.

**Consequences.** Writing memory is one tool call, so the incentive and the mechanics agree. Format changes are code changes with tests rather than prose edits hoping for compliance. Path traversal is closed by construction: the category comes from a fixed set, the slug must match a kebab-case regex, and link targets resolving outside the journal root are rejected. Turning the journal off removes the tools, the index and the skill together.

Legacy and hand-written journals still work — `SearchJournal` reads anything and the journal-directory write auto-approvals remain — but the machinery for the model to *build* one freehand is gone, and a hand-edited journal is no longer checkable. Accepted: a linter nobody was required to run was not providing the guarantee anyway. `DeleteJournalNote`'s full-tree scrub is `O(files)` per delete — accepted because the journal is personal notes, not a corpus.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| A single JSON note file | Flat, and it cannot grow into a browsable graph. |
| Embed all notes in the prompt | Token waste for content most turns do not need. |
| An external database | Overkill, and less portable than files in a git repo. |
| One `WriteJournal(kind=...)` tool | Merges two genuinely different argument sets behind an enum, forcing every caller to read both halves of the schema. |
| Keep the linter as a CLI command | Nothing would call it: the writers cannot produce output that fails it, and legacy journals are explicitly not migrated. |
| Keep the skill for structural work | Two descriptions of one tree, free to diverge. |
| Gate the four surfaces independently | The prior state, and the reason nothing could turn journaling off. |
| Treat an empty journal directory as "disabled" | Overloads a path with a mode, and silently disables journaling for anyone who cleared the variable expecting the documented default. |
| Give `core_skills/` a blanket toggle | Too broad; it would take the other core skills with it. |
| Turn a per-turn reminder hook on by default | Treats a nudge as a substitute for a followable rule, and pays a token cost every turn for a write most turns should not make; the compliance judge's widened trigger is still evidence-gated, not a standing reminder. |
| Add an OR primitive to `MatcherConfig` | A bigger blast radius (schema/matcher/types) for a combination only one hook needs; computing the combined field once at dispatch is cheaper and mirrors how `wrote_files` is precomputed. |
| Precise Related/Backlinks bookkeeping for `DeleteJournalNote` | Requires reasoning about the asymmetry between a note's own Related section, the hardcoded index backlink, and index-registration entries; a full-tree textual scrub is as precise (every link is a deterministic markdown line) and far simpler. |
| A per-file lock around every internal write | Closes torn writes but not the multi-file race between a note, its backlinks, and two indexes; a single lock over the whole call makes the graph update atomic as a unit. |
| Rely on the bounded in-file `## History` alone | Evicts the original after 3 revisions, has nothing for a delete, and is subject to model behavior; git history is unbounded and recoverable out of band. |
| Describe parameters in free-form docstring prose | Produces an empty per-parameter `description` in the schema the model fills one field at a time. |

**Where it lives.** `src/zrb/llm/tool/journal.py` (`SearchJournal`, `did_you_mean` suggestion), `src/zrb/llm/tool/journal_write.py` (the writers, the journal lock, git-backing (`_ensure_journal_git`, `_git_commit`), HUD eviction, the History block, `DeleteJournalNote`; its module docstring maps each behaviour to the invariant it replaces), `src/zrb/llm/hook/turn_evidence.py` (`turn_states_preference`), `src/zrb/llm/hook/journal_compliance.py` (the widened matcher), `src/zrb/llm/agent/run/runner.py` (`journal_worthy`), `src/zrb/llm/common_tools.py` (the registration gate), `src/zrb/llm/prompt/live_context.py` (`render_journal_index`), `src/zrb/config/mixins/llm_content.py` (`LLM_JOURNAL_GIT_ENABLED` alongside its siblings).

Tests: `test/llm/tool/test_journal_notes.py`, `test/llm/tool/test_journal_backlinks.py`, `test/llm/tool/test_journal_git.py` (git-backing: init, per-call commits, git-missing fallback, delete recoverability), `test/llm/test_common_tools.py::test_every_registered_tool_parameter_carries_a_description` (per-parameter schema description coverage, all registered tools), `test/llm/hook/test_journal_compliance.py`.
