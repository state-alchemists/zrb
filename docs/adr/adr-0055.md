# ADR-0055 — The journal is a markdown graph that only tools write, behind one master switch

**Status:** Accepted

**Context.** Agent long-term memory should be human-readable, organizable and cheap on tokens: not everything belongs in every prompt. A single JSON note store cannot grow into that.

A markdown graph gets the storage right, but a prose-authored one gets the *authoring* wrong. Recording one line of memory cost the model an 838-token prompt section, an 11 KB skill, three templates and a 295-line linter, so it could hand-build a bidirectionally linked graph. The linter checked four invariants: **broken-link** (target missing), **missing-backlink** (no reciprocal entry), **orphan** (unreachable from the root index) and **missing-index** (a directory of notes with no index). Each is a property of how the file was written, needing a check only because the model wrote freehand and nothing made it run the linter.

The observed failures:

- **Deferral.** An agent said "I'll log your name preference now" and yielded without a tool call, the cheapest legal action when the write is expensive and unobservable.
- **No off switch.** The journal reached the model through four surfaces (prompt section, index injection, search tool, built-in skill), each behind a different lever, and no combination disabled it: the directory path has no "unset" value, dropping the section left the skill in the catalogue, and zeroing the index size made the protocol lie about an empty journal.
- **Cost paid by the compliant.** A benchmark isolating each trial with an empty journal directory triggered structural work every time: compliant models built a 9-10-file tree, then discarded it.
- **Recall.** A regex-only `SearchJournal` miss reads the same as "never documented", so a wrong keyword silently produced a duplicate note.
- **Staleness and loss.** The HUD sections (`User`/`Preferences`/`Active Constraints`) had no eviction beyond char-count truncation of the injected copy, so a wrong preference could persist indefinitely. A revision overwrote Context/Finding without trace, and nothing could retract a note.
- **Unbound parameter guidance.** pydantic-ai attaches docstring text to a parameter's schema `description` only from a strict `Args:`-style block. `write_journal_note`'s schema had zero descriptions across 8 parameters despite thorough prose, and a model reused a slug for unrelated content because nothing said reuse overwrites.
- **Narrow compliance trigger.** The Stop-hook compliance judge ran only when `event_data.wrote_files` was true, missing the highest-value case: a stated preference or standing instruction with no file edit.

**Decision.** Store the journal as a hierarchical markdown directory (`ZRB_LLM_JOURNAL_DIR`). Only the index is injected, at the two points ADR-0042 defines; notes are read on demand. **Four tools own the format, and there is no prose:**

- `SearchJournal` reads. On zero hits it fuzzy-matches the query against every note title (`difflib.get_close_matches`) and returns near-misses under `did_you_mean`.
- `LogActivity(summary, files=None)` appends to `activity-log/YYYY/YYYY-MM/YYYY-MM-DD.md`. It derives the path and timestamp itself, creates the day file with heading and backlink, and creates or extends the year, month and day indexes.
- `WriteJournalNote(category, slug, title, context, finding, source, links=None, hud_line=None, pinned=False, applies_when=None)` writes `{category}/{slug}.md` (frontmatter plus a Context/Finding/Source body), inserts the reciprocal backlink in every linked file, and renders the indexes from the notes. The indexes list the note because the note exists, so retitling relabels index lines rather than duplicating them.
  - `hud_line` and `pinned` are stored in the note's frontmatter, beside `updated`, and the HUD line is rendered from them under the section its category and pin decide, ending in a link back to the note. A revision replaces its own line because it is the same note, and never another note's. Each section holds at most `LLM_JOURNAL_HUD_MAX_ENTRIES_PER_SECTION` entries, oldest `updated` evicted first, a pinned line only when every line in the section is pinned. A write that supplies no `hud_line` keeps the note's line and its pin.
  - Revising a slug prepends the superseded Context/Finding to a `## History` block capped at 3, so belief changes stay traceable.
- `DeleteJournalNote(category, slug)` removes a note, scrubs every markdown link to it elsewhere — any `## Related`/`## Backlinks` line and any index line that is only a link to it — and renders the indexes again. Labels are free-form and may contain `]`, so a link target is matched from the end of its line. A graph that can never retract a note is a worse guarantee than one more tool costs.

The five invariants are **unviolatable rather than checkable**: a link is written only after its target exists on disk; the backlink is inserted in the same call; every note is registered in its directory index; every directory index is linked from the root; and **no lost update** — an advisory lock (`fcntl.flock` over the journal root, held per writer call) makes each multi-file update atomic against a concurrent writer (a sub-agent, or the compliance judge racing its turn).

**A category names whose fact it is.** `NOTE_CATEGORIES` is `user`, `agent`, `preferences`, `projects`, `technical`, and the line between `preferences` and `agent` is drawn by subject, not by register: `preferences` holds what the user stated about how they want to be worked with, `agent` holds what is true of the assistant itself — its standing choices, its working style, how it wants to be treated. Without the second, an agent's own standing choice had nowhere to go but the user's section, which is how a wardrobe decision ended up filed as a fact about the user. The root index renders the durable HUD sections in a fixed order — `User`, `Constraints`, `Agent`, `Recent` — ahead of the unbounded `Recent Insights`, because the injected copy is capped and overflows from the end; the category and the pin decide the section (`user` and `preferences` to `User`, `agent` to `Agent`, `projects` and `technical` to `Recent`, or to `Constraints` when pinned).

**The indexes are a view of the notes.** A note's frontmatter is the one source of truth for what the indexes say about it: `status`, `applies_when`, `hud_line`, `pinned`, and `updated` (when it was last written). `journal_index.py` renders the root index (HUD sections, `Recent Insights` of active notes, `Directories`) and every category index (every note, superseded included) from the notes; a write, supersede, delete or refile changes the note and renders again, and rendering the same notes twice yields the same bytes. The earlier design edited `index.md` as text, so a note's pin and its line lived only there while its status lived in the note, and each bug was two files claiming one fact. The cap is part of the view: an evicted note keeps its `hud_line`, so raising the cap brings the line back, and the write that causes an eviction names it.

A **foreign line** is a line in a generated region that no note accounts for — a hand edit. The render carries it through unchanged and in place, never evicts it, and does not count it toward the cap. The ownership test reads the note link the line already carries, so the injected text gains no marker and nothing is kept beside the index: a HUD line belongs to the note its trailing note link names when that note has a `hud_line`; a catalog or category-index line (a bullet holding one titled link) belongs to the note whose file it links; every other line is foreign. The failure modes are the other side of the rule: a hand edit to the text of an owned line is reverted at the next render (the text is the note's `hud_line`); a hand-written line ending in a note link to a note that has a line is claimed by that note; a hand-written bullet that is only a link to a note, in a catalog, is relabelled; and a line that is only a link to a deleted note is removed with it, since it would be broken. Alternatives rejected: owning a line only when it equals a rendered line, which orphans the previous line of any note whose frontmatter is edited outside the tools and leaves a stale constraint in every prompt; and a sidecar file recording the rendered lines, which is a second record that can disagree with the index after a restore or an outside edit.

A journal written before the index was derived kept pins only in the index text. The first journal call (`_open_journal`, under the lock) reads the first line that links a note without an `updated` stamp into that note's frontmatter, stamps it so the order survives, and renders; lines no note accounts for stay as foreign lines, and a note is migrated once. A journal also keeps its old skeleton (`_write_if_absent` never rewrites an index), so the same step adds a missing HUD section at its place in the order — appending it at the end would put it after the unbounded section, where the cap evicts it first — and the missing link to a category's index in `## Directories`; an existing link keeps its text and its place.

**Guidance lives with the tools.** The judgment — what earns an entry, and that the write precedes the reply — lives in the tool docstrings (ADR-0045), which vanish with the tools when journaling is off. It is bound per parameter with `Annotated[T, Field(description="...")]`, independent of docstring-format detection and, per ADR-0058, no costlier than prose. `test_every_registered_tool_parameter_carries_a_description` pins every registered tool's parameters to a non-empty description. The tools use `defer_loading`, so their docstrings reach the model only after it searches for them.

The one rule needed before that (change the journal only through the writers, since a direct edit skips their index, backlink and git bookkeeping) sits in the `<journal-index>` header, the only always-present journal surface, under the same master switch. Without it, an agent edited the journal with Read/Edit for twenty calls.

**The journal root is git-backed (`LLM_JOURNAL_GIT_ENABLED`, default on).** The `## History` block is bounded and model-facing: three further revisions evict the original, and a delete leaves nothing in-file. So `ensure_journal_tree` runs `git init` on first use (best-effort: without `git`, journaling works without history), and every `LogActivity`/`WriteJournalNote`/`SupersedeJournalNote`/`DeleteJournalNote` call commits inside the same journal-root lock (`_open_journal`). A human can recover a delete or bad overwrite (`git log --diff-filter=D`, `git show <sha>:path`) regardless of yolo, sandbox or model behavior. History serves the model in-conversation; git serves a human out of band.

**Compliance covers stated preferences.** `MatcherConfig` has no OR and turn text is not a matcher field, so dispatch (`runner.py`) computes `event_data.journal_worthy = wrote_files or turn_states_preference(turn)`, a cheap regex over the turn's user-prompt text (`hook/turn_evidence.py`). `wrote_files` is unchanged for other consumers; the judge's single matcher targets `journal_worthy`.

**One master switch.** `LLM_JOURNAL_ENABLED` (default on; state-last per ADR-0026, since `LLM_JOURNAL_*` has siblings) gates tool registration in `apply_common_tools`, and `render_journal_index` checks it directly because the summarizer also calls it. Both checks sit on the actual surface, not a proxy. `LLM_JOURNAL_AUTO_SEARCH_ENABLED` (ADR-0042) separately toggles the first-turn recall addendum, under the same master gate.

**Consequences.** Writing memory is one tool call. Format changes are tested code, not prose hoping for compliance. Path traversal is closed by construction: categories come from a fixed set, slugs must be kebab-case, and link targets outside the journal root are rejected. Turning the journal off removes tools, index and skill together.

Legacy and hand-written journals still work (`SearchJournal` reads anything and journal-directory write auto-approvals remain), but freehand building is gone and a hand-edited journal is no longer checkable. Accepted: a linter nobody had to run gave no guarantee anyway. `DeleteJournalNote`'s full-tree scrub is `O(files)` per delete, fine for personal notes.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| A single JSON note file | Flat; cannot grow into a browsable graph. |
| Embed all notes in the prompt | Token waste for content most turns do not need. |
| An external database | Overkill, and less portable than files in a git repo. |
| One `WriteJournal(kind=...)` tool | Merges two different argument sets behind an enum; every caller reads both halves. |
| Keep the linter as a CLI command | Nothing would call it: the writers cannot fail it, and legacy journals are not migrated. |
| Keep the skill for structural work | Two descriptions of one tree, free to diverge. |
| Gate the four surfaces independently | Why nothing could turn journaling off. |
| Treat an empty journal directory as "disabled" | Overloads a path with a mode, and silently disables journaling for anyone who cleared the variable expecting the default. |
| Give `core_skills/` a blanket toggle | Would take the other core skills with it. |
| A per-turn reminder hook on by default | A nudge is no substitute for a followable rule, and costs tokens every turn; the widened judge trigger is still evidence-gated. |
| Add an OR primitive to `MatcherConfig` | Wider blast radius (schema, matcher, types) for one hook's need; a dispatch-computed field mirrors `wrote_files`. |
| Precise Related/Backlinks bookkeeping for `DeleteJournalNote` | Must reason about asymmetric Related sections, index backlinks and registrations; a full-tree textual scrub is as precise and far simpler. |
| A per-file lock around every internal write | Stops torn writes but not the multi-file race between a note, its backlinks and two indexes. |
| Rely on the bounded `## History` alone | Evicts the original after 3 revisions, has nothing for a delete, and depends on model behavior. |
| Describe parameters in docstring prose | Leaves the schema's per-parameter `description` empty. |

**Where it lives.** `src/zrb/llm/tool/journal.py` (`SearchJournal`, `did_you_mean`), `src/zrb/llm/tool/journal_write.py` (the writers, the lock, git-backing, HUD eviction, the History block, `DeleteJournalNote`; its module docstring maps each behaviour to the invariant it replaces), `src/zrb/llm/hook/turn_evidence.py` (`turn_states_preference`), `src/zrb/llm/hook/journal_compliance.py` (the matcher), `src/zrb/llm/agent/run/runner.py` (`journal_worthy`), `src/zrb/llm/common_tools.py` (registration gate), `src/zrb/llm/prompt/live_context.py` (`render_journal_index`), `src/zrb/config/mixins/llm_content.py` (`LLM_JOURNAL_GIT_ENABLED` and siblings).

Tests: `test/llm/tool/test_journal_notes.py`, `test/llm/tool/test_journal_backlinks.py`, `test/llm/tool/test_journal_git.py` (init, per-call commits, git-missing fallback, delete recovery), `test/llm/test_common_tools.py::test_every_registered_tool_parameter_carries_a_description`, `test/llm/hook/test_journal_compliance.py`.
