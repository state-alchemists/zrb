# ADR-0047 — Home-level `AGENTS.md` and `CLAUDE.md` are listed as user guidance, not project rules

**Status:** Accepted

**Context.** `project_context` searches for `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` and `README.md` across a path built from `~/.claude` plus every parent of the cwd, and used to list every hit under one heading with a mandatory-read instruction describing them as "project-specific overrides".

Because `~/.claude` is unconditionally on that path, a `~/.claude/CLAUDE.md` is found from *every* working directory on the machine. Three problems follow: a mandatory read that is usually irrelevant to the turn; a false label, since a user-wide preference is presented with project authority; and cross-contamination, because benchmark trials, sub-agent worktrees and one-shot runs in scratch directories all inherit the operator's personal instructions as if they were the task's project rules.

**Decision.** Keep the search path — discovering the files is useful — and split the presentation and the obligation by scope.

- `project_context` renders two headings. **Documentation Files Found** holds project-scoped hits, meaning anything from the cwd's parent chain. **User-Level Guidance** holds home-scoped hits, labelled as the user's cross-project preferences, explicitly not project rules, not part of the mandatory read, and to be consulted only when the turn's work depends on them.
- The project-documentation rule reads exactly the paths under **Documentation Files Found**, and states that User-Level paths never override a project file.
- "Home-scoped" is defined narrowly as the home directory itself and `~/.claude` — the two entries the search path contributes regardless of cwd. Every other entry comes from the parent chain and is genuinely project-scoped.
- If home cannot be resolved, hits fall into the mandatory bucket, so the pre-split behaviour is the safe default.

**Consequences.** The mandatory read is scoped to files that actually describe the project, and a home-level convention can no longer silently outrank `AGENTS.md`. Isolated runs stop inheriting personal instructions. The cost is that a user who relied on `~/.claude/CLAUDE.md` being read unconditionally now gets it read only when relevant — which is the intended change: an always-on global preference belongs in `ZRB_LLM_PROMPT_DIR` or a registered section (ADR-0044). Discovery itself is unchanged; the file is still one `Read` away.

**Alternatives rejected.** *Drop `~/.claude` from the search path* — loses the information entirely, when the problem is the obligation and the label, not the discovery. *Inline home-level content instead of listing its path* — pays the token cost on every request in the cached prefix, and still misrepresents scope. *Keep one heading and soften the wording* — the heading is what the model pattern-matches on; two obligations need two headings. *Classify by "is it under the cwd" instead of "is it home"* — equivalent in the common case and wrong when the project legitimately lives under `~`, where the parent chain would reclassify the repo's own ancestors.

**Where it lives.** `src/zrb/llm/prompt/claude.py` (`create_project_context_prompt`, `_is_user_level_dir`), `src/zrb/llm/prompt/markdown/workflow.md`.
