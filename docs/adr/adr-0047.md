# ADR-0047 — A variant is an overlay; a rule never lives only in one

**Status:** Accepted

**Context.** zrb is meant to run on both weak and strong models, but the
phrasing of each section was fixed — one `persona.md`, one `workflow.md`,
written in a dense, principle-led register well suited to a strong model and
lossy on a weak one.

A study of opencode's prompt set surfaced two findings. First, it selects a
whole hand-tuned monolith per model family by substring-matching the model id;
the cost is heavy duplication, with the same safety rules copy-pasted across
nearly every file — exactly the MECE violation composition avoids. Second, and
counter-intuitively, **weak does not mean fewer instructions**: the prompt for
the weaker family is the *longest and most repetitive*, full of few-shot
`<example>` blocks, while the strong-model prompt is shorter and leans on
judgment. The axis is register, not amount.

So the gap was that zrb could vary *which topics* appear but not *how each is
phrased for the model in use*.

Two corrections shaped the final form:

*The "more directive" premise did not survive measurement.* The first variant
pair re-phrased `persona` imperatively and added worked examples. Measured, the
variant was **+638 tokens (+8.3%)** over the base, with **37 negative phrasings**
against 27, while **82% of its lines were byte-identical**. Meanwhile the
sections a weak model most plausibly trips on — the Priority Order's
precedence-not-sequence abstraction, the Working Loop's routing table, long
activation paragraphs — carried no variant at all. Three findings contradict
the premise: added constraints reduce task performance more for smaller models
(arXiv 2601.22047); prohibitions decay as context grows while affirmative steps
persist (arXiv 2604.20911), and the variant added ten more of the decaying
kind; and demonstrations are the lever the evidence actually supports. The
re-phrased `persona` variant had *already* drifted — it had lost a rule the base
file still had.

*The name argued for the banned behaviour.* Once re-phrasing was removed,
"explicit" described a register the variant no longer used, and invited exactly
the mistake the rule forbids.

**Decision.** A second axis over section composition, with two rules.

1. **A variant is an overlay, not a second prompt.**
   `get_prompt(name, profile="lean")` resolves `{name}.{profile}.md` through the
   full override chain and falls back to the base `{name}.md`. A variant only
   needs files for the sections whose text actually changes. This is the *only*
   convention for varying a section's wording: there is no `workflow_lean`
   section name, because the section list says which topics appear and never
   which wording they appear in.

2. **A variant never becomes the only home of a rule.** A variant reaches only
   the models that resolve to it, so a rule that exists nowhere else silently
   misses everyone else — an invariant violated twice in this codebase's
   history and worth stating plainly.

   The rule bounds *where a rule lives*, not *how much prose a preset ships*. A
   variant may re-shape the rulebook for its model class: `workflow.lean.md`
   flattens the precedence ladder and merges the decision ladders,
   `workflow.minimal.md` reduces to one page. Both drop abstraction, and
   `minimal` drops method it also drops the tools for. What neither may do is
   quietly delete a rule that still applies — which is why the floor is a
   *test*, not a prohibition on subtracting:
   `test_every_preset_carries_the_rank_one_safety_rules` pins Priority Order
   rank 1 in every preset, and
   `test_rule_burden_falls_as_the_target_model_gets_weaker` pins the direction.

   `examples.lean.md` is the one variant that adds rather than subtracts. It was
   pinned as a **byte-prefix superset** of `examples.md`, which enforced the right
   thing the wrong way: it made the base a literal copy inside the variant, so the
   two drifted as one file and the variant grew unchecked until `lean` composed
   heavier than `full` (ADR-0075). The pin is now **concept coverage** — the
   variant must teach every stance the base teaches, in whatever words it likes
   (`test_a_variant_of_examples_still_teaches_what_the_base_teaches`), and must
   *not* embed the base verbatim
   (`test_a_variant_of_examples_is_not_a_superset_of_the_base`). Additivity is a
   property of this one variant, not a requirement on variants in general, and it
   is bounded: a demonstration that restates a rule the variant's own rulebook
   states is not additive, it is the same rule bought twice. Six of the fourteen
   in `examples.lean.md` were exactly that, which is what took it from 1,086
   tokens to 568 (ADR-0075). What survives teaches what prose cannot — scale,
   stance, or a form a rule can only describe.

An earlier revision of this ADR forbade subtraction outright, which forced
`lean` and `minimal` to carry *sections* named `workflow_lean` /
`workflow_micro` purely to route around the rule. That bought no safety — the
guard was always the test, never the file-naming — and cost a second convention
for the same idea. Consolidating on `{name}.{profile}.md` removes it.

The variant is named after the preset that selects it. There is **no alias** for
the old `explicit` value, nor for the old `terse`/`mini`/`micro` preset names:
the preserve-the-old-key rule (ADR-0026) covers released env *keys*, where a
stale config silently loses a setting, whereas these are knob *values* whose
consumers both fail loudly.

Which variant a session gets is not decided here — `LLM_PROFILE` selects a
preset that binds a variant to a section list and a tool surface, and owns the
declared-size selection that resolves it (ADR-0075).

**Consequences.** Small models receive both a lighter rulebook and worked
demonstrations with no configuration, through one mechanism. Variant drift is
the standing cost: a rule updated in `workflow.md` can go stale in
`workflow.lean.md`, which the burden and safety tests bound but do not
eliminate — three rulebooks is the real price of the ladder.

`examples` is also thin *in the base*, on purpose: the base keeps only the few
examples that fix a zrb-specific stance, and the rest live in the variant.
Adding a demonstration means adding it to the variant unless it teaches a
stance a frontier model gets wrong — and if it teaches a *rule*, it belongs in
neither file. That last clause was convention until it was tested:
`examples.lean.md` carried three `Wrong:` clauses, which is a rule wearing a
demonstration's clothes, landing in the one section `minimal` drops and the
burden ladder exempts. `test_examples_carry_no_rule_of_their_own` closes it.

The demonstration exemption is bounded on the other side too. A worked example
lowers burden rather than adding it, so `examples` is excluded from the
per-section burden ladder — but exempting it from the *budget* as well let the
exemption pay for itself out of the model's attention. The composed total is
ordered separately (`test_a_weaker_targets_preset_ships_less_prompt_in_total`,
ADR-0075), so a variant may demonstrate as much as it likes provided the whole
preset still weighs less than the one above it.

Every rule-carrying section needs a variant at every preset it serves, and the
silent base fallback is what hides a missing one. `persona` had none at all: all
three presets shipped the same 486 tokens of frontier-register prose, 35% of
`minimal`'s rule payload. `persona.lean.md` and `persona.minimal.md` now exist,
and the burden assertion measures per section so the next omission fails rather
than hiding inside a falling sum.

**Alternatives rejected.** *Per-model monolith selection, opencode's model* —
simple to reason about per model, but duplicates shared rules across files and
abandons composition. *Weak = drop sections* — the intuitive read, contradicted
by the evidence at the 7–14B scale this axis serves, where budget is not the
binding constraint; ADR-0075 revisits it at ~3B, where it is. *A full per-vendor
variant matrix* — maximal fidelity and a maintenance bomb. *Keep the re-phrased
`persona` variant but shorten it* — still spends tokens on a mechanism the
evidence does not support. *A `workflow` variant that adds rule text for weak
models* — the original reading of "the missing variant", rejected on the
measurement above: adding rule text to the models least able to carry it is the
wrong direction. The register-sensitive behaviours really do live in `workflow`,
and the gap was closed the other way — prohibitions converted to affirmative
form **in the base**, which helps every model, and lighter `workflow.lean.md` /
`workflow.minimal.md` variants that *subtract* abstraction for the presets that
need less of it. *Forbid a subtracting variant outright* — the rule as first
written; it pushed every reduction into a parallel `workflow_lean` section name
and bought no safety the burden and rank-1 tests were not already providing.
*Ship an alias for a retired name* — no silent-loss failure to prevent, and it
keeps a discarded name discoverable in docs and autocomplete. *Name the presets
`weak`/`small`* — `weak` reads as a judgement, and `small` collides with the
vendor tier labels the selector matches on (ADR-0075).

**Where it lives.** `src/zrb/llm/prompt/profile.py` (`LEAN_PROFILE`,
`MINIMAL_PROFILE`), `src/zrb/llm/prompt/prompt.py` (variant-aware loading),
`src/zrb/llm/prompt/manager.py` (variant threading),
`src/zrb/llm/prompt/markdown/`: `examples.md` + `examples.lean.md`,
`persona.md` + `persona.lean.md` + `persona.minimal.md`,
`workflow.md` + `workflow.lean.md` + `workflow.minimal.md`.
