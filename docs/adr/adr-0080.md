# ADR-0080 — Mermaid renders as Unicode diagram art via `termaid`; PlantUML stays deferred

**Status:** Accepted

**Context.** ADR-0079 deferred Mermaid and PlantUML rendering, assuming both needed external tooling (`mmdc`/Node+Chromium, `plantuml.jar`/Java) and a terminal graphics protocol (sixel/Kitty/iTerm2) that is unreliable across the terminals zrb runs in. Re-checked separately, the two are not symmetric.

**Mermaid:** [`termaid`](https://pypi.org/project/termaid/) is a pure-Python library with no required dependencies — `termaid.render(source: str) -> str` — that renders a real subset of Mermaid (flowcharts, sequence diagrams, and more) as Unicode box-drawing art in-process: no subprocess, Node, Chromium or image protocol. Flowcharts and sequence diagrams render legibly. Unparseable input returns `""` rather than raising — a silent failure (like an unrecognized LaTeX macro in ADR-0079) that needs the same "empty result → keep the raw fence" fallback.

The pinned version (`termaid>=0.8.0,<0.9.0`; zrb controls the pin, so these are facts about the shipped renderer) has authoring hazards, established from the installed parser source and confirmed by checking rendered *content*, not just that a render returned something.

The most consequential: **an unsupported diagram type is never rejected.** Type dispatch is a `startswith` chain in `__init__.py` that falls through to the flowchart parser, which turns each remaining line into a node box — so `requirementDiagram`, `sankey`, `C4*`, `radar` and `zenuml` render as boxes containing the author's Mermaid source.

The rest are per-construct and silent (unrecognized statements land in a parser `warnings` list nothing displays):

| Construct | Hazard |
| --- | --- |
| Inline edge labels | Unsafe in every arrow style: `A -- "t" --> B` drops the label; `A -- t --> B` and `A == t ==> B` survive but inflate the edge's computed length (all four dashes count), stretching the diagram; `A -.t.-> B` fails to parse, collapsing the statement into one node. `A -->\|t\| B` and its `-.->\|t\|` / `==>\|t\|` siblings are the only safe form. |
| Unquoted label containing `>` | `A[Line1<br/>Line2]` is matched by the asymmetric-node pattern before the rectangle pattern and **silently loses text**. A quoted one renders `<br/>` literally — it is a line break only inside a sequence or state `Note` (`parser/sequence.py`, `parser/statediagram.py` special-case it; no other parser does). |
| Raw line break inside a statement | Truncates a sequence message, spawns a phantom state, or breaks a pipe-labeled edge. |
| Identical edges | Not deduplicated — repeating a shared parent edge per child renders overlapping arrows. |
| `erDiagram` relationship without `: label` | Renders the **entire diagram empty**. |
| `sequenceDiagram` `title` | Dropped. |
| `box … end` | Corrupts block nesting. |
| Multi-line state `note … end note` | Injects phantom states. |

These are authoring rules for whoever emits the fence, not a pipeline concern, so they live in the `core-diagram` skill (`src/zrb/llm_plugin/core_skills/core-diagram/`), loaded only when a `mermaid` fence is about to be written — not in `example.md`'s always-on section (ADR-0044: "extensions belong in skills, tools, live context, or appended caller prompts"). `example.md` keeps only the behavioral example (reach for a mermaid fence when it clarifies structure over prose).

The skill's shape:

- **`SKILL.md` plus per-family companions under `reference/`** — universal rules, the supported-type list and one worked example up front, the progressive-disclosure shape ADR-0053 endorses and the other `core-*` skills use.
- **Companion granularity follows section size, not type count.** `sequence`, `class`, `state` and `er` (17–31 lines each) get their own file; the thirteen chart and layout types (3–6 lines each) share `charts.md`, since a five-line companion costs a whole tool-call round trip. One 192-line `reference.md` made a sequence diagram cost 306 lines to use 30; splitting cut it to 162.
- **`SKILL.md` guards against an unread companion** with a compact table of the silently destructive per-type traps (the mandatory `erDiagram` relationship label, the state-diagram phantom note, the dropped `sequenceDiagram` title), so skipping a companion degrades gracefully. It is complete for flowcharts, the most-emitted type, which need no companion read.
- **It carries fenced examples**, which the four methodology `core-*` skills avoid: it produces a syntactic artifact rather than teaching a method, following `init/SKILL.md`'s template precedent. It states what termaid *supports* as well as what breaks — an errata-only draft left the model unsure whether constructs like `subgraph` were safe, and it burned tool calls investigating.
- **It lives under `core_skills/`**, not the `CFG.LLM_ENABLE_BUILTIN_SKILLS`-gated `skills/` (ADR-0054), though it teaches syntax. That toggle trims optional conveniences; these rules separate a readable diagram from one silently mangled by `termaid`'s fall-through parsing, on every fence. Gating them would mean a deployment that disables built-in skills for cost or noise also loses the guardrails — a correctness regression with no signal to the user.

**PlantUML:** no equivalent exists. PlantUML can emit ASCII/Unicode art (`-txt`/`-utxt`) only by running `plantuml.jar`, which needs local Java — the external-binary problem avoided for Mermaid. The public `plantuml.com/plantuml/txt/...` server avoids Java but sends diagram source to a third party (opt-in only, unlike a pure-Python import), and its own documentation says ASCII output is reliable only for sequence diagrams — class/component/activity rely on Graphviz layout with no text-mode equivalent. Neither clears the "no subprocess, no network, works everywhere" bar, so PlantUML stays deferred.

**Decision.** `render_markdown` calls `convert_mermaid_to_art` (`src/zrb/util/cli/mermaid_diagram.py`) on the markdown string, gated by `CFG.LLM_UI_ENABLE_MARKDOWN_MERMAID` (default on) — a second, independent pass alongside `convert_math_to_unicode`, mirroring that module's shape rather than extending it.

1. **Own module, own toggle; a core dependency, like `pylatexenc`.** Mermaid and LaTeX are unrelated; sharing a file or flag would only complicate the fallback story. `termaid` is a core dependency (pinned `<0.9.0`, being pre-1.0), not an extra: it has zero transitive dependencies and a ~1.6MB footprint, and since the toggle defaults on, an optional dependency would make that default silently render nothing on a bare install. The import stays lazy and memoized (`functools.lru_cache`-wrapped `_get_renderer`) purely for cold-start latency, like `pylatexenc` in `latex_math.py` and ADR-0079's reasoning for `markdownify`/`pyperclip`.

2. **No masking pipeline.** Unlike `$...$` math, a ```` ```mermaid ````/```` ```mmd ```` fence is an unambiguous, delimited marker — no "$5 and $10" prose to guard against. The module is a fence-matching regex (the same shape as `latex_math.py`'s `_FENCED_CODE`) plus a per-fence render-or-fallback, with no code/inline-span protection.

3. **A successful render stays fenced.** Unlike converted math, which is short enough to flow as prose, diagram art is multi-line box-drawing whose spacing must survive verbatim; as paragraph text, Rich's reflow would corrupt it. The fence keeps its delimiters and drops the `mermaid` info string, so Rich renders it as a plain, unhighlighted code block via `rich.markdown.CodeBlock`.

4. **Fallback is per-fence.** A fence `termaid` can't parse, or whose result is empty after stripping, is left as its original fence — the pre-existing behavior (pygments has no `mermaid` lexer, so it already rendered as an unhighlighted code block via the `ClassNotFound` fallback in ADR-0079). One broken diagram doesn't affect any other fence.

5. **The diagram shrinks to fit the console width.** `CodeBlock.__rich_console__` (`rich/markdown.py`) always builds `Syntax(code, lexer_name, ..., word_wrap=True)` for every fence, so a diagram wider than the console is word-wrapped mid-line, splitting box-drawing characters. This shows up on resize: `rewrap_output` (`llm/ui/default/output.py`) re-renders tracked markdown blocks from source at the new width, and a diagram that fit the wider width often doesn't fit the narrower one. `convert_mermaid_to_art` takes the caller's console `width` and, mirroring termaid's CLI `--width` auto-fit (`termaid/cli.py::_auto_fit`), progressively shrinks `gap` then `padding_x` until the widest line fits `width - 2` (the measured cost of `Syntax`'s `padding=1`). If nothing fits, it uses the narrowest attempt — the residual case termaid's CLI also accepts (and warns about), since a box's minimum width is bounded by its label text.

**Consequences.** A ```` ```mermaid ````/```` ```mmd ```` fence in assistant markdown renders as a Unicode diagram wherever `render_markdown` is used; other fence languages are unaffected, since the regex matches only those two info strings. A bare `pip install zrb` renders Mermaid out of the box. PlantUML fences keep their plain-fence fallback.

**Alternatives rejected.**

- *Shell out to `mmdc` (Node/Chromium) or render to SVG/PNG* — needs a terminal graphics protocol not reliably available across zrb's terminals ("all possible terminals" is the deployment target, confirmed with the user); already rejected in ADR-0079.
- *Extend `latex_math.py` to handle mermaid fences* — the features share no logic (no masking, no math-span heuristics, different successful-render shape), so combining them would muddy one module's fallback story with another's.
- *Implement PlantUML alongside Mermaid* — no pure-Python, no-subprocess, no-network option exists; a local-Java or public-server path remains a possible future opt-in.

**Where it lives.** `src/zrb/util/cli/mermaid_diagram.py`, `src/zrb/util/cli/markdown.py`, `src/zrb/config/mixins/llm_ui_styles.py` (`LLM_UI_ENABLE_MARKDOWN_MERMAID`), `src/zrb/llm_plugin/core_skills/core-diagram/SKILL.md` (universal authoring rules, supported-type list, flowchart-complete) and its `reference/` companions (`sequence.md`, `class.md`, `state.md`, `er.md`, `charts.md`), `src/zrb/llm/prompt/markdown/example.md` (the "reach for a diagram" behavioral example).
