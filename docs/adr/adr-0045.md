# ADR-0045 — A rule lives where it is enforced

**Status:** Accepted

**Context.** The composed system prompt measured **32,621 chars (~8,150
tokens)** with the default section list. The comparable rule prose in Claude
Code and OpenCode's `anthropic.txt` is around 2,100 words (~2,800 tokens). The
totals were not the difference — once tool schemas land, those harnesses reach
12–15k tokens too. The *split* was:

| Layer | zrb before | Claude Code / OpenCode |
|---|---|---|
| Rule prose | ~5,200 tok | ~2,800 tok |
| Cross-tool selection guide | ~1,300 tok (a 30-entry registry) | ~200 tok, inline |
| Skill catalogue | ~600 tok | in the skill tool's description |
| Eager tool docstrings | ~1,500 tok (15 tools) | ~8–12k tok |

zrb carried its weight in a rulebook the model had to hold in working memory,
where the references carry theirs next to the schema the model is filling in.
`workflow.md` alone was 2,167 words and about 38 bolded directives, and six
independently-switchable rule sections had to be kept non-overlapping by hand —
a discipline that had already failed, shipping **two divergent delegation
trigger lists**, one in the tool-guidance registry and one in the Working Loop,
each missing a trigger the other had.

The external result that matters is IFScale (arXiv 2507.11538):
instruction-following accuracy degrades as instruction density rises, with a
**primacy bias** — later instructions are dropped first. Rule *count*, not just
token count, is the cost.

The naive fix — "move rules into tool docstrings" — saves nothing, and the
codebase already knew it: pydantic-ai serializes every registered tool's
docstring *and* parameter schema into every request, so a docstring is not
deferred context.

**Decision.** Sort every rule by **what can make it true**, in this order:

1. **The runtime.** If a hook, a tool policy, or the tool implementation can
   make the rule true, the prompt does not state it.
2. **The tool's docstring.** Per-tool mechanics — argument semantics, output
   shape, irreversibility, which tool to use instead — sit next to the schema.
3. **The prompt.** Only judgment no tool can make for the model: stance,
   precedence between conflicting rules, when to stop, when to ask.
4. **A skill.** Domain methodology, loaded on demand.

Applied, this leaves **three rule sections** — `persona`, `workflow`,
`examples` — plus the two data sections `system_context` and `project_context`,
which carry runtime facts rather than rules.

Concretely:

- **The Priority Order opens `workflow`.** It is the highest-value block in the
  prompt and primacy says it belongs first, so it is not in a separate section
  that could be toggled away from the procedure it governs.
- **The git rule section was deleted.** `bash_safe_command_policy()` already
  allowlists exactly `git status`/`diff`/`log`/`show` and routes
  `add`/`commit`/`push`/`merge`/`rebase`/`reset`/`clean` to the user. The prose
  was redundant *and* had drifted — it claimed `branch`, `remote -v` and
  `worktree list` were approval-free, which the allowlist never granted. The one
  behaviour a policy cannot produce — show `git status` and `git diff HEAD`
  before asking for approval — is one line in `workflow`. To make the deletion
  correct by construction, the policy moved from `builtin/llm/chat.py` into
  `apply_common_tools`, so enforcement travels with the tools it guards.
- **The tool-guidance registry was deleted.** It composed 5,178 chars from 24
  static entries plus 6 dynamic factories, filtered at runtime against the
  resolved tool names, duplicating by design what the docstrings also had to
  say. It also carried real API weight: `add_tool_guidance`, `add_tool_group`,
  `add_tool_guidance_factory` and `add_tool_guidance_section_factory` were
  implemented separately on `PromptManager`, `LLMTask`, `ChatBuilding` and
  `SubAgentManager`, with a per-agent copy-and-merge path to stop the
  process-wide singleton accumulating entries across unrelated agents. The 30
  entries landed in three places: genuine cross-tool forks appended a line to
  the relevant docstring; turn-level policy became a `### Tool usage` block in
  `workflow` (files go through the file tools; batch independent calls; never
  guess an argument; read a tool's description before first use); the
  model-aware parallel-call line moved to `system_context` (ADR-0038). The rest
  — `TodoRead`, `ListWorktrees`, `LspFindDefinition` and similar — were dropped,
  because their docstrings already say what they do.
- **The journal prose, its skill, its templates and its linter were deleted**
  in favour of tools. See ADR-0053.
- **`examples` was kept, profile-gated.** Demonstrations are the highest-value
  content per token for small models — the class the profile axis (ADR-0047)
  exists to serve. Cutting rules *and* examples would have taken from the
  weakest models twice.

**Known limits of the runtime rung.** A later attempt to push two more rules
down to rung 1 was built and then reverted before release, and its findings
constrain future work there:

- **A tool policy cannot annotate a result.** `check_tool_policies` is an
  *approval* chain returning `ToolApproved | ToolDenied | None`; its
  `next_handler` yields the next policy's decision, never the tool's output. A
  note appended there is dropped on every call. It is also only consulted when
  a `ToolCallHandler` is bound, which `--interactive false` does not do.
- **A synchronous tool cannot keep cross-call state in a `ContextVar`.**
  `read_file` is synchronous, so the safe wrapper dispatches it through
  `asyncio.to_thread` — a *copied* context whose `set` calls are discarded on
  return.
- **An injected instruction is the weakest lever for exactly the model that
  needs it.** An escalated "stop and report" was ignored 22 times in one trial.
  Such an instruction must be bounded, and must not prescribe an action that
  regenerates its own input — a whole-file rewrite by a small model regenerates
  the diagnostic that issued the instruction.
- **Outcome repetition, not invocation counting, is the right key for a loop
  detector.** Re-running a command after changing the code is new evidence;
  re-running it and getting the same answer is not.

**Consequences.** The composed default prompt dropped from 32,621 to about
**19,500 chars** (~8,150 → ~4,870 tokens), roughly 40%; eager tool docstrings
grew ~450 tokens, so the net context floor fell about 45%. The reduction is
smaller than a section count suggests, because `workflow` *absorbed* two
sections. Subset testing dropped from 63 combinations to 7, and the
MECE-versus-self-containment tension (ADR-0046) largely dissolved with only one
`<!--requires:-->` guard left. A pinned `ZRB_LLM_INCLUDE_SECTIONS` naming
`mandate`, `git_mandate`, `journal_mandate` or `tool_guidance` now resolves to
an empty custom section and logs a warning — a graceful no-op, and a clean break
with no aliases. Removing the registry is a **deliberate public API break**:
`ToolGuidance` is gone from `zrb.__init__` and the four `add_tool_guidance*`
methods raise `AttributeError`, which is the loud failure a clean break should
produce. A test pins the composed prompt under a 24,000-char ceiling so the
reduction cannot regress one paragraph at a time.

**What this does not claim:** parity with Claude Code on weak models. Frontier
models resolve under 65% of terminal-command tasks and small models around 15%.
Prompt hygiene stops zrb-specific failure modes from consuming the capability a
small model has; it does not add capability.

**Alternatives rejected.** *Two sections, dropping `examples`* — takes
demonstrations from exactly the models the change targets. *Keep all six
sections and write them tighter* — prose editing does not remove rules a policy
already enforces, and leaves six sections to keep MECE by hand, the discipline
that had already produced divergent duplication. *Move the rules into docstrings
to shrink the prompt* — shrinks nothing, since pydantic-ai ships every docstring
every turn; locality and adherence are the real benefits and are claimed as
such. *Keep the guidance registry with ~8 built-in entries* — preserves the API
and most of the token win, but keeps the two-sources-of-truth structure that
produced the divergent triggers.

**Where it lives.** `src/zrb/config/mixins/llm_prompt.py`
(`DEFAULT_LLM_INCLUDE_SECTIONS`),
`src/zrb/llm/prompt/markdown/workflow.md` (Priority Order, `### Tool usage`,
the `git diff HEAD` rule),
`src/zrb/llm/tool_call/tool_policy/bash_validation.py` (`_SAFE_PREFIXES` — the
allowlist that *is* the git rule), `src/zrb/llm/common_tools.py`,
`test/llm/prompt/test_section_composition.py`.
