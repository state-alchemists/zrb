# ADR-0093 — `auto` reads a *declared size*, never a family name

**Status:** Accepted (narrows ADR-0083)

**Context.** ADR-0083 established that zrb makes no capability inference from a
model id, because family names (`deepseek`, `qwen`, `llama`, …) span tiny
instruct models through frontier models: a substring match guesses, it does not
detect. `auto` therefore resolved to `terse` unless a user declared a mapping via
`register_model_profile`.

The registry ships empty and nothing in `src/` ever calls that function, so in
practice `auto` resolved to `terse` for **every** model, and ADR-0091's
conclusion — that worked demonstrations are the one adaptation the evidence
supports for weaker models — reached nobody by default. `examples.mini.md`
existed and shipped to zero sessions.

**Decision.** `auto` consults `DEFAULT_MODEL_PROFILES`, a built-in tier
consulted only after user declarations, which matches two things and only two:

* **A stated parameter count of 14B or less** — `-7b`, `-8B`, `gemma-2-9b`. A
  parameter count is not a hint about the model; it is the vendor stating its
  size. The regex accepts 1–14 only, so `-32b`, `-70b`, and `-405b` do not match.
* **A vendor's own small-tier label** — `mini`, `nano`, `tiny`, `small`, `lite`,
  `haiku`.

ADR-0083's actual claim is preserved: a **family** name is still never read as a
capability signal. What changed is the recognition that a size token is not a
family name.

`flash` is deliberately excluded: it is a *latency* tier, not a size one, and
spans weak to strong (`gemini-2.5-flash` is capable). Opt one in with
`register_model_profile("deepseek-v4-flash", "mini")`.

**Consequences.** Small models receive worked examples with no configuration.
The risk is asymmetric in the safe direction: under ADR-0091 `mini` adds
*demonstrations only, never rules*, so a false positive costs example tokens
while a false negative costs a weak model the one adaptation that helps it. Any
entry is reversible in one line, and a user declaration always beats a built-in.
`clear()` drops user declarations but keeps the defaults; a test needing the
no-mapping fallback constructs `ModelProfileRegistry(defaults=())`.

Because `mini` is now reachable, `examples.mini.md` must remain a strict
superset of `examples.md` — a variant *replaces* the base file rather than
appending to it, so anything only in the base would be lost. A test pins this.

**Alternatives considered.** *Leave `auto` inert* — honest but inert; the
mechanism never fires and the ADR-0091 finding stays theoretical. *Match family
names too* (opencode ships seven per-family prompts) — that is the inference
ADR-0083 correctly rejected. *Match on a curated model list* — accurate but
stale the week it ships; a size token stays true.

**Evidence.** `register_model_profile` had no call site in `src/`. Resolution
table: `claude-opus-4-8`, `deepseek-v4-pro`, `qwen3-32b`, `llama-3-70b`,
`llama-3.1-405b`, `gemini-2.5-pro` → `terse`; `qwen2.5-7b`, `gemma-2-9b`,
`qwen3-14b`, `gpt-5-mini`, `claude-haiku-4-5` → `mini`.
