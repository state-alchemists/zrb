# ADR-0093 — A slash command is always offered; an unavailable one explains itself

**Status:** Accepted

**Context.** Some slash commands only work under certain conditions. `/voice` needs the voice dependencies installed or `LLM_VOICE_ENABLED` set. `/rewind` needs a snapshot manager, which requires `LLM_ENABLE_REWIND` (off by default), a snapshot directory, and a named conversation. `/photo` needs `ffmpeg` or Termux:API on the machine.

There are two ways to handle a command that cannot run. Hide it — leave it out of `/help` and tab-completion, and let the handler decline the input. Or offer it anyway and have the handler explain the problem.

Hiding looks tidy and costs more than it appears. The condition has to be repeated at every place that lists commands: the help panel, the completer, and the handler. Those places live in different files, so one condition becomes three, and a fourth listing added later starts out wrong. Worse, a hidden command is a command nobody finds. A user cannot enable a feature they have never seen, and typing it produces nothing useful — an unhandled slash command is forwarded to the model as ordinary chat text.

**Decision.** Every slash command with a resolved alias is listed in `/help` and offered in tab-completion. Availability is decided in one place: the command's own handler.

**1. The handler matches its token first, then checks availability.** Checking availability first would make the handler decline input it was never meant to see, and the next handler in the chain would run instead.

**2. An unavailable command consumes its input and prints why.** The handler returns `True`, so `dispatch_command` treats the input as handled and does not forward it to the model.

**3. The message names the setting that fixes it.** Where several conditions can produce the same unavailable state, the message identifies which one applies rather than guessing — `/rewind` distinguishes "`LLM_ENABLE_REWIND` is off" from "this session has no snapshot directory or name".

**4. Nothing outside the handler filters the command list.** `UIConfig` carries every alias, and the completer and help panel render all of them.

**Consequences.** Adding a conditionally-available command means writing one handler; the help panel, the completer, and the dispatcher need no change. A user always sees the full command set and learns how to turn on the parts that are off. Command listings stay free of feature-specific conditions.

The cost is that completion offers commands that will refuse on this machine. That is the trade: a warning naming the fix is more useful than an absence that explains nothing.

Transient states are **not** availability. `/exec` and `/btw` are unavailable while the model is thinking, which changes many times per session; a menu that flickered with it would be worse than one that does not. Those are declared in `command_table()`'s `run_while_thinking` flag, and the dispatcher prints its own "not available while the model is thinking" notice.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Hide unavailable commands from help and completion | The condition spreads to every listing, and the feature becomes undiscoverable — decisive for `/rewind`, whose gate is off by default. |
| Return `False` and let the input fall through | `dispatch_command` forwards unclaimed input to the model, so the user gets a confused reply to `/rewind` instead of an explanation. |
| One shared "command unavailable" message | Each command has a different fix. A message that cannot name the setting sends the user looking. |
| A capability registry the listings consult | A second place to declare what the handler already knows, and it still has to be kept in step with it. |

**Where it lives.** `src/zrb/llm/ui/base/commands.py` (`handle_toggle_voice`, `command_table`, `get_help_panel`), `src/zrb/llm/ui/base/conversation_commands.py` (`handle_rewind_command`), `src/zrb/llm/ui/default/ui.py` (builds the completer from the unfiltered `UIConfig`). See ADR-0076 for voice and ADR-0082 for photo.
