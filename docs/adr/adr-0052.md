# ADR-0052 — Skills and agents are discovered from directories, with a fixed precedence

**Status:** Accepted

**Context.** LLM capabilities — skills and sub-agents — must be extensible per
project and shareable between projects, and ideally interoperate with Claude
Code's config layout so one library serves both tools.

**Decision.** Discover skills (`SKILL.md` / `SKILL.py`) and agents
(`*.agent.md`) from configurable directories: project-local, home
(`~/.claude/`, `~/.zrb/`), plugin directories (`ZRB_LLM_PLUGIN_DIRS`), and the
built-in `src/zrb/llm_plugin/`. Project overrides home overrides built-in. The
directory names themselves are configurable through `ZRB_LLM_CONFIG_DIR_NAMES`
(default `.claude:.zrb`).

**Consequences.** Extension is decentralized with no central registry, and one
skill library can serve both Claude Code and zrb. The cost is that the
precedence order is a non-trivial mental model, and a shadowed skill is
invisible unless you know to look.

**Alternatives rejected.** *A hardcoded skill set* — inflexible, and forces a
fork to add one. *pip-installed plugin packages* — install friction, weak
discoverability, and a poor offline story. *A single global registry* — a
governance bottleneck for what should be a per-project decision.

**Where it lives.** `src/zrb/llm/skill/manager.py`,
`src/zrb/llm/agent/subagent/manager_search.py`,
`src/zrb/config/mixins/llm_search.py`,
`docs/advanced-topics/claude-compatibility.md`.
