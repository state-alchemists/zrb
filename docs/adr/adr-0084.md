# ADR-0084 — `write_file(mode="w")` refuses to overwrite a file this run hasn't observed

**Status:** Accepted

**Context.** `write_file(mode="w")` on an existing file truncates it whether or not the current run has seen its current content. A model writing from a stale picture of a file — never read this run, or read turns ago before something else changed it — silently and irrecoverably destroys what was there.

**Decision.** `write_file(mode="w")` on a pre-existing file is blocked unless this run has observed the file's exact current content, via a prior `Read` or a prior `Write`/`Edit` whose result still matches disk. `record_observed(abs_path, content)` runs after each such operation; `check_observed(abs_path)` re-hashes the file right before a `mode="w"` overwrite and blocks with a `[SYSTEM SUGGESTION]` to re-read first if there is no record or it no longer matches (something else changed the file). `mode="a"` is exempt: it does not destroy existing content.

The observed-content map (`file_observation.py`'s `_observed`) is a plain `dict` keyed by a run-scope id, not a `ContextVar` holding the dict: a `ContextVar` propagates only within one asyncio task's context tree, so a sub-agent task's `.set()` would never reach its parent or siblings. Keying a plain dict by a `ContextVar`-scoped run id avoids that, mirroring `plan.py::TodoManager`'s keyed-dict pattern for run-scoped state.

The run-scope id is the `current_agent_run_scope` ContextVar, bound once per `run_agent()` call. A top-level conversation passes its stable session name (`conversation_name`), so the record survives across its turns. A delegated sub-agent (`delegate.py`) deliberately passes nothing and gets a fresh full-entropy `uuid4`: its `message_history` starts empty, so it has not seen what its parent or a sibling observed and must not inherit their bucket. `delegate.py`'s display-only `agent_id` is 32-bit-truncated — too collision-prone to key persistent state.

The map is in memory only, an LRU capped at `MAX_OBSERVED_SCOPES` (256) scopes. Every delegation mints a scope that outlives its run, so an uncapped map would grow one dead bucket per delegation for the process lifetime. Eviction is safe here, unusually for a cache: it only *relaxes* to "must Read again" — an overwrite under an evicted scope is refused with a pointer to `Read`, costing one round trip, never permitting an ungrounded overwrite. A process restart does the same wholesale, which is why nothing is persisted to disk.

**Consequences.** A `mode="w"` overwrite can no longer destroy content the model never looked at, and a race with an out-of-band edit (another process, another agent, the user) is caught rather than lost. The cost is one round trip — Read, then retry — on a path a well-behaved model rarely takes (it should Read before it Writes).

Memory is bounded at 256 buckets of path→hash entries (~200 bytes each), however many delegations a long-lived process (a web runner, heavy `DelegateToAgent` fan-out) serves. A lookup refreshes its scope's recency, so chatty delegations sharing the process cannot evict an active conversation.

**Alternatives rejected.**
- *Always allow `mode="w"`, no gate* — a stale or ungrounded overwrite has no recovery.
- *Warn but proceed* — the model already ignores softer nudges elsewhere; only a hard block makes the invariant hold.
- *Key the map by session alone, not run-scope* — a delegated sub-agent would see its parent's or a sibling's observations as its own, despite starting with empty history.
- *A raw `ContextVar` holding the dict* — a sub-agent's writes would not reach its parent or sibling tasks (see Decision).
- *No eviction* — correct but leaks one dead bucket per delegation on a long-lived process, and since eviction degrades safely (one extra Read), unboundedness buys nothing.
- *A TTL instead of LRU* — adds a clock dependency and evicts recently used scopes on age alone; recency is cheaper and fairer.
- *Evict `_path_locks` too* — dropping a lock between two concurrent acquirers voids its mutual exclusion, and the lock map is bounded by distinct written paths, not delegation count.

**Where it lives.** `src/zrb/llm/tool/file_observation.py`, `src/zrb/llm/tool/file_write.py`, `src/zrb/llm/tool/file_read.py`, `src/zrb/llm/tool/file_edit.py`, `src/zrb/llm/agent/run/runner.py` (`current_agent_run_scope`, `run_scope` param on `run_agent`), `src/zrb/llm/agent_state.py`, `src/zrb/llm/task/llm_task.py` (passes `conversation_name` as `run_scope`), `src/zrb/llm/tool/delegate.py` (deliberately omits it), `test/llm/tool/test_file_write.py`.
