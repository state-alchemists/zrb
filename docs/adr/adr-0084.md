# ADR-0084 — `write_file(mode="w")` refuses to overwrite a file this run hasn't observed

**Status:** Accepted

**Context.** `write_file(mode="w")` against an existing file blindly truncates it, regardless of whether the current agent run has ever seen that file's current content. A model that writes from a stale mental model of a file — one it never read this run, or read several turns ago before something else changed it — silently destroys whatever was actually there, with no recovery.

**Decision.** `write_file(mode="w")` against a pre-existing file is blocked unless this run has already observed that file's exact current content, via a prior `Read`, or a prior `Write`/`Edit` that itself now reflects the file's true on-disk state. `record_observed(abs_path, content)` is called after each such operation; `check_observed(abs_path)` re-hashes the file right before a `mode="w"` overwrite and blocks with a `[SYSTEM SUGGESTION]` to re-read first if there is no record, or if the record no longer matches (something else changed the file since). `mode="a"` is exempt — it is non-destructive to existing content, so the gate only guards the destructive path.

The observed-content map (`file_observation.py`'s `_observed`) is a plain `dict` keyed by a run-scope id, not a `ContextVar` holding the dict directly: a `ContextVar` only propagates within one asyncio task's context tree, so a value a sub-agent's task `.set()`s would never reach its parent or siblings. Keying a plain dict by an already-`ContextVar`-scoped run id sidesteps that — mirroring `plan.py::TodoManager`'s own keyed-dict pattern for the same class of run-scoped state.

The run-scope id itself is a new `current_agent_run_scope` ContextVar, bound once per `run_agent()` call. A top-level conversation passes its stable session name (`conversation_name`), so the record survives across that conversation's turns. A delegated sub-agent (`delegate.py`) deliberately passes nothing, taking a fresh full-entropy `uuid4` instead: a sub-agent's `message_history` starts empty, so it hasn't seen what its parent or a sibling observed, and must not inherit their bucket. `delegate.py`'s own display-only `agent_id` is a 32-bit-truncated id — too collision-prone for a map that keys persistent state, unlike the fresh `uuid4`.

No disk persistence; the map is an LRU capped at `MAX_OBSERVED_SCOPES` (256) scopes, least-recently-used scope first. Every delegation mints a fresh scope that outlives its run, so an uncapped map would grow one dead bucket per delegation for the process lifetime. Eviction is safe here in a way it rarely is for caches: the map only ever *relaxes* to "must Read again" — an overwrite under an evicted scope is refused with a pointer back to `Read`, costing one extra round trip, never allowing an ungrounded overwrite. A process restart has the same effect wholesale, which is why nothing is persisted to disk.

**Consequences.** A `mode="w"` overwrite can no longer destroy content the model never actually looked at, and a race with an out-of-band edit (another process, another agent, the user) is caught rather than silently lost. The cost is one more round trip — a blocked write means Read, then retry — on a path a well-behaved model rarely takes anyway (it should already Read before it Writes). Memory is bounded by the cap: at most 256 buckets of path→hash entries (~200 bytes each), regardless of how many delegations a long-lived process (a web runner, heavy `DelegateToAgent` fan-out) serves over its lifetime. A lookup under an existing scope refreshes its recency, so an active conversation is not evicted out from under itself by chatty delegations sharing the process.

**Alternatives rejected.** *Always allow `mode="w"`, no gate* — the status quo this replaces; a stale or ungrounded overwrite has no recovery. *Warn but proceed* — the model already ignores softer nudges elsewhere; a hard block is what makes the invariant actually hold. *Key the map by session alone, not run-scope* — a delegated sub-agent would then see its parent's or a sibling's observations as if it had read those files itself, despite starting with empty history. *A raw `ContextVar` holding the dict* — would not propagate a sub-agent's writes back to its parent or across sibling sub-agent tasks, since `ContextVar` values are confined to one task's context tree. *No eviction at all* — the original posture; correct but leaks one dead bucket per delegation on a long-lived process, and since eviction degrades to safe behavior (one extra Read), unboundedness bought nothing. *A TTL instead of LRU* — adds a clock dependency and evicts recently-used scopes on age alone; recency is both the cheaper and the fairer signal. *Evict `_path_locks` too* — dropping a lock between two concurrent acquirers voids the mutual exclusion it exists for, and the lock map is bounded by distinct written paths, not delegation count.

**Where it lives.** `src/zrb/llm/tool/file_observation.py`, `src/zrb/llm/tool/file_write.py`, `src/zrb/llm/tool/file_read.py`, `src/zrb/llm/tool/file_edit.py`, `src/zrb/llm/agent/run/runner.py` (`current_agent_run_scope`, `run_scope` param on `run_agent`), `src/zrb/llm/agent_state.py`, `src/zrb/llm/task/llm_task.py` (passes `conversation_name` as `run_scope`), `src/zrb/llm/tool/delegate.py` (deliberately omits it), `test/llm/tool/test_file.py`.
