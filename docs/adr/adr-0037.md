# ADR-0037 — Provider-agnostic, multi-vendor LLM support

**Status:** Accepted

**Context.** Locking to one vendor is exposure on cost, availability and terms of service, and teams want to choose a model per workload.

**Decision.** Model selection is configuration — model string, base URL, API key — resolved through pydantic-ai's provider abstraction. Each vendor SDK (anthropic, openai, cohere, google-genai, xai, groq, bedrock, …) is an optional extra, imported lazily per ADR-0033.

**Consequences.** Switching provider is an env var, not a code change, which makes cost optimization and failover practical. The cost is that zrb must track capability and error-shape quirks across every provider it claims to support — ADR-0038 and ADR-0039 exist because of this decision.

**Alternatives rejected.** *Single-vendor lock-in* — simpler everywhere, but it is the exposure this decision exists to avoid. *A bespoke provider abstraction* — duplicates what pydantic-ai already maintains, and would have to track every vendor's API drift.

**Where it lives.** `src/zrb/config/mixins/llm_core.py`, `pyproject.toml` (provider extras), `docs/configuration/llm-config.md`.
