# ADR-0075 — Shift+Tab cycles the interaction mode, with a Termux-detected Tab fallback

**Status:** Accepted

**Context.** zrb already had the two modes Claude Code's Shift+Tab cycles
between, but as **independent** controls: plan mode (a read-only permission
preset, ADR-0063) and yolo (auto-approval, `bool | frozenset[str]`, ADR-0062).
Users reached for one key that steps through an ordered set of modes with a
persistent badge and found neither the gesture nor the indicator. There was also
no first-class **auto-accept-edits** middle state, even though selective yolo can
express exactly that.

**Decision.** One key cycles three modes, reusing the existing enforcement
machinery — no new policy, no new permission primitive:

| Cycle step | plan store | yolo store |
| --- | --- | --- |
| `normal` | BUILD | `False` |
| `accept_edits` | BUILD | `frozenset({"Write", "Edit"})` |
| `plan` | PLAN | `False` |

- **State is derived, not stored.** `current_cycle_mode()` reads the two live
  stores and returns a name; advancing writes **both**, so plan and
  auto-approve can never stack. There is no third "current mode" cursor to drift
  out of sync with the stores that actually gate tools.
- **`accept_edits` is selective yolo** over the model-visible edit tool names,
  matched by the existing membership check. File writes auto-approve; shell,
  delegation and fetch still prompt.
- **Off-cycle yolo resets predictably.** Full yolo or a custom set is reported
  as such and is not a cycle member; the key re-enters at `normal`, so the
  gesture is always defined.
- **A persistent badge** in the status bar shows the mode and the hint.
- **Binding.** `s-tab` is bound unconditionally. Plain `tab` is bound **only
  under Termux**, where Tab and Shift+Tab both emit byte `0x09` and cannot be
  distinguished. Detection is a config knob, `CFG.IS_TERMUX`, auto-detected from
  `TERMUX_VERSION` or a `PREFIX` containing `com.termux` (either signal
  suffices, surviving a stripped environment) and overridable in both
  directions — so a user on any terminal where Shift+Tab does not survive can
  force the fallback. Both bindings keep a filter so a completion menu or a
  choice widget still owns Tab.
- **Freeing the key.** Shift+Tab was already bound: the input and output
  controls bound Tab and Shift+Tab to focus traversal, and control-level
  bindings sit at the **highest** precedence layer, so an app-level binding was
  silently shadowed. Rather than fight precedence, the two focus bindings were
  removed and `Ctrl+K` became the sole focus toggle — chosen over the original
  F6 because Termux maps F-keys to system actions, and it collides only with
  Emacs-mode kill-line.
- **`Ctrl+P` retired; slash commands kept.** The cycle reaches plan mode, so the
  redundant direct toggle went. `/plan` and `/yolo` remain: they are the only
  way to reach these modes in the web and multi-UI surfaces, and they are
  scriptable.

**Consequences.** One keystroke matches Claude Code, and auto-accept-edits
becomes a named, displayed state instead of folklore. Desktop terminals get the
expected behaviour with Tab free, Termux keeps a working cycle, and misdetection
in either direction is one env var away. Costs: the cycle imposes a linear order
on two orthogonal toggles, so combinations like plan-plus-custom-yolo remain
reachable only through the explicit controls, by design; the binding is
CLI-only; and the shared badge advertises only Shift+Tab, which understates the
Termux fallback.

**Alternatives rejected.** *Win the precedence fight with `eager=True`* — works,
but leaves two contradictory handlers registered for one key and relies on a
subtle priority rule. *Keep `Ctrl+P` alongside the cycle* — redundant surface
once the cycle reaches plan mode. *A new mode enum value for auto-accept-edits*
— unnecessary; selective yolo already encodes it, and a third enum would split
one concept across two stores. *A stored "current mode" cursor* — a third source
of truth that can disagree with the stores tools actually consult. *Bind both
keys on every terminal* — the original wiring; it imposes Termux's limitation on
every platform and makes Tab unusable for anything else. *Bind only Shift+Tab
with no fallback* — clean for desktop, silently removes mode cycling on Termux.
*Detect Termux inline at the call site* — no override for misdetection, and it
buries a reusable platform fact in the UI layer.

**Where it lives.** `src/zrb/llm/ui/base/model_commands.py`,
`src/zrb/llm/ui/default/keybindings.py`, `src/zrb/llm/ui/default/output.py`
(status bar), `src/zrb/config/helper.py` (`is_termux`),
`src/zrb/config/mixins/foundation.py` (`IS_TERMUX`).
