# ADR-0023 — Config resolution order: env var, then `default_factory`, then attribute default

**Status:** Accepted

**Context.** Config needs runtime overrides, computed defaults (one setting derived from another — paths under `ROOT_GROUP_NAME`, styles from the active theme), and static fallbacks.

**Decision.** On read, `EnvField` resolves in order: (1) the env var `{PREFIX}_NAME` or an alias, (2) `default_factory(self)` evaluated at read time, (3) the `DEFAULT_<NAME>` attribute set in the mixin's `__init__`. Unset and nullable yields `None`; otherwise the empty string.

**Consequences.** Twelve-factor overrides, computed defaults, and static defaults that are greppable by `DEFAULT_`. This one chain is also what makes themes (ADR-0027) work without new machinery. The cost is three places to look when reasoning about a value.

**Alternatives rejected.** *A single default map* — loses mixin ownership of defaults. *Env-or-`None`* — forces users to set everything. *A config file as the primary source* — adds file I/O and parsing to every startup, and contradicts ADR-0024.

**Where it lives.** `src/zrb/config/env_field.py`, `src/zrb/config/helper.py` (`get_env` tries names in order), `docs/configuration/env-vars.md`.
