# ADR-0127 — Usage is what pydantic-ai already reports, kept locally and read back as `/usage`

**Status:** Accepted

**Context.** pydantic-ai ends every run with a `RunUsage` carrying fifteen counters: input, output, cache read, cache write (and a 1-hour cache tier), reasoning tokens, audio tokens and seconds, request count, tool-call count, unmeasured-request count, details, and a `cost` when the model is priced. zrb read that object and printed three fields to the transcript — Total, Input, Output — then discarded it. Once the terminal scrolled, "what did this session cost" had no answer.

The reference harness answers the same question from local data: Claude Code's `/usage` computes its session block from local session history, not from an API. Its display is a total cost, an API duration beside a wall duration, a per-model breakdown of input / output / cache read / cache write / dollars, and a prompt-cache line giving the share of input served from cache.

Two of those shapes do not transfer. Claude Code's `/usage` also reports a subscription allowance (rolling 5-hour and weekly windows); zrb has no plan to measure against, and talks to Anthropic, OpenAI, Google, DeepSeek, Qwen, Moonshot, Z.AI and local Ollama models. And a dollar figure is meaningless for a model with no price — printing `$0.00` for a local run would say "free" when the truth is "unknown".

**Decision.**

1. **Record at the runner, not at the UI.** The UI already accumulates session totals, but a headless run has no UI and would be invisible. `_stream_one_round` writes the line at the moment the result arrives, so every round that reports usage is counted, interactive or not.

2. **Numbers only, so it can be on by default.** A record holds token and request counts, the model name, the session name, the run's duration, its cost, and per-tool call and error counts keyed by tool name. No prompt text, no tool arguments, no file content; a tool's name says which tool ran, never what it was given. That is what separates it from a trace, which must be opt-in.

3. **One file per month** (`~/.zrb/llm-usage/usage-YYYY-MM.jsonl`), named by the record's UTC month. A window bound is converted to UTC before its month is chosen, so local midnight on the 1st in a zone ahead of UTC still reads the previous month's file — a UTC+14 user asking for January would otherwise miss a row stored under December. A week's question reads one file, a month's reads one; a single growing file would be scanned whole by every query.

4. **The cache ratio is pydantic-ai's own definition.** `cache_read_tokens / input_tokens` — not a subtraction — because `input_tokens` already includes the cached reads for every provider, which is what makes the number comparable across them. `UsageRecord.cache_hit_ratio` repeats the formula rather than re-deriving it.

5. **Unpriced is unknown, not zero.** A model with no price shows `—` and a footnote counting the runs, and a row with some priced and some unpriced runs is marked `*`. A fabricated zero would be a lie in the same table as real money.

6. **Accounting never fails a turn.** A write that hits a full disk or a read-only home returns `None` and logs at debug; a corrupt line is skipped on read rather than making the whole history unreadable. A run that reported nothing at all — no request, no tokens — is not recorded, which also keeps a mocked agent in a test from writing a zero row per round.

7. **`/usage` renders four windows, and no argument means all of them.** `all` is the default because that is the question being asked: Claude Code's `/usage` reports what the plan has consumed, not what the current chat consumed, and a local log only answers "what have I spent" when it is read across sessions. `session` (this conversation, falling back to today when a headless run left no name), `today` (local midnight, not UTC's) and `week` (the last seven days) are one word away. It reads the log and never contacts a provider.

8. **A conversation is selected by its stable key, not its display name.** Auto-naming renames a conversation after its first turn (`bold-arch-1234` → `bold-arch-1234-greetings`, ADR-0109), so a row recorded before the rename stopped matching a filter on the current name and the first turn's usage vanished from its own session total. `UsageRecord.session_key` is `get_conversation_key(session)` — the identity sub-agent transcripts and session ownership already key on — and it is derived on read rather than stored, so rows written before this change are matched too.

9. **The reply is drawn in a panel where the UI has one.** A per-model table is read, not glanced at, and in the transcript it scrolls away with the next turn. `ActionCommand(panel_title=…)` routes the reply to `BaseUI.show_panel`: the default prints it under its title, so every UI shows the same content, and the default `UI` overrides the destination to fill the same panel `/btw` uses (docked above the input, never a float over the transcript). One panel serves both, so whatever asked for it last owns it — a `/btw` answer still on its way is dropped rather than painted over the table. The body is shown as written: a fixed-width table is laid out by its writer, so there is no markdown pass and nothing to re-wrap.

10. **Tool and journal telemetry sit under the same `/usage`, with no new subcommand.** The default output gains a `Tools` and a `Journal` section after the table, over the same period argument, and a section with no data in the window is omitted rather than printed as zeros.

    - *Tools.* `UsageRecord` carries `tool_counts` and `tool_errors` (`{name: n}`). They are counted once per round by `count_tool_calls`, read off the round's own `new_messages()` inside `_record_run_usage`: every call and its result are already there, so nothing runs per token or per tool call. A failure is a tool return whose outcome is `failed` or `retried` (or a retry prompt addressed to a tool). Lines written before the fields existed read back as empty, and a malformed map drops only itself. `/usage` lists the top tools by calls and errors, and the registered tools with zero calls — relative to this machine's current fixed tool set (`tool_registry.get_tools()`; per-run factory tools such as MCP and LSP are not in it).
    - *Journal events.* A second append-only log, `journal-YYYY-MM.jsonl`, sits in the same directory with the same month files and read tolerance (`zrb.llm.journal_usage_log`). One line per event: `injected` (bytes, whether the cap truncated, the hashed ids of the notes whose HUD line was injected), `searched` (word count, result rows, hashed ids of the notes the rows came from), `read`, `written`, `superseded`, `deleted` (a hashed id), each with a timestamp and the conversation key. The seams are the existing single points: `render_journal_index`, `search_journal`, the three write tools' entry points, and `read_file` for a path under the journal directory, counted only when the read succeeded (its result opens with the `[File: ` header; every refusal starts with `Error`). The auto-search of a first message goes through `find_in_journal`, which does not record, so it is never counted as the agent's own search.
    - *Transactions.* Inside `journal_transaction`, a change is not real until the body returns. `JournalTransaction.write_note`, `delete_note` and `supersede_note` each queue one event, and a public tool called inside the block queues into the same list instead of recording; the queue is flushed once, in order, after the commit, and a body that raises discards it, so a rolled-back change leaves no event. Outside a transaction a tool records immediately.
    - *Note ids are hashes.* A slug carries meaning, so the log stores the first ten hex digits of `sha256("category/slug")`. `/usage` resolves a hash to a title by scanning the current journal at display time; a note that no longer exists reads as `(removed)`. No title, slug, query, HUD line or note text is ever recorded.
    - *What the Journal section answers.* Average bytes injected per turn and the share truncated; searches, the share that found nothing, and how many were followed immediately (same conversation, no other journal event between) by another search; notes written and how many were read afterwards; and the injected HUD notes that were never read nor returned by a search in the window.
    - *Recording never raises.* Both recorders catch only the file-system and encoding errors a write can raise and log at debug. There is no off switch beyond `LLM_USAGE_DIR`, which moves both logs, matching the usage log itself.

**Consequences.** The log grows with use — one small line per round — and is never rotated; a year of heavy use is a few megabytes, and the month split keeps reads cheap. Attribution stops at the model: a delegated sub-agent's run is recorded with the parent's session and `kind="turn"`, so `/usage` sees the tokens but cannot yet say which sub-agent spent them. `kind` exists in the record for that, and for compaction and summarization runs, which are not distinguished yet either.

One boundary is worth stating: `/save <name>` copies a conversation to a new identity, so turns recorded before the save are filed under the old key and do not appear in the saved conversation's `session` total. Repairing that would mean migrating records on save; `today`, `week` and `all` still count them.

The one number that pays for this immediately is the cache line. ADR-0042 says to keep the cached prefix byte-stable; every miss re-bills the conversation. Until now that rule had no measurement behind it.

**Alternatives rejected.**

- *Compute usage from the saved history files* — they carry messages, not usage; the counts exist only on the run result.
- *Ask the provider afterwards* — none of the eight providers zrb speaks offers a per-turn usage query, and local models have no such endpoint at all.
- *Keep the totals in the UI only* — dies with the session, and misses headless runs entirely.
- *Record OpenTelemetry spans instead* — spans answer a different question (which phase took the time: approval wait, speech, compaction) at a much higher cost. Tokens and cost need none of it, so the cheap feature goes first.
- *Print `$0.00` for an unpriced model* — reads as "free" when it means "unknown", in a table whose whole purpose is cost.

**Where it lives.** `src/zrb/llm/usage_log.py` (`UsageRecord`, `record_usage`, `read_records`, `count_tool_calls`), `src/zrb/llm/journal_usage_log.py` (`JournalEvent`, the `record_*` functions, `read_events`), `src/zrb/llm/custom_command/usage_command_tools.py` and `usage_command_journal.py` (the two sections), `src/zrb/llm/prompt/live_context.py`, `src/zrb/llm/tool/journal.py`, `journal_write.py` and `file_read.py` (the event seams), `src/zrb/llm/agent/run/runner.py` (`_record_run_usage`), `src/zrb/llm/custom_command/usage_command.py` (`/usage`), `src/zrb/llm/custom_command/action_command.py` (`panel_title`), `src/zrb/llm/ui/base/ui.py` (`show_panel`), `src/zrb/llm/ui/default/ui.py` and `src/zrb/llm/ui/default/side_question.py` (the panel it fills), `src/zrb/config/mixins/llm_content.py` (`LLM_USAGE_DIR`), `src/zrb/config/mixins/llm_ui_commands.py` (`LLM_UI_COMMAND_USAGE`), `test/llm/test_usage_log.py`, `test/llm/test_usage_log_tools.py`, `test/llm/test_journal_usage_log.py`, `test/llm/tool/test_journal_usage_events.py`, `test/llm/custom_command/test_usage_command.py`, `test/llm/custom_command/test_usage_command_sections.py`.
