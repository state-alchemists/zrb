# ADR-0025 — White-labeling through `_ZRB_ENV_PREFIX` and `ROOT_GROUP_NAME`

**Status:** Accepted

**Context.** Organizations want to ship a rebranded CLI — `acme` rather than
`zrb` — with their own env-var namespace, without maintaining a fork.

**Decision.** Every config env var is read as `{ENV_PREFIX}_NAME`, where
`ENV_PREFIX` comes from the meta-variable `_ZRB_ENV_PREFIX` (default `ZRB`).
That one variable is deliberately never auto-prefixed, which resolves the
bootstrap chicken-and-egg. The CLI command name comes from
`CFG.ROOT_GROUP_NAME`. A custom `__main__.py` sets both before serving.

**Consequences.** A full rebrand happens from one entry point, and several
branded CLIs coexist on one machine without env collisions. The cost is that
white-labelers must translate `ZRB_` to their own prefix in their docs and
scripts.

**Alternatives rejected.** *Hardcode `ZRB`/`zrb`* — forces a fork for what is a
naming change. *A per-distribution config file* — file I/O at startup, and it
contradicts ADR-0024. *Inject the prefix through `Config.__init__`* — breaks
the singleton, since config is read during import of modules that run before
any such call.

**Where it lives.** `src/zrb/config/mixins/foundation.py` (`ENV_PREFIX`),
`src/zrb/runner/cli.py`, `docs/advanced-topics/white-labeling.md`.
