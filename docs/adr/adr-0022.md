# ADR-0022 — `EnvField` descriptor instead of hand-written config properties

**Status:** Accepted

**Context.** Every env-backed setting used to be a hand-written `@property`
getter (read env, cast, default) plus a setter that wrote or deleted
`os.environ` — roughly four methods of boilerplate each, and error-prone to
keep consistent across a hundred settings.

**Decision.** A reusable data descriptor, `EnvField(cast, serialize=…,
aliases=…, default_factory=…, nullable=…)`, collapses the pattern to one line
per setting. Its `__get__`/`__set__` reproduce the old property behaviour
exactly, so no caller changed. Genuinely irregular knobs — non-prefixed keys,
post-read transforms — stay hand-written on purpose.

A field also answers three questions a plain read cannot: `env_key(prefix)` (the
variable it writes), `serialize(value)` (how a value is rendered into it), and
`is_set(prefix)` (whether the user set it, aliases included). These reach
callers through `CFG` — `CFG.is_env_set("LLM_INCLUDE_SECTIONS")` — rather than
through `type(CFG).<NAME>`, so consumers keep the flat access ADR-0021
promises and never touch a descriptor. `is_set` exists because "chosen" and
"defaulted" are indistinguishable from the value alone, and some precedence
rules turn on the difference: a prompt preset supplies its own section list only
when `LLM_INCLUDE_SECTIONS` names none (ADR-0075).

**Consequences.** Around a hundred lines of boilerplate per mixin disappeared,
and read precedence and write semantics became uniform. The cost is a custom
descriptor to understand instead of plain properties.

**Alternatives rejected.** *Keep hand-written properties* — the maintenance
burden that prompted this. *Dataclasses* — cannot intercept reads and writes
against live `os.environ`. *Pydantic `BaseSettings`* — over-engineered here,
and it takes away direct `os.environ` control, which white-labeling (ADR-0025)
depends on.

**Where it lives.** `src/zrb/config/env_field.py` — its docstring lists exactly
which knobs are not migrated, and why.
