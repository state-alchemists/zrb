# ADR-0069 — Background work inherits permissions, interrupts to ask, and can be waited on with a bound

**Status:** Accepted

**Context.** Long, independent work — research, file generation, a slow build — should not block the main agent. But a detached agent has no obvious way to get tool approval: the synchronous approval model assumes the *parent blocks* while the UI is free. And checking whether detached work finished costs a model round-trip per poll, so the model either busy-polls or sleeps too long, with no way to say "block until done, but not forever".

**Decision.** `DelegateToAgentBackground` spawns a detached `asyncio` task and returns a handle immediately; `GetDelegationResult(handle)` collects it, and `MonitorProcess(handle)` does the same for background shell commands (ADR-0066). Polling is model-driven, so no lifecycle surgery is required.

**Inherited authority.** The task **copies the spawning context**, so it inherits the main agent's permissions, approval channel and UI. When a tool needs approval, its `BufferedUI` forwards to the parent UI's confirmation queue (ADR-0070), which **interrupts and prompts the user** — exactly like a synchronous delegate. Fan-out is simply several background agents.

**Bounded wait.** Both collection tools take `wait: float = 0` (and `kill: bool = False`). With `wait > 0` the call blocks up to `min(wait, CFG.LLM_BACKGROUND_WAIT_MAX)` seconds using `asyncio.wait`, which does **not** cancel on timeout, so the work continues. It returns the instant the work finishes, or else the usual "still running" status so the model can wait again or kill. `LLM_BACKGROUND_WAIT_MAX` defaults to 300s and is the only CFG timeout in seconds rather than milliseconds, because it is LLM-facing.

**Late spawns get authority explicitly.** Copying the context is correct only when the task is spawned *while the parent's scope is still bound* — true for `DelegateToAgentBackground` and every other `asyncio.create_task`/`ensure_future` site in `llm/`. The exception is `live_session.py`'s "keep talking to a sub-agent directly" continuations (ADR-0083 Phase E): a human's follow-up can spawn `_continue_live_session` via `asyncio.ensure_future` long after the delegation's `run_agent()` returned and reset its `ContextVar`s, so ambient inheritance would pick up whatever the TUI's own context holds, not what the delegation was granted. `live_session.py` therefore captures an `AuthoritySnapshot` (`llm/agent/run/authority_snapshot.py`) at session creation, while the scope is bound, and passes its `permission_policy`/`yolo`/`sandbox_policy` explicitly to each continuation's `run_agent()`. Any future spawn site that is detached only after its originating scope exits should do the same. This is resolved at `run_agent()`'s entry — the one place "explicit arg wins, else ambient" is decided for every run, immediate or late.

**Inside a running turn,** `permission_gate`/`sandbox_gate` (`agent/gates.py`) are consulted from `SafeToolsetWrapper.call_tool`, the chokepoint every tool call passes through:
- **Sandbox policy** — nothing mutates it mid-run, but it was still ambient state, so `run_agent` resolves it once and passes it via `agent.run(deps=...)`. `sandbox_gate` reads `ctx.deps` instead of the `ContextVar`, falling back to the ambient read only for the one caller with no `RunContext` (`create_safe_wrapper`'s own defense-in-depth gate, redundant with the chokepoint for real invocations).
- **Permission policy** — deliberately stays ambient: `get_effective_policy()` re-checks `current_agent_mode` on every call so a mid-run mode switch (the model calling `ExitPlanMode`) takes effect for the rest of that run (`test_in_run_mode_switch_propagates_to_caller`). A per-run snapshot would silently stop honoring it.
- **`yolo`** — already a closure variable resolved at `create_agent()` time, never read from a `ContextVar` in the approval path.

**Consequences.** Delegation is non-blocking without auto-approving or silently denying, and N polling round-trips collapse into one bounded, early-returning call. The wait is `async`, so the event loop stays free and a background sub-agent's approval prompt still surfaces through the parent's queue while the main loop is parked in the wait (covered by a regression test). Costs: results are not durable across a process restart; if the main agent stops polling before the user answers, the sub-agent parks on the prompt until answered (model pacing, not a bug); a runaway `wait` is capped.

**Alternatives rejected.**
- *Fail closed* — auto-deny anything not pre-approved. An earlier iteration; it made the feature useless: a "write a poem" delegation had `Write`, then `Shell`, then `echo` denied, and the agent gave up empty-handed.
- *Auto-approve everything* — an earlier iteration that worked but granted the sub-agent *more* permission than a non-yolo parent has. A sub-agent must not exceed its parent.
- *Push a notification on completion* — requires injecting results into a future turn, which is lifecycle surgery.
- *True in-call async* — a pervasive refactor of the per-turn synchronous model.
- *`asyncio.wait_for` for the bounded wait* — cancels the task on timeout, which is exactly wrong: the work must continue.
- *An unbounded `wait`* — one tool call could hang the entire turn.

**Where it lives.** `src/zrb/llm/tool/delegate_background.py`, `src/zrb/llm/tool/shell_background.py`, `src/zrb/llm/ui/default/confirmation.py`, `src/zrb/config/mixins/llm_limits.py` (`LLM_BACKGROUND_WAIT_MAX`), `src/zrb/llm/agent/run/authority_snapshot.py` and `src/zrb/llm/agent/subagent/live_session.py` (explicit authority propagation for post-scope continuations); `src/zrb/llm/agent/gates.py` (`sandbox_gate`'s `ctx.deps` read), `src/zrb/llm/agent/common.py` (`SafeToolsetWrapper.call_tool` passing `ctx` through) and `src/zrb/llm/agent/run/runner.py` (resolving and passing `deps=` into `agent.run()`) for the chokepoint-level fix.
