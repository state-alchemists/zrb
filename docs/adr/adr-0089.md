# ADR-0089 — Home-level `AGENTS.md`/`CLAUDE.md` are listed as user guidance, not as project overrides

**Status:** Accepted (refines ADR-0036)

**Context.** `create_project_context_prompt` searches for `AGENTS.md`,
`CLAUDE.md`, `GEMINI.md`, and `README.md` across a path built from `~/.claude`
plus every parent of the cwd (`_get_search_directories`), and lists every hit
under a single heading, **Documentation Files Found**. The prompt then made
reading them mandatory:

> **Reading is mandatory.** … use the `Read` tool to read each of these files in
> full before you search or edit the project's code:
> 1. `AGENTS.md` — project conventions … 2. `CLAUDE.md` — **project-specific overrides** …

Because `~/.claude` is unconditionally on the search path, a `~/.claude/CLAUDE.md`
is found from *every* working directory on the machine — verified from an
unrelated temp directory. Three problems follow:

1. **A mandatory read that is usually irrelevant.** Every session in every
   directory begins by reading a file about the user's cross-project habits,
   whether or not the turn has anything to do with them.
2. **A false label.** A home-level file is presented under the same heading and
   the same "project-specific overrides" description as the repo's own
   `CLAUDE.md`, so the model is told a user-wide preference has project
   authority.
3. **Cross-contamination in isolated runs.** Benchmark trials, sub-agent
   worktrees, and one-shot runs in scratch directories all inherit the
   operator's personal instructions as if they were the task's project rules.

**Decision.** Keep the same search path — discovering these files is useful — and
split the *presentation and the obligation* by scope.

- `project_context` renders two headings. **Documentation Files Found** holds
  project-scoped hits (anything from the cwd's parent chain). **User-Level
  Guidance** holds home-scoped hits, labelled "Outside this project — the user's
  cross-project preferences, not project rules. Not part of the mandatory read;
  consult only when the turn's work depends on it."
- The Project Documentation rule reads exactly the paths under **Documentation
  Files Found**, and states that User-Level paths are not part of the mandate and
  never override a project file.
- "Home-scoped" is defined narrowly: the home directory itself and `~/.claude`.
  Those are the two entries the search path contributes regardless of cwd; every
  other entry comes from the parent chain and is genuinely project scoped.
- If home cannot be resolved, hits fall into the mandatory bucket — the
  pre-split behavior is the safe default.

**Consequences.**

- *Good.* The mandatory read is now scoped to files that actually describe the
  project. Sessions in unrelated directories no longer open with an irrelevant
  full-file read.
- *Good.* The model is no longer told that a user-wide file carries project
  authority, so a home-level convention cannot silently outrank `AGENTS.md`.
- *Good.* Isolated runs (evaluation harnesses, worktrees, scratch dirs) stop
  inheriting the operator's personal instructions as project rules.
- *Cost.* A user who relied on `~/.claude/CLAUDE.md` being read unconditionally
  now gets it read only when relevant. That is the intended change: a global
  preference file that must be honoured every turn belongs in
  `ZRB_LLM_PROMPT_DIR` or a registered section (ADR-0061), which are the
  mechanisms for always-on content.
- *Neutral.* Discovery is unchanged — the file is still surfaced by path, one
  `Read` away.

**Alternatives rejected.**

- *Drop `~/.claude` from the search path.* Loses the information entirely. The
  problem is the obligation and the label, not the discovery.
- *Inline home-level content instead of listing its path.* Pays the token cost
  on every request in the cached prefix — worse than one conditional read, and
  it would still misrepresent scope.
- *Keep one heading and soften the mandate's wording.* The heading is what the
  model pattern-matches on; two buckets with different obligations need two
  headings.
- *Classify by "is it under the cwd" instead of "is it home".* Equivalent for the
  common case but wrong when the project legitimately lives under `~` — the
  parent chain would then include home and every ancestor, and a repo at
  `~/work/app` would have its own parents reclassified. Naming the two
  cwd-independent entries is exact.
