# ADR-0089 — Oversized tool results spill to a queryable store instead of being truncated

**Status:** Accepted

**Context.** A tool can return a payload large enough to dominate the context window. zrb's global backstop (`LLM_MAX_TOOL_RESULT_CHARS`) is *documented* as a cap, but ADR-0043 made it metadata-only: the model-facing `return_value` goes through whole, and only an `{"oversized": True, ...}` flag is recorded, so a real cap could be "decided separately on evidence." A pathological result (a minified 200k-char JSON, a huge MCP payload) therefore lands in history in full and is re-sent every turn until the summarizer compresses it.

Truncating is lossy: it discards the middle of the payload, where a JSON value or test failure often sits. pydantic-ai-harness's `ToolOutputLimits` offers a lossless alternative: `Spill` persists the full return to an overflow store and hands the model a handle plus a preview, paged back on demand by a `ReadToolResult` tool. That is the mechanism adopted.

**Decision.** When `LLM_ENABLE_TOOL_SPILL` is on and a non-multimodal tool result's model-facing text exceeds `LLM_MAX_TOOL_RESULT_CHARS`, zrb spills it rather than passing it whole: the full payload is written to a local overflow store, `return_value` becomes a spill preview (a `ReadToolResult` handle, a one-line shape sketch for structured values, and a head/tail preview), and the handle is stashed in `ToolReturn.metadata` — app-only, never sent to the model.

The common function-wrapper and toolset-wrapper paths apply this after a `PostToolUse` hook has made its final output decision.

A new `ReadToolResult(handle, offset, limit, from_end, pattern)` tool, tagged `Capability.META`, reads slices of a spilled payload, bounded in lines and characters so one call cannot itself overflow the context. Read-back output is not spilled again.

The store is a leaf module (`zrb.llm.agent.spill`) with a module-level `LocalFileStore` singleton shared by the spill path and the read tool. Security mirrors the harness: the root is created `0700`, refuses a symlink or (on POSIX) a directory not owned by the current user, and `read` resolves the target (following symlinks) before rejecting anything that escapes the root via symlink, `..`, or an absolute path; handle segments are sanitized.

The default root is under the system temp directory, an intentional sandbox writable root. Before a spill writes or `ReadToolResult` reads, zrb applies the active sandbox policy to that root; a deployment that lists it among denied paths disables the relevant operation.

**Consequences.** Oversized results no longer bloat the context or get silently lost; the full payload is recoverable on demand. It makes `LLM_MAX_TOOL_RESULT_CHARS` real, losslessly, reconciling its docstring with ADR-0043. Costs: the `ReadToolResult` schema ships on every request (only when spill is on); spilled files persist under the store root until the OS or a user removes them (new disk state). Off by default, since enabling it changes behavior (oversized results stop arriving whole); kept opt-in until measured.

**Alternatives rejected.** *Lossy truncation (the harness's `Truncate`)* — throws away the payload's middle; ADR-0043 already defers that. *Summarize at the source (the harness's `Summarize`)* — an LLM call on the hot tool-return path, and zrb already summarizes fat results in history; redundant. *Adopt `pydantic-ai-harness`'s `ToolOutputLimits` directly* — adds a 0.x alpha dependency for a mechanism zrb can own as a small leaf module. *A per-run store rather than a shared root* — the harness keeps a shared root so a later run or agent can read a spill; zrb mirrors that.

**Where it lives.** `src/zrb/llm/agent/spill.py`, `src/zrb/llm/agent/common.py` (`create_safe_wrapper`), `src/zrb/llm/common_tools.py` (registers `ReadToolResult`), `src/zrb/config/mixins/llm_limits.py` (`LLM_ENABLE_TOOL_SPILL`).
