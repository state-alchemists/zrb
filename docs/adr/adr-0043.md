# ADR-0043 — A tool result reaches the model once, through `ToolReturn.return_value`

**Status:** Accepted

**Context.** `ToolReturn` exposes two model-facing fields and they are **additive**, not alternative: `return_value` becomes the `ToolReturnPart` — the tool-result message — while `content` is documented as "content sent to the model as a separate `UserPromptPart`", intended for payloads a tool result cannot carry natively, such as an image a tool produced.

Every zrb tool wrapper populated both, on the reading that `content` was the model-facing string and `return_value` the structured value for programmatic consumers. There were no programmatic consumers: the only two readers of `.return_value` passed it straight back into another `ToolReturn`.

Measured against a real 9-turn session: 73,321 chars of `ToolReturnPart` against 74,025 chars of byte-identical `UserPromptPart`. No sanitizer strips a `UserPromptPart` — `sanitize_history`, `filter_nil_content` and `sanitize_orphaned_tool_calls` all key off `tool_call_id`, which a user part does not have — so the duplicate persisted into saved history and was re-sent every following turn: **73.6k of 356.3k input tokens, 21%**.

Worse, pydantic-ai appends all user parts after all tool-return parts, so each tool batch was followed by a `role: user` message containing the tool output. The model saw eight apparent user turns that were tool results, and could no longer locate the user's actual last turn — the shape of the observed re-analysis loops.

The size backstop applied to `content` only, so it never bounded what the model read; it shrank the duplicate. The gate and error paths had the mirror-image bug: `return_value=None` with the real message in `content` meant the model read a literal `null` tool result with the explanation arriving as a separate user turn.

**Decision.** Everything the model should read goes in `return_value`, and `content` is left unset. The invariant has one named home, `agent/tool_result.py::tool_return`, imported by both `agent/common.py` and `agent/gates.py`, so it is stated once and cannot be re-broken silently.

**`return_value` keeps the tool's own shape** — it is not stringified. Each provider serialises the field differently and two behaviours depend on it: Google's `model_response_object()` passes a dict through as the native `functionResponse`, while a string gets wrapped and `structured_content()` degrades to `None`; and the OpenAI/Anthropic/Mistral path extracts multimodal parts *out of* `return_value` into a trailing user message, so stringifying replaces an image with a Python repr and drops the file.

**The size cap is deliberately not made real here.** Because it only ever applied to the duplicate, capping `return_value` now would silently truncate payloads the model previously received in full — a behaviour change smuggled into a bug fix. `_oversize_metadata` records the fact in metadata, never sent to the model, so a real cap can be decided separately on evidence. That cap landed in ADR-0089: with `LLM_ENABLE_TOOL_SPILL` on, an oversized result spills losslessly to a queryable store instead of being passed whole; with it off, the metadata-only flag described here remains the behaviour.

Consequently: a `PostToolUse` hook's `updatedToolOutput` replaces `return_value` and `additionalContext` is appended to it; gate denials and tool errors *are* the tool result rather than a null plus a user turn; and `_tool_response_payload` reads `return_value`, which also hands hooks the structured dict instead of its string form.

**Consequences.** Tool-result tokens are halved and stop compounding across turns, and tool results stop presenting as user turns. A differential over 14 payload shapes — str, dict, nested dict, list, int, bool, None, empty string, empty dict, `BinaryContent`, list-with-image, unicode, oversized str, oversized dict — against `model_response_str`, `model_response_object`, `files` and `structured_content` reports **zero provider-visible deltas**; the only difference is the removed duplicate.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Keep `content`, drop `return_value` | Not possible; `return_value` is required and *is* the tool result. |
| Stringify `return_value` | The first draft; it reads uniformly but breaks Google's structured `functionResponse` and destroys every image an MCP tool returns. |
| Strip the duplicate `UserPromptPart` in `sanitize_history` | Treats the symptom, leaves the double payload inside the run that produced it, and adds a pass that must distinguish a real user turn from an echoed tool result. |
| Keep the duplicate | 21% of input tokens plus the turn-boundary corruption, for a change measured at zero provider-visible delta. |
| Patch pydantic-ai | The library matches its documented contract; the misuse was ours. |

**Where it lives.** `src/zrb/llm/agent_tool_result.py`, `src/zrb/llm/agent/common.py`, `src/zrb/llm/agent/gates.py`, `test/llm/test_agent_tool_result.py` (pins occurrence count and part-kind sequence with `FunctionModel`).
