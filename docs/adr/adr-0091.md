# ADR-0091 — The `explicit` profile carries demonstrations only, not re-phrasings

**Status:** Accepted (narrows ADR-0083)

**Context.** ADR-0083 introduced model-adaptive profiles: `terse` (the base
`*.md` files) and `explicit`, "a more directive register for weaker models."
It shipped two variant files — `persona.explicit.md` (re-phrased imperatively)
and `examples.explicit.md` (worked few-shot blocks) — and stated the premise
as *"Weak ≠ fewer rules: the explicit profile is more directive, not shorter."*

Measured on the composed prompt, `explicit` was **+638 tokens (+8.3%)** over
`terse`, with **37 negative phrasings** ("never", "do not", "no …") against
terse's 27, while **82% of its lines were byte-identical** to terse. The
sections a weaker model most plausibly trips on — the Priority Order's
precedence-not-sequence abstraction, the Working Loop's four-column routing
table, Skill Activation's 90- and 110-word paragraphs, the Journal's five-row
classification table — carry no variant at all and were unchanged.

Three findings contradict the "more directive" premise:

1. **More constraints hurt weaker models most.** Adding explicit instructions
   and constraints can reduce task performance, and the effect is stronger for
   smaller and weaker models, which have less capacity to balance competing
   directives ([arXiv 2601.22047][interference]).
2. **Prohibitions decay; affirmative steps persist.** Omission constraints
   ("never do X") degrade as context grows, while commission constraints
   ("before Y, verify Z") stay stable ([arXiv 2604.20911][omission]). The
   `explicit` variant added ten more of the decaying kind.
3. **Demonstrations are the supported lever.** Few-shot examples help more as
   task complexity rises and model capability falls; selection and format
   matter more than volume.

So the one element of `explicit` that the evidence supports is the examples.
The re-phrasing was cost without a mechanism — and it had already drifted:
`persona.explicit.md` lacked `persona.md`'s "Narrate only at key moments" rule,
the variant-drift risk ADR-0083 named as accepted.

**Decision.** A profile variant may add **demonstrations**. It may not add,
re-phrase, or restate **rules**.

- `persona.explicit.md` is deleted. `persona` has no variant, so `explicit`
  resolves it to the base file through the existing fallback in
  `_load_prompt_for_profile` — no code change.
- `examples.explicit.md` keeps its `<example>` blocks and drops the prose gloss
  that followed each one; every gloss restated a rule already stated in
  `persona`, `workflow`, or the uncertainty ladder.
- `explicit` is therefore **`terse` plus worked examples** — never longer in
  rule text, only in demonstration.

**Consequences.** `explicit` drops from ~8,314 to ~8,034 tokens against terse's
~7,676; the whole remaining delta is example blocks. Variant drift is bounded
to one file whose content carries no rules, so a rule updated in the base can
no longer go stale in a variant. Tests that used `"No preamble"` as the marker
for "the explicit profile loaded" now key on `"Worked Examples"`, and a new
test pins the fallback: a section with no variant resolves to its base under
`explicit`.

The profile axis is now thin — `explicit` differs from `terse` only by an
examples section that the base already partially ships. Whether it still earns
a separate axis, versus an examples-only knob, is left open.

**Alternatives.** *Keep `persona.explicit.md` and shorten it* — still spends
tokens on re-phrasing, the mechanism the evidence does not support. *Build the
missing `workflow.explicit.md`* — the four register-sensitive behaviors ADR-0083
named (autonomy/persistence, todo cadence, code-comment policy, verify/test
intensity) all live there with no variant, so this looked like the obvious gap;
rejected for now because it would add rule text to the models least able to
carry it. The gap is better closed by converting omission constraints to
commission form in the **base**, which helps every model. *Retire profiles
entirely* — premature; the examples axis is doing real work.

**Evidence.** Composed-prompt measurements taken from
`PromptManager(skill_manager=None).compose_prompt()` under
`ZRB_LLM_PROFILE=terse|explicit`, and a detached worktree at the pre-change
commit for the before/after baseline.

[omission]: https://arxiv.org/pdf/2604.20911
