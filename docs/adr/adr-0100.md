# ADR-0100 — `tool_guidance` deleted; `register_section` is the extension point

**Status:** Accepted (supersedes ADR-0043 and ADR-0086 where they describe the registry, extends ADR-0098)

**Context.** The `tool_guidance` section composed to **5,178 chars** from a
registry of 24 static entries plus 6 dynamic factories, rendered as a "Tool
Usage Guide" of `- **ToolName**: when to use / * key rule` lines, filtered at
runtime against the resolved tool names.

It duplicated, by design, information that also had to exist in the tool
docstrings — and the two were kept in sync by hand. That failed at least once in
a way `AGENTS.md` records: `DelegateToAgent`'s guidance entry and the Working
Loop shipped **two different trigger lists for one decision**.

The registry also had real API weight. `add_tool_guidance`,
`add_tool_group`, `add_tool_guidance_factory`, and
`add_tool_guidance_section_factory` were implemented separately on
`PromptManager`, `LLMTask`, `ChatBuilding`, and `SubAgentManager`, with a
per-agent copy-and-merge path in the sub-agent manager to stop the process-wide
singleton accumulating entries across unrelated `create_agent` calls.

**Decision.** Delete the section, the `ToolGuidance` dataclass, the
`ToolCatalogue`/`ToolGroups` types, `get_tool_guidance_prompt`, and all four
hosts' registration methods. Delete `PromptManager.tool_names`, whose only
purpose was filtering the catalogue.

The 30 entries land in three places:

- **Genuine cross-tool forks** append a line to the relevant docstring, where
  the model reads them next to the schema.
- **Turn-level policy** becomes a `### Tool usage` block in `workflow` — four
  rules: files go through the file tools; batch independent calls; never guess
  an argument; read a tool's own description before first use.
- **The model-aware parallel-tool-call block** moves into `system_context` as a
  `- Parallel tool calls: …` line. It is a stable fact about the model (it only
  changes on `/model`, which recomposes the prompt anyway), so it belongs with
  OS, CWD, and the model identity rather than in a section of its own.
- **The rest** — `TodoRead`, `ListWorktrees`, `LspFindDefinition`, and similar —
  are dropped. Their docstrings already say what they do.

`register_section(name, provider)` (ADR-0061) is the documented replacement for
downstreams that were calling `add_tool_guidance`: it already composes a
provider against the active context at a configured position, which is strictly
more than the guidance registry offered.

**Consequences.**

- ~1,300 tokens leave the prompt; ~300 tokens of docstring come back.
- **This is a public API break**, taken deliberately rather than shimmed:
  `ToolGuidance` is removed from `zrb.__init__`, and the four
  `add_tool_guidance*` methods are gone. Code calling them raises
  `AttributeError` rather than silently no-oping, which is the loud failure a
  clean break should produce.
- One source of truth per tool. A cross-tool rule now lives in exactly one
  docstring, so there is no second copy to drift.
- The runtime tool-name filter is gone with the catalogue. Guidance for a tool
  that is not registered can no longer leak, because there is no guidance —
  and a deferred tool's docstring only materializes when the model searches for
  it, which is a better version of the same property.
- `SubAgentManager` loses its guidance copy-and-merge path and its
  `inherit_sections` no longer needs to special-case `tool_guidance`.

**Alternatives rejected.**

- *Keep the registry, cut the built-in entries to ~8.* Preserves the API and
  most of the win, but keeps the two-sources-of-truth structure that produced
  the divergent delegation triggers.
- *Keep it as-is.* Leaves the inverted rules-to-tool-docs ratio that ADR-0098
  exists to correct.
