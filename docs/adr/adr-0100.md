# ADR-0100 — An opt-in Stop hook reviews each file-changing turn before it ends

**Status:** Accepted

**Context.** PR #534 took three review rounds. Each time, the CI reviewer (`zrb code review`, run by `code-review.yml`) found a defect in the agent's change, the user pasted the finding back into the chat, and the agent fixed it. All three findings shared one shape: the change altered a data format or promised a guarantee, and was tested only on the path it created — not on the other code that reads the format, and not on data written before the change. The agent could have caught each one; the reviewer that did catch them started from the diff with a fresh context, not from the author's transcript.

Everything a local loop needs already existed: a Stop hook returning `decision: "block"` extends the turn with its reason (`session_extension.py`), agent-type hooks run a sub-agent with named tools, and the Stop payload already carried the turn's messages and a `wrote_files` gate. A user could approximate the loop with a JSON agent hook, but four gaps made that version poor. The payload had no list of changed files, so the reviewer had to guess the scope from `git diff`. An agent hook's input is the author's transcript, which is costly and carries the author's framing. The global block cap of 8 is the only bound on rounds. And the default 30-second hook timeout is too short for a review.

**Decision.** Ship a built-in self-review gate (`llm/hook/self_review.py`), off by default behind `LLM_SELF_REVIEW_ENABLED`, registered as a default hook factory on every `HookManager` like the journal-compliance judge.

- **Scope is the working directory's diff since the turn started.** While the gate is on, a top-level turn snapshots its working directory before its first model request (`agent/run/turn_snapshot.py`), and the Stop payload carries it as `turn_start_snapshot` (`{workdir, tree, store, unreadable}`). At Stop the gate snapshots the directory again and diffs the two. A file git cannot read at Stop is listed for the reviewer instead of diffed, and counts as a change when the turn-start snapshot could read it or did not have it; one unreadable at both — a root-owned volume's file — shows no sign of the turn, and counting it would review every turn. A snapshot is the one ADR-0101 describes — every repository under the directory by its own ignore rules, nested repositories and submodules included, and the loose files outside them up to a budget — so the diff covers edits made through `Shell` and changes the turn committed, in every repository under the directory, and leaves out the user's uncommitted work from before the turn.
- **The turn's store is temporary and owner-only.** It lives in the system temp directory, reads the objects of every repository it lists as alternates — so tracked files are not copied, and only untracked files' contents are written, into the store alone — and is deleted when the turn ends, on success, error or cancellation. A cancelled turn waits for a snapshot still running to stop before its next git command (`run_in_worker`), so the store is never deleted while git writes to it. A snapshot that fails, for any reason — a working directory deleted mid-session included — deletes its store at once and leaves the turn without one; a snapshot never fails a turn. A directory over the listing's budget, or too large to hash within a git command's 30-second cap, is reported once and not tried again for the rest of the process: every attempt would fail the same way, the slow one after holding the turn up.
- **The gate only reads the turn's store.** The runner deletes that store when the turn ends — for a cancelled turn, possibly while the review still runs — so the gate takes its Stop snapshot and diff in a second temporary store, which starts from the turn store's objects and stat cache and which the gate deletes itself.
- **A repository that appears during the turn is diffed from where it started.** A worktree `EnterWorktree` creates, or a clone, has no entry in the turn-start tree, so its whole checkout would show as added. The gate adds its baseline first, from the commit it started from — its oldest `HEAD` reflog entry — and judged by the repository itself: each file it reports unchanged since that commit (`git diff --name-only`) is taken as it is now, each file it reports changed as the commit's content in the form its own checkout writes (`git cat-file --filters`), and a file the commit lacks is left out; a changed file the final snapshot lacks counts as deleted only while the listing would still take it. The diff then shows what the turn changed in it. Where that commit came from is read from git's structure: from the main repository for a linked worktree, from a remote when a remote-tracking ref holds it (a clone). Otherwise the repository started here (`git init`), with or without commits yet, and gets no baseline: all of it is new.
- **What the diff does not cover is listed, not diffed.** The Stop payload also carries `changed_paths`, the paths the turn's `Write`/`Edit`/`RM`/`MV` calls named. Those the diff does not cover — ignored, or outside the working directory — are listed for the reviewer to read. When there is no snapshot they alone are the scope, with no diff: a `git diff HEAD` over them would carry the user's uncommitted work from before the turn. A turn with nothing in scope is not reviewed. A working directory over the snapshot budget is reported once per session, as a warning, and its turns are reviewed from those paths. A file git cannot read at Stop is listed as unreadable rather than diffed, where it would read as deleted.
- The gate is **synchronous**, so it can block. It builds an ordinary agent hook through the registration seam `hook.manager` already uses (ADR-0086) and hands it a review request — the changed paths and their diff — instead of the transcript. The reviewer gets read-only tools (`Read`, `Grep`, `Glob`) so it can check the code around the diff, which is where the #534 defects were.
- The reviewer's prompt is `llm/prompt/markdown/self_review.md`, overridable like the other internal prompts. It asks specifically for the other readers and writers of a changed format, guarantees against pre-existing data, and doc claims the code does not keep.
- Only a closing `Request changes` verdict blocks. `LGTM`, an unclear verdict, a failed review, or an unavailable builder all let the turn end: a broken reviewer must never hold the author's turn hostage.
- The block reason tells the author to **check** each finding against the code, fix the real ones, and say why any is not a defect — findings are evidence to verify, not orders — and to restate its complete answer, since the continuation replaces the original response.
- **The timeout is enforced inside the hook.** The gate enforces `LLM_SELF_REVIEW_TIMEOUT` (default 240s) itself, as one deadline over the whole review. Every git command that resolves the scope gets only the time left before that deadline, and is killed when it runs out: cancelling cannot stop a git command a worker thread is already running. The reviewer runs under `asyncio.wait_for` in the hook's own event loop, where cancellation reaches `agent.run()`. A timed-out review ends the turn unreviewed. The executor's timeout is set past the deadline so it never fires first: it would end the review as a failed hook rather than a timed-out review.
- **A cancelled review stops.** The hook executor runs a synchronous hook's coroutine with `asyncio.run` on a pool thread. When its caller is cancelled — the user cancels the turn — or its own timeout passes, it cancels the hook inside that loop, where the cancellation reaches the reviewer's model request, rather than abandoning the thread while the request runs on, and waits for the hook to finish before its caller goes on. The scope is resolved through `run_in_worker`, so a cancelled review starts no further git command, waits for the one running, and deletes its store before the hook returns. Every synchronous hook gets the same: a command hook's process is killed. The wait is bounded — `cancel_grace_seconds`, 5 by default — so a hook blocked where cancellation cannot reach it, in a synchronous call or a git command near its cap, is left to finish with a warning rather than holding the turn.
- **A delegated sub-agent's run is not reviewed.** `run_agent` marks a run started inside another run's scope as nested; it takes no snapshot, and the gate skips its Stop (`nested_run` in the payload). What a sub-agent changes lands in the parent's working directory, or in a worktree under it, so the parent's diff covers it. Reviewing every sub-agent too would multiply reviewer runs and give each a diff mixing in its parallel siblings' changes. A live sub-agent continuation (`subagent/live_session.py`) is not nested: it runs after the parent's turn has ended, so no parent review covers it, and it is reviewed as a run of its own.
- `LLM_SELF_REVIEW_MAX_ROUNDS` (default 2) caps consecutive blocking reviews. The count is kept per run (the Stop payload's `run_scope`), since concurrent sessions share one hook manager, and exists only while the gate holds the turn open: a review that lets the turn end clears it, and a turn's first Stop, where `stop_hook_active` is false, restarts it. So the gate keeps no state for a finished turn — a turn cancelled mid-continuation leaves one entry until its run's next turn — and a turn another hook extends after a pass can be reviewed again, within the runner's global block cap. `LLM_SELF_REVIEW_MODEL` picks a different reviewer model; empty uses the run's own.

**Consequences.** On a file-changing turn the agent's defects surface inside the turn instead of in a later PR review the user relays by hand. The cost is two snapshots per turn — measured on this repository at 0.10s and 0.3 MB at turn start and 0.02s at Stop; the turn-start one hashes the whole directory, since each turn's store starts empty, so a 30,000-file, 119 MB repository takes 0.30s — and one reviewer run per turn that changed something, plus one per extra round, which is why the gate is opt-in. A process killed mid-turn can leave its owner-only store behind in the system temp directory. The reviewer model receives the turn's diff, including any secret the turn itself wrote; a separate `LLM_SELF_REVIEW_MODEL` may be a different provider. Files git ignores, and files outside the working directory, appear in the scope only when a file tool named them, and then without a diff. The CI reviewer's inline prompt in `zrb_init.py` is separate and unchanged.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Document a JSON agent-hook recipe only | Leaves the four gaps above; each needs code. |
| Scope by the file tools' paths alone | Misses edits made through `Shell`, shows nothing for changes committed mid-turn, and mixes the user's own uncommitted edits into the diff. Kept only as the fallback when there is no snapshot. |
| Scope by `git status` / `git diff HEAD` | Mixes in the user's uncommitted work from before the turn, misses changes committed during it, and sees one repository only. |
| Snapshot the enclosing repository with `git add -A` | Git's walk stops at a nested repository and records a gitlink, so a nested clone, a submodule, or a directory holding several repositories is invisible to the review. ADR-0101's listing sees inside them. |
| Snapshot each other repository a tool's `cwd` or path argument points into, before the tool runs | A guess from arguments: a command that changes directory itself (`cd lib && sed -i …`) or edits by relative path names no repository, so its changes go unreviewed. Listing every repository under the working directory needs no guess; a directory outside it is out of scope. |
| Graft the start commit's tree as a new repository's baseline | The commit holds clean blobs, the checkout what the repository's filters write: under `core.autocrlf` — the default on Windows — every text file of a fresh worktree is CRLF on disk and LF in the commit, so the whole checkout would read as changed. |
| Take a new repository's baseline when a tool first names it | The same guess. The commit a worktree or clone started from is recorded by git, so its baseline can be rebuilt at Stop. |
| Review each delegated sub-agent's run too | The parent's review already covers its changes; per-sub-agent reviews multiply reviewer runs, and parallel siblings share one working tree, so each diff would mix in the others' edits. |
| Reuse the rewind snapshots (`llm/snapshot/`) | Rewind needs a named conversation and lives in the interactive UI, while the gate also runs under `LLMTask`. Rewind's store keeps its own objects (ADR-0101); a per-turn store can borrow the repositories' objects, so its first snapshot costs a fraction as much. Both use the same `SnapshotStore`. |
| Snapshot into the repository's own object database | Persists untracked files' contents — secrets included — in `.git/objects` until garbage collection. |
| Leave pre-existing untracked files out of the snapshot | Keeps secrets out, but then an edit to an untracked file goes unreviewed; the private store keeps both. |
| Rely on the executor's timeout alone | It cannot stop a git command already running, and ends the review as a failed hook rather than a timed-out one. |
| Leave a cancelled hook's thread to finish | The reviewer's model request, or a command hook's process, runs on for up to the hook's timeout with nothing waiting for its result. |
| Prompt the main agent to self-review | The #534 defects came from the author's own blind spots; a fresh context is the point. Prose also proved unreliable in the transcripts that motivated this change. |
| Hand the reviewer the transcript as agent hooks normally do | Costly, and the author's reasoning is exactly the framing a reviewer should not inherit. |
| Block on any non-`LGTM` reply | An unclear or truncated reply would extend turns for nothing; blocking requires an explicit verdict. |
| Review with `Shell` available | A reviewer that can run commands can change state; reading is enough to check the code, and CI runs the tests. |
| On by default | A reviewer run per file-changing turn is a real cost most sessions have not asked for. |
