# ADR-0100 — An opt-in Stop hook reviews each file-changing turn before it ends

**Status:** Accepted

**Context.** PR #534 took three review rounds. Each time, the CI reviewer (`zrb code review`, run by `code-review.yml`) found a defect in the agent's change, the user pasted the finding back into the chat, and the agent fixed it. All three findings shared one shape: the change altered a data format or promised a guarantee, and was tested only on the path it created — not on the other code that reads the format, and not on data written before the change. The agent could have caught each one; the reviewer that did catch them started from the diff with a fresh context, not from the author's transcript.

Everything a local loop needs already existed: a Stop hook returning `decision: "block"` extends the turn with its reason (`session_extension.py`), agent-type hooks run a sub-agent with named tools, and the Stop payload already carried the turn's messages and a `wrote_files` gate. A user could approximate the loop with a JSON agent hook, but four gaps made that version poor. The payload had no list of changed files, so the reviewer had to guess the scope from `git diff`. An agent hook's input is the author's transcript, which is costly and carries the author's framing. The global block cap of 8 is the only bound on rounds. And the default 30-second hook timeout is too short for a review.

**Decision.** Ship a built-in self-review gate (`llm/hook/self_review.py`), off by default behind `LLM_SELF_REVIEW_ENABLED`, registered as a default hook factory on every `HookManager` like the journal-compliance judge.

- **Scope comes from git, not from tool calls.** While the gate is on, the runner snapshots the working tree at turn start (`util/git/worktree.py`: `git add -A` into a throwaway index, then `git write-tree`) and passes `{tree, store}` to Stop as `turn_start_snapshot`. The gate snapshots again and diffs the two trees. That covers edits made through `Shell` and changes the turn committed, and excludes the user's uncommitted work from before the turn.
- **Snapshots write nothing into the repository.** Hashing the working tree hashes untracked files too — a `.env`, a private key — and writing those blobs into `.git/objects` would copy secrets into the project's object database, recoverable until garbage collection and carried by any copy of `.git`. So every snapshot writes its index and objects into a private *store*: an owner-only temporary directory set as `GIT_OBJECT_DIRECTORY`, with the repository's own objects readable through `GIT_ALTERNATE_OBJECT_DIRECTORIES`. The runner creates the store before it starts the snapshot and deletes it when the turn ends, on success, error or cancellation; a snapshot still running in its worker thread when the turn is cancelled deletes the store again when it finishes. The repository's index, HEAD, files and object database are untouched. The Stop payload also gains `changed_paths`, the paths the turn's `Write`/`Edit`/`RM`/`MV` calls named: those the tree diff does not cover (ignored by git, outside the repository) are listed for the reviewer to read, and without both snapshots (outside git, or a snapshot that failed) they alone are the scope, with no diff: a `git diff HEAD` over them would carry the user's uncommitted work from before the turn. A turn with nothing in scope is not reviewed.
- The gate is **synchronous**, so it can block. It builds an ordinary agent hook through the registration seam `hook.manager` already uses (ADR-0086) and hands it a review request — the changed paths and their diff — instead of the transcript. The reviewer gets read-only tools (`Read`, `Grep`, `Glob`) so it can check the code around the diff, which is where the #534 defects were.
- The reviewer's prompt is `llm/prompt/markdown/self_review.md`, overridable like the other internal prompts. It asks specifically for the other readers and writers of a changed format, guarantees against pre-existing data, and doc claims the code does not keep.
- Only a closing `Request changes` verdict blocks. `LGTM`, an unclear verdict, a failed review, or an unavailable builder all let the turn end: a broken reviewer must never hold the author's turn hostage.
- The block reason tells the author to **check** each finding against the code, fix the real ones, and say why any is not a defect — findings are evidence to verify, not orders — and to restate its complete answer, since the continuation replaces the original response.
- **The timeout is enforced inside the hook.** The hook executor runs a synchronous hook's coroutine with `asyncio.run` on a worker thread and times out only the outer future, so its timeout abandons the thread while the reviewer's model request runs on. The gate therefore enforces `LLM_SELF_REVIEW_TIMEOUT` (default 240s) itself, as one deadline over the whole review. Every git command that resolves the scope gets only the time left before that deadline, and is killed when it runs out. Wrapping those commands in `wait_for` would not bound them, because cancelling cannot stop a worker thread and `asyncio.run` waits for its threads on exit. The reviewer runs under `asyncio.wait_for` in the hook's own event loop, where cancellation reaches `agent.run()`. The executor's timeout is set past the deadline so it never fires first. A timed-out review ends the turn unreviewed. Other synchronous agent hooks still have the executor's behaviour.
- `LLM_SELF_REVIEW_MAX_ROUNDS` (default 2) caps reviews per user turn; the counter restarts on the turn's first Stop, where `stop_hook_active` is false. `LLM_SELF_REVIEW_MODEL` picks a different reviewer model; empty uses the run's own.

**Consequences.** On a file-changing turn the agent's defects surface inside the turn instead of in a later PR review the user relays by hand. The cost is a working-tree snapshot per turn and one reviewer run per turn that changed something — plus one per extra round — which is why the gate is opt-in. A process killed mid-turn can leave its owner-only store behind in the system temp directory. The reviewer model receives the turn's diff, including any secret the turn itself wrote; a separate `LLM_SELF_REVIEW_MODEL` may be a different provider. Files git ignores appear in the scope only when a file tool named them. The CI reviewer's inline prompt in `zrb_init.py` is separate and unchanged.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Document a JSON agent-hook recipe only | Leaves the four gaps above; each needs code. |
| Scope by the file tools' paths alone | Misses edits made through `Shell`, shows nothing for changes committed mid-turn, and mixes the user's own uncommitted edits into the diff. Kept only as the fallback outside git. |
| Scope by `git status` / `git diff HEAD` | Mixes in the user's uncommitted work from before the turn, and misses changes committed during it. |
| Reuse the rewind snapshots (`llm/snapshot/`) | Rewind needs a named conversation, is off outside git repositories, and lives in the interactive UI, while the gate also runs under `LLMTask`. Its store must keep its own objects (ADR-0101); a per-turn store can read the repository's as an alternate, so its first snapshot costs a fraction as much. |
| Snapshot into the repository's own object database | Persists untracked files' contents — secrets included — in `.git/objects` until garbage collection. |
| Leave pre-existing untracked files out of the snapshot | Keeps secrets out, but then an edit to an untracked file goes unreviewed; the private store keeps both. |
| Rely on the executor's timeout | It abandons the worker thread without cancelling the reviewer, leaving the model request running. |
| Prompt the main agent to self-review | The #534 defects came from the author's own blind spots; a fresh context is the point. Prose also proved unreliable in the transcripts that motivated this change. |
| Hand the reviewer the transcript as agent hooks normally do | Costly, and the author's reasoning is exactly the framing a reviewer should not inherit. |
| Block on any non-`LGTM` reply | An unclear or truncated reply would extend turns for nothing; blocking requires an explicit verdict. |
| Review with `Shell` available | A reviewer that can run commands can change state; reading is enough to check the code, and CI runs the tests. |
| On by default | A reviewer run per file-changing turn is a real cost most sessions have not asked for. |

**Where it lives.** `src/zrb/llm/hook/self_review.py`, `src/zrb/llm/prompt/markdown/self_review.md`, `src/zrb/util/git/worktree.py` (the snapshots), `src/zrb/llm/hook/turn_evidence.py` (`turn_changed_paths`), `src/zrb/llm/agent/run/runner.py` and `turn_cursor.py` (the `turn_start_snapshot` and `changed_paths` payload fields, and deleting the store), `src/zrb/llm/hook/manager.py` (default factory), `src/zrb/config/mixins/llm_content.py` (`LLM_SELF_REVIEW_*`). Tests: `test/util/git/test_worktree.py`, `test/llm/hook/test_self_review.py`, `test/llm/hook/test_turn_evidence.py`, `test/llm/agent/run/test_runner_lifecycle.py`.
