# ADR-0100 — An opt-in Stop hook reviews each file-changing turn before it ends

**Status:** Accepted

**Context.** Defects in an agent's change often surface only when the CI reviewer (`zrb code review`, run by `code-review.yml`) reads the diff; the user then pastes the finding back into the chat and the agent fixes it, one review round per defect. These defects share a shape: the change alters a data format or promises a guarantee, and is tested only on the path it created — not on other code that reads the format, and not on data written before the change. The author could have caught them; the reviewer that does catch them starts from the diff with a fresh context, not from the author's transcript.

The pieces for a local loop exist: a Stop hook returning `decision: "block"` extends the turn with its reason (`session_extension.py`), agent-type hooks run a sub-agent with named tools, and the Stop payload carries the turn's messages and a `wrote_files` gate. A user-written JSON agent hook falls short in four ways: the payload has no list of changed files, so the reviewer guesses scope from `git diff`; an agent hook's input is the author's transcript, costly and carrying the author's framing; the global block cap of 8 is the only bound on rounds; and the default 30-second hook timeout is too short for a review.

**Decision.** Ship a built-in self-review gate (`llm/hook/self_review.py`), off by default behind `LLM_SELF_REVIEW_ENABLED`, registered as a default hook factory on every `HookManager` like the journal-compliance judge.

- **Scope is the working directory's diff since the turn started.** While the gate is on, a top-level turn snapshots its working directory before its first model request (`agent/run/turn_snapshot.py`); the Stop payload carries it as `turn_start_snapshot` (`{workdir, tree, store, unreadable}`). At Stop the gate snapshots again and diffs. Snapshots are ADR-0101's — every repository under the directory by its own ignore rules, plus loose files up to a budget — so the diff covers `Shell` edits and mid-turn commits in every repository, and excludes the user's uncommitted work from before the turn.
  - A file unreadable at Stop is listed for the reviewer instead of diffed (where it would read as deleted). It counts as a change when the turn-start snapshot could read it or lacked it; one unreadable at both (a root-owned volume's file) shows no sign of the turn and is not counted.
- **The turn's store is temporary and owner-only.** It lives in the system temp directory, uses every listed repository's objects as alternates (only untracked contents are written, into the store alone), and is deleted when the turn ends — success, error or cancellation.
  - A cancelled turn waits for a running snapshot to stop before its next git command (`run_in_worker`), so the store is never deleted mid-write.
  - A failed snapshot, for any reason (including a working directory deleted mid-session), deletes its store and leaves the turn without one; a snapshot never fails a turn.
  - A directory over the listing's budget, or too large to hash within a git command's 30-second cap, is reported once and not retried for the rest of the process.
- **The gate only reads the turn's store.** The runner deletes it when the turn ends — possibly mid-review for a cancelled turn — so the gate snapshots and diffs in a second temporary store, seeded from the turn store's objects and stat cache, which it deletes itself.
- **A repository that appears during the turn is diffed from where it started.** A worktree from `EnterWorktree`, or a clone, has no entry in the turn-start tree, so its whole checkout would show as added. The gate first adds a baseline from its start commit (its oldest `HEAD` reflog entry), judged by the repository itself:
  - files `git diff --name-only` reports unchanged since that commit are taken as they are now;
  - changed files take the commit's content in the form the checkout writes (`git cat-file --filters`); files the commit lacks are left out;
  - a changed file missing from the final snapshot counts as deleted only while the listing would still take it;
  - the start commit's origin is read from git's structure: the main repository for a linked worktree, a remote-tracking ref for a clone. Otherwise the repository began here (`git init`) and gets no baseline: all of it is new.
- **What the diff does not cover is listed, not diffed.** The payload's `changed_paths` holds the paths the turn's `Write`/`Edit`/`RM`/`MV` calls named. Those outside the diff (ignored, or outside the working directory) are listed for the reviewer to read. With no snapshot, they alone are the scope, without a diff — `git diff HEAD` would include pre-turn uncommitted work. A working directory over budget is warned about once per session and reviewed from these paths. A turn with nothing in scope is not reviewed.
- **The gate is synchronous, so it can block.** It builds an ordinary agent hook through the registration seam `hook.manager` already uses (ADR-0086), handing it a review request — changed paths and diff — instead of the transcript. The reviewer gets read-only `Read`, `Grep` and `Glob` to check the code around the diff.
- **The prompt** is `llm/prompt/markdown/self_review.md`, overridable like other internal prompts. It asks for other readers and writers of a changed format, guarantees against pre-existing data, and doc claims the code does not keep.
- **Only a closing `Request changes` verdict blocks.** `LGTM`, an unclear verdict, a failed review, or an unavailable builder lets the turn end: a broken reviewer must never hold the author's turn hostage.
- **The block reason** tells the author to check each finding against the code, fix the real ones, explain any non-defect (findings are evidence, not orders), and restate its complete answer, since the continuation replaces the original response.
- **The timeout is enforced inside the hook.** `LLM_SELF_REVIEW_TIMEOUT` (default 240 s) is one deadline over the whole review.
  - Each scope-resolving git command gets only the time left and is killed when it runs out, since cancellation cannot stop a command a worker thread already runs.
  - The reviewer runs under `asyncio.wait_for` in the hook's own event loop, where cancellation reaches `agent.run()`. A timed-out review ends the turn unreviewed.
  - The executor's timeout is set past the deadline so it never fires first; if it did, the review would end as a failed hook rather than a timed-out one.
- **A cancelled review stops.** The executor runs a synchronous hook's coroutine with `asyncio.run` on a pool thread. When its caller is cancelled or its timeout passes, it cancels the hook inside that loop — reaching the reviewer's model request — and waits for it before the caller continues.
  - Scope resolution runs through `run_in_worker`, so a cancelled review starts no further git command, waits for the running one, and deletes its store before returning.
  - Every synchronous hook gets this; a command hook's process is killed. The wait is bounded by `cancel_grace_seconds` (5 by default): a hook blocked where cancellation cannot reach is left to finish with a warning.
- **A delegated sub-agent's run is not reviewed.** `run_agent` marks a run started inside another run's scope as nested; it takes no snapshot, and the gate skips its Stop (`nested_run` in the payload). A sub-agent's changes land in the parent's working directory or a worktree under it, so the parent's diff covers them.
  - A message sent to a finished sub-agent from the TUI starts where no parent is bound, so it passes `nested=True` to `run_agent` explicitly.
  - A live sub-agent continuation (`subagent/live_session.py`) is not nested: it runs after the parent's turn ended, so it is reviewed as a run of its own.
- **`LLM_SELF_REVIEW_MAX_ROUNDS` (default 2) caps consecutive blocking reviews.** The count is per turn (the payload's `turn_id`), because concurrent sessions share one hook manager and may share a `run_scope` (the conversation's name).
  - It exists only while the gate holds the turn open: a passing review clears it, and a turn's first Stop (`stop_hook_active` false) restarts it.
  - A turn that ends another way mid-continuation (cancelled, capped) never clears its entry, so at most `LLM_SELF_REVIEW_MAX_TRACKED_TURNS` (64) are kept, oldest dropped first.
  - A turn another hook extends after a pass can be reviewed again, within the runner's global block cap.
- **`LLM_SELF_REVIEW_MODEL`** picks a different reviewer model; empty uses the run's own.

**Consequences.** Defects surface inside the turn instead of in a later review the user relays by hand. The cost is two snapshots per turn — measured on this repository at 0.10 s and 0.3 MB at turn start and 0.02 s at Stop; the turn-start one hashes the whole directory, since each turn's store starts empty, so a 30,000-file, 119 MB repository takes 0.30 s — plus one reviewer run per file-changing turn and per extra round. Hence opt-in.

A process killed mid-turn can leave its owner-only store in the system temp directory. The reviewer model receives the turn's diff, including any secret the turn wrote, and `LLM_SELF_REVIEW_MODEL` may be a different provider. Ignored files and files outside the working directory appear in scope only when a file tool named them, and then without a diff. The CI reviewer's inline prompt in `zrb_init.py` is separate and unchanged.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Document a JSON agent-hook recipe only | Leaves the four gaps above; each needs code. |
| Scope by the file tools' paths alone | Misses `Shell` edits and mid-turn commits, and mixes in the user's uncommitted edits. Kept only as the no-snapshot fallback. |
| Scope by `git status` / `git diff HEAD` | Includes pre-turn uncommitted work, misses mid-turn commits, and sees one repository only. |
| Snapshot the enclosing repository with `git add -A` | Git stops at nested repositories (gitlinks), hiding nested clones, submodules and directories of repositories. ADR-0101's listing sees inside them. |
| Snapshot each repository a tool's `cwd` or path argument points into, before it runs | A guess: `cd lib && sed -i …` or a relative-path edit names no repository, so its changes go unreviewed. Listing every repository under the working directory needs no guess. |
| Graft the start commit's tree as a new repository's baseline | The commit holds clean blobs, the checkout filtered ones: under `core.autocrlf` (default on Windows) every text file of a fresh worktree would read as changed. |
| Take a new repository's baseline when a tool first names it | The same guess; git records the start commit, so the baseline can be rebuilt at Stop. |
| Review each delegated sub-agent's run too | The parent's review covers it; per-sub-agent reviews multiply runs, and parallel siblings share a working tree, so each diff would mix in others' edits. |
| Reuse the rewind snapshots (`llm/snapshot/`) | Rewind needs a named conversation and lives in the interactive UI, while the gate also runs under `LLMTask`. Rewind's store keeps its own objects; a per-turn store borrows them, so its first snapshot costs a fraction. Both use `SnapshotStore`. |
| Snapshot into the repository's own object database | Persists untracked contents, secrets included, in `.git/objects` until garbage collection. |
| Leave pre-existing untracked files out of the snapshot | Keeps secrets out but leaves edits to untracked files unreviewed; the private store does both. |
| Rely on the executor's timeout alone | Cannot stop a running git command, and ends the review as a failed hook. |
| Leave a cancelled hook's thread to finish | The model request or command process runs on for up to the hook's timeout with no one waiting. |
| Prompt the main agent to self-review | These defects come from the author's blind spots; a fresh context is the point, and prose instructions proved unreliable. |
| Hand the reviewer the transcript, as agent hooks normally do | Costly, and the author's framing is what a reviewer should not inherit. |
| Block on any non-`LGTM` reply | An unclear or truncated reply would extend turns for nothing. |
| Review with `Shell` available | A reviewer that runs commands can change state; reading suffices, and CI runs the tests. |
| On by default | A reviewer run per file-changing turn is a cost most sessions have not asked for. |
