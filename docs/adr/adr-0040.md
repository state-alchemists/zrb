# ADR-0040 — Run-loop guards against corrupted history and degenerate output

**Status:** Accepted

**Context.** Two failure modes escape the stream-error classifier because neither raises where it can be caught, and both poison history so every later retry inherits the corruption.

*Orphaned tool-call metadata.* After a deferred tool is approved or denied the loop re-enters `run_stream_events()` with the resolved `DeferredToolResults`. Re-running the summarizer between those iterations could compress away the `ModelResponse` whose `tool_calls` match the pending results. pydantic-ai then finds no unprocessed tool calls and raises `UserError("does not contain any unprocessed tool calls")`. Unhandled, it reached the generic error handler, which injected `[SYSTEM] Error occurred:` into history and fed every task-level retry the same corrupted state — an infinite retry spiral.

*Degenerate model output.* Weak or overloaded models emit assistant turns with no text — narration goes into a `ThinkingPart` plus a tool call. The `filter_nil_content` sanitizer injected `TextPart("(tool call)")` whenever a response had no text, including tool-call-bearing turns. That placeholder is stored in history, re-sent every turn, and **the model learns to imitate it**: one production transcript showed 29 injected placeholders followed by 3 model-emitted imitations. Separately, under load a stream can *succeed* and return an empty completion, which the loop accepted and surfaced as the final answer.

**Decision.** Four guards, each at the layer that can actually see the problem.

**1. Do not re-run the summarizer between deferred iterations.** The deferred-tool branch carries `history` forward from `run_history` directly on every iteration. Summarization still runs in `_prepare_history` before the first stream call and on all non-deferred iterations.

**2. Catch the mismatch anyway.** `handle_stream_error` recognises that `UserError`, clears the stale results and retries with the *intact* history.

Returning intact history is load-bearing: the runner assigns `outcome.new_history` unconditionally and the next iteration passes it to `sanitize_history`, which raises `TypeError` on `None` — turning the rescue path into a hard crash. A one-shot gate stops re-entry on the same poisoned state.

**3. Scope the placeholder.** `filter_nil_content` injects `TextPart("(tool call)")` only when a response has **neither** text **nor** tool calls — the genuinely empty turn that Bedrock and OpenAI reject, as the code's own comment always intended. A tool-call-only turn is left text-less, so nothing imitable enters history.

**4. Reject empty completions.** After the stream, `_is_empty_completion` flags a blank-or-placeholder string output; the turn is regenerated after dropping the degenerate trailing `ModelResponse` (keeping tool returns, so the deferred-resume case still works), bounded by `max_empty_completion_retries` (default 2), then a clear `RuntimeError` rather than surfacing the placeholder or looping.

**Enforcement mechanism.** The invariants are named in code, not stated in comments — as loose locals, a plausible simplification (one end-of-turn slice against a fixed baseline, or a bare `history = run_history`) silently reintroduces the corruption.

- `TurnCursor` (`turn_cursor.py`, sibling to `RetryState`/`ExtensionState`/`PartialRunAccumulator`) owns guard 1's "carry forward, don't reapply" rule and the accumulation of a turn's new messages across rounds (needed for the STOP hook's `turn`/`wrote_files` payload). `carry_forward()` is the only place `history` is set from `run_history`; `commit_round()` is the only place a round's new messages join the turn's accumulator. Breaking either means deleting a named method, not editing an unmarked local.
- `sanitize_history`'s step order (guard 3 needs `filter_nil_content` before `sanitize_orphaned_tool_calls`) is an explicit `_SANITIZE_STEPS` tuple in `history_utils.py`, so reordering is a visible edit; a broken order surfaces as a DEBUG-level `_detect_problems` log right after the pipeline, at zero production cost like the existing pre-fix check.
- `drop_oldest_turn`'s `min_turns` (used by the prompt-too-long retry) is a `TurnPruneFloor` enum rather than a bare `0`/`1`, naming the "don't re-execute an approved deferred tool" reasoning guard 1 depends on.

**Consequences.** Both death spirals are cut at the root cause and backstopped at the symptom. A genuine answer is never empty prose, so guard 4 does not reject real output, and structured outputs and `DeferredToolRequests` are excluded by construction. The cost is a slightly larger retry state machine and one extra post-stream check per turn.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Increase the summarizer's keep window | Only probabilistically avoids the race, and risks context overflow. |
| Disable summarization | Undoes ADR-0041. |
| Patch pydantic-ai's deferred handling | A vendored fix that breaks on update. |
| Make the placeholder "non-imitable" | Fragile; any visible marker in history is imitable. |
| Drop the placeholder entirely | The truly-empty turns are genuinely rejected by providers, so it is still needed there. |
| Surface the empty output as the answer | A silent wrong result that also poisons the next turn. |
| Treat an empty completion as a stream error | It is not an exception; the stream succeeded, so the check belongs in the runner loop. |

**Where it lives.** `src/zrb/llm/agent/run/runner.py`, `src/zrb/llm/agent/run/retry_loop.py`, `src/zrb/llm/agent/run/history_utils.py`, `src/zrb/llm/agent/run/turn_cursor.py`, `docs/contributing/maintainer-guide.md`.
