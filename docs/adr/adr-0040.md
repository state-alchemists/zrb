# ADR-0040 — Run-loop guards against corrupted history and degenerate output

**Status:** Accepted

**Context.** Two failure modes escaped the stream-error classifier because neither raises where it can be caught, and both poisoned history so every subsequent retry inherited the corruption.

*Orphaned tool-call metadata.* After a deferred tool is approved or denied the loop re-enters `run_stream_events()` with the resolved `DeferredToolResults`. Re-running the summarizer between those iterations could compress away the `ModelResponse` whose `tool_calls` match the pending results. pydantic-ai then finds no unprocessed tool calls and raises `UserError("does not contain any unprocessed tool calls")` — unhandled, so it reached the generic error handler, which injected `[SYSTEM] Error occurred:` into history and poisoned every task-level retry with the same corrupted state. An infinite retry spiral.

*Degenerate model output.* Weak or overloaded models emit assistant turns with no text — narration goes into a `ThinkingPart` plus a tool call. The `filter_nil_content` sanitizer injected `TextPart("(tool call)")` whenever a response had no text, including tool-call-bearing turns. That placeholder is stored in history, re-sent every turn, and **the model learns to imitate it**: one production transcript showed 29 injected placeholders followed by 3 model-emitted imitations. Separately, under load a stream can *succeed* and return an empty completion, which the loop accepted and surfaced as the final answer.

**Decision.** Four guards, each at the layer that can actually see the problem.

**1. Do not re-run the summarizer between deferred iterations.** The deferred-tool branch carries `history` forward from `run_history` directly on every iteration. Summarization still runs in `_prepare_history` before the first stream call and on all non-deferred iterations.

**2. Catch the mismatch anyway.** `handle_stream_error` recognises that `UserError`, clears the stale results and retries with the *intact* history.

Returning intact history is load-bearing: the runner assigns `outcome.new_history` unconditionally and the next iteration feeds it to `sanitize_history`, which raises `TypeError` on `None` — a `None` here would turn the spiral into a hard crash on the very path meant to rescue it. A one-shot gate stops re-entry on the same poisoned state.

**3. Scope the placeholder.** `filter_nil_content` injects `TextPart("(tool call)")` only when a response has **neither** text **nor** tool calls — the genuinely empty turn that Bedrock and OpenAI reject. This aligns the code with the intent its own comment already stated. A tool-call-only turn is left text-less, so nothing imitable enters history.

**4. Reject empty completions.** After the stream, `_is_empty_completion` flags a blank-or-placeholder string output; the turn is regenerated after dropping the degenerate trailing `ModelResponse` (keeping tool returns, so the deferred-resume case still works), bounded by `max_empty_completion_retries` (default 2), then a clear `RuntimeError` rather than surfacing the placeholder or looping.

**Enforcement mechanism.** Guard 1's "carry forward, don't reapply" rule and the accumulation of a turn's own new messages across possibly-several rounds (needed for the STOP hook's `turn`/`wrote_files` payload) were originally two loose local variables in `_execution_loop`, with the invariant stated only in a comment — a plausible-looking simplification (a single end-of-turn slice against one fixed baseline, or a bare `history = run_history` with the comment deleted) silently reintroduces the corruption this ADR exists to prevent.

Both are now owned by `TurnCursor` (`turn_cursor.py`, sibling to `RetryState`/`ExtensionState`/`PartialRunAccumulator`): `carry_forward()` is the one and only place `history` is set from `run_history`, and `commit_round()` is the one and only place a round's new messages join the turn's accumulator — each named for the invariant it protects, so breaking either requires deleting a named method, not editing an unmarked local.

`sanitize_history`'s own step order (guard 3 depends on `filter_nil_content` running before `sanitize_orphaned_tool_calls`) is similarly now an explicit `_SANITIZE_STEPS` tuple in `history_utils.py` rather than three sequential statements — reordering the pipeline is a visible edit to that tuple, and a broken order surfaces as a DEBUG-level `_detect_problems` log immediately after the pipeline runs, at the same zero production cost as the existing pre-fix check.

`drop_oldest_turn`'s `min_turns` parameter (used by the prompt-too-long retry) is a `TurnPruneFloor` enum rather than a bare `0`/`1`, naming the same "don't re-execute an approved deferred tool" reasoning this ADR's guard 1 depends on.

**Consequences.** Both death spirals are cut at the root cause and backstopped at the symptom. A genuine answer is never empty prose, so guard 4 does not reject real output, and structured outputs and `DeferredToolRequests` are excluded by construction. The cost is a slightly larger retry state machine and one extra post-stream check per turn.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Increase the summarizer's keep window | Only probabilistically avoids the race, and risks context overflow. |
| Disable summarization | Undoes ADR-0041. |
| Patch pydantic-ai's deferred handling | A vendored fix that breaks on update. |
| Make the placeholder "non-imitable" | Fragile; any visible marker in history is imitable. |
| Drop the placeholder entirely | The truly-empty turns are genuinely rejected by providers, so it is still needed there. |
| Surface the empty output as the answer | A silent wrong result that also poisons the next turn. |
| Treat an empty completion as a stream error | It is not an exception; the stream succeeded, so the check belongs in the runner loop. |
