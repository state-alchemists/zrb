# ADR-0128 — Speech volume is a gain zrb applies to the samples it plays, named as a percentage or moved by a count of `+` and `-`

**Status:** Accepted

**Context.** zrb had no volume of its own. A backend renders speech at the level it chose, and zrb played it as delivered; the only lever was the machine's mixer, or a local engine's amplitude flag. In a voice-first session the voice *is* the interface, and "a bit quieter" is a request made mid-conversation, not a reconfiguration — it has to happen during the session, from the conversation itself.

Where the knob can live is decided by who owns the samples. When a backend renders audio for zrb to play (`create_audio`; the Pipecat services and the local voices do), every sample passes through `PcmUtterance._fill` on its way to the device. A local engine (`say`, `espeak-ng`, `termux-tts-speak`) and a cloud voice that hands its WAV to a player program (OpenAI, Gemini) never show zrb a sample at all.

**Decision.**

1. **A percentage of the speech's own level.** `LLM_SPEECH_VOLUME`, default 100, held inside 0–200. Not decibels: the user thinks in "a bit louder", and a percentage is the unit the mixer in front of them already uses. Above 100 is allowed because a quiet output device is a real reason to ask, and there is no way for zrb to know.

2. **Applied to the samples zrb plays, in integer arithmetic.** `sample * volume // 100`, clipped to what a 16-bit sample holds. Integer, not float, because this runs in PortAudio's real-time callback and a sample at 100% must come back bit-identical rather than re-rounded. Clipped, because a loud sample at 200% has nowhere left to go and wrapping it into the opposite sign is heard as a crackle.

3. **A sentence keeps the level it started with.** The volume is read when the utterance is made, not when each block is filled, so changing it mid-sentence does not fade the word being spoken — the same rule the barge-in bar already follows (ADR-0105). The next sentence is at the new level.

4. **A level is a number or a count of signs.** `/volume 15` sets the level to fifteen percent and `15%` is read the same; `/volume +++` raises three steps, `/volume --` lowers two, one sign is one step, and a step is ten percentage points. No argument reports the level. The two forms cannot collide because digits are a level only when they are the whole argument: a run of signs is a count of steps, and `-15` — neither a bare number nor a pure sign run — is read as a typo rather than given one of the two meanings silently. Both forms pass through the same clamp, so `/volume 500` lands at the 200% ceiling the way ten steps do, and a named level takes effect on the next sentence for the reason decision 3 gives. Mixed signs (`+-`), a word, or digits with anything else in them (`15 loud`) are typos too, and the help line says both forms. The command is `LLM_UI_COMMAND_VOLUME`, so it can be aliased or turned off like every other UI command.

5. **Offered with speech off, and honest where it does not apply.** The command exists whenever speech is enabled as a feature, even with the speaker switched off, because the level is what it comes back on at. When zrb is not the one playing — a player program, or a backend that renders nothing — the reply names the volume *and* says the program keeps its own, rather than reporting a level the next sentence will not honour. That answer is **observed, not predicted**: the speaker remembers whether the last sentence it made was a `PcmUtterance`. Asking the backend is wrong in both directions — a local engine answers "no zrb playback needed" and still renders a WAV for zrb to play — and a device that fails mid-sentence hands that sentence to a program, which flips the answer.

6. **The level is per session, not persisted.** A restart returns to `LLM_SPEECH_VOLUME`, like every other runtime control (`/speech`, `/yolo`). Persisting it would mean zrb writing its own configuration, which nothing else does.

**Consequences.** The voice can be adjusted while it is speaking, without touching the machine's mixer, and the level survives the session only as long as the session does. Above 100% the audio clips by nature: louder is possible, cleaner is not, and no amount of care in this layer recovers a peak the backend already rendered at full scale. A session played by a program is unaffected, and says so once per `/volume`. The known gap is the WAV path: a backend that hands a finished WAV to a player could be scaled before the file is written, and the streamed variant of that path would need a filtering reader — neither is done here, because the backends that use it are the ones zrb cannot play itself.

**Alternatives rejected.**

- *Drive the system mixer (`pactl`, `amixer`, `osascript`)* — changes the whole machine's volume rather than zrb's voice, needs a different program per platform, and would leave the user quieter after zrb is gone.
- *A volume flag per player program* — `afplay -v`, `paplay --volume` and `ffplay -volume` do not even agree on the range, and `aplay` has none; four formats to keep and one tool that silently cannot.
- *Scale the WAV before handing it to a player* — covers the finished-file path and not the streamed one, which exists so the first words start before the download ends.
- *Quiet / normal / loud* — three levels with nothing in between, and no way to say "two steps" or "a lot quieter", which is how the request is actually made.
- *Decibels* — a second unit to explain for no benefit at these levels; the mixer in front of the user reads percent.

**Where it lives.** `src/zrb/llm/speech/pcm_player.py` (`PcmUtterance._fill`, `clamp_volume`, `FULL_VOLUME`, `MIN_VOLUME`, `MAX_VOLUME`), `src/zrb/llm/speech/player.py` (`Speaker.volume`, `set_volume`, `is_playing_in_process`), `src/zrb/llm/speech/feature.py` (`/volume`, `change_volume`), `src/zrb/llm/speech/config.py`, `src/zrb/config/mixins/llm_speech.py` (`LLM_SPEECH_VOLUME`), `src/zrb/config/mixins/llm_ui_commands.py` (`LLM_UI_COMMAND_VOLUME`), `test/llm/speech/test_pcm_player.py`, `test/llm/speech/test_player_in_process.py`, `test/llm/speech/test_feature.py`. See ADR-0103 for what is spoken, ADR-0105 for the bar the level does not change, and ADR-0114 for the in-process player this scales.
