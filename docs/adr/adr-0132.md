# ADR-0132 — A send-now key moves a running delegation aside, so the message is read in the same turn

**Status:** Accepted.

**Context.** ADR-0123 gave the send-now key a way to reach a `Shell` call that is holding the turn: the command steps aside into the background under a handle, and the message is read in the same turn. A synchronous `DelegateToAgent` holds the turn the same way — the steered message waits for the next model request, and the next request is assembled only after the tool returns.

It holds it for longer. A shell command is bounded by its own timeout; a delegation runs a whole agent loop and can last an hour. In the session that prompted this record, one `DelegateToAgent` call ran for one hour and nine minutes while the user's message waited behind it, and the assistant was unreachable for that whole time.

The move itself already exists for tasks. `DelegateToAgentBackground` starts a sub-agent as a `Task`, keeps its `BufferedUI` transcript beside it, mints a handle, and `GetDelegationResult` polls, collects or kills it. The run's cut signal is already visible to the delegation: `signal_for_run()` hands a sub-agent its parent's signal, because a sub-agent belongs to the turn the user is steering (ADR-0123, decision 4). What was missing was a way to hand an *already running* task to that registry.

**Decision.**

1. **The synchronous path runs the sub-agent as a `Task` from the start.** `_run_delegation` wraps `run_agent_task` in `asyncio.ensure_future` and waits on `{run, cut_wait}` with `FIRST_COMPLETED`, the shape `_wait_for_exit_or_adopt` already uses for a command. A run that finishes first is reported exactly as before; there is no second code path for "it finished normally".

2. **A cut adopts the task; it never cancels it.** The run is recorded in the registry under a fresh handle together with its buffer, and registered as this session's own handle so the live context lists it on later turns. The model is told the work is still running and how to collect it — `GetDelegationResult(handle=...)`, `wait=N`, `kill=True` — in the wording `_moved_to_background_note` uses for a command, and is told not to delegate the same work again. It is never told the delegation failed.

3. **A fan-out adopts every sibling that is still in flight.** The sibling tasks are created one per delegation instead of being gathered: a `gather` cancelled with the turn cancels its children, and it holds nothing a handle could take over. The report names one handle per moved sibling, so each result is collected on its own, and the siblings that did finish report as they always did.

4. **A cancelled turn still stops a delegation that never moved.** Send-now steers the turn when it can and cancels it when it cannot (ADR-0116). If the cancel arrives before any adoption, nobody is left to read the result, so the run stops with the turn — the behaviour it had before this record. Once adopted, the task is nobody's child and outlives the frame that stopped waiting for it.

5. **Outside a run nothing changes.** No cut signal means no cut waiter, and the tool waits for the delegation exactly as it did before.

**Consequences.** A delegation no longer makes the assistant unreachable: the message is read within the turn it interrupted, and the sub-agent keeps working under a handle. The transcript keeps streaming into its `BufferedUI`, which nobody is watching until the handle is collected — the sub-agent's own live view stops being updated on screen, the same cost ADR-0123 accepted for a command. A fan-out allocates one `Task` per delegation where it allocated one `gather`, and a delegation that moves leaves its worktree cleanup to the moment it finally finishes, not to the moment the turn ended.

**Alternatives rejected.**

- *Cancel the sub-agent on a cut* — the user asked for the turn, not for the work to be thrown away; cancelling would also discard whatever the sub-agent has already produced.
- *Keep one `gather` over the fan-out siblings and adopt from inside it* — a cancelled `gather` cancels its children, so the siblings would die with the frame the send-now fallback cancels, and the handle would point at a corpse.
- *Let the model call `DelegateToAgentBackground` when a message arrives* — the model cannot know the user is typing, and by the time it reads the message the delegation has already returned or blocked the turn for an hour.
- *Report "failed" and let the model retry* — the work is still running; a retry would run a second copy of it beside the first.
- *A second registry for adopted runs* — the existing one already keys a task, a buffer and an agent name by handle, and `GetDelegationResult` already reads all three. `start()` and `adopt()` differ only in whether the task is created here or handed over.

**Where it lives.** `src/zrb/llm/tool/delegate.py` (`_run_delegation`, `_wait_for_runs`, `_adopt_delegation`, `_fan_out_reports`, the two moved-aside notes), `src/zrb/llm/tool/delegate_background.py` (`_BackgroundRegistry.adopt`, which `start` now delegates to), `src/zrb/llm/shell_cut.py` (the signal, unchanged), `test/llm/tool/test_delegate_cut_adopt.py`. See ADR-0123 for the command half and ADR-0116 for the fallback that cancels a turn whose delivery failed.
