# ADR-0002 — Program against `Any*` interfaces, not concrete types

**Status:** Accepted

**Context.** The engine and the runners must handle `Task`, `CmdTask`, `LLMTask`, and arbitrary user subclasses uniformly, and stay refactorable while users subclass the public types.

**Decision.** Define abstract interfaces (`AnyTask`, `AnyGroup`, `AnyContext`, `AnySession`, …) and program the engine and runners against those. Concrete types are imported only where objects are constructed.

**Consequences.** The engine is decoupled from task implementations; tests mock the interface; users inject their own implementations. The cost is one more abstraction layer plus the discipline to keep the interfaces honest.

**Alternatives rejected.** *Concrete types everywhere* — couples internals to the public API, so any refactor is a breaking change. *Pure duck typing* — less discoverable and weaker IDE support for the people writing task files.

**Where it lives.** `src/zrb/task/any_task.py`, `src/zrb/group/any_group.py`, `src/zrb/context/any_context.py`.
