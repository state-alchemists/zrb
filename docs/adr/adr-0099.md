# ADR-0099 — Factual-claim hardening against generative-engine-optimized content

**Status:** Accepted

**Context.** Generative Engine Optimization (GEO) is the practiced art of shaping content so LLM-based answer engines retrieve, trust, and *cite* it. The mechanism research is consistent: sources are preferred when they are easy to "lift" — self-contained definitions, key-takeaway bullets, one-claim paragraphs, numbered steps, and comparison tables — and the highest-yield levers are decorative **quotations** and **statistics** (visibility gains of up to ~40%+ across GEO-bench), with fluency/readability tuning worth another 15-30%. Keyword stuffing, the classic SEO move, barely registers; "authoritative tone" adds nothing. Citation selection is the bottleneck (only a handful of retrieved sources get cited), and being cited is weak evidence anyway: measured citation-hallucination runs 11-57% across deployed models, and deep-research fact-check accuracy *falls* as search breadth grows.

zrb had no mechanism telling the agent any of the parts it could act on.

- The strongest source-quality wording ("prefer official documentation over blog posts", "when sources conflict, report the conflict") lived **only** in the optional `researcher` sub-agent, not in the on-demand `core-research` methodology and not in the always-on `principle` section.
- `web_summarizer.md` listed "performance benchmarks, security warnings" as always-high-extract without an attribution test — the exact category GEO content uses for decorative figures. That file is also the summarizer's *entire* instructions: the sub-agent is built on `get_prompt("web_summarizer")`, which returns one section, so persona/principle/workflow never reach it.
- `WebFetch`'s **default** summarized path returned derived untrusted content with no `content_is` note; only the opt-in raw path carried one. The framing ADR-0048 ships with data for `Read`, `RAG`, and `MCP` results was absent on the most common web-read.

**Decision.**

1. **A web source is a claim, not proof.** `web_summarizer.md` gets a Source Reliability section: statistics/benchmarks/version numbers are kept only when the page names their origin; a figure with no named source is recorded as unverifiable, not relayed; a page that is promotional or shaped for extraction (thin prose around compressed bullets) is flagged in the summary rather than echoed as neutral fact. The High-priority table now requires each kept item to be tied to its origin on the page.
2. **Corroboration and primary-source preference move onto the always-on path and the on-demand methodology.** `principle.md` gains "corroborate contested or consequential claims with a second independent source"; `core-research` gains the same rule plus the snippet-is-a-lead guidance (fetch before quoting, check figures at their named source); `researcher` extends its existing Source Quality list with citation-verification and extraction-shaped-as-lower-trust.
3. **Untrusted framing travels with both web paths.** The summarized `WebFetch` result now carries `content_is: UNTRUSTED_DATA_NOTE` exactly like the raw path, so the default read does not look agent-authored at the point the bytes re-enter the main context. This extends ADR-0048's decision (framing co-located with payload) rather than revising it.

**Consequences.** The agent should be less likely to relay decorative statistics, give weight to a lone extraction-shaped source, or present a citation as proof. Cost: roughly one additive key on the default web-read (the same token cost ADR-0048 already accepted for the raw path); a handful of prompt lines in `web_summarizer.md` (offset by merging its four overlapping "keep signal, drop fluff" restatements); and two short clauses in always-on `principle.md`, which every profile shares. The corroboration rule is deliberately limited to "contested or consequential" claims so it does not force redundant fetching on every mundane fact.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Rely on the sub-agent's own hardened prompt for the summarized path | The summary re-enters the main agent's context and can echo the page's text verbatim through preserved quotes; unmarking it re-opens the exact gap ADR-0048 closed on the raw path. |
| Centralize or trim the repeated injection preambles in the extractor/summarizer prompts | ADR-0046: shipped prompt files are plain markdown that read whole on their own; a shared or referenced rule is not expressible in that format. |
| Trim tool docstrings to fund the new wording | ADR-0058: docstring prose is not the token lever; tool-definition weight is managed by tool count. |
| Keep source-quality guidance only in the delegated `researcher` agent | A normal chat session never activates it, so the agent it protects would not be the one helped. |

**Where it lives.** `src/zrb/llm/prompt/markdown/web_summarizer.md`, `src/zrb/llm/prompt/markdown/principle.md`, `src/zrb/llm_plugin/core_skills/core-research/SKILL.md`, `src/zrb/llm_plugin/agents/researcher.agent.md`, `src/zrb/llm/tool/web.py` (`content_is` on both paths). Extends ADR-0048.
