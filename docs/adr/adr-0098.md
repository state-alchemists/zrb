# ADR-0098 — A fixed action vocabulary, and boolean names that read as questions

**Status:** Accepted

**Context.** R5–R7 ([Framework Conventions](../contributing/framework-conventions.md)) already fix the verbs for one family: a collection is mutated with `append_X`/`prepend_X`/`add_X`/`set_X`/`remove_X`, and no concept answers to two names. They stop at collections. Every other function in the tree names itself.

Measured over the 5,507 functions and methods in `src/zrb`: **596 distinct leading tokens, 43% of them used exactly once.** The tail is not vocabulary, it is synonyms.

| One meaning | Verbs in use | Functions |
| --- | --- | --- |
| retrieve a value | `get` 375 · `resolve` 68 · `read` 28 · `load` 25 · `find` 19 · `extract` 19 · `collect` 11 · `fetch` 4 · `retrieve` 1 | 550 |
| produce a value | `create` 60 · `build` 29 · `make` 16 · `generate` 13 · `new` 5 · `compose` 1 | 124 |
| take something out | `remove` 44 · `clear` 12 · `prune` 6 · `delete` 4 · `drop` 2 · `discard` 2 | 70 |

`fetch` at 4 and `retrieve` at 1, against `get` at 375, are synonyms, not distinctions. Finding "the function that gets X" means trying nine verbs; grep answers only for the one that was picked.

A second gap is mechanical. **153 of the 490 functions annotated `-> bool` carry a boolean prefix — 31%.** The other 337 are named like values:

| Reads as a value | Reads as a question |
| --- | --- |
| `if task.cli_only:` | `if task.is_cli_only:` |
| `if handler.filter(record):` | `if handler.should_keep(record):` |
| `if get_current_yolo():` | `if is_yolo_enabled():` |

[kettanaito/naming-cheatsheet](https://github.com/kettanaito/naming-cheatsheet) is the reference for both: its Actions table and its `is`/`has`/`should` prefixes are the generalization of the rule R5 already states for collections. Its remaining rules are evaluated under *Alternatives rejected* — several are wrong for a Python framework whose abbreviations are public API.

**Decision.** One verb per meaning, from a closed list. A name outside it needs a reason, not a preference.

| Verb | Meaning | Not |
| --- | --- | --- |
| `get_X` | return X, computing or fetching as needed | `fetch`, `retrieve`, `lookup` |
| `resolve_X` | evaluate a deferred attribute against a context (ADR-0005) | folding into `get` |
| `read_X` | read from the filesystem or a stream | `load` for file contents |
| `load_X` | import or deserialize a module, config or plugin | `read` for a module |
| `create_X` | construct and return a new X | `build`, `make`, `new`, `generate` |
| `set_X` | assign X | — |
| `reset_X` | restore X to its initial value | `clear` for a single value |
| `remove_X` | take X out of a collection it belongs to | `drop`, `discard`, `prune` |
| `delete_X` | destroy X at its source (a file, a row, a worktree) | `remove` for destruction |
| `handle_X` | process an event or callback | `on_X`, `process_X` |

`resolve` stays distinct from `get` because it names what a getter does not do: evaluate a `StrAttr`/`BoolAttr` against a live `Context` at execution time. Naming it keeps 68 functions from hiding inside the 375.

**A function annotated `-> bool` is named as a question:** `is_`, `has_`, `should_`, `can_`, `needs_`, or a `_enabled`/`_active` suffix on a property. The annotation is the trigger, so the rule's subject is objective, not a judgement about what "reads boolean".

**The action vocabulary is review vocabulary, not a gate** — no fitness function, no R13, no allowlist. ADR-0097 puts the suite's weakest property at kill rate, not shape, and a shape rule needing a hand-maintained allowlist would cost more than the drift it prevents. The leading-token counts in *Context* are the baseline; re-measuring them audits this half.

**The `-> bool` half is ratcheted**, in `test/architecture/test_bool_naming_ratchet.py`. It needs no allowlist — the annotation is the trigger and the vocabulary is closed — so the check is one integer: the count of `-> bool` functions not phrased as a question, which may only go down. A paired tightness test fails if a rename lands without lowering the number, so repaid debt cannot be silently re-borrowed. It costs about fifty lines and no ongoing maintenance.

Names are corrected when a file is touched for another reason; there is no sweep. The ratchet caps the debt, it does not schedule repayment.

**Consequences.** A reviewer gets a citable rule (`that is get, not fetch`) where there was only taste, and a new contributor gets one table instead of 596 tokens to infer a pattern from. The `-> bool` half matters most at call sites: `if task.cli_only:` sends the reader to check the annotation, `if task.is_cli_only:` does not.

The action-verb half is unenforced and will drift — the accepted cost, mitigated by leading-token frequency being a few lines of AST away, so an audit is cheap without a standing test. The `-> bool` half cannot drift upward at all.

Renaming a *public* name is still a public API change and follows the existing rules: `zrb/__init__.py`'s exports and `test/public_api_snapshot.json` move together, and a released `CFG` knob keeps its old env key through `EnvField(aliases=...)`.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Adopt the cheatsheet's "avoid contractions" rule | `ctx` appears 1,115 times in `src/zrb` and **363 times in user-facing docs** as the parameter name in every task a user writes (`def my_task(ctx): ...`). `cfg`/`CFG` is the same. These abbreviations are the public surface; expanding them breaks every `zrb_init.py` in existence. |
| Adopt "avoid context duplication" | 221 methods repeat a word from their class name, but the sample is mostly correct: `CmdTask._get_cmd_script` repeats `cmd` because `cmd` there is the command *value*, not the class. A rule flagging 221 names to fix perhaps 40 is net negative. |
| Adopt S-I-D and "reflect the expected result" | Neither is measurable. An unmeasurable naming rule is a cudgel in review with no appeal, and it dilutes the two rules that can be checked. |
| Adopt camelCase, the cheatsheet's example convention | PEP 8, and the cheatsheet explicitly permits snake_case under "pick one and follow it". |
| Gate the `-> bool` half outright, failing on any violation | It would fail on the first run against a tree where most `-> bool` functions predate the rule, so it would be deleted or exempted within a day. A ratchet caps the debt without demanding a sweep the next alternative row rejects. |
| Add R13 for the action vocabulary too | The verb table has no objective trigger the way `-> bool` does — deciding whether a name *should* have been `get_` needs a reader. That is the allowlist-shaped cost this record declines. |
| Sweep the 337 unprefixed booleans now | A rename-only diff across 337 call sites has no behavioral test to back it, and the churn lands on every open branch at once. Correcting names on files already being edited costs nothing and carries the same information. |
| Leave naming to review, as before | R5–R7 exist because that did not work for collections; `get_search_directories()` and a `search_dirs` property coexisted until a rule named the collision. The same failure mode produced nine verbs for "retrieve". |

**Where it lives.** `AGENTS.md` (Code Style), alongside the collection-verb rule it extends. The collection half stays in [Framework Conventions](../contributing/framework-conventions.md) R5–R7, which is enforced by `test/architecture/test_mutation_surface.py`. The `-> bool` ratchet lives in `test/architecture/test_bool_naming_ratchet.py`.
