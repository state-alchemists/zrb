# ADR-0098 — A rule lives where it is enforced

**Status:** Accepted (supersedes ADR-0043 and ADR-0086 where they describe the
tool-guidance registry; narrows ADR-0061)

**Context.** The composed system prompt measured **32,621 chars (~8,150 tok)**
on this repo with the default `LLM_INCLUDE_SECTIONS`. The comparable rule prose
in Claude Code and OpenCode's `anthropic.txt` is ~2,100 words (~2,800 tok).

The totals were not the difference — once tool schemas land, those harnesses sit
at ~12–15k tokens too. The *split* was:

| Layer | zrb before | Claude Code / OpenCode |
|---|---|---|
| Rule prose | ~5,200 tok | ~2,800 tok |
| Cross-tool selection guide | ~1,300 tok (`tool_guidance`, 30 entries) | ~200 tok, inline |
| Skill catalogue | ~600 tok | in the Skill tool description |
| Eager tool docstrings | ~1,500 tok (15 tools) | ~8–12k tok |

zrb carried its weight in a rulebook the model had to hold in working memory;
the references carry theirs next to the schema the model is filling in.
`workflow.md` alone was 2,167 words, 37 bullets, ~38 bolded directives, and six
independently-switchable rule sections had to be kept non-overlapping by hand —
a discipline that had already failed once, shipping two divergent delegation
trigger lists (`DelegateToAgent`'s guidance and the Working Loop).

The relevant external result is IFScale (arXiv 2507.11538): instruction-following
accuracy degrades as instruction density rises, with a **primacy bias** — later
instructions are omitted first. Rule count, not just token count, is the cost.

The naive fix — "move rules into tool docstrings" — saves nothing, and the
codebase already said so: pydantic-ai serializes every registered tool's
docstring and parameter schema into **every** request, so a docstring is not
deferred context. Relocation buys *locality and adherence*, not size.

**Decision.** Sort every rule by **where it can be enforced**, in this order:

1. **The runtime.** If a hook, tool policy, or tool implementation can make the
   rule true, the prompt does not state it.
2. **The tool's docstring.** Per-tool mechanics — argument semantics, output
   shape, irreversibility, which tool to use instead — sit next to the schema.
3. **The prompt.** Only judgment no tool can make for the model: stance,
   precedence between conflicting rules, when to stop, when to ask.
4. **A skill.** Domain methodology, loaded on demand.

Applied, this leaves **three rule sections** — `persona`, `workflow`,
`examples` — plus the two data sections `system_context` and `project_context`,
which carry runtime facts rather than rules and are untouched.

Concretely:

- **`mandate` folded into `workflow`.** The Priority Order is the
  highest-value block in the prompt and primacy says it belongs first, so it
  opens `workflow` rather than living in a section that could be toggled away
  from it.
- **`git_mandate` deleted.** `bash_safe_command_policy()` already allowlists
  exactly `git status`/`diff`/`log`/`show` and routes `add`/`commit`/`push`/
  `merge`/`rebase`/`reset`/`clean` to the user. The prose was redundant *and*
  had drifted — it claimed `branch`, `remote -v`, and `worktree list` were
  approval-free, which the allowlist never granted. The one behaviour a policy
  cannot produce (show `git status` + `git diff HEAD` before asking) is one line
  in `workflow`. To make the deletion correct by construction, the policy moved
  from `builtin/llm/chat.py` into `apply_common_tools`: enforcement now travels
  with the tools it guards.
- **`journal_mandate`, the `core-journaling` skill, its three templates, and
  `journal-lint.py` deleted**, replaced by two tools. See ADR-0099.
- **`tool_guidance` and its registry deleted.** See ADR-0100.
- **`examples` kept, profile-gated.** Demonstrations are the highest-value
  content per token for small models — the class the profile axis
  (ADR-0083/0091/0093/0095) exists to serve. Cutting rules *and* examples would
  have taken from the weakest models twice.

**Consequences.**

- The composed default prompt drops from 32,621 to **~19,500 chars** (~8,150 →
  ~4,870 tok), about 40%. Eager tool docstrings grow ~450 tok. The net context
  floor falls roughly 45%. This is smaller than a naive section-count estimate
  suggests: `workflow` had to *absorb* two sections, so its own file barely
  shrank while carrying three sections' content.
- `test_section_composition.py` brute-forces 7 subsets instead of 63. The
  MECE-versus-self-containment tension that `AGENTS.md` documents largely
  dissolves: with three sections there are far fewer cross-references to keep in
  sync, and only one `<!--requires:-->` guard remains (`project_context`).
- A pinned `ZRB_LLM_INCLUDE_SECTIONS` naming `mandate`, `git_mandate`,
  `journal_mandate`, or `tool_guidance` now resolves to an empty custom section
  and logs a warning — a graceful no-op, not a crash. This is a clean break: no
  aliases, per the project's no-back-compat-shim stance on renames.
- A new test pins the composed prompt under a 24,000-char ceiling, so the
  reduction cannot regress one paragraph at a time.
- **What this does not claim:** parity with Claude Code on weak models. Frontier
  models resolve <65% of terminal-command tasks; small models ~15%. Prompt
  hygiene stops zrb-specific failure modes from consuming the capability a small
  model has. It does not add capability.

**Alternatives rejected.**

- *Two sections (`persona` + `workflow`) only.* Would have deleted `examples`,
  taking demonstrations away from exactly the models the change targets.
- *Keep all six sections, just write them tighter.* Prose editing does not
  remove the rules that a policy already enforces, and leaves six sections to
  keep MECE by hand — the discipline that had already produced divergent
  duplication.
- *Move the rules into docstrings to shrink the prompt.* Does not shrink
  anything; pydantic-ai ships every docstring every turn. Locality is the real
  benefit and is claimed as such.
