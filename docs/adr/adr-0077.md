# ADR-0077 — Queued messages are editable entries, edited in place from the input field

**Status:** Accepted

**Context.** A chat message typed while a turn is in flight is not sent: the message loop runs one job at a time, so it waits in the UI's message queue. Users hit this constantly — they spot a typo, or a refined instruction, the moment after pressing Enter while the assistant is mid-response. The only recourse was to let the bad message run, then send a corrective follow-up.

Editing a *queued* message should be an in-place edit, not a re-send: the still-waiting message's text is replaced (so the turn, when it starts, streams the corrected wording) and the echoed line in the transcript is rewritten to match. That required the queue to stop being an opaque bag of coroutines. The queue held bare `async def job()` closures — nothing to identify, index, or mutate a specific waiting message, and no way to know whether a message had already started.

**Decision.** The message queue holds `QueuedMessage` entries instead of raw jobs, and the default TUI lets the user recall, edit, and replace a still-queued message from the input field.

1. **The queue is an `asyncio.Queue` of `QueuedMessage` objects.** Each entry carries `text`, `attachments`, a `kind` (`message` vs `exec`), and `run` — an async job that reads `entry.text`/`entry.attachments` **at execution time** rather than capturing them. Because the consumer (and only the consumer) pops entries via `get()`, anything still in the queue is by definition not yet running; editing is therefore always safe and never needs to race the turn.
2. **`MessageQueue` subclasses `asyncio.Queue`** so every existing consumer keeps `get`/`put_nowait`/`task_done`/`join` semantics (the web chat awaits `join()`). It adds peek/navigation (`peek_latest`, `latest_editable`, `editable_before`, `editable_after`), `contains`, and `remove` — `remove` also decrements the unfinished-task counter (the removed entry will never reach `task_done`), so a `join()` still resolves. `latest_editable` and the navigation methods skip `exec` jobs — a shell command is not a user message and cannot be recalled for editing. All producers (`BaseUI._submit_user_message`, `MultiUI`, the `/exec` handler) build entries.
3. **Editing is a field write plus an echo redraw.** `BaseUI.edit_queued_message(entry, new_text)` refuses when the entry is no longer queued (its turn started) and otherwise replaces `entry.text` and asks each child UI to rewrite the echoed line. The echo span is recorded on the entry at submit time only when the line actually landed in the output buffer verbatim — a pending tool confirmation diverts content into a confirmation buffer, in which case the span is left unset and the edit is invisible-but-effective there.
4. **Up/Down recall in the default TUI.** With the input field focused, Up recalls the newest still-queued message into the buffer (saving the in-progress draft); further Ups walk older queued messages, Down walks newer and then restores the draft. This is wired as a buffer-level keybinding (layout) that falls through to prompt-toolkit history recall when nothing is queued, since buffer bindings shadow app-level bindings. The recalled text's cursor is pinned to the end — `Buffer.text` leaves the cursor where it was, which would strand it mid-message. A recalled message that the user has not yet edited keeps the Up binding active even when it spans multiple lines (the cursor is not on the first line, so the line-position guard would otherwise steal the press); the saved draft also survives a stale recall, when the recalled message's turn started mid-edit and a later Up drops the edit mode. Typing or moving the cursor returns the arrows to cursor movement.
5. **Enter edits instead of submitting.** While a queued message is in the buffer, Enter replaces that entry's text (broadcasting the redraw across every child UI in a MultiUI, since entries are shared) rather than queuing a new message. An empty edit cancels back to the saved draft; if the message's turn already started, Enter falls through to the normal submit path.
6. **The echo redraw splices by recorded span.** The default UI rewrites the echoed line in its output buffer and shifts the tracked re-wrap blocks (`_rendered_blocks`) that start after it, so a later terminal resize still re-wraps markdown at correct offsets. The span is validated before splicing: the entry remembers the echoed line it points at, and a redraw that finds different text there (a resize re-wrapped a preceding block and shifted the transcript) drops the span instead of splicing into the wrong offset — the edit stays effective, the echo just is not rewritten. Non-terminal UIs (telegram, polling, http) override nothing: their `_redraw_echo` is a base no-op and their edits update the message without a redraw.

**Consequences.** A typo'd or refined message can be fixed while the assistant is still working, without a corrective follow-up turn. The queue is now a structured, introspectable collection — future features (message reordering, per-message status, cancellation of a specific queued turn) build on the same seam. Costs: the echo redraw assumes nothing else rewrites the transcript inside a tracked span (already an implicit invariant of `rewrap_output`), and the queue holds references to entries until their turn starts.

**Alternatives rejected.** *Recall-only via prompt-toolkit history* — the recalled text would be a *new* message on Enter, not an edit; indistinguishable from a duplicate. *Text-matching at Enter time* — treating any Enter whose text equals a queued message's text as an edit is ambiguous when a user genuinely sends the same message twice. *A separate edit mode (`/edit <n>`)* — index-based editing forces the user to know queue positions and adds a command for something a keybinding does. *Rewriting the whole output buffer on edit* — correct but heavy; span splicing with block-offset shifting keeps re-wrap intact.

**Where it lives.** `src/zrb/llm/ui/base/message_queue.py` (`MessageQueue`, `QueuedMessage`), `src/zrb/llm/ui/base/ui.py` (`edit_queued_message`, `effective_message_queue`), `src/zrb/llm/ui/default/message_editing.py` (recall/Enter/echo-redraw part), `src/zrb/llm/app/layout.py` (Up/Down buffer bindings), `src/zrb/llm/ui/default/output.py` (`replace_output_span`).
