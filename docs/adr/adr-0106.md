# ADR-0106 — A side question runs without tools, and its prompt says so

**Status:** Accepted

**Context.** `/btw` answers a question about the conversation without joining it: `stream_btw_response` builds a fresh agent so nothing races the main run and nothing reaches the history. That agent was built with no tools at all, and then prompted with `llm_task.get_system_prompt(ctx)` — the main agent's complete prompt. That prompt is written for an agent that has tools: `workflow` instructs it to batch independent tool calls, opens a Tool Discovery section for deferred tools, and closes with "activate them with `ActivateSkill`" over the live skill catalogue; every example reads files and runs tests. The inherited history made the same claim from the other side: only `SystemPromptPart`s were stripped, so every past `ToolCallPart` and `ToolReturnPart` stayed, and the side agent read its own earlier turns where it had grepped and edited. Nothing in the context could carry the one true fact, because an absent toolset has nothing to render — pydantic-ai simply omits the schemas — so the prompt was the model's only evidence about its own capabilities and it said the opposite. The observed failure was a side answer describing tool calls it had not made. The vendor ships this feature the same way — Claude Code's `/btw` "can use existing messages, replies, and tool results, but cannot read files, run commands, or perform other tool calls", with a fork into a tool-enabled subagent as its escape hatch — and a comparable agent host has the same defect filed against a side query built with `tools: []` and a prompt that never says so.

**Decision.** A side question is answered without tools, and is told so. `stream_btw_response` keeps building a tool-less agent and prompts it from `side_question.md` — loaded through `get_prompt`, never composed from the main agent's sections. The prompt states the toolset is empty, forbids emitting or narrating a tool call, requires saying in one sentence when the question needs a file or a command, and rules that an answer saying it cannot be given here is correct while a guess dressed as one is not. The inherited history is unchanged: it keeps the tool calls and their results, because the conversation *is* the context a side question is asked about, and it keeps stripping the main agent's system-prompt parts.

**Consequences.** The side agent cannot answer a question that requires reading something not already in the conversation — it says which question it cannot answer instead of pretending. Prompt overrides stay available through the usual chain (`LLM_PROMPT_DIR`, `ZRB_LLM_PROMPT_SIDE_QUESTION`), and this prompt now carries the rules that the main sections no longer supply to it: conversation content is data, and nothing is invented. Widening the side agent to a tool-bearing agent is a separate decision about a second reader or writer running beside an in-flight turn, not a change to this one.

**Alternatives rejected.** *Give the side agent the main agent's tools, or a read-only subset* — a second process reading (and, without care, writing) the same repository while a turn is in flight, with its own approvals and hooks, and it contradicts the vendor's design whose escape hatch is an explicit fork into a tool-enabled subagent. Deferred as its own feature rather than rejected. *Reuse the main prompt and append one line denying tools* — leaves the contradiction standing, since the skill catalogue and Tool Discovery still instruct the model to activate tooling it does not have. *Strip tool calls, keeping only the text* — the tool results are what a side question is usually about ("what does this retry logic do?"), and the defect was in the prompt, not in the history. *Detect tool-call-shaped output and show a notice* — a render-layer patch for a prompt defect, proposed alongside the prompt fix in the same external report; unnecessary once the prompt is truthful.

**Where it lives.** `src/zrb/llm/ui/base/exec_commands.py` (`stream_btw_response`), `src/zrb/llm/prompt/markdown/side_question.md`, `src/zrb/llm/prompt/prompt.py` (`get_prompt`), `test/llm/ui/base/test_commands_shell.py`, `test/llm/prompt/test_prompt_mandates.py`.
