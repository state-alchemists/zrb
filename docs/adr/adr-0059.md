# ADR-0059 — Tool output is capped at the source; global overflow is separate

**Status:** Accepted

**Context.** Read, list, search, and shell output can become large enough to flood a model context. These tools know their own retrieval shape: file-oriented results are useful from the beginning, while build and test output usually matters at the end. Other tool sources, especially MCP, have no equivalent source-specific retrieval semantics.

**Decision.** Tools that can control their own output cap it against `CFG.LLM_MAX_OUTPUT_CHARS` (default 100k). `Read`, `List`, and `Grep`-style tools retain the head; `Shell` retains the tail, where errors and exit summaries land. Cuts snap to line boundaries. Shell also writes complete stdout and stderr to a temporary file and surfaces its path, so the model can recover a narrower slice with `Read` or `Grep`. `RunInBackground` and `MonitorProcess` share the same `StreamCapture` implementation, including its `flush()` support while a background process is still running.

`LLM_MAX_TOOL_RESULT_CHARS` is not a second truncation layer. Its global, lossless overflow behavior is owned by ADR-0089: with `LLM_TOOL_SPILL_ENABLED` enabled, an oversized result is replaced by a preview and a queryable spill handle; when disabled, it is recorded as oversized metadata only.

**Consequences.** Ordinary high-volume tools remain bounded with retrieval-aware output and no extra model call. Tool types that cannot safely decide which text to discard remain intact until the opt-in global spill mechanism handles them. A typical result is below both thresholds and unchanged.

**Alternatives rejected.** *One universal truncation strategy* — source tools know whether their head or tail is useful. *Per-tool caps only* — MCP and future tool sources can still return unbounded payloads. *No cap* — a large repository or command output becomes a context-flooding failure.

**Where it lives.** `src/zrb/util/truncate.py`, `src/zrb/config/mixins/llm_limits.py`, and `src/zrb/llm/tool/stream_capture.py` (`StreamCapture`, shared by `shell.py` and `shell_background.py`). Global overflow lives in the ADR-0089 locations.
