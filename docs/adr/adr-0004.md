# ADR-0004 — Ambient state travels in `ContextVar`s, not through every signature

**Status:** Accepted

**Context.** Execution nests deeply: runner → task → action → agent → tool → sub-agent. Threading state (UI, session, logger, yolo, approval channel) through every signature explodes the APIs users see.

**Decision.** Ambient state lives in `contextvars.ContextVar`s, written with the RAII pattern (`token = var.set(...)` / `var.reset(token)`) and read on demand. `src/zrb/contextvars.py` is the canonical registry of every var, its owning module, and its typed accessor. `asyncio` propagates context to child coroutines automatically (PEP 567), so sub-agents inherit parent state for free.

**Consequences.** Signatures stay clean and scoped resets prevent leaks. The cost is that state is implicit — you must consult the registry to know what is in scope — and every write must be scoped, or it leaks into sibling runs.

**Alternatives rejected.** *Thread the arguments* — signature explosion across every layer, and the public task API is one of those layers. *Thread-locals* — do not follow `await`. *Global mutable state* — unsafe under concurrency, with no cleanup story.

**Where it lives.** `src/zrb/contextvars.py` (registry), `src/zrb/llm/agent/run/runner.py` (canonical scoped-write pattern), `docs/contributing/maintainer-guide.md`.
