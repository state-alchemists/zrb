# ADR-0020 — `DotDict` for attribute-style access to context data

**Status:** Accepted

**Context.** `ctx.env['DATABASE_URL']` is noisier than attribute access for the
common case, but full dict semantics — iteration, dynamic keys, serialization —
must remain available.

**Decision.** `ctx.env`, `ctx.input` and `ctx.xcom` are `DotDict`s: a `dict`
subclass that also exposes attribute access (`ctx.env.DATABASE_URL`).

**Consequences.** Access reads cleanly and often autocompletes, with no loss of
dict behaviour. The cost is that truly dynamic keys cannot autocomplete, and a
key colliding with a dict method name shadows it.

**Alternatives rejected.** *Plain dict plus getters* — verbose at every call
site in user code. *A namespace object* — harder to iterate and serialize.
*Fixed attributes on `Context`* — cannot accept keys discovered at runtime.

**Where it lives.** `src/zrb/dot_dict/dot_dict.py`,
`src/zrb/context/context.py`.
