# ADR-0042 — Keep the cached prefix byte-stable: volatile state and mutable snapshots live in the conversation

**Status:** Accepted

**Context.** The system prompt is handed to pydantic-ai as `instructions`,
which places it at the very front of the message list, ahead of history. Every
provider that caches — DeepSeek and OpenAI automatic prefix caching, Anthropic
explicit breakpoints — requires the leading bytes to be **byte-identical**
across turns for a hit. Two things violated that.

*Volatile runtime facts.* The `system_context` section opened with
`- Time: <HH:MM:SS>` plus git status, pending todos, active worktree and the
interactive flag. Because that block preceded history in the request, the
prefix diverged on essentially every turn and **nothing cached — not even the
growing, expensive history**. Measured: `prompt_cache_hit_tokens: 0`.

*A mutable snapshot.* The journal index was embedded in the prompt through a
placeholder whose cache key included the index file's `mtime`, precisely so it
would refresh. But the agent journals as part of its normal loop, so one
journal write changed the mtime, changed the prompt, and invalidated the entire
cached prefix for the rest of the session.

**Decision.** Split by lifecycle, and inject the volatile half into the
conversation instead of the prefix.

- **`system_context` keeps only session-invariant facts** — OS, cwd, detected
  project markers, available tools, model identity — plus a stable anchor line
  explaining the `<live-context>` contract to the model.
- **`render_live_context` carries the per-turn lines** (time, git, todos,
  worktree, mode, interactivity) and performs the per-turn ambient wiring that
  must run every turn: session binding for the todo tools, interactive-mode
  binding for `ask_user_question`, stale-worktree cleanup. The body is wrapped
  in `<live-context>…</live-context>` and appended to the **end of the current
  user turn**.
- **The block is append-only** — frozen into history once written. That is
  exactly what keeps the prefix stable: each turn only appends, so the system
  prompt and all prior turns remain a byte-identical prefix.
- **The journal index is injected at the two — and only two — moments it can
  otherwise be absent**: the first turn of a session (detected as "history is
  empty", not by scanning), and inside `summarize_history`, which bakes the
  snapshot into the summary text. That function is the single choke point for
  both `/compress` and auto-summarization, so one hook covers both. Between
  those events the index simply persists in history untouched.
- **Sub-agents are single-turn** with empty history, so the cross-turn caching
  rationale does not apply; they keep the full block in their inherited system
  prompt.

The tag is `<live-context>` rather than `<system-reminder>` because zrb is
provider-agnostic and cannot rely on a model-specific learned prior; the
in-prompt anchor supplies the meaning portably.

**Consequences.** The whole cacheable prefix — system prompt *and* conversation
history — survives across turns, so cache hits scale with conversation length,
which is where the cost is. Older turns carry historical snapshots (turn 3's
block still shows turn-3's time at turn 9), which is more faithful and matches
how harness reminders already work, at the price of one small block per turn.
There is **no detection logic** for the index — no marker, no history scan, no
cross-turn flag — and no one-turn blind spot, because the history processor
runs before the model request, so the summary that re-seeds the index is in the
same compacted request. Switching model with `/model` still breaks the cache
once; accepted as rare. One deliberate coupling: `summarize_history` imports
`render_journal_index`, so the summarizer knows the index is context worth
preserving.

**Alternatives rejected.** *Coarsen the timestamp, or move `system_context`
last* — recovers caching of the static sections but still mutates the
instructions block ahead of history, so history never caches: half the win,
none of the hard part. *Anthropic `cache_control` breakpoints only* —
orthogonal; prefix stability is a prerequisite for every provider, and
breakpoints help only once the prefix is stable. *Strip stale blocks from
history before sending* — rewrites the prefix every turn, defeating the
purpose. *Keep the journal index in the cached prompt* — invalidates the prefix
on every journal write. *Inject the index on the first turn only* — the first
turn is the first thing summarization drops, so the index vanished after the
first compaction. *Inject it every turn* — accumulates stale copies and roughly
doubles the largest live-context component. *Scan history for a sentinel and
re-inject when absent* — correct and thrifty, but it reconstructs an observable
event after the fact, adds a per-turn history walk, and has a one-turn blind
spot. *An in-memory flag* — does not survive a conversation resumed in a fresh
process. *A persisted sidecar flag* — a new state store for what injecting at
the event records in history for free.

**Where it lives.** `src/zrb/llm/prompt/system_context.py`,
`src/zrb/llm/prompt/live_context.py` (`render_live_context`,
`render_journal_index`), `src/zrb/llm/prompt/manager.py`
(`create_live_context`), `src/zrb/llm/agent/run/runner.py`
(`_append_live_context`), `src/zrb/llm/summarizer/history_summarizer.py`,
`src/zrb/llm/agent/subagent/manager.py`.
