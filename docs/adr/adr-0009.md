# ADR-0009 — Inputs and Envs are first-class objects

**Status:** Accepted

**Context.** Tasks need typed parameters — with interactive prompting, parsing,
validation and web-form rendering — plus environment wiring, and both must
inherit down the group tree.

**Decision.** Inputs are typed classes (`StrInput`, `IntInput`, `BoolInput`,
`OptionInput`, `PasswordInput`, …) and environments are `Env`, `EnvMap`,
`EnvFile`. Each knows how to prompt, parse, default and update the context, and
both inherit recursively through the task graph.

**Consequences.** Type-specific validation, CLI prompting and web-form
rendering all come from one definition, and inheritance removes repetition. The
cost is more object types than bare strings and dicts.

**Alternatives rejected.** *Bare strings and dicts* — no typing, prompting or
inheritance, so every runner reimplements them. *One generic `Parameter`
class* — no type-specific behaviour, which is the whole point.

**Where it lives.** `src/zrb/input/`, `src/zrb/env/`,
`docs/core-concepts/inputs.md`, `docs/core-concepts/environments.md`.
