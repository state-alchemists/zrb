# ADR-0008 — `@make_task` alongside direct instantiation

**Status:** Accepted

**Context.** Simple one-off tasks should not require class-instantiation
ceremony, but reusable tasks sometimes need an object reference to chain with
`>>`.

**Decision.** Offer both. `@make_task(...)` wraps a function into a `BaseTask`
and auto-registers it to a group when one is given; direct `Task(...)` /
`CmdTask(...)` instantiation and `BaseTask` subclassing remain first-class.

**Consequences.** The common case is low-ceremony and the full object is
available when needed. The cost is two authoring styles to document and keep
consistent.

**Alternatives rejected.** *Decorator only* — no in-place object to chain.
*Class only* — too verbose for the one-liner case that dominates real
`zrb_init.py` files.

**Where it lives.** `src/zrb/task/make_task.py`,
`docs/core-concepts/make-task.md`.
