# ADR-0086 — Split `workflow` out of `mandate`; a config naming only `mandate` still receives both

**Status:** Superseded by ADR-0098 — `mandate` is folded back into `workflow` and the back-compat shim is removed. (Was: Accepted, refines ADR-0035, ADR-0079.)

**Context.** ADR-0035 established MECE prompt sections — one concern per
section, so a downstream can drop or reorder a concern without touching the
others. `mandate` did not hold to that. It had accumulated nine top-level
concerns:

| # | concern | what it governs |
|---|---|---|
| 1 | Priority Order | precedence between safety, scope, memory, conventions |
| 2 | Session Context | summarization / don't hand off mid-task |
| 3 | Project Documentation | which files must be read on turn one |
| 4 | Skill Activation | when to activate, authority, tie-breaks + the catalogue (ADR-0079) |
| 5 | Working Loop | turn stance table, Understand → Plan → Execute |
| 6 | Verify Before Done | the completion gate |
| 7 | Recovery | what to do when an attempt fails |
| 8 | Stop | halt on request |

At 13.6 KB it was **54% of the composed system prompt** (measured: persona 1.8 KB,
mandate 13.6 KB, git_mandate 0.8 KB, journal_mandate 3.9 KB, tool_guidance 5.2 KB)
and it is the section a model consults to resolve a conflict — the least
navigable place to put the arbitration rules. It also blocked the very
customization ADR-0035 exists to enable: a downstream that wants to replace the
mandatory-project-doc-read rule had to replace the Priority Order along with it.

**Decision.** Split the file in two along the boundary that already existed —
*what the rules are* versus *how a turn runs*:

- **`mandate`** keeps the Priority Order and Session Context (3.4 KB).
- **`workflow`** (new, 13.5 KB) takes Project Documentation, Skill Activation
  (including the `{CORE_SKILLS}`/`{AVAILABLE_SKILLS}`/`{PREACTIVATED_SKILLS}`
  placeholders from ADR-0079), the Working Loop, Verify Before Done, Recovery,
  and Stop.

`workflow` is inserted after `mandate` in `DEFAULT_LLM_INCLUDE_SECTIONS`, so the
default prompt is unchanged in content and order.

**Back-compat is explicit, not hoped for.** `include_sections` and
`ZRB_LLM_INCLUDE_SECTIONS` are released, user-pinned surface, and a list written
before this split names only `mandate`. Adding a section would silently drop the
Working Loop and the Verify gate from those configs — a behavior regression with
no error. So `PromptManager._get_composed_middlewares` emits **both files at
`mandate`'s position when `workflow` is absent from the resolved section list**
(`_file_section_middleware` accepts varargs for this). Because the split
preserved document order, the concatenation reproduces the pre-split section.

The shim sits **after** the `register_section` provider check: a registered
`mandate` provider still wins, because replacing a section means supplying its
content yourself.

**Consequences.**

- *Good.* The arbitration rules (Priority Order) are now a 3.4 KB section a
  model can hold in view, separate from the 13.5 KB procedure.
- *Good.* `workflow` is independently droppable/replaceable — the ADR-0035
  promise now holds for the turn procedure and the project-doc mandate.
- *Good.* No config breaks. Verified by test: `include_sections=["mandate"]` and
  `include_sections=["mandate", "workflow"]` compose to the same tokens.
- *Cost.* One more section name in the vocabulary, and one conditional branch in
  the composer that exists purely for history. Both are the price of not
  breaking pinned configs; the branch is commented as such and tested in both
  directions.
- *Cost.* ADR-0079 says the catalogue lives in `mandate`. Its decision (drop
  `claude_skills`, render via placeholders) stands unchanged — only the host
  section moved. This record is the forwarding pointer.
- *Neutral.* Total prompt size is unchanged; nothing was added or removed by the
  split itself.

**Alternatives rejected.**

- *Add `workflow` to the default list and let pinned configs lose the Working
  Loop.* The failure is silent and severe — an agent with no Verify gate looks
  like a worse model, not a misconfiguration. A silent regression in released
  config surface is not an acceptable cost for a naming cleanup.
- *Emit a deprecation warning instead of the content.* A warning the user reads
  once cannot restore behavior for the turns before they read it.
- *Leave `mandate` whole and add navigation headings.* Adds tokens to solve the
  legibility half and nothing for the composability half.
- *Split further (e.g. `verify` as its own section).* The Verify gate is
  referenced from Skill Activation ("never the Verify Before Done gate") and
  from the Working Loop's stance table; separating them would scatter one
  behavior across sections, which is what ADR-0035 forbids.
