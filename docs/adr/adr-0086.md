# ADR-0086 — The agent-type hook builder is installed through a registry, not imported directly

**Status:** Accepted

**Context.** `hook/manager.py` must build a callable for each of the three hook types (command, prompt, agent). The agent type is implemented as a real sub-agent turn, so building it needs the agent-building subsystem: `agent/common.py::wrap_tool`, `agent/subagent/manager.py::sub_agent_manager`, and `common_tools.py::ensure_common_tools`. But `agent/common.py` itself depends on `hook/manager.py` to fire `PreToolUse`/`PostToolUse`/`PostToolUseFailure` around every tool call (ADR-0071). That is a genuine circular *dependency*, not merely a circular *import*: the hook subsystem's lowest-level module cannot build one of its own hook types without reaching into the very subsystem that depends on it.

Before this decision, the dependency was "resolved" by deferring the agent-building imports to inside `hook/creator.py::create_agent_hook`'s function body, tagged `# lazy: circular`. This kept the interpreter from deadlocking, but the actual runtime call graph then existed nowhere as an import statement — only as prose in scattered comments across five files (`common_tools.py`, `task/llm_task.py`, `agent/subagent/manager.py`, `hook/creator.py`, `agent/common.py`), several of which had already drifted out of sync with what the code actually did (one cited a module, `default_tools.py`, that did not exist).

**Decision.** Move `create_agent_hook` (and its two private helpers) out of `hook/creator.py` into a new `agent/hook_agent.py`, where its agent-subsystem imports become ordinary, eager, one-directional dependencies — `agent/*` depending on sibling `agent/*` code and on `hook/*`, the same direction `agent/common.py` already takes. `hook/manager.py` no longer imports the agent-type builder directly; it reads it from a new leaf module, `hook/agent_hook_registry.py`, which holds nothing but `register_agent_hook_builder(builder)` / `get_agent_hook_builder()` and a `Callable` type alias (stdlib + `TYPE_CHECKING`-only types, so it can never itself be part of a cycle). `zrb.llm.agent`'s package `__init__` imports `agent/hook_agent.py` as its last line, registering the real builder as an import side effect. If `zrb.llm.agent` was never imported when an agent-type hook fires (only reachable in an isolated test, since every real entry point loads `zrb.llm.agent` transitively through `zrb/__init__.py`), `hook/manager.py` logs a warning and returns a failed `HookResult` instead of crashing.

**Consequences.** `hook/*` now has zero edges into `agent/*` or `common_tools.py` — a dependency graph that is a DAG, drawable on one page, verifiable by reading import statements instead of trusting prose. `hook/manager.py` is readable using only files inside `hook/`. The registry is a new *kind* of seam for this codebase (a settable-at-runtime builder, rather than a direct import or a lazy in-function one) — a future maintainer reaching for a direct import to "simplify" this would silently reintroduce the cycle, which is exactly why this decision is recorded rather than left to the comments it replaces.

**Alternatives rejected.** *Keep the lazy in-function import* (status quo) — works, but the true dependency graph is unverifiable without reading and trusting five separate comments, which had already drifted wrong in two of them. *A full plugin/DI framework* — this codebase's existing style is "parts + lazy import" (ADR-0035); a general plugin system is a heavier mechanism than one circular edge warrants. *Merge `hook/creator.py` and `agent/hook_agent.py` into one file* — would still need the module itself to depend on `agent/*`, recreating the cycle one level up. *A `__getattr__`-based lazy resolution on `hook/creator.py`* (the technique used elsewhere for `zrb.llm.ui`'s `UI` and for the two UI import pairs below) — fits a symbol resolved *by name on access*; `create_agent_hook` needs to be *installed* by the agent package at its own load time, which a registration call expresses more directly than a lazy attribute lookup would.

**Where it lives.** `src/zrb/llm/hook/agent_hook_registry.py`, `src/zrb/llm/agent/hook_agent.py`, `src/zrb/llm/hook/manager.py`, `src/zrb/llm/hook/creator.py`, `src/zrb/llm/agent/__init__.py`.
