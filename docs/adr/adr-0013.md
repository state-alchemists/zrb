# ADR-0013 — `execute_condition` skips a task rather than branching or raising

**Status:** Accepted

**Context.** Pipelines need conditional steps ("deploy only in prod") without
imperative branch nodes and without abusing exceptions for control flow.

**Decision.** Every task has `execute_condition` (bool, f-string, or callable).
When it is false the task is *skipped*: its action does not run, it pushes
nothing to XCom, it triggers no fallback, and it unblocks its downstreams.

**Consequences.** Conditional pipelines need no branch nodes, and skipped is
cleanly distinct from failed. The cost is one more state whose semantics —
skipped still unblocks downstreams — must be understood.

**Alternatives rejected.** *Branch / if-else task nodes* — imperative, and they
complicate the graph for what is a per-task property. *An exception to signal
skip* — exceptions are for errors, and this one would have to be caught
everywhere.

**Where it lives.** `src/zrb/task/base_task.py`,
`docs/core-concepts/tasks-and-lifecycle.md`.
