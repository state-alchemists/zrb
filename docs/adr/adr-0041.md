# ADR-0041 — zrb owns conversation history, with two-tier summarization

**Status:** Accepted

**Context.** Conversations outgrow the context window. At the time this decision was made (pydantic-ai ~1.x/2.2), `history_processors` applied to a *shallow copy* that was never written back — so a summary produced that way was silently discarded, which is the defect that forced this ADR. As of pydantic-ai 2.36.0 this has changed: a native `ProcessHistory` capability now writes its result back into the live run history (`_agent_graph.py`), and the old `Agent(history_processors=...)` constructor kwarg is gone, replaced by `capabilities=`. zrb never passed that kwarg directly, so nothing broke on the 2.36.0 bump, but the write-back defect that originally justified owning history in parallel no longer exists upstream. Whether to migrate any part of zrb's pipeline onto the native capability is a separate, not-yet-scheduled evaluation (needs an equivalence test plan) — the decision below still stands as current practice.

**Decision.** zrb owns history. Processors are stored on the agent and applied by zrb itself, before the first model call and between tool-loop iterations, where it controls the history reference. Summarization is two-tier: an oversized individual tool result is compressed by the message summarizer, and when total tokens cross a threshold the older portion is condensed into a `<state_snapshot>` while recent turns are kept verbatim. History is re-sanitized after compression.

**Consequences.** Summaries persist, and long sessions stay in budget while keeping recent fidelity. The cost is a parallel history pipeline that must be maintained against pydantic-ai's own behaviour — the guards in ADR-0040 exist because that pipeline interacts with the deferred-tool loop.

**Alternatives rejected.** *Rely on pydantic-ai's history processors* — at the time, the shallow-copy behaviour discarded them; that specific defect is fixed upstream as of 2.36.0, but zrb's two-tier summarization (state-snapshot condensation, per-result compression) has no native equivalent, so owning history remains the current decision. *Naive truncation* — drops decisions the model still needs. *No summarization* — the provider eventually rejects an over-long history.

**Where it lives.** `src/zrb/llm/summarizer/`, `src/zrb/llm/agent/common.py` (comment on why `history_processors` is omitted), `src/zrb/llm/prompt/markdown/conversational_summarizer.md`, `message_summarizer.md`.
