# ADR-0041 — zrb owns conversation history, with two-tier summarization

**Status:** Accepted

**Context.** Conversations outgrow the context window, and pydantic-ai applies
history processors to a *shallow copy* that it never writes back — so a summary
produced its way is silently discarded.

**Decision.** zrb owns history. Processors are stored on the agent and applied
by zrb itself, before the first model call and between tool-loop iterations,
where it controls the history reference. Summarization is two-tier: an
oversized individual tool result is compressed by the message summarizer, and
when total tokens cross a threshold the older portion is condensed into a
`<state_snapshot>` while recent turns are kept verbatim. History is re-sanitized
after compression.

**Consequences.** Summaries persist, and long sessions stay in budget while
keeping recent fidelity. The cost is a parallel history pipeline that must be
maintained against pydantic-ai's own behaviour — the guards in ADR-0040 exist
because that pipeline interacts with the deferred-tool loop.

**Alternatives rejected.** *Rely on pydantic-ai's history processors* — the
shallow-copy behaviour discards them, which is the defect that forced this.
*Naive truncation* — drops decisions the model still needs. *No summarization* —
the provider eventually rejects an over-long history.

**Where it lives.** `src/zrb/llm/summarizer/`, `src/zrb/llm/agent/common.py`
(comment on why `history_processors` is omitted),
`src/zrb/llm/prompt/markdown/conversational_summarizer.md`,
`message_summarizer.md`.
