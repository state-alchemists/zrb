# ADR-0097 — Test integrity is ratcheted on kill rate, not coverage

**Status:** Accepted

**Context.** `zrb-test.sh` gates coverage at ≥95%, and `test/architecture/` carries shape ratchets — facade line counts, constructor parameter counts, mccabe ≤15, radon ≤15, private-test-access ≤5, and the rest. All of them measure the *source*. Coverage is the only gate that claims to measure the *tests*, and it measures whether a line ran, not whether anything would notice the line being wrong.

A sampled mutation run over ten core modules measured the gap. 22 mutants scored, 12 killed. Four survivors were equivalent or near-equivalent on inspection; six were real:

| Survivor | Mutation | What ships undetected |
| --- | --- | --- |
| `util/cmd/command.py` | `children(recursive=True)` → `False` | `_process_tree_pids` exists because a shell's children are reparented once it exits. `CmdTask` runs `<shell> -c`, so the work is a grandchild; the force-kill survivor list comes from this snapshot, so a grandchild ignoring SIGTERM never gets SIGKILL. |
| `llm/prompt/manager.py` | `skill_manager or default_` → `and` | A caller-supplied `skill_manager` is silently replaced by the global; `None` sets the attribute to `None`. |
| `llm/prompt/manager.py` | `inject_journal_index=False` → `True` | Both production callers rely on the default; the journal index would be injected every turn instead of the first. |
| `util/cmd/command.py` | `decode(b"", final=True)` → `False` | An incomplete UTF-8 sequence at stream end is never flushed — trailing command output silently lost. |
| `llm/skill/manager.py` | `exists() and is_dir()` → `or` | A path existing as a file is appended and later scanned as a directory. |
| `llm/skill/manager.py` | `user_invocable = True` → `False` | Frontmatter-less markdown skills vanish from the `/` menu. |

That ad-hoc run scored each mutant against the *whole* suite: 12/18 non-equivalent, ~67%. Scored against only the mutated package's mirrored tests — the question a per-package floor asks — four packages kill 51/98, 52%: `task/base` 56%, `util/cmd` 35%, `llm/skill` 60%, `llm/prompt` 56%. The lower number is the one worth holding: a mutant killed by an unrelated integration test shows the system noticed, not that this package is asserted on.

The escapes are not obscure: boolean guards in process teardown, default parameter values, `or`-vs-`and` in constructor fallbacks. The suite holds 5729 `patch`/`Mock` uses across 5438 test functions, and a mock asserts that a call happened, not that the guard before it was right — the shape of every survivor above.

A second gap: one mutant made the suite hang past 1200s instead of failing. With no per-test timeout, a deadlock regression looked like a slow CI run.

**Decision.** Two changes, one per gap.

`pytest-timeout` is a dev dependency with `timeout = 60` in `[tool.pytest.ini_options]` and no `timeout_method`. 60s is deliberately generous — the slowest honest tests wait on real process termination — because this is a deadlock detector, not a performance budget.

The method is unset because the plugin chooses better than a pin: `signal` where `SIGALRM` exists, `thread` elsewhere or off the main thread. Both aborted three hang shapes — blocked on an `Event`, on a held lock, in `communicate()` — at the deadline, standalone and under `pytest-xdist`. They differ in blast radius, which favours the default: `signal` raises in the test and the worker survives; `thread` dumps stacks and calls `os._exit(1)`, taking the worker's remaining tests with it.

`scripts/mutation_ratchet.py` scores a reproducible sample of mutants per package against a `FLOORS` table, in the same only-ever-goes-up form as `FACADE_BUDGETS`. It runs on demand, not from `zrb-test.sh`, since a pass takes minutes. It uses three operators — comparison swap, boolean-operator flip, boolean-constant flip — because those found the escapes above; arithmetic and string operators here yield far more equivalent mutants per real one, inflating the denominator. Each mutant runs only the package's mirrored test directory: faster, and the sharper question (see *Context*).

Sampling is seeded per package, so a rate is reproducible. Floors sit a few points below the measured values, not pinned exact like a line-count budget: a budget moves only when someone edits that file, but this sample is drawn from a pool of mutation *sites*, so an ordinary edit changes which mutants are drawn and moves the rate with no test changing. The margin absorbs that drift; it is not slack for new untested code.

**Consequences.** A hang now fails as a hang, naming the test that stalled. The kill rate can only be argued upward, and the six escapes above are its first work. `util/cmd` at 35% is the weakest package and first to fix — it also holds the process-tree escape.

The ratchet is POSIX-only and refuses elsewhere rather than report a number it cannot stand behind: a timed-out mutant is killed by process group, the only way to reach descendants reparented after the direct pytest process exits. Windows has no group to signal; a Job Object is the native answer if needed.

Unlike the eight shape ratchets, this one is a script, not a pytest test — forced by runtime — so a violation surfaces only when someone runs it, not as a red local gate. `scripts/mutation_ratchet.py`'s own operators are covered by `test/scripts/test_mutation_ratchet.py`, since a silent bug there would report a healthy rate over mutants that were never applied.

No tool can identify equivalent mutants automatically, so a floor is raised by a human reading survivors, not by a green run. Four of ten calibration survivors were equivalent; skipping that step means chasing assertions for mutants that cannot fail.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| `mutmut` | mutmut 3 copies only `paths_to_mutate` into a `mutants/` tree and runs there, so `zrb.config.config` is absent and every import fails. Making it work means mutating all of `src/zrb/` — which discards the per-package scoping the floors are built on. |
| `cosmic-ray` | Session database, config TOML and a separate `init`/`exec`/`report` cycle, for a job whose entire output is one integer per package. |
| Raise the coverage floor above 95% | Coverage does not measure the property that failed. Every one of the six escapes sits on a line the suite already executes. |
| Run mutations in `zrb-test.sh` | Minutes per pass. The per-commit gate is 117s and that is worth protecting. |
| Mutate every site rather than sampling | Hours per package. A seeded sample gives a comparable number in minutes. |
