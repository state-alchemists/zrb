# ADR-0097 — Test integrity is ratcheted on kill rate, not coverage

**Status:** Accepted

**Context.** `zrb-test.sh` gates coverage at ≥94%, and `test/architecture/` carries eight shape ratchets — facade line counts, constructor parameter counts, mccabe ≤19, radon ≤20, private-test-access ≤5, and the rest. Every one of them measures a property of the *source*. Coverage is the only gate that claims to measure the *tests*, and it measures the wrong thing: whether a line ran, not whether anything would have noticed had the line been wrong.

A sampled mutation run over ten core modules measured the gap. 22 mutants scored, 12 killed. Four survivors were equivalent or near-equivalent on inspection; six were real:

| Survivor | Mutation | What ships undetected |
| --- | --- | --- |
| `util/cmd/command.py` | `children(recursive=True)` → `False` | `_process_tree_pids` exists because a shell's children are reparented once it exits. `CmdTask` runs `<shell> -c`, so the work is a grandchild; the force-kill survivor list comes from this snapshot, so a grandchild ignoring SIGTERM never gets SIGKILL. |
| `llm/prompt/manager.py` | `skill_manager or default_` → `and` | A caller-supplied `skill_manager` is silently replaced by the global; `None` sets the attribute to `None`. |
| `llm/prompt/manager.py` | `inject_journal_index=False` → `True` | Both production callers rely on the default; the journal index would be injected every turn instead of the first. |
| `util/cmd/command.py` | `decode(b"", final=True)` → `False` | An incomplete UTF-8 sequence at stream end is never flushed — trailing command output silently lost. |
| `llm/skill/manager.py` | `exists() and is_dir()` → `or` | A path existing as a file is appended and later scanned as a directory. |
| `llm/skill/manager.py` | `user_invocable = True` → `False` | Frontmatter-less markdown skills vanish from the `/` menu. |

12/18 non-equivalent is ~67% on that ad-hoc run, which scored each mutant against the *whole* suite. Scoring against only the mutated package's mirrored tests — the question a per-package floor actually asks — the rate over four packages is 51/98, or 52%: `task/base` 56%, `util/cmd` 35%, `llm/skill` 60%, `llm/prompt` 56%. The two numbers are not comparable, and the lower one is the one worth holding: a mutant killed by an unrelated integration test shows the system noticed, not that this package is asserted on.

The escapes are not in obscure corners: they are boolean guards in process teardown, default parameter values, and `or`-vs-`and` in constructor fallbacks. The suite holds 5729 `patch`/`Mock` uses across 5438 test functions, and a mock asserts that a call happened, not that the guard preceding it was right — which is precisely the shape of every survivor above.

The same run surfaced a second gap: one mutant made the suite hang past 1200s rather than fail. No per-test timeout was configured, so a deadlock regression presented as a slow CI run rather than a failure.

**Decision.** Two changes, one per gap.

`pytest-timeout` is a dev dependency with `timeout = 60` and `timeout_method = "thread"` in `[tool.pytest.ini_options]`. The method is not the default: `signal` needs `SIGALRM`, which is POSIX-main-thread only, and the suite runs under `pytest-xdist` and on Windows. 60s is generous on purpose — the slowest honest tests here wait on real process termination — because this is a deadlock detector, not a performance budget.

`scripts/mutation_ratchet.py` scores a reproducible sample of mutants per package against a `FLOORS` table, in the same only-ever-goes-up form as `FACADE_BUDGETS`. It is run on demand, not from `zrb-test.sh`: a pass is minutes, and the per-commit gate stays fast. Three operators — comparison swap, boolean-operator flip, boolean-constant flip — because those are the ones that found the escapes above; arithmetic and string operators produce far more equivalent mutants per real one in this codebase, inflating the denominator without adding signal. Each mutant runs only the package's mirrored test directory, which is both fast and the sharper question: a mutant killed by an unrelated integration test is not evidence that *this* package is asserted on.

Sampling is seeded per package, so a rate is reproducible. The floors sit a few points below the measured values rather than pinned exact the way a line-count budget is, for a structural reason rather than a statistical one: a budget's input is one number that moves only when someone edits that file, whereas this sample is drawn from a pool of mutation *sites*, so an ordinary edit shifts which mutants get drawn and moves the rate without any test changing. The margin absorbs that drift; it is not slack for new untested code.

**Consequences.** A hang now fails as a hang, naming the test that stalled. The kill rate is a number that can only be argued upward, and the six escapes above are the first work it points at. `util/cmd` at 35% is the weakest package and the one to fix first — it is also where the process-tree escape lives.

The ratchet is a script, not a pytest test, which is a departure from the eight shape ratchets. That is forced by runtime, and it costs the property those have: a violation surfaces only when someone runs it, not as a red local gate. `scripts/mutation_ratchet.py`'s own operators are covered by `test/scripts/test_mutation_ratchet.py`, since a silent bug there would report a healthy rate over mutants that were never applied.

Mutation testing cannot identify equivalent mutants automatically — no tool can — so a floor is raised by a human reading survivors, not by a green run. Four of ten survivors in the calibration run were equivalent; a reviewer who skips that step will chase assertions for mutants that cannot fail.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| `mutmut` | mutmut 3 copies only `paths_to_mutate` into a `mutants/` tree and runs there, so `zrb.config.config` is absent and every import fails. Making it work means mutating all of `src/zrb/` — which discards the per-package scoping the floors are built on. |
| `cosmic-ray` | Session database, config TOML and a separate `init`/`exec`/`report` cycle, for a job whose entire output is one integer per package. |
| Raise the coverage floor above 94% | Coverage does not measure the property that failed. Every one of the six escapes sits on a line the suite already executes. |
| Run mutations in `zrb-test.sh` | Minutes per pass. The per-commit gate is 117s and that is worth protecting. |
| Mutate every site rather than sampling | Hours per package. A seeded sample gives a comparable number in minutes. |
