# ADR-0097 — The journal has one master switch, gated at `active_sections`

**Status:** Superseded by ADR-0099 — the journal has no prompt section to gate any more, so `LLM_JOURNAL_ENABLED` moved to tool registration. (Was: Accepted, extends ADR-0073, narrows ADR-0069.)

**Context.** The cross-session journal reaches the model through four
independent surfaces: the `journal_mandate` prompt section, the
`<journal-index>` injection into the latest user turn (ADR-0082), the
`SearchJournal` tool, and the built-in `core-journaling` skill. Each was
reachable by a different lever, and no combination of them turned journaling
off:

- `LLM_JOURNAL_DIR` has no "unset" value. Its `default_factory` falls back to
  `~/<root>/llm-notes`, so clearing the env var relocates the journal rather
  than disabling it.
- Dropping `journal_mandate` from `LLM_INCLUDE_SECTIONS` removes the protocol
  but leaves `core-journaling` advertised in the `{CORE_SKILLS}` catalogue,
  because `_get_builtin_dirs` includes `core_skills/` unconditionally —
  `LLM_ENABLE_BUILTIN_SKILLS` gates only `skills/`.
- `LLM_JOURNAL_INDEX_MAX_CHARS=0` suppresses the injected snapshot alone, and
  Journal Protocol then tells the model that a missing `<journal-index>` means
  an empty journal — which that configuration makes false.

A benchmark harness surfaced the cost. `zrb-llm-evaluator` isolates each trial
by pointing `ZRB_LLM_JOURNAL_DIR` at a per-trial `notes/` directory and
`mkdir`-ing it, which leaves the directory **existing but empty** — precisely
the trigger for structural work (`core-journaling`: "The first write into an
empty journal is always structural"). Across a 288-run sweep the two models
that follow the protocol built a full HUD tree in 33/36 and 31/36 runs, 9–10
files each, then discarded it. Measured on clean traces, tool calls at or after
`core-journaling` activation were 13/33, 19/35 and 34/44 of the run. The
journal's value is cross-session reuse, so in a single-session trial the payoff
is structurally zero — and the cost fell only on the compliant models, making
the comparison unfair in the direction of ignoring the protocol. The same first
-session tree build lands on every new user.

**Decision.** Add `LLM_JOURNAL_ENABLED` (`ZRB_LLM_JOURNAL_ENABLED`, default
`on`) — state-last per ADR-0073, because `LLM_JOURNAL_*` already has three
siblings (`_DIR`, `_INDEX_FILE`, `_INDEX_MAX_CHARS`).

Gate it primarily in **`PromptManager.active_sections`**, which drops
`journal_mandate` from the resolved list. That one point reaches three surfaces,
because `active_sections` is already the single source of truth for section
presence: composition stops emitting the section, `_emitted_sections` no longer
lists it so `<!--requires:journal_mandate-->` blocks in `workflow` and `mandate`
strip themselves (ADR-0094), and every existing
`"journal_mandate" in active_sections` guard — the index injection and both
summarization paths — goes false at once. No consumer needed a new check.

Two surfaces sit outside prompt composition and are gated at their own site:
`render_journal_index` returns `None` early (reachable directly from
`summarize_history`, so it does not rely on its callers), and `SearchJournal`
moves from the static `add_tool` list to a conditional tool factory, matching
the `ask_user_question` idiom.

`core-journaling` is dropped **per skill, not per directory**: `core_skills/`
deliberately has no blanket toggle, and only the copy under
`BUILTIN_PLUGIN_DIR` is removed. A user or project skill of the same name
overrode it during the scan and survives — ADR-0069's rule that a toggle
suppresses built-in content, never the user's.

**Consequences.**

- Off removes ~4,000 characters (30,514 → 26,482 on the default composition)
  and the model is never told a journal exists, so it neither reads nor writes
  one. All four surfaces are verified to go dark together, with no marker leaks.
- The gate is read when each surface is first resolved, and the skill catalogue
  caches its scan. This is correct for a process whose config is fixed at
  startup, but flipping the knob mid-process will not retroactively rescan
  skills.
- `journal_mandate` now has two ways to be absent — trimmed from
  `LLM_INCLUDE_SECTIONS`, or switched off here. Both converge on
  `active_sections`, so downstream code keeps one condition to check.
- Benchmarks and other single-session harnesses should set it off, or pre-seed a
  root index so the structural trigger is false. Isolation alone guarantees the
  expensive path.

**Alternatives rejected.**

- *Gate each of the four surfaces independently.* What already existed, and the
  reason nothing could turn journaling off: three of the four levers were
  reachable and the fourth (`core-journaling`) had none. It also invites the
  half-off states that made the protocol lie about an empty journal.
- *Treat an empty `LLM_JOURNAL_DIR` as "disabled".* Overloads a path with a
  mode, and would silently disable journaling for anyone who cleared the
  variable expecting the documented `~/<root>/llm-notes` default.
- *Give `core_skills/` a blanket toggle.* Too broad — it would take
  `core-coding`, `core-research`, `core-writing` and `core-design` with it. The
  switch is scoped to one subsystem, so it removes one skill.
- *Leave `core-journaling` listed and rely on the protocol's absence.* Measured
  as insufficient in the sweep: the catalogue entry alone describes building the
  tree, which is the surface the switch exists to remove.
