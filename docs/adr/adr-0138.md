# ADR-0138 — Memory is one claim per file, two verbs, and a cap that refuses

- **Status:** Accepted
- **Date:** November 3, 2026

## Context

The journal kept a persistent memory in five category directories: one note per finding with six frontmatter fields, five writer tools, a generated root index and per-category indexes, an activity log, a handover section, and a compliance judge that decided after each turn whether to write. Measured on the live store on 2026-11-03: 327 notes, a 16,198-character index against a 3,600-character injection cap (22% resident), 107 notes whose `applies_when` said "not stated" and so could never be retired, 11 with a form anything could check, and 96 notes added in four days. Nothing in the system merged, promoted or retired a note. Retrieval had been improved twice (ADR-0136 ranked the injection; the per-turn claims block showed what a session recorded), but the store grew faster than anything pruned it, and recall still depended on the agent guessing the word a note had used.

Two things were structurally wrong rather than under-tuned. A note was identified by a slug the writer chose *per document*, so the same subject could be recorded twice and there was no merge to bring them together. And an append-only day file also carried a rewritten `## Handover` section, which is why `_without_handover`, `_insert_after_entries`, `_append_day_line` and a `[recovered from a handover]` marker all existed: four pieces of code whose only job was to stop one shape from eating the other.

A specification for a memory system was written the same day (`docs/technical-specs/llm-memory.md`) and reviewed against the journal's measured failures.

## Decision

Replace the journal with a store of four file kinds, three tools and a generated core.

- **A fact is a file, identified by its subject.** `facts/<id>.md` carries a `claim` — one sentence, at most 160 characters — and an optional body that is evidence and is never injected. `id` is kebab-case and validated, so a model-chosen id cannot name a path; re-using an id is how a claim is revised, and that is the whole deduplication rule.
- **A day is a file, identified by its date.** `diary/<YYYY-MM-DD>.md` carries the day in one line, an optional first-person body, and an optional `handover`. A second session on the same day merges into the same file. `log/<YYYY-MM-DD>.md` is append-only and holds events with clock times — the two shapes are separate files because an append-only stream and a rewritten section cannot share one.
- **The core is generated, and the cap is enforced by refusal.** `core.md` renders pinned facts and open loops, deterministically. A write that would exceed `LLM_MEMORY_CORE_MAX_CHARS` writes nothing and returns the deficit and the current core, so the decision to forget happens in that turn instead of never. A diary entry never enters the core.
- **Retrieval is three fixed layers plus a search.** The core and `## Recent` are injected on a conversation's first turn (never into the cached system prompt, which a mutable block would invalidate on every write); a per-turn delta carries what changed since; `SearchMemory` returns pointers — the claim and its path — for everything else.
- **Writing is two verbs.** `Remember` covers a fact, a loop, a diary entry and a handover; `Forget` retires with a reason and keeps the file. An argument left out keeps its stored value, so a merge cannot silently drop a pin.
- **A background reviewer writes most of it.** A Stop hook reads one completed turn with the three tools and writes what is durable. Its normal answer is nothing, and it runs off the critical path. The log line is appended by the hook from the reply's first sentence, because a hook on a conversation event can describe the conversation and a *day* is not something it can infer.
- **Git is the audit log.** Every write commits; nothing is deleted.

## Consequences

The store cannot drift by construction: a subject has one file, so "the same thing twice" needs a differently-chosen id rather than a merge pass that nobody schedules. Forgetting is one call and is visible in the next prompt. Reading a claim costs one line instead of opening a note, and the index that used to say a note *exists* now says what is *claimed*.

Costs and limits, all deliberate:

- **The cap is a hard edge.** A write that does not fit fails, and the caller must forget something first. That is the design, but it means pinning is a decision the agent can get wrong in both directions: too many pins and the store refuses; too few and the core empties while the store looks healthy. Refusal rate and core occupancy are the numbers to watch.
- **Dedup is by id, and the id is model-chosen.** `staging-ssh-port` and `ssh-port-staging` remain two files. This is much cheaper drift than the journal's, but the reviewer's search-before-add is a heuristic, not a guarantee.
- **The reviewer costs a small-model call on every completed turn**, most of which conclude "nothing". Turning it off leaves writing entirely to the agent's own `Remember` calls.
- **One writer process per directory is not assumed, but concurrent writers are only as correct as the lock.** The transaction takes the lock before it reads, and the default directory carries a version segment, because a session opens worktrees and this machine has two installs.
- **The journal's code was deleted in the same release, and `LLM_MEMORY_ENABLED` outlived it as the privacy switch.** The journal's modules, its five tools, its injection, its judge and their tests are gone — removing them was a cleanup of its own, and this is where it happened. With one store left, the switch no longer picks between two: off suppresses the three memory tools, the `<memory>` block and the reviewer, and the session reads and writes no memory at all. Dropping it with the journal would have left no way to say "not this session".
- **Search has no embeddings.** At three hundred facts, any-of matching on a one-sentence claim is measurable and debuggable; vector recall is a non-goal until searches miss in practice.

## Alternatives rejected

- **A consolidation pass over the journal's notes.** It schedules a cleanup for drift that should never accumulate, and the merge still has to decide which of two slugs is the subject.
- **Atomic-fact stores (Mem0-style extraction).** They lose the auditable source: a claim with no file is a claim nobody can check.
- **A vector store at three hundred facts.** The measured store is 1.6 MB; the cost is an index that has to be rebuilt and a score nobody can explain.
- **Keeping the journal's five tools and adding a memory one.** Two vocabularies for one act is the friction the replacement exists to remove.
- **A fourth verb for the log.** It is one line per event, written by the hook that already knows the turn; a tool for it would add a validation path and a per-turn instruction tax.
