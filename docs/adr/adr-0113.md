# ADR-0113 — Screen capture is a one-shot command plus an opt-in tool that always asks, through each platform's own capture program

**Status:** Accepted

**Context.** "Look at this error" is easier to say than to copy out, so the chat should be able to see the user's screen. A screen is not like a camera photo, though: it can show a password manager, a private chat or a bank tab, and an agent that looks at it on its own could send all of that to a model provider without the user noticing.

Screen access is as fragmented as camera access (ADR-0082). macOS has `screencapture`, gated by the Screen Recording permission the first capture asks for. Windows has a Win32 screen API, which Pillow, already a zrb dependency, wraps. WSL's Linux side has no screen; its desktop is Windows'. On Linux, Wayland denies clients one another's pixels, so each compositor family has its own program (`grim` on wlroots, `gnome-screenshot` on GNOME, `spectacle` on KDE), while X11 lets any client read the root window. Android lets no app capture the screen without root or adb.

**Decision.**

1. **The same shape as the camera** (ADR-0102): `enable_screenshot(chat, ScreenshotConfig)` registers a `/screenshot [display]` command and a `TakeScreenshot` tool factory, each config field mirrors a `CFG.LLM_SCREENSHOT_*` knob read when a session starts, and a backend is a name or an `AnyScreenshotBackend`. The built-in `llm_chat` calls it, so the command works out of the box.
2. **The command and the tool are separate switches.** The command is user-initiated, so it is on, like `/photo`; `commands=[]` leaves it out. The tool is off (`enable_tool`, `LLM_SCREENSHOT_ENABLE_TOOL`), so the agent can look at the screen only when the user opted in. Either can be had without the other.
3. **The tool always asks.** `TakeScreenshot` is tagged `Capability.EXECUTE`, not `READ`, as `TakePhoto` is: plan mode allows `READ` without asking and denies `EXECUTE`, and every call goes to the approval prompt. Its docstring tells the model to use it only when the user refers to their screen, not to check on them unprompted, and to prefer reading a file or command output.
4. **No new capability.** A "sensitive capture" capability was considered for screen and camera alike. `EXECUTE` already gives what is needed (always prompts, denied in plan mode), and a new member would have to be taught to every policy, the plan-mode gate and every UI for no different behavior.
5. **Capture shells out per platform, in a fixed chain** (`AutoScreenshotBackend`), all attempts within one `timeout`:

   | Platform | Chain |
   | --- | --- |
   | macOS | `screencapture -x` (no shutter sound) |
   | Windows | Pillow `ImageGrab`, then `powershell` drawing the screen through System.Drawing |
   | WSL | `powershell.exe` through interop, printing the image as base64 so nothing crosses file systems |
   | Wayland | `grim`, `gnome-screenshot`, `spectacle` |
   | X11 | Pillow `ImageGrab` over XCB, `scrot`, ImageMagick `import`, `gnome-screenshot`, `spectacle` |
   | Termux | none; the failure hint says to take the screenshot on the phone and `/attach` it |

   A Wayland session never falls back to the X11 grabbers: through XWayland they see only X clients and would return a black or partial screen instead of failing. Pillow is called with the X display named, so it never runs its own fallback programs, which have no time limit. A program writes into a fresh temporary directory, removed on every path out, so a failed capture never returns an earlier screen and nothing is left on disk.
6. **Every capture is scaled** with `scale_image_bytes`, like a pasted image, and reaches a text-only model by the rule a prompt attachment follows (`create_image_tool_return`, shared with the camera and `Read`).
7. **A failure explains itself** (ADR-0093): the platform's hint (on macOS, the Screen Recording permission) plus what each program tried said.

**Consequences.** `/screenshot` works with nothing to install on macOS, Windows, WSL and most X11 desktops. Wayland needs the compositor's program. The display argument means what the platform's program takes (a macOS display number, a `grim` output name, `all` on Windows), and other programs ignore it. On a non-local UI (the web chat, Telegram) the command refuses: the capture would show the server's screen, not the user's, so the user attaches an image from their own device instead. The tool, which asks for approval first, is how a user who wants the server's screen gets it.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Tag the tool `READ` | Plan mode would let the agent capture the screen without asking. |
| A new `Capability` member for captures | Same behavior as `EXECUTE`, at the cost of teaching it to every policy and UI. |
| The tool on by default | The agent could look at the screen of a user who never asked for it. |
| `mss` or another capture library | A new dependency for what each platform's program and Pillow already do. |
| Pillow `ImageGrab` everywhere | It shells out to `screencapture` and the Wayland programs itself, with no time limit and no way to say which failed. |
| The XDG desktop portal over D-Bus | Needs a D-Bus client and an asynchronous request/response dance; GNOME and KDE's own programs cover the same desktops. |

**Where it lives.** `src/zrb/llm/screenshot/feature.py` (`enable_screenshot`, `attach_screenshot`, `create_screenshot_tools`), `src/zrb/llm/screenshot/backend/` (`tool.py`, `pillow.py`, `auto.py`, `builtin.py`), `src/zrb/llm/screenshot/config.py`, `src/zrb/config/mixins/llm_screenshot.py`, `src/zrb/llm/util/deadline.py`.
