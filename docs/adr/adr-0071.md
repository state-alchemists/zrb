# ADR-0071 — Todo progress reaches the user through a UI side channel

**Status:** Accepted

**Context.** After a todo-list write, the tool result is consumed by the model
and appears in the stream only as a terse "executed" line, so the user has no
sense of overall progress. Three UI backends — terminal TUI, StdUI and web — all
implement `append_to_output()` with a `kind` discriminator, and tool functions
can already read the active UI from a ContextVar.

**Decision.** The todo-writing tool pushes a rendered progress view to the
active UI through a **separate `append_to_output()` call** with kind
`"todo_progress"`, *in addition to* returning its normal text result. The
model-visible contract is unchanged.

The rendered text carries a change description line, the full list with
per-item status icons, and a `~DATA~` line whose JSON payload feeds the web
frontend's stats card. The terminal TUI and StdUI render it at full opacity —
the one exception to the muting that normally applies to non-text kinds — and
the web UI renders a styled card with a progress bar.

**Consequences.** Users get immediate, persistent progress feedback in all three
backends, with zero change to tool return values and zero changes to the
confirmation, permission or auto-approval pipelines — the visualization is
fire-and-forget. Costs: the UI import must be lazy to avoid a circular import;
the `~DATA~` marker is a small structural convention readers of the output must
know about; and two backends need a one-line exclusion for the new kind.

**Alternatives rejected.** *Put the progress in the tool return value only* —
the model already sees it, but the user never does, which is the whole problem.
*Hook into the tool-confirmation pipeline* — the todo tools are auto-approved,
so a post-approval hook adds ceremony for no benefit. *A dedicated SSE event
type* — over-engineering for structured data that fits on one line beside the
human-readable text. *Have the UI poll the todo manager* — the wrong
abstraction; the UI should not know about todo state or a poll interval.

**Where it lives.** `src/zrb/llm/tool/plan.py`,
`src/zrb/llm/ui/default/output.py`,
`src/zrb/runner/web_route/chat_page/chat.js`,
`src/zrb/llm/util/stream_response.py` (`PrintKind`).
