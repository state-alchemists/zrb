# ADR-0036 — pydantic-ai as the agent framework

**Status:** Accepted

**Context.** `LLMTask` and `LLMChatTask` need a tool-calling agent loop with
streaming and multi-provider support. Building that loop from raw SDK calls
means reimplementing orchestration; a heavyweight framework takes away the
fine-grained control zrb needs over approval, UI and history.

**Decision.** Wrap `pydantic_ai.Agent`, created in `agent/common.py`. Tools are
type-annotated Python functions; the event stream drives zrb's UI and approval
flow; the provider abstraction supplies vendor-agnosticism. zrb keeps the
wrapper thin enough to override behaviour — history and retries in particular —
where the library's defaults do not fit.

**Consequences.** Async-native, structured tools, provider-agnostic, low
coupling. The cost is a dependency on pydantic-ai's message model, and the
occasional need to work around its internals — see ADR-0041 (history
processors) and ADR-0043 (`ToolReturn`).

**Alternatives rejected.** *Raw SDK calls* — reimplement the tool loop per
provider, a large bug surface for no differentiation. *LangChain* — heavy, an
opinionated callback model, and awkward async control at the point where zrb
needs to interpose approval. *RAG-first frameworks* — the wrong problem domain.

**Where it lives.** `src/zrb/llm/agent/common.py`.
