# ADR-0088 — A shared leaf module lives outside the package that happens to write it, not nested inside it

**Status:** Accepted

**Context.** `agent/run/runtime_state.py` (ambient `ContextVar`s: current UI, YOLO, hook manager, ...) and `agent/tool_result.py` (`ToolReturn` construction) had no real dependency on the rest of `zrb.llm.agent` — their own docstrings called them "leaf modules" — yet lived inside that package because `run_agent()`/`create_agent()` are their main callers.

Parent packages load before their submodules, so importing either from outside (`zrb.llm.tool.ask`, `zrb.llm.tool.plan`, `zrb.llm.ui.base.ui`, `zrb.llm.tool.wrapper` and others, each needing only a `ContextVar` getter or `tool_return()`) ran `zrb.llm.agent`'s package `__init__` first. That made `zrb.llm.ui`, `zrb.llm.tool.plan`/`ambient_state` and `live_context.py` genuinely circular with `zrb.llm.agent`: five `# lazy: circular` workarounds existed for this reason. (A sixth, structurally identical one in `hook/execution/creator.py` was fixed separately by deferring its two eager importers — see `test_circular_import_allowlist.py`.)

A closure walk (every module-level import, transitively, excluding `if TYPE_CHECKING:` blocks) found `zrb.llm.agent` and `zrb.llm.ui` each eagerly reach about 400 of the repo's ~430 `zrb.*` modules. At that density a leaf nested in either is reachable from many directions — `live_context.py` alone had 4 eager entry points from within `zrb.llm.agent`'s closure — so deferring the one import site a comment names leaves the module in the closure; the "circular" tag just moves.

**Decision.** When a module has no real dependency on the package it is nested in, and something *outside* that package needs it, move it to a plain top-level sibling instead of deferring the import. Both modules qualified: their docstrings said so, and both were verified to import nothing from `zrb.llm.agent`, not even lazily. `runtime_state.py` became `zrb.llm.agent_state`; `tool_result.py` became `zrb.llm.agent_tool_result`. The same rule later moved `zrb.llm.agent.activity` to `zrb.llm.agent_activity` and `zrb.llm.tool.ambient_state` to `zrb.llm.ambient_state` (the UI read both, so `llm.ui` imported `llm.agent` and `llm.tool` while those imported `llm.ui` back), and `zrb.llm.tool.registry` to `zrb.llm.tool_registry` (sub-agent building read it while the delegate tools imported `llm.subagent`). Neither location sits under a package whose `__init__` reaches back into `zrb.llm.agent`, so importing them never triggers that package's `__init__`.

All 5 lazy imports were then hoisted to ordinary module-level imports and their `# lazy: circular` tags deleted — no cycle remained. This was verified empirically both ways (in a scratch copy, hoisting each import raised `ImportError` before the move and succeeded after), not by hand-tracing the graph: partially-initialized modules and package-init ordering are subtle enough that manual tracing missed a second, unrelated cycle hiding behind the first during the same investigation.

**Consequences.** Five formerly circular imports are ordinary top-level imports with no comment — genuinely not circular, not recategorized. `zrb.llm.tool.ask`, `tool.plan`, `tool.shell`, `tool.web`, `tool.delegate`, `tool.delegate_background`, `tool.file_observation`, `ui.base.ui` and `tool.wrapper` no longer pull in `zrb.llm.agent`'s construction/run-loop machinery to read a `ContextVar` or build a `ToolReturn` — a real reduction in their eager-import closures.

The cost is five top-level modules under `zrb.llm` (`agent_state.py`, `agent_tool_result.py`, `agent_activity.py`, `ambient_state.py`, `tool_registry.py`), named for what they hold. A reader must know the convention — a top-level state module is a leaf shared across packages, not construction logic — rather than finding it by package nesting.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Defer more of the importing side's own imports | Fixed `hook/execution/creator.py`'s cycle, and was the first thing tried here; it fails when the target has many independent eager entry points (`live_context.py`'s 4) — fixing one or two leaves the rest, and the module never leaves the closure. |
| Keep the `# lazy: circular` comments as the permanent fix | They document a workaround for a misplaced module instead of removing the misplacement; every future consumer of the leaf inherits the tax and rediscovers the "must stay lazy" rule. |
| Split `zrb.llm.agent.__init__` to import less eagerly | Wrong lever for these two: their problem is placement, and moving them fixes it for every consumer at once. The barrel is a separate problem, deferred through PEP 562 in ADR-0096. |

**Where it lives.** `src/zrb/llm/shared/agent_state.py`, `src/zrb/llm/shared/agent_tool_result.py`, `src/zrb/llm/shared/agent_activity.py`, `src/zrb/llm/shared/ambient_state.py`, `src/zrb/llm/shared/tool_registry.py`, and every former importer of `zrb.llm.agent.run.runtime_state` / `zrb.llm.agent.tool_result` (now `zrb.llm.shared.agent_state` / `zrb.llm.shared.agent_tool_result`). `test/architecture/test_circular_import_allowlist.py` (the allowlist, and the per-module isolated-import check). ADR-0033 (the lazy-import discipline this works alongside, not replaces — most `# lazy:` imports correctly defer genuine third-party weight rather than stand in for a misplaced module).

## Amendment — 2026-11-07: the leaves move into `llm/shared/`

The rule this record sets out still holds; what changed is the shape of "a plain top-level sibling". Keeping the leaves at the top of `zrb.llm` put them beside features — `agent/`, `tool/`, `ui/` — so `llm/` read as one shelf holding two kinds of thing, and a reader had to know the convention before an import line made sense.

Every layer-0 leaf module now sits in `zrb.llm/shared/`: the five named above, plus `agent_runner` and `delegation_api` (the two seams a higher package registers itself into), `message`, `message_text`, `input_source`, `factory_resolver`, `stream_observer`, `shell_cut`, `usage_log`, and `feature_config` — which moved out of `util/` because it reads ambient session state, and leaving it there made `util` and `shared` import each other. `util/` is now a leaf: it imports nothing from `zrb.llm` at runtime but the `agent/types.py` contract.

The `config`, `memory` and `util` packages stay where they were. They are subsystems with structure of their own rather than leaves, and the layer rule is what put them at L0, not weight.

The argument that justified the original move no longer needs re-measuring: that record rested on `zrb.llm.agent` and `zrb.llm.ui` each eagerly reaching ~400 of the repo's modules. Importing `zrb.llm.agent` now pulls seven. What keeps the leaves outside their packages is the layer rule — a leaf nested in a package inherits that package's layer and grows an upward edge from everything beneath it.

The layering ratchet's layer-0 row is now four names (`config memory shared util`) where it used to be fourteen, and `test/architecture/test_seam_module_imports.py` refuses any runtime `zrb` import in either seam, since a module the package registers into is half-built while that package loads.
