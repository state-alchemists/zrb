# ADR-0035 — Compose large classes from parts via explicit collaborators, not multiple inheritance

**Status:** Accepted

**Context.** `BaseUI` had become a god object — `ui.py` at ~1,019 lines and its slash-command companion at ~907, each mixing unrelated concerns. The first split kept every attribute on one shared `self` and moved method clusters into classes the host combined via **multiple inheritance** (`class LLMChatTask(ChatBuilding, ChatRunning, ChatExecution, BaseTask)`), each part declaring a `TYPE_CHECKING` "host-contract" block of what it assumed the host provided.

That fixed file size but had two defects:

- `class Owner(Part1, Part2, Part3)` reads as "Owner IS-A Part1 AND a Part2 ...", when the relationship is HAS-A. Nothing in the class statement says these parts are not reusable bases; a reader has to already know the convention.
- Every host-contract block was a second, hand-maintained copy of the host's real attribute types.

**Decision.** Composition replaces multiple inheritance: the owner constructs each part and holds it as a named attribute, and keeps a normal single-inheritance base (`BaseTask`, `BaseUI`, ...) only where that is a genuine is-a relationship.

**1. A part is a class its owner instantiates**, not a base: `self._building = LLMTaskBuilding(self)` instead of `class LLMTask(LLMTaskBuilding, ...)`. A part's constructor parameter is typed as the real owner class, so the type checker verifies accesses directly and `TYPE_CHECKING` host-contract blocks disappear.

**2. How a part reaches what it needs is chosen per part:**

| Case | Example | How the part reaches it |
| --- | --- | --- |
| Pure data, no cross-part calls | `SubAgentManagerSearch`, `LSPManagerLifecycle`'s own caches | Passed directly as constructor/method arguments |
| Needs one specific sibling's behavior | `LSPManagerQuery` needs `LSPManagerLifecycle` | Holds a direct reference to that already-constructed sibling |
| Needs behavior spread across several siblings and the owner's own methods, or state reachable through a public setter the owner may reassign after construction | `BaseUICommands`'s conversation/model/exec collaborators, which call into `BaseUIReplay`, `BaseUISystemInfo`, and `BaseUI` itself; `LLMTaskBuilding`, whose `history_manager` has a public setter | Holds a reference to the **owner**, and reaches its state **only** through a public property or method (`self._owner.x`, never `self._owner._x`) |

If the owner has no public accessor yet, add one — a one-line cost per piece of state, like the delegators in point 3. Because the owner is the single facade every part calls through, an instance-level patch or subclass override (`patch.object(ui, "append_to_output", ...)`, a test double overriding `stream_btw_response`) is honored regardless of which part implements the method, and a test reaching the same state does so without a private name.

**3. The owner re-exposes every previously inherited public method/property as a one-line delegator** (`def append_tool(self, *t): self._building.append_tool(*t)`), so external call sites are unchanged. A `_`-prefixed method that is in fact called from outside the owner (a sibling part or a test) is **promoted to public**, delegator and part method alike: under inheritance "private" meant module-internal by convention, but under composition the same name is a cross-object reach, which case 3 of point 2 treats as a defect. Owner methods that called an inherited part method by bare name need no change, since the delegator provides the name.

**4. `Mixin` stays reserved for genuinely reusable classes** that read no state they do not set (`BufferedOutputMixin`, the `CFG` mixins under `config/mixins/`). They were never part of the per-owner multiple-inheritance pattern.

**5. A part is named `<Owner><Aspect>`**, in a file named for the aspect: `ChatExecution` in `task/chat/execution.py`, `BaseUICommands` in `ui/base/commands.py`. No `_mixin` suffix, no leading underscore.

**6. `X/manager/manager.py` flattens** to `X/manager.py` plus `X/manager_<aspect>.py`.

**Consequences.**

- **Behavior-preserving.** Every constructor and public method signature is unchanged; the existing suite passed without changes to test intent. Tests that subclassed a part directly (`class MockLLMChatTask(ChatRunning)`, `class MockUI(BaseUICommands)`) now construct the real part with a stand-in owner.
- **Uniform override is enforced for slash-command dispatch** by `test/architecture/test_command_dispatch_surface.py`: every handler in `command_table()` must be bound to the UI instance. A handler bound to the implementing part resolves before the subclass is in the lookup, so an override would be skipped with no error.
- **State is encapsulated behind public accessors.** `self._owner._attr` reaches, and the mirror-image `self._part._attr` from owner into part, are defects; `zrb-test.sh`'s private-access ratchet enforces zero tolerance.
- **Costs.** One delegator per part method (mechanical but real line count); a part reaching several collaborators takes the whole owner rather than a narrower interface; each piece of cross-part *state* costs a small get/set property pair where a bare attribute would have done.
- **Cooperative `super()` chains need an explicit sibling reference.** In `llm/ui/default/ui.py`, `UISelection` and `UIConfirmation` cooperated only because MRO flattened them onto one `self`: `UISelection.handle_confirmation` fell through to `UIConfirmation`'s base case via `super()`, and `UIConfirmation` called `self.begin_choice`/`self.end_choice` expecting `UISelection`'s override (no-ops on `UIConfirmation` "so it works standalone"). With no MRO, `UISelection` holds a **direct reference to its `UIConfirmation` sibling** (case 2) for that one base-case call — routing via `self._owner` would loop back into `UISelection`'s own owner-level delegator. `begin_choice`/`end_choice`/`resolve_current` are public methods routed through the owner (case 3), so overrides and test assertions go through the public name. The no-op defaults are gone from `UIConfirmation`: an owner composing only `UIConfirmation` (as several tests do) supplies its own trivial `begin_choice`/`end_choice`, as any test double supplies what its part expects.
- **State one part holds and siblings read needs a public forwarding property on the owner.** `UIAgentPicker`'s `viewing_agent_id`/`saved_main_output` are read by `UIOutput`/`UIKeybindings`/`UIConfirmation` via `self._owner.viewing_agent_id`. Without a property on `UI` forwarding to `self._agent_picker`, the read silently falls back to `getattr(..., default)` (an assignment is caught by pyright as `reportAttributeAccessIssue`). The property must be public: a private one (`_viewing_agent_id`) is as unreachable to an outside caller or test as none, just relocating the violation. Since several parts read it and one writes it, `UI` exposes a public get/set property over the part that holds it.

**Alternatives rejected.**

- *Narrower collaborator interfaces per part* (e.g. `LSPManagerQuery` takes a `Callable[[str], Awaitable[LSPServer | None]]` instead of the whole `LSPManagerLifecycle`) — more decoupled, but not needed for the actual constraint (public API preservation), and it would make "the owner passes exactly what a part needs" harder to apply uniformly across parts with very different needs.
- *Collapse each family's constructor into config objects* — a breaking change to public surface, out of scope for a behavior-preserving refactor.
- *Keep multiple inheritance and rely on naming discipline* — the naming already existed and did not fix the class statement reading as multiple inheritance.

**Where it lives.** `src/zrb/llm/ui/base/`, `src/zrb/llm/ui/default/`, `src/zrb/llm/task/`, `src/zrb/llm/task/chat/`, `src/zrb/llm/lsp/`, `src/zrb/llm/agent/subagent/manager.py`, `src/zrb/llm/ui/event_driven_ui.py`, `src/zrb/llm/ui/queue_based_input.py`, `src/zrb/task/base/` (`BaseTask`'s own parts — `BaseTaskContext`, `BaseTaskExecution`, `BaseTaskLifecycle`, `BaseTaskMonitoring`, `BaseTaskOperators`), `AGENTS.md` (Code Style).
