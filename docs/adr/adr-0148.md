# ADR-0148 — A turn that ends saying it is working is asked to work, or to name what it waits for

**Status:** Accepted

**Context.** The harness's unit of work is the turn. When the model returns text with no tool call, the runner settles the turn and waits for the next message. A model can therefore close with "I am fixing all ten findings now" and start nothing: the sentence reads like a report, the harness reads a final answer, and the work waits for the human to type again. Observed on 2026-11-26, twice in two minutes: 19:36 "I am fixing all ten before asking for another review", 19:37 "I am starting with the two security regressions", each followed by no tool call and five unanswered review findings. The user's next message is what restarted the work both times.

The pieces for a local check exist: a Stop hook can block the turn (`session_extension.py`), the Stop payload carries the closing message and the turn id, and the prompt can state the rule. What was missing is anything that reads the closing message and disagrees with it.

**Decision.** Ship a built-in Stop hook, `unfinished-action` (`llm/capabilities/hook/builtin/unfinished_action.py`), registered as a default hook factory on every `HookManager` and on by default behind `LLM_UNFINISHED_ACTION_ENABLED`.

- **It reads the closing message, and nothing else.** No model call, no file, no registry: one regular-expression pass over `last_assistant_message`, so it cannot fail a turn and does not slow one. `timeout=None` says the same thing to the executor.
- **Only a present-progressive claim of work blocks.** "I am fixing", "I'm starting with", "I'm going to fix" name work happening now; the verb allowlist is what separates them from closings ("I'm done", "I'm happy to") and offers ("I'll review the diffs when you hand them over"). "I'll" and "I would" are deliberately not matched: an offer is a legitimate way to end a turn, and blocking it would buy recall at the price of extending turns that answered correctly.
- **A negation is not a claim.** "I am not fixing #1074 tonight" is the opposite of the sentence the gate exists for.
- **One block per turn.** The count is keyed by the payload's `turn_id` (falling back to `run_scope`); the second Stop is the continuation, and a gate that blocked it too would hold a turn that has already answered. At most 64 turns' counts are kept, oldest dropped, because a cancelled turn never clears its own.
- **The block quotes the claim back.** The reason carries the matched phrase and asks for the work or for the name of what is really being waited on — a person's decision, a running process, an outside event — then asks the model not to announce the same action again. A model that reads its own words sees the gap faster than one that reads a rule.
- **Registered last among the built-in Stop hooks.** A block ends the chain, so the observing hooks (memory, self-review) see the turn before this one decides to continue it; the continuation's own Stop gives them the extended turn rather than a truncated one.
- **A delegated sub-agent's run is skipped.** Its report is read by the caller that delegated it, not by the human, and the caller's own Stop is the one that can carry a promise into the transcript.
- **The prompt states the rule the gate enforces.** `llm/contracts/shared/markdown/workflow.md`, step 3: end a turn only when the answer is complete or a decision that is the user's is outstanding, never on an announcement. The prompt is what should prevent the ending; the gate is the backstop for the turn it did not prevent.
- **`LLM_UNFINISHED_ACTION_ENABLED` (default on)** switches the gate off for anyone who wants the bare turn boundary.

**Consequences.** A turn that ends on a real claim costs one continuation: the model either does the work or says what it waits for. A false positive — a claim the model did not mean as one — costs the same single round. The gate cannot tell whether work happened outside its view, and it does not try: a model that did the edits and then closed with "I am fixing more" is asked once, and answers once.

It is not a loop driver. It extends a turn that already ended; it cannot re-open a session for an outside event (a review landing, a check turning green), and it does not track an objective across turns. That mechanism, if it is wanted, is a goal-round driver with its own state, round counts and fencing — a different decision.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Turn the existing self-review gate on by default | It reviews the diff, so the observed turns — which changed no file — report "no files changed" and end. It also costs two snapshots and a reviewer run on every file-changing turn, which is why ADR-0100 left it opt-in. |
| Ask a small model at Stop | A model round trip on every turn to decide a lexical question, and a judge that can itself be wrong about a sentence. |
| Match "I'll" and "I would" as well | Offers are legitimate endings ("I'll review the diffs when you hand them over"); precision over recall is the rule `turn_evidence.py` already uses for preference signals. |
| Leave it to the prompt | The prompt is a request, and the observed session shows a request missed twice in two minutes. |
| Build the goal-round driver instead | The durable answer for an objective that outlives a turn, but it needs its own state, limits and fencing against competing input. This hook answers the single-turn failure now and does not pretend to be that. |
