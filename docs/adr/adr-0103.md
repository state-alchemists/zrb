# ADR-0103 — Speech reads a reply aloud whole, cut at a sentence end, or summarized, then says the rest is on screen

**Status:** Accepted

**Context.** A user away from the screen, or talking hands-free (ADR-0076), needs to hear the reply, and to hear that a tool is waiting for approval. Before this, the way to get that was an external tool such as peon-ping, installed as a Claude Code hook: it plays sounds on events, but cannot read what the agent said.

An example did it with Python hooks on `Stop`, `PermissionRequest` and `Notification`. Two problems showed up. zrb awaits a Python hook inline, so a hook that spoke would hold up the turn. And a long reply was cut at a fixed character count, stopping mid-sentence with no sign that more existed.

**Decision.** `enable_speech` (ADR-0102) registers the hooks and a `/speech` command.

1. **Hooks only queue.** Each hook puts text on a `Speaker`'s queue and returns. One background thread per task plays the queue in order. At exit, queued speech gets `drain_timeout` seconds, since `zrb chat --message` exits right after its reply.
2. **What is spoken is chosen by `events`.**
   - `reply`: the reply at `Stop`, never a sub-agent's (`nested_run`).
   - `approval`: "I need to write a file /tmp/a.py. I need your approval." This is a template, not a model call, since the user is waiting on it.
   - `question`: notifications that wait on an answer (`elicitation_dialog`, `permission_prompt`).
3. **A reply is cleaned, then fitted.** Code blocks, tables, URLs, markup and emoji are removed. A reply over `max_chars` is cut at the last sentence end in the second half of the window, else the last clause break, else the last whole word, and followed by `on_screen_note` ("The full answer is on screen."). A dot inside a word such as `main.py` is not a sentence end.
4. **Summarizing is opt-in.** With `summarize`, a long reply is summarized by `summary_model` (the small model by default, prompt `speech_summarizer`) on the speaker's thread, with an event loop of its own — a hook runs on a loop that closes, cancelling what is left on it, once the hook returns. Queued there, the summary keeps its place among what is spoken, and the exit drain waits for it. The summary is spoken with the note. If summarizing fails, the cut opening is spoken instead.
5. **Sessions take turns.** Playback holds `lock_file` through `hold_file_lock` (flock on POSIX, msvcrt on Windows). An utterance that cannot get the lock within `lock_timeout` is dropped, since speaking a stale reply late is worse than not speaking it. `is_speaking` reports a count of utterances playing in this process, then the default lock file and every lock file a `Speaker` in this process uses, so dictation ignores zrb's own voice however speech was configured, and two speakers playing at once never hide each other.
6. **Backends are local first.** `auto` is `termux` (Termux:API's `termux-tts-speak`) on Termux, `say` on macOS, else `espeak-ng`: each a binary, no Python package. A backend that needs one (pyttsx3) lives in zrb-extras. `openai` and `gemini` go over `urllib`, so no package is needed, and play the returned WAV with `wav_player` or the first of `afplay`, `paplay`, `aplay`, `ffplay`. Synthesis happens before the lock is taken, so a slow cloud request does not hold it. A failing backend falls back to the local engine, without the configured voice, which names a voice of the requested backend.
7. **`LLM_SPEECH_ENABLED` is the starting state**, off by default. `/speech` switches speech during a session, runs mid-turn, and drops whatever is still queued when switching off.

**Consequences.** Replies, approvals and questions are heard without an external tool, which is what peon-ping was used for. Speech never delays a turn. Two sessions on one machine never talk over each other, though which one speaks first is not defined. There is no barge-in: new speech waits for the current utterance. Summarizing costs one model call per long reply, which is why it is off by default.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Speak inside the hook | zrb awaits Python hooks, so speech would delay every turn. |
| Cut at a fixed character count | It stops mid-word, and the listener cannot tell the reply was longer. |
| Always summarize | A model call and its latency on every long reply, for users who may not want either. |
| A summary through a separate OpenAI client | It needs its own key and model config; zrb's model resolution already knows the user's small model. |
| Queue speech instead of dropping it when the device is busy | A backlog plays replies minutes after they were current. |
| Require an audio package (pyttsx3, simpleaudio) | Local engines and a WAV player already cover every platform through a subprocess. |

**Where it lives.** `src/zrb/llm/speech/feature.py` (`enable_speech`, `SpeechSession`, `describe_tool_call`), `src/zrb/llm/speech/player.py` (`Speaker`, `play`, `is_speaking`), `src/zrb/llm/speech/text.py`, `src/zrb/llm/speech/backend/`, `src/zrb/llm/prompt/markdown/speech_summarizer.md`, `src/zrb/config/mixins/llm_speech.py`.
