# ADR-0067 — Background work inherits permissions, interrupts to ask, and can be waited on with a bound

**Status:** Accepted

**Context.** Long, independent work — research, file generation, a slow build —
should not block the main agent. But a detached agent has no obvious way to get
tool approval, because the synchronous approval model assumes the *parent
blocks* while the UI is free. And once work is detached, learning whether it
finished cost a full model round-trip per poll: the model either busy-polled or
slept too long, with no way to say "block until done, but not forever".

**Decision.** `DelegateToAgentBackground` spawns a detached `asyncio` task and
returns a handle immediately; `GetDelegationResult(handle)` collects it, and
`MonitorProcess(handle)` does the same for background shell commands
(ADR-0064). Polling is model-driven, so no lifecycle surgery is required.

The task **copies the spawning context**, so it inherits the main agent's
permissions, approval channel and UI. When a tool needs approval, its
`BufferedUI` forwards to the parent UI's confirmation queue (ADR-0068), which
**interrupts and prompts the user** — exactly like a synchronous delegate.
Fan-out is simply several background agents.

Both collection tools take `wait: float = 0` (and `kill: bool = False`). With
`wait > 0` the call blocks up to `min(wait, CFG.LLM_BACKGROUND_WAIT_MAX)`
seconds using `asyncio.wait`, which does **not** cancel on timeout, so the work
continues; it returns the instant the work finishes, or the existing
"still running" status so the model can wait again or kill.
`LLM_BACKGROUND_WAIT_MAX` defaults to 300s and is the only CFG timeout expressed
in seconds rather than milliseconds, because it is LLM-facing.

**Consequences.** Delegation is non-blocking without either auto-approving or
silently denying, and N polling round-trips collapse into one bounded call that
early-returns. Because the wait is `async` the event loop stays free, so a
background sub-agent that needs approval still surfaces its prompt through the
parent's queue while the main loop is parked in the wait — covered by a
regression test. Costs: results are not durable across a process restart; if the
main agent stops polling before the user answers, the sub-agent parks on the
prompt until answered (model pacing, not a bug); and a runaway `wait` is capped
rather than unbounded.

**Two earlier iterations are kept as record**, because both are the obvious
first ideas:

1. **Fail closed** — auto-deny anything not pre-approved. This made the feature
   useless: a "write a poem" delegation had `Write`, then `Shell`, then `echo`
   denied, and the agent gave up empty-handed.
2. **Auto-approve everything** — worked, but granted the sub-agent *more*
   permission than a non-yolo parent has. Rejected on principle: a sub-agent
   must not exceed its parent. The correct design inherits and routes to the
   existing queue.

**Alternatives rejected.** *Push a notification on completion* — requires
injecting results into a future turn, which is lifecycle surgery. *True in-call
async* — a pervasive refactor of the per-turn synchronous model.
*`asyncio.wait_for` for the bounded wait* — cancels the task on timeout, which
is exactly wrong: the work must continue. *An unbounded `wait`* — one tool call
could hang the entire turn.

**Where it lives.** `src/zrb/llm/tool/delegate_background.py`,
`src/zrb/llm/tool/shell_background.py`,
`src/zrb/llm/ui/default/confirmation.py`,
`src/zrb/config/mixins/llm_limits.py` (`LLM_BACKGROUND_WAIT_MAX`).
