# ADR-0067 — MCP servers are first-class tool sources

**Status:** Accepted

**Context.** A growing ecosystem of MCP servers already exposes useful tools. Reimplementing them would be wasteful, and a parallel integration path would give them different safety behaviour from native tools.

**Decision.** Load MCP server configs in the Claude Desktop format (`mcp-config.json`), discovered from cwd up to home with project overriding home. Spawn stdio servers or call SSE/HTTP ones, and wrap their tools with the **same** safety, truncation and permission layer as built-in tools.

**Consequences.** The MCP ecosystem is reusable and its tools behave consistently with native ones — capability tagging, permission rules, truncation and the sandbox all apply. The cost is that external server processes and their failure modes enter the agent loop.

**Alternatives rejected.** *A proprietary server spec* — incompatible with every existing server. *Python-only manual registration* — less discoverable, and it excludes non-Python servers. *Pass MCP tools through unwrapped* — inconsistent error handling and no permission coverage for exactly the least-trusted tools in the set.

**Where it lives.** `src/zrb/llm/tool/mcp.py`, `src/zrb/llm/agent/common.py` (`SafeToolsetWrapper`), `docs/llm/mcp-support.md`.
