# ADR-0109 — A conversation is renamed from its first message but keeps a stable key, and loading it restores its sub-agent sessions

**Status:** Accepted

**Context.** A conversation the user did not name gets `get_random_name()` — `trim-coil-1234` — which says nothing about what it holds, so `/load` and the session list are a wall of random names. Claude Code names a conversation after its first message.

Renaming is easy; what hangs off the name is not. Delegated sub-agent transcripts are saved as `{parent}-sub-{agent}-{id}` (ADR-0083) and live sub-agent sessions are registered under the chat session's key. If both follow the *display name*, a rename has to move every transcript, re-key every live session, and keep them consistent when a move fails half way. That is where an earlier attempt at this decision spent its complexity: multi-file moves, rollback, rollback of the rollback, and a conflict check on re-keying.

Loading a conversation restores its main history but not the in-memory `LiveSubAgentSession` entries, so a sub-agent the user could message before saving is gone after `/load`.

**Decision.**

**A conversation has a key, and the topic is only a display suffix.** The key is the generated name without a topic (`get_conversation_key`: `trim-coil-1234-greetings` → `trim-coil-1234`); a name the user chose is its own key. Everything that hangs off a conversation uses the key, never the display name:

- delegated transcripts are named with the key as their parent (`format_delegated_session_name`);
- live sub-agent sessions are registered under `get_session_ownership_key(name)`, which maps the display name to its key outside web chat;
- `/load` matches transcripts whose parent is the loaded name's key.

A rename therefore moves **one file**, the conversation's own history, and nothing else.

**Naming.** After the first user turn of a conversation whose name is still the generated default (`is_random_name`), the small model is asked for a two-to-four-word slug of that message and the conversation becomes `{generated}-{slug}`.

- A name the user gave (`--conversation`, `/save`, `/load`) is never renamed, nor is one that already carries a topic.
- The call runs in the background, never delays a turn, and on any failure leaves the generated name. One task runs per conversation, so switching conversations while naming is pending does not drop the new conversation's naming.
- The rename waits for a running turn to end, since that turn would otherwise save under the old name, and is dropped if the conversation was switched or renamed meanwhile. It never overwrites an existing history. After a failed attempt the next turn's message is the source; the first message is only guaranteed when naming succeeds first time.
- The model is `LLM_AUTO_NAME_MODEL`, falling back to the small model. `LLM_AUTO_NAME_ENABLED` (default on) is the master switch (ADR-0026).
- `LLM_HISTORY_RETENTION` prunes by the generated prefix (`has_random_name_prefix`), so a renamed conversation expires like any generated-name one; a user-chosen name is kept. The shape is the only signal: a name a user types that begins with a generated name (`bold-arch-1234-notes`) is also pruned. A marker file or manifest would tell them apart, at the price of a second source of truth beside the history files; the collision is not worth that.

**Sub-agent titles.** A delegated run gets a short title from the same helper, applied to its delegated task, shown in the live-session picker (which repaints when it arrives). The title is not in the transcript's file name, because `{parent}-sub-{agent}-{id}` is parsed by `parse_delegated_session` and the persona swap resolves the agent from it. It lives on `LiveSubAgentSession.title`. A session restored from disk has no title and shows its agent name.

**Restore on load.** `/load <name>` lists the saved transcripts whose parent is the key of `<name>` and re-registers each as an **idle** `LiveSubAgentSession` with its history. Restoration is all-or-nothing: transcripts are collected first and registered only when every one has loaded, one transcript is restored once however many files carry its name, and a transcript that loads empty (missing or unreadable) is skipped rather than restored as a blank conversation. Agents are resolved through the default `sub_agent_manager`, as the persona swap on `/load` already does (ADR-0083); a transcript whose agent only a custom `SubAgentManager` defines is skipped. Turns sent to a restored sub-agent are saved back to its transcript, as a delegation's own continuation is (`LiveSubAgentSession.persist_history`), so they survive the next load. Restored entries carry no `authority` snapshot, so a continuation runs under the permissions in force when it starts, not ones granted in an earlier process.

**Consequences.**

- Conversation lists become readable at the cost of one small-model call per new conversation and one per delegation.
- A rename can fail only on its own file, and then changes nothing.
- Sub-agent transcripts stay under the generated key after a rename; they are listed under the key, not the display name.
- A restored sub-agent can be messaged (ADR-0108) and continues from its saved history, with no title and no remembered permissions. Replaying an old grant would let a stale approval outlive the session that gave it.
- The cap in ADR-0083 (`LLM_SUBAGENT_HISTORY_RETAIN`) bounds what `/load` can restore.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Rename moves the history and every sub-agent transcript, and re-keys live sessions | Multi-file moves need rollback, and rollback can fail; re-keying needs a conflict check. A stable key removes all of it. |
| Replace the random name with the slug | Two conversations with the same opening ("hi") collide. |
| Name from the first words of the message | Reads as noise for "can you look at this?". |
| Slug in the sub-agent transcript name | Breaks `parse_delegated_session`'s grammar and the persona swap (ADR-0083). |
| A manifest of a conversation's sub-agents | The transcripts already are the manifest; a second source of truth can disagree with the files. |
| Restore the permission snapshot | A stale approval would outlive the session that granted it. |
| Title restored sessions with another model call | One call per restored sub-agent on every `/load`, for a cosmetic label. |
| Block the first turn on naming | Adds a model round trip to every new conversation. |
