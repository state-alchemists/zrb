# ADR-0109 — A default-named conversation is renamed from its first message, and loading a conversation restores its sub-agent sessions

**Status:** Accepted

**Context.** A conversation that the user did not name gets `get_random_name()` — `trim-coil-1234` — which says nothing about what it holds, so `/load` and the session list are a wall of random names. Claude Code names a conversation after its first message.

Sub-agents raise two further questions. Their transcripts are already persisted as `{parent_session}-sub-{agent_name}-{agent_id}` (ADR-0083), so renaming a parent would orphan them: the parent segment is how a transcript is tied to its conversation. And loading a conversation restores the main history but not the in-memory `LiveSubAgentSession` entries, so a sub-agent the user could message before saving is gone after `/load`.

**Decision.**

**Naming.** After the first user turn of a conversation whose name is still the generated default, a small model is asked for a two-to-four-word slug of the first message, and the conversation becomes `{random}-{slug}` (`trim-coil-1234-greetings`). Keeping the random prefix keeps the name unique.

- "Still the default" is `is_random_name` — the shape `get_random_name()` produces (retention uses the prefix form of the same check). A name the user gave (`--conversation`, `/save`, `/load`) is never renamed, nor is one that already carries a slug. If a turn is still running when the slug arrives, the rename waits for the next turn.
- The call is fire-and-forget, never delays a turn, and degrades silently to the random name on any error, timeout or empty answer. The slug is sanitised to `[a-z0-9-]` and capped in length.
- The model is `LLM_AUTO_NAME_MODEL`, falling back to the summarizer model. `LLM_AUTO_NAME_ENABLED` (default on) is the master switch (ADR-0026).
- A rename moves the main history file **and every `{old}-sub-*` sub-agent transcript** to the new parent segment, so the link survives. It runs through the history manager's own save path rather than a bare file move.

**Sub-agent titles.** A delegated run gets a short title from the same helper, applied to its delegated prompt, and shown in the live-session picker. The title is **not** put in the transcript's file name: `{parent}-sub-{agent_name}-{agent_id}` is parsed by `parse_delegated_session` and the persona swap resolves `agent_name` from it, so a slug in that grammar would corrupt the lookup. It lives on `LiveSubAgentSession.title`. A session restored from disk falls back to its agent name, because a title is not persisted.

**Restore on load.** `/load <name>` lists the sub-agent transcripts whose parsed parent is `<name>` (no new index — the file names are the index) and re-registers each as an **idle** `LiveSubAgentSession` with its history loaded. A session that was running when it was saved comes back idle; nothing resumes by itself. Restored entries carry no `authority` snapshot, so a continuation runs under the permissions in force at that moment rather than ones captured in an earlier process.

**Consequences.**

- Conversation lists become readable at the cost of one small-model call per new conversation.
- A rename touches several files. `FileHistoryManager.rename` saves first and moves the main file and the `{old}-sub-*` transcripts; it is not atomic across them, and timestamped backups stay under the old name. Live sessions are re-keyed (`LiveSubAgentSessionRegistry.rekey`) so the picker and the message tools keep finding them.
- A renamed conversation keeps its generated name as a prefix, so `LLM_HISTORY_RETENTION` prunes it like any other generated-name conversation (`has_random_name_prefix`). A name the user chose does not match and is kept.
- A restored sub-agent can be messaged (ADR-0108) and continues from its saved history, with a degraded title and no remembered permissions. That is a deliberate narrowing: replaying an old grant would let a stale approval outlive the session that gave it.
- The cost of the cap in ADR-0083 (`LLM_SUBAGENT_HISTORY_RETAIN`) now also bounds what `/load` can restore.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Replace the random name with the slug | Two conversations with the same opening ("hi") collide. |
| Name from the first message with a heuristic (first words) | Reads as noise for "can you look at this?"; the small model is cheap and already available. |
| Rename only while no sub-agent transcript exists | Leaves the common case — a first-turn delegation — unnamed. |
| Slug in the sub-agent transcript name | Breaks `parse_delegated_session`'s grammar and the persona swap (ADR-0083). |
| A manifest file listing a conversation's sub-agents | The transcripts already are the manifest; a second source of truth can disagree with the files. |
| Restore the permission snapshot | A stale approval would outlive the session that granted it. |
| Block the first turn on naming | Adds a model round trip to every new conversation for a cosmetic result. |

**Where it lives.** `src/zrb/llm/util/conversation_naming.py` (slug call and sanitising), `src/zrb/llm/ui/base/conversation_commands.py` (rename, restore on `/load`), `src/zrb/llm/util/subagent_session_naming.py` (listing by parent), `src/zrb/llm/agent/subagent/live_session.py` (`title`, restore), `src/zrb/llm/history_manager/file_history_manager.py` (`rename`), `src/zrb/llm/prompt/markdown/conversation_namer.md`, `src/zrb/llm/ui/default/agent_picker.py` (title), `src/zrb/config/mixins/llm_content.py` (`LLM_AUTO_NAME_ENABLED`, `LLM_AUTO_NAME_MODEL`).
