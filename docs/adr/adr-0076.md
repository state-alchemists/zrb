# ADR-0076 — Voice dictation is an opt-in UI input method with press-to-start, press-again-to-stop

**Status:** Accepted

**Context.** Voice dictation lets a user type precise file paths while voicing
reasoning, without switching contexts. zrb had keyboard-only input.

Two constraints shaped the design. First, a desktop application can read
OS-level key-down and key-up events; **a terminal cannot**. The spacebar emits a
single byte on press, there is no release event, and holding the key produces
kernel key-repeat — so the hold-to-record model is simply unavailable. Second,
zrb-extras already ships a speech-to-text pipeline, but as an **agent-callable
tool**: the model calls it to hear the user. Dictation is a different
integration point — a UI-level input method that replaces typing at the
prompt-toolkit layer.

**Decision.** A `/voice` toggle command plus a push-to-talk keybinding in the
default TUI, gated behind `ZRB_LLM_VOICE_ENABLED` (default false) and active
only when the configured backend is available.

1. **Opt-in.** Voice needs microphone access and audio dependencies; enabling it
   by default would break on systems without them.
2. **Press to start, press again to stop.** The first press of the push-to-talk
   key starts recording; a second deliberate press stops it and exits voice
   mode. OS key-repeat (~67ms on macOS) is filtered by a 300ms debounce so a
   held key cannot self-trigger a stop. There is **no** silence- or
   duration-based auto-stop. `/voice` again also stops any in-flight recording.
   `Ctrl+Space` inserts a literal newline and is not voice-gated, so multi-line
   input still works.
3. **Both the command token and the key are configurable.** The key defaults to
   `space` — the ergonomic thumb key — which does mean you cannot type a literal
   space while voice mode is active; rebind or toggle off.
4. **Transcription inserts at the cursor**, not as a replacement, which is what
   makes hybrid typed-and-spoken input work.
5. **The engine lives in zrb core, not zrb-extras**, because it is a UI input
   method rather than an agent tool. Every heavy import — the audio library,
   numpy, the recognizer, the agent stack for the multimodal backend — is lazy,
   so a disabled voice mode costs nothing at startup.
6. **Vosk is the default backend**, offline with no API key and no per-utterance
   cost. The small model auto-downloads on first use, read in 64 KiB chunks with
   an `await` between them so the download is **cancellable** at the next chunk
   boundary. OpenAI, Google and a multimodal-LLM backend are opt-in
   alternatives.
7. **No model capability gating.** Transcribed text is plain text, so any text
   model can consume it; audio-as-input is a separate feature.
8. **`/voice` runs while thinking**, like the other mode toggles, so it can be
   flipped mid-response.

**Consequences.** Push-to-talk dictation in the chat TUI with no new mandatory
dependencies and no effect on normal typing when voice is off. Because there is
no auto-stop, a recording that is started and forgotten runs until the next
press, holding captured audio in memory until then.

**Alternatives rejected.** *Build it in zrb-extras only* — its listen tools are
agent tools; the prompt-toolkit integration belongs in core. *Always-on voice* —
breaks spacebar typing and demands microphone access every session. *A fixed
non-spacebar key* — spacebar is the ergonomic default; configurability covers
the rest. *Auto-stop on silence, as a desktop app does* — the VAD machinery
exists in zrb-extras but was not ported in v1; press-again is simpler and fully
terminal-safe. *Multimodal as the default backend* — works with any
audio-capable model already configured, but it is slower and costs per
utterance. *Stream audio to a cloud API* — latency, API keys, and it leaks
audio; available opt-in.

**Where it lives.** `src/zrb/llm/voice/engine.py`,
`src/zrb/config/mixins/llm_voice.py`,
`src/zrb/llm/ui/base/commands.py` (the toggle),
`src/zrb/llm/ui/default/keybindings.py` (the debounced handler).
