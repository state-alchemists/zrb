# ADR-0076 — Dictation is push-to-talk by command, plus a hands-free mode that can answer approvals

**Status:** Accepted

**Context.** Dictation lets a user speak where they would type: a request, a path, the answer to a tool approval. zrb had keyboard-only input.

A terminal cannot see key-up events. The spacebar sends one byte on press, nothing on release, and key-repeat while held, so hold-to-talk is impossible. The first design worked around this with a push-to-talk keybinding (press to start, press again to stop), a 300 ms key-repeat debounce, a `🎤 VOICE` status-bar badge, and voice state on `BaseUI`. It worked, but it put a secondary feature into the UI's keybindings, status bar and command table, and it took the spacebar away from typing while voice mode was on.

An example built on the chat task's public extension points (`append_trigger`, `append_custom_command`, `append_hook_factory`) showed the other half: a hands-free listener that cuts the microphone stream into utterances by loudness and silence, with wake words. That needs no keybinding at all. Using it showed that the first thing a hands-free user gets stuck on is a tool approval they cannot answer, because a trigger's text only ever became a new turn.

**Decision.** Dictation is one feature, `enable_dictation` (ADR-0102), with two modes that share one microphone loop and one backend.

1. **Push-to-talk is a command, not a key.** `/voice` starts recording. A pause of `silence` seconds, or `/voice` again, stops it. The transcript is inserted at the cursor (`insert_input_text`), not sent, so it can be edited. The input box stays free while recording, which is what makes typing the stop command possible. `/voice` runs while the model is thinking.
2. **Hands-free keeps the microphone open.** `/handsfree` switches it; `mode=hands_free` starts a session with it on. Each utterance becomes a turn. With wake words, only an utterance starting with one counts, and a wake word said alone accepts the next utterance within `wake_window` seconds, measured from when it was spoken, not when transcription finished. Push-to-talk refuses while hands-free is on, since both would submit the same words.
3. **Hands-free answers the approval or question being asked — the one that was on screen when the user spoke.** The listener yields a `TriggerReply(text, approval, started_at)`, and the trigger loop routes it to `submit_answer` when the UI `is_waiting_for_answer` and the prompt was pending by `started_at` (`pending_answer_since`), else it becomes a turn. Transcription takes seconds, so without that check a "yes" said to nothing would approve a tool call that appeared meanwhile; a UI that cannot date its prompt gets no timed answers. A tool approval gets `approval` (falling back to `text`), a question gets `text` (`is_waiting_for_choice`). Only a `TriggerReply` does this: a plain string from any other trigger (a schedule, a webhook) still only starts a turn, so no remote source can approve a tool call.
4. **A spoken answer cannot approve by accident.** A tool approval reads `y`/`yes` as approve and anything else as a denial with that text as the reason. The listener sends `yes` only for a short answer (at most three extra words) opening with an approve phrase ("Yes.", "yes please"), `no` for a deny phrase said alone, and the transcript unchanged otherwise, so "no, use pytest" reaches the agent as a reason. An empty answer approves, so the trigger loop never sends one. A choice question maps an answer naming an option, by label or number, to that option's label; a multi-select one maps a list of them ("1, 3", "red and blue") when every item names an option, trying the whole answer as one label first.
5. **zrb's own voice is not dictation.** Each audio block is tagged at capture with whether speech is playing (`is_speaking`, ADR-0103), and the microphone ignores blocks while it is, plus `echo_cooldown` after.
6. **Speech length is measured from the first loud block to the last.** The `pre_roll` kept before speech (so the first word is not clipped) and the trailing silence do not count toward `min_speech`, or a single click would pass.
7. **Backends are pluggable.** `backend` is a name (`vosk`, `openai`, `google`, `multimodal`) or an `AnyDictationBackend`. vosk is the default: offline, no key, no per-utterance cost; its model downloads on first use in 64 KiB chunks with an `await` between them, so the download is cancellable. Every heavy import (sounddevice, numpy, vosk, the agent stack for `multimodal`) happens on first use; a missing one is reported with the install command.

**Consequences.** The UI has no dictation code: no keybinding, no badge, no voice state, and the spacebar always types. Hands-free works for a whole session without touching the keyboard, including approvals. Push-to-talk ends at the first pause longer than `silence`, so a user who stops to think mid-sentence sends half a sentence into the input box, where it can be finished by typing or another `/voice`. In hands-free without wake words, anything the microphone hears becomes a turn.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Keep the push-to-talk keybinding and badge | They need a keybinding and a status-bar extension point in the UI for one feature, and they took the spacebar from typing. |
| Push-to-talk that stops only on the second command | A forgotten recording runs and buffers audio until noticed. The pause stop costs nothing when the command stop is also there. |
| Route every trigger item to a pending approval | A scheduled or remote trigger could approve a tool call. The reply has to be marked as the user's. |
| Pass the raw transcript to an approval | "Yes." and "yes please" are not `yes`, so a spoken approval would never approve. |
| Separate listener and push-to-talk features | Two configs owning the same backend, microphone settings and wake words, and nothing stopping both from submitting the same words. |
| Dictation as an agent tool, like zrb-extras' former `listen` | The model decides when to listen, but dictation is the user choosing to speak. zrb-extras dropped `listen` once dictation was built in. |

**Where it lives.** `src/zrb/llm/dictation/feature.py` (`enable_dictation`, `DictationSession`), `src/zrb/llm/dictation/listen.py` (`UtteranceCutter`, `listen`, `record`), `src/zrb/llm/dictation/words.py` (wake words, `to_answer`), `src/zrb/llm/dictation/backend/`, `src/zrb/config/mixins/llm_dictation.py`, `src/zrb/llm/ui/trigger.py` (`TriggerReply`), `src/zrb/llm/ui/base/triggers.py`, `src/zrb/llm/ui/default/confirmation.py` (`submit_user_answer`).
