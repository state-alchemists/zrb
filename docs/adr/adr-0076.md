# ADR-0076 — Dictation is push-to-talk by command, plus a hands-free mode that answers approvals and can be talked over

**Status:** Accepted

**Context.** Dictation lets a user speak where they would type: a request, a path, the answer to a tool approval. zrb had keyboard-only input.

A terminal cannot see key-up events. The spacebar sends one byte on press, nothing on release, and key-repeat while held, so hold-to-talk is impossible. The first design worked around this with a push-to-talk keybinding (press to start, press again to stop), a 300 ms key-repeat debounce, a `🎤 VOICE` status-bar badge, and voice state on `BaseUI`. It worked, but it put a secondary feature into the UI's keybindings, status bar and command table, and it took the spacebar away from typing while voice mode was on.

An example built on the chat task's public extension points (`append_trigger`, `append_custom_command`, `append_hook_factory`) showed the other half: a hands-free listener that cuts the microphone stream into utterances by loudness and silence, with wake words. That needs no keybinding at all. Using it showed that the first thing a hands-free user gets stuck on is a tool approval they cannot answer, because a trigger's text only ever became a new turn.

Using hands-free as a conversation showed two more gaps. Every utterance waited a full second of silence, then its whole transcription, before anything happened. And the microphone was deaf while zrb spoke, so a reply going the wrong way could only be stopped by keyboard.

**Decision.** Dictation is one feature, `enable_dictation` (ADR-0102), with modes that share one microphone loop and one backend.

1. **Push-to-talk is a command, not a key.** `/voice` starts recording. A pause of `silence` seconds, or `/voice` again, stops it. The transcript is inserted at the cursor (`insert_input_text`), not sent, so it can be edited. The input box stays free while recording, which is what makes typing the stop command possible. `/voice` runs while the model is thinking.
2. **Hands-free keeps the microphone open.** `/handsfree` switches it; `mode=hands_free` starts a session with it on. Each utterance becomes a turn. With wake words, only an utterance starting with one counts, and a wake word said alone accepts the next utterance within `wake_window` seconds, measured from when it was spoken, not when transcription finished. Push-to-talk refuses while hands-free is on, since both would submit the same words.
3. **Hands-free answers the approval or question being asked — the one that was on screen when the user spoke.** The listener yields a `TriggerReply(text, approval, started_at)`, and the trigger loop routes it to `submit_answer` when the UI `is_waiting_for_answer` and the prompt was pending by `started_at` (`pending_answer_since`), else it becomes a turn. Transcription takes seconds, so without that check a "yes" said to nothing would approve a tool call that appeared meanwhile; a UI that cannot date its prompt gets no timed answers. A tool approval gets `approval` (falling back to `text`), a question gets `text` (`is_waiting_for_choice`). Only a `TriggerReply` does this: a plain string from any other trigger (a schedule, a webhook) still only starts a turn, so no remote source can approve a tool call.
4. **A spoken answer cannot approve by accident.** A tool approval reads `y`/`yes` as approve and anything else as a denial with that text as the reason. The listener sends `yes` only for a short answer (at most three extra words) opening with an approve phrase ("Yes.", "yes please"), `no` for a deny phrase said alone, and the transcript unchanged otherwise, so "no, use pytest" reaches the agent as a reason. An empty answer approves, so the trigger loop never sends one. A choice question maps an answer naming an option, by label or number, to that option's label; a multi-select one maps a list of them ("1, 3", "red and blue") when every item names an option, trying the whole answer as one label first.
5. **zrb's own voice is not dictation — unless barge-in is on, and then it is guarded against.** Each audio block is tagged at capture with whether speech is playing (`is_speaking`, ADR-0103). With `barge_in_enabled` off (the default) the microphone ignores those blocks, plus `echo_cooldown` after. With it on, those blocks are heard against a bar over zrb's voice, and a transcript of them has to pass the transcript guards before it reaches the model (ADR-0105). Without wake words, a partial transcript never stops zrb (a streaming recognizer guesses a word for a cough); the final transcript settles it, zrb paused meanwhile. An utterance with `barge_in_min_speech` of speech over zrb's voice is a barge-in and is marked `is_barge_in`; any utterance with some speech over zrb's voice is marked `is_over_speech`, since a crisp "stop" (about two 0.1 s blocks) is shorter than that, and its words stop zrb once transcribed.
6. **A barge-in pauses zrb, then stops or resumes it.** zrb's voice is paused the moment the barge-in is heard (`pause_speech`), before transcription. Words — in the streaming transcript while the user still speaks, or in the final one, starting with a wake word when wake words are set — stop it (`interrupt_speech`); an utterance with no words, without the wake word, or too short to keep (`on_barge_in_dropped`) resumes it (`resume_speech`), so a cough or leftover echo costs a moment's pause, not the reply.
7. **What a barge-in said goes where the user meant it.** An answer to a pending prompt stays an answer ("no" there denies a tool call). A stop phrase said alone (`stop_words`, a list of its own so "no" can deny an approval without stopping anything; "stop", "cancel", "no" by default), over zrb's voice or, with barge-in on, while a turn runs before zrb speaks, cancels the running turn through `AnyUI.cancel_current_turn("barge_in")` — the same call Esc makes — and is sent nowhere. Anything else steers the running turn (`barge_in_action=steer`, ADR-0078), or with `barge_in_action=cancel` cancels it, waits for it to unwind, and starts a new turn.
8. **Speech length is measured from the first loud block to the last.** The `pre_roll` kept before speech (so the first word is not clipped) and the trailing silence do not count toward `min_speech`, or a single click would pass.
9. **A backend that can stream transcribes while the user speaks.** `AnyDictationBackend.create_stream()` returns an `AnyTranscriptionStream` or `None` (the default, batch only); vosk streams. Hands-free feeds each utterance to its stream a block at a time, shows the partial transcript in the status bar, and finishes it when the utterance ends, so the transcript is nearly ready. With a stream, an utterance ends after `min_silence` quiet seconds once its words sound finished (`is_finished_phrase`: not trailing off on "and", "the", "um"), instead of the full `silence`.
10. **Backends are pluggable.** `backend` is a name (`vosk`, `openai`, `google`, `multimodal`) or an `AnyDictationBackend`. vosk is the default: offline, no key, no per-utterance cost; its model downloads on first use in 64 KiB chunks with an `await` between them, so the download is cancellable. Every heavy import (sounddevice, numpy, vosk, the agent stack for `multimodal`) happens on first use; a missing one is reported with the install command.

**Consequences.** The UI has no dictation code: no keybinding, no voice state, and the spacebar always types; its only contribution is the status badge every feature may set, and `cancel_current_turn`, which Esc uses too. Hands-free works for a whole session without touching the keyboard, including approvals, and with headphones a reply can be stopped or redirected by talking over it. Push-to-talk ends at the first pause longer than `silence`, so a user who stops to think mid-sentence sends half a sentence into the input box, where it can be finished by typing or another `/voice`. In hands-free without wake words, anything the microphone hears becomes a turn. Barge-in works on speakers once the canceller has learned the room, a few seconds into zrb's first reply of a session; before that, and with speech a player program plays, the microphone is deaf while zrb speaks, as with barge-in off.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Keep the push-to-talk keybinding and badge | They need a keybinding and a status-bar extension point in the UI for one feature, and they took the spacebar from typing. |
| Push-to-talk that stops only on the second command | A forgotten recording runs and buffers audio until noticed. The pause stop costs nothing when the command stop is also there. |
| Route every trigger item to a pending approval | A scheduled or remote trigger could approve a tool call. The reply has to be marked as the user's. |
| Pass the raw transcript to an approval | "Yes." and "yes please" are not `yes`, so a spoken approval would never approve. |
| Separate listener and push-to-talk features | Two configs owning the same backend, microphone settings and wake words, and nothing stopping both from submitting the same words. |
| Dictation as an agent tool, like zrb-extras' former `listen` | The model decides when to listen, but dictation is the user choosing to speak. zrb-extras dropped `listen` once dictation was built in. |
| Stop speech only after the barge-in is transcribed | Transcription takes up to seconds; the user talking over zrb wants it quiet now. |
| Barge-in on by default | It needs a few seconds of zrb speaking before the canceller is ready, and a microphone that picks up the room turns every conversation nearby into pauses. |
| Stop zrb at the first sound over it | A cough, a door or leftover echo would cut a reply off for good; a pause costs a moment and is undone. |
| A `headset` barge-in mode trusting the microphone | On laptop speakers it made zrb hear itself and answer its own words; trusting the microphone is now the `none` canceller, chosen on purpose. |
| Cancel the turn on every barge-in | "Also update the docs" said over a reply is a correction, not a stop; steering keeps the work already done. |
| A `/live` mode switching hands-free, streamed speech and its own barge-in together | Hands-free plus speech already is a voice conversation once speech streams by default (ADR-0103); a third mode meaning "those two, configured right" said the defaults were wrong, and doubled the barge-in setting. |
| A shorter `silence` for everyone | Batch backends cannot tell a finished sentence from a pause to think, so a shorter wait cuts people off; only a streaming transcript can. |

**Where it lives.** `src/zrb/llm/dictation/feature.py` (`enable_dictation`, `DictationSession`), `src/zrb/llm/dictation/listen.py` (`UtteranceCutter`, `listen`, `record`), `src/zrb/llm/dictation/words.py` (wake words, `to_answer`, `is_said_alone`, `is_finished_phrase`, `is_transcriber_guess`, `is_said_back`, reading `polite_words` and `trailing_words` from config), `src/zrb/llm/dictation/backend/` (`AnyTranscriptionStream`, `VoskTranscriptionStream`), `src/zrb/config/mixins/llm_dictation.py`, `src/zrb/llm/ui/trigger.py` (`TriggerReply`), `src/zrb/llm/ui/base/triggers.py`, `src/zrb/llm/ui/base/ui.py` (`cancel_current_turn`), `src/zrb/llm/ui/default/confirmation.py` (`submit_user_answer`).
