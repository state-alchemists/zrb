# ADR-0142 — A usage line names the call that spent it

- **Status:** Accepted
- **Date:** November 14, 2026

## Context

ADR-0127 made the log a faithful copy of what pydantic-ai reports. It was faithful about *numbers* and silent about *authors*: a compaction wrote a line of its own, and every other call zrb makes — the shell judge (ADR-0141), the memory reviewer, the self-review gate, the week note, the conversation namer, the barge-in judge, speech summaries, the `please` and changelog tasks — wrote nothing at all, because the only writer was the turn runner (`agent/run/runner.py::_record_run_usage`).

The tokens were not lost; they were misfiled. `/usage` read a conversation as doing its own work while three or four small models spent beside it, and a session with 172 records at ~4.7k input each reads as one long turn rather than as the harness talking to itself. That is board 0003 §7's item 8, and the same gap ADR-0141 recorded as a consequence of building the judge first.

## Decision

**One field, `component`, and a short vocabulary.** `main_agent`, `summarizer`, `hook_agent`, `auto_namer`, `shell_judge`, `subagent`, `other`. `kind` keeps answering *when* the work happened; `component` answers *who* spent it, and a compaction carries both. A name is earned by a reader acting differently on seeing it in `/usage`, not by being a distinct module — which is why the memory reviewer, the self-review gate and the week note share `hook_agent`: they are all one AGENT-type hook, run by `hook/execution/creator.py`, and splitting them would describe the hook's name rather than its cost.

**The tag travels, rather than being repeated.** A sub-agent's rounds go through the same runner loop as the conversation's, so no call site sees them: `usage_component(...)` sets an ambient `ContextVar` around the run and every line written underneath inherits it. The auxiliary calls that build their own agent call `record_agent_usage(result, component=...)` once, after the run; the model name is read from the result's response rather than guessed at the call site.

**A line belongs to the conversation it ran inside.** An auxiliary call is never handed the conversation's name either, and the first cut of this shipped with that hole: a judge acting on a session's command wrote a headless line, so its tokens showed up in `today` and `week` and were missing from `/usage session` — the window the new section is read in. `record_totals` now falls back to the session's own UI, the one bound for the whole conversation, so a call that cannot see the conversation still files into it. `session_key` strips the slug a rename appends, so a name read before a rename still names the same conversation. A run with no conversation behind it — `please`, `changelog` — keeps an empty session rather than inventing one.

**Old lines read back by their kind, and need no migration.** Only two modules wrote a line before this field existed, so a `summarization` line was the summarizer's and everything else was the turn runner's. A component this version does not know keeps its own name for the same reason an unknown `kind` stays in the turn totals: tokens the user paid for are worse lost than filed one row too wide.

**A test walks the tree instead of a reviewer remembering.** `test/architecture/test_every_model_run_is_attributed.py` finds every module that runs a model and fails on one that neither records nor is named in a debt register — the shape `test/builtin/test_registration_completeness.py` already uses for tasks. The register refuses to keep an entry that has since been fixed, so it cannot rot into a list nobody reads.

## Consequences

- **The judge, the reviewer and the namer are visible.** ADR-0141's open consequence is closed: a judge call writes its own line, under `shell_judge`, in the conversation whose command it judged.
- **Six sites are recorded but still misfiled.** A tool that calls `run_agent` — file analysis, web fetch, code analysis, multimodal describe, dictation's multimodal backend, `LLMTask` — reaches the engine without saying it is the tool's own work, so its line says `main_agent`. Naming them needs a component threaded through the tool path; they are in the debt register until then.
- **No per-request row, so a miss is still not attributable to a round.** Attribution answers "who", not "which request"; board 0003 §7 item 10 stays open.
- **No cost tree.** A hook's spend is added to the session it fired for, not linked to the turn that triggered it; `run_id` and `parent_run_id` are deferred to the per-request work, where they would earn their keep.
- **`/usage` gains a section only when there is something to say.** A window spent by one component — including every window from before this change — draws no breakdown.
- **A turn's numbers did not change.** The lines are the same lines, filed under a name.

## Alternatives

- **Record the component on the agent `create_agent` returns, by wrapping its `run`.** Rejected: it changes the object every caller holds (streaming, iteration, toolset access, `RunResult` type), to add a label — a wide blast radius for one field.
- **Only a call-site parameter, with no ambient tag.** Rejected: a sub-agent's rounds never pass through a call site the parameter could reach.
- **One log file per component.** Rejected: the questions `/usage` answers are windows over time (a day, a week, a session), and splitting the store by author would make every one of them a join across files.
- **A boolean `is_auxiliary`.** Rejected: after M0 the next question is *which* auxiliary call, and the shell judge's spend and the memory reviewer's are the two numbers worth separating.
