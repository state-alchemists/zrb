# ADR-0054 — The built-in plugin is split into core-skills, skills and agents, with toggles on the optional two

**Status:** Accepted

**Context.** The built-in plugin shipped every skill in one flat directory alongside the agents. Some of those are the agent's methodology baseline that the remaining utility skills delegate into; the rest are optional conveniences. The loader treated them identically, so a deployment could not slim the built-in surface without forking, and nothing structurally distinguished the load-bearing core from the extras.

**Decision.** Split the built-in plugin into three physically separate categories and govern the optional two.

- **`core_skills/`** — the `core-*` methodology skills. **Always loaded, no toggle**: disabling them would silently break the utility skills that delegate into them.
- **`skills/`** — the utility skills, gated by `CFG.LLM_ENABLE_BUILTIN_SKILLS` (default on).
- **`agents/`** — the built-in sub-agents, gated by `CFG.LLM_ENABLE_BUILTIN_AGENTS` (default on).

The toggles suppress **only built-in content**. The search order (ADR-0052) is unchanged; the toggles only decide which built-in directories are appended, so user, project and plugin skills and agents always load. A user or project skill that shadows a built-in by name survives regardless.

**Consequences.** A deployment can trim the built-in surface without losing its own content, and the directory split makes "always-on baseline" versus "optional extra" structurally obvious. Core skills are deliberately non-disableable, so there is no toggle to misuse. The toggle is read when the skill catalogue is first scanned, so flipping it mid-process will not retroactively rescan.

**Alternatives rejected.** *A third toggle for core skills* — the utility skills hard-depend on them; a switch to break that dependency is a footgun with no use case. *One master switch over all discovery* — disabling "skills" would also drop the user's own, conflating "trim the built-ins" with "turn the feature off". *A single comma-list (`LLM_BUILTIN_CATEGORIES=skills,agents`)* — less discoverable and inconsistent with the existing boolean search toggles. *Keep one flat directory and tag skills by metadata* — a physical split is self-documenting and lets the loader gate by directory rather than inspecting every skill.

**Where it lives.** `src/zrb/llm_plugin/{core_skills,skills,agents}/`, `src/zrb/llm/skill/manager.py`, `src/zrb/llm/agent/subagent/manager_search.py`, `src/zrb/config/mixins/llm_search.py`.
