# ADR-0095 — The second profile is named `mini`, not `explicit`

**Status:** Accepted (renames the profile introduced by ADR-0083)

**Context.** ADR-0083 named the non-base profile `explicit`, describing it as "a
more directive register for weaker models" — the name described a *writing
style*. ADR-0091 then removed that style: measured, the directive re-phrasings
were +638 tokens with 82% byte-identical lines and more of the prohibition
phrasing that decays over context, so the variant was narrowed to worked
demonstrations only, and `persona.explicit.md` was deleted. ADR-0093 made the
profile reachable by default for models that declare a small size.

After both changes the name is wrong in the way that matters: nothing about the
profile is more explicit than the base. It carries the same rules, in the same
words, plus examples. A contributor reading `explicit` reasonably infers there is
a licence to re-phrase rules more forcefully — the exact thing ADR-0091 forbids,
and the exact mistake the original variant made.

**Decision.** Rename the profile to `mini`. It names the model class the profile
exists for — the size tier ADR-0093 detects — rather than a register it no longer
uses. `MINI_PROFILE = "mini"`; `examples.explicit.md` becomes `examples.mini.md`.

**No alias.** `explicit` is not accepted as an input value. ADR-0073's
preserve-the-old-key rule covers released env *keys*, where a stale config
silently loses a setting; this is a knob *value* whose only consumers are a
`ZRB_LLM_PROFILE` line and a `register_model_profile(...)` call, both of which
fail loudly rather than silently: an unrecognized `ZRB_LLM_PROFILE` falls
through to `auto` (which now picks the right profile from the model id anyway,
per ADR-0093), and `register_model_profile(..., "explicit")` raises
`ValueError: Unknown profile`. Carrying an alias for a value nothing silently
depends on is cost without a failure to prevent.

**Consequences.** The name now states the target rather than a style, which
makes the ADR-0091 invariant self-enforcing at the point of authorship: "the
`mini` variant adds a rule" reads as obviously wrong in a way "the `explicit`
variant adds a rule" did not. A pinned `ZRB_LLM_PROFILE=explicit` stops forcing
the profile and falls back to `auto`; on a small model `auto` selects `mini`
regardless, so the observable change is limited to forcing the variant onto a
*large* model. A test pins both failure modes.

**Alternatives considered.** *Ship an alias* — no silent-loss failure to prevent (see above), and it would keep the discarded name discoverable in docs and autocomplete. *Keep `explicit`* — leaves a name that actively
argues for the behaviour ADR-0091 banned. *`weak` / `small`* — describes the
model pejoratively and reads as a judgement rather than a tier; vendors already
ship the word `mini`. *`examples`* — describes the current payload, but the
profile is a target audience, not a file list, and naming it after today's
content would misname it the moment a second variant file appears.

**Evidence.** `prompt/profile.py::MINI_PROFILE`, `VALID_PROFILES`;
`prompt/markdown/examples.mini.md`.
