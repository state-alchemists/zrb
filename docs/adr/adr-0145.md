# ADR-0145 — A reply that forgot its spoken block is repaired at the ear, and the record is left alone

- **Status:** Accepted
- **Date:** November 22, 2026

## Context

Speech reads a reply's `<spoken>` block aloud and leaves the rest for the eye ([ADR-0103](adr-0103.md), item 5). The block is the model's to write, and the prompt asks for it — but a prompt is not an enforcement point, and a reply with no block arrives often enough to have been reported more than once in a single session. What the listener gets then is ADR-0103's older path: the reply is cleaned of code, tables and markup and read whole, so the answer they needed in one breath arrives as the body of a reply written to be read, with its table stripped into a line of loose cells.

**The obvious fix was measured, and it costs streaming.** Requiring the block in an output type — a `spoken` field the model must fill — makes the miss impossible. It also makes every reply arrive at once: with a structured output type, pydantic-ai collects the answer as a `final_result` tool call, so the provider streams nothing a listener can hear until the turn is nearly over. In the measurement, one partial arrived at 4.30s of a 4.39s turn. ADR-0103 item 4's sentence-at-a-time speech dies, for a problem that shows up in a minority of replies.

**The other obvious fix is a lie.** Once a repaired line has been spoken, storing it in the assistant message as though the model had written it makes the transcript agree with the ear — one mechanism instead of two, and no notice needed, because the model would already "know" it wrote a block. The cost is what the transcript is for: it says what the model produced, and this would say it produced another model's sentence, in the turn where nothing of the kind was streamed.

## Decision

**The reply stays prose, and the miss is repaired at Stop.** Nothing in the output type forces a block, so streaming is untouched. When speech is on and the finished reply opened no `<spoken>` block, one small-model call reads the reply and writes the line the ear should have had (`repair_for_speech`), under its own switch, `LLM_SPEECH_REPAIR_ENABLED`, on by default.

**The repair answers in a shape, not in prose.** `RepairedSpeech` carries one `spoken` field and an `emotion`: a field the model must fill, not a line zrb parses out of an answer that may or may not contain it. An answer of the wrong type, a line that strips to nothing, and a line longer than the ear can hold are each a `SpeechRepairError` — a model that hands the reply back is not a repair, and speaking it would put the table on the ear by another road.

**A failed repair is the old behaviour, never silence.** Every failure — the shape, the emptiness, a provider that raises, the wait exceeding `summary_timeout` — ends with the reply read whole, exactly as before this record. A repair whose reply has been overtaken by a newer one is discarded rather than spoken.

**The record is not touched.** The repair produces audio and nothing else. The assistant message keeps what the model wrote, without a block, and the next turn still opens with `_MISSED_BLOCK_NOTICE` because `_missed_block` is still set from the reply. The two mechanisms are separate switches on purpose: `LLM_SPEECH_BLOCK_NOTICE_ENABLED` is what the next *request* is told, `LLM_SPEECH_REPAIR_ENABLED` is what this *turn* is heard as, and neither can hide behind the other. A block inserted into history would be drawn by the screen too, since the settled copy is rendered through `shown_text`, which quotes blocks — the transcript would show a quoted block that was never streamed.

**The repair pays for itself in `/usage`.** It records under `COMPONENT_SPEECH_REPAIR` and `REASON_SPEECH_REPAIR` ([ADR-0142](adr-0142.md), [ADR-0143](adr-0143.md)), so how often the net catches something is a number rather than an impression, and the teaching the notice does can be judged instead of assumed.

## Consequences

A blockless reply is heard as a line rather than read as a body, and streaming survives, because nothing was added to the output type. The cost is one small-model call on a miss, bounded by the summarizer's timeout, and a line the listener hears that no model in the turn wrote — which is exactly why the record must not be edited to match it. The repair is a net under the wire and not a licence to drop the block: it fixes the ear, and leaves the miss visible in the transcript and the notice in the next request.

Two switches where a reader might expect one is the price of keeping the record honest. The simplification exists and is named below; it can be taken later, from a measurement rather than a preference.

## Alternatives rejected

- **Require `spoken` in the output type.** Measured: the whole reply arrives as one `final_result` call, so streaming speech dies (one partial at 4.30s of a 4.39s turn). The fix would have to be paid for by every reply, to cover the minority that miss.
- **Rewrite the assistant message in history once the line is spoken.** The transcript would credit the main model with the small model's sentence; the screen would draw a quoted block that never streamed, because the settled copy goes through `shown_text`; and with nothing left to notice, the model would never learn the block was missing, so the repair would become the only mechanism instead of a fallback.
- **Rewrite history and keep the notice, so the model sees a block and is told it forgot one.** The record and the request would then contradict each other, and both would be wrong about the same turn.
- **Repair silently: no notice, honest history.** This is the honest version of "one mechanism instead of two" and it is the right simplification if two switches ever cost more than they teach. It is not taken now because making the model write its own block is the point, and the `/usage` row is what will settle whether it is learning.
- **Leave it as it was: read the blockless reply whole.** Correct, but it makes every miss permanent, and a listener away from the screen hears the body of a reply written for the eye.
- **Have the summarizer write the line when it is already reading the reply.** Summarizing is for a long reply that has a block; the miss is a different question, and one small call answering one question is easier to bound, test and switch off.
