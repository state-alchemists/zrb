# ADR-0046 — Every section reads whole on its own, and one Priority Order ranks everything

**Status:** Accepted

**Context.** Sections are independently switchable (ADR-0044), so every
sentence in section A that refers to section B is only correct in compositions
that include B. A config that dropped the journal section still received
`workflow` telling the model to "search the journal" — instructions about a
subsystem the prompt never described.

The first mitigation was prose hedging: "see *Skill Activation*, where
present", "only if a *Journal Protocol* section appears in this prompt". That
pays tokens in every configuration and delegates to the model a fact the
composer already knows.

Cross-references are also self-reinforcing: each one is individually cheaper to
write than restating the rule, and a pointer *looks* like less duplication — so
the composed prompt appears tidier as it becomes less switchable. Unguarded
references had accumulated (a section heading described as a "supplement to"
another; tool guidance deferring to "the Working Loop's escalation triggers"),
and the ones living in Python-assembled content could not be guarded at all.

The same pressure produced a worse failure around precedence, the one concern
that inherently spans sections. A draft shipped an "Across sources" chain that
placed `AGENTS.md` *below* the entire Priority Order while the Priority Order
placed it *inside* the ladder — a model resolving one against the other has no
fixed point. Two more partial rankings existed elsewhere.

**Decision.** Two rules, one enforcing the other.

1. **A section may not name another section, its heading, or a term another
   section defines.** When two switchable sections both need a rule, state it in
   both, phrased for each context. Where a reference is genuinely worth keeping,
   mark it:

       <!--requires:project_context-->
       Read the paths listed there before you search or edit.
       <!--/requires-->

   `prompt/section_filter.py::filter_requires` resolves the markers and
   `PromptManager` applies it to every file-backed section. Comma-separated
   dependencies must **all** be present. Markers are stripped whether or not the
   block survives, so nothing leaks to the model. Two forms are supported: a
   marker alone on its line removes the whole line, while a marker mid-sentence
   removes only itself. The set filtered against is what the prompt **actually
   emits**, not the configured list.

2. **`workflow` opens with one Priority Order that ranks everything.** Its
   preamble states that nothing outside the list outranks anything in it, which
   is what makes rule 1 affordable: no other section needs to describe its own
   standing, so no other section needs to name the ranking to do it. The rank
   count has changed as the prompt compacted and was never the decision — one
   ladder that ranks everything is.

**Enforcement.** `test_section_composition.py` brute-forces every subset of the
file-backed sections against an `OWNED_VOCABULARY` map, asserting that no
section's vocabulary survives without its owner and that no marker reaches the
model. **Adding a section-defining term means adding it to that map; renaming
one means renaming it there too** — the subset walk asserts a negative, so a
term the prompt no longer contains keeps passing while guarding nothing.
`test_every_owned_term_still_exists_in_its_owner` fails on that, and the test
only catches vocabulary it knows about either way. An unterminated block is
logged and kept rather than swallowing the rest of the section: a prompt with
one stale sentence is a smaller failure than a truncated one.

**Consequences.** The hedges are gone; a reference is either true or absent, and
any subset composes correctly by construction — verified rather than assumed.
The brute-force test caught two real leaks during the rewrite. Self-containment
costs characters: removing a pointer means restating the rule, so the structure
consolidates while the text grows, and every future section pair that shares a
concern pays that again. This **constrains but does not overturn** the MECE rule
(ADR-0044): MECE governs where a rule is *authored*, self-containment governs
what a *composition* may assume. Where they collide, duplicate — consistently.
The bug being prevented is not duplication but **divergent** duplication.
Precedence questions now have exactly one place to be answered, which is also
the one place to change.

**Alternatives rejected.** *Self-contained sections with no machinery at all* —
composes correctly by construction, but duplicates rules across sections in
every case rather than only where genuinely needed. *Keep the "where present"
hedges* — no code, but pays tokens in every config and still asks the model to
reason about absence. *Guard every reference with `<!--requires:-->` instead of
ever restating* — leaves the reader of a trimmed prompt with a rule silently
deleted rather than restated; the rule still applies, it just stopped being
stated. *Compose-time string rewriting without markers* — unpredictable, and it
would mangle prose that legitimately uses the word. *Declare a fixed section set
and drop `LLM_INCLUDE_SECTIONS`* — makes cross-references safe by removing the
configurability that is the point of ADR-0044. *Keep both precedence statements
and add a rule for reconciling them* — a third ranking to arbitrate two
rankings; the failure mode compounds rather than resolving.

**Where it lives.** `src/zrb/llm/prompt/section_filter.py`,
`src/zrb/llm/prompt/manager.py`,
`src/zrb/llm/prompt/markdown/workflow.md` (`## Priority Order`),
`test/llm/prompt/test_section_composition.py`.
