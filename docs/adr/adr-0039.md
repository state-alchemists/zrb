# ADR-0039 — Stream errors are classified, and each class gets its own one-shot fix

**Status:** Accepted

**Context.** Providers reject valid requests inconsistently: context-length
errors, malformed tool calls, missing `reasoning_content`, opaque Bedrock 400s.
A single retry strategy fails on most of them, and retrying an unchanged
request just reproduces the error.

**Decision.** Classify the stream error and apply an escalating, mostly
one-shot tactic. Transient (429, 5xx) gets bounded exponential backoff.
Prompt-too-long drops the oldest turn, bounded, keeping a minimum. An invalid
tool call gets one corrective system message. Missing reasoning strips thinking
parts. An opaque 400 collapses history to text-only. Every fix is surgical —
never "ask the model to fix it".

**Consequences.** The loop survives the quirks of the providers zrb supports,
cannot spin (each strategy fires once), and degrades to a text-only last resort
that every provider accepts. The cost is a classifier and a retry matrix that
must be maintained as providers change.

**Alternatives rejected.** *One fixed retry policy* — the same error repeats
until the budget is gone. *Regenerate the whole response* — costly and likely to
recur, since the cause is in the request. *Fail immediately* — loses the
session over a provider quirk. *Ask the user* — blocks unattended runs.

**Where it lives.** `src/zrb/llm/agent/run/retry_loop.py`,
`src/zrb/llm/agent/run/error_classifier.py`,
`docs/advanced-topics/maintainer-guide.md`.
