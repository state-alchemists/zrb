# ADR-0058 — Tool-definition weight is managed by tool count, not by prose

**Status:** Accepted

**Context.** Every *registered* tool's docstring **and** parameter schema is serialized into every request. That has one consequence people repeatedly get wrong, so it is recorded as a decision rather than left as folklore: **moving prose into a docstring does not save tokens.** A docstring is not deferred context. The only lever on tool-definition weight is the **number** of tools visible per request.

The external evidence for that lever is the strongest behind any decision in this log, and it is about *accuracy*, not merely cost. Retrieving only the relevant tool definitions instead of preloading all of them more than triples tool-selection accuracy (13.6% → 43.1%) while halving prompt tokens (RAG-MCP, arXiv:2505.03275); Anthropic reports the same direction for `defer_loading` via a tool-search tool — MCP-eval accuracy 49% → 74% on Opus 4 and 79.5% → 88.1% on Opus 4.5, with ~85% fewer tool-definition tokens. The academic line (Gorilla arXiv:2305.15334, MCP-Zero arXiv:2506.01056) and the vendor line converge. Note the widely-circulated "accuracy collapses past 10–15 tools" curve has no primary source and is not relied on here.

Counts and token weights are measured, not asserted: the eager schema figure below was produced by resolving factory-built tools against a context and printing eager schema tokens per tool. The figures previously quoted in ADR-0049 were hand-derived and had drifted apart from the measured ones by ~55%. Measured: 2,482 tokens over 20 eager tools, with `Shell` (539) and `Read` (328) alone accounting for 35%.

**Three passages carry hazards no behavioural sweep will price**, and each is pinned by a test rather than left to review. They read like methodology and are therefore standing candidates for deletion; the tests are what stop it.

| passage | hazard | pinned by |
| --- | --- | --- |
| `Shell` "ask for the summary first" | benchmarked: three unscoped `git diff` runs in a dirty repo, ~139MB each, all timed out | `test_shell.py::test_docstring_points_unbounded_output_at_a_summarizing_form` |
| `Shell` "call Shell, not Bash" | a Claude-authored skill or sub-agent instructs "use Bash"; the docstring is the only place that mapping is stated | `test_shell.py::test_docstring_routes_file_work_to_the_file_tools` |
| `Read` batching + its System-Context clause | a description is **static** and cannot be withheld per model, so a model ADR-0038 deny-lists would otherwise read "call this in parallel" and "issue exactly one tool call" in one request | `test_system_context.py::test_read_file_defers_to_the_system_context_override` |

Together they are ~1,045 characters, ~10% of the surface, and an agentic probe sweep prices them at zero — none of those three failures is one a probe battery naturally produces. That is a fact about batteries, not about the passages:

> **A null result from a battery that cannot exercise the hazard is not evidence of no cost.** Before trimming a docstring on a measurement, name the failure the passage prevents and confirm the measurement can produce it.

So the tool surface has no known slack, and finding some needs probes that generate unbounded output, load a skill naming `Bash`, and run a deny-listed model — not a larger sweep of the usual ones.

**Decision.** Manage the count on three axes.

- **Conditional registration.** Tools that only make sense in a particular environment or configuration are not registered otherwise: LSP tools, worktree tools, the plan-mode pair, and the journal tools (ADR-0055).
- **`defer_loading=True`** on tools that are genuinely rarely used. A deferred tool's *name* stays discoverable through native provider-side tool search, and its docstring and schema materialize only when the model searches for it.
- **The `minimal` profile drops delegation.** `LLM_PROFILE` selects a profile (ADR-0049); for `minimal` only, the built-in chat task registers no delegate (sub-agent) tools. `DelegateToAgent` is the one tool that loads eagerly in the main agent — its schema carries the sub-agent roster, and a model that has to search before it can see which agents exist mostly does not delegate at all. That is exactly why it is the right tool to gate on profile: the roster and fan-out machinery are second-order capability for a ~3B model, a pure token cost when unused. `minimal` subtracts the known set rather than re-allowlisting the rest, so this axis never closes any other tool.

Relocating a rule into a docstring is still worth doing — but for **locality and adherence** (ADR-0045), never as a size argument.

**A registered set must be closed under docstring cross-reference.** Docstrings route between each other — `Shell` names `Read`/`Write`/`Edit`/`Grep`/`Glob`/ `RM`/`MV` to say what it is *not* for. Because a docstring ships with its schema regardless of configuration, it cannot carry a `<!--requires:-->` guard the way a prompt section can (ADR-0046), so a reference to an unregistered tool dangles with nothing to catch it. Whichever axis removes a tool owns checking what still points at it — docstrings, prompt sections and injected context can all name a tool, and only a tool that ships will ever need its references intact.

**Consequences.** The per-request tool-definition floor tracks the tools a session can actually use. The cost is that a deferred tool is one search away rather than immediately visible, so deferral is wrong for anything on a common path; and `defer_loading` depends on provider-side tool search, so it is a weaker lever where that is unavailable.

**Alternatives rejected.** *Register everything eagerly* — pays for LSP, RAG and worktree schemas in every session that never touches them. *Trim docstrings to save tokens* — misidentifies the lever, and buys the reduction by making the tools harder to call correctly. *A single mega-tool with a `mode` argument* — collapses the count, and replaces N clear schemas with one union the model must disambiguate at every call.

**Where it lives.** `src/zrb/llm/common_tools.py` (its module docstring states the constraint), `src/zrb/builtin/llm/chat.py` (`_tool_factory`, `_delegate_tool_factory`), `AGENTS.md` (LLM Prompt System).
