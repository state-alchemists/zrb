# ADR-0068 — Delegation: a scope-clamp envelope, context-shaped criteria, and fan-out as a parameter

**Status:** Accepted

**Context.** Three things had to be decided together.

*Scope creep is delegation's main failure mode* — a sub-agent over-produces
against a fuzzy brief — and repeating the persona and rules in every agent
definition is wasteful.

*The criteria were shaped for code editing.* "Delegate only when the work needs
more than 5 tool calls, spans more than 3 files or requires speculative
exploration, and you cannot already write the exact edits; do it yourself for
2 files or fewer." Every anchor describes editing, which **excluded the use case
zrb ships an agent for**: the researcher agent holds no write or shell tools and
its own description says to delegate to it "to keep your primary context clean".
A research sweep never spans files in the edit sense, and "you cannot already
write the exact edits" is undefined when there are no edits. Yet research is the
*stronger* case — volume-to-signal is worse, the discarded material is genuinely
dead, and reads carry no write hazard. The thresholds also did not partition:
more-than-3 to delegate and 2-or-fewer to self-serve leaves exactly 3 satisfying
neither branch.

*There were three delegate tools* differing on only two axes — one-versus-many
and sync-versus-background — so the multi case forced a distinct tool name and a
list-of-dicts shape.

*And a hazard was undocumented.* The delegate signature has **no `cwd` and no
isolation parameter**. Sub-agents inherit the parent's working directory; an
active worktree is only *mentioned* in their context. The generalist agent holds
write tools. So a fan-out of write-capable agents runs concurrently in one tree,
and the reassurance that each task "runs blind to the others" is precisely the
failure condition for writes.

**Decision.**

**A structured envelope.** `DelegateToAgent` sends uppercase, unmissable
delimiters — `DELIVERABLE`, `NON-GOALS`, `TASK`, `CONTEXT`, and a
`BEFORE RETURNING` self-check — forcing the delegator to name concrete artifacts
and the adjacent work to avoid. Agent definitions declare `inherit-sections` to
reuse parent prompt sections while specializing their own body.

**Criteria stated on the axis that actually predicts value** — how much
intermediate material must be consumed to produce a small answer, and whether
the parent needs to keep it. Two justifying shapes:

- **It reads far more than it reports** — research fan-out, or broad exploration
  where the files cannot yet be named.
- **The parent's own context is the liability** — the same hypothesis has failed
  twice, or the work being checked is work the parent produced. Here a sub-agent
  *blind to the parent's reasoning* is the deliverable, not the token saving.
  The recovery rule already says a repeating error means the hypothesis is
  wrong; delegation is the mechanism for obtaining a different one.

Negative conditions are stated in non-edit terms — do it yourself when you
already know the answer's shape — plus two disqualifiers the old wording missed
entirely: **do not delegate when the next step depends on interpreting the
last** (a sub-agent returns a report you cannot interrogate), or **when you need
verbatim text to cite** (synthesis loses the fidelity the citation rule
requires). The numeric thresholds are dropped; the two surviving anchors —
"files you can name", "one or two searches" — are qualitative and cannot leave a
gap.

**Fan-out is a parameter, not a tool.** `DelegateToAgent` takes an optional
`tasks: list[dict]`; a non-empty list runs every entry concurrently and returns
the combined results, while the flat single-task arguments run as before. The
separate parallel tool is gone.

**The write-fan-out hazard is stated where the decision is made**: fan out reads
freely, but fanning out writes shares one working tree, so each task must enter
its own worktree first.

Two justifications are deliberately left *out*: structural enforcement
(delegating to a tool-restricted agent so mutation is impossible) is already
legible from the agent roster the model reads when choosing an agent; and
specialized methodology is what activating a skill in your own context does,
more cheaply and without losing the thread.

**Consequences.** The shipped researcher agent is reachable through the gate
that governs it, the 3-file coverage gap is gone because nothing counts, and a
corruption failure mode is stated at the point of decision rather than
discovered by hitting it. The tool surface is smaller and the mental model is
one thing — "delegate, optionally to several". Costs: qualitative criteria are
harder for a weak model to apply than a file count, mitigated by keeping two
concrete anchors; the delegator must articulate deliverable and non-goals, which
is deliberate friction; and the model must learn the `tasks` argument.

**Alternatives rejected.** *Prose-only scope with no envelope* — models expand
into adjacent work; the delimiters exist because prose did not hold. *Hardcode
every section per agent* — no reuse, and drift from the parent's rules. *Keep
the numeric thresholds and bolt on a research clause* — preserves the false
implication that file span is the governing quantity, and leaves the gap.
*Always require a list* — verbose for the common single case. *Keep three
delegate tools* — redundant surface. *Put `background` on this tool too* — the
handle-and-poll lifecycle is genuinely different (ADR-0069). *Add an
`isolation="worktree"` parameter* — the real fix for concurrent writes and what
Claude Code does; rejected **for now, not on merit**, because it adds a per-task
git worktree (setup cost and disk per agent), a cleanup path that must survive a
crashed sub-agent, and a result-merge story that does not exist yet. Naming the
constraint is the honest interim, since the capability is reachable today —
the generalist agent already holds the worktree tools. *Forbid write fan-out
outright* — over-broad; fanning out writes to provably disjoint paths is
legitimate, and a flat ban pushes users to work around the guidance.

**Where it lives.** `src/zrb/llm/tool/delegate.py` (`_format_envelope`,
`_run_parallel`), `src/zrb/llm/agent/subagent/manager.py`,
`src/zrb/llm_plugin/agents/`.
