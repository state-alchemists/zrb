# ADR-0068 — Delegation: a scope-clamp envelope, context-shaped criteria, fan-out as a parameter, and opt-in worktree isolation

**Status:** Accepted

**Context.** Four things had to be decided together.

- **Scope creep is delegation's main failure mode** — a sub-agent over-produces against a fuzzy brief — and repeating persona and rules in every agent definition is wasteful.
- **The criteria were shaped for code editing.** "Delegate only when the work needs more than 5 tool calls, spans more than 3 files or requires speculative exploration, and you cannot already write the exact edits; do it yourself for 2 files or fewer." Every anchor describes editing, which **excluded the use case zrb ships an agent for**: the researcher agent holds no write or shell tools, and its description says to delegate to it "to keep your primary context clean". A research sweep never spans files in the edit sense, and "you cannot already write the exact edits" is undefined without edits. Yet research is the *stronger* case — worse volume-to-signal, genuinely dead discarded material, no write hazard. The thresholds also left a gap: more than 3 to delegate, 2 or fewer to self-serve, so exactly 3 satisfied neither.
- **There were three delegate tools** differing on two axes — one-versus-many and sync-versus-background — so the multi case needed a distinct tool name and a list-of-dicts shape.
- **Write fan-out shared one tree.** With no `cwd` or isolation parameter, sub-agents inherited the parent's working directory (an active worktree was only *mentioned* in their context). The generalist agent holds write tools, so write-capable fan-out ran concurrently in one tree, and "each task runs blind to the others" was exactly the failure condition for writes. The objection to `isolation="worktree"` was cost (setup/cleanup/merge), not merit — and an opt-in means only a task that asks pays it.

**Decision.**

**A structured envelope.** `DelegateToAgent` sends uppercase delimiters — `DELIVERABLE`, `NON-GOALS`, `TASK`, `CONTEXT`, and a `BEFORE RETURNING` self-check — forcing the delegator to name concrete artifacts and the adjacent work to avoid. Agent definitions declare `inherit-sections` to reuse parent prompt sections while specializing their own body.

**Criteria on the axis that predicts value** — how much intermediate material must be consumed to produce a small answer, and whether the parent needs to keep it. Two justifying shapes:

- **It reads far more than it reports** — research fan-out, or broad exploration where the files cannot yet be named.
- **The parent's own context is the liability** — the same hypothesis has failed twice, or the work being checked is the parent's own. Here a sub-agent *blind to the parent's reasoning* is the deliverable, not the token saving. The recovery rule already says a repeating error means the hypothesis is wrong; delegation is how to obtain a different one.

Negative conditions are stated in non-edit terms — do it yourself when you already know the answer's shape — plus two disqualifiers: **do not delegate when the next step depends on interpreting the last** (a sub-agent returns a report you cannot interrogate), or **when you need verbatim text to cite** (synthesis loses the fidelity the citation rule requires). No numeric thresholds; the two anchors — "files you can name", "one or two searches" — are qualitative and leave no gap.

Two justifications are deliberately left out: structural enforcement (delegating to a tool-restricted agent so mutation is impossible) is already legible from the agent roster, and specialized methodology is what activating a skill in your own context does, more cheaply and without losing the thread.

**Fan-out is a parameter, not a tool.** `DelegateToAgent` takes an optional `tasks: list[dict]`; a non-empty list runs every entry concurrently and returns the combined results, while the flat single-task arguments run as before. There is no separate parallel tool.

**Fan-out concurrency is bounded.** Each concurrent entry is its own LLM run against the shared rate limiter plus, with `isolate_worktree: true`, its own git worktree, and `tasks` has no size limit — so an oversized batch would multiply both. `LLM_MAX_PARALLEL_DELEGATIONS` (default 10, mirroring `LLM_MAX_AGENTS_IN_ROSTER`) gates entry via an `asyncio.Semaphore`; `0` or negative disables it, as with `LLM_MAX_REQUEST_PER_RUN`. It caps *concurrency*, not count: a 50-task call runs all 50, at most N in flight.

**Opt-in worktree isolation per task.** A `tasks` entry may set `isolate_worktree: true` to run in its own git worktree (via the existing `enter_worktree`/`exit_worktree` tools), with a distinct auto-generated branch per task so concurrent isolated tasks cannot collide. It is not the default: read fan-out needs no isolation, nor does write fan-out to provably disjoint paths. Cleanup runs in a `finally` around the sub-agent's run, so it fires on error too: a clean worktree is removed; one with changes is left in place and its path appended to that task's result for the parent and user to review and merge manually. Merging stays deliberately manual.

**Consequences.**

- The shipped researcher agent is reachable through the gate that governs it; the 3-file gap is gone because nothing counts; write fan-out has a working opt-in fix, not just a documented constraint.
- Smaller tool surface, one mental model: "delegate, optionally to several, optionally isolated".
- Qualitative criteria are harder for a weak model than a file count, mitigated by the two concrete anchors.
- The delegator must articulate deliverable and non-goals — deliberate friction.
- The model must learn the `tasks` argument and `isolate_worktree`.
- A dirty worktree left behind is disk and state the user must clean up or merge — only in opt-in cases.
- The concurrency cap protects the rate limiter and worktree store at essentially no cost to normal use, since real fan-out rarely approaches ten concurrent sub-agents.

**Alternatives rejected.**

- *Prose-only scope with no envelope* — models expand into adjacent work; the delimiters exist because prose did not hold.
- *Hardcode every section per agent* — no reuse, and drift from the parent's rules.
- *Keep the numeric thresholds and bolt on a research clause* — preserves the false implication that file span governs, and leaves the gap.
- *Always require a list* — verbose for the common single case.
- *Keep three delegate tools* — redundant surface.
- *Put `background` on this tool too* — the handle-and-poll lifecycle is genuinely different (ADR-0069).
- *Make worktree isolation the fan-out default* — pays setup/cleanup on every fan-out, including the common read-only case; opt-in scopes the cost to callers that declare a write-collision risk.
- *Invent an automatic result-merge* — no merge story is safe to assume generically (conflicting edits, partial work, abandoned branches); leaving the worktree in place and naming its path is the honest interim.
- *Forbid write fan-out outright* — over-broad; writes to provably disjoint paths are legitimate, and a flat ban pushes users to work around the guidance.
- *Cap the total task count instead of concurrency* — would reject a legitimately large read-only batch rather than pace it; throttling in-flight tasks bounds the same resources without a hard rejection.

**Where it lives.** `src/zrb/llm/tool/delegate.py` (`_format_envelope`, `_run_parallel`, `worktree_has_changes`), `src/zrb/llm/tool/worktree.py` (`enter_worktree`, `exit_worktree`, reused unchanged), `src/zrb/llm/agent/subagent/manager.py`, `src/zrb/llm_plugin/{core_agents,agents}/`, `src/zrb/config/mixins/llm_limits.py` (`LLM_MAX_PARALLEL_DELEGATIONS`).
