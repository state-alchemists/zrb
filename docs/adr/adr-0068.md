# ADR-0068 — Delegation: a scope-clamp envelope, context-shaped criteria, fan-out as a parameter, and opt-in worktree isolation

**Status:** Accepted

**Context.** Three things had to be decided together.

*Scope creep is delegation's main failure mode* — a sub-agent over-produces against a fuzzy brief — and repeating the persona and rules in every agent definition is wasteful.

*The criteria were shaped for code editing.* "Delegate only when the work needs more than 5 tool calls, spans more than 3 files or requires speculative exploration, and you cannot already write the exact edits; do it yourself for 2 files or fewer." Every anchor describes editing, which **excluded the use case zrb ships an agent for**: the researcher agent holds no write or shell tools and its own description says to delegate to it "to keep your primary context clean". A research sweep never spans files in the edit sense, and "you cannot already write the exact edits" is undefined when there are no edits. Yet research is the *stronger* case — volume-to-signal is worse, the discarded material is genuinely dead, and reads carry no write hazard. The thresholds also did not partition: more-than-3 to delegate and 2-or-fewer to self-serve leaves exactly 3 satisfying neither branch.

*There were three delegate tools* differing on only two axes — one-versus-many and sync-versus-background — so the multi case forced a distinct tool name and a list-of-dicts shape.

*And a hazard was undocumented — since resolved.* The delegate signature originally had no `cwd` and no isolation parameter. Sub-agents inherited the parent's working directory; an active worktree was only *mentioned* in their context. The generalist agent holds write tools, so a fan-out of write-capable agents ran concurrently in one tree, and the reassurance that each task "runs blind to the others" was precisely the failure condition for writes. A per-task `isolate_worktree: bool` opt-in now closes this (see Decision) — the original objection to `isolation="worktree"` was cost (setup/cleanup/merge), not merit, and that cost is only paid by a task that asks for it.

**Decision.**

**A structured envelope.** `DelegateToAgent` sends uppercase, unmissable delimiters — `DELIVERABLE`, `NON-GOALS`, `TASK`, `CONTEXT`, and a `BEFORE RETURNING` self-check — forcing the delegator to name concrete artifacts and the adjacent work to avoid. Agent definitions declare `inherit-sections` to reuse parent prompt sections while specializing their own body.

**Criteria stated on the axis that actually predicts value** — how much intermediate material must be consumed to produce a small answer, and whether the parent needs to keep it. Two justifying shapes:

- **It reads far more than it reports** — research fan-out, or broad exploration where the files cannot yet be named.
- **The parent's own context is the liability** — the same hypothesis has failed twice, or the work being checked is work the parent produced. Here a sub-agent *blind to the parent's reasoning* is the deliverable, not the token saving. The recovery rule already says a repeating error means the hypothesis is wrong; delegation is the mechanism for obtaining a different one.

Negative conditions are stated in non-edit terms — do it yourself when you already know the answer's shape — plus two disqualifiers the old wording missed entirely: **do not delegate when the next step depends on interpreting the last** (a sub-agent returns a report you cannot interrogate), or **when you need verbatim text to cite** (synthesis loses the fidelity the citation rule requires). The numeric thresholds are dropped; the two surviving anchors — "files you can name", "one or two searches" — are qualitative and cannot leave a gap.

**Fan-out is a parameter, not a tool.** `DelegateToAgent` takes an optional `tasks: list[dict]`; a non-empty list runs every entry concurrently and returns the combined results, while the flat single-task arguments run as before. The separate parallel tool is gone.

**The write-fan-out hazard now has an opt-in fix at the point of decision.** A task in `tasks: list[dict]` may set `isolate_worktree: true` to run inside its own git worktree (via the existing `enter_worktree`/`exit_worktree` tools) instead of the shared working tree, with a distinct auto-generated branch name per task so concurrent isolated tasks cannot collide with each other. Isolation stays opt-in, not default: fan out reads freely with no isolation, and a write fan-out to provably disjoint paths still needs none — the cost (a worktree per task) is paid only by a task that asks for it, which is what makes this affordable where a default would not have been. Cleanup runs in a `finally` block around the sub-agent's run, so it fires even when the sub-agent errors: if the worktree is clean afterward it is removed immediately; if it has changes, it is left in place and its path is appended to that task's result so the parent (and the user) can review and merge it manually — the result-merge story stays manual, deliberately, rather than invented in this decision.

Two justifications are deliberately left *out*: structural enforcement (delegating to a tool-restricted agent so mutation is impossible) is already legible from the agent roster the model reads when choosing an agent; and specialized methodology is what activating a skill in your own context does, more cheaply and without losing the thread.

**Consequences.** The shipped researcher agent is reachable through the gate that governs it, the 3-file coverage gap is gone because nothing counts, and the write-fan-out corruption hazard has a working opt-in fix instead of only a documented constraint. The tool surface is smaller and the mental model is one thing — "delegate, optionally to several, optionally isolated". Costs: qualitative criteria are harder for a weak model to apply than a file count, mitigated by keeping two concrete anchors; the delegator must articulate deliverable and non-goals, which is deliberate friction; the model must learn the `tasks` argument and, now, `isolate_worktree`; and a task that leaves a dirty worktree behind is disk and state the user must eventually clean up or merge — bounded to opt-in cases, not a standing cost of every fan-out.

**Alternatives rejected.** *Prose-only scope with no envelope* — models expand into adjacent work; the delimiters exist because prose did not hold. *Hardcode every section per agent* — no reuse, and drift from the parent's rules. *Keep the numeric thresholds and bolt on a research clause* — preserves the false implication that file span is the governing quantity, and leaves the gap. *Always require a list* — verbose for the common single case. *Keep three delegate tools* — redundant surface. *Put `background` on this tool too* — the handle-and-poll lifecycle is genuinely different (ADR-0069). *Make worktree isolation the fan-out default* — would pay setup/cleanup cost on every fan-out call, including the common read-only case that needs none; opt-in scopes the cost to callers that actually declare a write-collision risk. *Invent an automatic result-merge* — no merge story is safe to assume generically (conflicting edits, partial work, abandoned branches); leaving the worktree in place and naming its path for manual review is the honest interim, same posture as the original "name the constraint" decision this replaces. *Forbid write fan-out outright* — over-broad; fanning out writes to provably disjoint paths is legitimate, and a flat ban pushes users to work around the guidance.

**Where it lives.** `src/zrb/llm/tool/delegate.py` (`_format_envelope`, `_run_parallel`, `worktree_has_changes`), `src/zrb/llm/tool/worktree.py` (`enter_worktree`, `exit_worktree`, reused unchanged), `src/zrb/llm/agent/subagent/manager.py`, `src/zrb/llm_plugin/{core_agents,agents}/`.
