# ADR-0068 — `BufferedUI` plus a confirmation queue for concurrent agents

**Status:** Accepted

**Context.** Several sub-agents — fanned out or backgrounded — share one
terminal. Their output and their approval prompts must not interleave into
unreadability or deadlock against each other.

**Decision.** Each sub-agent runs behind a `BufferedUI` that buffers its output
and forwards approval requests to the parent UI under a lock. The default UI's
`ask_user` is itself a **confirmation queue**: concurrent callers each wait
their turn, and a prompt renders only when its request becomes current.

**Consequences.** Interaction across concurrent agents is serialized and
readable, and the same machinery serves both foreground fan-out and background
agents (ADR-0067). The cost is that a sub-agent's buffered output appears at
flush, approval and completion points rather than strictly live.

**Alternatives rejected.** *No buffering* — interleaved, unreadable output and
racing prompts. *Disallow concurrency* — removes the feature. *Per-agent output
files* — needs a separate polling UI to be useful.

**Where it lives.** `src/zrb/llm/ui/default/confirmation.py` (the queue),
`src/zrb/llm/tool/delegate.py` (`BufferedUI`).
