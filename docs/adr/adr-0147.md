# ADR-0147 — The MCP loader honors only a config this process already loaded

**Status:** Accepted

**Context.** `mcp-config.json` decides what runs: each `mcpServers` entry's `command` and `args` reach `StdioTransport`, which starts a host process outside `build_sandboxed_argv`, outside the filesystem gate and outside every approval prompt.

Asking before the write (ADR-0146) answers the model's own edits. It does not answer the file arriving by another route: a `Shell` redirect, an external process, a second checkout of the same project, or a directory that becomes reachable between runs. The loader reloads per run — deliberately, so a long session picks up a config the user changed on purpose — and that reload is what turned an unseen file into a started process. The bytes parsed at load time were not the bytes any approval had ever covered.

**Decision.** A config file is honored only if this process has already loaded its content.

- **The first load is the baseline.** Every file discovered then is read once, its SHA-256 recorded, and the bytes that were hashed are the bytes that get parsed — one read, so what was vouched for and what was used cannot differ.
- **After the baseline, a file is used only if its digest still matches.** A file the process never loaded is refused, and so is one whose content changed.
- **The refusal is loud and local.** A warning names the file and says why, and that file's servers are skipped; the other configs still load, so one unexpected file does not disable MCP for the session.
- **The baseline is per process.** `clear_mcp_config_provenance` returns it to the unset state, which is what a test suite needs as it moves through many homes and working directories in one process.
- **The baseline is decided once, under a process-level lock.** Reading the digest map, deciding whether this is the first load, and filling it in are one critical section. Two loads racing at startup — two agents built at the same time — otherwise both enter between the read and the write: one takes the configs on disk as its baseline while the other, seeing a map already begun, refuses a file its sibling had just vouched for.

**Consequences.** A config the agent was never approved to write cannot become a started server in the same process, whichever route delivered it. The per-run reload survives, so a deliberate edit by the user still takes effect — on their restart, not silently mid-session.

Costs:

- A user who edits the config mid-session must restart zrb. The warning says so; the alternative is an unexplained dead server.
- The baseline is module-global state, so any caller that loads configs under a different home or working directory in the same process — tests above all — must clear it. It is named and documented rather than hidden.
- Nothing distinguishes a user's edit from an attacker's: both are refused until restart. That is the cost of having no way to attribute a write.
- The lock is held across the file reads, so two loads at startup serialize. The reads are small local files and a load happens once per run, so the wait is not measurable, and the alternative — a baseline that two loads can disagree about — is not a race worth leaving open.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Trust whatever is on disk at each load | The reported behavior, and the gap: a file written between runs started a process no approval covered. |
| Load the config once per process, never again | Closes the gap, and breaks the deliberate per-run reload a long session depends on. |
| Compare modification time instead of a digest | A `cp -p`, a restore, or a same-second edit passes; a digest has no such blind spot. |
| Refuse any config not loaded *before the first tool call* | Stricter than needed, and it fails a legitimate flow: the config discovered at startup may legitimately be edited by the user, who then restarts. |
| Deny the file outright while it is untrusted | Leaves the user with a session that reports nothing configured; skipping the one file keeps the rest working and names the cause. |

**Where it lives.** `src/zrb/llm/capabilities/tool/mcp.py` (`_get_vouched_config_sources`, `_read_config_bytes`, `clear_mcp_config_provenance`, `load_mcp_config`), `src/zrb/llm/engine/agent/tool_seed.py` (the per-run reload this bounds).
