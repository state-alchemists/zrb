# ADR-0090 — Delegation criteria are context-shaped, not file-count-shaped; concurrent write fan-out is called out as unsafe

**Status:** Accepted (relates to ADR-0045, ADR-0043)

**Context.** When to reach for `DelegateToAgent` was never recorded as a
decision — it lived only in the tool-guidance string, which read:

> Delegate only when ALL apply: (a) the work needs >5 tool calls, (b) it spans
> **>3 files** OR requires speculative exploration, (c) you cannot already
> **write the exact edits**. Do the work yourself for **≤2 files**, one-line
> changes, or any edit whose content you already know.

Every anchor and all three exit conditions describe code editing. Two problems
followed.

**It excluded the use case zrb ships an agent for.** `researcher.agent.md` holds
no `Write`, `Edit`, or shell tools and its own description says: "Delegate to this
agent for deep research tasks (documentation lookup, API investigation,
technology comparison, codebase archaeology) **to keep your primary context
clean**." A research sweep never "spans >3 files" in the edit sense, and criterion
(c) — "you cannot already write the exact edits" — is undefined when there are no
edits. Only the unexemplified `speculative exploration` disjunct kept research
eligible at all. Yet research is the *stronger* case: volume-to-signal is worse
(tens of thousands of tokens of pages for a few hundred of finding), the
discarded material is genuinely dead (unlike surrounding code the parent will
need for its next edit), and reads carry no write hazard. zrb already agrees one
level down — `open_web_page(summarize=True)` runs a summarizer sub-agent per page
(`web_summarizer.md`).

**The thresholds did not partition.** ">3 files" to delegate and "≤2 files" to
self-serve leaves exactly 3 files satisfying neither branch.

Separately, a hazard was undocumented. `delegate_to_agent`'s signature is
`(agent_name, deliverable, task, non_goals, additional_context, tasks)` — **no
`cwd` and no isolation parameter**. Sub-agents inherit the parent's working
directory; an active worktree is only *mentioned* in their context
(`tool/delegate.py`). `generalist` holds `Write, Edit, RM, MV`. So a
`tasks=[...]` fan-out of write-capable agents runs concurrently in one tree,
and the guidance's own reassurance — "each task dict carries its own clamp and
**runs blind to the others**" — is precisely the failure condition for writes.

**Decision.** State the criteria on the axis that actually predicts value: **how
much intermediate material must be consumed to produce a small answer, and
whether the parent needs to keep it.** Two justifying shapes, plus one that is
not about economy at all:

- **(a) Reads far more than it reports** — research fan-out (several independent
  questions, each needing multiple searches and page reads, answered as one
  synthesis); broad exploration where the files cannot yet be named.
- **(b) The parent's own context is the liability** — the same hypothesis has
  failed twice, or the work being checked is work the parent produced. Here a
  sub-agent *blind to the parent's reasoning* is the deliverable, not the token
  saving. `Recovery` already says "same error repeating → the hypothesis is
  wrong" but offered no mechanism for obtaining a different one; delegation is
  that mechanism.

Negative conditions are stated in non-edit terms — do it yourself when you
already know the answer's shape (an edit you can write now, a change confined to
files you can name, a lookup of one or two searches) — plus two disqualifiers
that the old wording missed entirely: **do not delegate when the next step
depends on interpreting the last** (a sub-agent returns a report you cannot
interrogate), or **when you need verbatim text to cite** (synthesis loses the
fidelity `persona`'s citation rule requires).

The numeric thresholds are dropped. The two surviving anchors ("files you can
name", "one or two searches") are qualitative and cannot leave a gap.

`DelegateToAgentBackground` is re-framed as *timing, not size* — the work may be
small; the justification is that you do not need it before continuing.

**The write-fan-out hazard is named in the guidance**: fan out reads freely;
fanning out writes shares one working tree, so each task must enter its own
worktree first. Documenting the constraint is deliberately preferred to adding an
`isolation` parameter — see Alternatives.

Two justifications are deliberately left *out* of the prompt: structural
enforcement (delegating to a tool-restricted agent so mutation is impossible —
already legible from the agent roster the model reads when choosing
`agent_name`) and specialized methodology (that is `ActivateSkill` in your own
context, which is cheaper and keeps the thread).

**Consequences.**

- *Good.* The shipped `researcher` agent is now reachable through the gate that
  governs it.
- *Good.* The coverage gap at exactly 3 files is gone, because nothing counts.
- *Good.* A corruption failure mode (concurrent writes in one tree) is stated
  where the decision is made instead of being discoverable only by hitting it.
- *Good.* Two real disqualifiers are now explicit; both were previously
  unaddressed, and both cost more than an unnecessary self-serve would.
- *Cost.* Qualitative criteria are harder for a weak model to apply than "counts
  more than three files". Mitigated by keeping two concrete anchors and by
  naming the two shapes rather than stating an abstract principle alone.
- *Cost.* The entry is slightly longer. Accepted: the tool it gates is the most
  expensive one in the set, and over-delegation costs a full agent's overhead
  plus the loss of the reasoning thread.
- *Neutral.* No code path changed. This is guidance only; the scope clamp of
  ADR-0045 is untouched.

**Alternatives rejected.**

- *Keep the numeric thresholds and add a research clause.* Preserves the
  false implication that file span is the governing quantity, and leaves the
  3-file gap.
- *Add an `isolation="worktree"` parameter to `delegate_to_agent`.* The real fix
  for concurrent writes, and what Claude Code does. Rejected **for now**, not on
  merit: it adds a per-task git worktree (setup cost and disk per agent), a
  cleanup path that must survive a crashed sub-agent, and a result-merge story
  that does not exist yet — none of which belong in a prompt-correctness change.
  Naming the constraint is the honest interim: the capability is reachable today
  because `generalist` already holds `EnterWorktree`.
- *Forbid write fan-out outright.* Over-broad — fanning out writes to
  provably disjoint paths is legitimate, and a flat ban would push users to
  work around the guidance rather than with it.
- *Leave "when to delegate" undocumented as a decision.* It is exactly the kind
  of judgement a later reader would otherwise re-litigate from the guidance
  string, having lost the reason the counts were dropped.
