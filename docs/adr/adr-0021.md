# ADR-0021 — `CFG` is one singleton composed from domain mixins, accessed flat

**Status:** Accepted

**Context.** zrb has well over a hundred tunable settings spanning LLM, web,
RAG, hooks, search and limits. One monolithic class is unnavigable, and nested
config objects would force caller churn every time a setting moves domain.

**Decision.** `Config` is composed from focused mixins — one per domain
(`foundation`, `web`, `llm_core`, `llm_limits`, `llm_prompt`, `theme`, …) — and
instantiated once as `CFG`. **Access stays flat**: `CFG.LLM_MODEL`,
`CFG.WEB_HTTP_PORT`, regardless of which mixin owns the attribute.

**Consequences.** Each domain is a small owned file, a setting can move between
mixins without touching a single caller, and a setting's home is discoverable
from the lookup guide in `config.py`. The cost is that the mixin MRO is
implicit machinery a reader has to know about.

**Alternatives rejected.** *One monolithic config class* — what this replaced;
unsearchable at this size. *Hierarchical access (`CFG.llm.model`)* — every
caller and test changes when a setting moves, which is the churn the flat
surface exists to prevent. *Module-level constants* — no env overrides and no
runtime setters.

**Where it lives.** `src/zrb/config/config.py` (thin shell + lookup guide),
`src/zrb/config/mixins/`.
