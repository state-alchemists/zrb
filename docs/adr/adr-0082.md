# ADR-0082 — Photo capture is a one-shot command with a pluggable backend, and carries no enable gate

**Status:** Accepted

**Context.** A photo has no lifecycle: one command, one photo. Dictation (ADR-0076) at first needed a toggled mode with a keybinding and a status-bar badge; a photo needs none of that.

Camera access is fragmented. Desktop OSes use their own device APIs (v4l2 on Linux, AVFoundation on macOS, DirectShow on Windows). Termux has no `/dev/video*` and must use `termux-camera-photo`, a Termux:API Android-intent binary. WSL2 has no camera passthrough unless the user sets up `usbipd-win`, and even then the stock kernel has no camera driver.

Field-testing found a proot-in-Termux gotcha. `termux-camera-photo` run inside a `proot-distro` guest does reach the Termux:API app, but the app is a separate, non-prooted Android process and cannot see the guest's `/tmp` or `$HOME`, so it fails with a `FileUtils Error`.

**Decision.**

1. **`/photo [device]` is a one-shot command**, added by `enable_camera` (ADR-0102) and modeled on `/attach`. It captures a JPEG, scales it like a pasted image (`scale_image_bytes`), and queues it as a `BinaryContent` in the UI's `pending_attachments` for the next message. No mode state, keybinding or badge.
2. **The optional argument is the device** (index, path or name, per platform). It completes from the backend's `list_devices`, which never blocks: Windows device names need a slow ffmpeg listing, so it runs in the background and the next completion picks it up.
3. **No enable gate.** The command is offered whenever it has an alias, and fails with a platform-specific hint (`get_failure_hint`) rather than hiding (ADR-0093). A gate protects against missing Python dependencies, and capture has none.
4. **Capture shells out to external binaries.** `backend` is a name or an `AnyCameraBackend`. `capture` returns JPEG bytes or `None` and never raises.

   | Backend | Captures with |
   | --- | --- |
   | `termux` | `termux-camera-photo`, writing to a fresh `.<root group name>_camera_<random>.jpg` in Termux's real home (`/data/data/com.termux/files/home`), read back, and removed on every path out, so a failed capture never returns an earlier photo and two sessions never share a file |
   | `ffmpeg` | `avfoundation` on macOS; `dshow` on Windows, auto-detecting the first video device from `ffmpeg -f dshow -list_devices true -i dummy`; `v4l2` on Linux and WSL, defaulting to `/dev/video0`, asking for 640x480 MJPEG first and falling back to the raw default |
   | `auto` (default) | `termux` on Termux when it is installed and captures, else `ffmpeg` |

   Termux does not use `tempfile.gettempdir()`, since a proot guest's `/tmp` does not exist for the app. Termux's home is at one fixed location whether the shell is native or prooted, so one path works everywhere without proot detection.

   The file name follows `ROOT_GROUP_NAME`, so a white-labeled build does not write `zrb`-named files.
5. **WSL gets no special-cased capture code.** To ffmpeg it is Linux. The failure hint tells the two WSL cases apart: no `/dev/video*` means the kernel has no camera driver; a device node that yields no frame means usbipd's USB/IP tunnel cannot sustain the stream. MJPEG at 640x480 is the largest that lands over the tunnel, and the capture `timeout` is the backstop when even that hangs.

6. **`timeout` bounds the whole capture, not each attempt.** One deadline is set per capture and every attempt gets only what is left of it: ffmpeg's MJPEG try and its raw fallback, and under `auto`, Termux and then ffmpeg. A backend's own timeout still applies inside `auto`, whichever ends first. `0` means no limit.

**Consequences.** `/photo` works in the chat TUI and every UI built on `BaseUI`, with no new dependency and no cost when unused. It is always listed in help and completion. Windows auto-detection is best-effort: a machine with several cameras or unusual driver names may need the device name passed explicitly.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| A toggled mode with a keybinding | A snapshot has no start or stop to key off. |
| An `opencv-python` (or similar) dependency | ffmpeg and `termux-camera-photo` already cover every platform through a subprocess, as the clipboard-image paste does without an image-clipboard library. |
| An enable gate | There is no missing dependency to guard; the failure hint does the job and keeps the command discoverable. |
| A temp file for Termux | A proot guest's temp directory is invisible to the Termux:API app. |

**Where it lives.** `src/zrb/llm/camera/feature.py` (`enable_camera`, `attach_photo`), `src/zrb/llm/camera/backend/` (`termux.py`, `ffmpeg.py`, `auto.py`, `builtin.py`), `src/zrb/llm/camera/config.py`, `src/zrb/config/mixins/llm_camera.py`. The WSL write-up is `docs/llm/voice-photo-troubleshooting.md`.
