# ADR-0053 — The journal is a markdown graph that only tools write, behind one master switch

**Status:** Accepted

**Context.** Agent long-term memory should be human-readable, organizable, and
cheap on tokens — not everything belongs in every prompt. A single JSON note
store could not grow into that.

The first design got the storage right and the *authoring* wrong. Recording one
line of memory cost the model an 838-token prompt section, an 11 KB skill,
three templates and a 295-line linter — all so it could hand-construct a
bidirectionally-linked markdown graph with no orphans.

The linter is the tell. It checked four invariants: **broken-link** (a link
whose target does not exist), **missing-backlink** (a forward link with no
reciprocal entry), **orphan** (a note unreachable from the root index), and
**missing-index** (a directory of notes with no index). Every one is a property
of *how the file was written*. They needed checking only because a language
model was writing freehand from prose instructions — and the model had to
remember to shell out to the linter afterwards. Nothing enforced any of it. The
observed failure was not malformed output but **deferral**: in a recorded
session the agent said "I'll log your name preference now" and yielded the turn
without a single tool call, which is the cheapest legal action when the write
is expensive and unobservable.

Turning journaling *off* was also impossible. The journal reached the model
through four independent surfaces — the prompt section, the index injection,
the search tool, and the built-in skill — each behind a different lever, and no
combination of them disabled it: the directory path has no "unset" value,
dropping the prompt section left the skill advertised in the catalogue, and
zeroing the index size made the protocol lie about an empty journal. A
benchmark harness made the cost concrete: isolating each trial with an empty
per-trial journal directory is precisely the trigger for structural work, so
compliant models built a full tree of 9–10 files in most runs and then
discarded it — a cost paid only by the models that follow the protocol.

**Decision.** Store the journal as a hierarchical markdown directory
(`ZRB_LLM_JOURNAL_DIR`). Only the index is injected into the conversation, at
the two points ADR-0042 defines; detailed notes are read on demand. **Three
tools own the format, and there is no prose:**

- `SearchJournal` reads.
- `LogActivity(summary, files=None)` appends to
  `activity-log/YYYY/YYYY-MM/YYYY-MM-DD.md`. It derives the path **and the
  timestamp** itself, creates the day file with its heading and its backlink to
  the month index, and creates or extends the year, month and day indexes on the
  way down.
- `WriteJournalNote(category, slug, title, context, finding, source, links=None,
  hud_line=None)` writes `{category}/{slug}.md` with frontmatter and a
  Context/Finding/Source body, inserts the reciprocal backlink entry in every
  file it links to, and registers itself in the category index and under the
  root index's recent-insights section. `hud_line` upserts a compressed line
  into the root-index section matching the category, which is how a stated
  preference reaches the always-injected index without a third tool.

The four invariants become **unviolatable rather than checkable**: a link is
only written after its target is confirmed on disk, the reciprocal backlink is
inserted in the same call, every note is registered in its directory index, and
every directory index is linked from the root. The *judgment* — what earns an
entry, and that the write happens before the reply rather than being deferred —
lives in the tool docstrings, which pydantic-ai ships every turn anyway
(ADR-0045) and which disappear with the tools when journaling is off.

**One master switch.** `LLM_JOURNAL_ENABLED` (default on, state-last per
ADR-0026 because `LLM_JOURNAL_*` already has siblings) gates tool registration
in `apply_common_tools`, and `render_journal_index` checks it directly for the
index injection — reachable from the summarizer, so it cannot rely on its
callers. Two enforcement points, both the actual surface rather than a proxy
for it.

**Consequences.** Writing memory is one tool call, so the incentive and the
mechanics finally agree. Format changes are code changes with tests rather than
prose edits hoping for compliance, and path traversal is closed by
construction: the category comes from a fixed set, the slug must match a
kebab-case regex, and link targets resolving outside the journal root are
rejected. Turning the journal off removes the tools, the index and the skill
together. Legacy and hand-written journals still work — `SearchJournal` reads
anything and the journal-directory write auto-approvals remain — but the
machinery for the model to *build* one freehand is gone, and a journal edited by
hand outside the tools is no longer checkable. That is accepted: a linter nobody
was required to run was not providing the guarantee anyway.

**Alternatives rejected.** *A single JSON note file* — flat, and it cannot grow
into a browsable graph. *Embed all notes in the prompt* — token waste for
content most turns do not need. *An external database* — overkill, and less
portable than files in a git repo. *One `WriteJournal(kind=...)` tool* — merges
two genuinely different argument sets behind an enum, forcing every caller to
read both halves of the schema. *Keep the linter as a CLI command* — nothing
would call it: the writers cannot produce output that fails it, and legacy
journals are explicitly not migrated. *Keep the skill for structural work* — two
descriptions of one tree, free to diverge. *Gate the four surfaces
independently* — what already existed, and the reason nothing could turn
journaling off. *Treat an empty journal directory as "disabled"* — overloads a
path with a mode, and silently disables journaling for anyone who cleared the
variable expecting the documented default. *Give `core_skills/` a blanket
toggle* — too broad; it would take the other core skills with it. *Turn a
per-turn reminder hook on by default* — treats a nudge as a substitute for a
followable rule, and pays a token cost every turn for a write most turns should
not make.

**Where it lives.** `src/zrb/llm/tool/journal.py` (`SearchJournal`),
`src/zrb/llm/tool/journal_write.py` (the writers; its module docstring maps each
behaviour to the invariant it replaces), `src/zrb/llm/common_tools.py` (the
registration gate), `src/zrb/llm/prompt/live_context.py`
(`render_journal_index`), `src/zrb/config/mixins/llm_content.py`,
`test/llm/tool/test_journal.py`.
