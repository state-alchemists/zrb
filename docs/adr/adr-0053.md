# ADR-0053 — Claude-compatible skills, loaded on demand, with a catalogue generated from the live scan

**Status:** Accepted

**Context.** Reusable domain expertise should be portable with Claude Code's ecosystem, and able to bundle scripts and data alongside its instructions.

Separately, the *catalogue* of skills used to live in its own prompt section while the *policy* governing activation — when to activate, authority, tie-breaks — lived in the rules section, which also carried a hand-maintained table of the core skills. The same subject was described in two sections, which is the MECE violation ADR-0044 exists to prevent, and the hand-maintained table could drift from the actual directory.

**Decision.** A skill is `SKILL.md` (YAML frontmatter plus body) or `SKILL.py`, matching Claude's format. Skills are listed as metadata and loaded in full on demand. Companion files in the skill's directory are auto-discovered and surfaced, so a skill can ship scripts, templates and references.

The catalogue is rendered **into the rules section** through placeholder substitution rather than existing as a section of its own. `build_skill_replacements(skill_manager, active_skills)` computes three values passed as extra replacements when `workflow` is composed:

- `{CORE_SKILLS}` — the activatable core methodologies (built-ins under `llm_plugin/core_skills/`, detected by path), listed from their live descriptions. “Methodology” distinguishes their baseline role from optional domain skills; both remain `ActivateSkill` bundles.
- `{AVAILABLE_SKILLS}` — every other model-invocable skill.
- `{PREACTIVATED_SKILLS}` — full content of any pre-activated skills, empty when none; these are excluded from the two lists above.

Both lists are **capped** by `LLM_MAX_SKILLS_IN_CATALOG` (default 10). A catalogue that outgrows the cap is truncated with a pointer to `SearchSkill`; the overflow is reachable on demand, so the cap only ever saves tokens, and the note keeps truncated entries discoverable instead of silently dropped. `SearchSkill` is registered alongside `ActivateSkill` in `common_tools.py` so the escape hatch is always on the tool surface when the catalogue is.

**Consequences.** Skill bundles are self-contained and directly portable with Claude setups, and lazy loading keeps context lean. The catalogue and the rules that govern it live in one place, and the core list is generated from the directory so it cannot drift.

Calling the core entries “methodologies” removes an otherwise misleading distinction between text that sounds activatable and bundles that actually are. The core/other split surfaces the ADR-0054 distinction directly in the prompt.

The cap (ADR-0058's tool-count lever applied to the catalogue) keeps the rules section from growing without bound as skills are added, with `SearchSkill` absorbing the retrieval cost.

Prompt caching is unaffected, because the skill scan is cached and the pre-activated set is a static task parameter. The cost is that the hosting section is no longer purely static markdown — it depends on `build_skill_replacements` at compose time.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| A hardcoded tool list per skill | Drifts out of sync with what the skill actually needs. |
| Flat skill files with no companion discovery | Awkward for anything multi-asset. |
| A rigid mandated directory layout | Too inflexible for user-authored skills. |
| Keep the catalogue as its own section | Duplicates the activation rules across two sections. |
| Register the catalogue as a config-positioned provider (ADR-0044) | Heavier machinery for content that is a natural, always-on part of the rules section, and it would separate the catalogue from the rules again. |
| An uncapped catalogue | The status quo, which made the rules section's weight a function of the user's accumulated skill dirs rather than a decision. |

**Where it lives.** `src/zrb/llm/skill/`, `src/zrb/llm/tool/skill.py` (`create_search_skill_tool`), `src/zrb/llm/common_tools.py`, `src/zrb/config/mixins/llm_prompt.py` (`LLM_MAX_SKILLS_IN_CATALOG`), `src/zrb/llm/prompt/claude.py` (`build_skill_replacements`, `_is_core_skill`, `_format_skill_list`), `src/zrb/llm/prompt/markdown/workflow.md` (the placeholders), `docs/advanced-topics/claude-compatibility.md`.
