# ADR-0120 — LS, Glob and AnalyzeCode agree about `.gitignore`, and the default is to hide

**Status:** Accepted

**Context.** ADR-0117 gave `LS` a `gitignore=True` default, so an orientation listing shows the repository's real shape instead of every generated artifact. `Glob` and `AnalyzeCode` were not changed, and they answer the same question about the same directory: which files are here. The result was three tools with two shapes — `LS` hiding `htmlcov/`, `Glob` returning its 1,400 files, and an `AnalyzeCode` run walking, reading and billing for files the repository refuses to track.

Part of the gap was masked: `DEFAULT_EXCLUDED_PATTERNS` already names `htmlcov`, `.pytest_cache`, `.coverage`, `.claude`, `.venv` and `node_modules`, so only a repository-specific ignore (`data/`, `output/`, `generated/`) exposed the difference at all.

This is a deliberate divergence from the reference harness. Claude Code's `Glob` does **not** respect `.gitignore` by default (`CLAUDE_CODE_GLOB_NO_IGNORE=false` opts in), while its `Grep` does. Copying that would reproduce the same disagreement inside zrb.

**Decision.**

1. **One filter, in one place.** `git_visible.py` exposes `git_visible_files` (tracked, or untracked and not ignored) and `without_gitignored`. `LS` uses it through `file_list.py`; `Glob` and `AnalyzeCode` import the same functions.

2. **`gitignore` defaults to `True` on all three.** The default answers "what is this repository?", which is the question these tools are asked; the ignored tree is the exception and needs the flag.

3. **Outside a checkout, nothing is filtered.** A missing git, a failed call or a non-repository directory returns the unfiltered set, because "git said nothing" is not evidence that every file is ignored.

4. **`AnalyzeCode` computes the visible set once per run** and filters while walking, so a scoped run pays one `git ls-files` instead of one per file, and never reads a file it would discard.

**Consequences.** The three tools now give the same answer for the same directory, and an analysis run no longer spends tokens on ignored output. `Glob`'s behaviour differs from Claude Code's default, so a model carrying that expectation from another harness may be surprised by a shorter result; `gitignore=False` restores it. A repository whose ignore file hides something the user actually meant to search now needs that flag explicitly, where before the list simply included it.

**Alternatives rejected.**

- *Match Claude Code exactly (`Glob` unfiltered)* — keeps an internal disagreement that is invisible until it costs tokens, and zrb's own `LS` already made the choice.
- *Filter only in `AnalyzeCode`* — an analysis and a listing would disagree, and the cheaper tool (`Glob`) is the one used for orientation.
- *Fold the common artifacts into `DEFAULT_EXCLUDED_PATTERNS` instead of asking git* — the list is a guess about other people's repositories; `.gitignore` is the repository's own answer.

**Where it lives.** `src/zrb/llm/tool/git_visible.py`, `src/zrb/llm/tool/file_list.py` (`list_files`, `glob_files`), `src/zrb/llm/tool/code.py` (`analyze_code`, `get_file_metadatas`), `test/llm/tool/test_glob_gitignore.py`, `test/llm/tool/test_file_ls.py`. See ADR-0117 for the `LS` side.
