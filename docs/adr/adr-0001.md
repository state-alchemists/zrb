# ADR-0001 — Pure-Python task definitions, no YAML or DSL

**Status:** Accepted — the defining choice of v2

**Context.** Automation tools traditionally describe pipelines in YAML or JSON (Ansible, GitHub Actions, GitLab CI, Airflow), and zrb v1 was itself YAML-driven. Declarative configs inevitably reinvent programming constructs — loops, conditionals, string interpolation — badly.

**Decision.** Tasks are defined exclusively in Python: class instances (`CmdTask(...)`, `Task(...)`), the `@make_task` decorator, or `BaseTask` subclasses. There is no YAML, JSON, or custom DSL for task definitions.

**Consequences.** Users get type checking, linting, IDE completion, and the whole PyPI ecosystem for free. The cost is that authoring requires Python literacy, and there is no language-agnostic config format for non-Python tooling to generate.

**Alternatives rejected.** *YAML/JSON declarative configs* — familiar, but they reinvent programming constructs poorly, which is the failure mode v1 lived with. *A custom DSL* — a parser to maintain and no editor tooling. *Implicit discovery by naming convention* — too magical to debug.

**Where it lives.** `src/zrb/task/make_task.py`, `docs/advanced-topics/architecture.md`. The v1 → v2 shift is visible in `docs/changelog-v1.md` versus `docs/changelog-v2/`.
