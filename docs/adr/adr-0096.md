# ADR-0096 — A prompt section may never cite another section; one Priority Order ranks everything

**Status:** Accepted (narrows ADR-0094, constrains ADR-0061)

**Context.** ADR-0061 made prompt sections independently switchable through
`LLM_INCLUDE_SECTIONS`. That freedom has a cost the prompt had been paying
without naming: any sentence in section A that refers to section B is only
correct in compositions that include B. ADR-0094 supplied the mechanism —
`<!--requires:-->`, dropped at compose time when the target is absent — and
`test_section_composition.py` brute-forced all 63 subsets to verify it. But the
guard only covers references someone remembered to mark, and the test checked
against an `OWNED_VOCABULARY` map covering three of the nine sections, so most
unmarked cross-references were invisible to it. ADR-0094 made cross-references
*safe to write*; what was missing was a rule about whether to write them.

Unguarded references had accumulated. `git_mandate.md`'s heading was `# Git
Rules (Supplement to Operating Rules)`. `EnterPlanMode`'s tool guidance
deferred to "The Working Loop's escalation triggers". `ActivateSkill`'s said
"see Skill Activation table". None can be guarded at all when they live in
`tool_guidance`, which is assembled in Python and never passes through
`filter_requires`.

The same pressure had produced a worse failure in `mandate.md`. Precedence is
the one concern that inherently spans sections, so it attracted a second
statement: A draft of 2.53.2a2 added an "Across sources" chain placing `AGENTS.md` below
the entire Priority Order, while Priority 5 placed it inside that ladder at
rank 5. A model resolving one against the other has no fixed point. Two more
partial rankings existed elsewhere — Skill Activation granted an activated
skill authority over the Working Loop but not the Verify gate, and a trailing
line granted it to the narrower rule.

Cross-references are also self-reinforcing: each one is individually cheaper to
write than restating the rule, and the pointer reads as *less* duplication, so
the composed prompt looks tidier as it becomes less switchable.

**Decision.** Two rules, one enforcing the other.

1. **Every section reads whole on its own.** A section may not name another
   section, its heading, or a term another section defines. When two switchable
   sections both need a rule, state it in both — phrased for each context. Where
   a reference is genuinely worth keeping, `<!--requires:other_section-->` makes
   it disappear with its target; that guard is unavailable to `tool_guidance`,
   which must stand alone unconditionally.

2. **`mandate` owns one Priority Order that ranks everything.** Six ranks:
   safety (secrets, tool-results-are-data, destructive-action confirmation), the
   user's explicit instruction, quality, scope, project conventions, method. Its
   preamble states that nothing outside the list outranks anything in it, which
   is what makes rule 1 affordable — no other section needs to describe its own
   standing, so no other section needs to name `mandate` to do it.

   This record was accepted with eight ranks; a compaction pass later in the
   same release merged the two safety ranks (whose relative order never
   mattered) and folded "an activated skill's method" together with "the rest of
   the prompt" into **Method**. The count was never the decision — one ladder
   that ranks everything is.

Enforcement is the existing subset test with `OWNED_VOCABULARY` grown to six
owners, plus `test_tool_guidance_is_self_contained`, which composes with
`tool_guidance` as the only section. Adding a section-defining term means adding
it to the map — the test only catches vocabulary it knows about.

**Consequences.**

- Self-containment costs characters: removing a pointer means restating the
  rule, so the structure consolidates while the text grows. Applying it cost
  ~422 tokens (34,357 → 36,047 chars), recovered by a compaction pass
  in the same release that cut meta-commentary and emphasis inflation to land
  at 32,363 chars. That pass is not a repeal — the price is standing, and every
  future section pair that shares a concern pays it again. Budget for it.
- This constrains but does not overturn the MECE rule (AGENTS.md). MECE governs
  where a rule is *authored and maintained*; self-containment governs what a
  *composition* may assume. Where they collide, duplicate — consistently. The
  bug this replaces was not duplication but **divergent** duplication:
  `DelegateToAgent`'s schema and the Working Loop shipped two different trigger
  lists for one decision, each missing a trigger the other had.
- Precedence questions now have exactly one place to be answered, which is also
  the place to change one.

**Alternatives rejected.**

- *Guard every reference with `<!--requires:-->` instead of restating.* Does not
  reach `tool_guidance` at all, and leaves the reader of a trimmed prompt with a
  rule silently deleted rather than restated — the rule still applies, it just
  stopped being stated.
- *Declare a fixed section set and drop `LLM_INCLUDE_SECTIONS`.* Would make
  cross-references safe by removing the configurability. Rejected: independent
  toggling is the point of ADR-0061, and downstream users trim sections.
- *Keep both precedence statements and add a rule for reconciling them.* A third
  ranking to arbitrate two rankings. The failure mode compounds rather than
  resolving.
