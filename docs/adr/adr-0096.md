# ADR-0096 — The agent barrel resolves lazily, and import safety is asserted per module

**Status:** Accepted

**Context.** A package `__init__.py` runs before any of its submodules. An eager re-export there is therefore a guarantee that everything the exported names transitively reach loads whenever *anything* under the package is imported.

`zrb/llm/agent/__init__.py` re-exported four names and imported `agent/hook_agent.py` for its registration side effect. Twenty lines that pulled `common.py`, `run/runner.py`, `summarizer.py` — and through them most of `zrb.llm` — into every import under `zrb.llm.agent`.

Over the module graph (`if TYPE_CHECKING:` blocks excluded), that made the largest strongly connected component 87 modules: 21 in `llm.tool`, 21 in `llm.ui`, 12 in `llm.agent`, 8 in `llm.task`, plus `runner.chat` and `runner.cli`. Deferring each barrel in turn isolates it to one file:

| barrel deferred | max SCC |
| --- | --- |
| *(none)* | 87 |
| `zrb.llm.agent` | **23** |
| `zrb.llm.ui` | 82 |
| `zrb.llm.summarizer` | 84 |
| `zrb.llm.tool` | 87 |
| any other | 87 |

ADR-0088 addressed the same mechanism at a different site — two leaf modules nested under `zrb.llm.agent` — and declined to touch the barrel because its imports are load-bearing for the package's job. That holds for *what* the barrel exports, not for *when* it resolves them.

What blocked the change was the safety net. `test_every_package_imports_with_its_parents_stubbed` imported each of 27 packages with its parents stubbed and nothing deeper, so the tree's 419 other modules were reachable by it only through whatever their barrel re-exported. Any barrel made lazy silently shrank the check — which is why `zrb.llm.tool`'s was restored to eager in 2.67.0, its docstring recording that the eager import, not the exported names, was doing the work.

**Decision.** Assert import safety per module; then defer the barrel.

`_all_modules()` replaces `_all_packages()`: every `*.py` under `src/zrb` whose path parts are identifier-legal, 417 targets, each imported in its own subprocess with parents stubbed. The filter excludes the skill tool scripts under `llm_plugin/*_skills/<skill>/tools/`, standalone CLI programs in hyphenated directories no `import` statement can name. No barrel is load-bearing for the check.

`zrb/llm/agent/__init__.py` resolves its four names through PEP 562 `__getattr__`, caching into `globals()`, with an `if TYPE_CHECKING:` mirror for pyright. `hook_agent`'s registration moves into that `__getattr__`, firing on first use of an agent name rather than on package load — still before any hook-manager read, since every entry point (`LLMTask`, `LLMChatTask`, `SubAgentManager`) resolves one of the four while building its agent.

Import spellings are unchanged. `from zrb.llm.agent import create_agent` is an attribute access, which is what `__getattr__` answers; all 14 call sites are untouched.

**Consequences.** Largest SCC 87 → 23. Modules in any cycle 102 → 23. `zrb.llm.agent`'s eager closure 338 of 447 modules → 1. Isolated-import coverage 27 packages → 417 modules, worth +392 tests and roughly +24s wall on `-n auto`.

`import zrb` is unchanged at 0.22s. The win is structural: `zrb.builtin` reaches the same modules by another route, and that is a separate question.

The four names now resolve through a dict lookup and one `importlib` call each, cached after first access. The cost is legibility — the barrel is an export table rather than a list of imports, and `_SOURCES` is where a reader has to look.

The `# lazy: circular` allowlist stays empty and the 295 `# lazy:` tags are untouched, but some were placed to dodge a cycle this removes, so they are worth re-auditing.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Defer every barrel | Nothing else moves the number: `zrb.llm.tool` is worth 0, `zrb.llm.ui` 5. Both are documented user-facing import surfaces (`docs/llm/llm-custom-ui.md`, `examples/chat-sse`, `examples/chat-telegram`). |
| Trim what the agent barrel exports | All four names have callers — 14 sites, including `llm_task.py`, `tool/code.py`, `builtin/llm/please.py`. Resolution time is the problem, not the export list. |
| Drop the barrel; make callers deep-import | Same structural result, but breaks every call site and doc example for no gain over deferring. |
| Keep the barrel eager | Correct while the check was package-level. Fixing the check removes the reason. |
| Register `hook_agent` from `hook/agent_hook_registry.py` instead | Inverts ADR-0086's seam: the registry is a leaf that knows nothing about the agent package, and importing one would return it to the cycle it exists to break. |

**Where it lives.** `src/zrb/llm/agent/__init__.py`, `test/architecture/test_circular_import_allowlist.py` (`_all_modules`, `test_every_module_imports_with_its_parents_stubbed`), `.coveragerc` (skill-tool-script omit, widened to `core_skills/`). ADR-0086 (the registration seam this preserves), ADR-0088 (the same mechanism at a different site), ADR-0033 (the lazy-import discipline).
