# ADR-0096 — The agent barrel resolves lazily, and import safety is asserted per module

**Status:** Accepted

**Context.** A package `__init__.py` runs before any of its submodules. An eager re-export there guarantees that everything the exported names transitively reach loads whenever *anything* under the package is imported.

Four eager re-exports in `zrb/llm/agent/__init__.py`, plus an `agent/hook_agent.py` import for its registration side effect, put `common.py`, `run/runner.py` and `summarizer.py` — and through them most of `zrb.llm` — in the import closure of every module under `zrb.llm.agent`. Over the module graph (`if TYPE_CHECKING:` blocks excluded) that yields a strongly connected component of 87 modules: 21 in `llm.tool`, 21 in `llm.ui`, 12 in `llm.agent`, 8 in `llm.task`, plus `runner.chat` and `runner.cli`. Deferring each barrel in isolation locates the effect in that one file:

| barrel deferred | max SCC |
| --- | --- |
| *(none)* | 87 |
| `zrb.llm.agent` | **23** |
| `zrb.llm.ui` | 82 |
| `zrb.llm.summarizer` | 84 |
| `zrb.llm.tool` | 87 |
| any other | 87 |

An isolated-import check parametrized over packages cannot coexist with a deferred barrel. Importing each of 27 packages with its parents stubbed and nothing deeper leaves the tree's other 419 modules reachable only through whatever their barrel re-exports, so deferring one narrows the check with no visible failure — `zrb.llm.tool`'s docstring records that trade, and the eager import there, not the exported names, is what the check relies on.

**Decision.** The isolated-import check parametrizes over modules: every `*.py` under `src/zrb` whose path parts are identifier-legal, 417 targets, each imported in its own subprocess with its parents stubbed. The filter admits only names an `import` statement can spell, which excludes the skill tool scripts under `llm_plugin/*_skills/<skill>/tools/`. No barrel carries import safety for anything but itself.

`zrb/llm/agent/__init__.py` resolves its four names through PEP 562 `__getattr__`, caching each into `globals()`, with an `if TYPE_CHECKING:` mirror so pyright still sees them. `hook_agent`'s registration lives in that `__getattr__`, installing the `HookType.AGENT` builder on first use of an agent name — always ahead of a hook manager reading the registry, since every entry point (`LLMTask`, `LLMChatTask`, `SubAgentManager`) resolves one of the four while building its agent.

`from zrb.llm.agent import X` is an attribute access on the package, which is what `__getattr__` answers, so the barrel's public API is identical whether it resolves eagerly or lazily.

**Consequences.** The largest strongly connected component in the tree is 23 modules, which is also the total sitting in any cycle. `zrb.llm.agent`'s eager import closure is one module — itself. The isolated-import check covers 417 modules, at 392 subprocess tests and roughly 24s wall under `-n auto`.

The gain is structural rather than latency: `import zrb` stays at 0.22s, because `zrb.builtin` reaches the same modules by another route.

Each of the four names costs a dict lookup and one `importlib` call on first access. The price is legibility: `_SOURCES` is the export table, so a reader asking what the package exports reads a dict rather than a list of imports.

The `# lazy: circular` allowlist is empty, and among the 296 `# lazy:` tags every one that mentions a cycle says "not a cycle, verified empirically". The rest defer third-party or transitive weight, which is a question about load time rather than about the import graph's shape.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| Defer every barrel | Nothing else moves the number: `zrb.llm.tool` is worth 0, `zrb.llm.ui` 5. Both are documented user-facing import surfaces (`docs/llm/llm-custom-ui.md`, `examples/chat-sse`, `examples/chat-telegram`). |
| Trim what the agent barrel exports | All four names have callers — 14 sites, including `llm_task.py`, `tool/code.py`, `builtin/llm/please.py`. Resolution time is the problem, not the export list. |
| Drop the barrel; make callers deep-import | Reaches the same structure at the cost of every call site and doc example, for no gain over deferring. |
| Keep the barrel eager | Sound only while the isolated-import check is package-level, where the eager import is what drags the package's modules into the check. A per-module check removes that dependency. |
| Register `hook_agent` from `hook/agent_hook_registry.py` | Inverts ADR-0086's seam: the registry is a leaf that knows nothing about the agent package, and importing one puts it back in the cycle it exists to break. |

**Where it lives.** `src/zrb/llm/agent/__init__.py`, `test/architecture/test_circular_import_allowlist.py` (`_all_modules`, `test_every_module_imports_with_its_parents_stubbed`), `.coveragerc` (the skill-tool-script omit covers `core_skills/` as well as `skills/`). ADR-0086 (the registration seam this preserves), ADR-0088 (the same mechanism at a different site), ADR-0033 (the lazy-import discipline).
