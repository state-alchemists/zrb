# ADR-0064 — `Shell` is the execution tool, `Bash` is an alias, and background is a flag

**Status:** Accepted

**Context.** The shell tool was named `Bash`, which is a Claude/ChatGPT-shaped
name: the model's strong prior is a Bourne-again shell on Linux, while the tool
actually runs whatever the host shell is — including PowerShell or cmd. The name
also carried no distinction between foreground and background execution.

An intermediate design split background execution into its own tool,
`ShellBackground`, on the reasoning that "call this, get a handle, call that to
poll" cannot be expressed as one tool. That reasoning conflates *launch* with
*poll*: only the poll step needs a separate tool.

**Decision.** One implementation, two names, one flag.

- **`Shell`** is the primary tool — `command`, `cwd`, `timeout`, truncation
  parameters — streaming stdout and stderr live and returning truncated output.
  The generic name works regardless of the host shell.
- **`Bash`** is a thin alias re-exporting the same implementation under
  `__name__ = "Bash"`. The model sees two tools resolving to one implementation,
  so a conversation that already called `Bash` keeps working.
- **`background: bool = False`** (plus an optional `description`) short-circuits
  to the background registry and returns a handle immediately, with no timeout
  and no foreground streaming. `MonitorProcess(handle)` polls, waits or kills
  (ADR-0067).

**Consequences.** The naming matches what the tool does on any host OS, existing
conversations keep working, and there is one fewer tool name to disambiguate.
Background launches now flow through the same command-validation approval path
as any other shell call, rather than a blanket auto-approval on a separate tool.
Costs: the model sees `Bash` and `Shell` as two tools that do the same thing,
which can produce redundant choices; and a boolean flag is selected marginally
less reliably than a distinct tool name — accepted as the symmetric counterpart
to the same trade in ADR-0066.

**Alternatives rejected.** *Rename `Bash` in place* — breaks a session
mid-conversation: the model's prior turn mentioned `Bash` and the next gets an
unknown-tool error. *Keep `Bash` as the only name* — the OS mismatch persists.
*Keep `ShellBackground` as a separate tool* — redundant surface, and the
argument for it does not hold for the launch step. *One tool that also polls* —
the poll genuinely needs its own tool, which is why `MonitorProcess` stays.

**Where it lives.** `src/zrb/llm/tool/shell.py`, `src/zrb/llm/tool/bash.py`,
`src/zrb/llm/tool/shell_background.py` (registry and `MonitorProcess`).
