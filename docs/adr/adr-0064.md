# ADR-0064 — A tool's advertised options are filtered by the active permission policy

**Status:** Accepted

**Context.** The delegate tool advertises the available agents in its docstring, but a permission policy can forbid delegating to some of them — leaving the model offered options it cannot use, and a wasted turn discovering that.

**Decision.** The agent roster is built per run — the tool factories already rebuild each turn — and filtered by the active policy. With no policy, the roster is shown exactly as it is, up to the `LLM_MAX_AGENTS_IN_ROSTER` cap; overflow is truncated with a pointer to `SearchAgent`, which is registered on the same delegate-tool axis as `DelegateToAgent` so it is always available to find an agent the roster no longer names.

**Consequences.** What is advertised matches what is permitted, at zero cost when no policy is set. The cost is a small coupling from the delegate tool to the permission module.

**Alternatives rejected.** *A static catalogue* — goes stale as agents are added or restricted. *Suppress the whole list whenever any policy is set* — loses the roster the model needs to choose an agent. *No filtering* — the reported confusion.

**Where it lives.** `src/zrb/llm/tool/delegate.py` (`_delegatable_agents`).
