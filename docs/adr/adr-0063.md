# ADR-0063 — Plan mode is a permission preset, not a separate execution path

**Status:** Accepted

**Context.** "Investigate before you change" was prose in the prompt and
nothing prevented an edit during discovery.

**Decision.** Plan mode is a preset `PermissionPolicy` — READ, NETWORK and META
allowed; EDIT, EXECUTE and DELEGATE denied; unknown denied — selected by the
`current_agent_mode` ContextVar, with `EnterPlanMode` and `ExitPlanMode` tools
(tagged `META`, so always reachable) and a System Context line while active.
The same execution gate as ADR-0061 enforces the denials. The default mode is a
no-op.

**Consequences.** Read-only discovery is enforced rather than requested, the
model or a CLI flag can toggle it, and a sub-agent cannot mutate on behalf of a
plan-mode parent because DELEGATE is denied. The cost is that the shell is
dual-use and therefore conservatively denied, so a read-only `ls` needs the
file tools instead.

**Alternatives rejected.** *A hardcoded read-only mode in the runner* — no
per-tool overrides, and a second enforcement path to keep in sync with the
permission gate. *Require the user to write permission rules each time* —
verbose for a mode people toggle constantly. *No toggle tools* — the model
cannot enter or leave discovery without restarting the session.

**Where it lives.** `src/zrb/llm/permission/policy.py` (`PLAN_MODE_POLICY`),
`src/zrb/llm/tool/plan_mode.py`, `src/zrb/llm/prompt/system_context.py`.
