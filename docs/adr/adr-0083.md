# ADR-0083 — Delegated sub-agent sessions: persisted, listed, resumable, and swappable in place

**Status:** Accepted

**Context.** opencode's `task` tool spawns a durable, parent-linked child `Session` a user can navigate into, list, and keep chatting with. zrb's `DelegateToAgent`/`DelegateToAgentBackground` (ADR-0068/0069) had no equivalent: `_run_agent_task` calls `run_agent(..., message_history=[])` and the result lives only in the returned string — the transcript is discarded, nothing is addressable or resumable.

opencode's model does not port directly. Its sessions are SQLite rows with a `parent_id` column and one uniform session-viewing route component. zrb's conversations are flat JSON files under `LLM_HISTORY_DIR` (`FileHistoryManager`); the web runner drives every session through one shared `LLMChatTask` reconfigured per message (`chat_session_runner.py`); the CLI TUI drives a single `LLMTask` for the life of the process. A parent/child database has no home here, but a naming convention and the existing per-session config-swap pattern do. The work is scoped as five independently shippable phases.

**Decision.**

**Phase A — persist the transcript.** For every completed delegation, unconditionally, `_run_agent_task` (`delegate.py`) saves the sub-agent's message history through `FileHistoryManager` as `{parent_session}-sub-{agent_name}-{agent_id}` (`format_delegated_session_name`, `llm/util/subagent_session_naming.py`).

- Transcripts live in `LLM_HISTORY_DIR/subagent/{agent_type}/`, apart from main-agent conversations (flat in the history root), so listing, backup and pruning never mix the two. Delegated files written before this layout stay readable flat in the root as a fallback, never auto-migrated.
- The name is appended to the tool's result string, so it is discoverable immediately.
- Persistence failures are logged and never break delegation, matching `_fire_subagent_hook`.
- There is no config gate. Two bounds make always-on safe: no backup is written for a session never resaved (`write_backup=False`), and `_prune_old_subagent_history` deletes the oldest files past `LLM_SUBAGENT_HISTORY_RETAIN` (default 50, global across agent types) after every write.

**Phase B — listable at zero new storage.** `ChatSessionManager._session_listing()` (`runner/chat/chat_session_manager.py`) already groups history files by base name; `parse_delegated_session` (same naming module) recognizes Phase A's shape and adds `parent_session_id`/`agent_name` to each entry (`None` for an ordinary session). The check applies only to history-file-only (non-active) entries, so an active session whose name happens to match is never misclassified. `chat_api_route.py` needs no change: it forwards `get_sessions()`'s dicts verbatim, so list/attach/message endpoints work for delegated transcripts as-is.

**Phase C — resume as the sub-agent, not the main agent.** `SubAgentManager.create_agent`'s tool/model/prompt resolution is a public `resolve_agent_build`, shared by three callers so they cannot drift. `SubAgentManager.create_llm_chat_task(name)` reuses it to build a real `LLMChatTask` — the same system prompt, tools (still delegate-tool-free) and model as the raw pydantic-ai `Agent` from `create_agent`, wrapped in the `Task` type the web runner's `.async_run(session=...)`/`.history_manager`/`.ui_factories` contract needs. `chat_api_route.py`'s `stream_chat` picks the driving task via `_resolve_llm_chat_task_for_session`: a delegated `session_id` resumes via `create_llm_chat_task`, never silently falling back to the shared main task. It returns `None` (surfaced as a named error, not a crash) for a definition built from `agent_instance`/`agent_factory`, since a pre-built `Agent` has no system_prompt/tools/model triple to re-derive.

**Phase D — the CLI TUI resumes in place.**

- **Session-scoped activity registry.** `agent_activity_registry` (`llm/agent/activity.py`) was a flat dict, which bleeds across sessions in a multi-session process like the web runner. Every entry (`start`/`update`/`finish`/`active`/`snapshot`/`clear`) is keyed by `session_id` (default `""`, the single-session CLI case, so existing callers are unchanged), threaded through `BufferedUI` and `_run_agent_task` via `get_current_tool_session()`. `finish()` empties an agent from its session's bucket but not the bucket, so `ChatSessionManager.remove_session()` calls `agent_activity_registry.clear(session_id=...)` — otherwise a long-running web process keeps one empty bucket per session_id ever seen.
- **`/load` swaps persona.** `/load <name>` (`llm/ui/base/conversation_commands.py`) already replayed any history file; it now also swaps the persona driving new messages when `name` matches the delegated shape, and restores the main persona when loading an ordinary name — one symmetric verb, no new command. The swap mutates the CLI's single `LLMTask` in place (`ui.llm_task.tools`, `.toolsets`, `.prompt_manager`, plus `ui.model`), because the UI holds a fixed reference to it. This adds `tools`/`toolsets`/`prompt_manager` setters to `LLMTaskBuilding`, and records the original config once, on first swap, so `_restore_main_persona` never restores an intermediate sub-agent's config as the main one.
- **Status bar.** Shows `🎭 Sub-agent: <name>` while swapped, absent otherwise — the same collapse-when-idle posture as the activity panel, and the cue Claude Code/opencode give in their session footer.

**Phase E — cancelled-then-continued sub-agents report back.** A sub-agent the user cancels (Esc while viewing it in the TUI) and then keeps chatting with runs its follow-up turns only inside its own live view (`live_session.py`'s `_continue_live_session`); the main agent heard only `"Cancelled by user"`. When such a session ends naturally, the continuation's latest response text — bare, nothing added — goes to the main agent as its next turn through a new `submit_message` channel on the parent UI: steered into the live main turn if one is in flight (ADR-0078), otherwise queued on the main `MessageQueue`. A sticky `notify_parent_on_end` flag set by `cancel()` limits this to cancel-then-continue sessions; continuations of a normally finished delegation do not report (their result already reached the main agent). Cancelling again suppresses the report, as does a history with no assistant reply; delivery is best-effort.

**Consequences.**

- A delegated transcript is inspectable, listable and — via the web API and `/load` alike — resumable as that sub-agent, closing zrb's largest delegation gap versus opencode. The naming convention is the only new index: no table or registry, so Phase B cost only a regex.
- Every delegation writes a history file, even when nobody will read it — bounded by `LLM_SUBAGENT_HISTORY_RETAIN`, traded for always-resumable work.
- Name parsing is best-effort: an agent or session name containing the literal `-sub-` can misparse (acceptable for a listing feature).
- The `LLMTaskBuilding` setters are new surface — additive and low-risk, mirroring the `history_manager`/`approval_channel` setters in the same file.
- Phase E can start a main-agent turn the user did not type — the requested payoff, at the cost of an occasional unsolicited response.
- **Explicit boundary, not a rejection:** the web runner's serialization ceiling is untouched. `run_chat_session` acquires `ChatSessionManager.task_lock` — one global lock, not per task — for every message, so a resumed delegated session, though it has its own `LLMChatTask`, still serializes against ordinary sessions; only its post-lock wiring differs. Scoping the lock per task instance is a separate refactor.

**Alternatives rejected.**

| Alternative | Why rejected |
| --- | --- |
| A real session-tree store (opencode's model) | zrb's conversations are plain JSON files with no row-based session table to extend; building one for this would dwarf the feature. |
| A primary/subagent `mode` on `SubAgentDefinition` (opencode's `mode: primary \| subagent \| all`) | Would let any sub-agent be driven as a top-level chat (the `--agent` CLI-flag idea); not built, since resuming a specific delegated session needs only "which persona does this session use", not a general primary-agent concept. |
| A separate `/resume-subagent <name>` command | A second verb for what the user sees as the same action ("switch what I'm looking at"); `/load` already switches sessions. |
| Rebuild a new `LLMTask` for the CLI swap, like the web path's `create_llm_chat_task` | The CLI's `BaseUI` holds one fixed `_llm_task` reference for the process lifetime; replacing it means re-wiring every place it is threaded through, while in-place mutation reuses the mechanism `/model` established. |
| Gate persistence behind an opt-in flag (`CFG.LLM_ENABLE_SUBAGENT_HISTORY`, off by default) | Without a cap, every delegation grew `LLM_HISTORY_DIR` with never-reused names, so opt-in kept growth contained. With `LLM_SUBAGENT_HISTORY_RETAIN` pruning, always-on is strictly more useful at bounded cost, with one less knob. |
| Auto-migrate legacy flat delegated files into `subagent/{agent_type}/` | Moves files under the user's feet and writes to disk as a side effect of reading; the read fallback needs no writes. |
| Defer the Phase E report until the user exits the sub-agent view | The report belongs in the main transcript and the user asked for immediate notification, so it is delivered on natural end regardless of view; a second cancel is the escape hatch. |
| Wrap the Phase E report with context (source sub-agent, transcript name) | Bare, the main agent treats it like any follow-up to act on, not a meta-note about a sub-agent. |

**Where it lives.**

- Naming: `src/zrb/llm/util/subagent_session_naming.py` (convention and `subagent/{agent_type}/` layout).
- Phase A/B: `src/zrb/llm/tool/delegate.py` (`persist_subagent_history`/`_prune_old_subagent_history`), `src/zrb/llm/history_manager/file_history_manager.py` (subagent-aware path resolution, backups, rotation, legacy fallback, search), `src/zrb/config/mixins/llm_content.py` (`LLM_SUBAGENT_HISTORY_RETAIN`), `src/zrb/runner/chat/chat_session_manager.py` (`_session_listing`; `remove_session`'s registry teardown, Phase D).
- Phase C: `src/zrb/llm/agent/subagent/manager.py` (`resolve_agent_build`, `create_llm_chat_task`), `src/zrb/runner/chat/chat_api_route.py` (`_resolve_llm_chat_task_for_session`).
- Phase D: `src/zrb/llm/agent/activity.py`, `src/zrb/llm/ui/buffered_ui.py` and `src/zrb/llm/tool/delegate.py`/`delegate_background.py` (session-scoped activity wiring; `buffered_ui.parent_ui` also serves Phase E), `src/zrb/llm/task/building.py` (setters), `src/zrb/llm/ui/base/conversation_commands.py` (persona swap on `/load`), `src/zrb/llm/ui/default/output.py` (status-bar indicator).
- Phase E: `src/zrb/llm/agent/subagent/live_session.py` (trigger and latest-response extraction), `src/zrb/llm/ui/base/ui.py` and `src/zrb/llm/ui/multi_ui.py` (`submit_message`).
