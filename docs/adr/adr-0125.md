# ADR-0125 — pydantic-ai's typed model errors answer first, and zrb's classifier answers for the rest

**Status:** Accepted

**Context.** zrb classifies provider failures in `error_classifier.py`: status code first, then keyword lists over the exception's text. It has to answer three questions per failure — is this retryable, is it permanent, and which of Claude Code's `StopFailure` tokens does it become — and it predates any of that being available from pydantic-ai.

From 2.55 to 2.61 pydantic-ai added a typed taxonomy of its own, decided where the provider answer is received: `ModelRateLimitError`, `ModelQuotaExceededError`, `ModelUnavailableError`/`ModelOverloadedError`, `ModelServerError`, `ModelConnectionError`/`ModelTimeoutError`, `ModelContextWindowExceededError` and `ModelHTTPError`. The classification is not an Anthropic-side convenience: `_model_errors.openai_compatible_category` reads `context_length_exceeded` and the wording OpenRouter, vLLM and Groq use, `bedrock_code_category` maps `ValidationException` and `ThrottlingException`, and `google_status_category` maps `RESOURCE_EXHAUSTED` and `INVALID_ARGUMENT`. `ModelHTTPError.for_category` raises an error that is both the HTTP error and its category.

That surfaced a real defect in zrb's version. `is_retryable_error` returns true for any 429, and an exhausted quota or spend limit arrives as a 429 — so zrb retried a wall, up to the retry budget, on every run against an account with no credit left. The status code cannot distinguish the two; the type can.

The same window deprecated `RetryPromptPart` in favour of `ToolReturnPart(outcome='retried')` and `RetryFeedbackPart`, which matters beyond the warning: a history round-trip through pydantic-ai's validation returns the new part, so `isinstance(part, RetryPromptPart)` no longer holds for history zrb itself saved.

**Decision.**

1. **Consult the typed error first, keep the heuristics as the fallback.** `classify_error_type`, `is_retryable_error`, `is_permanent_error` and `is_prompt_too_long_error` check `isinstance` against the typed classes before reading a status code or a keyword. The status and keyword branches stay: they cover a raw SDK exception, a gateway's own wording, and a provider path upstream has not classified yet.

2. **An exhausted quota is permanent.** `ModelQuotaExceededError` is not retried and counts as permanent, which is the one behaviour change here. `classify_error_type` still reports it as `rate_limit`: the token vocabulary mirrors Claude Code's, and adding one would break that contract for a distinction the retry path already makes.

3. **The token vocabulary does not grow.** Type-checked answers reuse the existing tokens — `context_length`, `overloaded`, `server_error`, `rate_limit`. A new token would flow into the `StopFailure` hook payload, where zrb says it speaks Claude Code's vocabulary.

4. **Retry parts move to the two parts that replaced them.** A retry that answers a tool call is that call's `ToolReturnPart` with `outcome='retried'`; one that answers no call is `RetryFeedbackPart`. `history_utils` decides the wording from the outcome rather than the class, and the deprecated class is gone from `src/`, including the `zrb.llm.agent.types` re-export.

5. **Readers dispatch on `part_kind`, and accept both.** The history formatter, the replay path and the history manager's content cleaner branch on the part's own kind string, so adding `retry-feedback` alongside `retry-prompt` renders history written before 2.60 without importing the deprecated class.

6. **The pins move together.** `pydantic-ai-slim>=2.61.0,<2.62.0` and `openai>=3.26.0`. We take `pydantic-ai-slim[mcp]`, not its `openai` extra, so the resolver never enforced the extra's floor: `openai` stayed at 3.19.0 across a pydantic-ai major-and-a-half, and `OpenAIChatModel` is exactly the code that extra's floor describes.

**Consequences.** Classification is more accurate for every provider zrb supports, and a dead account stops burning the retry budget. The classifier is now two layers rather than one, which is the cost: a typed branch and an untyped branch have to be kept in step, and the typed branch is only as good as upstream's coverage.

Removing `RetryPromptPart` from `zrb.llm.agent.types` is a breaking change for anyone importing it from there; the upstream class is deprecated and will be removed in v3, so the re-export had a short life either way.

**Alternatives rejected.**

- *Delete zrb's classifier and catch only typed errors* — loses three things it does that upstream does not: Claude Code's token vocabulary, the invalid-tool-name and missing-`reasoning_content` detections that exist because specific providers misbehave, and the credential hint that names `CFG.ENV_PREFIX`. It would also classify nothing for a raw SDK exception.
- *Keep the status-code-only classifier* — cannot tell an exhausted quota from a rate limit, which is the bug above.
- *Add a `quota_exceeded` token* — the token is a `StopFailure` hook contract, and the retry path is where the distinction actually changes behaviour.
- *Adopt `sanitize_messages` for zrb's history repair* — a different job. `sanitize_messages` strips parts that are unsafe to honour from *untrusted input*; `history_utils` converts a structurally broken history into one the provider accepts (orphaned returns, tool-less retries, empty content). Adopting it would not repair anything zrb's version repairs.
- *Adopt `ModelSettings['request_timeout']` and `max_retries` instead of the retry loop* — the loop's job is not only timing: on a context overflow it prunes history and retries with less input, and it reports each attempt. `request_timeout` covers one request's attempts and cannot decide to shrink the conversation.

**Where it lives.** `src/zrb/llm/agent/run/error_classifier.py` (`_typed_model_errors`, `_is_typed_model_error`, `_classify_typed_model_error`, `_classify_untyped_error`), `src/zrb/llm/agent/run/history_utils.py` (`_normalize_for_request`, `_tool_return_to_text`), `src/zrb/llm/util/history_formatter.py`, `src/zrb/llm/ui/base/replay.py`, `src/zrb/llm/history_manager/file_history_manager.py`, `src/zrb/llm/message.py`, `pyproject.toml`, `test/llm/agent/run/test_error_classifier.py`. See ADR-0039 for the earlier stream-error classification this extends.
