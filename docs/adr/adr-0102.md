# ADR-0102 — Two prompt rules move into tool policies

**Status:** Accepted (applies ADR-0098's ladder)

**Context.** ADR-0098 sorts every rule by what can make it true: the runtime
first, then the tool's docstring, then the prompt, then a skill. Two rules were
sitting in the prompt that the runtime can enforce, and a benchmark run showed
both being ignored by models that had read them.

**1. Overwriting a file the model has not seen since it last changed.**

`Edit` carries `old_text`, so it fails loudly when the model's memory has
drifted. `Write` carries nothing — it replaces the whole file on the strength of
the model's recollection. A trial read `worker.py`, edited it, received a
`[DIAGNOSTIC]` reporting three errors, and answered by rewriting the file whole
from memory. The rewrite flipped the worker's empty-queue exit from `return` to
`continue`, shipping an infinite loop; the validator subprocess hung and the
cell was recorded as an error.

Note what a plain read-before-write precondition — the rule opencode and Claude
Code both enforce — would have done here: nothing. The model *had* read the
file. What was missing was not a read but a **current** one.

Worse, `post_write_check`'s own `[SYSTEM SUGGESTION]` steered into it: on a
second failing edit it said "stop patching it — rewrite the whole file with
`Write` instead", without saying to re-read first.

**2. Repeating an attempt that has stopped producing new evidence.**

`workflow`'s Recovery ladder says "By the third, change what you are testing — or
stop and report what you cannot get past." One trial spent 89 tool calls across
**four files** — 32 shell runs, 45 writes — re-running the same simulation until
its 600s budget expired, having written mid-run that "the changes made to the
logic did not yield the intended results" and then continuing anyway. It is the
clearest single rule violation in the run, from a model that had the rule in
context the whole time.

**Decision.** Add two tool policies, registered in `apply_common_tools` beside
`bash_safe_command_policy`.

`write_freshness_policy` tracks a per-path freshness bit
(`zrb.llm.tool.file_freshness`) across three transitions — `Read` → fresh,
`Write` → fresh (the model authored every byte), `Edit` → stale — and refuses a
`Write` onto an **existing** file that is not fresh. Deliberately narrow: `Edit`
is never gated, creating a new file is never gated, and recording happens after
the downstream chain so a denied call grants nothing. The denial names the one
action that unblocks it.

`repetition_policy` counts byte-identical `Shell`/`Bash` invocations and, on the
`LLM_REPEATED_ATTEMPT_THRESHOLD`-th (default 3, matching the prose ladder),
appends a `[SYSTEM SUGGESTION]` to the result. It never denies — an agent
legitimately re-runs a test suite many times, and blocking that would be worse
than the loop it prevents — and it fires once per signature, not on every
subsequent call.

`post_write_check`'s suggestion is corrected to require the re-read before the
whole-file rewrite it recommends.

**Consequences.**

- The failure mode that produced the shipped regression is now unreachable
  rather than discouraged.
- A model that has genuinely lost track of a file pays one extra `Read`. That is
  the intended cost.
- The Recovery observation arrives *during* the loop, on the result the model is
  about to read, instead of in a rule it read hundreds of calls earlier.
- Both policies attach only where `add_tool_policy` exists. Programmatic
  `LLMTask` and `SubAgentManager` hosts have no approval channel and are
  skipped, exactly as `bash_safe_command_policy` already is.
- `repetition_policy` mutates a string tool result. Any non-string result is
  returned untouched.

**Alternatives considered.**

- *Strengthen the prompt instead.* Both rules are already in the prompt, and
  `gpt-4o-mini` resolves to the `mini` profile, so it also received the worked
  demonstrations ("Do it, don't announce it", "'Almost done' is not done"). More
  text was not the missing ingredient.
- *Gate `Edit` too.* `old_text` matching already enforces currency; a
  precondition there is friction without cover.
- *Deny the repeated command rather than annotate it.* Rejected. There is no
  reliable way to tell a diagnostic re-run from a stuck loop, and a false denial
  costs more than a false nudge.
- *Fuzzy-match "the same attempt".* Rejected. A model that varies its command is
  changing what it tests, which is precisely the behaviour being asked for, so
  only a byte-identical re-run counts.
- *Inject via `live_context`.* It renders once per user turn. A non-interactive
  run is a single turn, so it cannot reach a loop mid-flight; a tool result can.

**Evidence.** `llm-challenges` run of 2026-08-05, 156 cells. `bug-fix/trial-3`
(gpt-4o-mini): `Read worker.py` → `Edit worker.py` → `Write worker.py`, the
write reverting `return` to `continue`. `integration-bug/trial-2` (gpt-4o-mini):
89 calls, 4 distinct paths, 32 `Shell`, timeout at 600s.
