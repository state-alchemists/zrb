# ADR-0110 — Fleet tasks run through a label-selected `Host`/`Target` inventory, not a new task class

**Status:** Accepted

**Context.** `CmdTask` runs on one machine (`remote_host` is a single value). Admin questions — "what is the hostname of every kubernetes node", "can every node reach nexus, dockerhub and gitlab" — span many. `HttpCheck`/`TcpCheck` look like the answer to the second but are readiness checks: they poll until they pass, from the machine running zrb, not from the node.

**Decision.**

- **Two frozen dataclasses and two name-keyed `Inventory` instances** (`zrb.remote`): `Host` carries `CmdTask`'s `remote_*`, `cwd`, `shell` and `labels` (`remote_host=None` is localhost, which can be labelled like any host); `Target` carries host, port, `tcp`/`http`, scheme, path or `url`, and `labels`. Users register them in `zrb_init.py` with `host_inventory.add(...)` / `target_inventory.add(...)` (R5/R6: name-keyed collections take `add_X`). `remote_password` is excluded from `repr`.
- **Selection is by label**: `--host-labels` and `--target-labels` are `OptionInput`s whose choices come from the inventory (`Inventory.get_choices`, names and labels, read when the prompt or web form is built, so labels registered in `zrb_init.py` are offered). An item is chosen when its name or any label matches; an empty input selects everything. `Inventory.select` takes several labels (any-of), but `OptionInput` is single-select, so one run names one label.
- **Two builtin tasks, `zrb remote run` and `zrb remote check`**, not a task type. Both fan out with `asyncio.gather` under a semaphore (`concurrency`), run each host through `run_command` (locally, or over `get_remote_cmd_script`), and return a table: rendered by rich (`--format table`), raw markdown (`--format markdown`), plain CSV (`--format csv`), or JSON of the raw statuses (`--format json`) for scripts. Every format names each host's `remote_host` and each target's address (URL credentials redacted); markdown, CSV and JSON are also copied to the clipboard, and CSV neutralizes formula-looking cells because command output is untrusted.
- **`check` makes one connection per host that probes every selected target**, so N hosts × M targets cost N SSH sessions. The probe is POSIX `sh` — TCP through bash's `/dev/tcp` (else `nc`), HTTP through `curl` — and a host lacking the tool reports `n/a`. A failed probe is named by what the tool said: `refused` (the host answered, nothing listens), `timeout` (no answer, usually a firewall), `dns` (the name did not resolve), else `fail`; the words are read from the tool's error text and exit code, so an unfamiliar message degrades to `fail`. No Python is assumed on the host. The probe, and the `ssh` line for any remote host, are POSIX, so they always start under `sh` (`posix_only`); `Host.shell` applies only to a local `remote run` command. For HTTP any response counts as connected and the status code is shown.

**Consequences.**

- The per-host command and probe scripts reuse `CmdTask`'s SSH plumbing but not `CmdTask` itself, so a run prints one table rather than interleaved streams from every host.
- A host that is unreachable, times out or fails shows `❌`; its probe cells show `error`.
- The inventory is process-global state filled by `zrb_init.py`; two registrations of one name keep the later.

**Alternatives rejected.**

- *A task class of its own (`FleetCmdTask`)* — a fleet run is `run_on_hosts` under a semaphore plus a table, not a new lifecycle. Two `make_task` builtins cost less than a task type every later fleet task would have to subclass, and host selection, formats and concurrency stay ordinary inputs.
- *`HttpCheck`/`TcpCheck` for the reachability question* — they are readiness checks: they poll until they pass, from the machine running zrb. "Can every node reach nexus" is answered only by a probe on the node itself, and the answer wanted is a failure reported, not a wait for it to clear.
- *A Python probe pushed to each host* — it would assume an interpreter on the host. The probe is POSIX `sh` for that reason, and a host missing `bash`, `nc` or `curl` reports `n/a` for that target instead of a connection failure.
- *One `ssh` session per host-and-target pair* — it costs N × M sessions where N would do. `check` connects once per host and probes every selected target inside that one script.

**Where it lives.** `src/zrb/remote/inventory.py` (`Host`, `Target`, `Inventory.add`, `Inventory.get_choices`, `Inventory.select`, `host_inventory`, `target_inventory`), `src/zrb/remote/execution.py` (`run_on_hosts`, `_run_on_host`, `create_probe_script`, `parse_probe_output`), `src/zrb/remote/report.py` (`render_table`, `create_markdown_table`, `create_csv`), `src/zrb/builtin/remote.py` (`_host_labels_input`, `_select_hosts`, `_format`, `remote_run`, `remote_check`), `src/zrb/cmd/remote.py` (`get_remote_cmd_script`), `src/zrb/cmd/command.py` (`run_command`), `test/remote/test_inventory.py`, `test/remote/test_execution.py`, `test/builtin/test_remote.py`.
