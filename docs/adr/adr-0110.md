# ADR-0110 — Fleet tasks run through a label-selected `Host`/`Target` inventory, not a new task class

**Status:** Accepted

**Context.** `CmdTask` runs on one machine (`remote_host` is a single value). Admin questions — "what is the hostname of every kubernetes node", "can every node reach nexus, dockerhub and gitlab" — span many. `HttpCheck`/`TcpCheck` look like the answer to the second but are readiness checks: they poll until they pass, from the machine running zrb, not from the node.

**Decision.**

- **Two frozen dataclasses and two name-keyed `Inventory` instances** (`zrb.remote`): `Host` carries `CmdTask`'s `remote_*`, `cwd`, `shell` and `labels` (`remote_host=None` is localhost, which can be labelled like any host); `Target` carries host, port, `tcp`/`http`, scheme, path or `url`, and `labels`. Users register them in `zrb_init.py` with `host_inventory.add(...)` / `target_inventory.add(...)` (R5/R6: name-keyed collections take `add_X`). `remote_password` is excluded from `repr`.
- **Selection is by label**: `--host-labels` and `--target-labels` are `OptionInput`s whose choices come from the inventory (`Inventory.get_choices`, names and labels, read when the prompt or web form is built, so labels registered in `zrb_init.py` are offered). An item is chosen when its name or any label matches; an empty input selects everything. `Inventory.select` takes several labels (any-of), but `OptionInput` is single-select, so one run names one label.
- **Two builtin tasks, `zrb remote run` and `zrb remote check`**, not a task type. Both fan out with `asyncio.gather` under a semaphore (`concurrency`), run each host through `run_command` (locally, or over `get_remote_cmd_script`), and return a table: rendered by rich (`--format table`), raw markdown (`--format markdown`), or JSON of the raw statuses (`--format json`) for scripts.
- **`check` makes one connection per host that probes every selected target**, so N hosts × M targets cost N SSH sessions. The probe is POSIX `sh` — TCP through bash's `/dev/tcp` (else `nc`), HTTP through `curl` — and a host lacking the tool reports `n/a`. No Python is assumed on the host. The probe, and the `ssh` line for any remote host, are POSIX, so they always start under `sh` (`posix_only`); `Host.shell` applies only to a local `remote run` command. For HTTP any response counts as connected and the status code is shown.

**Consequences.**

- The per-host command and probe scripts reuse `CmdTask`'s SSH plumbing but not `CmdTask` itself, so a run prints one table rather than interleaved streams from every host.
- A host that is unreachable, times out or fails shows `❌`; its probe cells show `error`.
- The inventory is process-global state filled by `zrb_init.py`; two registrations of one name keep the later.
