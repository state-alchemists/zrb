# ADR-0010 — Hierarchical `zrb_init.py` discovery with explicit registration

**Status:** Accepted

**Context.** Tasks must be discoverable per project yet shareable across a directory tree, without magic that makes "why is this task here?" hard to answer.

**Decision.** zrb loads `zrb_init.py` files found from the cwd up to the home directory (configurable through `ZRB_INIT_FILE_NAME`, `ZRB_INIT_SCRIPTS`, `ZRB_INIT_MODULES`). A task becomes available only by explicit registration — `cli.add_task`, `group.add_task`, or `@make_task(group=...)` — never by name introspection.

**Consequences.** Parent-directory tasks cascade into subdirectories, so project and global layers compose; nothing runs unless someone registered it. The cost is that there is no zero-config auto-discovery.

**Alternatives rejected.** *Function-name introspection* — implicit, and an unrelated helper in the file becomes a command. *A dedicated task directory* — less flexible than walking the parent chain, and breaks the project/global layering.

**Where it lives.** `src/zrb/runner/cli.py`, `docs/core-concepts/tasks-and-lifecycle.md`, `docs/configuration/env-vars.md`.
