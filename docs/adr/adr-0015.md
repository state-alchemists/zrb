# ADR-0015 — An explicit task lifecycle state machine

**Status:** Accepted

**Context.** Fallback and successor routing, downstream gating and observability all need an unambiguous answer to "where is this task in its life?".

**Decision.** Track explicit states — started, ready, completed, skipped, failed, permanently_failed, terminated — with a timestamped history. Downstreams run only when their upstreams are completed or skipped.

**Consequences.** Transitions are deterministic, history is auditable, and fallback/successor routing is correct by construction. The cost is more bookkeeping than a couple of boolean flags.

**Alternatives rejected.** *Exception-driven control flow* — state gets lost in async stacks. *Boolean flags* — permit invalid combinations such as failed-and-completed. *Assume success* — runs successors after a failure.

**Where it lives.** `src/zrb/task_status/task_status.py`, `src/zrb/session/session.py` (`is_allowed_to_run`), `docs/core-concepts/tasks-and-lifecycle.md`.
