# ADR-0085 — Reserve the `Mixin` suffix for reusable mixins; single-host parts are named after their owner

**Status:** Accepted

**Context.** ADR-0060 decomposed `BaseUI` by mixin composition on a shared
`self`, and the same shape spread: `LLMChatTask`, `LLMTask`, the default `UI`,
`LSPServer`, `LSPManager`, `HookManager`, and `SubAgentManager` all grew
`*_mixin.py` siblings. The pattern is sound — the alternative (collaborator
objects) would change public constructors and break a test suite that couples
to instance internals — but the **naming** made it unreadable.

A static count of attributes each class reads off `self` but never assigns:

| class | reads-but-never-assigns |
| --- | --- |
| `ExecMixin` (chat) | 58 |
| `CommandsMixin` (BaseUI) | 35 |
| `RunnerMixin` (chat) | 22 |
| `PropertiesMixin` (BaseUI) | 17 |
| `BufferedOutputMixin` | 0 |

Everything above zero can only ever be mixed into exactly one host. Calling it
a "mixin" advertises reusability that does not exist and invites a reader to
look for other hosts. Meanwhile `BufferedOutputMixin` — genuinely reusable,
exported from `zrb.llm.ui`, documented for user subclasses — carried the same
suffix, so the suffix carried no information at all.

Three directories compounded it with path stutter: `hook/manager/manager.py`,
`lsp/manager/manager.py`, `agent/subagent/manager/manager.py` — an extra package
level whose only member of note was a same-named module.

**Decision.** Keep the composition mechanism from ADR-0060 unchanged. Change
only what things are called, so the name states the coupling:

1. **`Mixin` suffix is reserved for classes that are actually reusable** — they
   read no state they do not set, and any class may mix them in.
   `BufferedOutputMixin` keeps its name; the `CFG` mixins under
   `config/mixins/` keep theirs (each owns the attributes it exposes, per
   ADR-0021).
2. **A part with exactly one possible host is named `<Owner><Aspect>`**, in a
   file named for the aspect with no `_mixin` suffix and no leading underscore
   (a leading underscore would say "private module", which is a different and
   wrong claim — these are imported across modules).
3. **`X/manager/manager.py` packages flatten** to `X/manager.py` plus
   `X/manager_<aspect>.py`. Import paths are unaffected: `zrb.llm.hook.manager`
   resolves to a module instead of a package, so every existing
   `from zrb.llm.hook.manager import HookManager` keeps working.

Applied:

| was | now |
| --- | --- |
| `chat/{builder,runner,exec}_mixin.py::{Builder,Runner,Exec}Mixin` | `chat/{building,running,execution}.py::Chat{Building,Running,Execution}` |
| `task/{builder,history}_mixin.py::{Builder,History}Mixin` | `task/{building,history}.py::LLMTask{Building,History}` |
| `ui/base/*_mixin.py::*Mixin` | `ui/base/*.py::BaseUI*` |
| `ui/default/*_mixin.py::*Mixin` | `ui/default/*.py::UI*` |
| `lsp/server_operations.py::OperationsMixin` | `…::LSPServerOperations` |
| `{hook,lsp,agent/subagent}/manager/manager.py` | `…/manager.py` (+ `manager_*.py` parts) |

The state-declaration class introduced alongside this work (`chat/state.py::ChatState`)
already followed rule 2 and set the precedent.

**Consequences.**

- *Good.* `Mixin` in a class name is now a claim a reader can rely on: it means
  "reusable, brings its own state". There is exactly one such class in `llm/`.
- *Good.* `ChatExecution` cannot be mistaken for something reusable, so nobody
  tries; the host is in the name.
- *Good.* Two `BuilderMixin` classes (one for `LLMTask`, one for `LLMChatTask`)
  became `LLMTaskBuilding` and `ChatBuilding` — the collision that made
  grep-by-class-name ambiguous is gone.
- *Cost.* A wide rename touching ~45 files. Mitigated by the import paths being
  internal (`zrb.llm.ui.base.commands_mixin` was never a documented entry point)
  and by the three flattened `manager` paths resolving unchanged.
- *Cost.* Existing ADRs (0054, 0060, 0064, 0075, 0080, 0081, 0084) still quote
  the old filenames. Left as written — an ADR records what was decided then;
  this record is the forwarding pointer.
- *Neutral.* The coupling itself is unchanged. A part that reads 44 attributes
  off its host still reads 44; the name now says so instead of hiding it.
  Reducing that number is a separate decision.

**Alternatives rejected.**

- *Convert the parts into collaborator objects.* The honest fix, and the one
  `task/base/{execution,lifecycle,monitoring}.py` already uses (free functions
  taking `task` as the first argument). Rejected here for the same reason
  ADR-0060 rejected it: `BaseUI`/`LLMChatTask` constructors and internals are
  public surface, and the test suite reaches into them. Still the right target
  for `task/base`-style code written fresh.
- *Prefix the part modules with an underscore (`chat/_exec.py`).* Says
  "module-private", which is false — `task.py` imports them across the package
  boundary, and so do tests.
- *Leave the names alone and document the distinction in `AGENTS.md`.* A
  convention that contradicts the code teaches readers to distrust the
  convention. The same reasoning retired the unenforced "functions ≤ 30 lines"
  rule in the same pass.

**Evidence.**

- Rule 1 and the reusability test: `llm/ui/buffered_output_mixin.py` docstring
  shows a `TelegramUI(EventDrivenUI, BufferedOutputMixin)` host, and the class
  sets its own buffer state in `__init__`. [DOCUMENTED]
- Rule 2's precedent: `llm/task/chat/state.py` — "Sibling-*method* contracts stay
  in the mixin that calls them — this class owns state, not behaviour."
  [DOCUMENTED]
- Rule 3's safety: `zrb/__init__.py` imports `from zrb.llm.hook.manager import
  HookManager, hook_manager` and `from zrb.llm.agent.subagent.manager import
  SubAgentManager, sub_agent_manager` — unchanged by the flattening.
  [DOCUMENTED]
- Single-host coupling of the renamed parts: each carries a `TYPE_CHECKING`
  host-contract block naming the attributes its host must provide (e.g.
  `llm/lsp/server_operations.py`, `llm/ui/base/commands.py`). [DOCUMENTED]
- The attribute counts in the Context table are reproducible by walking each
  class's AST for `self.<name>` loads with no matching store. [INFERRED]
