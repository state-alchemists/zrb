# ADR-0123 — A send-now key moves a running Shell aside, so the message is read in the same turn

**Status:** Accepted, revised 2026-10-24 (a voice-first session may let a dictated message move the shell too, and a nested run shares its parent's signal; decisions 3 and 4).

**Context.** `Ctrl+G` already hands the queued messages to the live run (ADR-0078, ADR-0116): `send_queued_messages_now` calls `run_context.enqueue(...)`, and pydantic-ai delivers the message at the next model request. That makes the message *arrive* early — but the next model request is only assembled after the running tool call returns. A `Shell` call that is running a five-minute build is therefore still a five-minute wait for the user who pressed the key: the ladder delivers into a turn that will not ask anything until the command ends.

The reference harness treats this as part of the key, not as a separate feature. Claude Code's send-now moves "running shell commands and subagents that can move to the background" out of the way and reads the message in the same turn, and interrupts the turn only when there is nothing to move (`chat:sendNow`, v2.1.275+). Its *ordinary* queued message still never preempts: only the explicit key does that.

zrb already has the move itself. A command that outruns its own timeout is adopted by the background registry instead of being killed (ADR-0122's neighbour, `LLM_SHELL_TIMEOUT_BACKGROUND_SECONDS`), the registry keeps feeding the caller's captures so no output is lost, and `MonitorProcess` reads, waits on or kills it. What was missing is a way for the keypress — a UI task — to reach the tool call — a different task inside the run.

**Decision.**

1. **The signal belongs to a run, and it carries a generation.** `ShellCutSignal` lives in `zrb.llm.shell_cut`, is bound by the agent runner around `agent.run()` as a context variable (the same place the run's limiter is bound), and counts cuts rather than holding a flag. A shell reads `generation` when it starts waiting and is woken only by a cut **newer** than that, so a keypress during an earlier tool call cannot move a command that had not started yet — the failure a plain boolean would have, and the reason the signal is not a process-wide flag.

2. **The UI reaches it through the UI object, not through ambient state.** The keybinding handler runs in the UI's own task, where the run's context variables are not bound (`current_chat_session_id` is only visible inside the run task), so a per-session lookup from the UI side would silently miss. The runner publishes the signal beside `active_run_context` — the one object the handler already has — and `send_queued_messages_now` takes it as a parameter, which also keeps that module a pure function a test can call.

3. **Only an explicit send-now cuts, unless a voice-first session opts in.** The cut happens when the ladder is told to move the shell, there is a live run, and there is something to deliver. That permission is `may_interrupt` by default, but a separate `move_shell` argument can override it — cutting and interrupting are different acts, and the fallback that cancels a turn whose delivery failed must stay reserved for a caller that asked for it. Hands-free speech submits with `may_interrupt=False` and, only when `LLM_VOICE_MOVES_SHELL` is on, `move_shell=True`: a misheard word must not take a build out of the foreground, but a session that is worked hands-free has no key to press, so it can say yes once and get the same behaviour from its voice. The trigger passes that keyword **only** when the setting is on, so a custom UI that overrides `submit_message_now` with the older signature keeps receiving spoken messages. A turn suspended on a dialog has no shell holding it, so the dialog branch returns before the cut either way.

4. **A nested run shares its parent's signal.** A delegated sub-agent, and the helper runs behind `AnalyzeCode`, `WebFetch` and a multimodal description, all execute inside the turn the user is steering. `signal_for_run()` returns the parent's signal when there is one and mints one only at the top, so a `Shell` started inside a sub-agent is reachable by the same keypress. Minting a fresh signal per run — the first version — left those shells listening to a signal nothing ever cut.

5. **A cut and a timeout take the same exit.** On a cut the wait cancels the drain — whose own `finally` cancels the readers — and then adopts the process through the same registry call the timeout uses. One code path owns the pipes, the captures and the spill-file behaviour, so the guarantee that an adopted command keeps one complete overflow file cannot drift between the two triggers.

6. **What cannot move stays.** A `sleep` is a delay the caller wrote on purpose, and adoption can be turned off; neither has anywhere to move to, so the wait keeps going and the command is left alone. A cut is not a kill: the user asked for the turn, not for the work to be thrown away. The one case that still stops a command is its own timeout, unchanged.

7. **The report says which happened.** A moved command reports `(moved to background so the turn could continue)` rather than the timeout wording, and its suggestion tells the model to read the user's message first and not to run the command again. `_format_output` decides "the captures outlive this call" from `handle is not None` rather than from `timed_out and handle`: a cut moves a command without any timeout having expired.

**Consequences.** `Ctrl+G` now returns the turn within the time it takes the shell to hand its pipes over, instead of at the end of the running command, and the command keeps running under a handle the model can poll. The model sees a tool result that did not finish, which it must not interpret as failure — the report says so, and the live context lists the handle on every later turn. Two costs are real: a command that the user wanted to watch in the foreground is now in the background (readable and killable, but no longer streaming into the transcript), and a cut arriving while several commands run moves all of them, since each one is independently holding the turn. With `LLM_VOICE_MOVES_SHELL` on, the same holds for something said aloud, and a session that shares a microphone with other people should leave it off.

**Alternatives rejected.**

- *A process-wide cut flag* — two chat sessions in one process would move each other's commands.
- *Key the signal by `current_chat_session_id`* — the UI task cannot read it; the handler and the tool call are different tasks with different context, which is the whole problem.
- *Deliver the message into the blocked tool call* — no harness does this, and it would mean interrupting a call in progress rather than letting it finish somewhere else.
- *Kill the command on a cut* — the user asked for the turn, not for the work; the timeout already exists for "stop this".
- *Set a flag and clear it when consumed* — clearing is racy across concurrent waits, and a flag set before a command started would move it for no reason. The generation makes the question "was there a cut after I started?" instead.
- *Let voice pass `may_interrupt=True` to get the cut* — that flag also arms the fallback that cancels the turn when delivery fails, so a misheard word could stop the turn outright. Two behaviours, two flags.
- *Give a sub-agent its own signal* — the keypress means "this turn, now", and a sub-agent's shell is holding the same turn. A per-run signal made those shells unreachable.

**Where it lives.** `src/zrb/llm/shell_cut.py` (the signal, its context variable and `signal_for_run`), `src/zrb/llm/agent/run/runner.py` (bind, publish beside the run context, clear), `src/zrb/llm/ui/base/queue_delivery.py` (the cut, `move_shell`), `src/zrb/llm/ui/base/triggers.py` (`LLM_VOICE_MOVES_SHELL` reaching the ladder), `src/zrb/llm/ui/base/ui.py` and `src/zrb/llm/ui/multi_ui.py` (carry the signal and the permission to the ladder), `src/zrb/config/mixins/llm_limits.py` (the setting), `src/zrb/llm/tool/shell.py` (`_wait_for_exit_or_adopt`, `_can_adopt`, `_adopt_process`, the move reason), `test/llm/test_shell_cut.py`, `test/llm/tool/test_shell_cut_adopt.py`, `test/llm/ui/base/test_queue_delivery_cut.py`, `test/llm/ui/base/test_base_ui_shell_cut.py`, `test/llm/ui/base/test_base_ui_triggers.py`.
