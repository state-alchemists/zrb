# ADR-0033 — One Poetry-managed distribution with disciplined lazy imports

**Status:** Accepted

**Context.** zrb depends on many heavy, usually-optional packages — pydantic-ai, fastapi, playwright, anthropic, openai, boto3, chromadb. Importing them on every CLI invocation would make `zrb --help` slow for everyone.

**Decision.** Ship one Poetry-managed package (`pip install zrb`) with optional extras, and defer heavy imports to the code paths that need them. An in-function import must carry a `# lazy: <reason>` comment matching one of four accepted justifications: heavy third-party deferral, transitively heavy through an internal module, a named circular import, or a test patch seam. `flake8 src/zrb --select=F` runs in `./zrb-test.sh` and fails on unused or duplicate imports.

**Consequences.** CLI startup stays fast and optional capabilities cost nothing until used, from a single install. The cost is a discipline contributors must follow — and hoisting a lazy import silently re-introduces the slow load, which is why the reason must be written down at the import.

**Alternatives rejected.** *Namespace sub-packages* (`zrb-llm`, `zrb-web`) — install and discovery complexity for users, and cross-package version skew. *Eager imports everywhere* — startup bloat paid by every user for features most invocations never touch.

**Where it lives.** `pyproject.toml`, `AGENTS.md` (Imports), `# lazy:` comments throughout `src/zrb/`. `test/architecture/test_circular_import_allowlist.py` guards the circular-import category specifically (an exact-match allowlist of named cycles). `test/architecture/test_lazy_import_categories.py` guards all four categories together: every `# lazy:` comment in the tree must state a reason the test recognizes, and per-category counts are a reviewed ratchet, the same convention as the allowlist. That test folds call-frequency ("hot path") avoidance of an internal import under the transitively-heavy-through-an-internal-module category — it's the same "avoid paying this import's cost" concern, just keyed to how often the call site runs rather than how heavy the imported module is on its own.

An audit while adding that test found the circular-import allowlist had been vacuously passing: 17 comments in the tree gave a genuine circular-import justification in non-canonical wording (most commonly "zrb internal (heavy via transitive / circular)"), invisible to the allowlist's regex for the literal tag. Each was checked empirically — hoisting the import in a scratch copy and observing whether it actually raised an `ImportError` — rather than taken on the comment's word. Only 5 turned out to be real cycles (now tagged canonically and in the allowlist); the other 12 were mislabeled: 8 were plain transitively-heavy imports with no real cycle, and 4 (in `tool/web.py`) were test-patch-seam imports already justified by a shared comment one block above. All 12 were reworded to their real category rather than left tagged circular.
