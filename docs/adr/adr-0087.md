# ADR-0087 — `journal_mandate` owns the everyday write path; `core-journaling` owns structural work

**Status:** Accepted (relates to ADR-0039, ADR-0069, ADR-0082)

**Context.** `journal_mandate` used to be self-sufficient for ordinary writes. It
carried the activity-log path and a one-line format, an insight-note template,
and an explicit boundary:

> Activate `core-journaling` **only** for graph layout, indexes, journal-lint, or
> edge cases this template doesn't cover.

A later revision inverted that sentence to "**Before writing any entry, ensure
`core-journaling` is active** … The skill is the single source of truth for
journal mechanics," in the name of removing duplication. The cost was not
noticed: the skill is 6.8 KB, `templates/activity-entry.md` is 2.7 KB, and the
skill's activity entry is a six-field block (`Request` / `Skills used` /
`Actions` / `Outcome` / `Cross-links`) with a `## Backlinks` obligation and
index maintenance at three levels. Logging one turn went from *append one line*
to *activate a skill, read a template, then write 4–6 files.*

Two consequences followed:

1. The mandate's own incentive — "*When in doubt, log it* (cheap, promotable
   later)" — became false. It was written when the cheap path existed and
   survived its removal, so the prompt advertised a cost the protocol no longer
   offered.
2. The observed failure is deferral, not malformed output. In a recorded session
   the agent recognized a stated user preference, wrote "I'll log your name
   preference now," and yielded the turn without a single tool call — the
   cheapest legal action when the write is expensive and unobservable.

Meanwhile the *runtime* backstop is `LLM_INCLUDE_JOURNAL_REMINDER`, which
defaults to `off`, and its text had drifted to three exclusions plus "Do not log
merely because this reminder fired" — arguing against logging more often than
for it. So a Priority-Order rule ("a durable finding **must** be recorded before
the turn ends") had no mechanism behind it and an incentive pointing the wrong
way.

**Decision.** Restore the two-tier division, with the tiers named explicitly.

- **`journal_mandate` is self-sufficient for the everyday write.** It carries
  both shapes inline: the one-line activity append
  (`activity-log/YYYY/YYYY-MM/YYYY-MM-DD.md`) and the four-field insight note
  with its `## Backlinks` stub. No skill activation required.
- **`core-journaling` owns structural work** — new directories, index
  restructuring or repair, renaming/splitting/deleting notes, `journal-lint.py`,
  legacy-journal reconciliation, and entry shapes the mandate does not cover
  (the long-form activity entry). Its `SKILL.md` states this scope itself, so
  the two documents agree rather than contradict.
- **The graph protocol still governs every write.** The everyday shapes are a
  *subset* of the skill's protocol, not an exemption: one rule — "every forward
  link gets a reverse link in the target" — travels with the mandate, which is
  what the backlink obligation actually reduces to for a single note.
- **`templates/activity-entry.md` documents both forms**, short as the default
  and long for a multi-phase session, so the template no longer implies the
  heavy form is the only form.
- The false "cheap" claim is replaced with what is now true ("the activity line
  below is one line of text"), and the reminder text is rebalanced to a
  question plus one exclusion clause.

Three adjacent gaps in the same section are closed while the file is open:

- **Row collision.** The table said "find the row that matches", but "call me
  Go" matches both *greeting → skip* and *durable user preference → insight*.
  The narrower row now wins explicitly, and preferences get a named trigger:
  record on the turn they are stated, add to the HUD, honour immediately.
- **Negative claims about the journal.** ADR-0082 moved the index snapshot out
  of the cached prompt into the first turn's `<live-context>`, which is correct
  for caching but means the index scrolls out of view. `SearchJournal` is now
  required before asserting what the journal does or does not contain.
- **Deferral.** "Deferring a write is equivalent to discarding it" is restored
  from the pre-inversion text, alongside the general rule in `workflow.md`
  ("stating an action is not performing it").

**Consequences.**

- *Good.* The common case is one `Write` call again. The incentive and the
  mechanics agree.
- *Good.* The two documents have a stated boundary, so neither claims to be the
  single source of truth for the other's scope.
- *Cost.* `journal_mandate` grows 3.9 KB → 6.6 KB. Net context is lower whenever
  a turn journals at all: it replaces ~9.5 KB of skill + template that had to be
  loaded to write one line.
- *Cost.* The activity format now appears in two places (mandate and template).
  Accepted deliberately: the duplication is 1 line, and removing it is what
  caused this regression. The template is labelled as the authority for the long
  form.
- *Neutral.* `LLM_INCLUDE_JOURNAL_REMINDER` stays `off` by default. With the
  cheap path restored the prompt-level rule is followable on its own; flipping a
  hook default is a separate decision.

**Alternatives rejected.**

- *Keep the skill as the single source of truth and shorten the skill.* The
  graph protocol, layout, and lint contract are genuinely ~7 KB of material.
  Shortening it to fit the common case would delete the structural guidance that
  is the skill's reason to exist.
- *Turn the reminder hook on by default.* Treats a per-turn nudge as a
  substitute for a followable rule, and pays a token cost every turn for a write
  that most turns should not make.
- *Add a dedicated `JournalWrite` tool that encapsulates the protocol.* Real
  option, and better than prose — but it is a new tool on every request's schema
  and a new failure surface. Worth revisiting; out of scope for a prompt fix.
- *Leave the "cheap" claim and let the model judge.* Models did judge, correctly,
  that it was expensive — and skipped. The prompt was the thing that was wrong.
