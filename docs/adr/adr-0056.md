# ADR-0056 — Tool-definition weight is managed by tool count, not by prose

**Status:** Accepted

**Context.** Every *registered* tool's docstring **and** parameter schema is
serialized into every request. That has one consequence people repeatedly get
wrong, so it is recorded as a decision rather than left as folklore: **moving
prose into a docstring does not save tokens.** A docstring is not deferred
context. The only lever on tool-definition weight is the **number** of tools
visible per request.

**Decision.** Manage the count on three axes.

- **Conditional registration.** Tools that only make sense in a particular
  environment or configuration are not registered otherwise: LSP tools,
  worktree tools, the plan-mode pair, and the journal tools (ADR-0053).
- **`defer_loading=True`** on tools that are genuinely rarely used. A deferred
  tool's *name* stays discoverable through native provider-side tool search, and
  its docstring and schema materialize only when the model searches for it.
- **Preset gating.** `LLM_PROFILE` binds a tool surface alongside a section list
  (ADR-0075), so a model class too small to route among twenty tools is given
  ten. This is the only axis that can shrink the surface *below* what the
  environment supports, and the only one under which `defer_loading` can stop
  being a saving — but only where the preset closes the surface outright.
  Deferral trades a schema for a `search_tools` entry the model must call first,
  which pays while it hides a dozen tools and inverts at ten; it also depends on
  provider-side tool search, which the local runtimes a ten-tool preset targets
  generally lack, so a deferred tool there is unreachable rather than cheap. A
  preset that merely *subtracts* a few tools keeps enough behind the indirection
  for it to still pay, so un-deferring is keyed on `Preset.tools is not None` —
  on whether the surface is closed — not on whether the axis is constrained.

Relocating a rule into a docstring is still worth doing — but for **locality
and adherence** (ADR-0045), never as a size argument.

**A registered set must be closed under docstring cross-reference.** Docstrings
route between each other — `Shell` names `Read`/`Write`/`Edit`/`Grep`/`Glob`/
`RM`/`MV` to say what it is *not* for. Because a docstring ships with its schema
regardless of configuration, it cannot carry a `<!--requires:-->` guard the way
a prompt section can (ADR-0046), so a reference to an unregistered tool dangles
with nothing to catch it. Whichever axis removes a tool owns checking what still
points at it — and docstrings are only the first of the three channels that can
name a tool. Prompt sections and injected context are the other two; ADR-0075
states the closure invariant over all three.

**Consequences.** The per-request tool-definition floor tracks the tools a
session can actually use. The cost is that a deferred tool is one search away
rather than immediately visible, so deferral is wrong for anything on a common
path; and `defer_loading` depends on provider-side tool search, so it is a
weaker lever where that is unavailable.

**Alternatives rejected.** *Register everything eagerly* — pays for LSP, RAG and
worktree schemas in every session that never touches them. *Trim docstrings to
save tokens* — misidentifies the lever, and buys the reduction by making the
tools harder to call correctly. *A single mega-tool with a `mode` argument* —
collapses the count, and replaces N clear schemas with one union the model must
disambiguate at every call.

**Where it lives.** `src/zrb/llm/common_tools.py` (its module docstring states
the constraint), `src/zrb/builtin/llm/chat.py` (`_tool_factory`),
`AGENTS.md` (LLM Prompt System).
