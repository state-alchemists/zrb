# ADR-0017 — Cancellation is re-raised after cleanup, never swallowed

**Status:** Accepted

**Context.** `Ctrl+C` and programmatic cancellation must tear down the event
loop cleanly, without leaving tasks stuck in a "running" state.

**Decision.** Catch `(asyncio.CancelledError, KeyboardInterrupt,
GeneratorExit)` *separately* from ordinary exceptions: mark the task failed,
then **re-raise** so the loop unwinds. Only non-cancellation exceptions feed
the retry and fallback path.

**Consequences.** Shutdown is responsive and leaves no zombie tasks. The cost
is that every execution layer must follow the catch-separately-and-re-raise
discipline; a bare `except Exception` anywhere breaks it.

**Alternatives rejected.** *A broad `except Exception`* — swallows
cancellation, so `Ctrl+C` appears to hang. *Ignore cancellation entirely* —
leaves inconsistent state and confusing logs.

**Where it lives.** `src/zrb/task/base/lifecycle.py`,
`src/zrb/task/base/execution.py`,
`docs/advanced-topics/architecture.md`.
