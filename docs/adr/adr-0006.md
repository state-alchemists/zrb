# ADR-0006 — DAG dependencies declared with `>>` and `<<`

**Status:** Accepted

**Context.** Pipelines need ordered, parallelizable dependencies declared in a way that reads like data flow rather than bookkeeping.

**Decision.** Tasks form a directed acyclic graph. Dependencies are declared with overloaded shift operators — `task_a >> task_b` ("A feeds B"), or the reverse with `<<` — or with the explicit `upstream=[...]` parameter. The session walks upstreams to find roots and runs independent branches concurrently.

**Consequences.** Pipelines read as data flow and are self-documenting; acyclicity prevents deadlocks; independent branches parallelize for free. The cost is that operator overloading is a learned idiom, and very large graphs are still assembled in code.

**Alternatives rejected.** *A method-call API* (`b.add_upstream(a)`) — kept as the `upstream=` parameter, but too verbose to be the primary form. *A separate declarative DAG file* — loses the surrounding context and fights ADR-0001. *Linear execution* — no parallelism at all.

**Where it lives.** `src/zrb/task/base/operators.py`, `src/zrb/session/session.py` (`get_root_tasks`), `docs/core-concepts/tasks-and-lifecycle.md`.
